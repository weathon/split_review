## Summary

This paper proposes **RLIE**, a framework that combines LLM-based natural language rule generation with elastic-net regularized logistic regression for probabilistic rule weighting and selection, coupled with error-driven iterative refinement. The method is evaluated on six binary classification datasets from HypoBench. A hierarchical evaluation (E1–E4) compares direct linear inference against three levels of LLM-augmented inference, finding that the simple linear combiner consistently outperforms injecting rules back into the LLM — a result the paper interprets as evidence that LLMs are unreliable for fine-grained probabilistic integration.

## Strengths

* **Principled integration of LLM rule generation with probabilistic global weighting (Section 3.2).** Using elastic-net-regularized logistic regression to learn weights over LLM-generated rules is a clean architectural departure from prior LLM-based rule learners (HypoGeniC, IO Refinement), which rely on flat voting or single-hypothesis refinement without probabilistic calibration. The regularization enables automatic rule selection via L₁ and robust estimation via L₂.

* **Ternary rule judgments with explicit abstention (Section 3.1).** The LLM produces judgments z_{i,j} ∈ {−1, 0, +1}, where 0 denotes "not applicable." This explicitly models rule coverage and avoids forcing predictions when a rule does not apply, a more expressive representation than binary satisfaction used in prior work.

* **Error-driven iterative refinement via logistic regression residuals (Section 3.3).** Hard examples are selected by ranking prediction errors from the learned logistic model (d_i = |p̂_i − y_i|), making each refinement round targeted rather than relying on random sampling or rule-level accuracy alone.

* **Consistent top-two performance across six datasets (Table 1).** RLIE (DeepSeek-V3) achieves the best accuracy/F1 on 4/6 datasets (Dreadit, Headlines, Citations, LLM Detect) and ranks second on the remaining two, demonstrating robustness across diverse tasks.

* **Systematic hierarchical evaluation strategy (Section 3.4, Table 2).** The decomposition into E1–E4 (linear-only → rules → +weights → +reference prediction) is a thoughtful experimental design that probes how different levels of information affect LLM reasoning, even if the implementation has issues (discussed below).

## Weaknesses

### Major

* **Ambiguous and potentially confounded backbone LLM usage in Table 1.** Section 4.3 states "All experiments involving LLMs utilized `gpt-4o-mini`," while Table 1 lists backbones like DeepSeek-V3 for both baselines and RLIE rows, and Table 2 uses DeepSeek-V3/Qwen3-235B for the E2–E4 inference strategies. The paper never clarifies which LLM is used for each sub-component (rule generation, rule judgment, baseline inference). If RLIE's rule generation and judgment use `gpt-4o-mini` while the baselines use DeepSeek-V3 for their LLM calls, then the comparison is confounded: observed performance differences could stem from the LLM choice rather than the RLIE framework. If the same LLM is used throughout, the "Backbone" column is misleading. Either way, the experimental design as presented does not separate method effect from LLM effect. This undermines confidence in the headline claims of Table 1.

* **Missing standard deviations despite claiming to report them.** Section 4.3 states "Each experiment was repeated at least three times, and we report the mean and standard deviation of the results," yet Table 1 and Table 2 show only point estimates with no variance measure. With only 200 training samples and high sensitivity to random splits, readers cannot assess whether the reported improvements (often a few percentage points) are statistically meaningful or merely noise. This is a straightforward reporting gap that weakens the entire quantitative contribution.

### Minor

* **Cross-model confound in the inference strategy comparison (Table 2).** The E2–E4 strategies use DeepSeek-V3 or Qwen3-235B as the inference LLM, but the rules were generated by `gpt-4o-mini` (per Section 4.3). Rules written by one model may be suboptimally phrased for a different model's interpretation style. A cleaner test of whether LLMs can integrate probabilistic information would either (a) use the same LLM for rule generation and inference, or (b) at least acknowledge this cross-model transfer as a limitation. The paper's central claim about "LLMs being less reliable at fine-grained probabilistic integration" is therefore only weakly supported.

* **Initial rule generation sample size unspecified.** Section 3.1 says "We randomly sample k examples from S_tr" for initial rule generation, and Section 4.3 specifies only the hard-example size (k=20) for iterative refinement. The initial sample size is never given, hindering reproducibility.

* **Limited dataset scale (200/200/300 splits).** The paper does not justify why such small splits are adequate for LLM-based rule learning, nor does it discuss how results might change with larger datasets. While this follows HypoBench conventions, the concern about high variance with tiny training sets is not addressed.

* **Hyperparameter tuning for baselines not reported.** The paper states baselines use "default hyperparameter settings from original papers," but does not report whether these defaults were tuned on the validation set. If the baselines are not properly tuned while RLIE's logistic regression uses cross-validated Elastic Net, the comparison may be asymmetric.

## Removed Points

* **"Circular dependency in iterative refinement"** — The critic claims that using logistic regression residuals to identify hard examples creates a circular dependency. This is a designed feature of the approach (error-driven refinement), not a bug. Every iterative method uses its own errors to guide improvement. Removed as a strawman criticism.
* **"Not a fair comparison because LoRA uses a different architecture"** — The paper explicitly notes that LoRA achieves high scores on simple tasks but fails on complex ones, and does not claim RLIE beats LoRA. Removed because the paper handles this appropriately.
* **"Overclaiming 'superior over all performance' when RLIE is not best on all 6 datasets"** — The paper shows RLIE is top-2 on all datasets and best on 4/6, which is accurately described as "superior over all performance" in context (the LoRA baseline is acknowledged as an unfair comparator on simple tasks). Removed as an overly literal reading.
