Score: 6.0.## Summary

This paper introduces Ambig-SWE, a benchmark derived from SWE-Bench Verified where each of the 500 original issues is paired with a synthetically underspecified variant generated by GPT-4o. The core contribution is a three-capacity evaluation framework that decomposes how LLM agents handle underspecified code-repair instructions: detecting missing information, asking targeted clarification questions, and leveraging the interaction to improve task completion. The paper evaluates six models (Claude Sonnet 3.5/4/Haiku 3.5, Qwen 3 Coder, Deepseek-v2, Llama 3.1 70B) across Full, Hidden, and Interaction settings, finding that interaction recovers significant performance but that models default to non-interactive behavior and struggle to detect underspecificity reliably.

## Strengths

1. **Structured multi-capacity decomposition.** The paper separates underspecificity resolution into three measurable capacities (detection in §4, question quality in §5, leveraging in §3) with distinct metrics. This is more informative than prior work that treats underspecificity as a monolithic missing-detail problem. The decomposition enables targeted diagnosis — for example, revealing that Qwen 3 Coder extracts the most information (cosine distance 0.179) but fails to integrate it (resolve rate drops when given navigational info, Table 1), while Claude Sonnet 4 achieves comparable information with 50% fewer questions through an exploration-first strategy (Figures 5–6).

2. **Non-obvious empirical findings about interaction rigidities.** The paper documents specific, replicable failure modes: Qwen 3 Coder achieves 100% false negative rate (never interacts) across all three prompt conditions in Table 2, and when it does receive navigational information its resolve rate actually *worsens* (52.38% with info vs. 55.43% without, Table 1). The qualitative analysis (Section 5.3) attributes this to rigid protocol-following — the model re-explores the codebase for file locations the user just provided, wasting turns. These findings concretely challenge training paradigms that prioritize task completion over adaptive integration of interactive feedback.

3. **Causal attribution enabled by paired ground-truth data.** Because each underspecified instance has a known complete specification (generated synthetically from the SWE-Bench Verified gold standard), the design allows causal claims about whether performance improvements result from resolving genuine underspecification — something impossible with naturally underspecified issues that lack verified correct specifications (discussed in Section 2.1).

4. **Navigational vs. informational typology with differential model impact.** Table 1 shows that requesting file locations boosts performance for most models (e.g., Claude Sonnet 3.5 jumps from 37.94% to 59.52%) but helps little for Llama or even hurts Qwen. The analysis in Section 3.3 reveals that smaller models rely heavily on navigational cues while newer models show lower marginal gains — a concrete, actionable design insight for agent builders.

## Weaknesses

### Major

1. **Unequal interaction-turn limits confound the core resolve-rate comparisons.** Claude Sonnet 4 and Qwen 3 Coder receive up to 100 interaction turns in the Interaction setting, while all other models are capped at 30 turns (Section 3.1). The paper states that Qwen 3 Coder uses ~65 action steps and Claude Sonnet 4 uses ~75 steps in the Interaction setting — both exceeding the 30-turn limit imposed on the other models. If Llama, Deepseek, Haiku, or Sonnet 3.5 would have benefited from more turns, their Interaction performance is underestimated relative to the high-turn models. This is not a fatal flaw (the paper's main claims about interaction being beneficial overall are robust), but it weakens the *comparative* claims (e.g., "proprietary models generally demonstrate greater effectiveness in utilizing interaction compared to open-weight models") because the evaluation conditions are not held constant. A sensitivity analysis showing resolve rates under equalized turn budgets or per-turn performance curves would be needed to verify that the relative ordering is not an artifact of this asymmetry.

2. **Claude Sonnet 4 evaluated on only 100/500 instances in the Hidden setting.** This is reported in footnote 4 ("Claude Sonnet 4 is evaluated on a subset of 100/500 instances in the Hidden setting. The model compensates for the lack of information with increased exploration and solution attempts leading to substantially higher evaluation costs."). This reduces the statistical power for Hidden-setting comparisons involving Claude Sonnet 4, and the paper's claim that findings are "still statistically significant" (Table 4, in appendix) does not fully address the concern that the point estimate from 100 instances has substantially wider confidence intervals than those from 500 instances. The prominence of this limitation in a footnote rather than the main experimental design description is misleading.

### Minor

3. **The "up to 74%" improvement figure in the abstract and introduction is not clearly tied to a specific computation in the reported results.** The maximum relative improvement (Interaction over Hidden) among the reported models is 100% for Claude Haiku 3.5 and ~64% for Claude Sonnet 3.5. The 74% figure — which appears twice (abstract, Section 1) — does not correspond to any single model's relative improvement in the presented data. It may be computed as the gap-recovery ratio for Claude Sonnet 4: (61.4−40)/(68−40) ≈ 76.4%, but this is not explained and differs from the "relative performance" metric (Interaction/Full) used in Section 3.2. While this imprecision does not affect the paper's substance, it should be clarified.

4. **The detection experiment (RQ2, Section 4) conflates the cognitive capacity of detecting underspecificity with the behavioral decision to act on it.** The metric (accuracy/FPR/FNR) is based on whether the model *chooses to ask a question*, not whether it internally recognizes missing information. A model could detect underspecificity but decline to ask (e.g., because training rewards independent problem-solving). The finding that Qwen 3 Coder has 100% FNR could reflect recognition without action, not failed detection. The paper acknowledges this indirectly ("models default to non-interactive behavior") but the framing ("Can LLMs identify whether a given task description is missing crucial information?") overclaims what is directly measured. The results would be more precisely described as measuring *interaction initiation* rather than *detection capacity*.

5. **The 74% improvement and other headline numbers are stated without confidence intervals or error bars.** For example, Qwen 3 Coder's Interaction resolve rate of 53.8% on 500 instances has a binomial 95% CI of roughly ±4.4%, which overlaps substantially with the 45.6% Hidden rate. The paired Wilcoxon tests (Table 4 in appendix) address statistical significance but CIs would give readers a more intuitive sense of effect size precision.

6. **No ablation on the user proxy's cooperativeness.** The GPT-4o proxy always answers accurately and never misleads. The paper acknowledges this in Section 7 ("our simulated user proxy may be more cooperative than real users"), but the central claim about interaction recovering "up to 74% of performance" is an upper bound under near-ideal conditions. Testing degraded user behavior (e.g., vague answers, "I don't know" responses) would establish a more realistic lower bound on interaction benefits.

7. **No cost analysis.** Interaction improves resolve rates but requires more tokens and API calls. For practical deployment decisions, the efficiency tradeoff is critical. The paper mentions action-step counts (§3.2) but does not quantify total monetary cost, which would vary substantially between models.
