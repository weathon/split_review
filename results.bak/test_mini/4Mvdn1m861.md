## Summary

This paper proposes TokenCount, a training-free object counting framework built on SAM. It introduces two components working in synergy: (1) a probabilistic prompt generation stage that adaptively samples prompts based on a similarity-derived probability distribution updated iteratively, and (2) an output token-based verification stage that leverages SAM's decoder output tokens with a TS-SS geometric similarity metric (instead of image embedding similarity) to distinguish positive from negative instances. The method achieves MAE 16.25 on FSC-147 (best among SAM-only training-free methods) and MAE 4.68 on CARPK (outperforming all listed supervised methods on that dataset).

## Strengths

1. **Novel use of SAM output tokens for verification.** The paper is the first to directly repurpose SAM's decoder output tokens — rather than image embeddings — as the verification criterion for object counting. Table 5 shows output token space (MAE 16.25) outperforms the same method run on image embedding space (MAE 16.94), and Figure 5 provides PCA visualization showing cleaner separation of positive/negative instances in the output token space. This is a genuinely new idea distinct from prior training-free counting work.

2. **Probabilistic prompt generation is a principled improvement over deterministic alternatives.** The method (Section 3.1, Eq. 1) models the likelihood of object locations via a softmax over temperature-scaled cosine similarity, then iteratively samples from a multinomial distribution and suppresses verified regions (setting positive coordinates to 0, decreasing negative regions). Table 4 shows systematic improvement from 8×32 (MAE 29.10) to 16×128 (MAE 16.25), demonstrating that the adaptive exploration works.

3. **Competitive performance within a strict SAM-only, training-free constraint.** On FSC-147, TokenCount achieves MAE 16.25, the best among all SAM-only training-free methods (beating TFOC's 19.95 and C-Anything's 27.97). On CARPK, it achieves MAE 4.68, surpassing all listed supervised methods (e.g., BMNet+ 5.76, SAFECOUNT 5.33). These results validate that meaningful counting can be done without additional models or fine-tuning.

4. **Computational efficiency is explicitly reported and contextualized.** The paper reports 1.69 seconds per image on FSC-147 and claims "more than twice as fast" inference as TFCAC (which uses an additional DINO encoder). This practical deployment-relevant comparison is useful and largely absent from many prior counting papers.

## Weaknesses

### Fatal
None.

### Major

1. **The abstract makes a false quantitative claim.** The abstract states the method "outperforming existing training-based and training-free counting methods" with MAE 16.25. This is factually incorrect based on Table 1: LOCA (MAE 10.79), PseCo (13.05), BMNet+ (14.62), SAFECOUNT (14.32), and TFCAC (12.26) all achieve substantially lower MAE. The method only beats Counting-DETR (16.79) among training-based methods. While the main text (Section 4.2) is appropriately measured — correctly stating "best performance among training-free SAM only methods" — the abstract's overclaim is a serious misrepresentation that requires correction.

2. **The CARPK evaluation uses a non-standard 12-exemplar protocol.** The paper states "we randomly selected 12 objects from the training set to use as exemplars" for CARPK. Standard few-shot counting protocols typically use 3 exemplars, and the training-based methods in Table 1 (BMNet+ 5.76, SAFECOUNT 5.33) were evaluated with standard protocols. Using 12 exemplars for a single-class dataset inflates performance and makes the claimed "outperforming all supervised methods" on CARPK an apples-to-oranges comparison. The authors should report results with the standard protocol (e.g., 3 exemplars) to verify the comparison is fair.

3. **The TS-SS metric advantage over cosine similarity is marginal and unsupported by statistical testing.** Table 3 shows TS-SS (MAE 16.25) vs. cosine similarity (MAE 16.48) — a 0.23 absolute improvement (≈1.4% relative). Neither variance nor confidence intervals are reported. Given that RMSE values are high (~133) across all variants, this difference could easily be within noise. The paper's claim that "non-hybrid metrics have reached a performance plateau" (Section 4.4) is not strongly supported by the data. Since TS-SS is the core methodological contribution over simpler alternatives, the paper should demonstrate this advantage is robust (e.g., across multiple runs or seeds, consistent across datasets).

### Minor

1. **The verification threshold (300) lacks calibration or sensitivity analysis.** Section 4.1 states "Based on validation experiments, we set the token verification threshold to 300" with no further analysis. TS-SS is an unbounded product (Eq. 2–3), so this threshold is dataset-specific and likely non-transferable. A sensitivity curve showing MAE across a range of thresholds, or an automatic calibration procedure, would strengthen reproducibility.

2. **One-shot results are described as "comparable" when they are clearly not.** Table 2 shows the method's MAE (18.57) is substantially worse than TFCAC (15.15) and BMNet+ (16.89), and only beats CFOCNet (28.60) and FamNet (26.76). This is not "comparable" to the better methods. The language should be more precise.

3. **The FSC-147 few-shot exemplar count is not specified.** The paper describes the few-shot protocol in Section 4.2 but never states how many exemplars were used for FSC-147. Standard practice is 3 exemplars; this should be confirmed.

4. **The iterative update rule for negative regions is underspecified.** Section 3.1 states negative coordinates have their "value...decreased" but does not give the decrease factor or whether it is fixed or adaptive. This makes the algorithm incompletely specified.

### Trivial

- The "we could overlapping masks more precisely" sentence (Section 4.1) contains a grammatical error.
- Table 1's grouping "SAM + α" is potentially confusing — it includes OmniCount (which uses SAM + DINO) and TFCounter/TFCAC, but the caption does not clarify whether TFCounter uses additional models.
