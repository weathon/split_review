## Summary

This paper systematically evaluates nine open-source mid-sized LLMs (12–16B) on two reverse engineering tasks—name recovery (function and variable names) and type inference—using decompiled and assembly code from binaries compiled for four architectures (x86-64, ARM, MIPS) at multiple optimization levels. The main finding is that none of the models achieves high scores in zero-shot settings, with most F1 scores below 0.1. The paper also reports fine-tuning results using LoRA (200 steps) and analyzes factors like model size, training quality, and prompt sensitivity.

## Strengths

1. **Systematic multi-dimensional evaluation.** The paper tests nine LLMs across four architectures (x86-64, x86-32, ARM 32, MIPS 32), multiple optimization levels (O0–O3), and two input formats (decompiled code and assembly), with a total of 40,000 unique function samples (Section 4.1, Table 1). This breadth provides a reproducible baseline that prior work in this area lacked.

2. **Concrete evidence that training quality matters more than model size.** Figure 2 and Tables 2–3 show that CodeLlama-13B and Qwen2.5-14B outperform larger variants (CodeLlama-34B) and similarly-sized but differently-trained models (DeepSeek-R1 vs. Qwen2.5). This is a non-obvious insight with practical implications for model selection (Findings 4–6).

3. **Type inference remains near-zero even after fine-tuning.** Table 4 shows all models, both original and fine-tuned, achieve F1 scores below 0.1 on type inference across all optimization levels. This stark empirical result strongly supports the paper's central negative finding about the fundamental limitations of current LLMs on this task (Finding 2).

4. **Real-world firmware evaluation with two decompilers.** The paper validates findings on real-world firmware using both Ghidra and IDA Pro (Table 6), providing an operationally relevant test beyond synthetic benchmarks.

## Weaknesses

### Major

1. **Abstract claims a result (0.37 F1 for DeepSeek-R1) that does not appear in the reported tables.** The abstract states: "after fine-tuning, DeepSeek-R1 demonstrates a notable improvement, reaching an F1 score of 0.37." However, in the main tables (Tables 2–4), DeepSeek-R1's highest fine-tuned score is 0.17 (variable name recovery at O0, Table 3). No table in the main text shows 0.37, and the paper does not specify which task, architecture, or condition yields this figure. This is a serious inconsistency between the abstract's headline result and the presented experimental data.

2. **The auxiliary LLM used for response extraction is not validated, creating an uncontrolled confound.** The paper uses an unidentified LLM to post-process heterogeneous model outputs into a uniform schema (Section 3.2). However, it provides: (a) no details about which LLM is used, (b) no prompt template for the extraction step, and (c) no evaluation of extraction accuracy on a labeled set of model outputs. If the extraction LLM misparses or discards valid predictions, the target model's performance is artificially lowered; if it hallucinates, scores are inflated. This confound affects all experimental results (Tables 2–6) and is not quantified or bounded. The paper should at minimum validate extraction accuracy and disclose the extraction model and prompt.

3. **Fine-tuning is limited to 200 steps with no convergence tracking, making the fine-tuning results preliminary.** The paper fine-tunes on 160,000 samples for only 200 steps (Table 7), with no information about batch size, learning rate, number of epochs, or loss curves. At typical batch sizes (e.g., 8–32), this covers only ~1–4% of the training data. The modest and inconsistent gains (e.g., DeepSeek-V2 dropping from 0.10 to 0.05 in Table 3) may simply reflect under-training. The paper's conclusion that fine-tuning "can yield measurable improvements" (Section 5) is not adequately supported given this shallow protocol. This does not undermine the zero-shot results but significantly weakens the fine-tuning analysis.

### Minor

4. **The SYMLM/CodeWordNet-based F1 metric for name recovery is not fully specified.** The paper states it "adopts the SYMLM method" which uses CodeWordNet to compute semantic distances between sub-words (Section 3.4), but does not explain how partial similarity scores are converted into the binary decisions required for precision, recall, and F1. While the method is cited from prior work (Jin et al., 2022), the paper should summarize the conversion process (e.g., threshold, aggregation) for self-contained readability. This is a clarity issue, not a fatal flaw.

5. **The paper's scope is more limited than its title suggests.** The title "LLMs AS REVERSE ENGINEERS? NOT YET" implies a sweeping conclusion about LLMs broadly, but the paper evaluates only mid-sized open-source models (12–16B) and explicitly excludes larger models (GPT-4, Claude) and API-based systems. The paper states its scope (Section 4.2), so this is not a methodological error, but the framing overgeneralizes relative to the evaluated model class.

## Suggestions

1. Fix the abstract discrepancy: either clearly state which task/condition yields the 0.37 F1 for DeepSeek-R1, or remove the claim if it cannot be verified.
2. Add a validation study for the extraction LLM: hand-label at least 200 model outputs, measure extraction accuracy, and report the error rate.
3. For any revision, run fine-tuning to convergence (with loss curves) and report standard hyperparameters before drawing conclusions about fine-tuning effectiveness.

## Score and Decision

The paper tackles an under-studied problem with a broad experimental design, and its zero-shot results—showing that current mid-sized open-source LLMs perform poorly on reverse engineering tasks—are supported by the evidence. However, the paper has three significant weaknesses: (1) a headline result in the abstract (0.37 F1) that does not match the reported tables; (2) an unvalidated auxiliary LLM pipeline that could introduce uncontrolled noise into all measurements; and (3) a fine-tuning protocol too shallow to support the paper's conclusions about fine-tuning effectiveness. The first two issues are addressable through corrections and additional experiments, while the third mainly limits the fine-tuning claims rather than the main zero-shot findings. The paper offers a useful baseline but falls short of the rigor needed for a fully convincing evaluation.
