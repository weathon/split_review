## Summary:

This paper introduces HASTE, a novel framework designed to enhance the performance of Large Language Models (LLMs) in software engineering tasks by optimizing code context retrieval. The core challenge addressed is the limited context window of LLMs, which often hinders their ability to effectively process and understand large codebases. HASTE tackles this issue by combining Abstract Syntax Tree (AST)-guided selection with token-bounded extraction, aiming to strike a balance between semantic relevance and structural coherence in the retrieved code context. The framework employs a multi-stage process: first, it uses AST parsing to identify semantically relevant code snippets; then, it applies a hybrid retrieval strategy that combines lexical and semantic similarity measures to rank these snippets; and finally, it performs token-bounded extraction to ensure the context fits within the LLM's constraints. The key methodological innovation lies in the integration of AST-based structural information with semantic relevance scoring, which allows for more informed context retrieval compared to purely lexical or semantic approaches. The paper presents empirical findings from experiments conducted on Python codebases, demonstrating that HASTE can achieve up to 85% code compression while maintaining or even improving the performance of automated code edits. The authors use an LLM-as-a-judge framework to evaluate the quality of the retrieved context and the resulting code edits, comparing HASTE against several baselines, including IR-only retrieval, AST-only retrieval, and naive truncation. The results suggest that HASTE's hybrid approach outperforms these baselines, particularly in tasks requiring a deep understanding of code structure and semantics. The overall significance of this work lies in its potential to enable more effective use of LLMs in software development by addressing the critical challenge of context window limitations. By providing a mechanism for retrieving compact yet semantically and structurally coherent code contexts, HASTE paves the way for more reliable and scalable AI-assisted software engineering tools. The paper's contributions include the introduction of a novel code retrieval pipeline, empirical validation of its effectiveness using an LLM-as-a-judge framework, and an analysis of the trade-off between compression and quality. These contributions advance the field by offering a practical solution to a key bottleneck in the application of LLMs to software engineering, potentially impacting how developers interact with and leverage LLMs for code-related tasks.

## Strengths:

The paper's primary strength lies in its innovative approach to code context retrieval for LLMs. By combining AST-guided selection with token-bounded extraction, HASTE effectively addresses the critical challenge of balancing semantic relevance and structural coherence within the constraints of an LLM's context window. This hybrid approach, which integrates both lexical and semantic signals, represents a significant advancement over methods that rely solely on one or the other. The use of ASTs allows for a more nuanced understanding of code structure, enabling the retrieval of context that is not only semantically related but also structurally sound. This is particularly important for software engineering tasks, where the relationships between different code elements are crucial. The empirical evaluation, while having limitations, provides evidence of HASTE's effectiveness. The experiments demonstrate that HASTE can achieve substantial code compression (up to 85%) while maintaining or improving the performance of automated code edits. This is a notable achievement, as it shows that HASTE can reduce the amount of context needed by LLMs without sacrificing quality. The comparison against several baselines, including IR-only retrieval, AST-only retrieval, and naive truncation, further highlights the advantages of HASTE's hybrid approach. The use of an LLM-as-a-judge framework for evaluation is also a strength, as it allows for a more direct assessment of the quality of the retrieved context from the perspective of an LLM. This approach is particularly relevant for evaluating the effectiveness of context retrieval methods for LLMs. The paper is generally well-organized and clearly written, making it relatively easy to follow the proposed methodology and experimental results. The authors provide a logical flow that guides the reader through the problem statement, the proposed solution, and the empirical validation. The analysis of the trade-off between compression and quality is also insightful, providing valuable guidance for practitioners on how to balance these factors in real-world applications. The paper's contributions, including the novel code retrieval pipeline, the empirical validation, and the analysis of the compression-quality trade-off, represent a valuable addition to the field of AI-assisted software engineering.


## Weaknesses:

Despite its strengths, the paper exhibits several weaknesses that warrant careful consideration. One of the most significant limitations is the lack of a comprehensive comparison with a wider range of existing methods. While the paper discusses related work, the experimental evaluation only compares HASTE against a limited set of baselines: IR-only retrieval, AST-only retrieval, and naive truncation. This omission is particularly concerning given the existence of methods that leverage different code representations, such as program dependencies and data flow analysis, as well as those that employ alternative retrieval strategies, such as graph neural networks. The absence of a direct comparison against these methods makes it difficult to fully assess the relative strengths and weaknesses of HASTE. For instance, methods that use program dependencies might be better at capturing semantic relationships between code entities, while graph-based approaches could be more effective at modeling code structure. Without a thorough comparison, it remains unclear how HASTE performs in relation to these alternatives. This limitation is further compounded by the lack of a detailed analysis of the computational complexity of the proposed approach. The paper describes the various components of HASTE, including AST parsing, hybrid retrieval, and call graph expansion, but it does not provide a formal analysis of the time and space complexity of these operations. This is a critical omission, as it makes it difficult to assess the scalability of HASTE, particularly when dealing with large codebases. The absence of a theoretical complexity analysis, coupled with the lack of empirical measurements of processing time and memory usage for different codebase sizes, leaves a significant gap in our understanding of HASTE's practical applicability. The paper also lacks a thorough discussion of the limitations of the proposed approach. While the authors touch upon some aspects, such as the potential for degraded performance on very large codebases, they do not delve into the specific challenges that might arise in such scenarios. For example, the paper does not discuss how the performance of HASTE might be affected by highly nested code structures or by the presence of code with complex control flow. Similarly, the paper does not adequately address the sensitivity of HASTE to the quality of the input code. It remains unclear how HASTE would perform when dealing with code that contains bugs, inconsistencies, or unusual coding patterns. This lack of discussion about the limitations of the approach makes it difficult to assess its robustness and generalizability. Furthermore, the paper's evaluation is primarily focused on Python code, raising concerns about the generalizability of HASTE to other programming languages. The paper does not provide sufficient evidence or arguments to support the claim that HASTE can be effectively applied to languages with different syntax and semantics. The absence of experiments on languages such as C++, Go, or Rust makes it difficult to assess the portability of the approach. The paper also lacks a detailed analysis of the computational overhead introduced by the AST-guided selection process. While the paper mentions that latency is measured, it does not provide a breakdown of the time required for AST parsing, semantic similarity calculations, or the overhead of maintaining the vector store. This lack of detail makes it difficult to assess the efficiency of HASTE and to compare it with other context retrieval methods. Finally, the paper suffers from some issues with clarity and presentation. The overview figure (Fig. 1) is difficult to interpret, and the descriptions of some modules, such as the "Payload Builder" and "Identifier Extraction," lack sufficient technical detail. The "Hybrid Ranker" is mentioned, but its implementation details beyond the formula are not elaborated upon. The "Observability" section, while potentially useful, is not well-justified within the main narrative, and its inclusion in the main architecture diagram seems out of place. These issues with clarity and presentation make it more difficult to fully understand the proposed approach and its implementation.


## Suggestions:

To address the identified weaknesses, I recommend several concrete improvements. First, the paper should include a more comprehensive experimental evaluation that compares HASTE against a wider range of existing methods for code context retrieval and compression. This should include methods that use different code representations, such as abstract syntax trees, program dependencies, and control flow graphs, as well as methods that employ different retrieval strategies, such as graph-based methods, hybrid approaches, and methods that use learned embeddings. The comparison should not only focus on the compression ratio but also on the quality of the retrieved context, measured by metrics such as the ability to support downstream tasks like code completion, bug fixing, and code summarization. The evaluation should also include a variety of codebases with different characteristics, such as size, complexity, and programming language, to demonstrate the generalizability of the proposed approach. Second, the paper should provide a detailed analysis of the computational complexity of the proposed approach, including the time and space complexity of the AST parsing, call graph construction, and hybrid retrieval steps. This analysis should consider how these complexities scale with the size of the codebase and the number of nodes in the call graph. The paper should also discuss the practical implications of these complexities, such as the time required to process a large codebase and the memory requirements for storing the call graph and index. Empirical results demonstrating the performance of HASTE on codebases of varying sizes should be included to support the theoretical analysis. Third, the paper should include a more thorough discussion of the limitations of the proposed approach, including its performance on very large codebases, its sensitivity to the quality of the input code, and its ability to handle code with complex dependencies. The paper should also discuss potential future directions for addressing these limitations, such as using more efficient algorithms for call graph construction, developing more robust methods for handling noisy code, and exploring alternative code representations that are more suitable for large-scale code analysis. Fourth, to enhance the evaluation, the authors should expand the range of code editing tasks and programming languages considered. This could involve including tasks such as code refactoring, bug fixing, and feature addition, which are common in real-world software development. Furthermore, the evaluation should include a diverse set of programming languages, such as C++, Go, Rust, and JavaScript, to demonstrate the generalizability of HASTE. The authors should also consider using a more comprehensive benchmark suite that includes a variety of code editing tasks and codebases with different characteristics. Fifth, the paper should provide a more detailed analysis of the computational overhead introduced by the AST-guided selection process. This should include metrics such as the time required for AST parsing, the time required for context retrieval, and the memory usage of the framework. The authors should also compare the computational overhead of HASTE with other context retrieval methods to demonstrate its efficiency. This analysis should be conducted on a variety of codebases with different sizes and complexities to provide a more comprehensive understanding of the framework's performance. Sixth, the paper needs a significant overhaul in its presentation and technical detailing. The overview figure (Fig. 1) should be redrawn to clearly illustrate the flow of information and the purpose of each module. Each component, especially the "Payload Builder," "Identifier Extraction," "Hybrid Ranker," and "Observability," should have a dedicated section or subsection explaining its functionality, algorithms, and data structures. The writing quality needs to be improved throughout the paper, with a focus on clarity, conciseness, and technical accuracy. Finally, the observability component needs to be either justified more clearly or moved to the appendix. If it is intended to be a core part of the paper, its function and importance should be explained in detail. The paper should clarify how the metrics collected by the observability layer are used to improve the performance of HASTE or to debug issues. If the observability component is not essential to the core contribution of the paper, it should be moved to the appendix to avoid distracting from the main narrative.

Clarifying the role of the observability component and its contribution to the overall framework is essential. Finally, how does HASTE perform on a wider range of programming languages and code editing tasks, and what are the potential challenges in generalizing the approach?
