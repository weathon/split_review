# Review

## Summary
This paper presents a new evaluation framework for 3D scene generation tasks. The proposed evaluation framework is based on tool use. It first identifies constraints in the given instruction, and then uses different tools to verify the constraint one by one. The authors also present a benchmark that contains 130 instructions with manually annotated constraints and scenes. The evaluation framework is able to achieve higher agreement with human judgements than previous methods.

## Strengths
1. The proposed evaluation framework is sound. It is based on tool use, which is a proper way to tackle complex reasoning tasks.
2. The proposed benchmark is a valuable contribution to the community. It contains 130 instructions with manually annotated constraints and scenes. The instructions are diverse and complex, which are challenging for current methods.
3. The authors conduct extensive experiments to validate the effectiveness of the proposed evaluation framework and benchmark.

## Weaknesses
1. The authors use GPT-4.1 to identify constraints and categorize them into four types. However, it is unclear how the model is prompted to do so. It would be better to include an example of the prompt and the corresponding output.
2. The proposed evaluation framework relies on a set of hand-designed tools, which may introduce bias and are not scalable.
3. The authors use LEGO-EVAL to evaluate Holodeck and show that it can provide feedback for refinement. However, it is unclear how the feedback is provided. Does it require calling the API repeatedly to get the evaluation results of each refinement step? It would be better to include more details about the refinement process.
4. The authors claim that the proposed evaluation framework achieves higher agreement with human judgements than previous methods. However, there is no experiment to validate this claim. It would be better to include a human study to compare the agreement of different evaluation methods.

## Questions
1. How is GPT-4.1 prompted to identify constraints and categorize them into four types?
2. How is the feedback provided by LEGO-EVAL for refinement?
3. Is it possible to include a human study to compare the agreement of different evaluation methods?
