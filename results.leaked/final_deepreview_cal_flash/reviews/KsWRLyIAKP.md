## Summary
This paper introduces a novel formulation of lead-lag detection in financial markets as a temporal link prediction problem on dynamic graphs. The authors construct a custom dataset of 37 stocks and commodities over five years, adapt seven TGNN architectures (JODIE, DySAT, TGAT, TGN, APAN, GraphMixer, GM-TNF) plus an LSTM baseline, and evaluate them across two label scenarios (both positive/negative returns vs. only positive). GraphMixer, a simple MLP-based architecture, consistently achieves the best performance (AP≈0.79). The paper also contributes an ablation study and statistical significance tests.

## Strengths
- **First TGNN formulation for lead-lag detection.** The paper identifies a genuine gap — existing lead-lag work relies on statistical methods or static graphs, and no prior work has cast this as a temporal link prediction problem. This reframing is novel and opens a plausible new direction for the field.
- **Systematic, within-framework comparison of multiple TGNNs.** Seven TGNN architectures are adapted to the same task within the TGL framework, enabling a fair comparison that is often missing in TGNN papers. The consistent finding that GraphMixer outperforms more complex architectures (attention-based, memory-based) across both label scenarios and most feature configurations is a clear, reproducible empirical result.
- **Dual-scenario evaluation with statistical validation.** The paper evaluates both a "positive and negative" and an "only positive" definition of lead-lag relationships, showing consistent model rankings. The Friedman test followed by Conover's post-hoc analysis (Figure 2) confirms that the observed performance differences are statistically significant, lending rigor to the comparative conclusions.

## Weaknesses

### Major
- **Unvalidated ground-truth definition.** The edge labels are entirely defined by a strict heuristic (Eq. 1: both assets' daily returns exceeding 5% in the same direction on consecutive days). The paper explicitly declines to compare against established lead-lag detection methods (Granger causality, cross-correlation, LASSO-based approaches), stating this "lies outside the scope of this study" (Sec. 3.1). The paper also provides no external validation that the predicted edges correspond to economically meaningful relationships (e.g., supply-chain links, sector dependencies, or measurable trading outcomes). Without such validation, the benchmark task may not reflect the phenomenon the paper claims to address, and the models may be learning to predict a heuristic with no proven connection to real lead-lag dynamics. This is the most significant limitation of the paper.

- **The LSTM baseline is too weak to support the claim that "graph structure is essential."** The sequential baseline (Sec. 3.3) processes historical *edge features* (description embeddings) through an LSTM/GRU encoder, rather than receiving the raw return time series of the two assets. Since the label is defined entirely by return movements on consecutive days, and the baseline never sees price or return data, its near-random AP (~0.51) is expected. A proper time-series baseline — an LSTM or MLP that directly receives the return histories of the candidate asset pair — would be needed to measure the actual value added by graph structure. The paper's conclusion that TGNNs outperform "the sequential baseline" conflates "graph structure matters" with "a model that receives only static description embeddings cannot predict price-movement-based labels."

- **Potential static shortcut not investigated.** The ablation study (Table 3) shows that for 5 out of 7 model configurations, the best performance is achieved using only static description embeddings — adding temporal features (prices, financial indicators, sentiment) degrades performance. The paper's explanation ("temporal links reflect price fluctuations rather than exact price values, rendering explicit price features largely redundant") is plausible but not tested. A more concerning alternative exists: the description embeddings (generated by GPT-4o and embedded via MiniLM) likely encode sector or industry membership information, which could serve as a static shortcut. If assets in the same sector tend to co-move and trigger the Eq. 1 condition together, a model could achieve high AP simply by learning sector co-membership patterns rather than temporal dynamics. The paper provides no analysis to rule this out (e.g., training a simple MLP on description embeddings alone without graph structure to establish the shortcut-achievable upper bound).

### Minor
- **Small dataset with heuristic selection.** The dataset has only 37 nodes (29 companies + 8 commodities), selected via a heuristic approach covering five broad sectors. While sufficient for a proof-of-concept, this is a very small temporal graph, and the selection criteria limit reproducibility and generalizability. The paper's stated aim of introducing a "benchmark task for TGNNs" is undercut by this scale.
- **No analysis of edge dynamics or stationarity.** The ablation study's finding that static features work well suggests the edges may be largely stationary (i.e., the same asset pairs frequently trigger the Eq. 1 condition). The paper does not analyze edge turnover rates, temporal sparsity patterns, or performance under different market regimes (e.g., COVID vs. normal periods), which would be important for a temporal graph benchmark.

## Suggestions
1. **Run an external validation study** — even a simple analysis showing that predicted lead-lag edges cluster among known sector relationships (e.g., energy assets leading other energy assets) or correlate with trading strategy returns would substantially strengthen the paper's claim that the benchmark captures economically meaningful patterns.
2. **Diagnose the static shortcut** — train a non-graph classifier on description embeddings alone (no temporal structure) to establish a baseline for how much performance is achievable via sector co-membership alone. If this achieves AP > 0.7, the benchmark needs redesigning; if not, the temporal graph structure is clearly contributing.
3. **Add a fair return-based baseline** — an LSTM that takes as input the raw return sequences of both assets over the past k days. This would credibly measure how much the graph structure adds beyond what a competent time-series model can extract from the defining signal.
4. **Analyze edge dynamics** — report edge persistence rates across time windows to quantify how dynamic the graph actually is. If most edges recur between the same pairs, the paper should acknowledge this limits the temporal reasoning demands of the benchmark.
