## Merged Review

### Summary

The paper introduces DivScene, a large-scale synthetic dataset of 4,614 scenes across 81 scene types and over 22,000 object types, generated using Holodeck and Objaverse, and a baseline method NatVLM that fine-tunes Idefics2 (8B) with Chain-of-Thought (CoT) explanation traces on shortest-path trajectories. Experiments on the proposed benchmark show NatVLM outperforms zero-shot VLMs and GPT-4o by over 20% in success rate, and demonstrates zero-shot transfer to existing AI2Thor-based benchmarks. Reviewers note the dataset’s diversity as a strength but raise concerns about missing comparisons, limited real-world validation, and the novelty of the method.

### Strengths

- **Dataset contribution**: DivScene provides 4,614 scenes across 81 scene types and over 22,000 object types, substantially expanding the scope for studying generalizable open-vocabulary object navigation (Reviewers 1, 2, 4). It serves as a large-scale evaluation benchmark for this task (Reviewer 4).
- **Method and analysis**: NatVLM fine-tuned with CoT explanation traces achieves strong performance, outperforming GPT-4o by over 20% success rate (Reviewer 1). The paper demonstrates that CoT traces are important for action prediction, offering useful insight (Reviewers 1, 3).
- **Clarity and organization**: The paper is well-organized, easy to follow, with clear motivation and good references to related work (Reviewers 1, 2, 4).
- **Experimental rigor**: Includes comparisons to both open-source and closed-source baselines, ablation studies, and postprocessing for data quality (Reviewers 1, 3). Code and data examples are provided for open-sourced API evaluation (Reviewer 3).
- **Problem significance**: The open-vocabulary variant of closed-vocab object navigation is a reasonably important problem (Reviewer 2).

### Weaknesses

- **Overclaim of novelty**: One reviewer (Reviewer 3, score 5) strongly criticized the claim of being “the first to build an LVLM-based navigational agent”, noting that prior work NaVid already introduced an LVLM-based navigation agent and deployed it in real-world scenarios. The current work operates entirely in synthetic scenes, limiting novelty and practical significance. Other reviewers did not raise this point.
- **Missing comparisons with state-of-the-art methods** (multiple reviewers, high agreement):
  - As a method, the paper lacks comparisons to SOTA closed-vocab object navigation methods on ProcTHOR or MP3D in Habitat (Reviewer 2). Only VLM-based baselines are compared, which are not SOTA on existing benchmarks.
  - Should compare with state-of-the-art open-vocabulary object navigation methods (e.g., [1,2,3] as referenced by Reviewer 4) to validate claims about domain gap and captioning model limitations.
  - Only a single model (Idefics2 8B) is fine-tuned; additional baselines (RL-based, imitation learning-based) and studies of different LLM backbones/LVLM pre-trained weights are needed (Reviewers 3, 4).
  - Zero-shot transfer experiments are not convincing because iTHOR, ProcTHOR, and AI2-THOR share very similar visual styles, resulting in a marginal domain gap (Reviewer 3). In-domain experiments on iTHOR and ProcTHOR with NatVLM are required.
- **Limited real-world applicability and generalization**:
  - Reliance on synthetic platforms (AI2THOR) limits real-world applicability; experiments on real-world datasets or simulators (ARKit, MP3D) are needed to test generalization (Reviewers 1, 2). Discussion of challenges in transferring synthetic-trained models to real-world settings is missing (Reviewer 1).
  - Zero-shot generalization is only evaluated on other AI2Thor-based benchmarks (ProcTHOR, iTHOR) that share rendering style; performance on other simulators is absent (Reviewer 2).
  - The dataset’s synthetic scenes generated via Holodeck lack analysis of how well they approximate real-world environments; comparison with curated datasets such as Structure3D or ARKit would help assess trustworthiness (Reviewer 2).
- **Lack of failure analysis and task hardness breakdown**: No breakdown of failures (e.g., missing object vs. navigation failure) or explanation of why open-vocab is harder than closed-vocab, which would tie into 3D object detection literature (Reviewer 2).
- **Insufficient dataset details and quality analysis**:
  - How objects are arranged in scenes and how their relationships are ensured to be reasonable is not clarified (Reviewer 4).
  - The definition of scene type and criteria for choosing the 81 types are not explained (Reviewer 4).
  - Proper comparison with existing navigation datasets (domain, quantity, quality) is missing; explicit numbers of scenes, object categories, and trajectory complexity in prior datasets should be stated (Reviewer 3).
- **Scene complexity analysis absent**: No evaluation of how performance varies with scene complexity (cluttered vs. minimal scenes, varying occlusion); a quantitative complexity measure is missing (Reviewer 1).
- **Scalability of CoT traces**: Manual creation of CoT explanation traces introduces a labor-intensive bottleneck, limiting scalability and automation for new scenarios or larger datasets (Reviewer 1).
- **Computational cost unaddressed**: Training and deployment costs (hardware, energy, training/inference time) are not reported; comparison with baselines on these metrics is missing (Reviewer 1).
- **Limited technical contribution** (Reviewer 3, score 5): Sections 3–5 describe a standard pipeline for collecting navigation trajectories; the paper should more clearly delineate its unique contributions.
- **Dataset size not justified**: No experiment training on subsets of scenes (e.g., 1%, 10%, 50%) to check if performance saturates with 4k scenes (Reviewer 2).
- **Insufficient literature review**: The paper does not adequately cover prior VLM-based navigation agents (e.g., NaVid, VLM-Social-Nav), leaving a gap in positioning this work (Reviewer 3).
- **Typo**: Line 259 uses “validation” but should be “test” (Reviewer 4).
