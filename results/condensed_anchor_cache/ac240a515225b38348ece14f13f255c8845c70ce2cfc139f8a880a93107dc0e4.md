## Merged Review

### Summary
The paper proposes MoRE (Mixture of Low-Rank Experts), a parameter-efficient fine-tuning method for multi-task scenarios. Instead of using a separate LoRA module per task, MoRE employs a single shared low-rank matrix and an adaptive gating mechanism (rank selector) to select a cumulative subset of its ranks as task-specific experts. Experiments are conducted on GLUE benchmarks with LLaMA and other LLMs, showing consistent improvements over baseline LoRA variants.

### Strengths
- The idea of reusing a single low-rank matrix and using a gating function to select portions of it as distinct experts is interesting and provides a novel approach to multi-task PEFT. (R1, R2, R4)
- Experimental results are promising, with MoRE consistently outperforming baselines across most datasets, particularly in the LLaMA setting. (R1, R2, R3)
- The paper is well-written and easy to follow, despite some typos. (R2, R3)
- The topic of multi-task PEFT is important and well-motivated. (R2)
- MoRE integrates multiple low-rank experts into a single adaptive framework with an adaptive rank selector, providing flexibility and efficiency for multi-task learning without requiring separate modules per task. (R4)

### Weaknesses
1. **Limited novelty over existing mixture-of-LoRA methods**: Several reviewers found the contribution marginal. Reviewer 1 notes that MoRE can be interpreted as a specific case within frameworks like MixLoRA and MOELoRA, where each expert has rank 1 and selection is constrained to be cumulative (1:k) rather than arbitrary subsets. Reviewer 3 states there is no novelty compared to other MoE LoRA methods. (R1, R3)
2. **Inference cost and inability to merge**: Unlike standard LoRA, MoRE cannot merge into the original model during inference, increasing memory usage and preventing Transformer inference optimization. Reviewer 4 asks for clarification on whether merging is possible or for strategies to mitigate this increased inference complexity. (R3, R4)
3. **Scalability constraints**: The number of experts is bounded by the maximum rank of the shared low-rank matrix, limiting scalability when tasks outnumber the rank. Reviewer 1 asks how the method handles scenarios where the number of tasks significantly exceeds the maximum rank (Q1). Additionally, the selection of the maximum rank is not clearly explained (manual or automatic?) and needs details. (R1, R4)
4. **Concerns about shared low-rank matrix for heterogeneous tasks**: The design forces the first few rows/columns of the adapter matrix to be reused across tasks. This may work for correlated tasks (e.g., GLUE) but could become a bottleneck for tasks with highly distinct feature-label mappings. Reviewer 1 questions if the method fails when tasks have no shared information (Q2). (R1)
5. **Marginal performance improvements and lack of statistical significance**: The performance gain is marginal, and MoRE does not achieve the best results on several tasks (SST-2, MRPC, ARC). Statistical significance tests are missing to substantiate the claimed improvements. (R4)
6. **Insufficient evaluation scope**: The method is tested only on GLUE benchmarks, which focus on NLP tasks and do not explore reasoning or knowledge capabilities (e.g., MMLU, code, math). Reviewer 3 asks for evaluation on such benchmarks (Q1). Additionally, only LLaMA is tested; other architectures like Mistral-7B or Gemma2 are missing. (R2, R3, R4)
7. **Lack of analysis on rank selection**: There is no detailed analysis of how the rank selector determines ranks for each task, nor which tasks consistently require higher/lower ranks and why. (R4)
8. **Only tested with a fixed LoRA rank of 8**: The experiments only consider rank 8; testing with a range of ranks would provide a more comprehensive view of performance trade-offs. (R4)
9. **Insufficient exploration of multi-task scaling**: The evaluation does not test the effect of varying the number of concurrent tasks in a multi-task learning setting; scalability and robustness remain unexplored. (R4)
10. **Need for learning rate investigation**: The authors claim a smaller learning rate benefits MoRE training, but no experiments with different learning rates are provided to support this claim. (R2)
11. **Minor presentation issues**: There are typos; e.g., Line 161 has an incomplete sentence, and Line 243 incorrectly refers to argmax in eq(3) instead of eq(4). (R2)
12. **Justification of cumulative selection (1:k)**: Reviewer 1 questions why selection is enforced as 1:k rather than allowing an arbitrary subset of ranks from 1 to r_max (Q3); this design choice is not justified. (R1)
