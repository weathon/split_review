## Merged Review

### Summary
This paper introduces ToolDial, a dataset of 11,111 multi-turn dialogues (avg. 8.95 turns) for Tool-Augmented Language Models (TALMs), based on RapidAPI. Dialogues include 16 user/system actions and simulate scenarios where the system must request missing information or call additional APIs. An API graph is generated to represent input/output compatibility between APIs. The authors evaluate language models on action prediction, dialogue state tracking (DST), and API call correctness. One reviewer was more positive (score 8), emphasizing timeliness and multi-task evaluation; the other two rated 6, raising concerns about dataset construction bias, novelty, evaluation reliability, and lack of detailed error analysis.

### Strengths
- Moving to multi-turn tool calling is new and timely for the TALM literature (Reviewer 1, Reviewer 2).
- The benchmark supports three subtasks (action prediction, DST, API call correctness) providing a more comprehensive evaluation than a single metric (Reviewer 1).
- The dataset addresses a resource gap for TALMs, providing nuanced multi-turn interactions more reflective of real-world use (Reviewer 3).
- Dataset generation uses an API graph with GPT models, offering a scalable approach that may inspire future methodologies (Reviewer 3).
- Evaluation across multiple models provides actionable insights into TALM challenges in multi-turn, tool-augmented interactions (Reviewer 3).
- Appropriate citations and discussions positioning the work; the benchmark is timely compared to older datasets (MWOZ, SGD) and distinguishes itself from API-bank by highlighting many-turn interactions (Reviewer 2).

### Weaknesses
- **Reliance on GPT-generated dialogues and potential data artifacts**: The dataset is constructed using GPT-4o-mini, which may introduce bias and synthetic errors that undermine realism (Reviewers 1, 3). Although human evaluation is performed, a blind test prepared by human authors would also be helpful (Reviewer 1).
- **Lack of detailed error analysis**: The paper does not provide a breakdown of error types in DST, action prediction, and response generation beyond overall accuracy. Missing analysis for slot filling, value extraction, and API parameter selection (Reviewer 3). Qualitative examples of failures and successful completions are also requested (Reviewer 1).
- **Evaluation reliability concerns**: The upper bound results (with ground truth) are lower than expected, and TD-Llama (finetuned on Llama3-8b) scores lower than GPT-3.5-turbo, which appears counterintuitive (Reviewer 3). The setting for GPT-based experiments (zero-shot vs. in-context learning) is not specified, and details on number of test samples used in Tables 4 and 5 (the test set has 1,166 samples) are missing – integer scores are unusual and calculation methods should be clarified (Reviewer 1, 3). The concept of “correctness” (session-level? criteria?) needs clearer definition (Reviewer 3).
- **Missing baselines and comparisons**: Non-LLM baselines (e.g., BERT/T5-based DST/action recognition) should be included for completeness (Reviewer 1). Vanilla LLaMA results are missing from Table 5 (Reviewer 1). A comparison with other works using tool graphs, such as “Taskbench: Benchmarking Large Language Models for Task Automation,” is needed (Reviewer 3). CodeLLaMa benchmarking is suggested (Reviewer 1).
- **Insufficient dataset details**: More description of conversation complexity, domains of APIs, types of arguments, and differences from SGD is required (Reviewer 2). The language of the dataset should be stated (Reviewer 1). The dataset construction section is hard to understand; a running example would clarify (Reviewer 1). In Figure 2, the agent response contains symbolic terms (seasonId, tournamentId); the reason for this design and whether it makes interactions less natural should be explained (Reviewer 2).
- **Preliminary experiments**: The experiments are still preliminary; more experimental details, another open-source LLM, chain-of-thought prompting (e.g., arXiv:2403.04656) would strengthen the work (Reviewer 1). Standard metrics like goal accuracy (task completion) should be included (Reviewer 1, citing ACL 2022). Reporting results with at least three significant digits is needed (Reviewer 1). An ablation study on whether DST or action prediction are essential to achieving high correctness is requested (Reviewer 3).
- **Novelty and alignment concerns**: One reviewer questioned whether the proposed methodologies for dataset creation are adequately novel or aligned with ICLR values; the authors are asked to provide more evidence (Reviewer 2). Missing related work references include Toolformer, ToolLLM, and a survey on DST (Reviewer 1).
- **Other requests**: Release predictions from GPT runs for reproducibility (Reviewer 1). Condense the paper and move essential information from the appendix to the main paper (Reviewer 2). Explain why GPT-4o-mini performs better without ground truth in Table 4 (Reviewer 1).
