## Merged Review

### Summary

This paper presents an empirical analysis of the SWE-Bench dataset, identifying critical issues such as solution leakage (32.67% of successful patches had solutions directly in the issue) and weak test cases (31.08% of passed patches are suspicious). Based on these findings, the authors propose SWE-Bench+, which filters out issues containing solutions and uses only issues created after LLM training cutoff dates to mitigate data leakage. Evaluation on SWE-Bench+ shows a significant drop in resolution rates for models like SWE-Agent+GPT-4 (from 12.47% to 3.97% on refined SWE-Bench, to 0.55% on SWE-Bench+). The paper also provides a detailed classification of imprecise answers and includes qualitative examples. One reviewer (score 6) praised the thoroughness of the analysis, while the other three reviewers (score 3) found the proposed benchmark's contribution limited and the experiments insufficient.

### Strengths

- Clear motivation and well-articulated rationale for addressing issues in SWE-Bench.
- Thorough empirical analysis of SWE-Bench, with detailed classification and discussion of various imprecise answers and data quality issues (e.g., solution leakage, weak test cases, data leakage).
- Strong quantitative evidence demonstrating that stricter criteria drastically lower LLM resolution rates, underscoring the need for more robust benchmarks.
- Qualitative examples provided to illustrate problems.
- Writing is clear and easy to follow.

### Weaknesses

1. **Weak test case problem remains unaddressed.** SWE-Bench+ only filters solution leakage and uses post-cutoff issues, but does not improve the quality or strength of test cases. There is no definition of test strength, no calculation of code line/branch coverage on gold solutions, and no stronger test suites. This limits the benchmark's rigor. (R1, R2, R3, R4)
2. **Limited contribution of the new benchmark.** SWE-Bench+ differs from SWE-Bench only by removing answer-containing issues and updating the cutoff date. It does not tackle the weak test cases issue, so its claim of being a "more rigorous evaluation dataset" is questionable. The benchmark's scope is narrow, lacking broader comparisons with other code generation benchmarks like HumanEval or EvalPlus. (R1, R4)
3. **Data leakage solution is temporary.** SWE-Bench+ will become obsolete as LLMs evolve (e.g., with new models having later cutoff dates), requiring frequent manual updates. This is not a long-term solution to the data leakage problem. (R3)
4. **Scalability concerns.** The manual labeling process for excluding solution leaks is resource-intensive and may not scale to larger benchmarks. (R2)
5. **Insufficient experiments for a new benchmark.** Only model performance and cost are reported. Missing analyses include: comparison with other benchmarks (HumanEval, EvalPlus), ablation studies, analysis of why models fail or pass, and investigation of how models pass with incorrect implementations (e.g., Figure 4 example). (R1, R4)
6. **Presentation issues.** Experimental results are listed in paragraph form instead of a table, making data interpretation difficult. There is no basic introduction to the model methods or detailed experimental configuration settings. (R1)
7. **Specific open questions from reviewers** that overlap with criticisms:
   - How do models pass test cases with incorrect implementations (Figure 4)? (R1)
   - How does SWE-Bench+ ensure that test cases are strong, and what strategies exist to improve test case robustness? (R2, R3, R4)
   - Can SWE-Bench+ be expanded beyond GitHub issues? (R4)
   - Is it possible to leverage LLMs to automatically identify solution leaks and low-quality instances? (R2)
   - How will SWE-Bench+ evolve automatically as LLMs advance? (R3)
   - What are the code line/branch coverage statistics of the test suites in gold solutions? (R4)

**Contrast among reviewers:** One reviewer (score 6) strongly appreciated the thorough empirical analysis and clear motivation, but still noted the weak test case issue and scalability concerns. The other three reviewers (score 3) were more critical, emphasizing the limited scope of the solution, insufficient experiments, and presentation flaws. All reviewers agree on the value of the problem but disagree on the sufficiency of the proposed solution.
