## Merged Review

### Summary
The paper introduces Robust Gymnasium, a unified modular benchmark for robust reinforcement learning that supports disruptions across agents' observed state and reward, actions, and the environment. It includes over sixty diverse task environments spanning control, robotics, safe RL, and multi-agent RL. The paper also benchmarks existing standard and robust RL algorithms (e.g., SAC, PPO, RSC, OMPO, ALTA, DBC, PCRPO, CRPO, IPPO) within this framework, revealing significant deficiencies in current algorithms.

### Strengths
- Broad range of tasks (60+) across diverse domains (control, robotics, safe RL, multi-agent RL) (R1, R3, R4).
- Highly modular design allows flexible construction of tasks and easy integration with existing environments (R1).
- Supports different disruption types: random disturbances, adversarial attacks, internal dynamic shifts, external disturbances (R1).
- User-friendly with clear documentation and examples (R1).
- Clear presentation: Figure 1 and Figure 2 effectively summarize environments, agents, disruptions, and environment flow (R2, R3).
- Problem motivation is solid; the benchmark addresses a significant gap in robust RL evaluation (R2, R4).
- Novelty: no existing benchmark is as extensive for robust RL; offers comprehensive coverage of robustness types (R2, R4).
- Experiments demonstrate that current algorithms fail, highlighting the benchmark's necessity (R2).
- Two-setting evaluation (training and testing) is crucial for showing the importance of robustness (R2).
- The paper is well-written (R4).

### Weaknesses
- **Clarity / Organization**: Sections 2.1, 2.2, and 3.2 are wordy and redundant, repeating information without providing needed specificity (R2). Combining them would improve clarity (R2).
- **Missing Details on Disruptors / Action Spaces**:
  - It is unclear what "random noise on an environment disruptor" means and how "the environment-disruptor alters external conditions" (R2).
  - Section 3.2 lacks information on state-action spaces and how disruptors affect them for each environment; clustering environments by action space similarities would help (R2).
  - No explanation why some tasks do not support every disruption type (L213) (R2, Q2).
  - No guidelines for choosing disturbance parameters; e.g., in Section 4.3, why attacks follow a Gaussian rather than Uniform distribution? (R2).
- **Adversarial Disturbance via LLM**:
  - The use of an LLM at every environment step is computationally wasteful and limits usability; simpler adversarial strategies should be highlighted (R2).
  - The framing focuses too much on LLMs rather than general adversarial setups; the paper should emphasize the adversarial MDP formulation with LLM as just one example (R4).
  - It is unclear whether standard adversarial disruptors are already implemented or whether users must implement them (R2, Q4).
  - It is unclear whether the LLM requires the user to run a local model (R2, Q5).
- **Missing Robustness Metrics**: The benchmark lacks metrics beyond cost/reward to measure robustness (e.g., reliability metrics) (R2).
- **Missing Baselines**: M2TD3 (SOTA for robustness under model misspecification) and RARL are not included; their inclusion would strengthen coverage (R4).
- **Uncertainty Set Construction**: It is unclear how uncertainty sets can be built with the benchmark; examples (as in the M2TD3 paper) are needed for practical use (R4).
- **Limited Task Diversity**: Environments are primarily robotics-based; the benchmark would benefit from tasks like autonomous driving or drone simulations (R4). (R4) also notes: Reviewer 3 finds the benchmark of limited significance because existing benchmarks already allow adding disturbances; the technical contribution is mainly a wrapper, leading this reviewer to recommend rejection (R3).
- **Experimental Limitations**:
  - It is unclear how many seeds were used; given high variance in RL, more robust evaluation (e.g., many seeds) is needed (R2).
  - Not all tasks are evaluated with all baselines; running one algorithm on all tasks to verify learnability would strengthen the benchmark's utility (R2). (R3 also questions if some tasks become unsolvable due to perturbations, Q6.)
- **Overstated Uniqueness**: The claim of being "the first unified benchmark for robust RL" is overstated given RRLS and other benchmarks that allow robustness evaluations (R3).
- **Missing Discussion of Limitations**: The paper does not discuss limitations of the current implementation or how they might be addressed in future work (R1, R3).
- **Missing Citations**: The disruptors presented in Section 3.2 should cite prior work where they were used (R3).
- **Sensitivity / Data Dependence**: Effectiveness of some robust RL algorithms may rely on quality/quantity of offline demonstration data (R1). Hyperparameter tuning may not be straightforward (R1).
- **Handling of Partially Observable Environments / High-Dimensional Spaces**: Unclear whether the benchmark can evaluate robustness in POMDPs or with high-dimensional state/continuous action spaces (R1, Q1, Q6).
- **Safety Gym**: Unclear how disturbances interact with constraints in Safe RL tasks (R2, Q3).
- **Minor Issues**: Language errors (e.g., "In Disrupted MDP" missing "a"), formatting (space before "environment-disruptor" L132); first mention of "disrupted MDP" should be bolded (R2, R4).
