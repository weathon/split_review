## Merged Review

### Summary
MELODI is a novel Transformer-based memory architecture for efficient long document processing using short context windows. It employs a hierarchical compression scheme: short-term memory uses multi-layer recurrent compression across context windows, with summary branching to separate tokens for next-layer and next-window communication; long-term memory performs further compression in a single middle layer and aggregates compressed key-value pairs from the entire history via a FIFO queue and a gating mechanism. The overall “sandwich” structure places the long-term layer between multiple short-term layers. Experiments show MELODI outperforms baselines (Memorizing Transformer, Transformer XL, Block Recurrent Transformer) on perplexity on three datasets while reducing memory footprint by 8×. Ablation studies validate the complementary roles of short-term and long-term memory and design choices like memory sizes, window size, and summary branching.

### Strengths
- The hierarchical integration of short-term and long-term memory is a straightforward yet effective strategy, well-motivated and clearly explained with helpful figures.
- The architecture is original, combining and extending ideas from LSTMs, Transformer XL, and Memorizing Transformer. The summary branching mechanism with distinct linear token mixers for different compression flows is a novel contribution.
- Comprehensive experimental results on three long-context datasets (perplexity) demonstrate that MELODI outperforms several strong baselines while using 8× less memory.
- Detailed ablation studies analyze the impact of short-term/long-term memory sizes, long-term coverage, context window size, number of layers, and summary branching, providing strong evidence for design choices.
- The paper is well-written, clear, and easy to follow.

### Weaknesses
- **Limited evaluation beyond perplexity**: Experiments focus almost exclusively on perplexity; no results on long-context benchmarks (e.g., LongBench, Needle-in-a-Haystack) or downstream tasks (e.g., summarization, QA). This makes it harder to assess practical benefits in real applications.
- **Lack of background on memory compression integration**: Without prior knowledge, it is unclear how the memory network works with LLMs. A preliminary section on recent advances in memory compression would help (Reviewer 1). This also relates to Reviewer 1’s lower soundness (2) and confidence (2).
- **Old baselines and missing recent comparisons**: Baselines are old (e.g., Transformer XL, Memorizing Transformer). Several recently proposed long-context methods are not discussed or compared, such as Wang et al. (2024) “Augmenting language models with long-term memory” and YOCO (Sun et al., 2024). This weakens the evaluation’s timeliness.
- **Limited exploration of longer context windows**: The majority of experiments use a 512-token window. Only Figure 5 (briefly) gives perplexity for 12k-token contexts (192×64). There is no systematic study with 2k, 4k, or 8k windows, raising questions about scalability to very long sequences (Reviewer 2). Reviewer 2 suggests making Figure 5 more prominent.
- **Lack of fine-tuning / pre-trained model adaptation**: MELODI and baselines are trained from scratch. The paper does not explore fine-tuning on a pre-trained LLM, which is the typical use case for large models. Adaptation techniques like LoRA are mentioned only as future work.
- **Insufficient analysis of computational efficiency**: Memory footprint reduction is shown, but there is no comparison of training/inference times or computational complexity (e.g., FLOPs). This makes it hard to judge real-world latency implications.
- **Unclear training and generation behavior**: The recurrent/chunk-wise nature may impede efficient parallel training—this challenge is not discussed. Moreover, it is unclear how the chunk-wise approach affects token-wise generation (a key behavior in GPT-like LLMs). For example, does summary generation occur only after each chunk is complete?
- **Model size and scalability**: The model is relatively small (exact parameter count not specified; appears in the range of 100-200M?), raising questions about scaling to 1B+ parameters. Scalability to larger models is not addressed.
- **Experimental details missing**: How to choose the number of long-term memory slots M? How is memory footprint precisely evaluated? These details are lacking (Reviewer 4).
- **Single long-term layer may be insufficient**: Figure 8 shows that perplexity continues to improve as the number of long-term layers increases, yet the paper uses only one. This suggests a single layer may not be optimal, and experiments with more layers are needed (Reviewer 4).
- **Code not shared**: No code is provided for verification of implementation (Reviewer 1). This reduces reproducibility.
