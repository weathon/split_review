- Scores: 5, 6, 8

## Merged Review

### Summary
The paper proposes RuAG, a framework that automatically distills large volumes of offline data into first-order logic rules using Monte Carlo Tree Search (MCTS). LLMs are used to define body and target predicates, then rules are learned from data, translated into natural language, and injected into LLM prompts for downstream reasoning. The method is evaluated on relation extraction, anomaly detection, a multi-agent game, and an industrial task. Results show that providing learned rules in-context can outperform standard ICL, RAG, and some baselines like HtT, and is more computationally efficient because API calls occur only during rule construction.

### Strengths
- Integrates rule-based augmentation with generation models, leveraging rules learned from data (Reviewer 1).
- The idea of using LLMs for “feature extraction” to define predicates is interesting and novel (Reviewer 2).
- Empirical results show that for some use cases, abstract rules can improve performance (Reviewer 2). The method is tested on a wide array of tasks and shows improvement over strong baselines (Reviewer 3).
- RuAG offers a scalable solution for integrating extensive domain knowledge into LLMs, improving upon RAG or SFT in some settings (Reviewer 3).
- The framework is computationally efficient: calls to API models occur only once during logic rule construction (Reviewer 3).

### Weaknesses
- **Clarity of Section 3.1 (LLM-based Logic Rule Search):** Multiple reviewers found this section difficult to understand. Specific unresolved points include:
  - What do initial predicates look like across the three different datasets? (Reviewer 1)
  - How does the LLM eliminate impossible body predicates? Prompt examples are needed. (Reviewers 1, 3)
  - How does the LLM propose new target predicates? Prompt examples are needed. (Reviewers 1, 3)
  - Line 190 says “initial the features as the body predicates” without explaining what the features are or giving intuition. (Reviewer 2)
  - Figure 3 is a mix of text and emoji without proper explanation, making it difficult to understand the steps. (Reviewer 2)
  - The HtT baseline is not explained properly. (Reviewer 2)
  - Line 285: “we leveraged the LLM to filter out 15% of the relationships that were unlikely to serve as valid predicates” is unclear. (Reviewer 2)
  - Lines 189 onwards contain repeated sentences (copy-paste errors). (Reviewers 2, 3)
- **Scoping and generality:** It is unclear when this method is useful and when it is not. The method assumes input of N features with some feature description, not raw data like a sequence of words. The tasks chosen are diverse but rare, and the overall generality remains unclear. For instance, many problems (e.g., face recognition, cat recognition) are hard to express by rules. (Reviewer 2)
- **Applicability to real-world RAG:** The rules generated seem suited primarily for deterministic target predicates (classification tasks), not for dynamic, knowledge-based decision-making. The example in Figure 2 (weather prediction) does not reflect how real-world RAG decisions are made. It is not discussed how the approach would extend to real-world scenarios. (Reviewer 1)
- **Performance of rules alone:** The paper does not adequately address the limitations of relying solely on rules, especially when rules might be brittle or incomplete. There is no discussion of cases where test scenarios are more complex and rules may not generalize. (Reviewer 1)
- **Unclear if LLM looks at actual data:** In Section 3.1 it is not clear if the LLM considers the actual values of features in the data, or only the schema/feature descriptions. The MCTS applies rules on data to check performance, but the LLM might not be used to find patterns in the data, which could limit the approach. (Reviewer 2)
- **Experimental evaluation issues:**
  - Comparisons in Sections 4.1 and 4.2 are between models with very different capabilities (GPT-4 vs CNN, BiLSTM, BERT). Baselines should compare the same model using different in-context methods. (Reviewer 2)
  - The main claim that using rules in-context is better than ICL and RAG is not supported in Sections 4.1 and 4.2; ICL/RAG baselines only appear in Section 4.3. The paper needs more detail on what the ICL and RAG baselines in Section 4.3 actually involve. (Reviewer 2)
  - Ablation studies in Table 5 could include RAG or SFT on open-source LLMs; currently only COT is compared, which does not incorporate external knowledge. (Reviewer 3)
- **Experimental details lacking:** Very little detail is given on the features, labels, target predicates, and body predicates for each experiment. The table provided is insufficient for understanding the tasks. (Reviewer 2)
- **Questions that overlap with criticisms or missing experiments:**
  - How was the data partitioned for the cooperative game (train/validation/test)? (Reviewer 1)
  - Where do the confidences in Table 4 come from? (Reviewer 2)
  - Reviewer 1’s question about using only the train split to construct rules and testing on the test split (though expected, it highlights the method’s dependence on labeled data).
  - Reviewer 1’s question about adapting to real-world RAG scenarios with dynamic knowledge.

*Note:* Reviewer 3 was more positive overall (score 8) than Reviewers 1 and 2 (scores 5 and 6). Reviewers 1 and 2 raised significant concerns about clarity, scoping, and evaluation, while Reviewer 3 emphasized scalability and efficiency.
