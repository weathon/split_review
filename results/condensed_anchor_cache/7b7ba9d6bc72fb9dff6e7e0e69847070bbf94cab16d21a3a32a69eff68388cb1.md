## Merged Review

### Summary
The paper proposes HiP, a training-free method that reduces attention time complexity to \(O(T \log T)\) and space complexity to \(O(T)\) by exploiting “attention locality” (tokens close together have similar scores). For each query, a tree-search-like iterative refinement algorithm estimates the top-\(k\) key tokens. Additionally, KV cache offloading stores only \(O(\log T)\) tokens on GPU. Experiments on LongBench and other benchmarks show reduced prefill/decode latency and memory usage with minimal performance degradation. Reviewer scores are 6, 8, 5, 6; Reviewer 2 (score 8) is notably more positive, while Reviewer 3 (score 5) is more critical.

### Strengths
- Training‑free, allowing drop‑in application to pre‑trained LLMs without retraining.
- Reduces attention complexity from quadratic to log‑linear, enabling longer contexts.
- KV cache offloading effectively reduces GPU memory usage.
- Comprehensive experimental evaluation across different hardware (including RTX 4090), metrics, and comparisons with multiple FlashAttention variants.
- Provides theoretical analysis (including an informal theorem) showing better performance than random pruning.
- The iterative refinement dynamic search for top‑\(k\) tokens is interesting and novel.
- Code and implementation released.
- Extensive ablation studies are provided in the appendix.

### Weaknesses
- **Attention locality assumption**: The degree and robustness of “attention locality” across different model sizes, pre‑training datasets, and tasks are not sufficiently quantified. Reviewer 4 requests a more detailed analysis and quantification. Reviewer 3 notes potential violations when long‑range dependencies are critical; performance on such tasks is unclear.
- **Segment‑based design choice**: The algorithm divides the sequence into \(k\) segments and selects one token per segment, forcing top‑\(k\) tokens to be distributed and preventing concentration on important regions. The rationale for this design is not justified (Reviewer 1).
- **Limited evaluation scope**: Evaluation is restricted to MMLU and LongBench. Reviewer 2 requests broader benchmarks sensitive to long‑range reasoning and complex contextual understanding. Reviewer 3 also calls for tasks that test reasoning over distant parts of the input.
- **Missing model‑architecture diversity**: Experiments need to cover non‑Llama architectures (e.g., Gemma, Mistral) and Gemma 2’s sliding‑window attention (Reviewer 2). Reviewer 3 asks whether HiP applies to other Transformer architectures.
- **Scalability not demonstrated**: Experiments only reach 128k sequence length on 8B‑parameter models. Reviewer 4 requires experiments with significantly longer sequences (1M+ tokens) and much larger models (100B+ parameters) to prove scalability.
- **Pruning overhead not analyzed**: The iterative pruning process may introduce overhead, especially in the prefill stage. A breakdown of latency contributions from pruning versus actual attention computation is missing (Reviewer 4).
- **Hardware‑specific optimization**: Implementation and autotuning are tailored for specific GPUs (e.g., RTX 4090) with insufficient detail for portability to other accelerators. The autotuning mechanism is unclear (Reviewer 3).
- **Static sparsity pattern**: The method enforces the same sparsity across all rows of the attention matrix. Reviewer 3 suggests exploring dynamic sparsity mechanisms (e.g., based on attention weight magnitude or token importance).
- **Alignment and safety not addressed**: HiP alters the attention mechanism, but potential LLM alignment issues, safety, and robustness in sensitive applications are not investigated (Reviewer 3).
- **Missing comparison with related iterative‑refinement methods**: Reviewer 1 notes that other literature uses iterative refinement for dynamic attention efficiency; no comparison is provided.
- **Chunk‑size trade‑off unexplored**: The effect of chunk size choice on accuracy vs. efficiency is not analyzed (Reviewer 3).
- **Integration with other techniques**: How HiP integrates with quantization or model pruning is not explored (Reviewer 3).
