## Merged Review

### Summary
The paper proposes MGB, a unified benchmark for multiplex graphs comprising ten baseline models (GCN, GAT, HAN, etc.), eleven datasets (seven existing plus four new ones enriched with textual features via BERT), and four tasks (node classification, clustering, edge prediction, edge classification). It claims to address small-scale datasets, lack of representative features, and missing edge-level evaluations. Experiments show performance saturation on old datasets and large performance drops on new datasets, with end-to-end methods sometimes outperforming self-supervised ones. Reviewers acknowledge the effort but raise major concerns about missing related work, incremental contributions, flawed benchmarking methodology, and limited novelty.

### Strengths
- The data, code, and documentation are publicly available, ensuring reproducibility and accessibility. [R1]
- The proposed benchmark is more challenging than existing datasets, with larger scales and richer textual features, leading to larger performance variations among baselines. [R1, R4]  
- The paper provides insights and possible directions for future model design, such as models with global attention and stronger expressive power. [R1]
- The paper is well written and easy to follow. [R3, R4]
- Experiments are comprehensive, covering multiple datasets and tasks. [R3]
- The unified environment facilitates consistent and reproducible evaluation across methods. [R4]
- New datasets reveal that existing methods underperform, highlighting the need for more robust approaches. [R2 notes this as a strength: results on enriched datasets are poorer, depicting difficulty level.]

### Weaknesses
**Missing Related Work and Prior Benchmarks**
- The claim of being the first to benchmark multiplex graphs omits a prior benchmark on representation learning in multiplex graphs with an information-fused taxonomy [1] (ICCS 2024). This significantly undermines novelty. [R2, confidence 5]
- The overlap between multiplex and heterogeneous graphs is inadequately discussed. Larger heterogeneous graph benchmarks exist (e.g., OGB_MAG with >1M nodes, Freebase in HGBDataset with ~180k nodes), and relational GNNs (e.g., RGCN) could be applied, limiting this work’s contribution. [R4; also R3 suggests including RGCN; R2 mentions the overlap should be incorporated]
- The self-supervised method [4] (AAAI 2023) is missing from related work. [R2]

**Incremental Contributions and Dataset Scale**
- New datasets are still relatively small (Amazon-MGB ~35k nodes, IMDB-MGB ~4.6k nodes) and are processed from existing datasets, not original. [R1, R4]  
- Compared to existing larger graphs (OGB_MAG, Freebase in HGB), the scale improvement is not significant. [R4]
- Introducing edge-level tasks is not novel because prior heterogeneous graph studies (e.g., knowledge graph link prediction) already perform edge-level evaluation. [R4]

**Baseline Selection and Tuning Methodology**
- Baselines include only old methods (GCN, GAT, HAN); recent expressive methods [2] (Weisfeiler and Leman Go Relational, LoG 2022), [3] (Neural Bellman-Ford Networks, NeurIPS 2021) and graph transformers should be benchmarked, not left for future work. [R2; R3 also suggests graph transformer as common baseline]
- Constraining all algorithms to the same number of epochs, weight decay, and learning rate is incorrect; hyperparameters should be tuned individually for fair comparison. [R2]
- Missing baselines: a simple MLP using only text embeddings (to measure the value of graph structure) and relational GNNs like RGCN for heterogeneous graphs with a single entity type. [R3]

**Observations and Interpretations**
- The claim of a “performance ceiling” on existing datasets is inconsistent with results showing classification accuracies of only 40–60% on IMDB, Amazon, and Freebase; there is still large room for improvement. [R4]
- The observation that end-to-end methods outperform self-supervised methods is expected, as end-to-end methods are directly optimized for the task whereas self-supervised methods are not. [R4]
- The poor performance on enriched datasets is not convincingly explained. Increased label space, meta-paths, and textual content should potentially improve performance; further investigation is needed. [R2]

**Data and Experimental Details**
- There are discrepancies in train/val/test splits vs. the number of nodes for IMDB and Freebase. [R2]
- Figure 1 is difficult to read; it could be replaced or improved (e.g., split into two plots with an x=y line). [R3; R2 suggests omitting the figure or using a table]
- For edge prediction, why not use Hits@K (as in OGB link prediction tasks) which can be more challenging and useful? [R3]
- For clustering tasks, how are end-to-end methods applied? Clustering is unsupervised; what training objective is used? Also, in several cases clustering performance is higher than classification performance on the same dataset, which needs explanation. [R4]
- The best classification results on new graphs are achieved by simple GCN with a large gap (e.g., 50.72 vs 39.61, 95.04 vs 88.41), which is unexpected given increased dataset complexity. Explanation needed. [R4]

**Other Reviewer Comments**
- The difference between multiplex and heterogeneous graphs should be clarified with an example in Section 2.1. [R1]
- In line 104, defining both E_r and A_r is redundant as they carry the same information. [R1]
- During double-blind review, the README should not reference pip installation that reveals a non-anonymous package name. [R1]
- The motivation for why this benchmark is needed (e.g., why not just use relational GNNs) requires stronger justification. [R3]
