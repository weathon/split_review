## Merged Review

### Summary
This paper proposes LazyLLM, a training-free method that dynamically prunes tokens during the prefilling and decoding stages of LLM inference by selectively computing KV pairs only for tokens important for next-token prediction. An auxiliary cache (Aux Cache) stores hidden states of pruned tokens, allowing them to be revived in later decoding steps. The method is evaluated on Llama 2 and XGen across multiple long-context tasks, reporting a 2.34× prefilling speedup on multi-document QA with LLaMA 2 7B while maintaining accuracy.

### Strengths
1. **Sharp focus on dynamic token pruning for the prefilling stage** (Reviewer 2). The paper introduces an innovative approach to reducing time-to-first-token (TTFT) by shifting prompt token computation to the decoding stage and allowing previously pruned tokens to be revived when needed.
2. **Effective and flexible layer-wise progressive pruning strategy** (Reviewer 2). Pruning from earlier to later layers is well-justified and offers a flexible trade-off between efficiency and performance.
3. **Comprehensive analysis and convincing results** (Reviewers 1, 2, 3, 4). Experiments span multiple datasets and models (Llama 2, XGen), with ablation studies on token drop rates and locations, providing insights into performance-speedup trade-offs. The method is training-free and can be integrated seamlessly into existing transformers.
4. **Aux Cache ensures each token is computed at most once along the whole generation** (Reviewer 4). This design avoids redundant KV recomputation for pruned tokens that reappear in later steps.

### Weaknesses
1. **Limited baseline comparisons** (Reviewers 1, 3). The paper compares against token drop, static pruning, and prompt compression, but does not include standard TTFT reduction techniques that use parallel computation (e.g., [2]) or recent efficient cache management methods such as H2O [1] and SnapKV [2]. These methods can accelerate prefilling without accuracy loss and offer different KV cache reduction strategies. Including them would more comprehensively illustrate LazyLLM’s strengths and limitations.
2. **Potential memory overhead and unfair GPU memory comparison** (Reviewers 2, 3). The Aux Cache stores hidden states of pruned tokens on GPU, increasing the actual memory footprint beyond the retained KV cache. The experiments do not clarify whether GPU memory usage was fairly aligned across methods. If LazyLLM uses more memory, its speed advantages need reevaluation under equal memory constraints. Additionally, the Aux Cache may pose challenges for further reducing memory footprint during decoding; discussion on integrating with existing KV cache optimizations (e.g., Xiao et al. 2024, Liu et al. 2023, Zhang et al. 2023) is missing.
3. **Insufficient hyperparameter details and potential issues in token revival** (Reviewers 2, 4). The top-\(k\) percentile selection strategy uses layer-specific \(k^l\) values, but the paper does not clearly explain how these values were determined, their generalizability across tasks and decoding steps, or the sensitivity of performance to these parameters. For token revival, the method appends revived tokens without updating the KV of tokens before or after them, breaking sequential dependency. This approximation may affect the model’s ability to capture long-range dependencies and contextual nuances, but no discussion of trade-offs is provided. Furthermore, Reviewer 4 questions whether using the previous step’s KV cache for tokens that reappear in the current step is valid, since their representations differ between steps; the claim that “each token is computed at most once” needs justification.
4. **Potential bias from attention-based pruning and early-layer token exclusion** (Reviewer 2). Pruning a fixed number of tokens based on attention scores can unintentionally remove tokens with marginally lower scores in high-entropy distributions, potentially amplifying biases (e.g., for underrepresented groups). Moreover, early-layer pruning may exclude tokens that become important only in later layers (citing Li et al. 2023). The paper lacks analysis of how pruning decisions at early layers affect later attention and whether this disproportionately removes tokens from minority groups.
5. **Unexplained performance anomalies and confusing figures** (Reviewers 1, 4). In Table 2, code completion shows a high retained token percentage (68.57%) but a marginal speedup (1.01×), while single-document QA retains more tokens (87.31%) but achieves a larger speedup (1.34×). The reason for this non-linear relationship is not explained. Additionally, in Table 1, LazyLLM sometimes outperforms the baseline (standard full inference), which should be the performance upper bound; this observation requires explanation. Reviewer 1 also notes that Figure 4 is confusing.
6. **Generality and practical relevance questioned** (Reviewer 1, minority). Reviewer 1 (score 3, confidence 4) argues that the TTFT bottleneck may not be universal; in large-scale systems, prefilling and decoding often run on separate servers, and normalizing latency by number of tokens shows that prefilling itself is not necessarily problematic. The paper does not clarify scenarios where TTFT is 21× the decoding time, and should discuss when the problem is significant.
7. **Missing implementation details and template issue** (Reviewer 4). The paper does not provide Python or pseudo code to illustrate the core idea, making the method harder to understand. Additionally, the “Anonymous authors Paper under double-blind review” text is misaligned (centered instead of left-aligned), which may violate submission guidelines.
8. **Similarity to prior work** (Reviewer 1). The Aux Cache mechanism is similar to LESS [1] (https://arxiv.org/pdf/2402.09398v2); the paper does not clearly explain how it differs.
