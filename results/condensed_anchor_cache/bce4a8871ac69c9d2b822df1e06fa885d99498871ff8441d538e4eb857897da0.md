## Merged Review

### Summary
The paper proposes SPIKEGCL, a graph contrastive learning (GCL) framework built on spiking neural networks (SNNs) to learn binarized 1-bit graph representations. The authors claim nearly 32× storage compression with comparable or superior performance to full-precision methods, and provide theoretical guarantees. The paper is well-written and addresses an important topic (connecting SNNs and GNNs). However, reviews are mixed: one reviewer (score 3, confidence 2) is much more critical, questioning novelty, feature partitioning, missing comparisons, and the core idea’s justification; the other three (scores 6, confidences 2-4) find the work promising but raise several technical concerns and missing analyses.

### Strengths
- Novel combination of GCL and SNNs to learn biologically plausible, compact, binary (1-bit) representations.
- Clear motivation: reducing computation, memory and energy burden of full-precision GNNs.
- Theoretical guarantees on expressiveness comparable to full-precision counterparts.
- Extensive experiments across several graph benchmarks demonstrating up to 32× storage compression and performance comparable or superior to many state-of-the-art supervised and self-supervised methods.
- Interesting design: combining feature dimension partitioning with temporal axis in SNNs (reviewer 4).
- Well-written with clear model description and learning algorithm handling vanishing gradients.
- Framework tested on multiple benchmarks.

### Weaknesses
- **Feature partitioning into T groups (Section 4.1):** The uniform partition of node features along the dimension is not justified. Features (e.g., age vs. income) can represent different scales or semantics; grouping them arbitrarily may corrupt representations. One reviewer suggests using random masking instead to preserve feature distribution consistency. Another reviewer notes no explanation for why the 0th and N/T-th values should have a temporal relationship. A third reviewer points out that exchanging time-step characteristics (T-1 vs T-2) could produce the same output, raising a many-to-one compression issue. The claim that computation complexity is unchanged with T appears inconsistent with Fig 4 (reviewer 4).
- **Missing comparisons:** 
  - Table 2 compares parameter size/energy only with traditional (non-spike) methods, but Table 1 shows SPIKEGCL underperforms existing spike-based methods in most cases. A direct comparison with spike-based methods in Table 2 is needed.
  - The paper lacks quantitative analysis connecting compressed binary vectors to original vectors (e.g., distribution preservation, reconstruction error) and comparisons with other binary GNNs to explain why 1-bit representations are superior (reviewers 2, 3).
- **Unclear design choices:**
  - Motivation for using T separate encoders (one per time-step) is unclear. Usually SNNs share weights across time-steps; separate encoders increase model size. The claim of reduced complexity vs. Fig 4 is not explained.
  - Problem formulation (Sec 3) is not clearly stated as specific to this work versus general GCL formulation; reviewer 4 asks for explicit distinction.
  - How SPIKEGCL reduces *parameter* size is not explained. SNNs typically reduce activation storage, not parameters. A diagram of parameter size computation is requested.
- **Backpropagation and gradient flow:** Figure 3(b) “y1→y2” is unclear. It is not specified whether all y1…yn receive gradients directly from the loss. Section 4.4 introduces too much prior work; a clear diagram showing gradient paths for different blocks would help (reviewer 4).
- **Novelty concerns (minority reviewer):** One reviewer (score 3) finds the combination of spike and GCL insufficiently novel—essentially grouping features and applying standard GCL—and argues the approach does not leverage special properties of spike-GCL interaction. Other reviewers did not echo this but still request deeper analysis of learned representations.
- **Implementation dependence:** Reviewer 3 asks how much results rely on SNN details (reset-to-zero vs. reset-by-subtraction, IF vs. LIF neurons). This is not discussed.
- **Presentation issues:** Reviewer 4 notes insufficient background (problem formulation should be in background section) and too much existing work inside the method sections. Presentation rated fair by that reviewer, good/excellent by others.
