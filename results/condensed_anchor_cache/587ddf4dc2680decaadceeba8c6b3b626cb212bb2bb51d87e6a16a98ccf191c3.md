## Merged Review

### Summary
The paper introduces TabKANet, a model that combines Kolmogorov-Arnold Network (KAN) with Transformer architectures for tabular data modeling. The KAN is used as a numerical embedding module, while categorical features are handled by a transformer encoder. The model is evaluated on binary classification, multi-class classification, and regression tasks across multiple datasets. It outperforms selected deep learning baselines but shows only marginal or no improvement over GBDT models (e.g., CatBoost, AUC difference as small as 0.003 on 2 of 6 datasets). All three reviewers rate the paper 3 (marginally negative), citing limited novelty, insufficient evaluation depth, and missing baselines and ablations.

### Strengths
- Exploring the potential of KANs for tabular modeling is a timely and relevant topic (R1, R2).
- The model shows consistent improvement over the chosen neural network baselines (R1, R2).
- The evaluation covers a wide variety of tasks (binary, multi-class, regression) and datasets, which are described in detail (R2).
- The paper addresses an important problem: improving deep learning on structured tabular data (R3).
- Code is provided to reproduce some results (R1).

### Weaknesses
- **Novelty is limited** – The method is a simple combination of existing components (KAN, batch normalization, transformer) without deep theoretical or empirical justification for the design choices (R1, R2). The claim that KANs are fundamentally more powerful than MLPs is contested: a KAN with piecewise linear splines can be represented as an MLP with ReLU activations, and spline-based neural networks have been studied for decades (R2).
- **Inadequate baseline comparison** – Several state-of-the-art or widely-used tabular deep learning models are missing: FT-Transformer, MLP-PLR (R1), TabR, TabPFN (R1, R2), GANDALF, DeepTLF (R3). The paper relies on older or weaker NN baselines, which limits the significance of outperforming them (R1). GBDT baselines are compared without hyperparameter tuning – a fixed set of hyperparameters is used across all datasets, which is not standard practice and makes the comparison unfair to GBDTs (R1). The paper does not describe how hyperparameters were tuned for any method (R2). The authors claim "identical performance" to GBDTs on almost all datasets, but performance is consistently lower (R1).
- **Missing ablations and experimental depth** – No ablation replaces the KAN layer with a simple linear/MLP/piecewise linear encoder to isolate the contribution of KAN (R1, R2). Table 8 shows a large improvement from using BatchNorm vs LayerNorm, but an obvious baseline would be TabTransformer with BatchNorm (R2). The effect of removing the KAN layer entirely is not tested (R2). The claim that KANs are more flexible for tabular data is not supported by theoretical or empirical evidence (R1).
- **Dataset selection and benchmark choice** – The datasets are not drawn from established benchmark suites (e.g., AutoML benchmark, TabZilla, OpenML-CC18, Grinsztajn collection), which allows potential cherry-picking (R2, R3). Using widely recognized benchmarks like TabZilla would provide a more robust assessment (R3).
- **Overstated claims and unclear writing** – Several statements are misleading or unsupported: “Current scientific research has not yet proposed a simple, stable, and universal numerical embedding module” is an overclaim (R1). The introduction suggests existing transformer models only encode categorical variables, ignoring the variety of tabular transformer models (R1). The phrase “subconscious best solution” (Line 223) is unclear (R1, R2, R3). The justification for using BatchNorm over LayerNorm (page 5) lacks technical depth; it is presented as a key decision but the ablation (Section 4.7) does not sufficiently support it (R1, R2). The separation of NN and GBDT baselines into separate tables (Tables 2, 3) is confusing – a unified comparison would be clearer (R3).
- **Minor technical issues** – The statement “Repeatedly pairing numerical normalization results and category features will bring additional training data” (Line 238) appears to describe data augmentation, not additional data, and could benefit from an ablation study (R3). The model’s architecture description (Figure 2) is confusing: the output of a single row is reshaped to (m+n)×d, but it is unclear why multiple rows are shown (R2). The data splitting method (training/testing/validation, cross-validation?) is not clearly stated (R3). Line 377: “predict auc scores” should be “predict the target and compute AUC scores” (R2). Line 267: “MLP is a traditional deep learning model” needs clarification (R3). Typos: Line 027 (“The tabular” → “a tabular”), Line 030 (“medicineI” → “medicine”), Figure 1 (“Nurmerical” → “Numerical”), Line 212 (“Numercal” → “Numerical”), acknowledgements contain author instructions (R2).
