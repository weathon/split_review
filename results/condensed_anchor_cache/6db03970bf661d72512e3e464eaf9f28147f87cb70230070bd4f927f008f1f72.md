## Merged Review

### Summary
The paper proposes Mayfly, the first neural data structure for graph stream summarization, using memory-augmented networks with neatly designed representation, addressing, decoding, and store operations. It employs a two-stage training paradigm: a larval phase pre-training on synthetic graph streams, and a metamorphosis phase fine-tuning on real streams (e.g., Lkml, Enron). Mayfly supports multiple query types (edge, node, connectivity) via lightweight information pathway configurations, and achieves significantly better approximation accuracy than sketching-based baselines (TCM, GSS) under the same space budget, while scaling to billion-edge graphs. All three reviewers found the topic interesting and the overall design reasonable, though Reviewer 1 (score 6) was more critical of novelty and efficiency evaluation compared to Reviewers 2 and 3 (scores 8, 8).

### Strengths
1. The paper studies a novel and interesting problem—neural data structures for graph stream summarization—and presents a neatly designed framework with clear methodology (Reviewers 1, 2, 3).
2. The two-stage training strategy (larval phase on synthetic meta-tasks, metamorphosis phase on real streams), following a pre-training and fine-tuning paradigm, is inspiring and effectively adapts the model to evolving graph streams (Reviewers 1, 2, 3).
3. Comprehensive experimental results on Lkml and Enron datasets demonstrate strong performance across edge queries (ARE/AAE), node queries, connectivity queries, and throughput, significantly outperforming handcrafted competitors TCM and GSS (Reviewers 2, 3).
4. Mayfly successfully scales to billion-edge graphs, highlighting its practicality for real-world scenarios (Reviewer 3).
5. The framework is flexible, supporting multiple query types through configurable information pathways (Reviewer 1, 3).

### Weaknesses
1. The paper lacks theoretical analysis of complexity and accuracy (e.g., time complexity of addressing, decoding, store operations, and approximation guarantees). This was noted by Reviewer 3, and Reviewer 1 also commented that the innovation at the model level is minimal, as it primarily applies standard meta-learning and pre-training/fine-tuning techniques.
2. Presentation clarity needs improvement in several areas (Reviewer 3): the addressing scheme (how the 2D separated in/out-degree scheme is implemented and how it differs from existing approaches), the storage mechanism (specific compression techniques used and rationale for jointly compressing nodes and edges), and the decoding process (how altering information pathways in memory networks enables multi-decoding for different query types). Reviewer 2 further noted that a table of dataset statistics is missing.
3. Missing efficiency benchmarks: there is no direct runtime comparison between Mayfly and baselines under the same space budget (Reviewer 1). While throughput is reported, query time and other efficiency metrics are not provided; additionally, the throughput of Mayfly is not as high as rule-based baselines, which is somewhat expected but should be discussed (Reviewer 3). Reviewer 2 also requested other efficiency metrics (e.g., query time).
4. The method currently supports only weight-related queries (edge weight, node weight) and not more complex graph algorithms such as Dijkstra’s shortest path. It remains unclear whether such algorithms can be executed on the summary and, if so, how the time complexity compares to running on the uncompressed graph (Reviewer 3, question overlap with weakness).
5. Several requests for additional analysis and clarification were raised: (a) an explanation of why the Mayfly framework is particularly suitable for adapting to graph data streams (Reviewer 1); (b) a more detailed explanation of how the MiGain term contributes to the loss (Reviewer 3); (c) a discussion of how to balance parameter size and model accuracy (Reviewer 2); (d) reporting baseline ARE and AAE when using the mean as an estimate for all edge weights, to contextualize the error magnitudes (Reviewer 3).
