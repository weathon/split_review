## Merged Review

### Summary

Reviewers agree the paper targets an important problem (lightweight image captioning) and that the core proposal – a least‑squares linear mapping between visual and text embeddings, executed on a CPU in minutes, plus retrieval‑augmented generation with an LLM and an iterative self‑improvement loop – is interesting and practically motivated. One reviewer (score 5) was notably more positive, praising the training‑free alignment, the self‑improvement strategy, and the analysis of CLIP‑score’s hallucination blindness; other reviewers gave score 3. The dominant criticisms are insufficient novelty, performance below prior lightweight and retrieval‑augmented baselines, reliance on a pre‑existing caption pool (which limits autonomous captioning and generalization), grounding problems, and an imbalance between claimed “lightweight” training and heavier inference/memory requirements. Several missing experiments, comparisons, and detail clarifications were requested.

### Strengths

- Well‑written and comprehensible (R1).
- Addresses an important problem: lightweight image captioning (R2, R3, R4).
- Proposes a training‑free (no NN training) method to align visual and text spaces via a least‑squares linear mapping, computable on a CPU in minutes (R1, R2, R4).
- Only 1 M trainable parameters, computationally efficient (R4).
- The iterative self‑improvement loop uses synthetic captions from the LM and improves metrics without additional human‑labeled data (R2, R3, R4).
- Idea of using an LLM to summarize nearest retrieved captions is interesting (R2, R3); one reviewer (R2, score 5) found this particularly valuable.
- Shows competitive results on MS‑COCO and Flickr30k compared to lightweight captioning methods (R1, R2, R4), and cross‑dataset transfer experiments (R2).
- Highlights an important flaw in reference‑free metrics: CLIP‑score assigns high scores to hallucinated content (R2).
- Practical, efficient, accessible for resource‑limited scenarios (R4).
- Training the projection weight **W** is extremely low‑cost (R5).

### Weaknesses

**Novelty and conceptual framing**  
- The method lacks novelty: linear mapping with least‑squares is a basic constrained optimization; retrieval‑augmented captioning has been proposed in prior work (R1, R2). The only difference from existing retrieval‑augmented methods is the least‑squares training instead of training a layer (R2).  
- The approach is not image captioning but caption enhancement / text retrieval, because it assumes a pre‑existing pool of fairly accurate captions (R3). A title change is recommended (R3).  
- The method cannot produce fine‑grained details; captions are high‑level summaries (R4).  

**Performance and comparisons**  
- Performance is below prior lightweight and retrieval‑augmented baselines on most metrics (e.g., BLEU: SmallCap 36 vs. proposed 29; SPICE numbers similar) (R2).  
- Performance is far below current SoTA; the performance drop is disproportionate to the resource savings (R5).  
- Table 1 comparison is unfair: the proposed method uses a pre‑determined caption pool for retrieval, while baselines do not require such a resource (R3).  
- Only evaluated on COCO and Flickr, which have similar image distributions; lacks evidence on out‑of‑distribution data or diverse real‑world scenarios (R4).  
- Missing comparisons on datasets like VizWiz, MSR‑VTT (R2).  
- No comparison to large multimodal models (LLaVA, InstructBLIP, BLIP2, MiniGPT‑4) (R3 Q1).  
- Other retrieval‑augmented captioning works (REVEAL, RA‑C3M, HAAV) that train jointly are not compared (R5).  

**Dependence on a caption pool**  
- The method cannot do image captioning autonomously; it requires a large, pre‑existing repository of captions for retrieval (R3, R4).  
- If the testing distribution differs strongly from the reference set, the method can cause catastrophic errors and error propagation, and would need many iterations, diminishing efficiency (R4).  
- There is no criterion for selecting reference/testing sets to guarantee sufficient coverage; if a concept is missing from the caption pool, the LLM can only summarize whatever captions are present, leading to hallucination that iterations cannot remove (R4).  
- No experiments are conducted with reference and testing sets that are very different from each other (R4 Q3).  
- The total memory cost includes both **W** and the full caption pool; the latter may be large (R3).  

**Grounding and reliability**  
- The final caption is a summary of retrieved captions, not guaranteed to be grounded in the image; if the image contains a concept absent from all retrieved captions, the caption will be incorrect (R2).  
- The LLM never sees the image, only text summaries; iterative refinement with synthetic captions may introduce or amplify errors if synthetic captions are low‑quality (R4).  

**Computational efficiency claims**  
- “Lightweight” applies only to training time; inference requires image encoding, retrieval of several captions, and LLM generation, which can be slower than a standard VL model (R5).  
- Training does not save trainable parameters: recent VL models like LLaVA also use a single fc layer (R5).  
- Pre‑computation of all reference image‑text pairs and repeated updates of synthetic captions across iterations add computational overhead (R4).  
- No computational complexity estimates for each step are provided (R1).  

**Missing methodological details**  
- No algorithm or pseudocode is given, harming reproducibility (R1).  
- Notation is unclear: **W** is not explicitly defined; hyperparameters *k* and *l* are introduced without explanation or rationale for chosen values (R1).  
- The rationale for choosing high‑scoring captions for augmentation in the self‑improvement loop is not explained (R1).  
- No comparative analysis with existing joint models from VQA or other multimodal representation literature to highlight novelty (R1).  
- Details about the retrieval set are missing: what set is used during training vs. testing; whether the same set is used for COCO and Flickr; sensitivity to quality/distribution of the retrieval set (R5).  
- The proposed metric (linked to CLIP‑score) is not validated; its sensitivity to choice of metric is unclear (R4).  
- The CLIP‑score finding, while interesting, does not add value to the core captioning method (R2).
