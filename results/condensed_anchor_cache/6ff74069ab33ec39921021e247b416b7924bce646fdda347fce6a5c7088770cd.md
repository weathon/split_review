## Merged Review

### Summary
This paper proposes a deep reinforcement learning (DRL) guided *improvement* heuristic for the job shop scheduling problem (JSSP), in contrast to previous DRL *construction* heuristics. Complete solutions are encoded as disjunctive graphs, and a novel two-module graph neural network (GNN) architecture—topology embedding and context-aware embedding—is designed to capture dynamic topology and node-type information. A message-passing mechanism enables simultaneous evaluation of multiple solutions on GPU, accelerating training. The authors prove linear computational complexity with respect to problem size. Experiments on classic benchmarks compare the method with DRL-based methods, simple heuristics, and a tabu search using the same N5 neighborhood; the learned policy outperforms existing DRL methods by a large margin.

### Strengths
- Good literature review and clear articulation of the MDP process with a state transition example.
- Novel GNN architecture: two modules (topology and context-aware) specifically designed to encode existing solutions during improvement. Ablation studies independently evaluate each component.
- Efficient batch-schedule computation on GPU, accelerating DRL training.
- Proof that computational complexity scales linearly with problem size, enabling application to larger instances.
- Broad experimental evaluation across multiple benchmarks, instance sizes, and baselines—including DRL methods, simple heuristics, and tabu search.
- Outperforms state-of-the-art DRL-based methods in most settings, achieving excellent performance with reasonable time budgets.
- Comparative study with a tabu search algorithm using the same neighborhood structure.

### Weaknesses
- **MDP formulation and notation clarity**:  
  - The transition state calculation (Section 4.1) is not sufficiently detailed; it is unclear how the transition space is updated with current status information of all jobs and machines, and how edges are removed/added when swapping operations. The edge update rules for the disjunctive graph need explicit description.  
  - The notation uses the same $O_{ji}$ to denote both operation and machine ($m_{ji}$) without a separate subscript for the machine; this makes it difficult to track machine–operation associations in the text and figures. A different subscript (e.g., $m_k$) is needed.  
  - The notion of “machine predecessor” becomes clear only later. The N5 neighborhood definition could be more formally described (beyond the example).  
  - Some sentences are unclear (e.g., page 1: “given that the topological relationships could be more naturally modeled among operations”; page 3: first two sentences of Section 4.2.1 appear contradictory).  
  - Typos and awkward wording: “receives relatively less attention” → “has received”; “In specific” → “specifically”; “A delicate Markov decision process formulation”; “graph-based ones aforementioned”; “Precedent constraints” → “Precedence constraints”; “To fast calculate” → “to quickly calculate”; “till” → “until”; missing closing curly brace for $c_V$ (page 7); “Parameter $\theta$” should be “Parameter set $\theta$” (Section 4.2).

- **Reward design and learning details**:  
  - The reward function aims only to improve the initial solution; one reviewer questions whether this closely corresponds to the actual scheduling goal. Different reward formulations were not explored, and the impact on learning is unclear.  
  - The n-step REINFORCE return $R_{t-j}^b$ is not fully specified. Using returns over $n$ steps may ignore future rewards beyond that horizon; the authors should comment on whether this matters for a local search method.  
  - No baseline was used during REINFORCE training; the potential effect of adding a baseline is not addressed.

- **Generalization and scope**:  
  - The method relies on the handcrafted N5 neighborhood to define the action set (candidate operation swaps). This limits generalizability to other scheduling problems (e.g., with resource constraints or sequence-dependent setup times), and it is not evaluated on any non-JSSP problems.  
  - Generalization capability across instances is not thoroughly addressed (e.g., by training on one instance and testing on another of the same size, or using an order-swapping mechanism).  
  - No exploration of standard RL environments (e.g., OpenAI Gym) to facilitate reproducibility.

- **Comparison baselines and state-of-the-art**:  
  - Although compared with tabu search using the same N5 neighborhood, the proposed method does not outperform that tabu search in all settings. The choice of tabu search as a baseline is not justified.  
  - The paper does not compare to broader state-of-the-art JSSP methods (e.g., exact or advanced metaheuristics); it is unclear how the method ranks against the very best known approaches.  
  - Few citations of existing MDP-based job shop scheduling works are provided (explicit weakness from one reviewer).

- **Minor**:  
  - The very positive results in Appendix H (generalization and scalability) are relegated to the appendix and should be highlighted in the main text.  
  - The paper would benefit from another round of language polishing.
