## Merged Review

### Summary
The paper proposes Staple, a plan retrieval augmented reasoning framework that uses offline MCTS to construct a plan database of high-level instructions, and online search to retrieve optimal plans for guiding LLM reasoning on math and scientific problems. All four reviewers note the novelty of the approach and the focus on reducing token usage. However, most reviewers found significant shortcomings in clarity, methodology scope, missing baselines, and insufficient implementation details, leading to low scores (3/3/3). One reviewer (Reviewer 4) was substantially more positive (score 6), highlighting the novelty and cost-efficiency, though also noting limited task scope and missing ablation details.

### Strengths
1. **Novel idea**: Offline plan optimization via MCTS and online reuse by search is an interesting and novel approach (R1, R4). The design and construction of a step-wise plan database based on tree structure is novel and cost-efficient (R4). Reducing token usage is an important problem (R2).
2. **Competitive performance**: Experimental results show Staple achieves comparable solving rates to other methods while using fewer tokens during inference (R3). The approach proves to be cost-efficient (R4).
3. **Baseline comparisons**: The paper compares various baselines and prompt optimization techniques (R1, R2). Detailed evaluation parameters for language models are provided (R2). Code for reproducibility is included (R2).
4. **Addresses MCTS with LMs**: The authors design a complex procedure to address exploration and hallucination problems in MCTS with language models (R1).

### Weaknesses
1. **Clarity and presentation issues**:
   - Missing a diagram of the overall framework in the main text (R1, R2). The plan tree (line 187) should be illustrated; a simplified version of Figure 5 or 6 is needed (R2).
   - Poor organization: Line 156 introduces "the concept of a plan" before defining it (R2). Line 176: unclear why "min" is used for $P^*$ (plan that minimizes average accuracy) (R1).
   - Notation confusion: "node", "state", "plan", "thought" are not clearly defined (R3). Line 73: what is "node" and "state"? Section 3.2 is confusing; strongly suggest an example (R3). Line 175: should be "argmax" (R3). Line 206: bold $\psi$ should be $\Psi$ (R3). Line 414: $U_{800}$ is not defined (R3). Figure 1b is unclear: which line is number of nodes and which is solving rate? (R3).
   - Table 2 does not specify whether numbers are success rates or utilization scores; add "Success rate of models across..." (R2). Citation formatting inconsistencies (R2). Unnecessary repetition of algorithm names (R2).
   - Limitations discussion is in the appendix; should be in the main text (R2).

2. **Limited task scope and model evaluation**:
   - Only math and scientific reasoning tasks are tested (AQUA-RAT, MATH, TheoremQA). Effectiveness in dynamic environments (interactive sequential decision-making) is untested; benchmarks like ALFWorld, WebShop, WebArena are suggested (R4). Broader applicability, e.g., program synthesis, would be valuable (R2).
   - Although the paper claims to evaluate four models, Figure 1 and Table 1 only show GPT-4 results (R2). Results for other models (e.g., Llama 2-13b) are missing (R2 Q2). Testing on one or two additional subjects is needed (R2 Q3).
   - Transferability to tasks without category ID is unclear: how to obtain a corresponding plan tree? (R1 Q2). Search on multiple plan trees and whether that improves results is not explored (R1 Q1).

3. **Missing baselines and comparisons**:
   - An extra baseline comparing with online MCTS methods (e.g., [1][2][3]) should be added (R1). Also, a majority vote on the Adaptive method (vs. Ensemble-C which ensembles Direct) is not studied (R3 Q9).
   - Comparison with other reward/value function designs is missing (R4).

4. **Insufficient implementation details and ablation**:
   - Computation cost of offline plan optimization is not reported (R1 Q3, R2 Q1, R3 weakness). Average cost of creating the plan database is needed (R2 Q1).
   - Details of reward assignment and value function are lacking. The LLM evaluation score is implemented via a simple prompt; its impact on performance is unclear (R4). Provide more details on the value function and how it works during adaptive search (R4).
   - Adaptive search: search space per reasoning step is not defined; how is progress controlled if the LLM does not strictly follow the plan (e.g., finds a mistake and tries to fix it)? (R4 Q1)
   - Direct vs. Adaptive: The difference between Direct and Adaptive is unclear (R3 line 271-275). Direct is described as executing the plan sequence in a single interaction, but generation alternates between plan and thoughts—how is this a single interaction? (R3). Direct selects "highest r at each level", but the reward is conditioned on thoughts—this seems contradictory (R3). Does the direct search design influence results? (R4 Q2)

5. **Specific methodological concerns**:
   - Line 269: if multiple plan trees can be retrieved, will a search on multiple trees improve results? (R1 Q1) – already above.
   - Line 191-195: since $\psi$ is generated conditioned on $z_{0...n}$, why can it be used as guidance for the $n$-th thought generation? Is this referring to online plan searching? (R3)
   - Ensemble-C ensembles Direct; what about majority votes on Adaptive? (R3 Q9) – already in missing comparisons.
