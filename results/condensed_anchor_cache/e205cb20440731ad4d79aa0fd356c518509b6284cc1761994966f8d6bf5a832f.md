## Merged Review

### Summary
The paper proposes a fully offline method for skill stitching using model-based RL. It assumes a separate offline dataset for each skill, trains a dynamics model and value functions per skill, and at test time uses model predictive control (MPC) to plan transitions between skills while penalizing model and value uncertainty. The method is evaluated on several benchmarks (Maze Runner, Kitchen, etc.) against a few baselines. Two reviewers (score 3) are critical of novelty and missing comparisons; one reviewer (score 5) finds the problem important and the results promising, especially on the maze domain.

### Strengths
- Well-written and easy to follow. (R1)
- Evaluated on various domains. (R1)
- The offline skill stitching problem is important for real-world applications. (R3)
- The idea of using a learned dynamics model and planning (MPC) to stitch skills is interesting and a good direction for further research. (R3)
- Strong performance on the Maze Runner (discrete action space) compared to baselines. (R3; R2 also notes discrete actions make MPC feasible)
- Results are overall better than the baselines considered. (R3)
- Skill stitching offers a practical approach in hierarchical RL for long-horizon tasks composed of multiple sub-tasks. (R2)

### Weaknesses
- **Lack of novelty:** Stitching skills or sub-trajectories using value functions is a fundamental approach already explored in offline RL. The paper does not adequately differentiate from existing works such as PEX [R1 ref], Stitching Sub-trajectories with Conditional Diffusion Model (AAAI 2024) [R2 ref1], Model-based Trajectory Stitching (NeurIPS 2023) [R2 ref2], and Offline Policy Learning via Skill-step Abstraction (IJCAI 2024) [R2 ref3]. (R1, R2)
- **Missing baseline comparisons:** The evaluation lacks comparisons to OPAL [R1 ref] and LPD [R1 ref] (R1), to offline goal-conditioned RL methods like goal-conditioned IQL (R3 question), and to the trajectory stitching methods listed above. Without these, it is difficult to assess the true performance and novelty. (R1, R2, R3)
- **Model accuracy in complex environments:** The paper does not address what happens if the dynamics model learns inaccurately. (R1 question → weakness)
- **No normalized scores reported** for experimental results. (R1 question → weakness)
- **MPC inefficiency:** For continuous action spaces, MPC requires extensive sampling and value evaluation; in stochastic environments, optimization may be performed at every step, leading to high time complexity. (R2)
- **Minimal gain on Kitchen:** Performance on the Kitchen benchmark (continuous action space) shows only small improvements. The value function may be unreliable there, requiring extensive MPC search. This raises questions about effectiveness in continuous action settings. (R2; R3 also notes the method fails to accomplish more than one skill in complicated tasks per Table 2)
- **Strong assumption of per-skill datasets:** It is unclear whether the method can be extended to learn diverse skills from a single offline dataset, or if the assumption can be relaxed. (R3)
- **Training cost:** Training each skill separately via offline RL is expensive and time-consuming. (R3)
- **Hyperparameter sensitivity:** Selection of some hyperparameters (e.g., maximum steps of skill execution) is not clearly justified and appears problem-dependent. (R3)
- **Generalization concerns:** The method may not generalize to dynamic or unpredictable environments because it relies solely on offline data without real-time adaptability. (R2)
- **Dependence on dataset diversity:** Effectiveness is highly dependent on the diversity of the aggregated offline datasets. (R2)
- **Value function reliability during stitching:** Value functions for each skill are learned on distinct datasets; it is unclear how they can accurately evaluate states never visited during stitching (distribution shift). (R2 question → weakness)
- **No techniques discussed** to reduce the computational burden of MPC in continuous/stochastic environments, or to improve generalization within offline constraints. (R2 questions → weaknesses)
- **Unclear performance across skill permutations:** The paper does not examine whether the method works better for some skill orderings than others. (R3 question → weakness)
- **Minor typos:** line 97: “over-estimate” → “overestimate”; line 215: “continous actions space” → “continuous action space”; line 257: missing subscript in `T_{\phi}(\cdot|s_t,a_t)`. (R2)
