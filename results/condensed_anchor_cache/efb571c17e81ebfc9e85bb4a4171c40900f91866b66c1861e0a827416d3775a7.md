## Merged Review

### Summary
The paper introduces ADOPD-Instruct, a multimodal dataset for visually-rich document editing derived from the existing ADOPD dataset. It provides entity-level masks, step-by-step edit instructions (curated via GPT-4o + human annotators), and targets both text and non-text masking/inpainting. The authors evaluate 8 MLLMs on instruction generation and 4 image editing models on instruction following, revealing significant limitations. Reviews are mixed: three reviewers rate 5, one rates 3. The dataset is seen as filling a gap, but concerns about data generation clarity, technical contribution depth, and evaluation thoroughness are raised.

### Strengths
- **Useful, novel dataset filling a critical gap.** ADOPD-Instruct is a large-scale, publicly available multimodal dataset with detailed entity-level annotations (masks, step-by-step instructions) for both text and non-text design elements in document editing. It stands out for its scale and annotation detail (R1, R2, R4).
- **Clear annotation process (minority view).** One reviewer found the annotation process clear and easy to understand (R1); others found it lacking (see Weaknesses).
- **Extensive benchmarking.** The paper evaluates a wide range of current models (8 MLLMs and 4 image editing models), demonstrating that the task is challenging and revealing current limitations in instruction-following and text rendering (R1, R2, R3).
- **Practical relevance.** The task of document editing is under-explored yet highly applicable to real-world scenarios (R2, R3).

### Weaknesses
- **Lack of clarity in data generation.** The dataset generation process is ambiguous: how source and target images were generated is not adequately explained, and more details on human annotators and image sources are needed (R2, R3). There is disagreement among reviewers: R1 found the annotation process clear, but R2 and R3 consider it insufficiently described given the 8-page limit (R2).
- **Ambiguity regarding GPT-4o instruction generation.** Table 2 shows >60% of GPT-4o instructions are incorrect; the justification for relying on these instructions, given that human annotators must refine them, is unclear (R1, R2). Further, the performance of GPT-4o itself for image editing on this dataset is not explored (R2).
- **Task setup questioned.** The separation of the task into instruction generation (masking) and instruction-following (inpainting) appears disconnected from real-world applications: if the mask and target image are already prepared, the need for generating instructions is unclear (R1). One question explicitly asks why the tasks are separated (R1).
- **Limited technical and insightful contribution.** The dataset is derived from an existing public dataset (ADOPD), and while new annotations are provided, the scale is relatively small and offers limited insights for future research (R3). The evaluation highlights failures but provides no guidance or analysis on how to improve model performance (R3, R4). Error analysis and explanations for differences across models (e.g., why newer models may perform worse) are missing (R4).
- **Insufficient evaluation metrics.** Metrics used (e.g., in Table 5) may not be appropriate for local edit tasks; local metrics like SSIM or CLIP score on the masked area could be more accurate (R2). LaMa’s best performance might be due to simply copying the input image (R2). Additionally, GPT-4-based evaluation was suggested as a more comprehensive metric (R4). The specific dataset split used in the evaluation is not detailed (R2).
- **Limited classification of edit tasks.** The dataset only considers Masking and Inpainting for single text and non-text elements; a more detailed classification of edit types would benefit the paper (R2).
- **Missing related work.** The paper should discuss relevant prior work on image editing datasets/models (MagicBrush, Emu Edit, HQ-Edit, UltraEdit) and text rendering capabilities (TextDiffuser-2, GlyphDraw2, etc.) (R2). Also, connections to text-rich and layout multimodal reasoning works (TRINS, LayoutLLM) are not made (R3).
