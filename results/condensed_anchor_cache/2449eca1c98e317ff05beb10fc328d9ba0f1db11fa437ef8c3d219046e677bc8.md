## Merged Review

### Summary
The paper introduces LLMPhy, a zero-shot black-box optimization framework that combines an LLM (GPT-4o) with a physics simulator to infer physical parameters and predict object dynamics after an impact on a tray. The method uses iterative LLM-generated code and simulator feedback to estimate friction, damping, stiffness, rotational inertia, and scene layout, then synthesizes video sequences to answer multiple-choice questions about object stability. The authors also present the TraySim dataset of simulated multi-object interactions. Evaluations show improvements over random-parameter baselines and Bayesian optimization.

### Strengths
- The paper is well written and organized, with clear mathematical formulation and illustrations (Reviewer 1; Reviewer 2 disagrees—see Weaknesses).  
- The problem—reasoning about complex multi-body physical interactions—is challenging and relevant for embodied AI (R1, R4).  
- The ablation comparing Random and Ground Truth physical parameters is informative and the conclusions drawn are sound (R1).  
- The approach is novel: combining LLMs (via in-context learning and code generation) with a non-differentiable simulator in a black-box optimization loop (R3, R5).  
- TraySim provides a tailored benchmark for multi-object dynamics, supporting future research (R3, R5).  
- Results show notable improvements over baselines (random parameters, direct LLM, Bayesian optimization) (R1, R3, R5).  
- The paper attempts low‑level physical reasoning (trajectory/parameter estimation) rather than only high‑level semantic reasoning, which is an interesting direction (R2).

Reviewer disagreement: One reviewer (R1, score 6) found the paper very strong on clarity and ablation; others (R2, R4, score 3) raised significant concerns about writing quality, experimental breadth, and methodology clarity.

### Weaknesses
1. **Experimental scope and validation**  
   - Only three object categories, a single tray size, and one pusher initial condition tested; the reasoning question is simple (“which objects remain upright”) rather than detailed pose prediction (R1).  
   - Dataset has only 100 sequences, limiting complexity and generalization claims (R3).  
   - No real‑world validation; results are purely simulated and the sim‑to‑real gap is not addressed (R1, R3, R4).  
   - No comparisons on established physical‑reasoning benchmarks (CoPhy, ComPhy) or with existing methods (e.g., the ComPhy paper, https://arxiv.org/abs/2012.08508) (R4).  
   - No comparison with other black‑box optimizers (e.g., CMA‑ES) that might achieve similar or better results (R5).  
   - Claim of generalizability to any simulator is unsubstantiated: only PyBullet is used (R2).  
   - The optimization algorithm appears to rely on LLM trial‑and‑error and must be re‑invoked per scenario; no mechanism for the LLM to retain learned parameters across scenes (R5).  
   - Only GPT‑4o is evaluated, preventing conclusions about other LLMs (R1).

2. **Methodology clarity and presentation**  
   - Writing is often informal or vague (e.g., “leads to significant improvements” without numbers, “promising results”, ambiguous notation like “X is the input data, and Λ is the desired result”) (R2).  
   - Unclear how multiview images are used to reconstruct object shapes and what exactly is input to the LLM (R4).  
   - It is not explained how raw RGB video is converted into simulation inputs, raising concerns about applicability to realistic scenarios (R4).  
   - In Phase 2, the purpose of predicting object colour is irrelevant for dynamics; object location could be extracted directly from the first frame using τ (R5).  
   - The final step where the LLM processes the synthesized video to answer the question is not detailed (R5).  
   - Choice of IoU as evaluation metric is unclear; why not exact match on the answer set? (R5).  
   - Why generate programs for parameter values instead of outputting the values directly, since no program logic (loops, conditions) is used? (R5).  
   - No qualitative example is in the main paper (only supplement) (R2).  
   - Plots in the supplement are not referenced in the main text (R2).

3. **Limited parameter scope**  
   - Only four physical parameters are considered, constraining applicability to richer environments (R3).  
   - Each object category uses the same allowable tilt α (R1).  
   - Only one object category is present per scenario? (implicit limitation).

4. **Missing ablations and analyses**  
   - No ablation with ground‑truth scene layouts to isolate the LLM’s ability to optimize physical parameters alone (R1).  
   - No per‑parameter error analysis; it is unclear which physical properties are hardest to infer (R1).  
   - No test of consistency (e.g., asking the inverse question “which objects will be knocked over”) (R1).  
   - No analysis of how the framework handles cases where parameter estimation fails due to high variability in initial conditions (R3).  
   - No study of performance when scaling to more objects, more parameters, or different physics engines (R3).  
   - Reproducibility with open‑source LLMs is not discussed (R3).

5. **Related work positioning**  
   - The abstract and introduction do not clearly differentiate the proposed work from existing literature (R2).  
   - The method is similar in spirit to Eureka (reward design via coding LLMs) but this connection is not discussed (R5).
