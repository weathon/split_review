## Merged Review

### Summary

The paper proposes a benchmark for evaluating synthetic relational data generation methods, combining known fidelity metrics with a new "discriminative detection" approach to distinguish real from synthetic data across single and multiple tables. Six methods (including two commercial tools) are compared on five datasets. The main finding is that even single-table assessment fails with current methods; utility shows moderate correlation. Reviewers generally found the benchmark vision valuable but identified significant weaknesses in novelty, comprehensiveness, depth of analysis, dataset variety, formalization, and missing state-of-the-art methods. One reviewer (score 6) was considerably more positive, highlighting the general framework and useful evaluation, while the majority (scores 3) found major issues.

### Strengths

- **Valuable benchmark initiative**: Establishing a benchmark for synthetic relational data with a focus on fidelity and utility is a useful contribution (R1, R4). The paper presents a fairly general framework for comparing relational data synthesis methods (R2 S1). Independent assessment and comparison of synthetic data generation tools is valuable (R3 S1).
- **Useful experimental evaluation**: The experimental comparison provides useful information about existing methods (R2 S2). The discriminative detection approach (classifier discriminator) is a common and useful baseline for single-table assessment (R3 S2).
- **Vision for generic metric**: The initiative to define a generic fidelity metric that can work across multiple methods is commendable (R4).

### Weaknesses

- **Limited novelty and insufficient benchmarking of proposed approach** (R1 W4, R3 W1, R1 W1): The core idea of using a classifier to distinguish real from synthetic data (discriminative detection) is a standard practice, not novel (R1 W4, R3 W1). Algorithm 1 simply trains a model to discriminate using a Binomial test, which is standard (R1 W4). The extension to multi-table data using simple aggregation from child tables is simplistic and not well-argued; it lacks justification for why aggregations improve over denormalization and ignores complex relational schemas (R3 W1, R1 W4). The comparison with statistical cardinality in Table 1 is only briefly discussed (~4 lines in Section 4.3), lacking rigorous analysis of why the proposed benchmark is superior (R1 W1). A more thorough ablation or redesign with a clear research question (e.g., Q1: Is the proposed benchmark more effective than SOTAs?) is needed (R1 W1).
- **Missing state-of-the-art methods, including differential privacy and recent generative models** (R1 W2, R4 W1, R4 W2): Despite the paper's claim that privacy protection is a motivation (Chapter 1), major approaches such as differential privacy for relational data are omitted (e.g., Yang et al. "SAM: Database generation from query workloads" SIGMOD 2022; Cai et al. "Privlava: Synthesizing relational data with foreign keys under differential privacy" SIGMOD 2023) (R1 W2). The benchmark also overlooks recent GAN and diffusion model works for tabular data (e.g., VLDB Journal 2024 "Tabular data synthesis with generative adversarial networks: design space and optimizations"; "Diffusion Models for Tabular Data Imputation and Synthetic Data Generation"; Tabsyn which combines a diffusion model and a VAE; CoDi which uses diffusion models) (R4 W1). The authors' claim that related work lacks accessible APIs/code is incorrect; code for many of these methods is publicly available (e.g., Daisy for the VLDBJ paper, Tabsyn, CoDi) (R4 W2). The benchmark should either include these methods or explain why they are excluded given the stated privacy motivation.
- **Imbalance between fidelity and utility evaluation** (R1 W3): The paper heavily focuses on fidelity (single-column, single-table, multi-table) with extensive analysis, while utility is only assessed on single-table input with limited space (R1 W3). The title and abstract claim fidelity and utility have equal importance, but utility experiments are not comprehensive enough to justify this. Utility experiments should be expanded to include: 1) using regression/classification for estimating different attribute values; 2) joining different numbers of tables and using them as input to train models (R1 W3). The current set only uses single-table input, creating a potential inconsistency with the paper's emphasis on multi-table data generation (R1 question). How multi-table data is input to ML models for utility evaluation needs clarification (R1 question).
- **Insufficient dataset variety and depth of analysis** (R4 W3, R3 W2): Only five datasets are used, which is limited for a robust benchmark; other works (e.g., the diffusion model paper) use ten datasets (R4 W3). The paper does not address the critical distinction between numerical and categorical data types, which require different generation techniques (R4 W4). The main takeaway that single-table assessment fails with current methods is not deeply analyzed: the reason may be that a too weak model (logistic regression) was used as discriminator – this is already known in the subfield (R3 W2). Given that single-table assessment already fails, the multi-table results offer limited additional insight; a more useful test would be to identify cases where single-table does not fail to evaluate the aggregation method's contribution (R3 W2). The paper reports many empirical results but lacks deeper analysis, discussion, or suggested next steps (R3 W2). A clear, consistent conclusion to guide researchers and practitioners is missing (R4 W6).
- **Lack of formalization of relational data** (R2 W1): The notion of relational data is not properly formalized. Key details missing: how parent-child relationships are defined (e.g., via foreign keys) and which attributes participate in the foreign key dependency (R2 W1). A row is defined as a set of values, but since a set is unordered, it is unclear how attribute values are assigned; the notation shows values {v_{p_{T_i}}, v_{k_1}, ..., v_{k_o}, v_{a_1^{T_i}}, ..., v_{a_l^{T_i}}} but the first group of values do not correspond to the table's own attributes, leaving them unexplained (R2 W1).
- **Readability and consistency issues** (R1 W5): Several graphs in the experimental section lack descriptions on the X and Y axes (R1 W5). In Figure 2, the description "Most methods model the parent table (store) better since the tests find more differences for the child table (historical)" applies to (b) but not to (a) (R1 W5). Inconsistency between Section 4.5 (first and third most important features) and Figure 5 (1st and 4th most important features) (R1 W5).
- **Unaddressed questions overlapping with criticisms**: Multiple reviewers raised questions that reflect missing experiments or formal gaps:
  - Why Q-error, a standard measure for query count accuracy, was not adopted (R1 question).
  - How the phrase "generating child rows conditionally on parent rows" is consistent with "propagating errors down the hierarchy" – the former implies parent→child information flow but is described as propagation to the child side (R1 question).
  - How many relational data synthesis methods in each category should be considered sufficient for a robust benchmark (R4 Q1).
  - What minimum number of datasets is required for an effective benchmark (R4 Q2).
  - How real-world applications can justify a single generic fidelity metric, and what makes it suitable across diverse applications (R4 Q3, R4 W5).
  - The fidelity evaluation should be context-dependent; the authors must justify how one metric can encompass diverse applications before proposing a generic metric (R4 W5).
