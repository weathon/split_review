## Merged Review

### Summary
The paper presents Agent-E, a multi-agent system for autonomous web navigation. It uses three LLM-powered agents: a planner agent for high-level task decomposition, a browser navigation agent for executing actions, and a validation agent that checks completion and provides feedback for re-attempts (a self-refinement mechanism). The system introduces flexible DOM distillation (text-only, input-fields, all-fields representations) that adapts to the task, and change observations that monitor state after each action to generate natural-language feedback. Agent-E is evaluated on the WebVoyager benchmark, where it achieves state-of-the-art performance, beating prior text-only and multimodal agents by 10–30% (per one reviewer) or over 16% (per another). The paper also distills lessons from the development into general design principles for agentic systems.

### Strengths
- **Originality**: The hierarchical architecture with distinct specialized agents (planner, browser navigation, validation) is a novel approach to task decomposition and delegation in web agents. The flexible DOM distillation mechanism moves beyond static DOM handling, dynamically selecting representations to reduce cognitive load. The self-refinement mechanism (validation agent feedback enabling re-attempt) and change observations are also original contributions.
- **Performance**: Agent-E achieves superior empirical results on the WebVoyager benchmark, with detailed comparisons to both text-only and multimodal baselines. The ablation that evaluates the impact of the validation agent is included, and the reported gains (10–30% improvement over prior SOTA per one reviewer, or over 16% per another) are strong.
- **Clarity**: The paper tells a clear narrative and well describes the high-level architecture and capabilities of each agent. The DOM distillation and change observation mechanisms are explained in detail in the appendix.
- **Significance**: The work addresses key challenges in web automation – handling complex multi-step tasks and dynamic DOMs. The modular architecture and self-correction pathway are likely to inspire future research on adaptable agent systems and increase reliability in real-world applications.
- **Research direction**: Using LLMs to automatize web tasks is a sensible and timely direction.
- **Extracted learnings**: The paper extracts key design principles (e.g., task-specific agent design) from the method, which are a useful summary of lessons learned.

### Weaknesses
- **Limited benchmarking**: Evaluation is restricted to a single (older) benchmark, WebVoyager. Missing experiments on WorkArena, WebArena, and ST-WebAgentBench. This makes it hard to judge generalization and the state-of-the-art claim (R1, R3). (Reviewer 1 flags this as a major weakness.)
- **Code and implementation details unavailable**: The code is not released, and supplementary materials (e.g., exact prompts used for each agent, detailed architecture of validation agent) are absent. This limits reproducibility, makes it difficult to assess the accuracy of the description, and weakens the theoretical contributions (R3). In particular:
  - The change observation mechanism is not explained: what data is passed to the LLM (DOM before/after, a diff, or something else)? (R3)
  - The architecture of the validation agent – what information it receives to assess task completion and generate feedback – is not described. (R3)
- **Unclear source of performance gains**: It is not clear whether the improvements come from the multi-agent architecture or from the hand-made DOM API. An ablation with a single LLM using the API (without multi-agent decomposition) is missing (R2).
- **Model choice confound**: The validation agent uses gpt-4o while the other agents use gpt-4-turbo; no justification is given for this choice. The observed gains may be partly due to the stronger model. Additionally, only the validation agent uses vision modalities – the asymmetry is unexplored (R2, R3).
- **Unquantified claims**: The claim that “primitive skills we enabled in Agent-E to be enough for the vast majority of general web automation tasks” is not backed by statistics (e.g., proportion of benchmark tasks requiring skills not enabled) (R3).
- **Agent Design Principles lack scientific grounding**: The principles are derived solely from authors’ intuition and do not reference existing literature on agentic architectures, LLM planning, or accuracy optimization with structured data. The principle “Routinely analyze, reflect” uses vague language; it appears to describe production workflow optimization (common tasks turned into reproducible workflows) rather than a scientific insight – the term “reflect” does not refer to fine-tuning, which one might expect (R3).
- **Insufficient related work comparison**: The related work section lists other methods without concisely highlighting the delta between Agent-E and those works (R2).
- **No open-source model experiments**: The paper does not attempt experiments with open-source models or fine-tuning, which could strengthen the work (R2).
- **Computational overhead not evaluated**: The paper does not address the computational cost or scalability of the three-agent architecture compared to simpler single-agent systems; no resource usage benchmarks are provided (R1).
- **Missing architectural ablation**: It is unclear how the three-agent decomposition was chosen; no evidence that other architectures were tried or considered (R3).
- **No comparison to models with built-in chain-of-thought**: The paper does not test whether the hierarchical architecture still provides benefit when using models like o1-preview that can perform task decomposition internally (R3).
- **Missing performance analysis of DOM distillation**: The paper does not analyze how each DOM distillation representation performs under different conditions (R1).
- **Missing study of self-refinement on error types**: The paper does not analyze which types of errors the self-refinement mechanism addresses or its trade-offs (R1).
