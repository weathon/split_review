## Merged Review

### Summary
GraphAgent reframes node classification on text-attributed graphs as an agent planning problem parameterized by an LLM. The agent uses pre-defined actions (“get features”, “get neighbors”) and a memory mechanism to gather information and predict labels via in-context learning. Experiments on Cora, ogbn-arxiv, and ogbn-products (50 samples each) are compared to GNN and MLP baselines. Reviewers find the idea novel but question the experimental evidence, performance, and clarity. Scores: 3, 5, 5, 3 (two low, two high).

### Strengths
- Novel idea of using an LLM as an agent with explicit graph-related actions (get neighbors, get features) to reason about node classification on text-attributed graphs. Reviewer 2 notes this chain-of-thought approach can bring new ideas to the community; Reviewer 3 calls it a novel application of agent planning to graphs with sensible action designs.
- The random-sampling strategy for generating in-context learning examples is considered smart (Reviewer 3).
- Case studies (Figures 2 and 5) illustrate how the LLM uses the actions to gather useful information and yield interpretable predictions. These examples are intriguing and contribute to interpretability (Reviewer 4).
- Reviewer 2 highlights that GraphAgent can compete with supervised learning without needing an external GNN, inspiring further work on LLM-based graph reasoning. (Other reviewers dispute this comparative strength – see Weaknesses.)
- The general exploration of LLMs for graph learning is timely and interesting (Reviewer 1, Reviewer 4).

### Weaknesses
1. **Limited and weak experimental validation.**  
   - Only 50 test samples per dataset, undermining credibility (Reviewer 1).  
   - Performance gap with conventional GNN/MLP methods is large: 9.7% on ogbn-arxiv and 6.5% on ogbn-products are not comparable (Reviewer 1). Reviewer 3 similarly states performance cannot outperform GNN-based methods.  
   - Reviewer 3 notes that GPT-3.5 without the agent can achieve much higher accuracy (67% on Cora, 50% on arxiv, 70% on Product per Chen et al. 2023), yet Table 2 shows low performance for the “gpt-3.5-turbo + ICL” baseline. A better prompt for the baseline should be used.

2. **Missing comparisons and baseline issues.**  
   - No comparison with other LLM-augmented graph models, e.g., GraphText (Ye et al. 2023) and GraphText (Zhao et al. 2023) (Reviewer 4).  
   - An existing graph agent work (Qinyong Wang et al. 2023, “Graph Agent: Explicit Reasoning Agent for Graphs”) is not discussed or compared (Reviewer 4).  
   - Possible test data leakage: GPT’s training corpus includes arXiv papers, so it may already know the paper’s field (test node labels). The authors should test by asking GPT directly for a paper’s category given its text attributes (Reviewer 1).  
   - No quantitative evaluation or further elucidation of the claimed interpretability (Reviewer 1).

3. **Lack of clarity and incomplete presentation.**  
   - Agent prompt only in Appendix, making it hard to understand the method without supplementary (Reviewer 2).  
   - Figure 2 is unclear: which part is LLM output and which is environment response? The actions “get features” and “get neighbors” are shown, but the final answer is given in natural language – the action format is inconsistent (Reviewer 3).  
   - Confusing notations in Section 3.1: e.g., \(f_v\) undefined, \(y_L\)/\(y_U\) labels, and “K is the number of labeled nodes of each category” implying equal K per class (Reviewer 1); \(s_v\) undefined, multiple uses of \(i\) in \(y_i\) and \(c_i\) cause confusion (Reviewer 4).  
   - Section 4.3 description of short-term vs long-term memory is unclear; how are they placed in the context? Provide a concrete example (Reviewer 3).

4. **Novelty concerns.**  
   - The framework appears to be a straightforward application of chain-of-thought reasoning to graphs; novelty is limited (Reviewer 4).  
   - The claim of “parameterizing the agent as an LLM” is not demonstrated – the LLM is inherently pre-parameterized (Reviewer 4).

5. **Missing analyses: efficiency, stability, and generalization.**  
   - No efficiency comparison: actions allow the LLM to process more node information but at additional cost. Show the cost of accessing each dataset via ChatGPT (Reviewer 2).  
   - No discussion of stability: small perturbations may make the agent unstable, affecting reliability and reproducibility (Reviewer 2).  
   - Can the paradigm be applied to other tasks (link prediction, graph classification)? Provide experimental results (Reviewer 4).

6. **Writing and formatting issues.**  
   - Overclaiming: “solution for graph machine learning tasks” but only node classification is studied (Reviewer 1).  
   - Tables and figures should be placed at the top of each page for readability (Reviewer 1).
