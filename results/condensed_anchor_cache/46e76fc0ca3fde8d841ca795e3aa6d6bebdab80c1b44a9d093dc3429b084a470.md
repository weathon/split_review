## Merged Review

### Summary

The paper introduces MobileAgentBench, a benchmark for evaluating LLM-based mobile agents on Android. It provides 100 tasks across 10 open-source apps (from SimpleMobileTools) with multiple difficulty levels, automated evaluation on real devices via a final-state and event-signal judgment, and easy integration with existing agents (minimal code changes). Five agents (AndroidArena, AutoDroid, AppAgent, CogAgent, MobileAgent) are evaluated and baseline performance is reported.

### Strengths

- Addresses an important gap in evaluating mobile LLM agents; essential for advancing the field.
- Automated evaluation on real devices makes testing dynamic and realistic, reducing manual effort and increasing reproducibility.
- Easily extendable and integrable: requires only a few lines of Python code; likely to attract community contributions.
- Evaluation checks final UI state (allowing trajectory variance) – an effective and efficient task success judgment.
- Provides 100 tasks across 10 open-source apps, categorized by difficulty for nuanced evaluation.
- Evaluates five existing agents (AndroidArena, AutoDroid, AppAgent, CogAgent, MobileAgent) and supplies valuable baseline data.
- Open-source and reproducible.
- Convinces on important dimensions: scalability, robustness to diverse action sequences, realistic device-based testing, and ease of integration.
- Multiple difficulty levels allow systematic comparison.

### Weaknesses

- **Scale and scope smaller than existing benchmarks**: SPA-bench has 340 tasks with cross-app settings; MobileAgentBench has only 100 tasks across 10 simple apps from a single developer (SimpleMobileTools), limiting UI diversity, interaction patterns, and complexity. This may not capture real-world mobile interactions. Reviewers explicitly note that tasks are too simple and lack multi-app scenarios; one reviewer asks for more multi-app tasks.
- **Limited metric depth**: Proposed metrics (SR, SE, Latency, Tokens, FFR, OER) are relevant but could be expanded to include robustness to unexpected UI changes, error recovery, and action efficiency. The computation cost metric is limited to cloud-based LLM token cost, not considering local resource constraints on mobile devices.
- **Missing comparison with locally deployed LLMs**: Experiments do not include agents using on-device models like Phi-3, which have unique advantages for privacy and latency.
- **Inadequate analysis and error analysis**: The analysis lacks robustness and depth; detailed error analysis (with failure examples) is missing but needed to understand why success rates are low and to identify bottlenecks.
- **Limited explanation of implementation and protocol**: The underlying protocol for implementing MobileAgentBench is not detailed (hindering reproducibility). The Android Accessibility Service-based event listener app is not fully explained (robustness/reliability of event capture is unclear). The action space formulation is not explained.
- **Writing and presentation issues**: Writing can be improved (e.g., overly detailed related work, space better used for benchmark analysis). Large blank spaces (lines 69–74, 246–249) should be fixed. Limitations and future work section is insufficient on its own and could be merged into conclusion.
- **Missing relevant citation**: OSWorld (benchmark for real computer tasks) is related and should be cited when discussing digital assistant and HCI.
- **Implementation details unclear**: How does the benchmark handle system-level UI (notifications, permission requests)? What is the specific “hit test” for successful button clicks? How are agent / app crashes handled? Why was UIAutomator chosen as backend for AndroidViewClient, and were other backends considered?
- **Disagreement among reviewers**: While most reviewers (score 5, 5, 6) find the benchmark useful, one reviewer (score 3) notes that the writing and presentation issues are significant enough to require improvement before acceptance; that reviewer also considers the benchmark “new” but still sees the weaknesses above as limiting.
