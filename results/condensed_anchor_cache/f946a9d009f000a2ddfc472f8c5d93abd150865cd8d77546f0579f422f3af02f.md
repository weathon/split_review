## Merged Review

### Summary
The paper proposes FoG (Foundation model Guided), a skill discovery method that uses foundation models (LLM for state-based, CLIP for pixel-based) to extract a score function that evaluates states according to human intentions. This score re-weights the intrinsic rewards of an existing skill discovery method (METRA) to encourage desirable behaviors and discourage undesirable ones. Experiments on MuJoCo environments (Cheetah, Quadruped, Franka Kitchen) in both state and pixel spaces show that FoG can avoid hazardous areas and eliminate flipping, rolling, or other dangerous skills.

### Strengths
- The paper is generally well-written and easy to follow; the underlying idea is straightforward.
- The authors adopt the METRA framework, allowing the method to handle image inputs.
- Experiments demonstrate that the proposed method successfully learns diverse skills while avoiding undesirable behaviors, on both object state and image space.
- FoG shows flexibility by being applicable to both state-based and pixel-based tasks.
- FoG demonstrates the ability to learn complex behaviors that are difficult to define, such as ‘twisted’ postures.
- The description of the FoG approach and its score function is detailed.

### Weaknesses
- **Limited novelty.** The core methodology closely resembles the DoDont approach: both use a score function derived from human-provided preferences, and FoG’s objective form is a special case of DoDont’s \(p(s,s')\). Using foundation models simply as an undesirable behavior recognizer is a narrow application; several prior works (e.g., Eureka, VLM reward models) generate full reward functions or propose tasks, which is a more natural use of foundation models. The idea of using a vision-language model to capture human intention has been proposed by Rocamonde et al. (2024).
- **Trivial score function.** For state-based RL, FoG uses ChatGPT to write a threshold function (e.g., `lambda s: s[1] > threshold`), which is a trivial implementation of the score function. For pixel-based RL, FoG uses CLIP similarity (e.g., `CLIP(s', "ground is blue") > CLIP(s', "ground is orange")`) as a binary classifier. One could easily obtain labeled desired/undesired states and train an image classifier for DoDont; the descriptions of “flip over” vs. “stand” and “twist” vs. “stretch” can be trivially distilled from CLIP or human annotators.
- **Unfair baseline comparison.** The comparison to METRA is unconvincing because METRA does not incorporate any human intentions. FoG should be compared with methods that also integrate human intentions, such as METRA+ (used in DoDont), DGPO, and SMERL. No comparison is made with other studies that utilize foundation models for skill discovery (e.g., Rho et al., "Language Guided Skill Discovery").
- **Experiments lack thoroughness.**
  - Only 3 seeds are used; no justification is given.
  - Missing visual comparison between the score functions of FoG and DoDont, especially in pixel-based tasks (Section 4.2). The claim that DoDont “fails” needs to be supported by a performance comparison of the score functions (e.g., FoG’s CLIP vs. DoDont’s image classifier).
  - For the “twisted” vs. “stretched” experiment (Section 4.3), such samples are easy to obtain via MuJoCo UI or by having a VLM label states; this weakens the claim that these behaviors are “hard to define.”
  - The full context/descriptions used to generate the score function are not provided.
- **Score function limitations.**
  - It is unclear how the foundation model develops insights about specific state dimensions (e.g., the cheetah’s front tip angle); there is no guarantee the score functions are always appropriate.
  - The score function only considers the next state \(s'\) (Eq 6). It does not capture process-based alignment (e.g., cutting fruit with a kitchen knife vs. a hacksaw) that depends on the trajectory, only outcome/state-based alignment.
  - When there is no color difference or when the color distribution is the same, the CLIP image encoder would fail because it does not capture motion-related features.
- **Dependency on METRA.** Skills that cannot be generated by METRA likely cannot be generated by FoG either, so the overall performance is bounded by the underlying skill discovery method.
- **Claim regarding learning hard-to-define behaviors is not new.** Preference-based RL (Christiano et al., 2017) has already documented this capability.
- **Questions that overlap with missing experiments or criticisms:**
  - How does FoG relate to Safety-aware unsupervised skill discovery (Kim et al., 2023) and Controlled Diversity with Preference (Hussonnois et al., 2023)? Does FoG provide specific advantages over these works?
  - Is it assumed that the score can be captured purely by observing \(s'\)? What about process-based alignment?
  - Is the score function always binary? If so, does setting \(\alpha>0\) matter as long as \(\alpha<1\)?
  - In Fig 6, is the task to move while being stretched/twisted, or only to be in those positions? Why are videos needed?
  - How would the method handle an agent that starts stretched and later becomes twisted?
  - One reviewer (R2) questions the design choice of using foundation models only as recognizers rather than task proposers. The argument that Eureka requires multiple iterations is not fully convincing.
  - Figure 5 is confusing: the top subfigure shows METRA, DoDont, and FoG all occupying both sides of the plane, contradicting the claim that FoG avoids the right side. Please clarify.
  - The paper mentions that FoG fails in the Franka Kitchen environment, while prior work (Rho et al., 2024) reports useful skill discovery in similar robotic arm environments. What underlying difference leads to this result?
- **Typos:** Lines 244, 257-258, 395.
