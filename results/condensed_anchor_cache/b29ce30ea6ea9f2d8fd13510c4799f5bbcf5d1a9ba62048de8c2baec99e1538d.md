## Merged Review

### Summary
The paper proposes AnyGraph, a graph foundation model built on a Graph Mixture-of-Experts (MoE) architecture. It aims to handle structure heterogeneity, feature heterogeneity, fast adaptation to new domains, and scaling law emergence. AnyGraph uses SVD for dimension alignment of graph structures and node features (Eq. 5), employs multiple expert models trained on edge samples via link prediction, and routes new graphs to the best expert using a competence score (Eq. 4). Experiments on 38 graph datasets report strong zero-shot link prediction and node classification performance, outperforming baselines trained with few-shot data. The model is also claimed to follow a scaling law and to use only 1/K of the memory resources of non-MoE models.

### Strengths
- **Tackles an important problem**: The paper addresses the challenging goal of building a graph foundation model that can efficiently adapt to diverse graph domains and tasks, handling structure and feature heterogeneity [Reviewers 1, 2, 3, 5]. Reviewer 5 specifically notes that the ambition of exploring graph foundation models without relying on LLMs is rare and commendable.
- **Use of Mixture-of-Experts (MoE) architecture**: The MoE design with a graph expert routing mechanism (using dot-product-based relatedness scores for positive and negative edges) is considered a sound and effective approach for cross-domain heterogeneity [Reviewers 1, 2, 3].
- **SVD for feature unification**: The use of SVD to align different feature spaces (Eq. 5, lines 224-225) is seen as a nice idea [Reviewer 1], and the unified mapping function is a key component [Reviewer 3].
- **Strong empirical results**: The paper provides extensive experiments on 38 datasets showing superior zero-shot prediction performance compared to baselines’ few-shot (10% training data) performance [Reviewers 1, 3]. The ablation studies demonstrate the positive contribution of individual components [Reviewers 1, 3].
- **Scaling law demonstration**: The paper reports that AnyGraph’s performance scales with model parameters and data size, which is impressive [Reviewer 3]. (But see weaknesses for minority skepticism.)

### Weaknesses
- **Hard to read and missing problem definition**: The paper is very hard to follow. The abstract and introduction do not clearly define the problem (prediction, generation, etc.); it only becomes clear in Section 2 [Reviewers 2, 4]. Figures are unclear (e.g., Figure 2 not understandable, Figure 4(c) missing, “-Feat” undefined), notations are poorly explained (e.g., \(v_{c1}, v_{p1}\) in Section 3.1, \(\hat{y}_{max}\) in Eq. 9, \(S\) in Eq. 3, subscripts for expert \(k\) missing), and tables lack captions/definitions (e.g., Table 2: what is “Baseline”, “AnyGraph-F”? Columns confuse GraphGPT and OpenGraph) [Reviewers 2, 4]. Reviewer 5 (minority) found the presentation nice, but the majority of reviewers rated presentation as low (1 or 3).
- **Generalization to truly novel domains is unclear**: The test graphs are from similar academic/social groups; the method may not generalize to fundamentally different domains (e.g., patient-doctor-diagnoses graphs) [Reviewer 1]. The routing mechanism selects the best expert, but if all training domains differ significantly from a new domain, no expert can perform well [Reviewer 3]. Additionally, the “cross-domain” claim is weakened because Link 1 and Link 2 training sets have overlapping domains [Reviewer 5].
- **Semantic alignment across datasets not convincingly solved**: Using SVD for dimension alignment and link prediction as a training target does not guarantee that features from different datasets are in the same latent semantic space. The feature heterogeneity problem may remain unsolved; the positive results might be due to the selected datasets sharing feature semantics by chance [Reviewer 5]. Reviewer 2 also questions similarity to NetInfoF and asks for a comparison.
- **Structure heterogeneity not adequately tested for heterophily**: The paper does not evaluate on heterophilic graphs. The embedding combination via addition (Eq. 6, line 243) may fail under heterophily; concatenation would be better (citing SlimG paper) [Reviewer 1]. There is no explicit solution for structure heterogeneity that handles both homophilic and heterophilic graphs together [Reviewer 5].
- **Scaling law claims are not convincing**: The observed performance range is narrow (∼0.1–0.2), and the model size and data scale are far smaller than counterparts in NLP. Graphs have “unlimited tokens,” making direct analogy to scaling laws in language models questionable. Extending the x-axis further is needed [Reviewer 5]. Reviewer 3 accepts the scaling law, but the minority view raises strong doubt.
- **Comparison with graph prompting baselines is logically flawed**: Comparing AnyGraph (a graph foundation model) with graph prompting methods applied to GNNs is like comparing GPT-4 with a prompted GPT-1; one is the model and the other is a usage technique. These comparisons in Table 1 are therefore meaningless [Reviewer 5]. Additionally, the setup of Table 2 is confusing and lacks justification for why certain baselines were chosen [Reviewers 2, 4].
- **Missing comparison with full-training baselines and large-scale graphs**: The paper compares AnyGraph zero-shot against baselines’ few-shot (10% data) but not against baselines trained on the full training set. This leaves unclear the gap to full supervision [Reviewer 2]. Evaluation is limited to graphs with at most 1M nodes; large graphs like ogbn-products or ogbn-paper100M are not tested [Reviewer 2].
- **Unjustified design choices**: Several aspects lack clear intuition or justification:
  - In Eq. (5), the Flip() function aligns important features of the adjacency matrix with less important features of the feature matrix; this seems counterintuitive [Reviewer 3].
  - In Eq. (4), the training frequency regularization uses \(+1.0 - \rho/2\) without explanation [Reviewer 3].
  - The use of adjacency matrices for initial node embeddings is not justified, and they are used twice (in initialization and message passing) [Reviewer 2].
  - The preprocessing for feature and structure augmentation is unspecified [Reviewer 2].
- **Memory and efficiency claims not properly justified**: The claim that AnyGraph consumes only 1/K of computational and memory resources compared to non-MoE models is unsubstantiated. All experts must be stored in memory, and the routing adds overhead. A memory complexity analysis is missing; training K separate models would require similar memory [Reviewers 2, 4].
- **Cannot handle heterogeneous graphs**: The model is designed only for homogeneous graphs with numerical node attributes; it cannot handle graphs with multiple node/edge types [Reviewer 2].
- **Reproducibility details missing**: The paper is not self-contained; many experimental details are only in the appendix (which reviewers are not required to read) [Reviewer 4]. Missing information includes:
  - Per-dataset evaluation results for Table 1 [Reviewer 2].
  - A clear definition of zero-shot: whether the test set overlaps with training data or is a completely new dataset [Reviewer 4].
  - How baselines were set up (same datasets? full training?) [Reviewer 4].
  - How the number of experts was chosen (why 7?). Impact of fewer or more experts is not studied [Reviewer 2].
  - Dataset sources and citations are missing in Appendix A.1 [Reviewer 3].
- **Concern that the model might not really classify node labels**: The model is trained on link prediction, and it is unclear how it can correctly predict node labels without considering labels in the process [Reviewer 4].
- **Equation and notation issues**: Several reviewers point out specific missing definitions (e.g., \(d_0\) in line 127, \(S\) in Eq. 3, \(\hat{\mathbf{e}}_i\) as node embedding, subscript \(k\) missing from Eq. 3) [Reviewers 2, 4]. A table of symbols and definitions would help [Reviewer 1].
- **Minor**: Paper lacks total wall-clock training and inference time and hardware specifications (only per-100-step time given in Table 3) [Reviewer 1]. Acronyms should be defined before use (line 242) [Reviewer 4]. Figure 1 is not mentioned in text [Reviewer 4]. Typo: “topologies.Furthermore” (line 94) [Reviewer 4].
