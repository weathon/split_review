## Merged Review

### Summary
The paper introduces X-VILA, an omni-modality model extending LLMs to handle image, video, and audio input and output. It uses modality-specific encoders, a large language model (LLM), and diffusion decoders. A key component is the Visual Embedding Highway (VEH) module to prevent visual information loss. The authors also curate an X-to-X multi-modal instruction-tuning dataset. X-VILA is evaluated on cross-modality understanding, reasoning, generation, and some general QA/caption benchmarks.

### Strengths
- **Original contribution of Visual Embedding Highway (VEH):** VEH is highlighted as a significant advancement over existing visual alignment methods, preserving visual details and improving performance (Reviewers 1, 2, 3, 4). Reviewer 3 considers it a “significant advancement” (score 8). Reviewer 2 notes it “makes sense.”
- **Valuable large-scale X-to-X dataset:** The curated instructional tuning dataset is considered a helpful resource for multi-modality generation research (Reviewers 2, 3, 4).
- **Surpasses Next-GPT on compared benchmarks:** The proposed method outperforms Next-GPT on multi-modal generation benchmarks (Reviewer 2).
- **Thorough methodology and evaluation:** The paper is well-written, well-structured, and provides a comprehensive performance evaluation (Reviewers 1, 4). Reviewer 4 highlights high quality, thorough experiments, and rigorous evaluation.
- **Open-source plan:** Authors commit to releasing code and data, promoting reproducibility and follow-up research (Reviewer 3).

### Weaknesses
- **Limited novelty:** The overall architecture (multimodal encoders + projectors + LLM + diffusion decoders) has been extensively explored in prior works (Next-GPT, CogView, Emu, AnyGPT). The paper offers performance improvements rather than new fundamental insights (Reviewers 1, 2). In contrast, Reviewer 3 (score 8) did not consider this a major weakness.
- **VEH only applied to visual modality:** Despite the paper’s any-to-any claim, the highway module is implemented only for vision, raising questions about scalability and generality. This contradicts the stated cross-modality objective (Reviewers 1, 4). One reviewer suggests VEH seems designed for edit-like tasks, not a general design (Reviewer 2).
- **Weak performance on standard QA/caption benchmarks:** Visual QA and audio caption results are too weak (Reviewer 2). The use of Imagebind as a universal encoder is questioned – replacing it with specialized encoders (e.g., CLIP for vision, Whisper/Beats for audio) could likely improve performance (Reviewer 2).
- **Insufficient comparisons:** Only Next-GPT is compared. More baselines (e.g., AnyGPT, Emu series) are needed (Reviewer 2).
- **Missing ablations on dataset scaling:** The larger instruction tuning dataset used versus Next-GPT may partly explain gains, but no ablation studies isolate its effect (Reviewer 4). Also, data quality of the X-to-X dataset is not ensured; creation process not detailed (Reviewer 4).
- **Confusion in training and architecture details:**
    - Stage 1 “encoder-LLM-decoder alignment training” description is unclear – what does the decoder train on? (Reviewer 2)
    - Figure 1 example lacks a “video” input component, disrupting clarity (Reviewer 3).
    - The long-context claim in Figure 4 is questionable; the context is not long enough (Reviewer 2).
- **Modality interaction and scalability concerns:**
    - How does modeling in one modality affect another (e.g., audio on image)? This interaction is not addressed (Reviewer 1).
    - The architecture appears to require LLM re-training for adding new modalities, limiting true any-to-any scalability (Reviewer 1).
- **High computational costs:** Training is resource-intensive, potentially limiting accessibility and reproducibility for smaller groups (Reviewer 3). Reviewer 3, despite a high score (8), notes this as a weakness.
