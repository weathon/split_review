## Merged Review

### Summary

This paper introduces EASE (Evolvable Symbolic Visual Grounder), a fully interpretable symbolic framework for 3D visual grounding. It uses an LLM to translate grounding descriptions into symbolic expressions and generates explicit Python programs for relation encoders, learned from a small subset of training data via an LLM-based self-refinement loop with unit-test feedback. Experiments on ReferIt3D report 50.7% accuracy on Nr3D, surpassing most training-free methods, and competitive performance on Sr3D, while achieving substantially reduced inference time and token costs compared to agent-based LLM methods.

### Strengths

- **Low inference cost and high efficiency**: EASE significantly reduces inference time and token costs compared to agent-based LLM models, making it practical for large-scale deployment (R1, R2, R4). Reviewer 5, however, notes that a quantitative efficiency proof is missing.
- **Eliminates human-provided relation annotations**: By generating Python code with LLMs and refining it via a unit-test-based feedback loop, EASE autonomously produces relation encoders without manual annotation effort (R1, R6).
- **Weak supervision reduces data reliance**: The program library is learned from a tiny subset of training data, reducing dependence on large-scale annotated data (R4).
- **Full interpretability of the symbolic pipeline**: The explicit program-based relation representation enables step-by-step reasoning, providing interpretability beyond end-to-end and black-box LLM methods (R1, R4, R6).
- **Novel and interesting approach**: Using self-reflective PLM code generation for 3D visual grounding is a novel application avenue (R3, R5). The idea is considered effective and well-motivated (R3).
- **Thorough experiments and ablation studies**: Experiments cover easy vs. hard splits, view-dependent vs. view-independent conditions, and include comprehensive ablation studies that provide insights (R1, R3, R5).
- **Surpasses training-free methods**: On Nr3D, EASE outperforms most training-free baselines (R6). However, Reviewer 2 notes it does not surpass Transcrib3D.

### Weaknesses

- **Over-reliance on LLMs and question of novelty**: The framework heavily depends on LLMs for description parsing, code generation, and refinement. Multiple reviewers question the originality beyond applying existing LLM-based approaches (R2, R4, R5, R6). Reviewer 2 asks for a clear specification of distinct technical innovations versus existing methods. Reviewer 5 points out that the prompt design in the Appendix includes expert-level knowledge (e.g., helpful tips in lines 718-730), contradicting the claim of relieving human expertise; an ablation that removes such hints is suggested. Reviewer 6 argues that using LLMs is not justified—50.7% accuracy is not compelling—and recommends either a comprehensive analysis of LLM suitability for this task or a direct comparison with SOTA methods. (Reviewer 3, the most positive, finds the idea interesting but defers to colleagues.)
- **Interpretability limitations**: While the symbolic pipeline is interpretable, the internal workings of the LLMs remain a black box, limiting overall interpretability (R2, R4). Furthermore, the code refinement process may not resolve deeper logical errors or misinterpretations from the LLM (R1).
- **Performance gap relative to Transcrib3D not addressed**: Reviewer 2 notes that EASE does not surpass Transcrib3D (which also uses LLMs) and the paper lacks a comparative analysis to explain the performance gap and clarify methodological differences. This weakens the claim of superior performance.
- **Poor writing and insufficient explanation of figures**: Multiple reviewers criticize the writing quality. Reviewer 5 says the writing is hasty; Figures 1-3 are not well explained in the text, making it hard to correlate figure content with description. Figure 2 (method comparison) is too messy to convey novelty clearly. Reviewer 6 adds: Figure 1 is not referenced, Figure 2’s caption misaligned with its diagram, legends are too small, and Figure 6 is low-resolution. The introduction lacks discussion of related agent-based approaches and the significance of the problem (R6). The paper lacks self-containment and sufficient background, hurting readability (R6). Minor errors include “we constraints...” on line 528 (R2) and repetitive lines 087-089 (R5). (In contrast, Reviewer 3 finds the paper well-organized and easy to follow.)
- **Simplified scene representation**: The system represents scenes as a list of 3D bounding boxes, omitting object orientation, texture, and color, which may be vital for nuanced tasks. Handling complex relations or compound instructions may require significant modifications (R1).
- **Strong engineering nature**: A significant part of the work explores prompt engineering to make LLMs generate better Python code, which is difficult to evaluate as academic research (R4).
- **Other reviewer-identified issues and questions** (overlap with criticisms or missing experiments):
  - Can the framework adapt to other 3D visual grounding tasks outside ReferIt3D? (R1)
  - How does performance vary with different LLMs (e.g., GPT-4 vs. others)? (R1)
  - Can iterative code refinement be parallelized to reduce computation? (R1)
  - Could reinforcement learning further optimize LLM-generated code for relation encoding? (R1)
  - What are the specific contributions to the logical reasoning module, and what are its strengths and limitations? (R2)
  - An actionable ablation is needed: remove the expert-level hints from the prompt and observe performance (R5).
