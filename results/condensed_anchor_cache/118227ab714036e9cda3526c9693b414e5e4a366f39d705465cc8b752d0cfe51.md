## Merged Review

### Summary

This paper introduces Think-on-Graph 2.0 (ToG-2), a hybrid RAG framework that integrates unstructured text and structured knowledge graphs (KGs) in a tightly coupled manner to improve retrieval quality and reasoning accuracy for LLMs. By alternating between KG-guided context retrieval and context-enhanced graph retrieval, ToG-2 iteratively refines the search for in-depth clues. Experiments across six datasets (multi-hop KBQA, complex document QA, slot filling, fact verification) show state-of-the-art performance on 6 of 7 benchmarks with GPT-3.5, and can elevate smaller models (e.g., LLAMA-2-13B) to the level of GPT-3.5 direct reasoning. One reviewer gave a score of 8 (confidence 3) and found the contributions more significant; the other three reviewers each scored 6 (confidences 5,5,4) and noted several limitations.

### Strengths

- **Tight-coupling approach is well-motivated and novel.** Reviewers agree that using KGs to guide document retrieval while treating documents as entities in the KG creates a beneficial feedback loop. This hybrid approach is considered a systematic, coherent methodology that surpasses previous hybrid RAG methods.
- **Iterative retrieval mimics human reasoning.** The process of refining search based on initial results is intuitive and effective.
- **Comprehensive evaluation.** Experiments cover six datasets across four distinct tasks (multi-hop KBQA, multi-hop complex document QA, slot filling, fact verification). Baselines include CoT, text-only RAG, KG-based RAG, and hybrid RAG. Ablation studies, efficiency analysis, and case studies are provided.
- **State-of-the-art performance.** ToG-2 achieves SOTA on 6 out of 7 knowledge-intensive datasets (all reviewers). Table 1 shows superiority over well-set benchmarks.
- **Implementation details and reproducibility.** The paper provides detailed pseudocode and implementation guidance, making the method reproducible.
- **Figures and graphics are well-done.** They aid understanding of the methodology.
- **Analysis depth.** Manual analysis of error cases and runtime studies provide valuable insights.

### Weaknesses

- **Incremental contribution over ToG 1.0.** One reviewer noted that core improvements—adding context-retrieval and context-guided entity pruning—are not transformative. Another reviewer (score 8) considered the approach more novel, showing reviewer disagreement.
- **Statistical significance not reported.** No tests (e.g., two-tailed t-test) are conducted to determine if performance gaps in Table 1 are significant; improvement is subtle in some columns. Ablation results also lack significance measures. (Reviewer 1)
- **Effect of KG quality not quantified.** The framework’s performance likely depends on KG completeness, but this is not studied. The quality of the newly created ToG-FinQA KG is unknown. A suggested experiment is to use incomplete WikiData (e.g., with 10%, 20%, 50% entities/relations). (Reviewer 1)
- **High financial cost due to frequent LLM API calls.** Processes such as Knowledge Exploration, Relation Pruning, Relation Discovery, Entity Pruning, and Reasoning all require LLM calls. The methodology is financially demanding and may deter further research; a refined cost analysis and optimization suggestions are needed. (Reviewer 2)
- **Efficiency concerns.** The approach is time-consuming; Table 3 shows laborious times for Relation Pruning, Entity Pruning, and Reasoning. Table 7 must clarify whether times are per query or per iteration. Total runtime and API call counts compared to direct LLM methods and text-based RAG are missing—evaluating only against ToG 1.0 is not impartial. (Reviewer 2)
- **Why does ToG (version 1) outperform ToG-2 on Creak dataset?** A detailed analysis of performance on Creak—including potential reasons and implications—is missing. (Reviewer 2)
- **Scalability analysis lacking.** There is insufficient discussion about how ToG-2 scales with very large KGs or document collections and how performance changes when entity linking fails. (Reviewer 3)
- **Error analysis is not systematic.** Although some manual analysis exists, a more systematic categorization of failure modes and potential strategies to address them is needed. (Reviewer 3)
- **Hyperparameter sensitivity analysis incomplete.** Only width and depth are studied; impact of other parameters (e.g., threshold for relation pruning, number of candidate entities) is not explored. (Reviewers 3 and 4)
- **Analyzing relation pruning threshold and its contribution.** No analysis of threshold scores for relation pruning (e.g., how performance varies with threshold, distribution of scores). The threshold of 0.2 is present in the code but not mentioned in the manuscript. Furthermore, Table 6 shows that removing relation pruning (along with topic pruning and retrieval feedback) actually increases performance across all datasets—this nullifies the claimed contribution of relation pruning. (Reviewer 4)  A question is raised: does ToG-2 perform better without relation pruning when topic pruning and retrieval feedback are also removed? (Reviewer 4)
- **ToG-FinQA dataset is small.** With only 97 QA pairs, the domain-specific evaluation is limited; a larger dataset would strengthen this analysis. (Reviewer 3)
- **Classification as Hybrid RAG.** The main figure and text distinguish ToG-2 from Hybrid RAG, but it is essentially a fancy version of Hybrid RAG (selecting n-order neighbors of query entities). It should be considered a Hybrid RAG approach. (Reviewer 4)
- **Figures need improvement.** The main figure lacks a caption explaining the methodology flow; important details (e.g., relation/entity scoring, prompts used) are not depicted. Creating an additional figure with these details is suggested. (Reviewer 4)
- **Grammatical and formatting errors.** Specific issues: missing space between “issues” and “(Zhao et al., 2024)” (page 1); unclear query wording (“born who almost broke”); unorthodox “and” between equations 2 and 3; missing space in “Figure2”; stray “a” in “Given a topic entities”; double parentheses in citations in Section 4.2; missing space in “Width&Depth Settings”; ablation Table 6 should be in main content, not appendix. (Reviewer 4)
- **LLM experiments should be repeated multiple times** given inherent variance in LLM outputs. (Reviewer 4)
- **Additional technical questions left unanswered:**
  - How does ToG-2 improve efficiency if considering more entities (via KG neighbors) than just query-extracted entities? (Reviewer 4)
  - In Figure 3b, why does performance of ToG-2 with BGE-Ranker decrease as the number of entities increases (e.g., from 38% to 33% when jumping from 3 to 5 entities)? (Reviewer 4)
  - Why not use a dynamic number of candidate topic entities per iteration (e.g., first-order neighbors may be more important)? (Reviewer 4)
  - What is “CMB” with respect to relation pruning (equation 3, tables 11 & 12)? (Reviewer 4)
