## Merged Review

### Summary
The paper introduces LiveCodeBench, a dynamic benchmark that continuously collects new coding problems from LeetCode, AtCoder, and CodeForces, aiming to evaluate LLMs for code with minimized contamination. Beyond code generation, it covers self-repair, code execution, and test output prediction. The authors evaluate over 50 LLMs (1.3B–70B) on more than 600 problems published between May 2023 and May 2024. Time-segmented analyses reveal contamination, overfitting on HumanEval, and saturation of existing benchmarks. Reviewers overall found the benchmark practical and the analyses informative, but raised concerns about novelty, reliability, representativeness, and the choice of tasks.

### Strengths
- **Dynamic, contamination‑free evaluation:** The live‑update mechanism and time‑segmented analysis allow fair evaluation by testing only on problems after each model’s cutoff date. This provides direct evidence of contamination (e.g., performance drops after release date) (Reviewers 1,2,4).
- **Difficulty‑guided curation:** Filtering by platform‑labeled difficulty levels improves differentiation between models of similar size, making comparisons more meaningful (Reviewers 1,4).
- **Clustering for overfitting detection:** A clustering method identifies models that overfit HumanEval, offering empirical evidence beyond anecdotal concern (Reviewer 4).
- **Large‑scale, multi‑task evaluation:** 50+ models are benchmarked across four tasks (code generation, self‑repair, code execution, test output prediction), providing a broad reference for the community (Reviewers 1,2,3).
- **Well‑written and thorough:** The paper is clearly organized, and the appendix includes legal compliance details and benchmark‑creation steps (Reviewer 2).
- **Benefiting the community:** The benchmark will be continuously updated and released with prompts/completions, encouraging rigorous evaluation (Reviewer 3).

### Weaknesses
- **Limited novelty:** Dynamic benchmarking has been used as early as 2021 [1‑4], data contamination has been examined in prior works [5,6], and competitive programming problems are a well‑adopted source. The evaluation scenarios (e.g., test output prediction) are adapted from prior work. One reviewer (score 8) was more positive overall, while others (scores 5‑6) found the novelty modest (Reviewers 1,2,4).
- **Small problem pool raises reliability concerns:** With ~40 LeetCode problems every two months, the sample size is small. The paper does not estimate variance or statistical significance of pass@1 comparisons (Reviewer 2).
- **Unproven data representativeness:** No rigorous analysis of problem‑type distribution, difficulty levels, or coverage of programming concepts (e.g., graph vs. dynamic‑programming problems) is provided. It is unclear whether the benchmark reflects the diversity of real‑world coding challenges (Reviewer 3).
- **Workflow reliability not evaluated:** The automated extraction pipeline (e.g., HTML parser accuracy) lacks error analysis. The frequency and impact of extraction errors on problem interpretability are unknown (Reviewer 3).
- **Test case completeness unanalyzed:** The average of 18 test cases per problem is far fewer than competition platforms use; the sufficiency and coverage of edge cases and boundary conditions are not justified (Reviewer 3).
- **Biased filtering:** Problems with multiple correct outputs are removed, potentially introducing bias toward single‑solution tasks. The impact on representativeness and evaluation of models suited for multi‑solution problems is not analyzed (Reviewer 3).
- **Multi‑step evaluation missing:** Only one‑step revision is tested, while state‑of‑the‑art competition‑level code generation (e.g., AlphaCodium) uses multi‑step iterative refinement. This limits the benchmark’s scope for real‑world software development (Reviewer 3).
- **Olympiad vs. real‑world code:** OI/competitive‑programming problems differ stylistically from real software engineering. Recent work (SWE‑bench, RepoBench) focuses on open‑source projects, making LiveCodeBench less representative of practical coding (Reviewer 4).
- **Unaddressed re‑phrasing contamination:** The benchmark does not detect or mitigate re‑phrasing‑based contamination, e.g., equivalence checking of test cases or canonical solutions (Reviewer 1).
- **Rating bias across platforms:** Problems from CodeForces are generally harder than LeetCode/AtCoder, but the potential selection bias in platform‑labeled difficulty ratings is not addressed (Reviewer 4 question).
- **Similarity of tasks:** Code execution and test output prediction appear very similar (the latter is a natural‑language version of the former). No correlation analysis is provided to clarify their distinction (Reviewer 4 question).
- **Unconventional test generation formulation:** The test output prediction task uses (input, NL function description) → output, whereas practical test generation (e.g., Copilot) uses (input, code) → output. The choice is not motivated (Reviewer 4 question).
- **Long‑term maintenance required:** The benchmark’s value depends on continued updates, but no detailed sustainability plan is presented (Reviewer 3 question).
