## Merged Review

### Summary
This paper introduces the Instance Feature Generation (IFG) task, aimed at ensuring both positional accuracy and feature fidelity in generated instances, and proposes the Instance Feature Adapter (IFAdapter). IFAdapter uses learnable appearance tokens (via a perceiver-like Resampler) to extract instance-specific features from descriptions, and constructs a 2D Instance Semantic Map (ISM) with gated semantic fusion to link instance features to spatial locations and resolve feature leakage in overlapping areas. The plug-and-play module is tested on a new COCO IFG benchmark (annotated with VLMs) and evaluated with a verification pipeline. Qualitative and quantitative results show superiority over baselines.

### Strengths
- **Important task and benchmark:** The IFG task and the accompanying benchmark/verification pipeline address a relevant problem. (R1, R2, R4)
- **Novel perceiver-like Resampler design:** The fixed-set appearance token extraction from detailed instance captions and bounding boxes is novel and effective. (R3)
- **Gated semantic fusion mechanism:** This is very useful for handling overlapping instances in layout-to-image generation. (R3)
- **Plug-and-play adaptability:** The method is architecture-agnostic and can be integrated into various community models. (R2, R4)
- **Strong qualitative results:** Visual comparisons show clear superiority against competing baselines. (R2, R1)
- **User study:** The paper includes a user study, providing additional evaluation insight. (R4)
- **Well-written and easy to follow.** (R2)

### Weaknesses
- **IFG task not new:** InstanceDiffusion (Wang et al. 2024c) already introduced the same setup using detailed instance captions plus global caption and bounding boxes. The paper does not clearly differentiate its task from prior work. (R3)
- **Unfair experimental comparison:** All main baselines (InstanceDiffusion, GLIGEN) use SD1.5, while IFAdapter uses SDXL, a more powerful base generator. Improvements in Tables 1 and 2 are confounded. Authors should report results with SD1.5 or retrain InstanceDiffusion on SDXL to support claims. (R3)
- **Benchmark and metric not justified:** Authors introduce a new benchmark (COCO IFG) and metric (IFS Rate) without using the exact evaluation setup of InstanceDiffusion (COCO/LVIS val sets, YOLO-based detection). They should first compare on existing rigorous benchmarks and quantitatively justify why VLMs (used for both annotation and evaluation) are better than CLIP for this task. Potential unfairness if the same VLM is used for annotation and evaluation. (R3, R1)
- **Dataset quality not assessed:** All ground truth annotations are generated by VLMs (prone to hallucinations). No human-level quality evaluation is provided. A detailed analysis of VLM error types/frequencies is needed to understand dataset limitations. (R4, R1)
- **Misleading "without retraining" claim:** IFAdapter is a training-based module; "seamlessly empower...without retraining" only holds within the training data distribution (COCO). Zero-shot capability is not demonstrated. (R4)
- **Semantic-instance map lacks novelty:** Using a 2D semantic map to link instance features to spatial locations is common in prior layout-to-image methods (e.g., BoxDiff, ICCV 2023). The paper does not adequately highlight technical differences or advantages over such zero-shot methods. (R4)
- **Appearance tokens show minor improvement:** In Table 3, adding appearance tokens yields only small gains. The paper needs to explain when these tokens help and when they do not, and justify the added complexity. (R4)
- **Missing computational cost analysis:** The additional attention layers from Appearance Tokens and Instance Semantic Map introduce overhead in inference. The paper should analyze memory usage, inference time, and scaling with number of instances. (R2)
- **Unstable object size/shape across community models:** In Fig. 4, object sizes and shapes appear unstable when applying IFAdapter to different base models, possibly due to the re-weighting strategy from ISM. Robustness concerns should be investigated. (R2)
- **No evidence that network *f* learns importance scores:** The paper claims a lightweight network *f* predicts an "importance" score for each location in ISM construction, but provides no qualitative or quantitative evidence that *f* learns this without direct supervision. (R3)
- **Missing visual comparisons between generated images and ground truth (GT):** Visual comparisons of GT vs. generated images would help assess fidelity. (R4)
- **Limited handling of complex spatial relationships:** The paper does not discuss how the method copes with intricate spatial relationships or out-of-domain prompts (e.g., "a blue dog with red legs running on a colorful river" with multiple boxes). Such limitations of the method should be addressed. (R2)
- **Method clarity and baseline details:** The method details (e.g., why Fourier+MLP from bounding boxes can extract appearance features without image input) and dataset construction / baseline settings are insufficiently explained. (R1)
- **Textual error:** A sentence appears twice in succession in the Introduction. (R1, R3)
- **Minority reviewer (R3, score 5) is more critical:** R3 stresses that the IFG task is not novel, the experimental comparison is unfair, and the benchmark/metric are unnecessary. This reviewer also questions the contribution of point 3 (comprehensive experiments) and the related work section's lack of differentiation. (R3)
