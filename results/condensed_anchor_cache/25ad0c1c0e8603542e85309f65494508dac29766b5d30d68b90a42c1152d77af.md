## Merged Review

### Summary
The paper proposes three guardrailing models: TaskGuard (single-policy, fine-tuned on synthetic data), MultiTaskGuard (multi-policy pre-trained on large synthetic multi-task data), and UniGuard (merges TaskGuard and MultiTaskGuard via search-based model merging). It claims state-of-the-art performance across 11 benchmarks, outperforming GPT-4o and LlamaGuard with sub-1GB classifiers. Reviewers are sharply divided: one (score 8) finds the merging approach technically sound and novel; the other three (scores 1, 3, 3) cite major clarity, reproducibility, and fairness issues. All agree the problem is important.

### Strengths
- Superior accuracy and efficiency: sub-1GB classifiers (e.g., RoBERTa) achieve SOTA guardrailing, outperforming GPT-4o and LlamaGuard by an average 21.62 and 29.92 F1 respectively on 7 public + 4 new benchmarks (Reviewers 1, 4; also noted by Reviewer 3).
- Comprehensive evaluation on 11 datasets (Reviewer 1).
- Novel, technically sound approach for merging multiple guardrails across multiple policies into one model using multi-armed bandit search (Reviewer 3, the minority positive reviewer; score 8).
- Resource efficiency: based on synthetic data and small models, without high demand for computation or hosting (Reviewer 4).

### Weaknesses
- **Missing hyperparameters and reproducibility details**: Key parameters λ, k, n are not specified; synthetic data generation details (meta prompt, self-reflection template, sample outputs) are absent (Reviewers 1, 4). This makes reproduction and sensitivity analysis impossible.
- **Missing ablation studies**: No ablation of the multi-task training loss components (line 173) – unclear relative importance of each (Reviewer 1). No ablation comparing merging only TaskGuard models vs. only MultiTaskGuard models vs. both (Reviewer 4). Over-refusal rate on xstest not reported (Reviewer 1, Q5).
- **Unclear data statistics and processing**: Training/validation/test splits, counts of safe/unsafe samples, policy definitions, and criteria for borderline/in-domain/out-of-domain samples are not given. Whether syntactic augmentation for noise robustness was used is not stated (Reviewer 1).
- **Unfair comparison setting**: Baseline LLMs (GPT-4, LlamaGuard) are presumably tested zero-shot, while TaskGuard/MultiTaskGuard are trained on real or synthetic data tailored to each benchmark. No comparison to a fine-tuned LLM (e.g., Llama2-7B tuned on the same training data) is provided (Reviewer 4; also Reviewer 2 notes missing GPT model version, prompt details, few-shot setting).
- **Presentation and clarity issues**: Paper is hard to follow: uses “1GB classifier” oddly, unnecessary abbreviations (SDG), inconsistent math symbols (P_name vs. P_i), incorrect escape characters (line 169 “\n”). Related work is given as links instead of citations (lines 258–265). Tables lack reasonable captions (Reviewer 2). No appendix despite promising details there (Reviewers 2, 4). Proposed methods (synthetic data generation, model merging) are not clearly introduced (Reviewer 2). It is unclear what output MultiTaskGuard provides per class (e.g., confidence levels) and how multi-policy output is structured (Reviewer 3).
- **Modest improvement from model merging**: The proposed MMS (UniGuard) yields only modest gains, raising questions about its practical utility given added complexity (Reviewer 1). Cost of model merging compared to baseline is not reported (Reviewer 1, Q6).
- **Missing input format details**: Whether TaskGuard and MultiTaskGuard share the same input schema is not stated; if not, merging them is anomalous (Reviewer 4). Input format for all three models during inference is not specified (Reviewer 1, Q3). Number of training stages and policy examples are missing (Reviewer 1, Q1, Q2).
- **Extensibility not addressed**: How to incrementally add new policies without degrading original performance is not discussed; MultiTaskGuard and UniGuard may fail on new, unseen policies (Reviewer 4).
- **Potential data contamination**: Unclear whether the training data used for data synthesis overlaps with the public benchmark test sets (Reviewer 1, Q7). Backbone model used in Table 3 is not named (Reviewer 1, Q8).
- **Missing public release details**: No commitment to release the new test sets (Reviewer 2).

**Reviewer disagreement**: One reviewer (score 8) considers the merging approach technically sound and novel, while the other three (scores 1, 3, 3) find the paper insufficiently clear, reproducible, and fairly evaluated. The positive reviewer’s sole weakness is the lack of clarity on multi-class output; the negative reviewers cite numerous missing details and unfair comparisons.
