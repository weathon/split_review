## Merged Review

### Summary
The paper proposes Q*, a framework that guides LLM decoding during multi-step reasoning by learning a plug-and-play Q-value model from offline data and then using it as a heuristic within an A* search during test time. The approach is tested on GSM8K, MATH, and MBPP. Two reviewers (scores 5,5) find the idea well-motivated and the execution clear, while two reviewers (scores 3,3) raise significant concerns about formulation mismatch, incremental novelty relative to prior work (e.g., RAP‑MCTS), lack of proper justification for A*, admissibility issues, missing OOD experiments, and insufficient statistical rigor.

### Strengths
- The paper is well‑structured and clearly written, with figures that effectively explain the algorithm and process (Reviewers 1, 2).
- The motivation for developing a reliable, fine‑tuning‑free framework for multi‑step reasoning is both evident and well‑founded (Reviewer 2).
- The core idea—learning a Q‑function offline and deploying it during test‑time to guide search without re‑training the LLM—is sound (Reviewer 3). Reviewer 3 notes that prior offline RL work has used similar ideas on LLMs, but the paper’s presentation of this approach is still a strength.
- Section 5.4 provides useful evidence that the method is preferable to fine‑tuning, as fine‑tuning on one task can degrade performance on other tasks (Reviewer 3).
- The comparison of three different techniques to estimate the Q‑value function (offline RL, Best‑of‑K, offline MCTS) is valuable (Reviewer 1).
- The paper acknowledges that Q* improves smaller models but cannot outperform GPT‑4 variants, as shown in Tables 3,4,5 (Reviewer 3).
- Q* appears more efficient than MCTS‑based deliberation methods (Reviewer 4).
- The paper provides sufficient background and related work, giving a clear explanation of the Q* framework (Reviewer 4).

### Weaknesses
- **Formulation mismatch (Reviewer 1, high severity):** The formulation models multi‑step reasoning as an MDP where states are questions and actions are tokens, but there are no new observations or intermediate rewards. The problem can be cast as a single‑step search over a large action space, making the “multi‑step” framing unnecessary. This work aligns more with a beam‑search approach than with true planning.
- **Lack of novelty / incremental contribution (Reviewers 2, 3, 4):** The work appears to be an incremental extension of the RAP‑MCTS framework. The primary novelties—integrating A* and replacing the heuristic function with Q‑values—are already present in earlier work (e.g., RAP, offline RL for LLMs). Formalizing reasoning as an MDP is not novel (see RAP). Q‑value estimation and A* search have each been separately studied.
- **No justification for A* over other heuristic algorithms (Reviewer 2):** Alternative methods like Particle Swarm Optimization (PSO) or Ant Colony Optimization (ACO) are not considered. The claim that A* guarantees optimality when the heuristic is admissible is not supported because admissibility of h(st) is not established.
- **Reward function design does not ensure admissibility (Reviewer 2):** The design described in line 240 does not convincingly demonstrate that h(st) satisfies the admissibility condition (i.e., it does not overestimate the true cost to the goal). This casts doubt on the claim of optimal reasoning paths.
- **Missing OOD experiments (Reviewer 4, high severity):** The paper claims a “general” framework, but the Q‑value estimator is trained on the same benchmarks (GSM8K, MATH, MBPP) used for evaluation. Without out‑of‑distribution tests (e.g., LiveCodeBench, other math/code/agent benchmarks), the claim of generality is unsubstantiated. Existing deliberation methods may still be better on in‑distribution tasks.
- **Distribution mismatch between offline data and test‑time data (Reviewer 3):** In classic RL, learning a Q‑function entirely from offline data is known to be problematic when test‑time states are unseen (e.g., in Go or Chess). There is no discussion of how the learned Q‑value would generalize to novel math questions not seen during training.
- **No repeated trials or error bars (Reviewers 1, 3):** The experiments lack uncertainty estimates. Given the stochasticity of LLMs, it is necessary to report mean/variance or repeated runs. Without this, the reported numbers may reflect a single best run.
- **Aggregated utility g(st) is not clearly explained (Reviewer 3):** The paper does not clarify how the instantaneous utility (g) for each state (e.g., a segment of code) is learned from static offline data. The experimental section mentions some methods but the learning process remains ambiguous.
- **Domain knowledge and manual selection still required (Reviewer 4):** The paper claims no reliance on domain knowledge for the heuristic, but in practice the aggregation function is manually chosen, and the Q‑value estimator training requires task‑specific choices. This contradicts the claim of being domain‑agnostic.
- **Algorithm initialization issue (Reviewer 1):** In Algorithm 1, at the first iteration of the while loop, the unvisited set contains only the question—so `argmax` over q(s) is undefined. The authors likely intended to initialize the unvisited set with all states in line 2. Also, using Q(s') instead of f(s') might not change the solution because g(s') is constant for the traversed path.
- **Question about scalability (Reviewer 2):** No experiments are provided that assess how Q* performs as the complexity or size of reasoning tasks grows.
- **Comparison with TOOLCHAIN* missing (Reviewer 4):** Given that both methods use A* search for LLMs, a direct comparison in terms of performance and efficiency is needed.
- **Unrelated Section 5.4 (Reviewer 4):** The section showing that fine‑tuning on one task hurts others seems disconnected from the Q* method; a more relevant baseline would be LLAMA3.1 + MetaMath + Q*.
- **Writing issues (Reviewers 3, 4):** Several grammatical mistakes are noted (e.g., “as heuristic function” → “as a heuristic function”, “the solutions are Python code that is excepted” → “expected”). The overall presentation quality is low according to Reviewer 3 (score 1 out of 5).
- **Project name confusion (Reviewer 4):** The title “Q*” matches an existing OpenAI project and may mislead readers; a name change is recommended.
