## Merged Review

### Summary
The paper proposes LARG2, an LLM-based approach to automatically generate reward and goal-generation functions from text-based task descriptions for goal-conditioned and multi-task RL. It uses a code correction loop and a supplemental code example database for in-context learning. The method is evaluated on a simulated tabletop robotic arm environment, achieving decent success rates on several pick-and-place tasks.

### Strengths
- The problem of automating reward design and goal-generation in multi-goal/multi-task RL is pertinent and important. (Reviewer 2, 4)
- The idea of combining LLMs with a database search to generate program-based reward functions and goals is interesting and potentially novel in LLM-aided decision making. (Reviewer 2)
- Using an LLM to generate reward functions as code (fast to execute, refinable) is a promising direction for RL and autonomous learning. (Reviewer 4)
- The proposed method achieves decent success rates in the simulated tabletop robot arm environment (Tables 1 and 2). (Reviewer 1)
- The overall approach is considered novel and relevant by some reviewers. (Reviewer 3)

### Weaknesses
- **Writing, formatting, and clarity are subpar.** The method description (Sec 4) is not well-structured or motivated; it interleaves general explanation with implementation details, making it hard to assess generality. (Reviewer 1, 2, 4) Many notations are duplicated and confusing (e.g., R, S, p, T, G reused for different concepts). (Reviewer 1, 3) Numerous typos and grammatical errors exist (“Chain-of-though”, “rewards functions”, “if the code fail”, “can not be guarantee”, “commonly encounter”, “bellow” vs “below”, “re-arranging” wording). (Reviewer 1, 3) Figures have small text (Fig 3) and Fig 15 is mislabeled as Fig 2. (Reviewer 1, 3) The main paper gives little sense of key details (e.g., how reward functions look, how the correction mechanism works); these are left to the appendix. (Reviewer 4)
- **No visuals or detailed description of the experimental setup**, making it hard to judge task difficulty. (Reviewer 1)
- **Contribution is questionable.** Automatic code correction with LLM and code interpreter feedback is not a new concept (reference [1] given). (Reviewer 1) The supplemental code examples (a major claimed contribution) show no clear performance gain: L (without examples) still performs reasonably well in Table 2, and GPT4 results in Table 1 are similar with and without examples (each beats the other in about half of the tasks). The evaluation lacks statistical significance tests. (Reviewer 1, 4) The process of retrieval and example addition seems superfluous given the inconclusive results. (Reviewer 4)
- **No baseline comparisons.** There is no comparison to human-written reward functions, existing LLM-based reward generation methods, or standard baselines. (Reviewer 1, 2, 4)
- **Experiments are preliminary.** Only a single pick-and-place setup is used, with limited diversity of goals (placing blocks in 3D positions). The approach should be evaluated on more varied tasks (navigation, manipulation, crafting) and robot morphologies. (Reviewer 2, 4)
- **LARG2 requires many assumptions.** The LLM primarily samples Cartesian coordinates (goal generation) or composes reward functions from existing components pre-coded in the simulator. Half of the reward function is pre-coded, making the system custom to the environment and unclear how it transfers to new tasks without such assets. (Reviewer 2, 4)
- **Missing ablation studies.** Besides LLM choice, no ablation of components is performed, so the importance of each module (e.g., retrieval, correction loop) is unknown. (Reviewer 2)
- **Missing discussion of related works.** Several similar or relevant approaches are not cited: LLM-based goal generation (2305.12487, 2302.06692), other LLM reward generation works (2309.11489, 2303.00001), reward machines, learning from human preference. (Reviewer 4)
- **Confusion between tasks and goals.** The framing could be clarified; multi-goal problems are a subset of multi-task, and the paper’s two proposed methods essentially target the same type of goal. (Reviewer 4)
- **Limitations section is insufficient.** It does not clearly state limitations and gives the impression that all issues are resolved by the auto-correction loop. (Reviewer 3)
- **Several unresolved questions that indicate missing explanation or analysis:**
  - How exactly are the supplemental example codes used in prompting? (Reviewer 1)
  - What is the performance metric in Tables 1 and 2? Is each number the percentage of goals that matched a hardcoded validation function? How many goals per point? How are reward functions ranked in Table 2? (Reviewer 1, 3, 4)
  - What is the purpose of Figure 7? Could the goals be overlaid on the actual tabletop environment for interpretation? (Reviewer 1, 2)
  - What are the limitations on goal complexity? Can the approach handle non-goal based reward functions (e.g., training an agent to move in a circular pattern or do a backflip)? (Reviewer 3)
  - Does the code-validation step only ensure code execution, or does it also check reward validity/proximity to optimal? Is there any way to guarantee the reward is close to ideal? (Reviewer 3)
  - Is the correction mechanism only triggered on execution errors (Figure 4)? (Reviewer 4)
- **Minor issues:** Notation I_b is not defined in Table 2. (Reviewer 4) Opening quotes are not well-formatted; appendix prompt examples have low resolution. (Reviewer 4) The example addition is more about in-context learning than chain-of-thought prompting. (Reviewer 4) The high-level idea and scope should be better introduced in the introduction. (Reviewer 3)
