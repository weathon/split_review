## Merged Review

### Summary
The paper proposes a tool-augmented preference modeling approach, Themis, that enables reward models (RMs) to interact with external tools (e.g., calculators, search engines) via task-specific tool engagement and reasoning traces. The authors provide a tool-augmented reward dataset (TARA) with 15k instances across seven tools, and show overall 17.7% improvement on preference ranking across eight tasks, outperforming Gopher 280B by 7.3% on TruthfulQA. RLHF trained with Themis achieves a 32% average win rate in human evaluations.

### Strengths
- Addresses an important limitation of conventional RMs (e.g., arithmetic, code execution, factual lookup) by integrating external tools; the idea is novel, timely, and practically useful.
- The methodology is innovative: the model selects tools and generates reasoning traces autonomously, with a level of interpretability that is desirable for reward models.
- Experiments are comprehensive and include RLHF application, scaling experiments, and comparisons across multiple tasks and baselines; implementation details appear thorough.
- The dataset TARA and the proposed framework provide a foundation for future research on tool-augmented preference modeling.

### Weaknesses
- **Method clarity (R1, R2, R3):** The description of the method is unclear, especially in Section 3.1. It is not sufficiently detailed how explanation generation integrates with tool use (e.g., are explanations before or after tool invocation, how is tool information incorporated into the scalar reward?), whether the model is trained end-to-end or in stages, and how the final scalar reward is obtained from the hidden state (e.g., via a separate output layer).
- **Training data issues (R1, R2):** The paper does not provide sufficient information about the composition and size of the training data. Also, the use of GPT-4 to generate RM training data is questionable: if GPT-4 itself is a strong system, one could argue for using it directly as a reward model rather than training a smaller RM on its outputs.
- **Trust and bias risk (R2):** There is a risk of biasing the reward model and generative model toward outputs of the specific tools used, which are not guaranteed to be unbiased.
- **Missing standard RM benchmarks (R3):** The paper lacks experiments on widely used reward modeling datasets such as the Anthropic HH dataset (only a small portion is analyzed, not the test set), Stack Overflow, OpenAI WebGPT, and ChatGPT comparisons. The reported test accuracy is worse than some prior conventional RM work (e.g., RAFT [1]), undermining the claim that tools improve accuracy.
- **Hyperparameter sensitivity (R3):** THEMIS introduces several hyperparameters (e.g., alpha in Eq. 2), but no study of their sensitivity or effect on performance is provided.
- **Dataset creation difficulty (R3):** The dataset generation process involves complex steps including tool selection and heuristic design, which may be difficult to scale to large preference datasets.
- **Limited model size (R2):** The experiments use a 7B model, which may be too small to capture knowledge compared to tools; results could differ with larger models.
- **Write-up improvements (R2, R3):** The paper would benefit from clearer exposition (especially Section 3.1) and a more thorough discussion of related work on tool use in reward design, e.g., [2-5] that use compilers or execution feedback for code generation.
- **Minor clarification requests / unanswered questions (R1, R2, R3):**
  - What explains the large difference between Themis (Vicuna-7B + LoRA) and Themis in Table 1? Does beta=0, w=0 in Table 1 correspond to RM (Vicuna-7B)?
  - Why is the binary classification accuracy for RM (Vicuna-7B, Zero-shot) below 50% in Table 2?
  - When alpha=0 in Eq. 2, does the RM still implicitly use tools via simple prompting? Is that understanding correct?
