## Merged Review

### Summary
The paper proposes GAMformer, a transformer that uses in-context learning (ICL) to estimate shape functions of a generalized additive model (GAM) in a single forward pass. It is trained exclusively on synthetic data created from random causal graphs, then applied to real-world tabular data, including a MIMIC-II ICU mortality case study. The method aims to eliminate iterative optimization and hyperparameter tuning. Experiments compare GAMformer against EBMs, NAMs, and other interpretable models. Reviewers found the core idea novel but raised concerns about limited novelty relative to prior ICL work (TabPFN), insufficient experimental rigor (missing significance tests, poor `mgcv` baseline setup, lack of shape function comparisons), scalability (25 GPU days vs. seconds for `mgcv`), and missing evaluation of interpretability (no user study or quantitative measure). One reviewer was more positive (rating 6), another strongly negative (rating 3); the others were moderate (5).

### Strengths
- **Novel application of ICL to GAMs**: Using in-context learning to estimate shape functions is original and interesting (Rev 4). It removes iterative optimization and hyperparameter tuning, simplifying the GAM fitting process (Rev 1, Rev 2).
- **Interpretability**: Maintains full interpretability, crucial for healthcare, while matching performance of EBMs (Rev 1). Non-parametric binned representation can capture discontinuities (Rev 1).
- **Synthetic-to-real generalization**: Trained only on synthetic data but generalizes well to real-world benchmarks (Rev 1, Rev 2).
- **Code and clarity**: Code and a Jupyter notebook are provided (Rev 3). The paper is well-written with clearly stated ideas, goals, and limitations (Rev 2, Rev 3; Rev 4 noted redundancy).
- **Thorough experimental scope**: Rigorous testing across multiple benchmark datasets and a detailed public-health case study (Rev 1, Rev 2). Comparisons cover a variety of model classes (Rev 4).
- **Limitations acknowledged**: The paper discusses limited higher-order interactions, quadratic complexity, and scaling issues (Rev 2). (Rev 4 considered these insufficiently addressed.)

### Weaknesses
- **Limited/incremental novelty**: The core ideas (transformer trained on synthetic data for ICL on tabular data) already appear in PFN and TabPFN; the main difference is using a GAM as the classifier rather than a prior network or SCM (Rev 3). Rev 4 found the contributions (C1–C3) weak: automatic smoothing in `mgcv` already eliminates tuning (C2), and the MIMIC case study adds no new insights (C3).
- **Experimental rigor is incomplete**:
  - No standard deviations or statistical significance tests reported; stated performance differences may not be significant (Rev 3). Lack of quantitative results tables for recent baselines (Rev 1).
  - `mgcv::gam` comparisons appear flawed: logistic regression outperforms `mgcv::gam` in Fig. 6, suggesting a setup error; formula, basis functions, and smoothing selection method are not detailed (Rev 4). In appendix experiments, authors switch to `pyGAM` (inferior to `mgcv::gam`) without reporting `mgcv` performance (Rev 4).
  - Simulated data are not true GAMs – no distributional assumption, no noise; only a deterministic function with sigmoid. This makes it impossible to assess recovery of a true GAM structure (Rev 4; T2).
  - Only discrete target variables are considered; it is unclear if the method works for regression with continuous targets (Rev 2, question 1).
  - No shape functions of GAM methods are shown for direct visual comparison (Rev 4; E1).
  - The agnostic case (ground truth outside hypothesis space) is not tested (Rev 3, weakness 3).
- **Interpretability evaluation is insufficient**: Shape functions look similar to those of EBMs/NAMs, but no user study or quantitative measure (e.g., alignment with domain knowledge) is provided (Rev 4; C1). Claims of “highly interpretable” are vague and apply equally to competitors (Rev 3, weakness 2).
- **Scalability concerns**:
  - Transformer attention scales quadratically with number of data points, causing bottlenecks on large datasets (Rev 1, Rev 2). Model requires millions of parameters and 25 days on a high-performance GPU, whereas GAMs (including `mgcv::bam`) can fit datasets up to 10⁸ points in seconds (Rev 4; S1). Combinatorial explosion in high dimensions is overlooked (Rev 3, weakness 4).
- **Method limited to main effects and second-order interactions** (Rev 1, Rev 2). Proposed extension for higher-order effects is mentioned but not evaluated (Rev 2).
- **Binning and discretization issues**:
  - Features are binned by quantiles of the training set. Quantile-based binning can alter the data distribution and is likely inferior to equidistant binning (Li and Wood, 2017); the choice is not justified (Rev 4; T3).
  - Shape functions are discrete, which may be limiting (Rev 2).
- **Missing competitor code**: Code does not include competitor models, hindering reproducibility (Rev 4; R1). (Rev 3 notes code is available but no reproducibility checks.)
- **MIMIC case study inappropriate**: The dataset contains censoring; a time-to-event model would be more appropriate. Using standard classification may miss key properties (Rev 4; E3).
- **Comparison with TabPFN unclear**: GAMformer does not outperform TabPFN. TabPFN could also be analyzed with SHAP for interpretability, raising the question of whether a dedicated GAM architecture is needed (Rev 4; S2, S3).
- **Presentation issues**:
  - Redundancy between Sections 1 and 2 (Rev 4; W1).
  - Notation $j_{x_i}$ is confusing (Rev 4; W2).
  - Terminology: “shape functions” is non-standard (GAM literature calls them smooth terms/partial effects) (Rev 4; M1). $g$ does not map to $\mathbb{R}$ but to $\mathcal{Y}$ (e.g., (0,1) for logistic) (Rev 4; M2). $q_\theta$ in equation (2) is not defined (Rev 4; M3).
  - Incorrect historical claims: “spline-based GAMs use backfitting” – modern approaches (e.g., Wood) use PIRLS or INLA (Rev 4; M4). Citation for `mgcv` in footnote 3 appears incorrect (Rev 4; M5).
  - No shape functions for pairwise interactions are shown (Rev 4; M6).
- **Limited domain scope**: Only healthcare is evaluated; testing across finance, manufacturing etc. would strengthen the claims (Rev 1).
- **Missing details in introduction of GAMs**: The distributional assumption (part of the GAM definition) is omitted; the response variable distribution should be stated explicitly (Rev 4; T1).
