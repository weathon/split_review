## Merged Review

### Summary
The paper proposes AutoModel, an LLM-agent framework that autonomously builds and optimizes image classification models by assigning specialized roles (Project Architect, Data Engineer, Model Engineer, Training Engineer, Performance Analyst) to GPT-4o agents. It is evaluated on diverse datasets (benchmarks and Kaggle competitions) and claims to outperform zero-shot LLM-generated pipelines and achieve human-level performance. All four reviewers gave a score of 3/5 (reject-level), but with varying confidence and emphasis.

### Strengths
- The idea of framing end-to-end image classification model development as a multi-LLM-agent collaborative process is interesting and well-motivated (Reviewers 1, 2, 3). The design choice of agents and their components seems reasonable and well thought through (Reviewers 1, 2).
- AutoModel is an end-to-end framework that only requires the dataset as input (Reviewer 4).
- The approach can incorporate dataset-specific information to optimize different system components, which is a core potential strength (Reviewer 1).
- The experiments use a fair selection of datasets covering varying sizes and domains, including both standard benchmarks and non-standard Kaggle datasets (Reviewers 1, 2).
- The iterative approach leads to consistent model improvement over zero-shot LLM baselines (Reviewers 1, 4).
- The objective (automating network design for ML practitioners) is clear and the topic aligns with the conference (Reviewer 3).

### Weaknesses
- **Limited novelty / similarity to existing work**: The technical novelty is limited; the framework appears to be a straightforward application of prompting GPT-4o (Reviewer 3) and closely resembles MetaGPT applied to AutoML without highlighting key differences (Reviewer 4). The essential idea of multi-role LLM collaboration for a programming project is not new, and the authors should explicitly analyze how AutoModel differs from and improves over MetaGPT for AutoML (Reviewer 4).
- **Missing comparisons to strong baselines and related AutoML works**: No comparisons are made against traditional AutoML methods (e.g., hyperparameter optimization, AutoAugment, HPO) (Reviewers 1, 2). The paper does not compare with other full-pipeline AutoML approaches such as AutoMMLab, Prompt2model, AutoML-GPT, DHA, and Multi-Agent Automated Machine Learning (Reviewers 2, 4). Only zero-shot LLM-generated pipelines are used as baselines, which are too weak (Reviewer 2). Low-effort alternatives (e.g., CLIP zero-shot, pre-trained DINO as a feature extractor with linear/kNN classifier) are mentioned as simpler and more practical, but not compared (Reviewer 1).
- **Performance concerns and lack of robustness**: The reported Kaggle ranking (2892/3900) is not high, and even after 20 iterations the improvement is marginal (Reviewer 2). Accuracies are reported without standard deviations / error bars; experiments should be repeated multiple times to assess robustness (Reviewer 1). Section 4.4 provides only anecdotal evidence that the framework “intelligently” adapts to dataset information; structured experimentation is needed to rule out improvement by random chance (Reviewer 1). No analysis is shown of which agents contributed most to improvement, nor is it demonstrated that the multi-agent setup is superior to an iterative single-LLM setup (Reviewer 1).
- **Insufficient ablation experiments**: There is no ablation study of the different agents or modules (Reviewers 1, 2). The ablation on smaller LLMs is inadequate; the effect of LLM choice on accuracy or code error-rate is not shown (Reviewer 1). The model scale and computational cost of generated models are not compared, making performance improvements potentially meaningless (e.g., Model Engineer can always choose a larger model, and no constraints are placed on model size) (Reviewer 4).
- **Poor presentation and reproducibility**: Key implementation details are missing, such as the specific prompts for each agent, the input/output format of each component, the exact collaboration process, and how agents are coordinated (Reviewers 1, 2, 3). The framework diagram lacks detail (Reviewer 2). The supplementary material with prompts and examples is absent (Reviewer 1). These omissions make it impossible to reproduce the results (Reviewer 3). One reviewer (Reviewer 3) has very low confidence (1) due to these severe documentation gaps.
- **Limited scope**: Only image classification is evaluated, ignoring more comprehensive tasks (e.g., object detection, image segmentation) that are common in related work (Reviewer 2). Experiments are limited to small-scale datasets (CIFAR, Tiny-ImageNet); scaling to ImageNet-1K is not addressed, and the challenges of large-scale data are not discussed (Reviewer 4).
- **Other specific criticisms / questions (as weaknesses)**:
    - Why is accuracy only reported after the first and final iterations? A full curve would show stability over iterations (Reviewer 1).
    - The claim that the code error-rate is comparable to humans is unsupported (Reviewer 1).
    - Why is ViT-B/16 specifically selected by the framework? (Reviewer 3)
    - What exactly does “zero-shot LLM-generated training pipelines” mean? (Reviewer 3)
    - Are the same LLM (GPT-4o) and the same specialist prompts used for all agents? Shouldn’t specialist LLM agents for each component be different? (Reviewer 3)
    - What is the best model and training recipe produced by AutoModel, and are they dataset-dependent? (Reviewer 3)
    - How is code execution automated from code generation? (Reviewer 1)
    - Minor: Missing “Figure” in cross-reference (line 186); non-English quotation marks in several lines (Reviewer 1).
