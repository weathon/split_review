## Merged Review

### Summary
The paper proposes Incremental Latent Rectification (ILR), which chains lightweight "rectifier" modules to map the current feature backbone's representation backward to that of previous tasks. Three alignment set options are introduced (ILR-P using stored prior-task data, ILR-C using current task data as a surrogate, ILR-G using a generator). Evaluations are on CIFAR-10, CIFAR-100, and Tiny ImageNet under both task-incremental (Task-IL) and class-incremental (CIL) settings. The method is seen as novel but faces substantial criticisms regarding novelty overclaiming, architectural design, experimental fairness, and missing comparisons.

### Strengths
- The idea of backward chaining of latent space rectification is relatively novel and well-motivated. [R2, R4]
- The paper is clearly written, well-organized, and easy to follow. [R1, R2, R3, R4]
- Multiple alignment set options (ILR-P, ILR-C, ILR-G) are sensible and provide deployment flexibility, with a good summary in Table 1. [R2, R4]
- Alternative rectifier architectures are explored in the appendix. [R4]
- ILR integrates into existing CL pipelines with minimal modifications. [R3]
- Competitive performance is reported on standard benchmarks (CIFAR10, CIFAR100, TinyImageNet). [R1, R3]
- The rectifier unit is compact; parameter growth is linear and small relative to the backbone (though still substantial in absolute terms). [R1, R3]

### Weaknesses
- **Overclaiming novelty:** ILR is essentially a model expansion + distillation method; the claim of a “new CL direction” is overstated. [R1] A very similar core idea (learn a predictor to map current representations back to past ones) already appeared in self-supervised CL (CVPR2022), which is neither cited nor discussed. [R1]
- **Insufficient baselines:** Comparisons are dominated by old methods (o-EWC, LwF); recent relevant approaches such as Foster (ECCV2022), SupSup, EFT, Lightweight Learner, and Learn-to-Grow are missing. [R1, R2]
- **CIL evaluation is weak:** Only limited results are provided; performance gains diminish compared to Task-IL. [R1, R4] The CIL setting uses a simplistic averaging strategy that assumes equal class counts per task, which is not practical. [R2]
- **Architectural flaws in the chain design:**
  - Inference becomes linearly slower as tasks increase; for CIL the whole chain must be traversed per sample. [R4]
  - A single poorly learned rectifier breaks the chain and makes earlier tasks unrecoverable. [R4]
  - The method becomes impractical for long sequences (only up to 20 tasks tested); scalability to more tasks is unaddressed. [R2, R3, R4]
  - The chaining is unnecessary: independent rectifiers per task (as in Side-Tuning) would avoid these issues. [R4]
- **Suboptimal alignment loss:** The \(\ell_2\) error does not account for classifier-weight importance; a weighted loss could be more effective. [R2]
- **Alignment set drawbacks:**
  - ILR-P saves data from task \(t-1\), which is effectively a replay buffer and contradicts the claim of not needing one. [R4]
  - ILR-C/G require storing the previous feature extractor, doubling model size during training. [R4]
  - When tasks differ substantially, current-task data may poorly represent the prior latent space. [R4]
- **Unfair experimental comparisons:** ILR-P uses an alignment set of 5000 samples vs. baselines with buffer size 1000; even with this advantage it does not convincingly outperform. [R4] (Minority: R3 views the performance as strong.)
- **Only one ILR-G result** (Task-IL S-CIFAR-100); more results are expected given the prominence of this variant. [R4]
- **Limited evaluation scope:** Tests use only ResNet-18 on streams with equal class counts; no evaluation on domain-shift benchmarks (e.g., VDD), larger backbones (e.g., Vision Transformer), or long task sequences. [R2, R3]
- **Dependence on task identity:** The method assumes task identity during inference; task-agnostic scenarios are not explored, and CIL’s averaging strategy also assumes known task boundaries. [R3]
- **Clarity issues:** Abbreviations LRB/ILR are undefined in the abstract; notation for \(s(x)\) is confusing (used for different meanings); Section 3.3 has a notable drop in writing quality. [R3, R4] Several typos and minor errors (e.g., “Distiction”, “risk” vs. “risking”) are present. [R4]
- **Reproducibility:** No open-source code is provided, limiting verification and follow-up. [R3]
- **Missing analyses:** No quantitative inference timings are given. [R4] The effect of alignment set size (e.g., 1000 vs. 5000) is not ablated. [R4] Long-term memory/computational overhead over many tasks is not studied. [R3]
