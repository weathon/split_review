## Merged Review

### Summary
The paper proposes an attack-agnostic statistical detection method that compares feature map statistics from a compressed and an uncompressed neural network pair to identify adversarial examples. It uses JPEG-style compression as a denoising step and builds class-specific distribution identities. Most reviewers acknowledge the intuitive idea and good performance on limited tests, but they raise serious concerns about novelty, experimental rigor, missing evaluations (especially adaptive attacks), computational cost, and a critical data leakage issue.

### Strengths
- **Attack-agnostic design**: The method does not require prior knowledge of attack types, making it practical for unpredictable adversarial scenarios (R1, R2, R5).
- **Strong empirical results**: High detection accuracy is reported across multiple attack types (e.g., Table 2), with improvements over existing baselines (R1, R2, R3, R5). R3 specifically notes that the cross-attack comparison in Table 2 provides direct evidence of performance.
- **Intuitive core idea**: Using compression (e.g., JPEG) to remove adversarial noise is an approach that is easy to grasp and well grounded in known properties of adversarial perturbations (R3, R5).
- **Minority positive on presentation**: R4 states the paper is “relatively well-structured and complete,” though this is contradicted by multiple other reviewers.

### Weaknesses
- **Insufficient evaluation of attack strength and adaptive adversaries**: The method is tested only on weak attacks (small epsilon) (R2). No evaluation is performed against **AutoAttack** (R1 cites [1]), **adaptive attacks** that can circumvent the threshold-based detection (R1, R2, R3, R4), or attacks with varying perturbation magnitude (R2, R4). R2 recommends testing with stronger epsilon values and more sophisticated attacks. Without adaptive evaluation, the claimed robustness remains unsubstantiated.
- **Poor presentation and clarity**: The writing is criticized for lacking motivation and intuition, forcing readers to piece together notation scattered across the paper (R3, R4). There is **no flowchart or diagram** of the detection pipeline (R4, R5). Core concepts and statistical metrics (Section 3) are not properly explained and rely on external references without adequate analysis (R5). The experimental results are presented only in tables without commentary, insight, or ablation studies (R5). R4 notes “too many details and figures that can be moved to appendix” while the method itself lacks a diagram.
- **Limited novelty and insufficient related work**: Using compression/redundant networks for detection is already known (R3, R4). The paper omits several key prior works: **Feature Distillation** (R3), **“Detecting Adversarial Image Examples in Deep Neural Networks with Adaptive Noise Reduction”** (R4), **Defensive Dropout** [2], and **Random Self-Ensemble** [3] (R1). No comparison with these or other noise-based/stochastic defenses is provided (R1, R4). R2 describes the approach as an incremental combination of existing techniques.
- **Missing computational and runtime analysis**: The method introduces overhead via compressive sensing, batch processing (generating $N$ images), and distribution matching, but no evaluation of inference time, memory consumption, or runtime relative to baselines is given (R1, R2, R3, R5). R2 notes that batch processing implies $\mathcal{O}(N)$ runtime, which raises scalability concerns. The paper’s claim of “real-time detection” lacks supporting evidence (R3).
- **Critical data leakage issue** (raised solely by R2): The method uses **test set knowledge** (lines 196 onward) to build class distribution identities. This violates standard machine learning practice (test set must remain unseen during model preparation) and can bias results, compromising the validity of the reported performance. R2 recommends reworking the methodology to avoid this leakage.
- **Missing analysis of detection parameters and trade-offs**: The impact of the empirical threshold on detection performance is not explored (R3, R4). **False positive rates** are not reported (R3). The trade-off between adversarial detection rate and benign accuracy is not quantified (R1). **Ablation studies** on different compression methods or similarity metrics are absent (R5).
- **Narrow experimental scope**: Only a **ResNet** model is tested, which is insufficient to demonstrate stability and reliability across architectures (R3). It is unclear how baseline results in Table 2 were obtained (reproduced or cited?) and whether they are directly comparable (R4). The dataset composition (e.g., 50/50 clean vs. adversarial?) is not stated (R4).
- **Additional concerns**: The paper uses the term “adversarial examples” imprecisely; it should refer to the broader category “adversarial attacks” (R2). The reliability of the distribution identity and the criterion for terminating the $I$ iteration are not justified (R3). **Sampling bias** may affect divergence measurements during the identity-building stage (R3). The detection performance is assumed to depend on the transferability between natural and adversarial noise, but this is not theoretically analyzed (R5). No theoretical justification for the detection scheme is provided (R5).
