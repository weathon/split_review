## Merged Review

### Summary
The paper introduces a compressed context memory (CCM) system for Transformer LMs in online interaction, where context continually expands. It compresses attention key/value pairs into a compact memory using a compression token (<COMP>) and a conditional LoRA adapter without full model fine-tuning. Training is parallelized via masked attention to simulate recursive compression in one forward pass. Evaluated on MetaICL (26 tasks, few-shot), LaMP (personalization), and DailyDialog (conversation), CCM achieves near full-context performance with 5× smaller memory. Variants CCM-merge (average of memory vectors) and CCM-concat are also proposed.

### Strengths
- The problem of efficiently handling expanding contexts in online LM systems (e.g., ChatGPT) is highly relevant and important.
- The method is novel and flexible, applicable to diverse online inference scenarios (multi-task learning, personalization, conversation).
- Empirical evaluations across three diverse datasets (MetaICL, LaMP, DailyDialog) substantiate memory and computation advantages: near full-context performance with 5× smaller memory.
- The parallel training strategy (masked attention) enables efficient optimization of large models without sequential processing.
- Conditional LoRA adapter improves compression capability and acts as regularization against overfitting.
- Complexity analysis clearly articulates efficiency benefits; ablation studies validate design choices (adapter, architecture variants).
- The method is efficient in both training and inference: uses KV cache of <COMP> token, no need to recompute sentence embeddings; LoRA tuning reduces adaptation cost.
- Paper is generally easy to read.

### Weaknesses
- **Task-specific limitation (strong concern from Reviewer 3; also noted by Reviewer 1):** The compression module must be retrained for each task, requiring additional data and computation, and cannot generalize to new tasks. This is a significant drawback for foundation models intended for general-purpose use. Reviewer 3 argues that at least in the current experiments the method is only validated on specific tasks/benchmarks (few-shot classification, dialogue), not on general generative scenarios. In few-shot learning, users provide all demonstrations at once—not online interaction—making the claim of “online interaction” questionable.
- **Performance gap between compressed and full context models:** The paper notes a gap but does not provide a clear explanation or analysis (e.g., which data types or tasks suffer more). Reviewer 3 also questions the results: in Table 15, RMT performance is almost the same as “No context,” which seems implausible; experiments on OPT-2.7b may be heavily influenced by sample arrangement but no discussion is provided.
- **Baseline comparisons insufficient:** In main tables, CCM is only compared to “no context” and “full context.” Missing comparisons to retrieval-based methods (e.g., MemoryBank), recurrent memory approaches (linear Transformers), LongMem, UnlimitedFormer, and the most relevant works RMT, AutoCompressor, and Gist. None of these are in the main text (only in appendix). Reviewer 2 and Reviewer 4 specifically request these comparisons.
- **Memory update mechanism is basic:** CCM-merge is a vanilla average of all memory features, which ignores temporal ordering. Weighted merging (e.g., time-decay) could improve. The paper does not explore more sophisticated update functions.
- **Unclear design in parallel training:** Equation (1) conditions \(h(t)\) on \(Mem(t-1)\), but Figure 4 and the parallel training description suggest all \(Mem(*)\) are computed after \(h(*)\) for the same layer. It is unclear if conditioning is on the previous layer’s memory. The masking in Figure 4b may not be autoregressive.
- **Conditional adapter regularization insufficiently analyzed:** Authors report only training loss of LLAMA 7B without context. To clarify overfitting, they should report loss with context and test performance with/without context (Reviewer 4).
- **Evaluation scope limited:** Results on MetaICL dominate; Tables 3 and 4 lack numbers for LaMP and DailyDialog. No experiments on long-context benchmarks (e.g., using sliding window) to demonstrate broader applicability. Only instruction-tuned T5 was tested; non-instruction-tuned T5 was not (Reviewer 4).
- **Novelty concerns (Reviewer 2):** Similar ideas exist in earlier memory networks, fast weights, and Compressive Transformer; the paper does not discuss these relations. Missing references to those works.
- **Memory size metric:** Tables 4 and 5 report disk size in MB, but number of tokens would be more intuitive (Reviewer 2).
