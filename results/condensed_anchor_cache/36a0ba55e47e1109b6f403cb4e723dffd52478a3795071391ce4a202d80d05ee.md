## Merged Review

### Summary
The paper proposes LongLoRA, an efficient fine-tuning approach to extend the context lengths of pretrained LLMs. It combines two components: (1) shifted sparse attention (S²-Attn), which uses local attention with shifted groups during training (retaining full attention at inference) to reduce computation, and (2) an improved LoRA that unfreezes embedding and normalization layers to prevent performance loss. Experiments on Llama2 models (7B, 13B, 70B) show strong perplexity and retrieval performance with reduced cost, and the method is compatible with existing techniques like positional interpolation.

### Strengths
- **Simple and effective** – The method is extremely simple, performs well, and is applicable to existing pretrained models (R1, R2, R3, R4).
- **Strong empirical results** – Thorough evaluation on long language modelling and a retrieval task shows strong performance across model scales (R2, R3). The evaluation is considered thorough and the results are strong (R3).
- **Thorough ablations** – Key design decisions (attention shift, unfreezing embedding/norm layers for LoRA) are isolated and validated with careful ablations (R3, R4).
- **Compatibility** – The approach can be combined with existing context extension methods such as positional interpolation (R2). It also retains the original architecture and is compatible with Flash-Attention2 (noted in abstract, not contested by reviewers).
- **Detailed related work discussion** – The paper provides a detailed discussion of related work (R2).
- **Implementation simplicity** – The core method can be implemented in a few lines of code (R2).
- **Well-written** – Some reviewers found the paper well-written and easy to follow (R3, R4), though one reviewer (R2) rated presentation as fair and suggested improvements (see Weaknesses).

### Weaknesses
- **Limited evaluation** – The paper only evaluates perplexity and a retrieval task; generative tasks that require longer context are not tested (R1, R4). Both reviewers consider this a gap.
- **Missing ablation on group size** – The selection of the group size for sparse local attention (25% heuristic, group size 2048 for 8192 sequence length) is not ablated for different target sequence lengths, and it is unclear whether this heuristic generalizes to longer contexts (R1, with high confidence; also flagged as a question by R2).
- **Unclear FLOPs estimation** – The method used to estimate model FLOPs (Table 10) is not explained in sufficient detail; the authors should provide the formula, specify whether it accounts for training or inference, and list the operations included (R1, confident).
- **Presentation issues (R2)** – Several aspects need improvement:
  - Figure 3 is difficult to understand; add indices/annotations to matrices and visual connections between matrices and attention patterns.
  - Terminology (S², shift short attention, LoRA+, LongLoRA) should be more consistent, and it should be made explicit that LongLoRA = S² attention + LoRA.
  - Table 7 would be better as a line plot.
  - References to appendix results should point to specific sections.
  - The “attention patterns” ablation feels repetitive; its distinction from the “consistency to full attention” discussion in Section 3.2 is unclear.
  - The phrase “somehow” in the retrieval evaluation is vague.
- **Inference-time attention details** – The paper claims standard self-attention can be retained at inference, but more details are needed; the evidence from Table 2 should be elaborated (R2).
- **Missing baseline** – Table 3 should include an additional baseline that trains LoRA + embeddings (R2).
- **Inconsistent perplexity improvement** – In Table 4, the perplexity improvement is not consistently superior across settings (R4).
- **Efficiency discussion** – The efficiency aspects of the approach could be more prominently discussed in the main body (R2).
- **Minor clarifications needed** – (R3, who otherwise reported no major weaknesses) asks:
  - Why do regular LoRA and LoRA+ use the same memory in Table 11? Does S²-Attn reduce memory or only FLOPs?
  - A comparison to training a long-context LM from scratch would be informative.
