## Merged Review

### Summary
The paper proposes HiZOO, a diagonal Hessian-informed zeroth-order optimizer for fine-tuning LLMs. It uses an additional forward pass (three total) to estimate diagonal Hessian as a preconditioner, aiming to improve convergence and accuracy while preserving the memory advantage of ZOO. A low-rank variant HiZOO-L is also introduced. The paper includes theoretical convergence analysis, visualization on test functions, and experiments on models from 350M to 66B parameters (RoBERTa, OPT, Phi-2, LLama3) on GLUE tasks. Two reviewers rated 6, one rated 5; the lower-rated review raised concerns about theoretical rigor and estimator validity.

### Strengths
- **Novel and motivated approach**: First work to incorporate second-order information (diagonal Hessian) into zeroth-order optimization for LLM fine-tuning. Clear motivation and step-by-step explanation in Section 3.3.
- **Low-rank variant HiZOO-L**: Reduces memory overhead while maintaining optimization quality, addressing practical memory constraints.
- **Empirical breadth**: Extensive experiments across encoder-decoder and decoder-only architectures, multiple model sizes, and evaluation on GLUE benchmark. Uses number of forward passes for fair comparison, discusses memory and time efficiency. Reports concrete improvements: e.g., on SST2, 8× speedup and 1.55% accuracy improvement over MeZO.
- **Preliminary theoretical analysis**: Provides convergence guarantee for HiZOO and illustration on test functions showing superior generalization over baselines (including Adam). The paper is well-organized with clear sections.

### Weaknesses
- **Theoretical analysis needs strengthening**:
  - The convergence analysis does not cover how the diagonal Hessian improves convergence relative to MeZO/other zeroth-order methods; no discussion of query complexity, condition number improvement, or interaction of Hessian approximation with stochastic gradient estimation.
  - One reviewer found the convergence result (Theorem 3.2) unusual: it bounds the norm of the stochastic gradient rather than the true gradient, and the rate (ϵ^−4) is on par with first-order methods, which does not obviously reflect an advantage from second-order information.
  - The bound involves \(\max_t \mathrm{Tr}(\Sigma_t)\); initialized as identity, \(\mathrm{Tr}(\Sigma_0)=d\) (parameter dimension), and if the trace grows beyond \(d\) the rate could be slower than vanilla ZO-SGD, undermining the claimed theoretical benefit.
- **Hessian estimator validity questioned**:
  - The estimator (Eq. 3) assumes Σ is close to the inverse Hessian, but Algorithm 1 initializes Σ₀ as identity, so early estimates may be inaccurate; it may simply estimate a positive definite matrix rather than the true inverse Hessian.
  - A reviewer noted a code implementation inconsistency: the paper describes the update using outer product \(u_i u_i^\top\), but the code treats the Hadamard product \(u_i \odot u_i\) as a diagonal matrix, which could introduce inaccuracies.
  - The hyperparameter `Hessian_smooth` is set to \(1\times10^{-6}\), which one reviewer considered so small that Hessian information might contribute insignificantly to convergence.
- **Missing evaluation diversity**:
  - Experiments are limited to GLUE classification tasks; no generation or SFT-style datasets are included, limiting understanding of HiZOO’s performance on broader language modeling tasks where generative capabilities are critical.
  - One reviewer requested verification on additional supervised fine-tuning (SFT) datasets with different data distributions and task complexities.
- **Training stability concerns**:
  - While Table 5 shows promising results on SST2, Figures 12–14 reveal cases of poor training performance or even training failure, raising concerns about optimizer stability and reliability under different conditions.
- **Algorithm efficiency issues**:
  - Algorithm 2, line 9: computing \(R^{-1}\) and \(C^{-1}\) introduces significant computational overhead, which could hamper practical efficiency.
- **Test function experiments are from-scratch optimization, not fine-tuning**: One reviewer noted the test function comparisons do not simulate fine-tuning; if the advantage over Adam holds, experiments on pre-training would strengthen the case. Hyperparameter settings for these tests were not detailed.
- **Presentation**: Some derivations in Section 3 are verbose and could be simplified; the three test functions in Section 3.5 should be defined in the main text rather than deferred, and a clearer separation of theory and empirical content would improve readability.
