## Merged Review

### Summary
The paper presents FacTool, a tool-augmented framework for detecting factual errors in LLM-generated text. It employs a five-step pipeline (claim extraction, query generation, tool querying, evidence collection, agreement verification) using external tools like search engines, code interpreters, and calculators. The framework is evaluated on four tasks: knowledge-based QA, code generation, mathematical reasoning, and scientific literature review, across five datasets. The authors constructed datasets for these tasks and compared FacTool against a Self-Check baseline, showing improved accuracy.

### Strengths
1. The framework intertwines "tool use" with factuality detection, showcasing versatile application of LLMs for auxiliary tasks like claim extraction and query generation in a fact-checking pipeline. (Reviewer 1)
2. Extensive evaluation across four tasks (KBQA, code generation, math reasoning, scientific literature review) and five datasets, with detailed analysis including content in the appendix. (Reviewers 1, 2, 3)
3. The authors made the codebase publicly available and introduced a ChatGPT plugin for enhanced accessibility. (Reviewer 1)
4. The studied topic is important, and the proposed framework is a valuable contribution to the community as a one-stop factuality tool. (Reviewers 2, 3)
5. Significant effort in prompt development for claim extraction in various use cases. (Reviewer 2)

### Weaknesses
1. **Limited novelty:** The use of search engines for evidence-based fact-checking is well-established, and generating queries via LLMs is not a major conceptual leap. One reviewer considered the technical contributions "somewhat limited and mostly incremental," and another noted the intermediate question generation for validation has been proposed in prior works (e.g., arXiv:2210.08726, arXiv:2309.11495). The novelty primarily lies in claim generation tailored to different tasks. (Reviewers 1, 2; more negative from Reviewer 2, who rated contribution 2 vs. 2-3 from others)
2. **Missing comparative baselines:** The study lacks comparisons with non-LLM methods or previous LLM-based fact-checking systems like RARR (Gao et al., 2022a) and SELF-REFINE, which could have been used for at least KBQA. This makes it difficult to isolate the contribution of FacTool. (Reviewers 1, 2; Reviewer 1 explicitly requests a detailed comparison with RARR)
3. **Absence of standard fact-checking datasets:** Notable datasets like FEVER and SciFact are not included in the evaluation, limiting comparability with existing fact-checking systems and generalizability. (Reviewer 1)
4. **Stretching the definition of factuality:** The application to code generation is questionable, as there can be multiple correct ways to write a code snippet, and factuality is not a natural property. (Reviewer 2)
5. **Heavy reliance on ChatGPT:** The framework relies on ChatGPT for many functions (e.g., checking whether list A is a subset of list B), which may hinder reproducibility by other researchers and incur additional costs. (Reviewer 3)
6. **Methodological details needed:** The setup of the Self-Check baseline is unclear (e.g., existing code or author-developed prompts). For code generation, how does the model determine appropriate corner cases for unit testing? In Appendix C (Fig 6), the use of all-caps in prompts raises questions about design choices and potential performance differences with standard casing. (Reviewer 2, questions)
7. **Disagreement on contribution:** While all reviewers rated the paper similarly (score 6), one reviewer (Reviewer 2) gave lower ratings for soundness (2) and contribution (2), emphasizing incremental nature, whereas others found the soundness good (3) and contribution fair (2-3). (Confidence: Reviewers 1 and 3 at 4, Reviewer 2 at 3)
