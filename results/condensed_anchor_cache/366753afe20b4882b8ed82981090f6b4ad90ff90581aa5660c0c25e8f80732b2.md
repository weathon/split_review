## Merged Review

### Summary
SpQR is a weight-only quantization method for LLMs that identifies outlier weights and stores them in FP16 using unstructured sparse-matrix multiplication, while compressing all other weights to 3–4 bits via fine-grained grouped quantization with two-level quantization. On LLaMA and Falcon models (Wikitext2, C4, PTB), it achieves <1% relative perplexity loss, >3.4× memory reduction, and 15–30% inference speedup over 16‑bit baselines. Reviewers acknowledge the detailed outlier analysis, the GPU inference algorithm (Table 3), and the clear presentation, but raise concerns about novelty, complexity, hardware dependence, missing evaluations on generative benchmarks (MMLU, GSM8K, Humaneval), insufficient baselines (RTN, GPTQ, AWQ), latency overhead from unstructured sparse patterns, and applicability to activation quantization. One reviewer (score 8) is more positive, citing the first demonstration of weight outliers and the practical speedup; the other three (score 6) have more extensive criticisms.

### Strengths
- Compresses LLMs to 3–4 bits per parameter with <1% relative accuracy loss, achieving >3.4× memory reduction and 15–30% inference speedup versus 16‑bit models. (R1, R2, R4)
- First work to demonstrate that outliers occur in LLM *weights* (along specific output hidden dimensions), not only in activations. (R3)
- Provides deep analysis of outlier distribution patterns (group-wise and individual). (R2, R4)
- Proposes grouped quantization with a two-level quantization scheme to reduce overhead of group-wise statistics. (R2)
- Designs a sparse-matrix multiplication algorithm for GPU inference, with real speedup demonstrated (Table 3). (R2, R3)
- Clearly written and well-organized, with detailed supplementary material (e.g., Table 10). (R3, R4)
- Overall problem statement and algorithmic solution are easy to understand. (R4)

### Weaknesses
- **Novelty**: SpQR is an evolutionary improvement. Prior works have already studied outlier impacts on quantization [1] and used mixed-precision quantization [2]. (R1, confidence 4)
- **Complexity**: The two-step quantization process may be more complex to implement and tune than traditional methods. (R1)
- **Hardware dependence**: Benefits are maximized on specific hardware (e.g., A100) and may not be universally available. (R1)
- **Activation quantization**: Method is not easily applicable to activation quantization, and activation memory accesses also consume significant inference time. (R2; also R3 asks for experimental results quantifying activation)
- **GPU-unfriendly sparse pattern**: The unstructured sparse pattern of outliers imposes significant computational overhead on GPUs. (R2, R4)
- **Missing generative benchmarks**: No evaluations on MMLU, GSM8K, or Humaneval, which are crucial for assessing downstream task performance. (R4; authors acknowledge this limitation)
- **Insufficient baselines and ablation**: 
    - Should compare accuracy and inference latency with RTN, GPTQ, and AWQ using the same group size. (R4)
    - Missing comparison with 8‑bit weight quantization to see if 4‑bit is worth the overhead. (R2)
    - No ablation showing latency breakdown without and with sparse outliers, nor comparison with existing prior kernels (GPTQ, AWQ) for weight‑only quantization. (R4)
    - Need breakdown of memory for indices and computational cost of sparse outlier representation versus dense representations. (R4)
    - Should compare quantized GEMM with 4‑bit SpQR versus normal 4‑bit weight quantization to isolate overhead from grouped quantization and unstructured outliers. (R2)
- **Implementation details unclear**: How was 3‑bit matrix multiplication executed on A100? Was computation performed using 4‑bit multiplication for performance? (R1)
- **Outlier representation ambiguity**: In Section 4.1, two types of outliers are described (group-wise and individual). Are both used, and are they stored with the same Run‑Length Coding format? (R2)
- **Weight quantization uniformity**: Are multi-head attention and MLP weights quantized the same way, or differently? (R2)
- **Large vision models**: Experiments on vision models (SAM/DINOv2) are expected. (R3)
- **Minor issues**: Typos (e.g., “emory” in Section 5). Clarify “16‑bit statistics” in the Ablations paragraph regarding group size. (R4)
