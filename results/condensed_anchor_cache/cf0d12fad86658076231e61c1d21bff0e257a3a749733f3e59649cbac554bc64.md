## Merged Review

### Summary
This paper introduces LongMemEval, a benchmark with 500 human-curated questions embedded in scalable user-AI chat histories, evaluating five core long-term memory abilities: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention. It also proposes a unified three-stage framework (indexing, retrieval, reading) with design choices including session decomposition for value granularity, fact-augmented key expansion, and time-aware query expansion. Experiments on GPT-4o and Llama-3.1 (both 8B and 70B) demonstrate that commercial assistants and long-context LLMs drop ~30% accuracy on sustained interactions, and that the proposed optimizations improve memory recall and downstream QA.

### Strengths
- **Valuable benchmark**: LongMemEval is comprehensive, scalable, and practical, covering five core memory abilities with 500 human-curated questions in multi-turn task-oriented dialogues.
- **Well-formulated problem**: The paper identifies and formulates crucial long-term memory capabilities (multi-session reasoning, knowledge updates, temporal reasoning, abstention) that are often overlooked in existing benchmarks (e.g., MultiWoZ, CoQA, SituatedQA).
- **Clear framework with actionable designs**: The three-stage pipeline (indexing, retrieval, reading) with control points (key, value, query, reading strategy) provides a structured decomposition. Specific designs—session decomposition, fact-augmented key expansion, time-aware query expansion—are insightful and experimentally motivated.
- **Solid experiments and analysis**: Comprehensive evaluation across GPT-4o and Llama-3.1 (8B and 70B) reveals systematic challenges and yields useful insights, e.g., models differ in reading vs. retrieval strengths, and design choices (value granularity, key expansion size) significantly impact performance.
- **Practical insights**: Ablations (different value formats, key expansion, query expansion) produce actionable guidelines, such as fact decomposition helping multi-session reasoning and time-aware indexing improving temporal queries.

### Weaknesses
- **Baseline and model comparison**: The paper tests only GPT-4o and Llama-3.1 (8B and 70B) and does not compare with existing RAG systems, external memory systems, or other long-term memory models. The pilot study on proprietary assistants (ChatGPT, Coze) uses only 97 samples with much shorter histories (~10× shorter), insufficient as a baseline. A systematic benchmark of the dataset on more LLMs (including small models) and standard baselines is missing.
- **Dataset curation concerns**: The human-AI dialogue generation requires extensive human editing (line 248); how hallucination, repetition, and dialogue quality are controlled is not addressed. The construction of history sessions is not well motivated: temporal order is randomly assigned (“messy historical session construction”, “timestamp randomly assigned”), which may undermine temporal reasoning evaluation. Dataset size is only 500, with 31% single‑session questions that overlap with existing QA and task-oriented dialogue datasets (MultiWoZ, CoQA, SituatedQA are missing from references). Analysis distinguishing LongMemEval from these prior works is weak.
- **Framework formalism and originality**: The proposed “unified” framework is criticized as a combination of existing designs (R3: “combination of several existing designs”) and lacks a formal mathematical definition (R4: “no formal mathematical definition, unclear how it encompasses RAG”). The connection between the framework and specific experiments (e.g., CoN experiment in Section 5.5) is not clearly shown. Figure 5 does not include a concrete example, making it hard to follow; a simple example (possibly reusing earlier examples) is needed. Too many technical terms and heavy use of italics (e.g., “realistic and extensible”, “budget-aware”, “time-aware indexing and query expansion”) hamper readability.
- **Presentation quality**: The paper has an unusually high number of typos and inconsistent writing. Examples: typo in line 468; answer in Figure 2(a) is wrong (should be 50, not 5); best performance of Llama-3.1 70B when value=sentence in Table 2 appears wrong (0.590 not bolded but smaller than 0.592). Tables and figures do not follow ICLR format (titles should be on top, Table 1 placed on page 2 but first mentioned on page 3, column separator lines inconsistent, Figures 3(c) bars for rounds 7–10 are invisible, Figure 4(b) has duplicate label “Llama-3.1 8B Instruct” for both 8B and 70B). No evaluation metric (accuracy) is stated in captions for Figure 4(b). Numerical rounding is inconsistent: abstract claims 7%–11% improvement, but text reports 6.7%–11.4%, and the improvement only holds for GPT-4o, not Llama-3.1 (8B).
- **Insufficient analysis and discussion**: The results and discussion of the proposed framework occupy only two pages (Sections 5.2–5.5) in the main paper, which is too brief for a major contribution. There is no discussion of which of the five memory aspects contributes most, whether they overlap, or how failure in one aspect affects others (R2). No limitations or future work section is provided. The ethics statement for human annotation is missing.
- **Specific methodological questions**: (a) Why are there no answers located in rounds 7–10 (Figure 3(c))? (b) Why is the multi-session subset listed separately in Figure 6 but not analyzed in later experiments? (c) Why do some experiments use both Llama-3.1 70B and 8B, while others use only 8B? (d) How does random timestamp assignment guarantee the validity of temporal reasoning evaluation? (e) What is the temperature setting and GPT-3.5-turbo version used? (f) What motivates the differentiation between human-AI and human-human conversations? (g) Why are K=summary and K=V+summary experiments not included in Table 2?
