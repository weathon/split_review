## Merged Review

### Summary
The paper addresses path-based algorithmic recourse, focusing on the FACE algorithm’s failure to find recourse paths when training data points are sparsely connected. The authors propose learning a distance function and threshold parameter to define feasible transitions, and augmenting the dataset with synthetic samples to guarantee a path exists for every individual. Theoretical PAC guarantees for learning feasible transitions are provided. Reviewers note the problem is well-motivated but raise concerns about the method’s real-world applicability, experimental evaluation, and integration of theory.

### Strengths
- Novel application of theoretical machine learning (PAC/VC-dimension) to the recourse problem, which is new compared to prior recourse generation works (R1).
- The paper builds on and improves the FACE algorithm by addressing its tendency to terminate prematurely when large distances between data points block recourse (R3).
- Problem statement is well motivated: ensuring recourse is available to all individuals, including those in sparse regions, is an important and neglected issue (R2, R3).
- Provides several theoretical results regarding learning feasible transitions (R2).

### Weaknesses
- **Privacy concerns with FACE as a foundation**: Using FACE inherently involves traversing other users’ data points, which exposes sensitive information and undermines real-world applicability, as highlighted by prior work (Pawelczyk et al., 2023) (R3).
- **Limited experimental evaluation**: 
  - Comparison is restricted to only two recourse algorithms (nearest neighbor and one other), omitting diverse baselines available in the CARLA library (e.g., gradient-based methods that can also produce recourse paths) (R2, R3).
  - All datasets are tested only on logistic regression; the paper claims model-agnosticism but does not validate on neural networks or tree-based classifiers (R3).
  - No comparison of total cost between path-based and single-step recourse methods (R2).
  - Figure 1 uses different starting points for FACE and the proposed method, making the comparison inconsistent and non‑comparable (R3).
- **Inadequate handling of categorical variables**: The paper does not specify how categorical features are encoded or managed, yet tabular datasets commonly include such variables; this casts doubt on applicability in real‑world settings (R3).
- **Theoretical contributions are not useful or disconnected from practice**:
  - The VC-dimension bounds and feasibility learning results do not directly support the method’s empirical performance; no efficient algorithm for managing a large set of parameterized distance functions is provided (R3).
  - No theoretical guarantees that the synthetic augmentation stays on the data manifold, which is necessary for the generated points to be realistic (R3).
  - While R1 finds the theoretical component interesting, its integration with the experiments is weak (R1, R3).
- **Lack of human‑centric insight**: The paper does not explain why the graph becomes disconnected in human‑understandable terms; simply augmenting points does not address the root cause (R1).
- **Unclear formulation and missing details**:
  - Motivation for searching for a distance function is unclear, because the initial threshold \(h^*\) is obtained assuming an \(\ell_1\) distance (line 381–388) (R2).
  - In line 389 the text mentions “learning \(d,\tau\)” but \(\tau\) is not discussed; crucial details on how transition weights are created are omitted (line 395) (R2).
  - The role of \(\tau\) is ambiguous: it should be tuned as a maximal-effort parameter rather than learned, because for an input without a path the model could simply increase \(\tau\) to suggest a feasible path, which would also resolve unconnectedness without augmentation (R1).
- **Sequential augmentation approach is suboptimal**: The order in which nodes are augmented affects the final set of synthetic points; a holistic method that finds the minimal number of nodes to connect the graph is needed (R1).
- **Justification for learning from a labeled dataset created with a fixed cost function is missing** (R2).
- Minor writing issues: formatting error in \(\rho\)-ERM definition (line 244) (R2).
