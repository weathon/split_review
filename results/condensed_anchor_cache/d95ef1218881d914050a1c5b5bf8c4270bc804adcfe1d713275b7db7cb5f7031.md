## Merged Review

### Summary
The paper introduces SWE-bench, a benchmark of 2,294 GitHub issues from 12 Python repositories, requiring LLMs to generate patches to resolve real-world bugs. The authors fine-tuned CodeLlama (7B and 13B) and evaluated Claude 2, GPT-4, and others. The best performer (Claude 2) solved only 1.96% of issues. The paper analyzes difficulties like context length, retrieval (BM25, oracle), and patch formatting, aiming to provide a challenging real-world testbed for LLMs.

### Strengths
- Practical relevance: benchmark uses real product-sized repositories and actual issues/pull requests (Reviewers 1, 3).
- Well-designed, can be continuously updated and expanded (Reviewer 2).
- High-impact: expected to be widely adopted by other practitioners (Reviewer 2).
- Qualitative analysis comparing LLM-generated patches to human patches is insightful (Reviewer 2).
- Fine-tuning CodeLlama yields at least some positive performance on repository-wide edits (Reviewer 3).
- Proposes retrieval methods (BM25) to compose input within context limits (Reviewer 3).
- Clear writing and substantial work (Reviewer 1, 4).
- Dataset includes test scripts for evaluation (Reviewer 4).

### Weaknesses
- The benchmark does not clearly indicate where specific model weaknesses lie; observed trends (e.g., difficulty correlates with context/output length) are expected and uninteresting (Reviewer 1).
- Patch generation differs from code generation; models pretrained on code (not patches) are out-of-distribution, potentially explaining some poor performance (Reviewer 2).
- Pretraining context limits mean models rarely see complete files or repository structure; the paper does not explain how file names and directory structure are provided in experiments (Reviewer 2).
- No novel solutions are presented; the contribution is primarily the benchmark, which may be more suitable for a software engineering venue than an AI conference (Reviewers 3, 4).
- Paper organization is poor: tables/figures are not collocated with text; the description of BM25 retrieval (Table 3) is unclear and needs rephrasing (Reviewer 3).
- Comparison is unfair: training data cutoffs (Claude 2 up to early 2023, GPT-4 Sep 2021, Code Llama unknown) overlap with benchmark instances (before 2023), potentially advantaging later models (Reviewer 4).
- SWE-Llama contribution is insignificant; missing a direct comparison between Code Llama and SWE-Llama (Reviewer 4).
- Experimental analysis is unsolid: “Difficulty correlates with output length” (Section 5, Table 8) only shows successfully applied patches, not all patches, so correlation is not properly demonstrated (Reviewer 4).
- Lack of discussion and comparison with prior automated bug-fixing work (both LLM-based and traditional e.g., Jiang et al., ISSTA 2018; Sobania et al., arXiv 2023) (Reviewer 4).
- GPT-4 results are on a 20% random subset; other models were not evaluated on the same subset, so conclusions may not be consistent (Reviewer 4).
- The selection of the 12 Python repositories and programming language is not justified; potential influence on results is unclear (Reviewer 4).
- With all models performing poorly, the benchmark may be too hard; a benchmark of intermediate difficulty might better test specific model aspects (Reviewer 1).

*Note on reviewer disagreement:* Reviewer 2 (rating 8) strongly praised the qualitative analysis and impact, while Reviewer 4 (rating 5) considered the contributions limited and the analysis unsolid. The strengths and weaknesses above reflect this contrast.
