## Merged Review

### Summary
The paper presents GReaTer, a prompt optimization technique that uses gradient information over task-specific reasoning to enable smaller LMs to self-optimize without relying on large LLMs. Reviewers generally find the idea novel and empirically promising, but raise concerns about presentation clarity, generalizability to non-reasoning tasks, computational cost analysis, missing comparisons with other gradient-based methods, and theoretical justification. Reviewer 1 is strongly positive (score 8), while Reviewers 2 and 3 are more critical (score 6, 6), citing substantive issues.

### Strengths
- **Novelty**: Incorporating gradient information over reasoning tokens into prompt optimization is a departure from traditional text-based feedback methods (Reviewer 1, 2, 3).
- **Addresses a significant limitation**: Reduces reliance on large LLMs for prompt optimization, enabling smaller models to self-optimize (Reviewer 1).
- **Practical utility**: Demonstrates improved performance of smaller LMs, with empirical success on several benchmarks (Reviewer 1, 3).
- **Clear illustration**: Figure 1 clearly demonstrates the difference between GReaTer and previous methods (Reviewer 1).
- **Well-structured**: Paper has a clear problem statement and detailed method explanation (Reviewer 2).
- **Empirical success**: Method shows effectiveness across two models and multiple benchmarks (Reviewer 3).

### Weaknesses
- **Generalizability beyond reasoning tasks is unclear**: The method relies on task-specific loss gradients; its applicability to tasks like text generation or summarization without clear objective evaluation is not discussed. How GReaTer could be adapted for tasks where the loss function is not straightforward to define needs addressing (Reviewer 1, 2).
- **Computational cost not analyzed**: The number of forward/backward passes, memory footprint, scaling with model size/input length, and a comparison with traditional text-based prompt optimization methods are missing (Reviewer 2).
- **Missing thorough comparison with other gradient-based methods**: The evaluation lacks comparison with methods like AutoPrompt and PEZ; differences in optimization strategies, performance, and prompt characteristics should be discussed. Recent gradient-related prompt optimization literature should be cited (Reviewer 2, 3).
- **Presentation clarity issues**:
    * Notation abuse: output space of \(f_{\text{LLM}}\) is not well-defined (texts vs token probabilities inconsistent in Eq. 2&3) (Reviewer 3).
    * For main results (e.g., Table 2), it is unclear which model is used for prompt evaluation and which for optimization (Reviewer 3).
    * The complete Algorithm 1 (Appendix B.1) should be moved to the main text for better understanding (Reviewer 3).
- **Theoretical justification is insufficient**:
    * The claim that “simply considering \(f_{\text{LLM}}(y|x \odot p)\) would give us the wrong objective” is not well-justified; intuition suggests the direct answer distribution might be more skewed than when reasoning is included (Reviewer 3).
    * The physical meaning of the gradient direction \(\frac{\partial \mathcal{L}}{\partial \epsilon_i}\), the role of the negative sign, and why the token with the highest negative gradient is selected instead of the largest gradient norm are not explained (Reviewer 3).
    * More theoretical analysis of why gradients over reasoning work better is needed (Reviewer 1).
- **Case studies analysis too shallow**: The section lacks detailed analysis of why certain prompts work better (Reviewer 1).
- **Section 5.6 provides little insight** and could be omitted from the main text (Reviewer 3).
- **Missing experiments on smaller model sizes**: Performance on 1.5B or 3B models is needed, as 9B is not very small in practice (Reviewer 3).
- **Sensitivity to prompt initialization not explored**: Best practices for initializing prompts should be discussed (Reviewer 2).
- **Potential issue with Eq. 4**: What if there is no intersection in the candidate sets? How is semantic coherence among different token positions guaranteed? (Reviewer 3).
- **Performance gap between models unexplained**: Why are gains much smaller on Gemma compared to LLaMA? (Reviewer 3).
- **Minor typos**: Line 462 re-defines “LLMs” already defined in introduction; line 1186 has duplicate “Step” in a prompt example (Reviewer 1).
