## Merged Review

### Summary
The paper proposes ARMAP, a framework to automatically learn a reward model from LLM-agent interactions without human annotations. The reward model scores action trajectories and is combined with planning algorithms (MCTS, Reflexion, Best-of-N) to improve task completion. Evaluation spans Webshop and other benchmarks using Llama, Phi, and Mistral models. The approach reduces reliance on closed LLMs and fine-tuning.

### Strengths
- **Automated reward modeling**: An innovative method that generates diverse action trajectories via LLM agents, then synthesizes task goals and negative/positive responses to train a reward model without human annotation, addressing data scarcity and API limitations.
- **Framework flexibility**: Compatible with multiple planning algorithms (MCTS, Reflexion, Best-of-N) and different LLMs (Llama, Phi, Mistral), demonstrating generality and potential for broader application.
- **Controllable task customization**: Ability to modify reward targets for behavior control (e.g., minimizing action length or cost), shown in Webshop experiments.
- **Cost-effectiveness**: Avoids fine-tuning LLMs and reliance on proprietary LLM APIs, making high-performing agents more accessible.
- **Clarity and presentation**: Well-written paper with clear flow and accessible core concepts (one reviewer, confidence 4, notes strong clarity despite minor formatting issues).
- **Significance**: Demonstrated performance boost in LLM-agent tasks and reduction of dependency on large LLMs or human labeling (highest-score reviewer, 8).

### Weaknesses
- **Limited environment scope**: Evaluated environments are relatively constrained (online shopping, elementary science). One reviewer (score 8) states evaluation is limited to a single environment; others note multiple but limited task diversity. Missing complex long-trajectory datasets such as ALFRED, BEHAVIOUR, HABITAT, AlfWorld, BabyAGI, or PDDL. The framework’s ability to handle complex state spaces, long-horizon planning, noisy observations, or high-stakes decisions is untested.
- **Missing reward model specification**: Several reviewers flag insufficient detail on the reward model architecture, parameter count, layer configuration, activation functions, and whether it is a classification or regression model. Training challenges (convergence, overfitting, hyperparameter sensitivity) are not discussed. Specific references: Lines 100, 161.
- **Synthetic data quality and bias**: The quality and diversity of LLM-generated synthetic trajectories are not validated against real-world decision-making patterns. Overhead of in-context LLMs for task generation and trajectory synthesis may introduce computational cost and bias; a cost-benefit analysis is missing. One reviewer questions why pairwise comparisons are used instead of a simpler success/failure reward or value function.
- **Computational overhead**: Integration of planning algorithms like MCTS introduces significant computational costs, potentially limiting real-time application in resource-constrained settings. Strategies to reduce overhead while retaining performance are not addressed.
- **Insufficient detail on multimodal/visual input integration**: The paper mentions multimodal feedback and visual inputs (Line 150) but does not specify how visual information is encoded, whether visual inputs are fused with text embeddings, or their impact on reward model training. An ablation study isolating visual vs. text-only inputs is missing.
- **Application in dynamic environments**: Effectiveness in rapidly changing real-world environments is uncertain; the model may struggle when training data patterns shift. Generalization to domain-specific tasks (legal, medical) is untested.
- **Missing granular analysis**: Failure case analysis for tasks with complex dependencies is absent. Error patterns across environments are not discussed.
- **Minor clarity issues**: The phrase “corresponding environment observations” (Line 225) could be refined to distinguish the extra initial observation. In Figure 2, it is unclear if an LLM was used to extract keywords (e.g., “Jeans”) from language instructions during trajectory generation. Figure 1 formatting note: “Tree Planning” should use lowercase “(c)”.
