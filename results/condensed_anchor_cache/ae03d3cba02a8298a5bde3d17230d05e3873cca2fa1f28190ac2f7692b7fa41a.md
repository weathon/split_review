## Merged Review

### Summary
The paper introduces SubgoalXL, a system for formal theorem proving in Isabelle that uses three LLM-based generators (formal statement, formal proof, and subgoal) trained via expert iteration with KL constraints. The subgoal generator produces step-by-step informal proofs to guide formal proof generation. An aligned informal–formal dataset is constructed from existing sources. Evaluated on miniF2F, SubgoalXL achieves 56.1% (claimed SOTA). The approach leverages Isabelle’s forward proof style to make subgoal generation independent of the original theorem. One reviewer (score 6) is much more positive than the other three (each score 3).

### Strengths
+ Tackles a challenging problem: ML-guided formal theorem proving (R1, R2, R3, R4).
+ Novel idea: using an intermediate step of generating informal “subgoal proofs” before formal proofs, enabled by Isabelle’s forward proof style (R1, R3). The subgoal generation is independent of the original theorem (R3), and a separate subgoal generator is trained (R3).
+ Substantial improvement on miniF2F compared to published approaches (R1, R2, R4). The improvement is notable (R2) and validates the approach (R4).
+ Constructs an aligned informal–formal dataset that could benefit the community if released (R2, R4).
+ Ablation studies reveal the impact of subgoal generation and human-written informal proofs (R2).
+ Code is released (R1).

### Weaknesses
- **Insufficient novelty / extension of prior work** (R3, R4). The core ideas—decomposing proofs into subgoals, expert iteration, aligned dataset creation—are already explored in LeanStar, Draft-Sketch-Prove, Formal Math Curriculum Learning, and LEGO-Prover. The main difference is using Isabelle and subgoal formulation instead of informalization; the authors do not clearly explain what is new beyond that (R3). The paper offers no significant new insights (R4).
- **Evaluation concerns**:
  - **Data contamination / leakage** (R1, R3, R4). The initial subgoal annotations use manually proved theorems from miniF2F-valid as in-context examples (R3). Training data includes problems from AMC, AIME, IMO, GSM8K, MATH with only a 10% 3-gram overlap filter, leaving potential structural similarity to miniF2F (R4). The huge performance drop when subgoal generation is removed (12% on valid vs. 3% on test) suggests possible leakage from miniF2F-valid (R3). The fine-tuning datasets are not disclosed, making overlap checks impossible (R1). Evaluation only on miniF2F, which is well-known and likely in LLM training data; PutnamBench recommended instead (R1, R3, R4).
  - **Unfair search budget comparison** (R1, R4). Table 1 uses a budget of 16,384 for SubgoalXL while baselines use 100–200; this is not mentioned in the table and is misleading (R4). When budget is reduced to 64, performance drops to 46.3%/39.3% on miniF2F-valid/test (R4). The question of performance with budgets 100/200 is raised (R4).
  - **Inconsistent results** (R2). SubgoalXL outperforms the -subgoal variant by 11.5% on miniF2F-valid but only 2.8% on miniF2F-test; the authors do not explain this gap.
  - **Heavy reliance on sledgehammer** (R4). Most proofs in Figure 5 are completed via sledgehammer, suggesting the model only generates a formal sketch; it is unclear whether SubgoalXL could prove anything if sledgehammer were disabled. 
  - **No out-of-distribution evaluation** (R1, R3, R4). Only miniF2F (high-school level) is used; PutnamBench (undergraduate) would test generalization.
  - **Lack of inference-cost analysis** (R1). The paper trains 4 formal proof generators per iteration; it is unclear whether all are used at test time, making inference potentially much more expensive than baselines.
- **Methodology / writing issues**:
  - **Poor clarity and inconsistencies** (R1, R4). Key terms “subgoal-based proofs” and “expert learning” are confusing; “expert learning” is actually “expert iteration” (R4). The description of mathematical formulations is simple but unnecessary and distracting (R4). Subscript “pfg” is introduced without explanation and appears to cover both informal and formal proof generation (R4). Algorithm 1 omits Isabelle verification and includes a suspicious line about resetting datasets (R1). Section 3.2 vs. Figure 6 inconsistency: Figure 1 and Section 3.2 imply subgoal generation is conditioned on formal proofs, but Figure 6 shows no formal proof in the prompt (R4).
  - **Missing details** (R1, R3, R4). The 26 in-context demonstrations (Appendix C) are not provided (R1). Sampling steps in Algorithm 1 are not explained; equations referenced are in the appendix (R3). Meaning of “-subgoal” in Table 2 is unclear (R1, question 5). The “Overall” setting in Figure 2 is not defined (R2). Node types SN20, SN40 in Section 4.3 are unexplained (R2).
  - **Only one LLM tested** (R1). Only Llama-3-8B is used; results for Mistral, Gemma, etc. are missing.
  - **Related work omits non-LLM ML-based provers** (R1). Works like Graph2Tac, TacticToe, MaLARea, etc. are not cited.
- **Quality of generated subgoals** (R2). An example: for a gcd problem, the model generates “gcd(6*2+k)(6*2+3) ≠ 1” when k=4, which is incorrect; the correct subgoal should involve “gcd(6*2+k)(6*2+2) ≠ 1”. This shows subgoal generation needs refinement.
- **Human-written proofs hurt performance** (R3, R4). The ablation claims that human-written informal proofs degrade formal proof generation, contrary to the DSP paper. The authors provide no detailed study or explanation for this discrepancy (R3).
- **Relaxed correctness criteria** (R3). Verification uses both Isabelle 2021 and Isabelle 2022; a proof is considered correct if either passes. This hides model’s ability to generate consistent proofs in a single language and may cause subgoal alignment issues. The split of proofs per version is not reported (R3).
- **Potential evaluation fairness issues with miniF2F-valid** (R4). In-context examples for data generation are manually annotated from miniF2F-valid, and then the same dataset is used for evaluation; despite filtering, this raises contamination concerns.
