## Merged Review

### Summary
This paper introduces BioDiscoveryAgent, an LLM-based agent that iteratively designs genetic perturbation experiments by reasoning about previous outcomes and using external tools (literature search, Reactome, code execution, a critique agent). The agent outperforms Bayesian optimization baselines by an average of 21% in predicting relevant genetic perturbations across six datasets and 46% on non-essential genes. For the two-gene perturbation task, it achieves more than twice the accuracy of random sampling. Evaluation includes an unpublished dataset to guard against data leakage. The approach is presented as interpretable at every stage.

### Strengths
- **Novel application of LLMs to gene perturbation experiment design.** This is a new closed-loop paradigm in this domain, distinct from existing Bayesian optimization methods.
- **Strong empirical performance.** The agent (using Claude 3.5 Sonnet) achieves a 21% improvement in hit rate over BO baselines (46% for non-essential genes) and >2× improvement for two-gene perturbations.
- **Thorough experiments.** The study tests multiple backbone LLMs (Claude 3.5 Sonnet, GPT-4o, etc.), both seen and unseen datasets, single and double gene settings, and different tool combinations. Ablations on prompts and observations provide insight into what drives performance.
- **Clear, accessible writing.** The method, motivation, and analysis are easy to follow.
- **Detailed appendix.** Full prompts and example agent conversations are provided, supporting reproducibility.
- **Interesting insights from analysis.** The examination of predicted gene similarity across datasets and across experimental rounds helps explain the agent’s behavior.
- **Positive minority view:** Some reviewers (R3, R5, score 8) found the method highly interesting, the experiments extensive, and the contribution significant for the field.

### Weaknesses
- **No wet-lab validation.** The paper only uses in-silico simulations and existing datasets; real-world experimental confirmation is missing. (R1)
- **Concerns about metric and precision.** The paper focuses on hit ratio but does not report precision – the number of non-hit genes suggested also matters. (R3)
- **Insufficient baseline comparisons.** Baselines are limited to Bayesian optimization and random sampling. Missing comparisons with other interactive LLM agents (ReAct, reflection-based methods, LLMs as optimizers) and with a pure Retrieval-Augmented Generation (RAG) approach using the same corpus. (R2)
- **Two-gene perturbation baseline only includes random.** Why were other baselines not included for this task? (R5)
- **Performance improvement mainly in early rounds.** The agent’s advantage is largest in early rounds and declines later, likely due to the LLM’s pre-existing knowledge; its ability to learn from feedback over many turns appears limited. (R1, echoed by R4)
- **Surprisingly linear performance curve without saturation.** Figures 2 and 3(a) show near-linear improvement over 30 turns, which is unusual for LLM-based multi-turn agents. Why does this occur, and when might saturation begin? (R2)
- **Effectiveness of tools is inconsistent and often not significant.** Adding tools (literature search, Reactome, critique) sometimes does not improve or even hurts performance, especially for stronger LLMs (e.g., Claude 3.5 Sonnet). Confidence intervals in Appendix Table 7 overlap widely, and the impact varies by backbone with no clear explanation. (R3, R4, R2)
- **Method validity questioned due to backbone and tool variability.** In Table 1, different backbones show near-random performance differences; Table 3 shows inconsistent tool benefits across backbones. This raises concerns about the method’s robustness. A multi-turn comparison of backbones and tools would be more informative. (R2)
- **Potential information leakage.** The agent uses literature and gene databases; if the task query (e.g., phenotype–gene associations) is already covered in those sources, performance could reflect memorization rather than reasoning. (R2)
- **Lack of technical/methodological novelty.** The core idea – task-specific prompts plus an iterative loop of calling an LLM with updated context – is common across LLM agent works. (R4, R5) *However, one reviewer (R5) noted this is not a major weakness given the application context, while another (R4) found the prompting techniques intuitive and not particularly novel.*
- **Claims of interpretability are overstated.** The model’s stated reasoning (research plans, reflections) may be unfaithful to its actual decision process, as shown in prior work. The literature search tool could also produce misleading summaries or hallucinations, harming rather than aiding interpretability. (R5)
- **Critique agent’s benefit is not justified.** Unless the critique agent is complementary or has access to different information, it is unclear why another LLM of similar or weaker capability would improve accuracy. (R4)
- **Curiosity about the source of information in the agent’s reasoning.** In the example (line 1855), the agent mentions log-fold change – where does this information come from? The paper only describes tools for literature and Reactome. (R3)
- **Under-explained inconsistency in results.** The paper lacks an in-depth discussion on when tools help or hurt, why tool effects differ across LLMs, and other empirical contradictions. (R4)
- **What does the agent add beyond traditional pathway enrichment + Google?** A more explicit comparison to standard bioinformatics pipelines would clarify added value. (R3)
