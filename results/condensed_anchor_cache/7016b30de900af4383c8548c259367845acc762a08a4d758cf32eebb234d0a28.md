## Merged Review

### Summary
This paper proposes LVLM-Playground, a game-based evaluation benchmark for Large Vision-Language Models (LVLMs). It uses six games (Tic-Tac-Toe, Reversi, Minesweeper, Gomoku, Sudoku, Chess) and four tasks (Perceiving, Question Answering, Rule Following, End-to-End Playing) to assess capabilities beyond traditional VQA benchmarks, which suffer from insufficient detailed visual perception, data contamination, and lack of multi-turn reasoning. Experiments reveal that frontier models excel at perception but are weaker on QA (attributed to RLHF); all models fail at gameplay against strong opponents. The work also shows that gameplay data can improve reasoning during supervised fine-tuning. Reviewers generally acknowledge the novelty and clear exposition, but raise concerns about the alignment of task design with claimed abilities, insufficient quantitative analysis, limited evidence for the SFT improvement claim, and the proximity to prior text-only game-based evaluations.

### Strengths
- **Novel benchmark with visual input**: LVLM-Playground provides a dynamic, comprehensive assessment beyond static VQA benchmarks (R1, R2, R4). It is the first to extend game-based evaluation to include detailed perception capabilities from RGB images, distinguishing it from prior text-only works such as SmartPlay and GAMA-Bench (R2).
- **Rigorous methodology**: Well-structured task formulations (perception, QA, rule following, gameplay), clear evaluation metrics, AI opponents, and a human study for difficulty ratings (R1, R2, R3, R4). Games are designed to vary in difficulty across perception, reasoning, decision, and adversary dimensions with explicit complexity definitions (R1, R3).
- **Significant findings**: Reveals key limitations of current LVLMs—trouble with long structured outputs, detailed visual perception, and instruction following (potentially due to RLHF). Frontier models are weaker on QA than open-source models, attributed to post-training (R2). All models completely fail at end-to-end gameplay against strong opponents (R2). The Chess perception challenge (Table 2) highlights scope for future development (R2).
- **Useful subtasks**: Breaking evaluation into perception, QA, and rule following provides deeper insight beyond end-to-end playing ability (R2).
- **Practical implication**: Suggests gameplay data can enhance reasoning during SFT, offering a potential improvement avenue (R1, R4).
- **Presentation clarity**: Clearly motivated, well-written, with effective illustrations such as Figure 4 communicating key takeaways (R2, R3). Sufficient technical details and effective illustrations (R3).

### Weaknesses
- **Limited evidence for Finding 6 (gameplay data enhances reasoning)**: The SFT experiment uses MiniGPT-4 as the base model, whose SFT stage only used detail description data; performance gains may stem from data format rather than game VQA data. Recommendation to use more robust base models like LLaVA-1.5 or LLaVA-One-Vision (R1). Additionally, only tested on a subset of one VQA benchmark; it is unclear whether that subset actually tests VLMs’ reasoning ability. A more suitable benchmark or a revised claim is needed (R3).
- **Task design conflates perception/reasoning with instruction following**: The Perceiving task requires outputting matrices matching the game state, heavily relying on instruction-following. QA tasks impose specific output formats; commercial models frequently fail to match the format or refuse to answer (Finding 3), so these tasks do not purely measure perception/reasoning (R3). The issue is an evaluation design flaw: VLMs produce long answers, but expected answers are short. The authors could use few-shot prompts with short answers, regex parsing, or an LLM-based answer extractor (as in VLMEvalKit) to better decouple instruction following from target abilities (R3, R4). Consequently, results such as Table 3 deviate substantially from existing benchmarks (R3).
- **Insufficient quantitative analysis**: Missing granular analysis, e.g., how perception performance on Gomoku/Chess varies with board complexity (number of pieces) (R2). No manual categorization of error types for the QA task to inform the distribution of failures (R2). Intermediate evaluation metrics for the end-to-end play setting would help assess incremental progress (R1).
- **Contribution scale diminished by prior work**: SmartPlay (Wu et al., 2023) and GAMA-Bench (Huang et al., 2024) also use games for LLM evaluation, though only in text-space. The visual distinction is important, but proximity reduces novelty (R2). Concurrent works like GTBench (Duan et al., 2024) and GameBench (Costarelli et al., 2024) also evaluate LLMs on games, with GameBench using visual input for supported models; these should be cited (R2 suggestion).
- **Game output format too challenging**: Dense grid patterns and the required output format may be overly difficult for current models, potentially limiting evaluation of decision-making abilities (R1).
- **“Unbeaten rate” is a weak gameplay metric**: This metric is high-variance and tightly tied to the opponent implementation (exact minimax opponent). Consider computing Elo ratings against a pool of opponents at different strengths, or including non-search-based opponents (e.g., random) to establish basic competency, as done in GTBench (R2).
- **Minor issues**: Typo “soonet” for sonnet in Table 4.1; missing parenthesis on L379 (R2). Suggest citing MuZero as a canonical example of RGB-based gameplay with learning and search (R2).

**Reviewer disagreement**: Three reviewers assign scores of 6, while one reviewer (R4) gives 8, finding the benchmark novel and the methodology rigorous, but also noting the evaluation problem with Finding 3. Reviewer 3 (score 6) is particularly critical about the alignment between experimental designs and claims (soundness 2, contribution 2).
