## Merged Review

### Summary
Motivated by the explosion of publicly shared models (over one million on Hugging Face) and associated intellectual property disputes, this paper introduces the task of Unsupervised Model Tree Heritage Recovery (MoTHer Recovery). The goal is to reconstruct a directed tree showing which models were directly fine-tuned from which parent models, using only the model weights. Assuming all models share the same architecture, the method computes pairwise weight distances and applies a directed minimal spanning tree algorithm. The approach is unsupervised, requires no training data, and is validated on several fine-tuning scenarios and the Stable Diffusion model family.

### Strengths
- Novel and timely problem formulation: systematically addressing model heritage recovery for legal and documentation purposes (Reviewers 1, 2, 3, 4, 5).
- Unsupervised approach that leverages only model weights, requiring no training data (Reviewer 4).
- Simple yet effective method based on weight-distance properties (Reviewers 1, 5: but note this relies on a well‑known fact that fine‑tuning makes small weight changes).
- Empirical validation is convincing across different fine‑tuning scenarios and on the Stable Diffusion model family (Reviewers 2, 4).
- The writing and presentation are clear and well‑structured (Reviewers 3, 4, 5; Reviewer 1 notes mixed clarity in some sections but overall finds parts easy to follow).

### Weaknesses
- **Architecture limitation:** The method can only handle models with the same architecture; it cannot be applied to models obtained through distillation, quantization, or other transformations (Reviewers 1, 3: quantized models not tested).  
- **Mixed heritage not supported:** The approach assumes a single parent per model, so it cannot handle models created from multiple parents (e.g., weight averaging, model soups) or partial weight sharing (Reviewer 4).  
- **Scalability and runtime analysis missing:** The computational complexity of pairwise distance calculations and clustering is not analyzed; runtime for different scales (e.g., 100, 1000, 10000 models) is not provided (Reviewers 2, 4).  
- **Sensitivity to fine‑tuning hyper‑parameters not investigated:** The reliability of weight‑based relationships under different learning rates, optimizers, number of steps, or aggressive optimization/pruning is not studied; it is unclear when the monotonicity observation (Directional Weight Score) holds and when it fails (Reviewers 3, 4).  
- **Lack of theoretical underpinning:** Especially concerning legal or copyright applications, a stronger theoretical justification is missing (Reviewer 2).  
- **Novelty concerns:** The dense matrix construction and the graph algorithm are not new; the clustering method using equations (1) and (2) lacks justification and alternative criteria are not discussed (Reviewer 5).  
- **Clarity issues in specific sections:** Section 4.2 is hard to comprehend; the meaning of μ in eq. (3) and the “pretraining stage” in Figure 2 are unclear (Reviewer 1).  
- **Unclear practical necessity:** For many open models, information about the pre‑trained base model is already available at release; the value of recovering heritage for all released models is debatable (Reviewer 1).  
- **Claim about wrongful use of data not elaborated:** How the method can help identify models resulting from improper use of proprietary training data is not explained (Reviewer 3).  
- **Generalization across model types:** The monotonicity observation has only been verified on a limited set of models; its generality across different architectures is unknown (Reviewer 3).  
- **Minority reviewer perspectives:** Reviewer 1 questions the significance of the problem overall, while Reviewer 5 finds the methodology lacking novelty, in contrast to the more positive assessments of novelty and contribution from Reviewers 2, 3, and 4.
