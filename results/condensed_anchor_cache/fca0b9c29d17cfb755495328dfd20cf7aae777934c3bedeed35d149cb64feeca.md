## Merged Review

### Summary
This paper proposes a diffusion-based approach for interactive 3D layout control in text-to-image (T2I) generation. It leverages depth-conditioned pre-trained models, replaces traditional 2D boxes with 3D boxes, and introduces a multi-stage generation process where users insert, move, or change objects in 3D while preserving earlier objects. Key technical contributions are the Dynamic Self-Attention (DSA) module and a consistent 3D object translation strategy. Experiments show a 2× improvement in object generation success rate over standard depth-conditioned T2I methods and better preservation under layout changes. Reviewer scores range from 3 to 8 (one very positive, one very negative), reflecting disagreement on technical novelty and experimental scope.

### Strengths
- **Task and motivation**: The task of interactive 3D layout control is well-defined and timely; controlling relative object positions and distances in 3D is more natural than with 2D interfaces (R1, R3, R4).
- **Simple and sound core idea**: Using inpainting to preserve background during interaction is simple yet effective; manipulating in 3D world keeps mask calculation fully under control (R2, R3).
- **DSA module**: The Dynamic Self-Attention module merges key tokens from stage i–1 and stage i, enabling style consistency across stages while allowing new objects of different styles; combined with mask-guided latent blending and AdaIN, it effectively maintains surrounding styles (R1, R3). DSA is easy to implement and a clear technical contribution (R2, R3).
- **Multi-stage pipeline**: The iterative per-object control provides fine-grained guidance; generation proceeds from empty scene, adding objects one by one (R1, R4).
- **Demonstration**: The video demo clearly illustrates the 3D layout control process; results are well-organized and experiments comprehensive (R1, R3).
- **Practical advantages over 2D layouts**: 3D boxes allow control over object-on-object placement and relative distances from the camera (R3).

### Weaknesses
- **Limited 3D awareness**: The current approach does not exploit full 3D degrees of freedom—camera view, object rotation, zoom-in/out are missing; only 2.5D depth-conditioned generation is used (R1). Likewise, no evaluation metric captures 3D correctness (e.g., monocular depth estimation or 3D detection); Table 1 lacks any 3D comparison (R4).
- **Weak technical contribution**: Reviewer 2 (score 3) questions whether organizing masks from 3D boxes is sufficient contribution for a paper, given mature T2I pipelines. Even though DSA is a contribution, the ablation study states “when DSA is disabled, the model isn't capable of inserting new object,” which contradicts the paper’s claim that DSA is for maintaining background—making the technical motivation confusing (R2). The high runtime (3× “loose control”) may harm interactivity; further discussion is needed (R2).
- **Scene complexity is low**: Generated scenes are simple—all objects placed on flat surfaces (floor, desk). The box-based interface inherently restricts objects to planar surfaces; freeform or slanted surfaces (e.g., placing an object on a sofa, draped cloth, curved sculpture, or a person sitting on a chair) are not supported, limiting realism and diversity (R3).
- **Missing interface and motivation details**: No description of the actual user interface; only a code-driven demo, which is insufficient for practical applications (R1). The paper does not clearly articulate the specific challenges that make this task hard and why the proposed pipeline/modules are necessary (R1).
- **Disagreement on method description**: The pipeline figure (Fig. 3) omits key stages (warping, DDIM inversion) that are essential for understanding the method; these should be explained even if not novel (R4). Expressions in the METHOD section that argue why other methods are unsuitable for “this attention” are out of place (R2).
- **Question about DSA design**: Why are only key tokens combined between stage i–1 and stage i? The reviewer asks about the effect of combining V tokens instead; a discussion on the choice of keys is necessary for understanding the DSA design (R3).
- **Insufficient focus on depth/zoom movement**: The paper mainly shows side-to-side object movement; only one example (Fig. 6) demonstrates moving objects toward/away from the viewer; more such examples should be central (R4).
