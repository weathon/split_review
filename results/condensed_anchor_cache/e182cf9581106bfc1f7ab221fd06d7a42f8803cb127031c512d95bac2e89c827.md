## Merged Review

### Summary

The paper proposes ChuLo, a chunk-level key information representation method that uses unsupervised keyphrase extraction (improved PromptRank) to create semantically meaningful chunks for long document classification and token classification. The method aims to preserve core content while reducing input length. Evaluations on multiple document-level and token-level classification datasets show competitive results, including outperforming GPT-4o on some tasks. Reviewer opinions are split: two rate the paper 5 (positive on feasibility and performance), two rate it 3 (critical of novelty, evaluation rigor, and missing analyses). Disagreement exists on originality (R1/R4 view combination as novel; R2/R3 see limited novelty). Reviewer confidence ranges from 3 to 4.

### Strengths

1. **Novel combination** – The integration of unsupervised keyphrase extraction with chunk-level representation to improve long document understanding is uncommon in prior work (R1, R4). R2 notes the method of dividing documents into manageable chunks is reasonable; R3 acknowledges it outperforms GPT-4o on certain tasks.
2. **Thorough evaluation** – Empirical evaluation across several datasets (including long document and token classification) shows clear performance improvements over traditional baselines and SoTA API-based models (R1, R4). Analysis across different document lengths provides useful insights (R1).
3. **Token-level performance** – Particularly good results are obtained on token-level classification tasks (R2, R1).
4. **Clarity of method description** – The paper is clearly structured with logical progression, and the detailed description of the SKP algorithm (Section 3.4) aids understanding (R4).

### Weaknesses

1. **Limited novelty and outdated baselines** – R2 and R3 argue the design is similar to hierarchical-BERT (Lu et al., 2021) and that keyphrase extraction is widely used. R3 states baselines are mostly from 2022 or earlier. R2 and R3 explicitly disagree with R1/R4 on originality. R3 notes the title *“Long Document Processing”* is broader than the classification tasks tested.
2. **Motivation and efficiency claims unaddressed** – R2 points out that the claimed efficiency (“handle long documents… while retaining all key information,” lines 55–56) is not demonstrated; the method actually increases computational load by adding chunk-level details. A dedicated analysis of cost savings (FLOPs, model size) is missing. R3 asks for inference speed comparisons.
3. **Unfair LLM comparisons** – R2 and R3 criticize comparing ChuLo (fine-tuned) with proprietary LLMs (GPT-4o, Gemini1.5pro) without fine-tuning them. Both request fine-tuning open-source LLMs (e.g., LLaMA, Qwen) on the same dataset for fair comparison. R3 also notes that LLMs like LLaMA support 131k context length, while the paper handles only up to 10k, calling into question the “long document” framing. R2 further notes GPT4o/Gemini1.5pro only have results on the “2048” setting (R1 question).
4. **Evaluation inconsistencies** – R1 raises several issues: Table 3 “All” results do not match Table 1; Table 3 does not compare ChuLo with baselines used in Table 1; GPT4o/Gemini only tested on the 2048 setting. R1 also questions the NER prompt used in Figure 8, suggesting suboptimality (citing Ashok & Lipton, PromptNER). R4 notes that significant performance differences in Sections 5.4 and 5.5 lack scientific explanation.
5. **Keyphrase extraction inductive bias** – The position penalty (in Algorithm 1) is introduced without explanation or ablation study, assuming earlier noun phrases are more important (R1). The effect of this bias on different use cases is not discussed. R1 also asks why noun phrases are emphasized rather than key sentences containing facts about the key phrases.
6. **Missing training details** – R4 reports insufficient detail on training: data sources, data processing, optimization algorithms, and parameter configurations are not provided. R1 notes many hyperparameters (a, b, n, α, γ) without their chosen values or selection procedure.
7. **Generalization unconfirmed** – R4 notes the paper claims applicability to various NLP applications (line 72) but does not test on tasks like long document QA or summarization.
8. **Unexplained results and minor errors** – RoBERTa underperforms BERT in Table 8 without explanation (R1). Algorithm 1 contains unclear notations (h in line 8, l_k should be l_{k_i}) and a typo (missing space in “key phrases” line 216) (R1).
