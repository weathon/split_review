## Merged Review

### Summary
The paper proposes a multi-step detection pipeline for object detection on resource-constrained IoT devices, using object size and inter-correlation to gate subsequent YOLO model calls. The system is implemented on a hardware prototype and tested in a collaborative smart surveillance system with real-world pilot testing involving a police department. Reviewers agree the problem is important and the real-world testing gives credibility. However, two reviewers (scores 1, high confidence) consider the contribution very low, viewing the work as a straightforward implementation of existing YOLO models on a custom dataset with no novel ML or software contribution. One reviewer (score 3, moderate confidence) is more positive about the readability and practical deployment, but still identifies major weaknesses in evaluation, novelty, and completeness. The abstract claims a 3× execution time improvement and improved mAP, but reviewer 3 notes these results are not shown in the paper.

### Strengths
- *Practical problem addressed*: Running advanced computer vision on resource-constrained, latency-critical devices where cloud offloading is not possible is important for smart cities and law enforcement (R2, R3).
- *Real-world validation*: Testing with a police department in real surveillance scenarios adds credibility and demonstrates practical applicability (R2, R1, R3).
- *Clear writeup*: The paper is easy to read, especially for newer researchers (R1).
- *Hardware prototype*: The prototype described in Section 4.1 is a positive aspect (R1).
- *Detailed motivation*: The description of existing methods and the motivation for the work is clear and detailed (R3).

### Weaknesses
- **Lack of novelty**: The work is merely an implementation of existing YOLO architectures (R2) on a custom dataset. The pipeline-based approach is a standard software engineering practice for deploying ML solutions, not an innovation in ML or software design (R3). One reviewer (R1) notes the use of older YOLO models (e.g., YOLOv3/4) without explanation for why state-of-the-art models (like YOLOv8) were not used.
- **Insufficient evaluation & missing metrics**:
  - No comparison with other surveillance-related or pipelined systems (R2, R3).
  - The abstract claims improved execution time (3×) and mAP, but these results are not presented in the results section (R3).
  - No result comparison among the four YOLO models used (R1).
  - No metrics to demonstrate resource-constrained suitability: FLOPs, parameters, energy consumption, or computational power of each model on the device (R1).
  - The quantitative analysis of the pilot testing is insufficient (R2).
- **Pipeline timing and event-handling issues**: Using multiple sequential YOLO runs adds delay (e.g., ~1.5s + 0.5s + 6s = 8s to generate an event from stage 3). The system may miss other important events while processing one event (R2). No explanation is given for how concurrent event generation is handled (R2).
- **Missing details and documentation**:
  - No research questions are defined (R1).
  - The abstract is too small; does not explain what the “multi-step detection pipeline” does (R1).
  - No sample data provided (R1).
  - No limitation or discussion sections (R1).
  - No information on number of classes in the custom dataset (R2).
  - Unclear whether the model was trained on the edge device (Labrador) or only used for inference (R2).
  - Frame rate used for detection not stated (R2).
  - No measures described for detecting occluded objects (R2).
  - No process for identifying false events transmitted to authorities (R2).
- **Writing quality issues**: Mixture of past/present tense, use of commas instead of full stops as decimal separators (R1).
- **Literature review**: Too elaborated on individual papers but overall too few references; recommends shortening similar works and adding more (R1).
- **Absence of ML optimization**: The paper focuses only on pipelining multiple models; no discussion of edge-efficient architectures, quantization, or other ML-level optimizations that would be more impactful (R3).
