## Merged Review

### Summary

The paper proposes Loss2Net, a meta-learning framework for regression tasks where the target performance metric is unknown a priori, non-differentiable, time-correlated, or depends on multiple predictions. It jointly trains a predictor network and a loss-shaper network (parameterized by an INR) that approximates the unknown metric, enabling gradient-based optimization of the regressor. Experiments on power grid and telecommunications infrastructure optimization are presented. Reviewer opinions diverge: two reviewers rate 3 (reject-leaning), two rate 5, and one rates 6. Supporters cite the practical importance and flexibility, while critics question the meta-learning framing, novelty relative to existing loss learning methods, experimental scope, and missing theoretical justification.

### Strengths

- Addresses an important and practical problem: regression with a-priori unknown performance metrics, where standard losses like MSE cause loss-metric mismatch.
- The proposed method does not require prior assumptions about the loss function structure; it learns non-differentiable, multi-dimensional loss functions directly from system responses.
- The dual-architecture (predictor + loss shaper) and joint optimization are interesting; the loss shaper uses an INR to learn geometric representations based on coordinates.
- The method is capable of handling non-differentiable performance metrics without requiring gradient estimators.
- Experiments are grounded on real-world measurement data from power grid and telecom applications, demonstrating the model’s ability to learn previously unidentified loss functions.
- For one reviewer (R4), the motivation is clear and the paper is easy to follow.

### Weaknesses

- **Meta-learning framing is questionable.** R2 points out that equations (2) and (3) do not form a bi-level optimization problem because the inner-layer regressor parameter θ^p does not depend on the outer-layer parameter θ^l; hence the algorithm is not meta-learning. R4 similarly states the algorithm is closer to learning a loss function approximator for a non-differentiable target than to existing meta-learning frameworks.
- **Lack of comparisons to existing loss learning methods.** R5 notes no experiments compare Loss2Net against prior methods such as TaylorGLO, ML^3, or EvoMAL – only simple handcrafted losses (MSE, MSLE, α-OMC) are compared. R4 adds that for non-differentiable cases, gradient estimators like Reinforce or REBAR should have been baselines. R4 also asks why the L2 objective on the training set is used instead of unrolled differentiation on validation loss (as in ML^3).
- **Limited experimental scope and missing benchmarks.** R3 states there are no synthetic experiments or benchmarks illustrating when Loss2Net outperforms standard losses; synthetic datasets with known target loss functions would help understanding. R4 notes experiments use only shallow neural networks on two datasets; more regression tasks are available in [Lathuilière 2019] and on standard benchmarks. R5 would prefer standard benchmarks like CIFAR-10 or ImageNet to gauge general performance.
- **Missing theoretical analysis.** R3 highlights a lack of theoretical insights on convergence, stability, and generalization; no explanation why the proposed objective improves test performance. R5 similarly asks for theoretical justification.
- **Unclear motivation and presentation issues.** R2 finds the motivation not clearly explained (e.g., no visual illustration of MSE issues for non-experts); contributions are mixed with existing work; mathematical symbols and definitions of variables (especially how the metric M is computed from ŷ and v) are missing from the experimental section. R4 comments the writing is not well-structured (discussion and comparisons appear in the method section). R5 finds algorithm description straightforward but overall communication could be improved.
- **Background inaccuracies.** R5 notes that lines 138–143 incorrectly claim methods like GLO cannot be applied to regression (they can) and misstate EvoMAL’s task setting; given that these methods also optimize non-differentiable metrics, further novelty clarification is needed.
- **Sensitivity to noise and computational complexity.** R1 questions robustness when system response data is noisy; the joint optimization may lead to high computational cost, unsuitable for lightweight/real-time applications.
- **Missing hyperparameter and initialization details.** R3 asks for hyperparameter tuning details; R4 asks how the loss function is initialized.
- **Training instability and numerical issues.** R4 wonders about the learning curve given joint unstable supervision, and whether discontinuous loss landscapes cause numerical problems (NaN).
- **Claimed novelty of random vector injection.** R4 states that feeding prediction ŷ with random vectors (Remark 2) is common practice for robustness, not a novel contribution.
