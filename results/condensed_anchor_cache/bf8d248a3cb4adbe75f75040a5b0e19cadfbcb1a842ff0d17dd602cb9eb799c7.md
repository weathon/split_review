## Merged Review

### Summary

The paper introduces ICTSP (In-context Time Series Predictor), a Transformer-based model that reformulates time series forecasting (TSF) as in-context learning by constructing input tokens from a series of (lookback, future) pairs. This approach aims to leverage the Transformer's in-context capabilities without pre-trained LLM parameters. Experimental results across full-data, few-shot, and zero-shot settings indicate improved performance compared to previous Temporal-wise and Series-wise Transformers.

### Strengths

- **Novel framework for in-context learning in TSF:** Proposes an innovative token construction using context examples (multiple (lookback, future) pairs) to align TSF with Transformer in-context mechanisms, showing utility across benchmarks. (Reviewers 2, 3, 4)
- **Clear and fluent writing:** The paper is well-written and clearly presented, facilitating understanding of the approach and contribution. (Reviewers 2, 3)
- **Comprehensive experiments:** Includes multiple settings (full-data, few-shot, zero-shot) and datasets, plus ablation studies, providing a robust basis for evaluation. (Reviewers 2, 3)
- **Well-explained differences from earlier frameworks:** Distinction from Temporal-wise and Series-wise Transformers is clearly articulated, with a “category theory” flavor. (Reviewer 4)
- **Parameter efficiency:** Avoids using pre-trained LLM parameters, unlike other LLM-based TSF methods. (Implied from paper; noted positively by multiple reviewers)

### Weaknesses

- **Innovation and theoretical depth questioned (minority view):** One reviewer (score 3) finds the innovation limited, describing the methodology as simplistic and more like a heuristic trick that lacks solid theoretical support; the same reviewer notes the approach is confined to forecasting tasks (not classification, interpolation, or anomaly detection) without stronger justification. (Reviewer 1) Other reviewers (scores 6,8,8) consider the framework novel.
- **Unfair comparison due to input length discrepancy:** Baselines use input length 512, while ICTSP uses 1440. This longer input window may allow ICTSP to capture longer-range dependencies, making the comparison unfair. (Reviewers 2, 3) Request: Provide results with ICTSP input length set to 512 for equitable comparison in Tables 1 and 6. (Reviewer 3) Also requested: Rerun baselines under the same experimental settings or articulate rationale for chosen lengths. (Reviewer 2)
- **Baseline results collected from source papers with different settings:** Baselines are taken from source papers that often use different input lengths, potentially leading to unfair comparisons. (Reviewer 2)
- **In-context learning mechanism not convincingly demonstrated:** Because adjacent historical data is used as context examples, the model may simply benefit from a longer input window rather than truly learning from in-context examples in a generalizable way. (Reviewer 3) Request: Ablation study using randomly selected examples (without look-ahead bias) instead of adjacent history to clarify this design choice. (Reviewer 3)
- **Missing computational costs details:** No computational cost analysis or details for Table 5 (number of layers, hidden dimensions) are provided. (Reviewer 2)
- **Zero-shot improvements over full-data not sufficiently explained:** The paper does not adequately justify why ICTSP shows a pronounced advantage in few-shot and zero-shot settings compared to full-data tasks. (Reviewer 1)
- **Model reduction analysis lacks support:** The adaptive model reduction feature is claimed but lacks visualization or detailed examination; it is unclear whether it significantly contributes to performance or is a byproduct of the architecture. (Reviewer 3) Request: Provide more detailed analysis/visualizations for Adaptive Model Reduction. (Reviewer 3)
- **Formulation of existing TSF Transformers incomplete:** Methods using patching embedding (e.g., [1,2]) cannot be simply categorized as Temporal-wise or Series-wise in Section 2.2. (Reviewer 2) Request: Add discussion of patching-based methods from an ICL perspective. (Reviewer 2)
- **Cross-channel dependencies not addressed:** How ICTSP handles inter-channel relationships (e.g., in traffic data) is unclear. (Reviewer 3)
- **Code repository inaccessible:** The provided GitHub link is broken, hindering reproducibility. (Reviewer 1)
- **Presentation could be more accessible:** More detailed explanation and illustration of the “using time series forecasting tasks as input tokens” idea and its implementation would help readers outside the immediate field. (Reviewer 4; Reviewer 1 gave presentation score 2, others higher)
