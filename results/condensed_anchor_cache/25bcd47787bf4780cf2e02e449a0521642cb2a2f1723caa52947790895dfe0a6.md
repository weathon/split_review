## Merged Review

### Summary
The paper introduces EdgePrompt, a graph prompt tuning method that learns prompt vectors for edges to adapt pre-trained GNNs to downstream tasks. EdgePrompt integrates edge prompts through message passing, and EdgePrompt+ customizes prompts per edge via anchor prompts and scoring. Experiments on multiple datasets (ten) and pre-training strategies (four) for node and graph classification show improvements over fine-tuning and existing prompt methods.

### Strengths
- **Clear motivation and presentation** (Reviewers 1, 3, 4): The paper is well-organized, easy to follow, and motivated by the need to integrate structural knowledge via edge-level prompts.
- **Compatibility with pre-trained GNNs** (Reviewer 1): EdgePrompt can be integrated with various existing pre-trained GNNs.
- **Bridges objective gap** (Reviewer 2): Edge-level prompts help align pre-training and downstream objectives.
- **Extensive experiments** (Reviewers 2, 3): Evaluated on diverse datasets and multiple pre-training strategies (including Infomax, EdgePred, AttrMasking, MGSSL, GraphMAE, Mole-BERT are suggested as additional comparisons), showing performance gains.
- **Theoretical analysis** (Reviewers 3, 4): The paper provides theoretical guarantees (e.g., universality of GPF) and formal derivations to support effectiveness.

### Weaknesses
- **Overly strong assumption of single edge type** (Reviewer 1): The adjacency matrix is modeled as \(\mathbf{A} \in \{0,1\}^{N \times N}\) (line 154), which implies no multi-relational graphs. Since the method focuses on edge-level prompting, ignoring multiple edge types undermines the contribution. The paper should clarify this limitation.
- **Missing edge-level downstream tasks** (Reviewers 1, 4): The experiments only cover node and graph classification, not edge classification or link prediction. For a method emphasizing edge prompts, this is a significant gap. Real-world scenarios often require predicting edge types (e.g., evolving social network features). If out of scope due to unavailable pre-trained models, that limitation should be stated.
- **Technical contribution overlap / insufficient novelty** (Reviewer 1): Core Equation (4) in EdgePrompt+ closely resembles the relation weighting in CompGCN, which also uses base embeddings and scoring. The paper needs to elaborate on unique technical contributions beyond that.
- **Unclear motivation and advantages over existing prompt methods** (Reviewer 4): Why is EdgePrompt necessary? What core problem does it address compared to ALL-in-one and GPF? The paper’s motivation for designing edge-level prompts is insufficiently argued.
- **Per-layer prompt vectors not justified** (Reviewer 4): Unlike ALL-in-one and GPF (which add prompts only in the first layer to reduce dependency on model structure), EdgePrompt sets different prompt vectors \(p^{(l)}\) for each layer. The rationale for this design is not explored, and no ablation or comparison demonstrates its necessity.
- **Shared prompt vectors vs. computational complexity** (Reviewer 2): EdgePrompt uses shared prompts that may not capture diverse edge relationships; EdgePrompt+ adds anchor prompts and score calculations, increasing complexity and cost for large graphs.
- **Few-shot learning struggles** (Reviewer 2): The method underperforms in few-shot scenarios because most edges lack supervision. A reviewer asks how to improve performance in few-shot node classification.
- **Inaccurate claim about GraphPrompt** (Reviewer 3): The paper states GraphPrompt is based on a specific pre-training strategy (link prediction). Actually, GraphPrompt is not strategy-specific; link prediction can be replaced, as unified by GraphPrompt+ via subgraph similarity for any contrastive method. This inaccuracy weakens the positioning.
- **Missing comparison with GraphPrompt+** (Reviewer 3): GraphPrompt+ also adds prompt vectors to each layer of the pre-trained encoder. The paper lacks a detailed comparison of how EdgePrompt’s prompt integration differs from layer-wise prompt addition in GraphPrompt+.
- **Unclear anchor prompt initialization and representation** (Reviewer 3): The meaning of anchor prompts in EdgePrompt+ is unclear. It appears they address overfitting from learning edge-specific prompts, but the paper does not explain what they represent, how they are initialized, or how they differ from GNN parameters. Conditional prompting is suggested as a more reasonable alternative.
- **No edge features in datasets** (Reviewer 4): The datasets used do not contain initial edge features, raising doubts about effectiveness on graphs that naturally have edge features. The paper should discuss how EdgePrompt integrates with existing edge features and evaluate such scenarios.
- **Limited pre-training models tested** (Reviewer 1): The experimental section could include more classic and promising pre-trained GNNs (Infomax, EdgePred, AttrMasking, MGSSL, GraphMAE, Mole-BERT) or provide an explanation for their exclusion.
- **Efficiency analysis missing** (Reviewer 1): Figure 2 shows convergence in epochs, but the paper lacks learning curves or running time comparisons to evaluate computational overhead.
