## Merged Review

### Summary  
LayouSyn is a two-stage text-to-layout generation framework: (1) objects are extracted from the text by a lightweight open-source LLM, and bounding boxes are obtained via GroundingDINO (used only during training); (2) a conditional diffusion Transformer predicts the layout (bounding boxes) conditioned on T5-encoded text. The pipeline is trained end-to-end on image-caption pairs (COCO augmented with GroundingDINO) and evaluated on NSR-1K and COCO-GR. Two reviewers (R1, R4) gave scores of 5 and were generally positive; two (R2, R3) gave scores of 3 and were more critical.  

### Strengths  
- The acquisition pipeline (LLM for objects + GroundingDINO for boxes) is valid and brings robustness from vision-based models (R1, R2).  
- Converts captioned datasets (e.g., COCO) into text-to-layout training data, enabling open-vocabulary generation (R2).  
- Superior performance on closed and open-vocabulary benchmarks (e.g., Table 5) compared to baselines like LayoutGPT (R1, R3).  
- Versatile: supports LLM-initialization to reduce sampling steps and object addition for image editing (R2, R3).  
- Supports various generation resolutions (R2).  
- Reduces dependency on large, closed-source LLMs, offering a more transparent and cost-effective solution (R3).  
- Proposes a text-conditioned layout generator using diffusion models (R4).  

### Weaknesses  
- **Evaluation validity and fairness**:  
  * Table 5’s evaluation is questionable because GLIDE (layout-to-image) is also trained on COCO, introducing bias; a training-free method (e.g., layout-guidance) should be used (R1).  
  * Closed-set evaluation on COCO uses Layout2Im (2019) for image generation, which is outdated and inappropriate for measuring layout quality; it is unclear why GLIGEN was not used instead (R2).  
  * Numerical reasoning experiments (Tab 5) are unfair: the proposed method pre-extracts objects via LLM, so count accuracy depends entirely on LLM prompt engineering, not on the diffusion model (R2).  
  * Using CLIP similarity for numerical/spatial reasoning is not intuitive (R2).  
  * Human evaluation (Tab 4) shows insignificant advantage, uses graduate students (not a proper evaluator group), and the setup is arbitrary (R1).  
  * Image quality from GLIGEN is unsatisfying and cannot compete with modern generators (FLUX, SD3); layout is too simplistic to capture real-world overlap, occlusion, and poses (R4).  
  * Only LayoutGPT is compared as open-vocabulary baseline; other methods (e.g., LayoutDM) could be adapted but were not surveyed or compared (R2, R3).  

- **Limited novelty and theoretical depth**:  
  * All key components (LLM, GroundingDINO, diffusion Transformer) are off-the-shelf and rarely altered, yielding limited scientific novelty (R1, R3).  
  * Theoretical analysis is incremental; the work is engineering-like and does not meet ICLR standards (R3).  
  * The contribution of the trained diffusion model for location prediction is not clearly disentangled from the LLM’s role (R2).  
  * The claim of being “first end-to-end pipeline” is overstated and amounts to an engineering improvement (R3).  

- **Complexity and efficiency**:  
  * The two-stage pipeline adds complexity; details on computational efficiency and scalability are lacking (R3).  
  * Throughput is a concern: 250 denoising steps are used; impact of faster schedulers (e.g., DDIM with 10/20 steps) is not explored, and current throughput compared to the baseline is not reported (R2).  

- **Missing analysis and ablations**:  
  * No ablation studies on key components (e.g., language model size, transformer architecture) (R3).  
  * Evaluation metrics for semantic/geometric plausibility need more discussion; correlation with human judgment is unclear (R3).  
  * No experiments demonstrating generalization to real-world layout generation (R3).  
  * Text prompts used are simplistic (only quantities and object names) (R4).  

- **Presentation issues**:  
  * Figure 6 has confusing “Top”/“Bottom” indicators that appear to be typos (R1).  
  * Figure 2 has unclear denotations (e.g., “T5”, “LM”) and lines with unclear colors (R3).  
  * Emphasis on using an open-source LLM is confusing/unnecessary because baselines like LayoutGPT can also use open-source LLMs (R1).  
  * Diversity of the layout generator is shown but could be explored further; applications should be extended beyond image generation (R4).
