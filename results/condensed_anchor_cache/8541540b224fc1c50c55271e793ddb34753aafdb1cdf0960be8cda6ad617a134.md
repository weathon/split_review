## Merged Review

### Summary
The paper proposes PAIR, an automated red-teaming method that uses an attacker LLM to iteratively refine jailbreak prompts against a target black-box LLM, inspired by social engineering attacks. Experiments show PAIR often requires fewer than twenty queries and achieves competitive jailbreak success rates on GPT-3.5/4, Vicuna, Gemini, and other models compared with GCG. Reviewers found the method sensible, novel, and query-efficient, but raised significant concerns about technical depth, evaluation rigor, baseline comparisons, query fairness, and result consistency across models.

### Strengths
- The proposed method is sensible and novel: it uses an attacker LLM with chain-of-thought and in-context learning to automatically generate semantic jailbreaks, mirroring human red-teaming more closely than prior work (R1, R2, R3, R4).
- Query efficiency is a key strength: often fewer than twenty queries per jailbreak, orders of magnitude less than GCG (R1, R3, R4).
- The paper includes ablation studies that demonstrate the importance of several components of the system prompt (R1, R4).
- Presentation is clear, with detailed prompt design and methodology (R4).
- Results on multiple black-box LLMs (GPT-3.5/4, Claude-1/2, PaLM-2) are remarkable, showing broad applicability (R3). Reviewer 3 (score 6, more positive) particularly highlighted the novelty and importance of query-efficient black-box red-teaming.
- The work addresses an active and important area: LLM safety and red-teaming (R2).

### Weaknesses
- **Technical contribution is limited.** The method is fairly simple and heuristic, with the main innovation being the system prompt in Appendix B. There is little insight into why the approach works or analysis of the strategies the attacker LLM generates (R1, R2, R4). R4 questions whether the long, complex system prompt is truly necessary despite the ablation.
- **Baseline comparisons are insufficient.** Only GCG is used as a baseline; missing baselines include the few-shot iterative method from Perez et al. and handcrafted jailbreaks from jailbreakchat.com (R1, R2). Transferability comparisons—since GCG can craft adversarial prompts that transfer to other LLMs—are also absent (R2).
- **Evaluation has several issues:**
  - Only 50 test prompts from AdvBench are used, raising concerns about generalizability (R2).
  - The evaluation uses temperature=0 for target models, which is not the default setting. A recent study (arXiv:2310.06987) shows that changing generation hyperparameters can weaken safety alignment; results with default parameters (and more runs for statistical meaning) are needed (R3).
  - GPT-4 is used as the judge for evaluating jailbreak success. This makes results hard to reproduce (API model not guaranteed) and raises reliability concerns, especially if the judge model is the same as the attacker/target. Cross-validation with manual checks or the word list from Zou et al. is recommended (R1, R2).
- **Query analysis may be unfair to GCG.** PAIR is prompt-specific: the number of queries grows linearly with the number of test prompts. GCG finds a universal adversarial suffix, so once found it requires zero queries per new prompt. The paper should compare on the same 50 prompts and show a jailbreak success rate vs. query count plot (R3). The claim that PAIR uses ~20 queries while GCG uses 256,000 is misleading because GCG can be run per prompt; a fair comparison on the same set would clarify (R3).
- **Missing experiments:** GPT-4 is not used as a target despite being available (R1). It is surprising that GPT-3.5 performs worse than Vicuna 1.5; GPT-4 experiments would be informative. Also, the specific versions of closed-source models (e.g., GPT-3.5, GPT-4) are not reported, which is critical for reproducibility (R4).
- **Inconsistent jailbreak success across models.** PAIR fails on Llama2 and Claude (low success rates), making the method less convincing and its generalizability questionable (R4). This may stem from the naive loss function (True/False scoring), which resembles random searching and lacks a meaningful optimization signal (R4). Minor: jailbreaking percentages are generally low for several LLMs (R2).
- **Factual error:** Section 3.3 claims that modifying the system prompt is a feature only available on open-source LLMs, but OpenAI API allows editing system prompts, and GPT-3.5 experiments in the paper use this (R1).
- **JSON format handling is unclear.** The attacker LLM could violate the required JSON output format. How often does this happen and how is it handled? (R1). Figure 4’s left plot is ambiguous: the x-axis appears to be depth, but the caption does not match the context (R1).
- **Related work omitted:** Query-based black-box attacks on ML models are relevant for discussing query efficiency, yet the paper only covers recent LLM jailbreaking works (R3).
