## Merged Review

### Summary
This paper proposes MemTree, an online algorithm that uses a dynamic, tree-structured memory representation to manage long-term context for LLMs. Construction involves encoding information, traversing the tree, expanding leaf nodes when similarity to existing nodes is below a threshold, then summarizing and propagating aggregated content upward to parent nodes. The retrieval process flattens the tree for efficient matching. The algorithm is evaluated on four benchmark datasets (MSC, MSC-E, QuALITY, and others) for multi-turn dialogue and document QA. Results show strong performance in long-context tasks, often matching or surpassing offline methods like GraphRAG and RAPTOR while offering higher update efficiency.

### Strengths
- The algorithm design is clear, well-defined, and does not make excessive claims; the description and experimental setup are straightforward.
- Extensive experiments and analysis are provided, and most baselines are outperformed on the tested benchmarks.
- The tree structure effectively organizes memory content, mimicking how humans summarize and store knowledge at higher abstraction levels.
- On long-context dialogue tasks (MSC, MSC-E) MemTree shows strong and stable performance; on QuALITY it matches or surpasses offline methods (e.g., GraphRAG) with better update efficiency.
- The method provides higher update efficiency than offline approaches (RAPTOR, GraphRAG) while achieving comparable performance.
- The flattened retrieval mode is simple and enhances efficiency compared to traditional tree-based search, and the dynamic feature allows seamless integration with LLMs.

### Weaknesses
- Performance improvements are less pronounced on non-long-term dialogue data; generalizability to other tasks is limited (Reviewer 1).
- The retrieval process flattens the tree and uses methods from prior work, which overlooks the stored structural characteristics; it is unclear how collapsing the hierarchy ensures more efficient retrieval than directly traversing all nodes to find the closest match (Reviewers 1, 2).
- Lack of specific experiments comparing update and retrieval times against baselines, despite efficiency claims; no breakdown of computational costs (e.g., time per instance, memory usage, number of operations) or how input length and memory size affect efficiency (Reviewers 2, 4).
- Insufficient details on how memory is constructed for each evaluation dataset. For example, lines 303–306 state that MemTree is online while RAPTOR is offline; this may imply MemTree’s memory is typically smaller, making direct comparison of results difficult (Reviewer 2).
- No experiments on the impact of varying the similarity threshold, which controls tree width (Reviewers 2, who also note that such experiments would be beneficial).
- The analogy to human cognitive schemas is unclear: does it lie in dynamic updates or the tree structure? Human schemas are typically considered graph-like, not strictly tree-like (Reviewers 2, 3).
- Aggregation (parent node summarization) relies heavily on the LLM; the paper does not sufficiently discuss how this affects accuracy—e.g., whether semantic similarity matching remains reliable after abstraction and summarization (Reviewer 1).
- Collapsed retrieval from non-leaf nodes may lead to information loss; for knowledge that spans multiple branches, the tree structure may not retrieve the complete required set (Reviewer 3).
- There is no explicit mechanism to enforce tree balance; observed balance may be due to insufficiently long contexts, and imbalance could degrade summarization quality in non-leaf nodes (Reviewer 3).
- No detailed error analysis for RAG tasks: errors could stem from embedding similarity inaccuracies, incomplete retrieved knowledge, or summarization errors (Reviewer 3).
- Only two base LLMs are tested (GPT-4o and LLaMA2); more models across different sizes and architectures are needed to demonstrate generalizability, including other long-context LLMs (e.g., long-lora, LongLLaMA) and prompt compression methods (e.g., LongLLMLingua) (Reviewer 4).
- The cost of using GPT-4o (API calls, tokens, overall expense) is not considered in efficiency evaluation, which is critical for practical applications (Reviewer 4).
- More human studies are needed, especially comparing retrieval quality across methods using human-annotated evidence, to evaluate relevance, coherence, and why MemTree is better (Reviewer 4).
- Minor: typo on line 154 where the first \(c_v\) should be lowercase (Reviewer 1).
