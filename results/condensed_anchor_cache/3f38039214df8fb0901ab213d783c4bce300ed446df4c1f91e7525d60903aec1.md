## Merged Review

### Summary
The paper addresses the domain shift of CLIP ViTs from global image representation to local region representation for open-vocabulary dense prediction (detection, semantic/panoptic segmentation). It proposes CLIPSelf, a self-distillation method that adapts the image-level recognition ability of CLIP ViT to local regions without requiring any region-text pairs. CLIPSelf aligns a region representation extracted from the dense feature map with the image-level representation of the corresponding image crop, using only unlabeled images. The method is evaluated on multiple benchmarks (COCO, LVIS, ADE20K, etc.) and achieves new state-of-the-art results, outperforming prior works like F-VLM, CORA, and RO-ViT under comparable settings. Reviewers find the idea simple, well-motivated, and the experiments extensive, but raise concerns about novelty relative to ZeroSeg, overfitting to the COCO distillation set, lack of comparison with Swin-based methods (GLIP, Grounding DINO), and insufficient analysis of generalization.

### Strengths
- The paper tackles an important and timely topic: adapting large vision-language models (CLIP) for open-vocabulary dense prediction.
- The core idea is conceptually simple, intuitive, and well motivated by a clear analysis (Fig. 1) showing that CLIP ViT has strong image-level but weak region-level features compared to CLIP CNN, and that cropped image patches outperform feature pooling.
- CLIPSelf requires only images (no region-text pairs, no extra annotations), which simplifies the data and modeling pipeline.
- Extensive experiments span three open-vocabulary dense prediction tasks (object detection, semantic segmentation, panoptic segmentation) across multiple benchmarks (COCO, LVIS, ADE20K, etc.), with thorough ablation studies.
- Results are strong: CLIPSelf outperforms prior works that use equivalent frozen backbones (e.g., F-VLM, CORA) and notably beats RO-ViT, which trains a new backbone from scratch. Combining CLIPSelf with RegionCLIP yields further gains.
- The paper is clearly written, with sufficient technical detail to reproduce the method. The writing clarity has improved since a previous submission (NeurIPS 2023).

### Weaknesses
1. **Overlap with prior work (ZeroSeg):** The methodology resembles ZeroSeg (Chen et al., ICCV 2023), which also distills patch-level CLIP knowledge to regional feature representations for open-vocabulary segmentation. The distinction in the distillation process and loss functions is not sufficiently articulated. [Reviewer 2; novelty concern]
2. **In-domain distillation and limited generalization:** All main experiments use COCO/LVIS images for self-distillation. This may overfit to the COCO distribution, favoring downstream tasks on COCO and ADE20K. The paper lacks experiments with other unlabeled datasets (e.g., CC3M, YFCC-15M, SA-1B) to verify that improvements are not simply from in-domain training. [Reviewers 2, 3]
3. **Missing comparison with Swin-based open-vocabulary detectors:** The paper only studies ViT backbones. Many state-of-the-art open-vocabulary detectors (GLIP, GLIPv2, Grounding DINO) use Swin Transformers (which have local attention and translation equivariance). It remains unclear whether CLIPSelf benefits Swin-based models or how it compares to these methods. [Reviewer 4; also implied by Reviewer 1’s question about local attention]
4. **Unclear necessity of task dataset for distillation:** Reviewer 3 questions whether self-distillation on COCO is necessary or if a large diverse unlabeled set (e.g., Conceptual Captions, RedCaps, SA-1B) would suffice. An experiment with such data would strengthen the claim that CLIPSelf is a general fine-tuning step.
5. **Potential loss of zero-shot recognition capacity:** After distillation, it is unclear whether the new localized representations preserve the original CLIP zero-shot classification and retrieval ability. Reviewer 1 suggests testing this via a retrieval experiment or evaluating features directly for zero-shot detection/segmentation (e.g., as in RegionCLIP Table 4).
6. **Padding handling for object detectors:** Current ViT detectors (e.g., ViTDet) pad input images to a square, introducing padding patches unseen by pre-trained CLIP. Reviewer 3 asks whether accounting for this (e.g., adding random padding during distillation) would ease adaptation for detection.
7. **Limited comparison with ViT-based methods:** In Table 3, most cited prior methods use CNN or Swin backbones; the few ViT-based methods use variants different from the ones used with CLIPSelf, making direct comparison difficult. [Reviewer 4]
8. **Minor presentation issues:** Figure 3(b) uses “initiate” instead of “initialize”; Figure A2 caption incorrectly says “image segmentation” instead of “object detection”. [Reviewer 3]
