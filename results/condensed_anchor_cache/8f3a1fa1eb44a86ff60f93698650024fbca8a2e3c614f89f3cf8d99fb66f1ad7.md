## Merged Review

### Summary
Three reviewers assessed the paper. Reviewer 2 was considerably more positive (score 5, contribution 4) than Reviewers 1 and 3 (score 3, contribution 2). All reviewers agree the paper addresses a relevant problem (scalable graph reasoning with LLMs) and demonstrates good performance on certain tasks. However, Reviewers 1 and 3 raise major concerns about novelty, comprehensiveness of experiments, missing evaluations on complex problem types, and insufficient analysis of computational cost and scalability, while Reviewer 2, though positive, also notes missing ablations, baseline comparisons, and efficiency analysis.

### Strengths
- The paper is well-written, easy to follow, and clearly identifies the critical issue that larger graph size causes performance drops in single-LLM graph reasoning (Reviewers 1, 2, 3).
- The proposed GraphAgent-Reasoner (GAR) is a fine-tuning-free, multi-agent collaboration framework that decomposes graph problems into node-centric tasks, effectively improving accuracy and scalability (Reviewers 1, 2).
- GAR achieves near‑perfect accuracy on polynomial‑time graph reasoning tasks from the GraphInstruct dataset, significantly outperforming both closed‑source and fine‑tuned open‑source models, especially on larger graphs (Reviewers 1, 2).
- The paper provides a novel insight by analyzing why a single LLM cannot handle large‑scale graph analysis from a memory perspective (Reviewer 3).
- The framework is inspired by distributed algorithms and provides detailed algorithmic processing steps for several fundamental graph theory problems (Reviewer 3).

### Weaknesses
- **Novelty and task‑specific design**: The multi‑agent approach is adopted from other domains without a specific design tailored to graph reasoning; overall novelty is limited (Reviewer 1).
- **Missing evaluation on complex problem types**: The paper evaluates only 6 of the 9 problem types in the GraphInstruct/GraphWiz dataset. No results are provided for maximum flow, Hamilton path, and subgraph matching (which are medium/hard tasks), making the claim of solving complex graph reasoning over‑claimed (Reviewers 2 [Question 2], 3 [Weakness 1, Question 1]).
- **Potential error in example output**: Reviewer 3 tested the provided Hamilton Path execution example (Appendix) with GPT4‑turbo and found that GAR’s output appears incorrect; this raises doubts about the soundness of the results.
- **Insufficient baselines**: Missing comparison with single LLM using advanced prompting techniques such as Chain‑of‑Thought (CoT), Tree of Thought (ToT), and Iteration of Thought (IoT) (Reviewer 2). Additionally, baselines should be given the same distributed graph algorithms (e.g., for shortest path) for fair comparison; it is unclear whether they were (Reviewer 1).
- **Lack of computational cost analysis**: No analysis of reasoning time, token consumption, API costs, memory usage, or number of agents required as graph size increases. The method models each node as an agent, which may incur high cost and may not scale to very large graphs (Reviewers 1, 2, 3 [Weakness 2, Question 2]).
- **Missing ablation and hyperparameter studies**: No evaluation of the impact of using different LLMs, varying the maximum number of iterations, or incorporating a distributed algorithm library (Reviewer 2).
- **Unclear experimental details**: Experiment 2 lacks construction details and sample description (Reviewer 1). The paper does not mention whether results are from repeated experiments (Reviewer 3). The termination condition for agent communication is not clearly specified (Reviewer 2, Question 1). The method for message preparation and state update is only given by examples, not a principled description (Reviewer 1).
- **Inconsistent performance pattern**: In Figure 4(a), performance of GraphAgent and GraphWiz‑DPO is better at graph size 80 than at size 60, which is not explained (Reviewer 3).
- **Missing experiment on PageRank**: A distributed algorithm for PageRank is provided in the appendix but no corresponding quantitative experiments are given (Reviewer 3, Question 5).
- **Underutilization of LLM reasoning**: The framework may underuse the generative and reasoning capabilities of LLMs for interpretability (Reviewer 2, Question 3).
- **Typos and presentation issues**: Missing spaces (e.g., “Reasoner(GAR)” in line 80, Figure 4 caption) and “TAG” should be spelled out as “Text‑Attributed Graph” for clarity (Reviewer 2).
