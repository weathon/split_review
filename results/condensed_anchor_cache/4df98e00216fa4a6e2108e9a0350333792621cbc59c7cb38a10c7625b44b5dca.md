## Merged Review

### Summary
This paper proposes online speculative decoding (OSD), which continuously updates the draft model via online knowledge distillation on observed user query data to improve token acceptance rate and latency reduction. The authors frame the learning as online knowledge distillation (teacher=target LLM, student=draft model). Results on synthetic and real query data show a substantial increase in token acceptance rate (0.1 to 0.65) translating to 1.42×–2.17× latency speedup. Reviewers generally find the idea simple and clear, with thorough theoretical analysis and distribution-shift evaluation, but raise concerns about missing comparisons, real-hardware evaluation, novelty, and experimental scope.

### Strengths
- **First to introduce online draft model updates** to speculative decoding; previous work assumed a static draft model (R1, R3, R4).
- **Idea is simple** and continuously modifying the draft model can improve token acceptance rates and provide higher speedups (R3).
- **Thorough theoretical analysis** of speedup, latency, and FLOPs (R1).
- **Clear presentation** of the method (R4).
- **Evaluation is thorough** under distribution shift to mimic real-world scenarios; the space of distillation is well explored (R3, R4).
- **Demonstrates that online decoding/adaptation improves acceptance rate** over offline static training (R2).

### Weaknesses
- **Novelty and contribution unclear** (R2 rates contribution 2/4; others 3/4). The idea is straightforward: adapting a draft model via distillation on observed data (R2, R3). It is unclear what the true novelty is beyond that.
- **Lack of comparison with SOTA multi-draft model methods** such as Medusa (multi-head speculative decoding) (R1).
- **No real-hardware evaluation; speedup is theoretically estimated** (R1). Concrete runtime numbers are missing; only token acceptance rates are reported (R3).
- **Memory bandwidth concern:** The authors claim spare compute because LLM serving is memory-bandwidth bound, but concrete numbers for this are missing. The draft model’s training also consumes memory bandwidth and could interfere with LLM serving (R3).
- **Baseline comparisons are insufficient:**
    - Compared only against offline distilled model, not against vanilla speculative decoding (R4) or against a static model on mixed data (R2).
    - Claim of expected improvement over vanilla SD is not shown empirically (R4).
- **Translation between token acceptance rate and latency reduction:** Is this done empirically or theoretically? More clarification needed (R4).
- **Data mixes and evaluation scope:**
    - Why separate draft models per language? What are English-only numbers without filtering? (R3)
    - Does the approach fail on certain data mixes? No evaluation on LMSys-chat without filtering (R3).
    - Performance during the first two epochs of fine-tuning is not shown (R4).
    - When mixing data in a sequential evaluation vs. mixing, how does OSD compare to static models? (R2)
- **Real-world deployment realism:**
    - Fine-tuning requires computational resources; could those resources instead be used to fit a larger draft model? Why use online distillation? (R4)
    - The duration of each phase in the distribution-shift experiments is set arbitrarily and may not reflect real deployment (R4).
