## Merged Review

### Summary
CASD (Context-Aware Speculative Decoding) is a training-free, draft-model-free decoding method that retrieves draft tokens from the input context, then accepts them via a conditional probability threshold. It targets long-context tasks (QA, summarization, code completion) and reports average generation score improvements of +3.3, a mean acceptance length of 3.10, and a speed-up ratio of 1.99 over vanilla Llama3.1-8B-instruct. CASD is also combined with prompt compression (LLMLingua‑2) to reduce memory overhead.

### Strengths
- Plug-and-play, requires no additional training or draft models; easy to implement.
- Improves generation accuracy across multiple LongBench tasks (QA, summarization, code completion) by +3.3 average score.
- Reduces inference latency, achieving a speed-up ratio up to 2× (mean acceptance length 3.10, speed-up 1.99).
- Works well with context compression (e.g., LLMLingua‑2), addressing memory overhead of long contexts.
- Conditional verification provides flexibility to balance context reliance and generation quality.
- Reasonable design for long-context tasks where the answer is likely to appear directly in the input.

### Weaknesses
- **Novelty is limited.** The method is a minor modification of REST: the same retrieval algorithm is used, but the general external database is replaced by the input context. The contributions are largely incremental.
- **Generalizability is limited.** CASD is only applicable to tasks with long prompts where answers are extractable from the input; it is unsuited for abstractive/creative generation, common chatbot scenarios (which often use different templates per dataset), and short prompts. It also conflicts with common sampling techniques (e.g., temperature, top-k) that are used for multiple generations per sample.
- **Soundness concerns with the verification scheme.** Using the original model itself as the draft model to compute probabilities is a backward step compared to standard speculative decoding (where a small draft model provides speed). This approach may yield only minor speed gains. Accepting the longest draft can violate the autoregressive style and may cause unwanted text behavior.
- **Insufficient baseline comparisons.** No comparison is made with other training-free speculative decoding methods (e.g., REST, “Inference with Reference”). Traditional speculative decoding with a small LM is also not compared. Only vanilla decoding of Llama3.1-8B-instruct is used as a baseline. Only one base model is evaluated, leaving open the question of how base model performance affects the improvement.
- **Threshold sensitivity and lack of generalizability.** The acceptance threshold δ is manually tuned per dataset (0.1 on most datasets but 1e-5 on NQ); performance varies significantly with δ. There is no generalizable heuristic to set δ automatically. The reason for different thresholds across datasets is not explained (e.g., the higher speed-up on NQ may be due to its lower threshold).
- **Incomplete experiment setting details.** The paper does not specify the temperature, sampling sizes, maximum context length, or maximum generation token length used for the vanilla decoding baseline.
- **Missing ablations.** To ablate the effect of conditional verification (threshold-based acceptance), the method should be compared with REST’s top‑k verification, not just vanilla decoding.
- **Writing and presentation issues.** Details of prompt compression (why LLMLingua‑2 is used and why it works) are limited. A typo exists: “mean accuracy length” (line 369) should be “mean acceptance length.”
