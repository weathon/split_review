## Merged Review

### Summary
The paper introduces DaTikZ, the first large-scale dataset of 120 k TikZ drawings paired with captions, and fine-tunes LLaMA and CLiMA (LLaMA + CLIP adapter) for TikZ code generation. Models are compared with prompted GPT‑4 and Claude‑2. Reviewers generally found the dataset contribution significant, the evaluation thorough, and the writing clear. However, there are substantial concerns about insufficient ablation studies (missing baselines, unreported effects of data sources, augmentation, re‑sampling, and CLiMA’s training strategy), limited output examples, and the modest technical novelty of the baseline method. One reviewer (score 8) was notably more positive, praising the dataset as first‑of‑its‑kind and the paper’s high quality, while three reviewers (scores 6) had more reservations.

### Strengths
- **Novel dataset contribution**: DaTikZ is the first large‑scale dataset of TikZ drawings aligned with captions (120 k pairs), filling a gap in scientific vector graphics generation. The release of dataset, model weights, and code is a significant resource for the community (R1, R2, R3, R4).
- **Evaluation thoroughness**: The paper uses multiple automatic metrics and two human subjective evaluations (Sections 5.2 and D), providing comprehensive assessment. Metrics are extensive and convincing (R1, R2, R4).
- **Model performance**: CLiMA and LLaMA outperform commercial GPT‑4 and Claude‑2 in similarity to human‑created figures, with CLiMA additionally improving text‑image alignment. This demonstrates that fine‑tuning on a domain‑specific dataset can beat larger closed‑source models (R1, R2, R3).
- **Error handling**: The iterative regeneration strategy to ensure compileable TikZ code is a practical contribution (R1).
- **Clarity and presentation**: The paper is well‑written, easy to follow, with a clear description of dataset composition, model architecture, and evaluation choices. No typos (R1, R2, R3).
- **Memorization analysis**: The paper includes an analysis showing models are not susceptible to memorization, strengthening result validity (R2).

### Weaknesses
- **Insufficient ablation studies and missing baselines**:
  - No comparison with vanilla LLaMA (without fine‑tuning) or prompt‑tuned LLaMA, making the comparison with prompted GPT‑4/Claude‑2 not exactly fair (R2).
  - Effect of artificial samples (50 % of DaTikZ) not measured, as evaluation is on real samples only (R2).
  - Effect of iterative re‑sampling (average >1.5 regenerations) not reported; performance without regeneration is unknown (R2).
  - Effect of CLiMA’s data augmentation (50 % caption, 50 % reference image during training) not ablated (R2).
  - Contributions of individual DaTikZ data sources (curated vs. scraped from TeX Stack Exchange) not evaluated – a detailed analysis of biases, noise, and source importance is needed (R4).
  - Contribution of data augmentation techniques (geometric and color transformations) not assessed via ablation (R4).
- **Limited output examples**: Only 6 examples are shown in the appendix; one labeled “good” does not match the caption (“some dots are clustered together” but the image shows rows of points) (R2). More examples with simple captions in the main draft would help illustrate capabilities (R3).
- **Modest technical novelty**: The baseline method combining LLaMA with a CLIP adapter is a straightforward combination of existing methods. The novelty of the proposed approach is not clearly established relative to existing techniques (R4). The error handling strategy is standard practice in programming languages (R1). A more detailed comparison with existing methods and analysis of advantages/disadvantages is needed (R4).
- **Missing comparison with ChatGPT**: The paper does not compare with ChatGPT, even a fine‑tuned version on a small subset (R3). This would strengthen baseline comparisons.
- **Missing or under‑reported analyses**:
  - Code compilation success rate is not reported (R1).
  - The paper does not explore using TikZ compiler error messages or stack traces to improve iterative generation (R2).
  - How the specific prompt for GPT‑4 / Claude‑2 was chosen to ensure a fair comparison is not described (R2).
  - Examples of different models’ behavior to typographic attacks are not provided (R3).
  - Correlation between automatic evaluation metrics and human subjective evaluation is not measured; it is unclear if the authors plan to do so (R4).
  - No demonstration of interactive code editing/optimization in a chat‑like setting (R1).
- **Radar chart issue**: Figure 2’s radar charts could be improved by adjusting score ranges to allow cross‑chart comparisons (R4).
