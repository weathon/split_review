## Merged Review

### Summary
This paper introduces LLMEraser, a unified framework for parameter-efficient unlearning in LLMs that supports three tasks: instance removal, query modification, and response correction. The core technique uses influence functions to approximate the effect of data points, then applies parameter adjustments via PEFT (LoRA) without full retraining. All four reviewers acknowledge the problem is important and the framework is well motivated. However, there is a split: two reviewers (scores 8, confidence 4 and 3) are more positive about the method’s novelty and efficiency, while the other two (scores 6, confidence 3 each) raise substantial concerns about evaluation scope, forgetting metrics, and approximation errors.

### Strengths
- **Unified formulation** of three unlearning tasks under a single simple framework (all reviewers).
- **Practical efficiency**: the method avoids full model retraining by using influence functions + fast Hessian-vector products and mini-batches, with convincing convergence arguments (R1, R4). One reviewer specifically highlights this computational improvement for LLM applications (R4).
- **Clear taxonomy** of unlearning scenarios, well-defined and easy to follow (R2, R4). Two reviewers (R2, R4) find the writing clear; one reviewer (R1) disagrees and finds the paper hard to read.
- **Comprehensive evaluations** across recommendation and multimodal relation mining tasks, with both LLM and MLLM experiments (R1, R2, R4). However, other reviewers note important limitations in this same evaluation set (see Weaknesses).
- **Maintains model performance** after unlearning, and shows high efficiency compared to baselines (R3).

### Weaknesses
- **Limited evaluation scope and missing generative tasks.** All four reviewers express concern that experiments only cover tabular recommendation tasks and multimodal classification, not the core generative capabilities of LLMs (e.g., text generation, QA, summarization). Reviewer 2 specifically notes that real privacy concerns involve sensitive text (e.g., bank accounts, SSNs), which are not tested. Reviewer 3 states it is crucial to evaluate unlearning on generative tasks because they exhibit different unlearning characteristics. Reviewer 4 adds that the current tasks differ from those used in baseline papers, making cross-method comparison difficult. (R1 also suggests comparing to more unlearning approaches and evaluating asymptotic complexity rather than wall-clock seconds alone.)
- **Lack of forgetting evaluation.** Reviewer 3 points out that the paper does not measure how much the model actually “forgets” the removed data (e.g., drop in performance on removed samples, change in model output). This is a fundamental gap for an unlearning method. This concern aligns with Reviewer 2’s request for privacy-related metrics on realistic data.
- **Approximation errors from influence functions.** Reviewer 1 questions whether the method relies on first- or second-order expansions (influence functions typically use second-order; the limitation section mentions “first-order Taylor expansion”). Reviewer 4 elaborates that the first-order approximation can introduce estimation errors, especially given LLMs’ non-convex loss landscape, and the paper lacks a detailed error analysis to assess impact on unlearning precision. (Both reviewers consider this a significant limitation.)
- **Memory and scalability concerns.** Reviewer 4 provides a detailed criticism: the inverse Hessian-vector product, even with iterative solvers, still requires storing intermediate gradients and Hessian approximations, leading to high memory overhead. The paper does not analyze memory footprint, storage of gradients, or whether the method can run on lower-memory GPUs than an Nvidia A100. No comparison of memory usage with baselines is provided.
- **Missing experimental details.** Reviewer 4 notes that key configuration information (LoRA rank, number of trainable parameters, optimization settings, sample sizes in unlearning experiments) is not provided, making reproducibility and assessment of hyperparameter sensitivity difficult.
- **Distinction between pre-training and fine-tuning influence.** Reviewer 3 raises a conceptual question: when a sample was used in both pre-training and PEFT, it is unclear how to attribute influence solely to the PEFT module, and whether unlearning through PEFT alone is sufficient. The paper does not address how to tell whether forgetting occurs in the LoRA adapter or the base model.
- **Minor typos** (e.g., “handling handle” on p.9; R3).
- **Readability concerns** (R1): suggests moving most equations to appendix and focusing on high-level explanations in the main text; also notes that Algorithm 1’s adapter usage is unclear. (Contrast with R2 and R4 who find writing clear.)
