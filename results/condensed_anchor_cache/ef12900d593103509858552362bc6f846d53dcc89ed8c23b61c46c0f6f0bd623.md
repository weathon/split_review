## Merged Review

### Summary
The paper proposes a framework that learns state and action abstractions from language-annotated demonstrations. An LLM parses a language goal into a verb and objects (action predicates), which become an abstract action space. A point cloud transformer encodes raw states into a latent abstraction; an abstract transition model and a feasibility function are learned from demonstrations. During inference, a breadth‑first search plans a sequence of abstract actions, then a low‑level policy executes each. The method is evaluated on BabyAI and Kitchen Worlds, testing generalization to novel objects, environments, and longer horizons.

### Strengths
* **Originality**: The combination of symbolic planning with action predicates extracted from natural language and latent‑space representation learning via point cloud transformers is novel (R1, R2, R3, R4). The framework uses LLM prompting, imitation learning, and reinforcement learning in a new way (R2, R3).
* **Quality**: The overall description is easy to understand (R1, R2, R4). The problem is well‑motivated, the approach is clearly laid out, and the experimental design is sound (R3). The method generalizes across novel object instances, unseen concept compositions, and longer planning horizons (R1, R3, R4).
* **Clarity**: Figures help illustrate the overall approach (R1). The paper is mostly well‑written and the problem formulation is clear (R2, R3, R4).
* **Significance**: The work is interesting, integrates many components (R1), has potential to be impactful for language‑based agent interactions (R3), and can be adapted to other sequential planning domains (R3).

### Weaknesses
* **Missing training details and reproducibility**: Many critical details are omitted, making the results hard to reproduce (R1, R2, R4). Specifically missing: loss functions for state abstraction, abstract transition, and feasibility prediction; number of training trajectories; optimization algorithms; hyperparameters (learning rate, batch size); architecture of the abstract transition model; how the point cloud transformer is trained for each environment; details of the feasibility function; low‑level policy actor‑critic details. No code or supplementary material was provided (R2, R4). The inputs and end‑to‑end training process are unclear (R4). The evaluation protocol is vague – *“success rate”* is not defined (R2). The number of training runs and variance are not reported (R2).
* **Insufficient baseline comparisons**: The method is compared only against simple baselines (end‑to‑end RL, behavior cloning). It is not compared with hierarchical RL or other symbolic planning methods that use object‑centric representations (R1). Existing relevant approaches such as Peng et al. (*Learning with Language‑Guided State Abstractions*) and LIV (Ma et al. *LIV: Language‑Image Representations and Rewards for Robotic Control*) with PointCLIP are not discussed or compared (R4). For BabyAI, there are established baselines (Hui et al. *BabyAI 1.1*) that could be compared (R1).
* **Scalability concerns**: As the number of actions, objects, and their combinations increases, the required training data grows intractably (combinatorial explosion) because the abstract transition model must cover all combinations of abstract states and actions (R2). This raises doubts about feasibility in real‑world applications (R2).
* **Experimental evaluation issues**: 
    * The generalization test in BabyAI (withholding the red key) is more a verification that the model is agnostic to object properties; the accuracy for *“novel concept combinations”* is only 91%, and the reason for not reaching 100% is not explained (R4). 
    * No experiments evaluating the accuracy of the feasibility function were performed (R4). 
    * The Kitchen Worlds experiments involve mostly plans of length one or two, and details on the number of high‑level actions and the plans are missing (R1). 
    * The description of the experimental domains, especially the difference between key‑door and two‑corridor environments, is lacking (R3).
* **Role of LLM and “learning from language”**: The LLM is used only for parsing an instruction into action predicates; the rest of the pipeline is language‑independent (R1). The parsing could be done manually or by other methods, so it is unclear what is actually learned from language (R1). No rationale is given for using an LLM beyond demonstrating that it can parse such sentences (R1). Questions: What if the goal description does not reveal enough information to extract the required high‑level actions? (R1). Who provides the examples for prompting in Fig. 3? (R4).
* **Missing definitions and clarity issues**: *“Tasks”* and *“language goal”* are not formally defined (R2). The number of objects in the environment is assumed known? The pooling operation (max or average?) and the dimensionality of per‑object latent features are not specified (R2). The use of $\hat{s}$ for the next state is a deviation from RL conventions ($s'$), and it is unclear why (R2). Numerous typos and style issues are present (R2, R4).
* **Incorrect citation**: The claim that Silver et al. learn (invent) new predicates is incorrect (R4).

**Note on reviewer disagreement**: Reviewer 3 (score 8) found no major weaknesses, stating that the experimental design is sound and the results support the claims. In contrast, other reviewers raised significant concerns about reproducibility, scalability, experimental evaluation, and missing comparisons.
