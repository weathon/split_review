## Merged Review

### Summary
The paper proposes PromptGFM, a graph foundation model that replicates GNN message passing by prompting an LLM and uses a language-based graph vocabulary (textual node IDs) to enable LLM inference for node classification and link prediction. It comprises a graph understanding module (LLM prompted for neighbor aggregation over multiple hops) and a graph inference module (fine-tuned LLM on prompts with language-based IDs). Experiments on four citation datasets show competitive results. One reviewer (score 5) found the approach novel and strong, while three reviewers (score 3 each) were more critical, questioning the foundation model claims, experimental scope, and theoretical grounding.

### Strengths
- Novel attempt to unify LLMs and GNNs by prompting an LLM to simulate message passing, including explicit steps for feature transformation, message passing, and aggregation (R1, R2).
- Tackles the out-of-vocabulary (OOV) problem for nodes in LLMs by mapping nodes to language-based IDs (R1).
- Achieves superiority over several existing LLM+GNN architectures on node classification and link prediction (R1).
- Provides a comprehensive review of current methods and includes state-of-the-art baselines in Table 1 (R1). *Note: Reviewer 2 disagrees, stating strong baselines like TAPE are missing.*
- Intra- and inter-domain transferability experiments may be of interest (R3).
- Promising results on basic benchmarks (R4).

### Weaknesses
- **No faithful reproduction of GNN message passing:** Prompts perform sequential summarization, not the iterative message-passing and aggregation of GNNs (R1, R3). There is no formal analysis, proofs, or experimental evidence that LLM prompts can capture the math of message passing or its permutation-invariant property; autoregressive LLMs are permutation-variant due to positional encodings (R3). The claim of “oversmoothing” after 4 layers lacks evidence—there is no discrete node representation in the prompt space to measure distance between representations as formalized by Oono & Suzuki (2020) and Southern et al. (R3). The non-deterministic LLM may lose node/structural information across layers; the paper does not address how embeddings of all nodes are preserved (R1).
- **Text-only limitation & universality claim overblown:** The method requires text-attributed graphs; it cannot handle graphs without textual features (R2, R3, R4). The paper claims a “universal graph vocabulary” but does not propose new vocabulary—it relies on existing LLM token vocabularies and textual node descriptions (R3). The so-called “graph vocabulary” is simply a rephrasing of input textual features; how it addresses OOV is unclear (R1). Many existing methods (e.g., OFA, GraphText) also use textual node features in prompts, contradicting the claim that “existing methods treat nodes as OOV tokens” (R3). The universal vocabulary claim is further undermined because the inference LLM is fine-tuned only on the tasks/datasets used (R1). The distinction between a regular node textual feature and a language-based ID is unclear—the case study suggests the latter is just a rephrasing (R1). It is also unclear which module creates the vocabulary (Figure 4 shows it before the predictor LLM but Section 4.2 discusses it under the inference module) (R1).
- **Scalability and cost concerns:** Processing nodes sequentially raises practical issues for large graphs due to LLM input length limits and performance decline on long sequences; no demonstration of handling long-range dependencies (R1). Comparing billion-sized components (GPT 3.5 Turbo for Node IDs + fine-tuned T5) against much smaller GNNs (100–1000x smaller) that run on CPUs presents a biased and myopic perspective (R3).
- **Underwhelming experimental agenda:** Only 4 standard citation datasets for node classification and link prediction (R3, R4). Link prediction baselines are unsuited; the authors are aware of the stronger benchmark by Chen et al. (2024) comprising 20 tasks with baselines like BUDDY (R3). Inter-domain experiments are limited to citation graphs (Cora/Citeseer/Arxiv to PubMed), which may share patterns—not a convincing test of inter-domain generalization (R2). Table 1 missing strong baselines such as TAPE (R2). *Contrast: R1 praised the baselines as SOTA, but R2 and R3 disagree.*
- **Missing experimental details:** Not reported how node labels are encoded (text label or selection from options), number of negative samples for link prediction (for PromptGFM and GNN baselines), size of the fine-tuned T5 model, and whether fine-tuning was full or LoRA (R3). Also unclear: how are high-dimensional node features (e.g., Cora, PubMed) converted to text? (R1). How many tokens are needed per node? (R2).
- **Misleading terminology and presentation:** The term “prompt-based GNNs” is misleading because the model is an LLM, not a GNN; Figure 2 incorrectly portrays a GNN module where none exists (R1). The “Data Description” section mistakenly says datasets like Cora/Citeseer/PubMed are “introduced” by this work (should be “used”) (R1). Sections on graph vocabulary learning and GNN replication are overly detailed and should be condensed or moved to appendix (R1). Examples in Figure 3 and Appendix are not sufficiently informative; a concrete template with special tokens/words is needed (R1).
- **Novelty concerns:** The fundamental idea of prompting an LLM for 1-hop message passing is already explored in similar methods [1,3] (R1). The paper oversells its contributions (e.g., claiming “faithful reproduction” and “universal vocabulary” without support) (R3). It is unclear what novel technical contributions exist beyond combining existing techniques (R4).
