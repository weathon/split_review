## Merged Review

### Summary
GraphPulse is a framework for temporal graph property prediction that combines topological data analysis (Mapper method) and recurrent neural networks (LSTM+GRU). For each graph snapshot, it extracts handcrafted snapshot features (number of nodes, edges, average edge weight) and mapper features (number of nodes, edges, max cluster size, average cluster size, average edge weight from the Mapper graph). These features are fed into a sequential model to predict future graph properties, specifically binary classification of whether the number of edges will increase. Experiments on synthetic (ER, SBM) and real-world financial/cryptocurrency networks show a 10.2% ROC-AUC improvement over state-of-the-art baselines. The paper also introduces new cryptoasset benchmark datasets.

### Strengths
1. **Novel integration of TDA (Mapper) into temporal graph learning.** All reviewers recognize this as a significant methodological advancement. R2 (high confidence) calls it “interesting and innovative”; R3 and R4 highlight the novelty of using Mapper to capture topological structure for dynamic graph representation learning.

2. **Clear presentation and reproducibility.** R1 (low confidence) praises the clear exposition, helpful examples, and solid supporting materials; R4 agrees the paper is generally clear despite multiple steps. The algorithm is described as simple and easy to implement (R1).

3. **Newtonian phase space insight.** R3 (score 8, high confidence) considers the identification of graph evolution as a temporal trajectory in a Newtonian phase space a valuable theoretical contribution that advances understanding of graph evolution principles. (Note: R1 (score 6, low confidence) views this concept as interesting but unexploited in the actual model – see Weakness 4.)

4. **Strong empirical performance.** R3 and R4 note that GraphPulse achieves a 10.2% ROC-AUC improvement over state-of-the-art dynamic graph networks on several datasets.

5. **New benchmark datasets.** The paper creates and publishes cryptocurrency transaction network datasets as temporal benchmarks for future research (R3).

6. **Well-motivated problem.** R2 highlights the motivation of tracking evolving graphs as a strength.

### Weaknesses
1. **Limited to binary growth rate prediction.** The model is only evaluated on whether edges increase or decrease, leaving adaptability to other graph properties (node counts, density, diameter, degree distribution, triangles) unexplored (R1, R2). R2 further suggests predicting the specific number of edge changes rather than binary classification for a finer-grained assessment. Missing experiments on other tasks (temporal global efficiency, betweenness centrality – R1; link prediction, edge sign prediction – R3) limit the claimed generality.

2. **Incomplete baseline comparisons.** Key recent models are omitted: PINT (continuous-time dynamic graphs) and ROLAND (static GNNs in dynamic settings), potentially skewing perceived performance (R1).

3. **Input representation loses graph structure.** The aggregated node features (sum of incoming/outgoing edge weights and counts) discard adjacency information, which is fundamental in graph analysis. Two nodes with similar aggregated features can have very different graph roles depending on their connections (R2, high confidence). The overall structural connectivity is not retained.

4. **Disconnect between Newtonian analogy and implementation.** The Newtonian phase space concept is introduced but not leveraged in the model architecture or training; the paper lacks theoretical justification linking the framework to Newtonian dynamics, making the analogy appear decorative (R1, low confidence). (Contrast with R3, who defends it as a key insight – see Strength 3.)

5. **Missing implementation details.** The clustering algorithm and lens function used for the Mapper network are not specified; Mapper hyperparameters are not reported (R4). Hyperparameter sensitivity is not explored (R3). Minor typos exist (e.g., page 18 – R3).

6. **Untested generalizability.** The framework should be tested by replacing Mapper with other static graph embedding techniques to assess its impact (R3). The applicability conditions for GraphPulse to perform better than specialized embedding algorithms are not discussed (R3).

7. **Baseline fairness and missing end-to-end learning.** Using GIN as a static baseline may be unfair because it lacks access to temporal evolution information; a better baseline would be an MPNN using edge timestamps (R4). An end-to-end learnable approach using a GNN to extract graph features from the Mapper network (instead of handcrafted features) was not explored and could potentially improve performance (R4).

8. **Reviewer disagreement.** R1 and R2 (score 6) are less positive: R1 rates contribution as “fair” and expresses low confidence; R2 (high confidence) criticizes the loss of graph structure and simplicity of the prediction task. In contrast, R3 and R4 (score 8) rate contribution and soundness as “good” and strongly endorse the novelty and performance. The Newtonian phase space argument is a point of particular contention (R1 sees it as unexploited; R3 sees it as a key advance).
