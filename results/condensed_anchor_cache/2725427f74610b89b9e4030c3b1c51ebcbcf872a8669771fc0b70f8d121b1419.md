## Merged Review

### Summary

This paper connects in-context learning (ICL) to Occam’s razor via compression theory. It shows that the next-token prediction loss used to train sequence models (e.g., Transformers) is equivalent to prequential coding, and minimizing this loss jointly minimizes training error and the complexity of the model implicitly learned from context. Experiments on linear regression, sinusoid, and Mastermind tasks contrast standard ICL with a variant that minimizes only training error, demonstrating generalization gaps and architecture dependencies.

### Strengths

*   The paper is well-written and the theory is interesting, with experiments that serve the main points.
*   The connection between next-token prediction loss minimization and prequential coding is a useful and relatively novel perspective, and it makes intuitive sense that the model learns to represent new data better as training proceeds.
*   The prequential code-length perspective offers a promising route to understanding ICL, and the innovative use of prequential coding to balance model complexity and training accuracy provides a practical metric for simplicity.
*   The paper contrasts ICL with typical machine learning approaches, offering a novel perspective grounded in Occam’s razor, and provides comprehensive empirical validation across different tasks, architectures, and training conditions.
*   Kolmogorov complexity nicely frames generalization as compression, and any effort connecting modern LLMs (trained on next-token prediction) to this principle is welcome.

### Weaknesses

*   **Novelty and Theoretical Rigor**
    *   The relation between next-token prediction loss and prequential code length appears not novel; it is explained in Delétang et al. (ICLR 2024, Sec. 2), which is cited only for other reasons and not given sufficient emphasis.
    *   The major theoretical claims (e.g., that Transformers “explicitly” optimize an objective involving model complexity) rely on inequality (4) being an approximate equality, but this leap is not adequately justified. The justification is brief (around line 162) and references Blier-Ollivier, but the connection from an inequality to an approximate equality requires a rigorous theoretical or empirical argument. Without it, the claim that minimizing prequential code length is equivalent to minimizing training loss plus model complexity remains unsubstantiated.
    *   The overall connection, while an interesting story, lacks rigor. There is no quantitative analysis of how well prequential code length approximates Kolmogorov complexity, and the bound is likely very loose.
    *   The prequential coding algorithm assumes the learner improves as it sees more data, but this is not universally true (especially for complex models or non-stationary distributions). No quantitative analysis (e.g., sample complexity, data distribution assumptions) is provided for this assumption.
    *   Equation (4): the first equality expresses code length as the sum of bits for the data based on the learner, but it is unclear if extra bits are needed to represent the learner itself. Please comment.
    *   The approximation in equation (6) is stated without details; please elaborate on what is missed.

*   **Experimental Design and Interpretation**
    *   *Bottleneck experiment (Figure 2b):* It is suspicious that a Transformer without a bottleneck performs worse than one with a bottleneck, as intuition suggests the bottleneck would lose essential information for predicting the query label. Furthermore, the two models were presented with different input formats (one with (x,y) concatenated, the other without), making the comparison unfair.
    *   *Train-risk ICL setup:* It is unclear how sequences are processed—whether broken into subsequences of length j (j∈[k]) or passed as a whole sequence with causal attention. If the latter, how is the query x selected? If x is always x_1, this could allow a shortcut solution. If the former, there is no causality requirement, so why use a decoder-only Transformer?
    *   *Performance gap explanation:* The gap is smaller for linear regression but larger for sinusoid and Mastermind; the paper attributes this to task difficulty, but this is vague. Fixing the function class and varying the problem dimension would be a more concrete test.
    *   *MLP baseline:* The paper does not clarify whether model complexity was minimized through regularization (e.g., weight decay) in the MLP, limiting insight. Also, what would be the Bayesian optimal model’s generalization error?
    *   *Expressivity claims (Section 3.2):* The statement that a Transformer’s expressivity scales with the number of activations (N) while a DNN’s scales with the number of weights (N²) needs elaboration, given that attention layers involve multiplication of d×n matrices and have d² parameters per weight matrix.
    *   *Figure 3b:* It is unclear whether the x-axis is data points seen during training or context length, and how generalization error is measured on the y-axis (prequential code length vs. error over a batch).
    *   *Experimental connection to theory:* The experiments in Section 3.1 appear scattered; the claim that they “follow directly from our theory” (line 312) is not explicit. The observed gap below 10 in-context datapoints is not clearly linked to prequential code length minimization, and its significance is not established.

*   **Generalization to Non-IID and Real-World Scenarios**
    *   The theoretical and experimental setup assumes i.i.d. data, but ICL properties in practice arise from training on non-i.i.d. data (e.g., language). The paper does not address how the prequential coding framework handles changing distributions, complex dependencies, or real-world LLM cases (which may involve out-of-distribution scenarios and deviate from the meta-ICL format). Can any results be generalized to non-i.i.d. settings?
    *   The paper focuses on small-scale experiments and does not provide additional insights for improving small-scale training, let alone for real LLMs.
    *   The assumption of monotonic learner improvement with more data is especially problematic for non-stationary streams; the paper lacks discussion on overfitting and mitigation.

*   **Architectural Dependencies**
    *   The paper notes that model architecture influences the effectiveness of ICL but does not explore which features (e.g., attention mechanisms, depth, width) are most beneficial for minimizing prequential code length and improving generalization.

*   **Other Missing Details**
    *   How is T_ϕ (in Section 2.3) prevented from memorizing a single dataset?
    *   In the “standard SGD vs ICL” distinction: it is unclear because both use SGD to minimize cumulative next-token prediction loss. Please clarify the setting.
    *   Section 2.4 stops short of explicitly writing the next-token prediction loss and connecting it to prequential code length—a direct calculation would strengthen the contribution.
    *   Figure 1(a): the decode function in the prequential coding algorithm is not defined; please add details.
    *   Section 3.4 references Figure 2a (line 392) but should reference Figure 3a.
    *   The abstract’s first sentence (“A central goal of machine learning is generalization”) is a bold claim; generalization is not the only goal of ML—this warrants caution.

*   **Minority Views / Contrasting Opinions**
    *   Reviewer 1 initially scored 5 but raised to 6 after author discussion; concerns remain that the work is limited to small-scale experiments and does not address real LLM cases.
    *   Reviewer 3 finds the prequential coding perspective promising but concludes that the theoretical arguments fail to link next-token prediction to Occam’s razor in their current form, and that the experiments are not strongly confirmatory.
    *   Reviewer 5 views the connection as a good story but lacking rigor; Reviewer 2 and Reviewer 4 also question the extension to non-i.i.d. data, while Reviewer 1 and Reviewer 2 found the experiments well-conducted.
