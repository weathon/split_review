## Merged Review

### Summary
The paper proposes LayoutDETR, which reformulates multimodal layout generation as a detection problem using a transformer architecture (DETR) combined with VAE and GAN training. A new ad banner dataset with 7,196 samples and rich semantic annotations is collected. The method achieves SOTA performance on three datasets (ad banner, CGL, CLAY) across six metrics. The system is integrated into a graphical tool and evaluated via user studies.

### Strengths
- The idea of applying a visual detection framework (DETR) to layout generation is interesting and effective (Reviewers 1, 3).
- Studying content-conditioned layout generation is an important and practical problem (Reviewer 2).
- The newly constructed ad banner dataset with detailed semantic annotations (text objects, background inpainting, class labels) can be valuable to the community (Reviewers 1, 2, 3, 4).
- The method achieves excellent SOTA performance on multiple metrics for realism, accuracy, and regularity (Reviewers 1, 3, 4).
- A graphical system is built and a user study is conducted (Reviewer 3).
- The paper is easy to follow (Reviewer 4).

### Weaknesses
- **Limited technical novelty**: The approach largely borrows DETR and combines components from existing layout methods (e.g., Kikuchi et al. 2021, Li et al. 2020) without significant modification; the contribution is more system-oriented than providing new insight (Reviewers 2, 4). Reviewer 1 did not cite this as a weakness, but other reviewers were critical.
- **Missing evaluation of layout-content consistency**: The paper only evaluates layout quality (metrics and user study), ignoring whether generated layouts match the input foreground contents. An experiment on content-layout alignment is needed (Reviewer 2).
- **Missing diversity evaluation**: The paper does not show variation in generated layouts for the same background or discuss diversity of outputs (Reviewers 1, 3).
- **Missing computational cost/runtime analysis**: The model has multiple input modalities, but no cost or runtime comparison with existing works is provided (Reviewer 1).
- **Unclear justification for VAE and DETR design choices**: The necessity of the VAE pipeline and the DETR structure are not well-motivated or validated (Reviewer 4). The paper uses dozens of loss functions without clear guidance on tuning the weighting factors (Reviewer 4).
- **Dataset concerns**: The dataset only includes text as foreground objects, ignoring vector shapes, images, etc., making it limited (Reviewers 3, 4). The background is inpainted and may contain artifacts that the generator could exploit as shortcuts (Reviewer 3). The text image patches are cropped from the original image, meaning they contain the same background pattern, which may leak location information (Reviewer 3). The dataset itself is not entirely new—images are from prior work; the new contribution is the text detection, inpainting, and class annotation, which is less significant than a fully new dataset (Reviewer 3).
- **Missing comparison with decoupled approach**: The paper does not compare against a baseline that first detects empty space in the background and then generates layout elements, which would justify the joint detection model (Reviewer 3).
- **Ignoring font information and box aspect ratios**: The method only predicts box layouts and ignores font style and aspect ratio constraints, which limits extensibility to real design tasks (Reviewer 4).
- **Unclear handling of arbitrary background image sizes**: The method does not clarify how to distinguish foreground from background when background images have arbitrary sizes (Reviewer 1).
- **Questionable evaluation metric**: Image FID uses image features pre-trained on ImageNet, which may not be appropriate for evaluating graphic design quality (Reviewer 1).
- **Missing evaluation on multi-modal document model benchmarks**: The paper does not discuss or evaluate on problems like “Towards Flexible Multi-modal Document Models” (Reviewer 3).
- **Minor typo**: Equation 6 likely has a subscript error (should be \(p_1^i\)) (Reviewer 3).
- **Scope concern**: One reviewer noted the paper may be more suitable for system-oriented venues than ICLR (Reviewer 2).
