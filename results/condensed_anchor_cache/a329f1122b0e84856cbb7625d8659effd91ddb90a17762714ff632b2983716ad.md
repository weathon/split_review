## Merged Review

### Summary

This paper proposes Evoke, an automatic prompt refinement framework for LLMs. Evoke uses two instances of the same LLM (GPT-4): a reviewer that scores the current prompt and an author that edits the prompt based on feedback and edit history. Additionally, a data selector exposes only hard samples. Experiments on instruction induction tasks (including logical fallacy detection) show large gains (e.g., Evoke scores >80 vs. baselines <20). The method is evaluated against human-generated prompts and paraphrasing-based automated prompt engineering, and ablation studies analyze the selector’s effect and robustness to typos.

### Strengths

- **Novelty of the author-reviewer framework with data selector** – using a feedback loop and hard-sample selection is an interesting and effective approach (Reviewers 1, 4).
- **Impressive performance on difficult tasks** – e.g., logical fallacy detection, movie recommendation, common concept identification; improvements are substantial and clear (Reviewers 1, 3, 4).
- **Simple yet effective** – no additional training phase, straightforward combination of LLM roles (Reviewer 2).
- **Self-improving adversarial setting** – the interplay between reviewer, author, and selector is interesting (Reviewer 4).
- **Problem importance** – automatic prompt generation is a crucial area for LLM usage (Reviewer 2).
- **Robustness analysis** – experiments on perturbed prompts show Evoke produces instructions that handle typographical errors, improving robustness (Reviewers 2, 3).
- **Not human-labor intensive** – method automates prompt refinement without human intervention (Reviewer 4).

### Weaknesses

- **Similarity to prior work** – The method shares core contributions with DeepMind’s “Large Language Models as Optimizers” (released before the ICLR deadline). The paper must discuss and distinguish itself (Reviewer 2).
- **Unfair comparison** – Evoke uses supervised information (training set performance) while some baselines do not; this should be acknowledged when presenting results (Reviewer 2).
- **Limited to GPT-4** – The paper only experiments with GPT-4; it is unclear if the method works with other LLMs (e.g., Llama2, ChatGPT, Falcon 180B). No scaling study across model sizes is provided, limiting generality of takeaways (Reviewers 2, 3).
- **Iteration dependency and computational overhead** – Efficacy depends heavily on number of iterations and feedback quality; the iterative process requires running the LLM multiple times on the entire training set, raising efficiency concerns for large datasets (Reviewers 1, 2).
- **Missing details on Evoke process** – Insufficient explanation of modules, loss functions, and targets for the difficulty ranking module (Reviewers 2, 4). The paper lacks the details needed for reproducibility (Reviewer 4).
- **Rationale for dataset selection** – Choice of Instruction Induction and Big Bench Instruction Induction datasets is not clearly justified; some tasks may be toy tasks (Reviewer 2).
- **Unclear how initial prompt quality affects performance** – No analysis of sensitivity to the initial prompt (Reviewer 1).
- **Are all generated prompts concatenated during evaluation?** – This detail is missing and affects understanding of the final prompt ensemble (Reviewer 1).
- **Number of iterations and prompt length per task** – These operational details are not reported (Reviewer 2).
- **LLM-Selector effect on easy examples** – Section 4.4 shows the selector helps on hard samples, but does not explain why performance on easier examples is not consistently improved (Reviewer 2).
- **Why use reviewer scores instead of direct end-task accuracy?** – The choice to estimate scores via a reviewer rather than use end-task scores directly is not justified; possibly for computational cost, but this is not explained (Reviewer 3).
- **Writing and presentation** – Some parts of the paper are unclear; tables/figures could be moved to the appendix to allow more space for experimental details and method explanation (Reviewers 2, 3).
