## Merged Review

### Summary
This paper proposes FLAG, a clustered federated learning (FL) method that combines both data similarity and gradient similarity to group clients. FLAG uses a weighted class-wise similarity metric integrating principal vectors from data and cosine angles between gradients. Clustering is performed one-shot in the first iteration and kept fixed thereafter; the optimal clustering is found via a brute-force search over thresholds. Experiments on multiple benchmark datasets show accuracy improvements of 0.5%–4% over three baselines.

### Strengths
- The problem of clustered FL under data heterogeneity is important and well motivated [R1,R2,R3,R4].
- The method is clear, intuitive, and well presented; readability is good; the background is written well [R3].
- Combining both data and gradient similarity to assess client similarity is novel and a promising alternative to prior work that uses only one signal [R1,R4].
- The weighted class-wise similarity metric enhances clustering accuracy and robustness to different types of data skew [R4].
- Experiments across multiple datasets and models demonstrate superior performance over competing methods and faster convergence [R3,R4].

### Weaknesses
- **Unsupported claims about concept shift/drift.** The abstract and introduction mention addressing limitations under complex heterogeneity scenarios such as concept shift and drift, but no experiments or analyses target these scenarios. This weakens the motivation [R1,R2,R4]. (R3 and R4 do not contradict.)
- **Multiple incorrect or unjustified statements.** (a) IFCA is inaccurately characterized as gradient-based clustering (IFCA uses an iterative consensus approach, not direct gradient clustering) [R1,R2]. (b) The claim that using only gradient or data similarity is insufficient (lines 78–81) lacks justification; gradient similarity may not capture underlying data/task similarity if clients have different initial weights or objectives, and the impact of local updates on gradient similarity is not discussed [R1,R2]. (c) The explanation of PACFL (lines 88–91) misrepresents its methodology (PACFL measures subspace angles, not direct data similarity) [R1,R2].
- **Incomplete experimental setup details.** Table 1 and Table 2 lack crucial FL context: number of clients, data distribution across clients, local batch size, number of local updates, learning rate, and whether different heterogeneity settings are mixed. This makes results irreproducible and hard to interpret [R1,R2].
- **Shallow related work discussion.** The related work section omits several state-of-the-art clustered FL approaches, including methods that use model parameters, prediction probabilities, or other similarity metrics. Specific missing baselines: FedAC [Zhang et al. 2024], FedRC [Guo et al. 2024], and works [7,8,9] from R1’s list (Yan et al. 2024, FedSoft, Stochastic Clustered FL). A comprehensive literature review is required [R1,R2,R4].
- **Unclear gradient communication mechanism.** It is not clarified whether the approach uses FedSGD or FedAvg-style local updates, how gradients are computed, averaged, or aggregated, and whether gradients or local updates are exchanged per round [R1,R2].
- **Brute-force clustering algorithm is inefficient and lacks novelty.** The algorithm for determining optimal clustering is a brute-force search over thresholds, unlikely to be communication-efficient. More efficient approaches (e.g., hierarchical clustering, k-means) should be explored and justified [R1,R2]. (Minority: R3 and R4 do not comment on this directly; R4 asks about necessity of hierarchical clustering.)
- **Sensitivity to HC threshold and need for normalization.** The hierarchical clustering threshold depends on similarity matrix values (line 280–281); it is unclear whether the matrix is normalized. No sensitivity analysis is provided [R1,R2].
- **Privacy leakage risk from sharing singular values and gradients.** FLAG uses truncated SVD on raw data and sends singular values along with gradients to the server. Prior work shows gradients can leak local data [Zhu et al. 2019]; singular values could facilitate such attacks. The paper does not address privacy implications or compare risks to other methods [R3,R4].
- **Missing complexity analysis.** No time or space complexity analysis is given for the three algorithms. Truncated SVD must be run on every class of data, which may hinder parallel processing and practical scalability [R3,R4].
- **One-shot clustering inconsistency with gradient dynamics.** Gradients are known to align early and diverge later, yet FLAG performs one-shot clustering in the first iteration based partly on gradients. The paper does not justify why this is sufficient or provide similarity heatmaps of G, D, and G+D across iterations [R3,R4].
- **“Predefined cluster numbers” limitation not addressed.** FLAG uses the elbow method to choose a clustering threshold, which is analogous to predetermining the number of clusters in other methods. It is unclear how FLAG solves this limitation [R3]. (Minority: R4 similarly asks about the difference between setting thresholds and setting cluster numbers.)
- **Insufficient hyperparameter sensitivity analysis.** Key hyperparameters (β, δ, number of local steps, α interval size, number of cluster FL rounds, number of sampled clients m′, client sample ratio, total number of clients) are not studied. Only extremes of β are shown in ablation [R1,R4].
- **No evaluation on concept drift or shift.** The experiments do not include any dataset or partition that exhibits concept drift or shift, contradicting the paper’s motivation [R1,R2,R4].
- **Missing clustering capability benchmark.** No ground-truth clustering membership experiment (e.g., label-based or feature-based partition of CIFAR-100 or SVHN) to directly evaluate clustering accuracy [R1].
- **Theoretical analysis gaps.** The paper lacks deeper analysis on: privacy leakage from sharing data and gradient knowledge, communication convergence under hierarchical clustering, and communication/computation burden [R4].
- **Typos and formatting issues.** Examples: line 016 “distributed i.i.d.” is grammatically wrong; lines 128–131; line 170 tautology; Table 4 reporting errors; Figure 2 dataset name repeated; “cluster FL” should be “clustered FL” [R1,R3].
