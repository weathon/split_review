## Merged Review

### Summary

The paper addresses heterogeneous strict retrieval, motivated by retrieval-augmented generation (RAG) for LLMs. It proposes Adapted Dense Retrieval (ADDER/ADDER2), which transforms pretrained black-box embeddings (e.g., OpenAI ADA) using lightweight adapters that add residual perturbations via a learned dictionary and attention mechanism, trained with contrastive loss and global hard negatives. The method is evaluated on five BEIR datasets (e.g., SciFact, FiQA) and three code retrieval datasets from NL2X (SMCALFLOW, BASH, CONALA). Results show improvements on some tasks but not all, with best gains at small k (1-5). Reviewers generally found the problem well-motivated and the black-box adaptation practical, but raised concerns about limited novelty, insufficient baselines, missing ablations, inconsistent improvements, and experimental methodology.

### Strengths

- The problem of task-specific adaptation of general-purpose embeddings for heterogeneous strict retrieval is interesting and practically important for RAG with LLMs (R1, R2, R3, R4, R5, R6).
- The black-box setting (treating the embedding model as an API) is a less explored but practical approach, enabling adaptation without accessing model weights (R2, R5).
- The proposed low-rank residual adapter is computationally efficient, trainable on simple hardware, and requires only a small tuning dataset (R1, R2).
- The paper clearly describes the method, making it potentially reproducible (R1, R4, R5, R6).
- The method shows some improvements over the basic OpenAI ADA baseline on several datasets, particularly at top-k with small k (R1, R2, R4, R5).
- The formulation of heterogeneous strict retrieval as a distinct problem is a helpful conceptual contribution (R1).

### Weaknesses

1. **Limited novelty**: Adding trainable parameters on top of a fixed embedding model is similar to prior work; the specific attention+residual transformation is only one of many possibilities, and no alternative formulations (e.g., simple MLP, linear adapter, trainable skip connection) are ablated (R6; echoed by R5).
2. **Insufficient baselines**: The only baseline is general-purpose OpenAI ADA embeddings. Missing comparisons to: (a) fine-tuning the same embedding model directly if accessible; (b) other dense retrievers such as ANCE, DPR; (c) neural rerankers (state of the art for small candidate lists); (d) adaptive similarity methods from similarity search (R1, R3, R4, R5). This makes it hard to assess the true advantage of the adapter approach.
3. **Inconsistent improvements**: The method fails to consistently outperform the baseline. It underperforms on FiQA (BEIR) and CONALA (code), and on some tasks adapting only query vs. both query and corpus gives mixed results. The paper lacks detailed analysis explaining these failures (R1, R2, R4). Improvements are described as "not impressive" and "not clear winner" (R2).
4. **Strict retrieval claim not substantiated**: While the paper argues for strict retrieval (small k), the evaluation does not clearly analyze performance at very small k (e.g., k=1,2,3) beyond standard nDCG measures that prior work already reports. No specific method is proposed that differs for small vs. large k (R1, R4).
5. **Dataset scale limitation**: All experiments use small corpora (up to 57K items). The paper assumes this is a relevant setting, but does not justify why retrieval on small datasets is a separate problem, nor evaluates on larger BEIR datasets (up to 8M items) (R4, R6). The assumption that corpus is small and limited good retrievals are available is restrictive (R2).
6. **Missing ablations and analysis**:
   - No study of the effect of varying the adapter dimension \( h \) (stated range 16–128, but not fixed per dataset or justified) (R1, R2).
   - No ablation of the global hard negative strategy; it is unclear how negatives are selected (random or mined), and batch-local negatives are said to be worse but no numbers given (R3, R5). Implementation details (refreshing index each step) are missing (R5).
   - No evaluation with different base embedding models (e.g., SBert) – SBert results are mentioned but omitted due to being uniformly worse; this could have been shown (R3, R5).
   - No analysis of how performance varies with training data size (R5, R6).
   - No study of the effect of corpus size (R6).
   - No evaluation of whether the adapted embeddings improve downstream RAG tasks (R2).
7. **Experimental methodology concerns**:
   - Hyperparameter selection is unclear – it is not specified whether a separate development set was used or tuning was on the test set (R3).
   - The loss function is described only at a high level; no concrete formula is given (R3).
   - Section 4.2 (training/testing setup) is vague, missing training data size and setup details (R5).
   - There is a contradiction: the paper claims experiments were run on regular laptops/desktops, then states use of a VM with a single Nvidia K80 GPU (24GiB vRAM), 4 CPU cores, and 28 GB RAM (R3).
   - Tables would be more readable with results from competing approaches side by side (R3).
8. **Heterogeneous dataset claim is misleading**: NL queries + code is cross-media retrieval, not heterogeneous in the sense of multiple modalities within the same dataset. The method does not demonstrate handling of truly heterogeneous data (R4).
9. **Adaptation is model-specific**: The adapters are tied to a specific pretrained embedding model; they would need retraining if the base model is updated (R2).
10. **Minor issues**: Typo "retrivers" (R3); repeated references (R2); use of \(\mathbb{C}\) for corpus is non-standard (R6).
