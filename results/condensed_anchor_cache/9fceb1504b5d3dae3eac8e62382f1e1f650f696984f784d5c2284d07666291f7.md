## Merged Review

### Summary
The paper proposes a program synthesis method called "tree diffusion" that operates on abstract syntax trees of context-free grammars. It corrupts programs (with constraints) and learns to invert the corruptions, conditioned on the output of the corrupted program and a target image. The approach is applied to inverse graphics tasks (CSG2D and TinySVG), where it writes programs that render images. It combines autoregressive generation, diffusion-based editing, and beam search guided by a value network that predicts edit distance to the target. The method is validated with ablation studies, including the impact of search and training on the reverse mutation path. The paper also extends to hand-drawn sketches.

### Strengths
- **Innovative methodology**: Novel combination of diffusion models with explicit syntax tree mutations for program synthesis. The reverse mutation path algorithm provides an efficient way to generate training targets (R2, R4). The approach avoids reinforcement learning by using beam search with output observation (R4).
- **Neurosymbolic framework**: Designs a formal evaluation that ensures program specifications are met through iterative execution and verification (R3). The method maintains syntactic validity throughout editing (R1, R4).
- **Comprehensive ablation studies**: Thorough experiments ablate key hyperparameters and the impact of search, enhancing understanding of the method's efficacy (R2, R4).
- **Clarity and replicability**: Paper is well-written, easy to follow, with sufficient detail (including appendix) to enable replication (R1, R2, R4). Supplementary videos effectively illustrate the editing process (R3, R5).
- **Data efficiency**: Uses randomly generated programs as a dataset, sidestepping dataset curation; only a specification of the language is needed (R1).
- **Practical extension**: Demonstrated applicability to hand-drawn sketches (R3).
- **Key design choices**: The backward edit path that is better than reversing the corruption path, removal of the need for a partial renderer, and reliance on beam search instead of RL are clearly justified (R4).
- **Permuting on syntax tree**: Allows for a more efficient model with better performance compared to autoregressive generation (R5).

### Weaknesses
- **Scope and scalability**: The approach is limited to simple program domains (CSG2D, TinySVG). It is unclear whether the method scales to larger, structured programs in general-purpose languages. For example, going from recursion to a loop, implicit lambda to declared function, or splitting functions may require large edits or intermediate invalid states. Some reviewers (R1, R3, R4) question scalability; one reviewer (R5) found the results notably better but did not address scaling directly. The fuzzing and edit algorithms' generalizability to non-context-free grammars (e.g., general programming languages) is also unclear (R1).
- **Figure 3 and architecture description unclear**: Figure 3 is confusing, particularly the meaning of v(x) with subscript ϕ (R1). The description in Section 3.4 lacks detail on how grammar-constrained autoregressive decoding ensures syntactic validity when replacing “(” with a subexpression. The role of the EOS token is ambiguous. It should be clarified that the entire subexpression is replaced (not just the opening parenthesis) and how variable-length sequences and EOS are handled (R3).
- **Value network analysis missing**: The value network (vϕ) training and effectiveness are not thoroughly evaluated. The paper lacks analysis of its architecture, training procedure, loss functions, and training data size. Alternatives to edit distance estimation (e.g., direct calculation from syntax trees) are not explored or compared. The computational cost of training the value network is not discussed, nor is its performance compared to simpler heuristics for estimating progress during search (R2).
- **Insufficient computational efficiency analysis**: The “no reverse path” ablation shows the method reaching performance comparable to the control after ~50-60 nodes, but the maximum node budget is 5000. No time-related metrics are provided to support claims of efficiency gain. The relationship between "number of nodes expanded" and "number of compilations needed" is not defined (R3, R4). The computational cost per node expansion and overall time to solution should be reported (R3).
- **Missing related work citations**: Two relevant works should be cited and discussed:
  - “Outline, Then Details: Syntactically Guided Coarse-To-Fine Code Generation” (ICML 2023) – also takes multiple passes and edits the program (R2, R5).
  - “Symbolic Visual Reinforcement Learning: A Scalable Framework with Object-Level Abstraction and Differentiable Expression Search” (TPAMI) – learns visual symbolic programs (R5).
- **Training details missing**: The number of diffusion steps trained for is not covered (R1, R5). The model’s decoder size is only mentioned in the appendix; it should be in the architecture section (R5). The ablation that trains only on the last mutation step (z5→z4) is not compared to training on all denoising steps as a baseline (R4). The number of steps in the diffusion procedure and how performance scales with program complexity (number of symbols, tree depth) are not discussed (R5).
- **Escape local minima claim not substantiated**: The claim that diffusion + base tree editing can escape local minima is not sufficiently supported. An analysis or example demonstrating that the method explores beyond the initial syntax tree structure and achieves global optimality is lacking (R3).
- **Ground-truth mutations and scalability**: Access to ground-truth mutations (required for the reverse mutation path) may not be readily available in most cases. If not automated, the scalability of the approach is limited (R3).
- **Baseline comparisons**: The baselines only include older models (4+ years old). Comparisons against recent vision-language models (e.g., VILA, LLaMA) would strengthen the evaluation (R2). Additionally, RL-based algorithms from previous work could have been compared to show their brittleness (R4).
- **Evaluation criteria for TinySVG unclear**: The tolerance for pixel matching (“within 0.005 ≈ 1/256”) is not explicitly stated as applying to 8-bit color intensity per channel. It should be clarified how this metric is applied to RGB images (R3).
- **Definition of “Rollout” vs “Search”**: The difference between “tree diffusion search” and “tree diffusion rollouts” is not explicitly stated or defined (R3, R4). Section 4 should define these clearly.
- **Minor presentation issues**: Figure 3’s labeling (vϕ subscript) is confusing (R1). The description of the initial program generation (random fuzzing) is not explained in the main text (R1).
