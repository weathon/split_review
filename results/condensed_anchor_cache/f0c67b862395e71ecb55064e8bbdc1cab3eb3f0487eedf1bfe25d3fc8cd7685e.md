## Merged Review

### Summary
This paper proposes Uni²Det, a multi-stage prompting framework for unified multi-dataset 3D object detection. It addresses distribution discrepancies across datasets (KITTI, Waymo, nuScenes) by introducing three dataset-aware modules: (1) mean-shifted batch normalization that applies instance- and batch-level normalization to correct point distribution shifts; (2) BEV-based range masking that selects features corresponding to each dataset’s point cloud range; (3) object-conditioned residual learning that injects dataset-specific features into RoI features via a discriminator trained with classification loss. The modules are designed as plug-and-play components for detectors like PV-RCNN and Voxel R-CNN. Experiments show that Uni²Det outperforms existing methods (e.g., Uni3D) on both multi-dataset training and zero-shot cross-dataset transfer.

### Strengths
- Tackles the practical issue of integrating diverse 3D detection datasets, opening avenues for broader data utilization and better generalization.
- Modular design: the three prompting stages are plug-and-play and compatible with multiple advanced 3D detectors.
- Frame-specific mean shifts for batch normalization are considered novel; one reviewer specifically noted this contribution.
- Comprehensive experiments demonstrate: (a) outperformance over baselines like Uni3D, (b) compatibility with different detectors, (c) each prompting stage contributes to performance gains, (d) object-conditioned residual learning improves alignment of object size distribution with ground truth.
- Robust zero-shot generalization: impressive results on unseen datasets without additional retraining.
- Scalability: effectively uses additional datasets without negative transfer.
- Treatment of dataset-specific attributes as prompts is noted as interesting.
- Paper is well-organized and easy to follow.

### Weaknesses
- **Mean-shifted batch normalization**: 
  - The parameter α captures frame-specific (instance) characteristics, not broader dataset-level traits; it is unclear how frame-level shifts capture dataset-level statistical properties. The reviewers request clarification on whether α is learned, fixed, or dynamically computed, and how it is integrated into the architecture.
  - Missing comparison with an alternative that first demean data using instance-specific mean, then batch-wise demeaning without α weighting, and missing ablation on discarding this stage entirely.
  - No ablation study on the hyperparameter α itself.
- **BEV-based range masking**: 
  - Rationale for concatenating the mask as an additional channel rather than directly masking BEV features is not explained; reviewers ask how this design choice improves performance or cross-domain generalization.
  - During inference, the method requires knowledge of the dataset-specific point cloud range; if the target domain range is used in domain generalization experiments, this may be unfair as domain-specific knowledge is injected. What happens if the point cloud range of the test dataset is unknown?
- **Object-conditioned residual learning (OCRL)**:
  - Unclear how the dataset ID is encoded during training and how the pipeline obtains the object-conditioned residual during zero-shot testing.
  - Motivation of OCRL is similar to data-level correction and semantic coupling/recoupling; the paper should explicitly discuss advantages over such prior ideas.
- **Assumption of identical categories**: The framework assumes shared categories across datasets, limiting applicability to datasets with non-overlapping or diverse label spaces. No exploration of handling unique categories or adapting to a shared embedding space.
- **Limited component analysis**: The paper could provide more detailed ablation studies (e.g., removing each module individually and in combinations) to isolate the impact of each prompting stage.
- **Computational overhead**: Not thoroughly discussed; reviewers request metrics such as parameter count, FLOPs, memory usage, and latency compared to baselines.
- **Limited class diversity and domain scope**: Evaluation is restricted to autonomous driving datasets; no experiments on indoor datasets (e.g., Scannet, SUN-RGBD) or on classes that do not intersect with the existing vocabulary. One reviewer explicitly asked about performance on indoor scenes.
- **Outdated detectors**: The method is only evaluated on PV-RCNN and Voxel R-CNN, both several years old. Performance on more recent 3D detectors is not shown.
- **Lack of failure case analysis**: No examples or analysis of scenarios where the framework might underperform.
- **Minor confusion**: Abbreviation MDF vs. MDT used inconsistently (MDF from preliminary, then MDT later).
- **Real-world limitations**: The paper does not discuss how the method handles highly dynamic or heterogeneous environments where data distribution may change rapidly.
