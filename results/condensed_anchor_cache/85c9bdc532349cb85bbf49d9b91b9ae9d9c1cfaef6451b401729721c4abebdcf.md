## Merged Review

### Summary
The paper presents DB-GPT-Hub, an open benchmark suite for evaluating fine-tuned LLMs on text-to-SQL tasks. It provides a modular codebase supporting multiple datasets (Spider, BIRD, WikiSQL, CoSQL, Chase) and LLMs (Llama2/3, Qwen, Baichuan, ChatGLM, CodeLlama), with experiments across fine-tuning methods (full, LoRA, QLoRA) and prompting (zero-shot, few-shot). Reviewers acknowledge the practical value of the unified framework but raise serious concerns about unclear motivation, overclaimed contributions, lack of innovation, insufficient depth in analysis, and missing comparisons with state-of-the-art methods.

### Strengths
- The open-source framework provides an integrated, easy-to-follow pipeline for data construction, model training, and result evaluation, which is valuable for text-to-SQL fine-tuning research.
- The codebase is modular, supports popular LLMs (including medium-to-large sizes up to 72B) and fine-tuning methods (LoRA, QLoRA), and enables fair comparison – also supporting closed models.
- Experiments are thorough, covering model sizes, sample sizes, LORA vs. QLoRA, zero-shot/few-shot, and multiple metrics; findings on when fine-tuning is effective are clearly presented.
- The paper includes practical details (GPU usage, time cost) and is generally readable with sufficient technical depth.
- One reviewer (score 6) highlights high impact potential, noting that current benchmarks focus on prompting, making a dedicated fine-tuning benchmark useful.

### Weaknesses
- **Unclear motivation and contributions** – It is not explicitly shown what gap this work fills beyond existing benchmarks (Spider, BIRD already have training sets for fine-tuning). No new datasets, metrics, or evaluation methodologies are introduced, making the claimed novelty unclear. The motivation for fine-tuning over in-context learning is inconsistent: they criticize ICL for requiring expert annotation yet use only 7 exemplars, while fine-tuning datasets have >10k examples. Overstatements (e.g., “standardized”, “comprehensive”, “extensibility”) are not proven; the pipeline is described too briefly (only 2 lines plus Figure 1), and many aspects (database schema distributions, question distributions, training distributions, compositional generalization) are missing, undermining “comprehensiveness”.
- **Insufficient comparison with existing tools and state-of-the-art methods** – There is no clear comparison of DB-GPT-Hub with existing prompt-based evaluation frameworks. The work focuses on baseline fine-tuning, while current state-of-the-art text-to-SQL systems incorporate schema/value linking, SQL validity checks, multi-turn reflection, and DB content – not supported by the framework. Missing comparisons with prompting-based methods on closed-source LLMs (e.g., GPT-4) limit the analysis of strengths/weaknesses. Important related works (CoSQL, Dr.Spider, Spider-SSP, BIRD benchmarks with trained models like CodeS, granite, SuperSQL) are omitted. The claimed value of the benchmark is not supported by a comparison table against other benchmarks.
- **Experimental limitations and missing analyses** – Experiments are only on Spider and BIRD, with several issues:
  - For BIRD, the `evidence` field is not used, explaining lower scores than official leaderboard.
  - Fine-tuning vs. few-shot prompting is tested only on Spider, not BIRD, raising bias concerns. The Spider leaderboard is outdated (many open-source models now surpass older top methods like DAIL-SQL).
  - The claim that CodeLlama “unsurprisingly” performs best is not justified; more code-focused LLMs (StarCoder, Qwen-coder, DeepSeek-coder) should be compared.
  - Observations like larger improvement on Spider than BIRD ignore evaluation differences between datasets (hash set comparison in BIRD) and need deeper analysis.
  - The analysis of “fine-tuning with more exemplars” is unclear: “exemplar” is ambiguous (training data or few-shot demonstrations?). Only tested on Qwen, only on one dataset, error bars missing, EM reported despite its acknowledged unreliability, and “random-shot” is not properly defined or repeated.
  - QLORA vs. LORA results for Qwen models are unintuitive and require more discussion.
  - No ethical considerations (hallucination, flawed SQL in critical applications) or dataset biases discussed. Limitations of metrics (e.g., EM, post-processing needs) not addressed.
- **Writing and structure issues** – Introduction is too short, ambiguous, and illogically structured (sudden jumps from seq2seq to decoding, “While” used instead of causal linking, vague terms like “ambiguity and complexity”). Claims like “universally acknowledged” and “relatively smaller” lack precision. The paper reads more as an integration report than a research study, lacking innovation. The framework structure is underdetailed; its unique contributions (if any) are not spelled out. Reviewers disagree on writing quality: one finds it clear and detailed, another finds it hard to follow and overclaimed.
- **Technical details and definitions** – Task formulation is confusing: database D not specified as relational, variable `k` used inconsistently, Formula (1) includes `q_i` twice and mixes theta sizes. Fine-tuning formulation omits database schema from input (only question and SQL), and `hat{s_i}` is undefined. PEFT is defined only via LoRA; other popular methods (prefix-tuning, adapter-tuning) are not considered.
- **Extensibility and comprehensiveness limitations** – The framework does not support newer prompting techniques (Tree-of-Thought, agentic workflows, react-like prompting, iterative SQL refinement). Extensibility primarily accommodates new models, not new task-specific techniques; the effort required to add these is not discussed. One reviewer (score 3) questions why the paper did not test recent models (Qwen2, Llama3) or coder-specific LLMs.
- **Academic overstatements** – Using GitHub stars as evidence of academic value is inappropriate; a user study or formal evaluation is needed. The paper claims to be a benchmark but lacks new analytical dimensions beyond existing dataset metrics (EX, EM, VES).
