## Merged Review

### Summary
This paper introduces SPA-BENCH, a benchmark for evaluating smartphone agents powered by (multimodal) LLMs. It features 340 tasks covering both English and Chinese, single-app and cross-app scenarios, and includes system and third-party apps. A plug-and-play framework supports 11 agents (7 off-the-shelf, 4 fine-tuned) and enables real-time interaction with Android devices. The automated evaluation pipeline assesses multiple dimensions (e.g., success, efficiency, resource consumption, termination detection). Extensive experiments reveal that proprietary agents outperform open-source ones, but all face challenges in UI understanding, action grounding, memory retention, and cost/time inefficiency. The benchmark provides insights for future agent design.

### Strengths
- Studies an important and timely problem; comprehensive benchmark to advance LLM agents in smartphone applications.
- Diverse task collection of 340 tasks covering single- and cross-app, English and Chinese, system and third-party apps.
- Introduces several new evaluation metrics and a coarse-to-fine evaluation approach.
- Plug-and-play framework supports 11 agents (including fine-tuned ones) and can be extended; enables real-time interaction with Android devices.
- Inclusion of Chinese applications expands benchmarking scope to multilingual contexts.
- Comprehensive experiments with 11 agents on diverse tasks provide valuable insights (e.g., need for better memory, termination understanding).
- Provides extensive baselines and comparative analysis, enabling a thorough understanding of current limitations.
- Benchmark design is adequately motivated and generally well-written.

### Weaknesses
- Paper organization needs improvement: there are large blank spaces (e.g., between lines 188-191); text formatting issues.
- The unique challenge posed by this benchmark compared to existing ones is not clearly articulated.
- The design choice to avoid shortcuts in human-executed trajectories is questioned—if an agent can solve a task via a shortcut, that may be a valid and efficient behavior.
- Termination metrics (newly introduced) require more careful design: (1) How to apply them to agents that do not produce language-based rationales for termination? (2) The significance of termination ability (why it matters for agent development) should be emphasized when introducing these metrics.
- The criteria for difficulty levels (1, 2, 3) are ambiguous. If levels are based solely on number of steps, the division seems unnecessary. Clarify whether cross-app complexity is also considered.
- The coarse-to-fine evaluation design lacks a stated rationale. Additionally, what happens if an agent satisfies the fine-grained part but misses the coarse-grained part?
- Several claims need elaboration: (a) The qualitative complexity of the accessibility (a11y) tree should be quantified (e.g., token count) as referenced in lines 367-371; (b) the phrase "adequately grounding them in real-world context" (lines 386-397) needs clarification.
- The source of parsing errors is unclear—are they from agent operations or the environment? (Also a typographical error with a misplaced comma in line 449.)
- The paper lacks details on the specific prompts used for agents; supplementary materials would improve reproducibility.
- The process of recruiting human annotators and quality control protocols should be discussed. The possibility of synthesizing behavior trajectories (e.g., for fine-tuning or pre-training) could extend the work's impact.
- The taxonomy of agents should be reorganized into two main categories: agent-as-a-model (fine-tuned/pre-trained models) and agentic workflow (modular design with off-the-shelf models). Locally deployable vs. cloud-based agents are particularly relevant for mobile settings and should be evaluated.
- It is unclear whether fine-tuned agents were trained on this benchmark's dataset. If not, comparing them without fine-tuning may be unfair, and training details should be noted to avoid misleading readers.
- The term "shortcut" for the M3A agent (line 430) is ambiguous: does it mean the agent generated an action outside the predefined action space? If so, how is this handled? Clearer phrasing is needed.
- The motivation for separating English and Chinese in some experiments (e.g., human annotation, line 318) should be clarified.
- The applicability of SPA-BENCH to broader smart devices (e.g., tablets with Android, iOS devices) and the associated potential and challenges should be discussed. Also, key differences between smartphone agents and PC/cloud agents should be elaborated to provide context.
- Note: One reviewer (score 6) is more critical than the other two (score 8) on several of these points, particularly regarding clarity, unique challenge, termination metric design, and reproducibility details.
