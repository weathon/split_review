## Merged Review

### Summary
This paper addresses class-incremental continual learning for multi-view clustering, proposing CCMVC. The method operates in two iterative phases: multi-view cluster search (learning a common feature space and estimating cluster distributions via GMM) and multi-view cluster consolidation (harmonizing clusters using self-supervised data replay with pseudo-labels). A cross-view synchronous loss is introduced to mitigate asynchronous convergence. Experiments on six MVC datasets (1000–10000 samples, 7–10 classes) show improvements over baselines. One reviewer (score 5) was strongly positive about the problem and experiments; three reviewers (score 3) raised significant concerns about novelty, dataset scale, missing analyses, and methodological assumptions.

### Strengths
- The problem of class-incremental continual learning for multi-view clustering is interesting and practically relevant.
- The paper is well-structured, clearly written, and easy to follow; the two-stage framework (search + consolidation) is clearly motivated.
- The originality lies in the synergistic integration of view-related autoencoders, cross-view contrastive learning for GMM, and self-supervised data replay with dual-anchor contrastive learning.
- Ablation studies isolate the contribution of each loss component and confirm their effectiveness.
- Experimental results demonstrate strong performance on the tested datasets, and the ablation study validates the critical components.

### Weaknesses
1. **Dataset scale and evaluation design are insufficient.** The largest dataset has ~10000 samples and only 7–10 classes; the incremental setting adds only ~2 new classes, which does not convincingly demonstrate scalability to larger class increments. Standard deviations and variance are missing from all result tables (Tables 2–4), and no statistical significance test is provided. Dynamic visualization of streaming clustering is missing.
2. **Novelty of the contrastive learning component is limited.** The cross-view contrastive learning is largely based on existing contrastive clustering methods; the only difference is contrasting clustering anchors rather than instance-level features. Several relevant works are not cited or discussed (e.g., Li et al. 2023, Multi-View Class Incremental Learning; MVStream, TNNLS 2020; Split-merge Evolutionary Clustering, Procedia 2020; Incremental Multi-view Spectral Clustering, KBS 2019).
3. **Choice of Gaussian mixture model (GMM) is not justified.** The paper does not explain why GMM was chosen over alternative clustering models, nor does it discuss how GMM parameters are updated as the number of classes increases (e.g., whether components are added incrementally). Moreover, GMM parameters are shared across views, which assumes similar distributions across views—contradicting the classic MVC goal of mining complementary information.
4. **Lack of computational complexity and efficiency analysis.** The paper does not analyze runtime or memory complexity; Eq. (12) computes pairwise view feature similarity, which could become costly with many views. No time-efficiency comparison with baselines is provided, raising doubts about scalability to large-scale data.
5. **Two-stage independent optimization carries risk.** The cluster search and cluster consolidation phases are optimized separately, which may lead to inconsistent optimization objectives. Additionally, the pseudo-label set L (Eq. 11) is critical for data replay; if its quality is low, both modules may degrade.
6. **Sensitivity of random sampling and hyperparameters.** The task memory uses random sample selection with no guarantee of balanced class representation; extreme cases (no samples from a cluster) could hurt performance. Important hyperparameters, especially memory size N', are not analyzed or selected systematically. The number of hyperparameters in the method (e.g., loss weights) somewhat reduces its practical appeal.
7. **Missing technical details and analyses.** The paper does not explain how or why Eq. (2) avoids model collapse. The notation for sample count should be N_t (varying per task) rather than a fixed N. The paper lacks a detailed limitation analysis and a deeper discussion of the practical significance of class-incremental MVC.
8. **Methodological assumptions may limit applicability.** The model only learns a common feature space and ignores view-specific heterogeneity, which is a core aspect of multi-view data. The assumption that all views share the same cluster distribution via shared GMM parameters may be unsuitable when views exhibit distinct statistical properties.
