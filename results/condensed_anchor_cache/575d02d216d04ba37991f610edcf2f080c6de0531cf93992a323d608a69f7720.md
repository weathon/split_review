## Merged Review

### Summary
The paper proposes KVTQ, a dynamic quantization method that compresses the KV cache into ternary digits (−1, 0, +1) using multiple ternary channels per value (4 channels for K, 3 for V). This is intended to reduce both memory footprint and computational cost by replacing dequantization and matrix multiplication with addition/subtraction. The method is evaluated by perplexity (PPL) on LLaMA and OPT models. Reviewers have mixed opinions: some find the motivation clear and the PPL results promising, while others question the novelty, the actual bit‑width, and the lack of hardware‑level measurements.

### Strengths
- **Systematic study of KV‑cache quantization settings** (dynamic/static, symmetric/asymmetric, different bits for K and V). Experimental findings show that more bits are needed for K due to its larger numerical range. [R1, R2]
- **Promising perplexity results** on LLaMA and OPT models, especially with newer LLaMA. One reviewer (R4, score 6) found this particularly noteworthy given the computational simplifications. [R1, R4, R5]
- **Unique computational advantage of ternary representation**: eliminates the dequantization step and replaces matrix multiplication with addition/subtraction operations. This has potential for reducing computational complexity. [R2, R3, R4, R5]
- **Detailed analysis of K and V value ranges** across layers, validating the decision to allocate different quantization bits. [R3]
- **Demonstration of sparsity across channels**, highlighting potential savings from zeros in ternary representations. [R3]
- **Clear and uncomplicated** explanation of quantization techniques and computational approaches. [R3]
- **Pioneering claim** that KV caches can be quantized to ternary digits with minimal impact on perplexity. [R5]
- **One reviewer (R4) was more positive** overall (score 6 vs. 3/5/3/5), praising the paper’s clarity, logical flow, and practical implications. However, even R4 identified missing practical measurements.

### Weaknesses
- **Limited novelty**: the ternary quantization and compensation algorithm originate from ABC‑Net. The paper does not sufficiently detail how this algorithm is adapted to the KV cache or justify why this particular method was chosen over alternatives. [R1, R2]
- **Misleading use of “ternary”**: using multiple channels per value (4 for K, 3 for V) effectively equates to 4‑bit and 3‑bit quantization, not a true ternary system. The implications for memory footprint and computational efficiency are not adequately discussed. One reviewer (R2) asks whether the claimed benefits are actually realized, and another (R3) notes that 2 bits per ternary digit may exceed binary‑based quantization. [R2, R3]
- **Missing measured memory usage/footprint** of the KV cache under KVTQ. Without this, the storage reduction claim is unsubstantiated. [R1, R2, R4, R5]
- **Missing measured latency/throughput/FLOPs reduction**. The claim that ternary computation yields speedups is not validated with runtime measurements. LLM inference is often memory‑bandwidth bound, so computational savings may not translate to faster decoding. Reviewers request comparison with baselines such as TRT‑LLM and actual decoding latency numbers. [R1, R2, R3, R5]
- **Dynamic quantization is hardware‑unfriendly**: it requires scanning the entire tensor to determine max/min values, introducing overhead that is not quantified. Moreover, the KV cache must be stored in original precision and quantized on‑the‑fly before attention, leading to additional memory and latency compared to static quantization (e.g., TRT‑LLM). [R2, R5]
- **No comparison against sparse attention methods**. Given that a large fraction of values may quantize to zero (one reviewer gives an example: if K follows a normal distribution with μ and σ such that 86.6% of numbers fall within ±1.5σ, they are quantized to zero), sparse attention could achieve similar or better perplexity, runtime, and memory usage. This comparison is missing. [R5]
- **Insufficient distribution analysis** of KV cache data beyond max/min statistics. [R5]
- **Minor writing issues**: sentences starting with conjunctions; typo “konw” (should be “known”); “Experiment setup/result” should be “Experimental setup/result”. [R5]
- **Overall lack of practical implementation details**: the physical size of the KV cache under KVTQ, memory overhead, and latency during forward passes are not provided. [R4]
