## Merged Review

### Summary
This paper introduces a greedy agglomerative graph clustering algorithm that optimizes ratio cut and normalized cut objectives without eigendecomposition. Starting from singleton clusters, it iteratively merges the pair with the largest inter-cluster edge weight using a criterion \(h(i,j,w_{ij})\). Speed is achieved via union-find, max-heaps, and a pruning condition, yielding \(O(m \log m)\) expected time for single-view and \(O(m \log m + v(n-k)\log n)\) for multi-view. A randomized variant and a new “linfcut” criterion are proposed. Experiments on COIL (image obj43), UCI Multiple Features, and SF-MASK images are shown, with comparisons against spectral clustering baselines on ncut, ARI, NMI, and runtime. The authors claim the new criterion “makes more sense” to human observers based on a single image example.

### Strengths
**S1.** Takes an entirely different approach from spectral methods for low-conductance clustering, using a simple greedy merging heuristic, which could lead to new work in the area. (R1, R4)

**S2.** Clever use of data structures (union-find, max-heaps) and pruning to accelerate the naive greedy algorithm, resulting in a strong empirical runtime that is independent of \(k\) and can be faster than spectral methods when \(k\) is large. (R1, R2, R3, R5)

**S3.** The algorithm is adaptive to various cut types (ratio cut, normalized cut, Cheeger cut, linfcut) and extends naturally to multi-view (multiplex) graphs with little overhead. (R6)

**S4.** The paper is well-written and provides a clear overview of related spectral clustering methods; the proof sketches for runtime are useful. (R4, R5)

**Minority positive view:** Reviewer 3 notes the runtime is very good and the regime (sparse graphs, large \(k\)) is interesting; they would rate the paper much higher if proper proofs were provided. Reviewer 6 highlights the straightforward greedy nature as a strength. However, all reviewers ultimately find the contributions insufficient due to major weaknesses.

### Weaknesses
**W1. Lack of theoretical guarantees (all reviewers).**  
- No approximation guarantee for the output clusters relative to the optimal normalized cut, ratio cut, or any other objective. Classical spectral clustering provides a relaxed optimum, but the proposed algorithm has no such bound. (R1, R2, R3, R4)  
- The main runtime claim (Lemma 1) is only sketched; a full proof is missing from the paper and supplementary material. (R3, R4)  
- The randomized variant also lacks any theoretical analysis (e.g., edge sampling independence is questioned). (R4)  
- **Reviewer 2 specifically** notes that nearly-linear time spectral clustering with guarantees exists (Peng et al., SICOMP 2017), so the poly-log improvement in runtime without any guarantee is a clear downside. (R2)  
- A proof even for a simplified setting (e.g., \(d\)-regular graphs, \(k=2\), average normalized cut) would significantly increase impact. (R1)

**W2. Insufficient experimental evaluation (all reviewers).**  
- Only three small datasets are evaluated: one image from COIL (obj43), the UCI “Multiple Features” dataset, and a small SF-MASK image. (R1, R5, R6)  
- Largest dataset (Table 4) has 16384 samples, smaller than MNIST. To demonstrate scalability, experiments on graphs with \(10^4\)–\(10^6\) nodes (e.g., SNAP benchmarks) are missing. (R5, R6)  
- For “Multiple Features” the number of ground-truth clusters is \(k=2\); thus the main advantage of the algorithm for large \(k\) is not tested, and the runtime difference may stem from implementation, not the intrinsic method. (R6)  
- No synthetic experiments (e.g., stochastic block models) to validate asymptotics. (R1, R6)  
- Single-view experiments lack competitors: several methods listed in Table 1 (classical spectral, FastSimple, etc.) should have been compared, but were not. (R5)  
- Multi-view competitors are over a decade old; recent multi-view surveys should guide evaluation. (R5)  
- **Human evaluation of linfcut is unscientific:** only one image is shown to claim superiority over ncut and Cheeger; no human subjects trial, no annotation study, no evaluation on standard segmentation benchmarks (BSDS, more COIL/SF-MASK images). (R1, R3)  
- Missing experimental details for reproducibility: graph construction method for images (e.g., Gaussian kernel parameters \(\sigma\)), dimensionality, compute equipment (CPU, RAM). (R1, R6)

**W3. Limited novelty and missing related work (multiple reviewers).**  
- The greedy agglomerative approach is conceptually very close to GANC (Tabatabaei et al., Pattern Recognition 2012), which merges clusters based on maximal improvement in normalized cut. The main difference is the use of \(h(i,j,w_{ij})\) instead, but running time and data structures are almost identical. (R1, R5)  
- The acceleration via max-heap and union-find is standard textbook material; the paper is primarily an engineering improvement over GANC. (R5)  
- Missing references:  
  - Hierarchical agglomerative clustering literature (Müllner, 2011) and its connection to Dasgupta’s cost function (Dasgupta, 2015). (R1, R4)  
  - Nearly-linear time spectral partitioning with guarantees (Peng et al., COLT 2015 / SICOMP 2017). (R2, R6)  
  - Other non-spectral methods for min-bisection (Lin–Kernighan) and billion-scale spectral analysis (Kang et al., PAKDD 2011). (R6)  
- The claim that the algorithm “minimizes the same criteria as classical spectral clustering” is misleading; classical algorithms are known to minimize a *relaxed* objective, while the greedy algorithm has no such guarantee. (R4)

**W4. Reproducibility concerns.**  
- Code is provided but has no comments. (R3)  
- Reviewer 4 states no code is available to reproduce results. (R4) – *Note: this may refer to the supplementary material not containing an executable code release; we keep both observations.*  
- Key parameters not defined (e.g., \(l\) in Table 1, parameter \(r\) in randomized algorithm). (R1, R5)

**W5. Minor issues and missing discussions.**  
- Several typos: “Laplaian” (p.1), “algorithms” (p.1), “Bader(2022)” (sec.1.3), “depending depending” (eq.7), “he” for “the”, “replacing then” in Algorithm 2. (R1, R6)  
- Appendix A header present but no appendix. (R1)  
- Notation inconsistency: \(h(i,j,w)\) vs \(h(i,j,w_{ij})\). (R1)  
- Lemma 1: introducing \(x\) is unnecessary. (R3)  
- The phrase “expected time” should clarify randomness source earlier. (R6)  
- Equation (5) feels unnatural. (R3)  
- The final paragraph of the conclusion is unclear. (R6)
