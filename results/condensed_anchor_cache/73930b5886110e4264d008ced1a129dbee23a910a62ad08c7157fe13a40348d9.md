## Merged Review

### Summary
The paper proposes SoftMatcha, an algorithm for soft (semantic) pattern matching over billion-scale text corpora. It combines inverted indexes with word embeddings so that only a constant number of costly soft comparisons are needed per query, independent of corpus size. The method is compared to exact string matching and dense vector search on English and Japanese Wikipedia, and applied to a Latin case study. A web demo is provided.

### Strengths
- The paper is clearly written and easy to follow; the algorithm is simple and straightforward. [R1, R2, R3]
- The algorithm requires only a constant number of soft word comparisons relative to corpus size, enabling billion-scale search in under a second without GPU, comparable in speed to exact string matching and much faster than dense vector search. [R1, R3]
- The demo is functional and accessible. [R1, R2, R3]
- The method shows practical utility for linguistic analysis (English, Japanese, Latin) and for extracting harmful content from large corpora. [R2, R3]

### Weaknesses
- **Dense vector search baseline lacks reproducibility details (R1):** Missing specification of chunking granularity (sentence/paragraph?), model input formatting (prefixes/special tokens per intfloat/multilingual-e5-large), maximal input length handling (truncation vs. splitting), pooling method for chunk-level scores, and HNSW hyperparameters (number of neighbors, construction/search parameters).
- **Table 2 performance evaluation is under-specified (R1):** Only average search time is reported. Missing: number of queries used (e.g., 1, 100, 1000), query length distribution, and variation in search times (standard deviation, min/max). A single query is insufficient; query length can significantly affect soft matching time.
- **Missing approximate string matching baselines (R1):** Tools like agrep and TRE handle typos and inflected forms, directly relevant to the Latin case study. The paper claims approximate matching is orthogonal (Section 2.3) yet motivates the need to catch non-standard spellings and morphological variants (lines 076–080). A comparison would clarify the advantage of soft matching for these cases.
- **Lack of quantitative relevance/ranking metrics (R1, R2):** Only qualitative examples are given; no precision/recall, MAP, or NDCG are measured. Although labeled data is challenging, a quantified tradeoff between efficiency and retrieval quality (e.g., impact of threshold α on speed and result relevance) is missing. It is also unclear how sample results for Table 3 were selected (R1).
- **Reliance on static embeddings (GloVe) limits semantic accuracy (R3):** Contextual embeddings (e.g., BERT) are now standard; static embeddings can match semantically opposite terms like “lived” vs. “died” because they share contexts. The paper does not justify this choice or discuss the impact on search quality.
- **Limited handling of out-of-vocabulary (OOV) words (R3):** The algorithm operates only on the corpus vocabulary. If a word like “John” is not in the vocabulary, can it still be used in a query? How are OOV terms handled? This affects scalability across languages and domains with rich or evolving vocabularies.
- **No analysis of threshold α (R1, R2):** How does α affect the number of results, their relevance, and execution time? What fraction of additional results are irrelevant? How should users rank the additional entries found by SoftMatcha? (Questions include: how to choose α, how to rank additional entries.)
- **Fixed word order is restrictive (R1):** Matching requires exact word order. A future extension for flexible order or insertion/deletion (e.g., finding “a fantastic jazz musician” from “the jazz musician”) would be helpful; fixed order limits the ability to find paraphrases with different syntax.
- **Minor issues (R1):** Footnote about Japanese Wikipedia ranking is outdated (Japanese is now 17th, Chinese 10th). The speed claim (0.1 seconds) should include hardware specifications (156 cores, 226 GiB) explicitly in the paper rather than only in the rebuttal.
