## Merged Review

### Summary
This paper presents Dynamic Skill Adaptation (DSA), a framework for adapting LLMs to novel skills. It automatically generates training data organized in a skill graph inspired by human learning pathways (decomposing complex skills into sub-skills with dependencies) and then dynamically adjusts training data based on model performance: down-weighting easy examples, generating harder examples, and filtering errors. Evaluated on math reasoning (Pre-Calculus, MATH, GSM8K, Arithmetic) and social studies using Llama and Mistral models, with ablation studies showing component contributions.

### Strengths
- Addresses important problem of LLM adaptation and specialization.
- Motivation is clear and paper is well-structured and well-written, easy to follow.
- Approach of imitating human learning pathways through skill graphs is intuitive and insightful.
- Detailed ablation studies validate impact of each component (skill graph, dynamic update, etc.) and also examine training sequence shuffling effect.
- Dynamic training approach appears novel, offering a simple yet effective method for data filtering.
- Evaluation spans multiple datasets and tasks (math reasoning, social studies).

### Weaknesses
- **Novelty concerns relative to prior work.** Compared with [1] (Skill-it! NeurIPS 2023), this work appears to be an extension with marginal technical novelty.
- **Baseline comparison is unfair.** The paper compares fine-tuned DSA models against non-fine-tuned older models. A proper baseline should fine-tune the same base model on the same training dataset but without DSA's dynamic training scheme to isolate the benefit of the dynamic updates.
- **Heavy reliance on GPT-4 for data generation, but prompt design details are missing.** All data collection (skill decomposition, textbook/exercise generation) uses GPT-4 via prompts, yet no prompt templates or designs are provided. Prompt quality likely has large impact on performance and reproducibility.
- **Method implicitly distills GPT-4's knowledge, yet underperforms GPT-4.** DSA's trained models still perform below GPT-4 (Table 2, GPT-4 best across all tasks). This raises the question: why invest in costly GPT-4 API calls for data generation to create a specialized LLM that underperforms the general teacher? A more compelling demonstration would use a weaker model (e.g., Llama 2) to generate data, showing DSA improves the LLM's own domain-specific performance without relying on a stronger teacher.
- **Data leakage concerns not rigorously addressed.** Authors state a sanity check ruled out exact test-train matches, but GPT-4 is unlikely to reproduce training data verbatim. A more convincing check would verify that generated exercises do not yield the same answers as test questions. Notably, DSA models underperform ChatGPT on the custom Arithmetic task but outperform on Pre-Calculus and Social Studies, suggesting possible leakage advantage on the latter tasks.
- **Performance limited by GPT-4's ability to decompose skills.** If GPT-4 cannot decompose skills well, DSA's performance will drop. This implies DSA's upper bound is GPT-4. Since GPT-4 itself solves the math questions well, the need to train a weaker model becomes questionable.
- **Crucial details missing about data and training.** No definitions or thresholds for "easy-to-learn" vs "hard-to-learn" examples; boundary is unclear. Statistics (counts, proportions) of training/evaluation datasets are absent, raising concerns about evaluation reliability. It is also unclear in the ablation study whether the model is still fine-tuned when removing each component.
- **Lack of handling cyclical skill dependencies.** The hierarchical skill graph assumes clear unidirectional dependencies, but many real-world skills have cyclical dependencies (e.g., skill A helps learn B, which reinforces A). The method's strict hierarchy may constrain such bidirectional learning. How does DSA handle this?
- **No mechanism to detect or correct fundamental misunderstandings.** The method generates harder examples but does not identify when a model learns an incorrect approach or guide unlearning of errors. This is critical given reliance on self-generated training data.
- **No verification that model learns intended skills vs. shortcuts.** How does DSA ensure the model understands underlying problem structure rather than memorizing fixed patterns?
- **Assumption that complex skills decompose into clear subtasks may not hold for holistic skills.** Some skills are emergent from interacting components that cannot be cleanly separated. How does DSA handle such cases?
- **Missing iteration-level statistics on data categories.** Reviewer requests proportions of easy, hard, error, and ambiguous examples per iteration: initial error rate, whether most data is ambiguous, and how these change across iterations. (Minor typo: in Algorithm 1, $L_{ambiguous}$ should be $E_{ambiguous}$.)
