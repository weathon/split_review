## Merged Review

### Summary
The paper proposes API-based and hybrid (API + browsing) agents for web tasks, evaluating them on WebArena. Most reviewers (3, 3, 3) rate it low due to insufficient depth and flaws, but one reviewer (5) is substantially more positive, praising originality and empirical quality. The consensus is that the idea is promising but the execution, literature survey, result reporting, and analysis are incomplete.

### Strengths
- **Novelty of problem formulation**: Incorporating API interactions as an additional action space alongside GUI-based browsing is a creative and promising direction (Reviewers 1, 2, 3). The notion has practical implications for making websites more agent-friendly (Reviewer 1).
- **Robust empirical evaluation**: The experiments on WebArena are well-designed, with clear key findings supported by data (Reviewer 2). Use of current LLM tools (ChatGPT, CodeAct) minimizes human interference (Reviewer 4).
- **Significance**: Addresses a critical gap; findings could influence future research and web infrastructure design (Reviewer 2).

### Weaknesses
- **Incomprehensive literature survey**: API-based agents are not new; prior work includes ToolBench’s ToolLlama, AnyTool’s hierarchical agent, etc. (Reviewer 3). The paper falsely claims “no other real-world web task benchmarks are available at the moment”; actual benchmarks include WebVoyager, GAIA, Webshop, WorkBench, WebCanvas, ST-WebAgentBench (Reviewers 1, 3).
- **Poor writing and errors**: Multiple typos and inconsistencies: “Nonetheless, However,…” (p.1), “that combining” → “that combines” (p.2), “withe” (p.3), “Fig 2” → “Fig 1” (p.3), “see section ??” (p.4), Table 2 caption: “Each row columns sums up to 1.” → “Each column sums up to 100”, spelling “bemchmark” (Reviewers 1, 3).
- **Insufficient technical detail**: The hybrid agent’s decision mechanism for switching between API calls and GUI interactions is unclear; the paper lacks architecture details, error-handling, and integration specifics (Reviewer 2).
- **Imperfect representation of results**:
  - Table 1: Claim that API-based agent scores higher than browsing on *all* websites is false; it fails on Shop-Admin and Multi-Sites (Reviewer 3).
  - Browsing agent’s best scores are not on Gitlab and Map as stated (Reviewer 3).
  - Hybrid agent does NOT outperform other agents in all categories; SteP outperforms it on Shopping, Reddit, and average (Reviewer 3).
  - Table 4: Claim that browsing takes “consistently more steps” is false; it takes the fewest steps for Shopping, Shop-Admin, and Multi-Sites (Reviewer 3).
  - Claimed improvement from 9.43% to 14.15% for Reddit is unsupported by any table (Reviewer 3).
- **Missing analysis**: No error-mode analysis for API and hybrid agents; unclear how many tasks are solvable exclusively via APIs, the minimal API calls required, or common failure causes. The statement “good quality APIs influence performance” is too generic (Reviewer 1).
- **Limited evaluation scope**: Only WebArena; should include WorkArena, WorkArena++, ST-WebAgentBench, WebCanvas (Reviewer 2). WebArena is simulated; WebVoyager is more realistic and not simulated (Reviewer 3).
- **Unaddressed practical dependencies**: The approach assumes prior knowledge of API endpoints and complete documentation. No discussion of handling incomplete, undocumented, or changing APIs (Reviewers 2, 4). Only RESTful APIs considered; SOAP and GraphQL not addressed (Reviewer 4).
- **Security and ethical gaps**: No mention of authentication, rate limiting, or compliance with terms of service (Reviewer 2).
- **Incomplete performance evaluation**: Only success rates reported; missing execution time, resource utilization, learning efficiency, and statistical significance (Reviewer 2).
- **No adaptation to web changes**: How the agent copes with UI/API updates is not discussed (Reviewer 2).
- **Lack of research depth and optimization**: The use of web APIs is straightforward and not novel by itself; no research challenges identified (Reviewer 4). The two-phase documentation retrieval method is simplistic; unclear how endpoints are obtained in the absence of a readme, and the reliability of GPT-4-generated documentation is unexamined (Reviewer 4).
- **Baseline and comparison issues**: The baseline browsing agent description is too brief; SOTA agents (STeP, Agent-E, AgentOccam) are not used. Comparisons with SteP, AutoEval, AWM lack description; references for AutoEval and AWM miss publication venues; why browsing is much less effective than these baselines is not explained (Reviewers 3, 4).
- **Limitations underexplored**: When human interference is unavoidable and how to minimize it are not discussed (Reviewer 4).

*Note: One reviewer (score 5) is significantly more positive than the other three (scores 3), especially on originality and evaluation quality.*
