## Merged Review

### Summary
The paper proposes CrossMed, a method for modeling structured EHRs by integrating both visit-level (discrete codes) and finer-grained monitoring-level (e.g., lab test results) data. It constructs a cross-level interaction temporal graph for each visit at the monitoring level, then aggregates via a temporal network into a visit embedding for downstream prediction. Experiments on disease prediction and drug recommendation using MIMIC-III (15k patients) and MIMIC-IV (19k patients) show performance improvements over several baselines.

### Strengths
- Integrates both visit-level and monitoring-level EHR data, capturing finer-grained health trends.
- Ablation studies demonstrate the effectiveness of individual modules.
- Comprehensive experimentation on both diagnosis prediction and drug recommendation tasks.
- The paper is well-written overall, with clear text, figures, and appendix (though some reviewers found parts unclear).
- Good selection of evaluation tasks and metrics.

### Weaknesses
- **Clarity of monitoring data definition:** The term “monitoring data” is vague. Reviewers ask: Are these continuous signals (e.g., ECG time series), imaging (MRI), or numerical lab test results? Which specific lab tests (e.g., blood glucose, cholesterol) are included, and how are they represented (raw values, normalized, categorical bins)? Are monitoring events available for all patients (provide statistics)?
- **Incremental contribution:** Multi-level EHR modeling is not new; the paper does not discuss prior work like MiME [1] and its successors.
- **Causal assumptions:** It is unclear why only responses from visit to monitoring events are modeled. What are the causal assumptions? What outcomes are targets, and what features are confounders?
- **Dataset appropriateness:** MIMIC-III/IV are ICU datasets where monitoring events occur within a single ICU stay. Do monitoring events in one ICU stay affect the next visit? The very small dataset sizes (15k, 19k) raise skepticism: the method may not scale to larger data where a deep network could learn interactions automatically (the authors themselves note a single graph layer performs best).
- **Missing comparisons to multimodal baselines:** If monitoring data includes lab signals, this is a multimodal setting. Baselines that handle both discrete EHR codes and continuous lab values are needed. Current baselines use only discrete codes; a simple feedforward network using both monitoring and visit features as a baseline is missing.
- **Hyperparameter details lacking:** No table of optimal hyperparameters or search grids for either the proposed method or baselines. It is unclear if equal effort was spent on hyperparameter tuning for all models.
- **Statistical significance not reported:** Many results are very close; p-values should be reported. Improvements are often within one standard deviation of baseline performance (Table 1).
- **Analysis of cross-level interactions missing:** The major contribution is the cross-level interaction, yet no analysis of the learned interactions is provided. The t-SNE plot is not straightforward: why does “sparser” indicate better? The difference in patient representation plots looks similar; forming subclusters might be more informative.
- **Missing code for data preprocessing:** The functions `preprocess.drug_recommendation_mimic34_fn` and `preprocess.diag_prediction_mimic34_fn` are not provided, hindering reproducibility.
- **Computational cost:** The temporal graph size grows with the number of monitoring sessions per visit, potentially increasing cost significantly.
- **Unclear model details:** 
  - The visit-to-patient stage is poorly explained in the main text (how are patient and visit representations combined to obtain $h_H$?). The content in Appendix B.4 should be in the main text.
  - In the cross-level interaction temporal graph, all monitoring event-disease pairs use the same aggregate value from the relationship discovery module. Why not use unaggregated values to give different weights? (Same for m-P and m-R pairs.)
  - How is $\alpha$ in Eq 3 chosen? Is $z_i$ in Eq 4 a trainable parameter or fixed?
  - What does the “temporal recurrent component in feature interaction” in the ablation study refer to? Is it the GRU aggregating $h_vt$ or the feature interaction on cross-time edges?
- **Figures need improvement:** Current figures depict only high-level concepts and lack detail. Figure captions (e.g., Figure 3) are not self-explanatory. A detailed diagram of data flow, transformations at both levels, and interaction mechanisms is needed.
