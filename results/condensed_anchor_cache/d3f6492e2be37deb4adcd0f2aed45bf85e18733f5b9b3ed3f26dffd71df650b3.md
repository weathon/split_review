## Merged Review

### Summary
The paper proposes Skeleton-of-Thought (SoT), a two-stage prompting method to reduce LLM inference latency. It first prompts the LLM to generate a skeleton of key points, then elaborates each point in parallel via batched decoding or parallel API calls. Evaluated on 12 LLMs across FastChat and LLMZoo benchmarks, SoT achieves speedups of 1.13x–2.39x, with mixed quality effects: improvement on some categories (knowledge, role-play, common-sense) and degradation on others (coding, immersion/coherence). A router-based variant (SoT-R) trades speed for better quality by falling back to sequential decoding when needed.

### Strengths
- Well-written, clear exposition, easy to follow.
- Simple and intuitive idea, good empirical motivation, effective for certain tasks.
- Thorough and extensive experimentation across 12 LLMs, multiple benchmarks (FastChat, LLMZoo), and categories; authors did not conceal poor performance (e.g., coding).
- Demonstrates considerable speedups (up to 2.39x) across models.
- For some models and categories, SoT provides both efficiency and quality improvements, which is attractive for practical adoption.
- Hybrid method (SoT-R) achieves speedup of up to 1.80x with improved quality for certain categories (common-sense, generic, counterfactual).
- Good use of LLM prompts for skeleton generation and router.
- Problem is important and worth pursuing with widespread use of LLMs.

### Weaknesses
- **Limited applicability:** SoT only works for answers decomposable into independent points with low interdependence; it is not suitable for chain-of-thought, code generation, or tasks requiring coherence. This is a fundamental constraint that is not clearly stated in the introduction (only clarified in Section 3).
- **Quality degradation:** Hurts overall coherence and immersion (Section 3.2.4); quality degrades on about half the models/categories, raising robustness concerns. Without the backoff strategy (SoT-R), the quality benefit is unclear.
- **Lack of human evaluation:** All automatic evaluation is done by GPT-4 or ChatGPT-3.5, which could be biased or misleading; human evaluation is required.
- **Missing comparisons:** No direct comparison to existing speedup methods (model quantization, knowledge distillation, speculative decoding, batch inference). These orthogonal techniques should be discussed to contextualize the contribution (e.g., where they would appear in Figure 1b).
- **Undocumented overhead:** Skeleton generation and repeated prompts (increasing linearly with bullet points) introduce latency, memory, and inference costs. The prefill stage and KV cache memory footprint for multiple parallel contexts are not quantified in the main results. Overall throughput given fixed compute may decrease.
- **Confounding length bias:** SoT produces longer answers than normal prompting (Section 3.1.1), which may bias automatic evaluations that prefer wordier responses. No analysis of this effect is provided.
- **Sensitivity to prompt design:** The method’s effectiveness depends on prompt specifics (e.g., number of points, point length “3-5 words” / “3-10 points”). A systematic study of these parameters is missing.
- **Limited novelty:** The core idea (first list key points, then elaborate) is straightforward and similar to existing hierarchical text generation or planning approaches, which are not discussed. The contribution is mainly experimental rather than conceptual.
- **Misleading title:** The title “Skeleton-of-Thought: Prompting LLMs for Efficient Parallel Generation” implies a modification to the LLM’s decoding loop, but the method is purely a prompting strategy. The actual decoding remains sequential.
- **User experience doubts:** Parallel generation of multiple points does not speed up per-point token generation; humans read sequentially, so the perceived latency benefit may be minimal if per-point speed is not faster than reading speed.
- **Real-world deployment concerns:** In online serving (batch size > 1), the actual speedup may differ because parallel point expansions compete for the same compute; the reported numbers assume batch size = 1.
- **Naturalness of generated text:** The prompt forces each sentence to start with “{point index}. {point skeleton}”, which feels unnatural and may affect quality.
- **Reliance on supplementary material:** The main manuscript should be more self-contained.
- **Open questions that overlap with weaknesses:** Whether SoT can be extended to arbitrary partial answer segments beyond bullet points; how often the router decides to use SoT (especially for models where SoT-R yields ~1.0x speedup); whether a final summarization step would improve coherence at what efficiency cost; and what percentage of training examples are suitable for SoT.

**Notable reviewer disagreement:** One reviewer (score 8, raised after author response) was notably more positive, considering the idea well-executed, likely to inspire future work, and noting that some models achieve both efficiency and quality gains. Other reviewers were more critical, questioning the method’s novelty, generality, thoroughness of evaluation, and practical overhead.
