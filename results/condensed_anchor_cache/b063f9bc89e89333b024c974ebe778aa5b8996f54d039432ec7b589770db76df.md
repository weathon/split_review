## Merged Review

### Summary
This paper proposes a safety filtering framework for PDE boundary control. It learns a neural operator mapping boundary control inputs to output trajectories, then uses a learned neural boundary control barrier function (BCBF) to filter a nominal (RL) controller via quadratic programming. The goal is to guarantee that boundary outputs stay within a safe set. The approach is evaluated on hyperbolic, parabolic, and Navier-Stokes PDEs.

### Strengths
- Clear writing and easy to follow (Reviewer 2).
- Interesting connection between PDE control and neural certificates; the overall approach is straightforward (Reviewer 2).
- The key module of learning the transition function from boundary input to output, i.e., \(Y(t)=G(U)(t)\), enables model-based CBF to be applied (Reviewer 3).

### Weaknesses
- **No statistical significance reported.** No error bars are provided for feasible rate or average feasible steps. Running 10 sets of 100 episodes would allow reporting mean and std. In Tables 1, 2, 4, and 5, none of the rewards should be in bold because they are all within 1 standard deviation of each other (insufficient evidence to claim one method achieves higher reward). The same issue applies to SAC results in Table 3 (Reviewer 2). The rewards are very noisy with large std., and PPO/SAC without safety filters do not consistently achieve the highest reward, which undermines the conclusions (Reviewers 2 and 3).
- **Insufficient baselines.** The paper only compares against an RL controller that was not trained with safety constraints. Missing comparisons to other safe PDE control strategies, retraining the RL controller with a safety term, using constrained RL (instead of PPO/SAC), or a model-based controller using the learned neural operator (Reviewer 2).
- **Safety rate is not 100% despite the title claiming “guaranteed” control.** The feasible rate reaches only 71% on some problems. The paper does not adequately explain why. Possible causes (BCBF not fully trained, model mismatch, distribution shift from using nominal controller data) are not investigated (Reviewer 2). The trade-off between reward and feasibility is not significant; in Table 3 feasibility improves by 13% with minimal reward loss, raising questions about the severity of the safety problem (Reviewer 3).
- **The non-Markovian property of boundary control is not truly addressed.** Explicitly using time \(t\) as an argument to learn the input-output map still gives a point-to-point map at time \(t\) (Reviewer 3).
- **The core approach is largely standard CBF.** After learning the model (neural operator + BCBF), the CBF loss functions and QP formulation can be readily found in existing work (e.g., Dawson et al. 2023, Garg & Panagou 2021b). The novel component is the model learning; other parts are not novel (Reviewer 3).
- **Learning the model \(Y(t)=G(U)(t)\) is generally hard and sample-complex for PDEs.** Scalability to high-dimensional PDEs beyond 1-D and 2-D is unclear (Reviewer 3).
- **Data collection for \((U(t), Y(t))\) may be computationally expensive.** How is the data collected? By solving the PDE repeatedly? This could be inapplicable for high-dimensional PDEs (Reviewer 3).
- **Experimental results are confusing to interpret.** For PPO approaches in Table 1, the time-independent filter \(\phi(Y)\) failed to improve the feasible rate; for SAC it even lowered the feasible rate significantly, casting doubt on the effectiveness of the method or its implementation (Reviewer 3). Similar issues appear in Tables 2 and 3 (Reviewer 2).
- **Different boundary feasibility constraints for PPO and SAC are used in Tables 1 and 2**, but no justification is given (Reviewer 2).
- **The filtering threshold \(\eta\) allows unsafe behavior when \(\dot{U}_{\text{nominal}}\) is far from being safe.** The intuition for including \(\eta\) is not clear (Reviewer 2).
- **Using pre-trained RL controllers to collect training data risks distribution shift** when the nominal controller is replaced by the filtered controller, causing error in the learned transfer function \(\&\) BCBF. The paper does not discuss how to mitigate this, nor does it consider using a different (e.g., persistently exciting) control input for data collection (Reviewer 2).
- **Equation (7) is missing a subscript “\(]_+\)”.** The QP in (13) is a single-variable convex problem that could be solved analytically, so it is unclear why real-time solvability is a concern (Reviewer 3).
- **Terminology:** “Partial derivative equations” should be “partial differential equations” (Reviewer 3).
- **Minor:** Consider using `\citep` to put citations in parentheses (Reviewer 2).
