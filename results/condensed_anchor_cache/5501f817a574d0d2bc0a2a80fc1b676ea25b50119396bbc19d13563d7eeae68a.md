## Merged Review

### Summary
The paper proposes AnoLLM, a framework that uses large language models (LLMs) for unsupervised tabular anomaly detection. Tabular data is serialized into text, a pre-trained LLM is fine-tuned with a causal language modeling loss, and anomaly scores are derived from negative log-likelihood. The approach handles mixed-type data (textual, numerical, categorical). It achieves best performance on six mixed-type datasets and is competitive with KNN on 30 numerical ODDS datasets.

### Strengths
- Novel use of LLMs for tabular anomaly detection (Reviewers 1,2,3; but Reviewer 4 finds the method too simple and novelty lacking).
- Paper is well-written and easy to follow (Reviewers 1,2,3).
- Provides theoretical grounds for length-bias mitigation when computing anomaly scores (Reviewers 1,3).
- Effectively handles text and categorical features, which are challenging for traditional methods (Reviewers 3,4).
- Strong performance on mixed-type datasets and competitive results on numerical datasets (Reviewers 1,2,4).
- Explores small LLM variants and shows they are no less effective (Reviewer 2).
- Introduces a preprocessing technique to make tabular data amenable to LLM fine-tuning (Reviewer 3).

### Weaknesses
- **Novelty and claims**: Reviewer 4 strongly questions novelty, arguing the method is straightforward (using negative log-likelihood) and that the claim of being the first to apply LLMs to tabular anomaly detection is inappropriate given prior works: e.g., *Anomaly detection of tabular data using llms*, *LLMClean: Context-Aware Tabular Data Cleaning via LLM-Generated OFDs*, and *Enhancing Anomaly Detection in Financial Markets with an LLM-based Multi-Agent Framework*. Other reviewers found the problem statement innovative, but this contrast should be noted. Also, Reviewer 4 finds contributions 3 and 4 indistinguishable (both about experiments).
- **Baseline comparisons and metric reporting**: 
    - Reviewer 3 states that claims of outperforming deep learning methods may be overstated: strong baselines like ICL (Shenkar and Wolf 2022) and DTE (Livernoche et al. 2024) are missing or perform better; the use of column permutations as an ensemble strategy should be applied to baselines for fair comparison (Appendix C suggests permutations may not be critical). Include F1 score or AUC-PR due to class imbalance.  
    - Reviewer 1 requests standard deviations or critical difference plots for statistical significance; include actual results for other metrics (e.g., precision/recall) in the main paper, not just appendix.  
    - The discrepancy in ICL results between this paper and the original paper needs explanation (Reviewer 3).  
    - Hyperparameter choices for baselines should be described (Reviewer 3).  
    - Only one dataset contains text columns; more datasets with text and higher dimensionality should be tested (Reviewer 4).
- **Computational cost and reproducibility**: 
    - Reviewer 3 identifies this as the biggest weakness: fine-tuning uses 7 A100 GPUs, making access difficult; no code is provided, hindering replication. Most anomaly detection methods run on basic GPUs or CPUs. A discussion of training and inference time, as well as total computational cost, is missing. Reviewer 1 also asks for time comparison and trade-off analysis. Reviewer 3 also asks if the code will be released.
- **Data preprocessing and handling**: 
    - Unclear how high-cardinality categorical features are handled; grouping rare categories may be insufficient and the impact should be discussed (Reviewer 1).  
    - The phrase “50% of normal samples for training” is confusing; the evaluation protocol needs clarification (Reviewer 1). Reviewer 3 further notes that a clear distinction between unsupervised (training set may contain anomalies) and semi-supervised (training set is clean) anomaly detection should be made; the paper’s experiments are semi-supervised.  
    - Effect of number of decimal digits in numerical features not explored (Reviewer 2).  
    - Effect of normalization not explored in detail; could raw numbers rounded to a fixed decimal place work? (Reviewer 2).  
    - Why were less widely-known LLMs used instead of Llama, Qwen, Mistral? (Reviewer 4).  
    - Consider training a model from scratch using the AnoLLM framework to understand the role of pretrained text knowledge (Reviewer 3).  
    - Consider handling numerical columns separately and/or using other categorical encodings (Target Encoder, Skrub) (Reviewer 1).
- **Ablation and analysis gaps**: 
    - Effect of not permuting column names (canonical ordering) is not studied; would it improve results? (Reviewer 2).  
    - Need case studies and failure analyses (false positives/negatives) to understand what constitutes an anomaly (Reviewers 1,4).  
    - Ablation on random column permutations is missing (Reviewer 4).  
    - Experimenting with contaminated training data (truly unsupervised setting) is missing (Reviewer 3).
- **Presentation issues**: 
    - Provide an explicit example of an anomaly in tabular data (e.g., a sample from the dataset) in Figure 1 (Reviewer 1).  
    - Typos: “specicious” → “specious” (Introduction); double colon in equation (line 213); missing space in Figure 2 title (Reviewer 3).  
    - Use conference/journal citations instead of arXiv versions where possible (Reviewer 3 lists 14 such citations).  
    - Formatting issue on line 249 (Reviewer 4).
