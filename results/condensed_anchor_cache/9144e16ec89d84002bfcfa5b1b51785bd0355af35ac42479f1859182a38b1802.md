## Merged Review

### Summary

Reviewers appreciate LeanQuant’s core idea of learning a loss-error-aware quantization grid to replace the standard min-max affine grid in iterative PTQ frameworks, and its demonstrated scalability up to 405B parameters. Several reviewers find the method novel, the fused GPU kernels valuable, and the ablation study thorough. However, a minority of reviewers are more critical regarding the novelty, arguing that the non-uniform variant resembles GPTQ + k‑means (similar to GPTVQ) and the affine grid search is comparable to GPTQ’s own MSE range search. There is significant disagreement on the need for hardware-aware lower-bit quantization: one reviewer questions the computational and memory benefits of 3/2‑bit weights when hardware commonly uses 4‑bit or higher storage formats. Multiple reviewers note missing comparisons (e.g., AWQ in the main text, recent SoTA like QuIP, QuIP#, QuaRot, SpinQuant, and SqueezeLLM’s Hessian-diagonal metric), missing details on non-uniform extension, and the omission of group‑wise quantization results. Several reviewers also request clearer definitions of basic quantization terminology and more efficiency comparisons with prior methods.

### Strengths

- **Loss-error-aware grid tuning** – The approach of learning the quantization grid using a layerwise loss objective is well motivated and directly addresses the observed issue of outliers in inverse Hessian diagonals degrading min‑max grids.  
- **Both uniform and non-uniform methods** – The paper provides a unified framework for affine (uniform) and non-uniform (k‑means based) quantization, enhancing versatility.  
- **Fused GPU kernels** – Custom CUDA kernels accelerate grid learning (up to 50× speedup), making the calibration process practical for large models.  
- **Scalability** – The method is demonstrated on Llama‑3.1 405B using only two Quadro RTX 8000‑48GB GPUs in 21 hours, confirming low resource overhead.  
- **Comprehensive evaluations** – Experiments cover multiple recent LLM families and sizes, with detailed ablation studies on loss error, k‑means initialization, and the effect of the hyper‑parameter \(p\).  
- **Compatibility** – LeanQuant generalizes to both affine and non-uniform quantization types, improving integration with existing frameworks without requiring specialized inference kernels.

### Weaknesses

- **Novelty concerns** – Several reviewers note that the non-uniform loss‑error‑aware grid is essentially GPTQ + k‑means, similar to GPTVQ, and the affine grid search is equivalent to GPTQ’s MSE grid search already present in its codebase. A direct comparison with GPTQ’s MSE range search is requested to clarify the conceptual difference.  
- **Missing comparisons with recent state‑of‑the‑art** – The paper does not compare with QuIP, QuIP#, QuaRot, or SpinQuant.  
- **Missing AWQ results in the main text** – AWQ is listed as a baseline but its results only appear in the appendix; reviewers request either a summary in the main text or an explicit justification for the omission.  
- **Lack of group‑wise quantization results** – Table 1 uses row‑wise quantization only. Group‑wise quantization is common in LLM PTQ; results for group‑wise affine or non-uniform settings are needed to assess fairness and performance across schemes.  
- **Efficiency comparisons incomplete** – Table 5 reports LeanQuant’s runtime with and without the custom kernel, but does not include runtimes for GPTQ, AWQ, OmniQuant, or other baselines.  
- **Peak GPU memory missing for baselines** – Table 4 omits memory usage for AWQ and GPTQ; reviewers ask to include these or explain why they are missing.  
- **Hardware‑awareness questioned** – One reviewer argues that reducing bit‑width to 2/3 bits may not yield computational acceleration on GPUs that natively support 4‑ or 8‑bit operations, and that 2/3‑bit weights are often stored in higher‑width formats, diluting memory and transfer benefits.  
- **Non-uniform extension poorly explained** – Reviewers find the step‑by‑step adaptation of the grid learning for non-uniform quantization unclear, and the key differences from the affine process are not formally laid out.  
- **Equations and derivation need more context** – Equation 6 (k‑means objective) and the equation on line 285 appear without proper derivation or citation; it is unclear which parts are novel and which are from prior work.  
- **Definition of basic quantization terms is lacking** – The concepts of “quantization grid,” “grid points,” “uniform vs. non-uniform grids,” and “group of weights” are not clearly defined or visualized, making the paper less accessible to non‑specialists.  
- **Outlier analysis limited** – The claim that outliers in inverse Hessian diagonals harm min‑max grids is demonstrated on only one dataset/model; reviewers request evidence across different datasets and models.  
- **Contradictory ablation on \(p\)** – Table 10 shows that \(p>0\) performs similarly to \(p>1\), yet the paper argues that accounting for outliers (via the inverse Hessian diagonal raised to \(p\)) is crucial. The absence of \(p=1\) and the lack of comparison with other methods using the same outlier‑aware metric weaken this claim.  
- **Missing vanilla FP16 baseline** – Tables 2 and 3 do not report the full‑precision FP16 accuracy; also non-uniform LeanQuant results are not shown in those tables.  
- **Questions from reviewers** (summarized as weaknesses where they overlap with missing experiments or clarification requests):  
  - How does the initial grid placement (uniform spacing vs. k‑means++) affect accuracy? Provide a visualization.  
  - Is the k‑means grid search parallelizable on GPU, or is it CPU‑bound?  
  - Can the fused kernel technique be applied to prior methods to make them faster?  
  - What is the effect of weight updates during GPTQ iterations on k‑means centroids? Does the weight deviate significantly from the original?  
  - In which scenarios should affine vs. non-uniform quantization be recommended?  
  - If group‑wise quantization is applied to the affine method in Table 1, how does the result change?  
  - Can the authors directly ablate the “inverse Hessian diagonal” metric against SqueezeLLM’s “Hessian diagonal” metric?
