## Merged Review

### Summary

The paper introduces SEEKER, a multimodal large language model that compresses long text input by rendering it as images (visual tokens) instead of using text tokens, aiming to efficiently handle long-form multimodal context within a fixed token budget. Evaluations on six long-context tasks claim SEEKER outperforms existing proprietary and open-source MLLMs. Reviewers agree the method is novel and validated on selected tasks, but raise concerns about task simplicity, missing baselines (text-only LLMs with large context windows), data leakage from training, lack of ablation studies, and insufficient analysis of rendering details and modality superiority.

### Strengths

1. **Novel tokenization approach**: Using visual tokens to represent textual content compacts long-context data, enabling efficient processing within limited token length and faster inference (Reviewer 1).

2. **Strong empirical performance**: SEEKER outperforms existing multimodal models on multiple long-context tasks, with comparative evaluations across diverse datasets including multi-image and long-form output tasks (Reviewer 1, Reviewer 3). Reviewer 3 notes experimental results validate effectiveness across selected tasks.

3. **Well-identified real-world problem**: The paper effectively highlights the difficulty of text-based multi-image document reasoning. Figure 1 is notable and relevant to industry domains like robotic process automation (Reviewer 2).

4. **Valuable tasks and dataset**: The proposed tasks and curated training dataset contribute to advancing vision-language model research. Sharing data/code would benefit the community (Reviewer 2). Reviewer 3 finds writing clear and straightforward, making it easy to follow.

5. **Disagreement on writing quality**: One reviewer (2) states the paper is well-written and organized with clear background and relevant citations, while another (1) criticizes poor writing—incorrect citation format, confusing method section, non‑standard formulas. Reviewer 3 also finds writing clear. The negative judgment is held by a minority (1 out of 3).

### Weaknesses

1. **Task simplicity and risk of information loss**: The selected tasks are relatively simple and favor the proposed method. Rendering text on images may lose fine-grained linguistic details (e.g., small fonts, low resolution), limiting performance on precise textual analysis or long-form generation (Reviewer 1, Reviewer 3).

2. **Missing evaluation of text-only LLMs with large context windows**: Text-only LLMs that support 128k tokens (or more) are not included as baselines, despite being a practical real‑world alternative (Reviewer 3).

3. **Lack of criteria for token sequence length**: The paper does not discuss when the visual token sequence is shorter than the text token sequence, which is critical for real‑world utility. Metrics such as tokens per image or pixels per token could set a clear threshold (Reviewer 3).

4. **Insufficient ablation and generalization analysis**:
   - The low performance of existing models in Table 2 may indicate lack of generalization for the proposed tasks rather than a modality advantage. To test this, the reviewer recommends filling the "img" in Section 3.2 with OCRed text, then training the baseline model and evaluating in text‑based approach (Reviewer 2).
   - An ablation study on the contribution of task‑specific datasets (Section 3.2) to final metrics (Section 4.3) is needed (Reviewer 2).
   - No exploration of interpretability mechanisms (e.g., visual attention maps, token significance) to understand image‑text integration in complex contexts (Reviewer 1).

5. **Missing details on text rendering and OCR assembly**: Key factors—average number of text tokens rendered per image, whether OCR layout bounding boxes are used, font type/size analysis—are not provided. Font choice affects OCR and model performance (Reviewer 2, Reviewer 3).

6. **Ambiguity about text availability and training setup**:
   - If input text is available, is the number of visual tokens always less than true text tokens? (Reviewer 3, Weakness 3)
   - If input text is unavailable, the experiment essentially compares VLLM with OCR+LLM, a well-studied scenario. The advantage may stem from training on a specific rendering format rather than true long‑context improvement (Reviewer 3).
   - It is unclear whether SEEKER was trained on the dataset in Section 3.2, while comparison models were evaluated zero-shot in Table 2 (Reviewer 2, Question 1).

7. **Figure and metric concerns**:
   - In Figure 1, using ROUGE‑L over other metrics is not justified (Reviewer 1).
   - In Figure 3, should "4k context length" be updated to "8k context length"? Labels (1) and (2) need clarification (Reviewer 2).

8. **Table and experiment inconsistencies**:
   - In Table 1, "SentR" performs better than "Index," which seems counterintuitive because "Index" is more straightforward (Reviewer 2).
   - "SentR" was conducted as a single‑image task; why was it not set up with multiple images? (Reviewer 2)
   - In Table 2, some open source models struggle more with WikiVerb than ArxivVerb; is there a variation in difficulty beyond corpus difference? (Reviewer 2)
   - In Section 3.1, why was GPT‑4(V) used for testing? Would similar trends appear with open‑source models or the baseline DeepSeek-VL? (Reviewer 2)

9. **Minor presentation issues**: Citation format is incorrect (should use \citep), method section confusing, mathematical formulas not standardized (Reviewer 1).
