## Merged Review

### Summary

This paper introduces coRMAB, a generalization of restless multi-armed bandits where actions are coupled by combinatorial constraints (multiple interventions, path constraints, bipartite matching, capacity constraints). The authors propose SEQUOIA, which embeds a Q-network into a mixed-integer linear program (MILP) to select combinatorial actions at each timestep. Experiments on four novel restless bandit problems show SEQUOIA outperforms existing methods by an average of 28.3%. The problem setting is interesting and practically motivated (e.g., public health). However, the paper lacks theoretical guarantees, comparison with state-of-the-art RL algorithms, real-data experiments, and discussion of scalability and computational costs.

### Strengths

- **Novel and well-motivated problem setting.** coRMAB is a natural and general extension of restless bandits that captures real-world scenarios where actions cannot be decoupled across arms (R1, R2, R3, R4, R5). The four example settings (multiple interventions, path constraints, bipartite matching, capacity constraints) are compelling and use public health as a running example (R3).

- **Practical algorithm combining DQN with MILP.** The idea of solving the combinatorial optimization based on a Q-network’s estimate as an approximate approach is innovative and effective (R1, R5). SEQUOIA directly optimizes for long-term reward over the feasible action space, addressing the computational bottleneck of large action spaces (R4).

- **Strong empirical results.** SEQUOIA significantly outperforms existing baselines (which cannot address sequential planning and combinatorial selection simultaneously) by an average of 28.3% on four difficult instances (R2). The algorithm works with minimal hyperparameter tuning across domains (R4).

- **Clear presentation and nice figures.** The paper is well-written, with figures that aid understanding (R3).

### Weaknesses

- **Lack of theoretical guarantees.** All reviewers note the absence of regret bounds, convergence proofs, or suboptimality analysis, which is critical for bandit/RL papers (R1, R2, R3, R4, R5). No theoretical analysis is provided for any of the four problem settings (R1). This reduces the paper’s appeal to theoretical RL circles (R2).

- **No comparison with state-of-the-art RL algorithms.** The paper does not compare SEQUOIA with advanced RL algorithms (e.g., DDPG, or standard DQN with discretized action spaces) (R1, R3). For the restless bandit special case, comparison with restless-UCB (Wang et al., NeurIPS 2020) or Whittle-index-based methods would be valuable (R4). Also, the approach mentioned in lines 494-498 is not compared (R3).

- **Lack of real-world data experiments.** The paper contains only synthetic experiments; real-world datasets are necessary given the applied motivation (public health) (R2, R5). Without this, the practical utility is unclear (R2).

- **Computational scalability concerns.** 
  - Training times extend to hours (Table 3), prohibitive for online applications (R2).
  - Solving an MILP for each sample and each timestep is extremely expensive (R3). 
  - For standard DQN, output size scales with action space size; in SEQUOIA the *input* size must be of the size of the action space (exponential). Why is this more tractable? (R3)
  - Memory footprint is not discussed (R2). Parallelization potential is unexplored (R2).
  - The complexity growth with neural network size is not analyzed (R4).
  - Step 9 in Algorithm 1 involves an argmax over actions; how is this more tractable given the combinatorial action space? (R3)

- **Limited experimental design.** 
  - The four instantiations appear interdependent (e.g., multiple interventions implicitly contains path and capacity constraints); their unique contributions need clarification (R2). 
  - No sensitivity analysis of hyperparameters (R2). 
  - No comparison against domain-specific solutions for each constraint type (R4). 
  - Metrics: normalized average reward is used; would regret or comparison with optimal policy be better? (R4). 
  - The description of how the cumulative impact is modeled (linear vs. non-linear) in multiple interventions is missing (R2). 
  - For path constraints, how the path is represented and feasibility ensured needs clarification (R2). 
  - For capacity constraints, whether budget \(b_j\) is static or dynamic is unclear (R2). 
  - Inconsistency: line 431-432 claims ITERATIVE MYOPIC is 14.6% lower than MYOPIC, but Figures 3(b) and 3(c) show them very close, and Figure 3(a) shows ITER.MYOPIC higher (R5). 
  - Why only these four coRMAB settings? The algorithm should not be restricted to them (R5).

- **Confusing mathematical formulation.** 
  - Is the problem infinite-horizon (discounting suggests yes)? (R3) 
  - In Eq. (2), why is \(s'\) missing on the RHS? (R5) 
  - The set \(C\) is described as fixed; but actions might change over time due to coupling constraints (e.g., path constraints) (R3). 
  - For schedule-constrained, capacity-constrained, and path-constrained, what are the transition formulations? (R5)

- **Strong assumptions.** The paper assumes known transition dynamics and rewards (offline planning setting) (R3, R4). This is limiting for real-world problems where dynamics are unknown and must be learned through interaction (R4). In high-stakes domains (e.g., public health), poor early-stage predictions could lead to unacceptable decisions; no mitigation is discussed (R2).

- **Limited novelty of technical approach.** The idea of embedding a neural network into an MILP is not new; the paper should elaborate on the specific technical challenges overcome (R3).

- **Missing details.** 
  - The “Multiple interventions” description in line 1028 appears empty (R3). 
  - Why piecewise linear approximation of the sigmoid link function (line 181) is needed, when it can be computed exactly? (R3) 
  - Interpretation of self-loops (line 196) is missing (R3). 
  - The number of workers in Table 3 is not specified (R3). 
  - The size of the combinatorial action set in each of the four experiments is not given (R3).
