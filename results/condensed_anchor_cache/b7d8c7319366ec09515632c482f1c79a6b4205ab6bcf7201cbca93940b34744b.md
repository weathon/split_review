## Merged Review

### Summary

The paper presents IterComp, a framework that aggregates composition-aware preferences from multiple diffusion models (FLUX, SD3, RPG, etc.) via reward models for attribute binding, spatial relationships, and non-spatial relationships, and uses an iterative feedback learning loop to improve both the base model (SDXL) and reward models progressively. Reviewers broadly find the approach novel and well-supported by theoretical proofs and extensive experiments, with two reviewers (scores 8,8) more positive, emphasizing the dataset contribution, iterative mechanism, and significant performance gains, while three reviewers (scores 6,6,6) raise concerns about missing comparisons, incomplete ablations, dataset/training costs, and potential biases. Overall, the reviews agree on the framework’s promise but point to several necessary clarifications and additional experiments.

### Strengths

- First work to introduce a reward-controlled framework for compositional text-to-image generation; novel aggregation of model preferences across multiple diffusion models.
- Well-structured paper with clear formulas, mathematical proofs, and theoretical details.
- Strong empirical results showing significant performance gains over SOTAs in user studies, quantitative metrics, and qualitative assessments.
- Collection of a high-quality composition-aware preference dataset (52.5K image-rank pairs) covering three key metrics: attribute binding, spatial relationships, non-spatial relationships. The dataset can be used for other RLHF methods (e.g., Diffusion-DPO) and opens new research directions.
- Iterative feedback mechanism is a novel way to simultaneously improve the base model and reward models in a closed-loop manner.
- Code is shared, allowing reproducibility and detailed inspection.
- Inference is efficient; no additional computational overhead at test time compared to baseline models.
- Illustrative images and detailed experiments substantiate the approach.

### Weaknesses

- **Missing comparisons with advanced models:** RPG is not compared in Tab. 2, despite the paper noting RPG’s limitations. One reviewer (R2, score 6) states that RPG’s reported performance on T2I-Compbench is already better than the paper’s. Additionally, direct comparisons with FLUX-dev and SD3 (which are used to generate training data) are not provided. Including compositional metrics, image quality, and inference time for these models is needed to assess practical advantages.
- **Insufficient ablation of reward model components:** No study isolates the individual contribution of each reward model (attribute, spatial, non-spatial). It is unclear if all three contribute equally or if one dominates. A full ablation training the base model with each reward individually and in combinations is required.
- **Unclear effectiveness of iterative training:** The paper does not compare the final iterative model against a version fine-tuned only in the first round (with human-annotated data). Such a comparison is needed to justify the necessity of multiple iterations. (R4, score 8)
- **Missing generalizability tests across base architectures:** Experiments are only conducted with SDXL as the base model. Testing on models with weaker/stronger compositional abilities (e.g., SD1.5, SD2.1) is needed to understand dependency on base architecture. (R5, score 8)
- **Direct comparison with Diffusion-DPO on the same dataset is missing:** The paper should train Diffusion-DPO on the collected dataset and compare, to evaluate the proposed method’s advantages with consistent data.
- **Qualitative evaluation issues:** Fig. 4 examples (lines 3 and 4) show marginal improvement; the difference from baselines is not clearly recognizable. More examples per case and an evaluation of model stability are needed. (R1, score 6)
- **User study limitations:** The user study uses only 16 samples, which is too small for a complex compositional task. It also lacks deep analysis of attribute binding and object relationships, relying solely on user preferences.
- **Potential aesthetic bias in reward models:** When applied, IterComp also improves aesthetic scores, raising the question of whether reward models are capturing compositional aspects or are inadvertently influenced by image aesthetics (e.g., because better composition leads to more aesthetic images, or because expert rankings are confounded). This needs investigation.
- **Inference step discrepancy:** All models are evaluated with 40 inference steps, but some models (e.g., FLUX-dev) optimally use 28 steps. This may not represent each model’s true capabilities. (R5, score 8)
- **Inconsistency in dataset statistics:** Line 185 states “500 prompts” for attribute binding, but Table 1 reports 1500. Which is correct? (R4, score 8)
- **Unfair comparison with InstanceDiffusion:** InstanceDiffusion is a layout-guided method requiring detailed layout inputs, but only one box is provided for prompts containing multiple instances (Fig. 4, line 3). Also, a recent SOTA layout-to-image method MIGC is not included. (R1, score 6)
- **Limited discussion of training cost and scalability:** The cost of model training and data collection is not clear; the paper claims fast inference but does not compare training overhead. One reviewer (R3, score 6) notes that without this, the method feels less likely than DPO to be widely adopted. Additionally, training time for the iterative feedback loop is not specified; IterComp requires image decoding for reward models (unlike latent-space DPO), possibly causing slower training. (R3, R5)
- **Potential instability and overfitting of iterative RLHF:** RLHF in diffusion can be unstable; the paper does not analyze whether the iterative process consistently produces stable results or risks occasional poor outcomes. Overfitting on reward model biases is a concern. (R4, score 8)
- **Code/paper discrepancy for iterative update:** In `feedback_train.py`, only UNet parameters (base model) are passed to the optimizer, contradicting the paper’s description of iteratively updating both reward models and the base model. Clarification is needed. (R5, score 8)
- **Minority skepticism on improvement magnitude:** One reviewer (R2, score 6) suspects that the improvement over FLUX-dev on T2I-Compbench may not be significant, given that FLUX-dev’s results are not directly reported. (Contrast with R5’s view that performance gain appears significant.)
- **Table 5 placed in appendix:** This table shows clear outperformance over prior methods and should be in the main text. (R5, score 8)
- **Questions regarding test-time adaptation:** Could the iterative feedback be used for test-time adaptation (e.g., Slot-TTA) to adapt the base model to a specific prompt without full training? (R5, score 8)
