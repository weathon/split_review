## Merged Review

### Summary
This paper presents GenoAgent, an LLM-based multi-agent system for automated gene expression data analysis, comprising agents such as Project Manager, Data Engineer, Statistician, Code Reviewer, and Domain Expert. The authors also introduce GenoTEX, a benchmark dataset for evaluating gene identification tasks. Experiments show promising accuracy, but the work receives mixed reviews: two reviewers find it innovative and well-executed (scores 5), while two others cite insufficient experimentation, lack of detail, and reliability concerns (scores 3). The following consolidates the strengths and weaknesses raised across all reviews.

### Strengths
- **Innovative application**: GenoAgent is among the first to apply an LLM-based multi-agent system to gene expression data analysis, simulating collaborative bioinformatics workflows (Reviewers 1, 3). The team-based approach with specialized roles (Project Manager, Data Engineer, Statistician, Code Reviewer, Domain Expert) brings modularity and facilitates troubleshooting (Reviewer 4).
- **Benchmark contribution**: The GenoTEX dataset is a novel resource comprising gene identification problems from open databases, with manual expert curation, quality control, and assessment, providing a standardized evaluation framework for automated genomics tools (Reviewers 1, 2, 3, 4).
- **Clear writing and motivation**: The paper is generally well-written with clear problem motivation and thorough coverage of related work (Reviewer 1). The dataset curation process is carefully defined and reasonable (Reviewer 1).
- **Promising results**: The method achieves positive results in gene identification, with iterative correction and expert consultation enhancing performance (Reviewer 1, 3). The modular agent pipeline is clearly defined (Reviewer 4).

### Weaknesses
- **Insufficient experimental depth and comparison**:
  - The experiments are not sufficiently detailed or comprehensive (Reviewer 2). There is no exhaustive comparison with existing domain-specific methods (Reviewer 4) or a comparative table showing how GenoAgent improves upon prior multi-agent or bioinformatics workflows (Reviewer 3). The paper lacks a reference or baseline to interpret metrics such as CSC=79.71 (Reviewer 1). The comparison with Llama 3 (8B) is uninformative; a more powerful open-source model like Llama 3 (70B) or Llama 3.1 (70B) should have been used (Reviewer 1).
  - Performance metrics like F1 and accuracy are not fully expressive for genomics tasks; data filtering requirements are critical and not well captured (Reviewer 4). Context-dependent evaluations are needed (Reviewer 1).
  - GenoAgent has only been tested on benchmark datasets; testing on novel, unseen real-world genomics data to assess robustness is missing (Reviewer 3).
- **Reliability of code generation and feedback mechanism**:
  - The code generation success rate is not reported; how does GenoAgent ensure runnable code given the Code Reviewer is also LLM-based without fine-tuning? (Reviewer 2). The feedback mechanism from the Code Reviewer shows diminishing performance after the first feedback round, raising reliability concerns (Reviewer 4). The frequency and impact of inconsistent feedback on downstream tasks is not quantified (Reviewer 3).
  - The function library L – is its construction automatic or purely prompt-based? (Reviewer 2).
- **Lack of detail in results and methodology**:
  - Results are not clearly described; the paper uses ambiguous statements like "good overall Accuracy" or "decent performance" without proper context (Reviewer 4). The significance of metrics and tasks is not elaborated (Reviewer 1). Specific questions remain about what "merged data", "raw input data", "DF" vs "DS" in Table 2 refer to (Reviewer 1). The end-to-end performance section lacks clarity on whether this is multi-label classification and how many classes/imbalance (Reviewer 1).
  - The preprocessing of trait data is weak (CSC 32.28%) due to complexity of clinical data extraction and nuanced knowledge inference; this requires elaboration (Reviewer 1). Data normalization could be refined to reduce variability for traits (Reviewer 4).
  - The statistical analysis results are presented without expected values or interpretation (Reviewer 1).
- **Computational cost and scalability**:
  - The computational costs of using expensive models like GPT-4o are not discussed; a runtime, memory usage, or optimization analysis is missing (Reviewers 3, 4). The feasibility for widespread use is unclear (Reviewer 3).
- **Ethical and reproducibility issues**:
  - Potential ethical issues (e.g., poor accuracy leading to wrong diagnosis, biases in LLM genomic analysis) are not addressed (Reviewer 1). The paper does not mention if the GenoTEX benchmark will be publicly available, and no source code link or supplementary material is provided, hindering reproducibility (Reviewer 1).
- **Minor technical and presentation issues**:
  - Several typos (e.g., bold letters in "Data", "Automatic", "Exploration" on line 57 without abbreviation), reference formatting errors (e.g., URLs spilling, incorrect citations for Llama 3 "Lamma", and citing a non-serious work "BPC (2023)") (Reviewer 4). Reference consistency is poor (Reviewer 4).
  - The novelty of the methodology could be better differentiated from existing multi-agent LLM systems and automated bioinformatics workflows (Reviewer 3).
- **Data leakage and generalization concerns**:
  - No discussion of data leakage in gene identification problems or comparison experiments between GenoAgent and other LLMs (Reviewer 2). Prompt engineering alone may not eliminate hallucination risks (Reviewer 4).
