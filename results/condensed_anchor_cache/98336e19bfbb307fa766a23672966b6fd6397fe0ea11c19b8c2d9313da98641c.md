## Merged Review

### Summary
This paper proposes a diffusion-based model, Masked Temporal Interpolation Diffusion (MTID), for procedure planning in instructional videos. It introduces a latent space temporal logical interpolation module to generate intermediate visual features from start and goal observations, providing dense visual supervision to the diffusion process. A masked projection and a task-adaptive masked proximity loss further constrain the action sequence predictions. Experiments on CrossTask, COIN, and NIV datasets show state-of-the-art performance on most metrics.

### Strengths
- Addresses a limitation of prior diffusion models (e.g., PDPP) by incorporating intermediate visual supervision to capture temporal dependencies between actions.
- The latent space temporal interpolation module provides helpful dense supervision for the diffusion process, a novel application in this setting.
- The task-adaptive masked proximity loss contributes to performance gains.
- Strong experimental evidence: MTID achieves SOTA on the majority of key metrics across CrossTask and COIN datasets (and competitive results on NIV).
- Ablation studies are present and considered detailed and informative by one reviewer (R2), though other reviewers dispute sufficiency (see Weaknesses).

### Weaknesses
- **Misleading terminology**: The “Latent Space Temporal Logical Interpolation” module has no connection to logic or reasoning; it simply performs linear interpolation weighted by time steps. The name implies formal logic, which is absent. (R1)
- **Experimental setting inconsistencies**:
  - The paper follows PDPP’s evaluation protocol, but baseline results for KEPP, SCHEMA, etc., come from a different setting (e.g., different window sizes), making fair comparison difficult. (R1)
  - NIV table omits PDPP results; MTID does not outperform PDPP on all metrics for both time horizons. (R1)
  - Table 3 should merge results from Appendix Table 13 for a complete view of all metrics on COIN and NIV. (R1)
  - A discrepancy exists: NIV classification accuracy is far higher than COIN, but procedure planning success rate and mAcc are similar or better on COIN; the authors should explain this trend. (R2)
- **Unclear component contributions**: Without full ablations (e.g., diffusion + interpolation only, diffusion + masked projection + loss) on all datasets, it is difficult to isolate the impact of each proposed module. (R1, R3) One reviewer (R2) found the provided ablations sufficient, indicating disagreement among reviewers.
- **Motivation and baseline for interpolation**: The core idea of linearly interpolating intermediate visual features from start/goal observations is physically simplistic and lacks justification. An experiment using actual observed mid–state visual features (as in DDN) should be added as an upper bound. (R3)
- **Architecture choices questioned**:
  - The task classifier uses a Transformer; previous works (EGPP, PDPP) used a simple MLP for this classification. (R3)
  - The masked projection introduces strong prior knowledge (exact action space per task), which may limit generalizability. (R3)
- **Loss analysis incomplete**: The ablation of Task-Adaptive Masked Proximity Loss shows a tiny gain (MSE+GW 15.1 vs. MSE+W+GW+M 15.26). The “weighted gradient loss” and its derivation should be explained more explicitly in the Method section. (R3)
- **Limited novelty**: Overall novelty compared to prior work PDPP is limited, as the core diffusion framework is inherited. (R3)
- **Presentation and clarity issues**:
  - Need to clarify which parts of MTID are from PDPP (e.g., predicting task class for the input matrix, masking intermediate features). (R1)
  - Equation (1): why introduce a separate index M when v_{1:M} should simply be v_{2:T-1}? (R1)
  - Action notation is inconsistent: \hat{a}_t, \bar{a}_t, a_t are used interchangeably (e.g., Eq. (10) vs. Figure 2). (R1)
  - Figure 2 and Figure 3 captions need elaboration, fonts are too small, and the excluded-actions part in Fig. 2 is not shown. (R1)
  - Line 316: PDPP weights *both* start and end actions. (R1)
  - Table 1 caption: explain the dagger symbol. (R1)
  - Line 359: CrossTask actually has 105 action classes. (R1)
- **Model complexity**: The architecture combining latent interpolation with diffusion processes is difficult to grasp; more intuitive visualizations or a simplified explanation would help readers. (R2)
