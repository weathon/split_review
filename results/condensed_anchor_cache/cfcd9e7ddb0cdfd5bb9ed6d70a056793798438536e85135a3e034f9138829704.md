## Merged Review

### Summary

The paper proposes the implicit self-improvement (PIT) framework, which reformulates RLHF objectives at all three stages (SFT, reward model training, RL) to maximize the quality gap between a generated response and a reference response. This allows the model to learn improvement goals from human preference data without requiring explicit rubrics or prompts. Experiments on two real-world datasets and one synthetic dataset show PIT outperforms prompting-based self-improvement methods (e.g., self-refine). The method uses pairwise relation encoding in reward training and a curriculum RL approach for iterative improvement.

### Strengths

- The motivation for implicitly learning self-improvement from preference data (rather than constructing explicit rubrics) is well thought out, convincing, and likely of interest to the community.
- The core ideas – maximizing the quality gap between responses, pairwise relation encoding (Eq 2), and iterative curriculum RL – are novel and intuitively reasonable.
- The PIT framework bypasses the need for expensive manual rubric design; it only requires the same preference data used to train reward models.
- Instead of updating the original LLM (as in standard RLHF), PIT trains a separate model that learns to improve the original LLM’s outputs, which is a novel technique.
- The experimental evaluation is thorough: PIT is compared against self-refine on three datasets, and ablation studies demonstrate the effectiveness of each component (e.g., the necessity of multiple RL stages).
- The paper is generally well-written, with clear presentation and motivation.

### Weaknesses

- **Missing comparisons and baselines:**  
  * PIT is compared only to prompting-based self-refine; it should also be compared to other RL-based self-improvement methods (e.g., Preference Ranking Optimization [Song et al., 2023]).
  * A direct comparison with standard RLHF (i.e., applying RLHF to the original LLM rather than to an improvement model) is missing. The motivation for using RLHF for output improvement vs. directly improving the original LLM is not empirically validated.
  * The comparison with self-refine may be unfair because PIT uses additional human preference labels (though the paper states it uses the same data as reward model training; this point is contested). At minimum, the paper should clearly state that PIT requires human preference data beyond what is used for the base model.

- **Computational cost and inference overhead:**  
  * The iterative self-improvement process incurs increased computational time and cost during inference (e.g., determining the number of iterations). The paper does not provide a detailed cost analysis or a comparison with the cheaper, forward-pass-only self-refine method.
  * The improvement over self-refine is not always significant; in some metrics (e.g., GPT-4 evaluation) self-refine can be stronger, though the authors offer possible explanations.

- **Lack of clarity and missing details:**  
  * It is unclear whether the three models in Figure 1 (LLM, PIT, PIT reward model) are distinct or the same model; the model used in each component is not clearly stated.
  * No algorithmic block is provided to illustrate training with objectives (4) and (5).
  * The method for determining the number of iterations in the self-improvement process is not specified.
  * It should be explicitly stated whether PIT is run on top of an RLHF-finetuned model. If not, why not? RLHF would be an obvious baseline.

- **Empirical validation gaps:**  
  * Some key design choices are argued qualitatively rather than validated experimentally. For example, the pairwise relation training in Eq (2) is justified with intuitive explanations, but no ablation or comparison against the simpler alternative is provided.
  * It is unclear whether the reward model remains discriminative after multiple improvement rounds, since it was trained only on the original \(y_w\) and \(y_l\) annotations, while new outputs may exceed the original best response.

- **Qualifying comparisons with prompting methods:**  
  * Even though PIT uses fewer tokens, prompting-based methods (like self-refine) require only forward passes and no model weight adjustments; this advantage should be more clearly acknowledged in the discussion.
