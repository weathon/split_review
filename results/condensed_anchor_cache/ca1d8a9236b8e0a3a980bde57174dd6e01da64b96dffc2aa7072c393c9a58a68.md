## Merged Review

### Summary
The paper proposes DESIRE, a rehearsal-free continual learning method using LoRA-based parameter-efficient fine-tuning. It retains only two sets of LoRA parameters (previous and current) via a greedy merging algorithm, and refines the classifier via pseudo-feature generation to address new-class bias. Experiments are conducted on several benchmarks with a fixed pre-trained backbone. Reviewers note strengths in clarity, memory efficiency, and some performance gains, but raise significant concerns about missing baselines, data leakage from using unlabeled test samples, lack of cross-domain evaluation, insufficient justification of the greedy LoRA selection, missing hyperparameter details, reproducibility gaps, and limited novelty of the classifier refinement.

### Strengths
- **Clarity and structure** (R1, R3, R4): The paper is well-written, logically structured, and easy to follow.
- **Rehearsal-free design** (R2): Operates without storing past data, reducing memory overhead.
- **Efficient use of unlabeled data** (R2): Uses a small subset of unlabeled data to learn merging coefficients – considered innovative and resource-efficient by R2.
- **Performance gains** (R1, R2): Achieves superior performance on multiple benchmarks compared to other rehearsal-free methods (R2). R1 also notes performance gain on several benchmarks.
- **Storage reduction via LoRA selection** (R3): Greedy algorithm to retain only two LoRA sets avoids large storage overhead that would arise from storing many LoRA sets.
- **Classifier bias alleviation** (R3): Retraining the classifier avoids weight bias issue.
- **Interesting problem framing** (R1): Exploring the effect of the gap between pre-trained data and incremental learning data is interesting.

### Weaknesses
- **Missing comparison to HiDe-PET** (R1): HiDe-LoRA (from HiDe-PET, arxiv2024) achieves SOTA on split-CIFAR100 (FAA=76.46%, CAA=84.89%), while DESIRE on CIFAR100-10T reports FAA=72.47%, CAA=81.55%. A direct performance and memory cost comparison is needed.
- **Missing cross-domain and large-gap benchmarks** (R1): The authors should evaluate on benchmarks that avoid pre-training data overlap (e.g., ImageNet-A, ObjectNet, OmniBenchmark, VTAB from [b] arxiv2023). Cross-domain CL (e.g., VTAB tasks) each present very different tasks; can maintaining only two LoRA sets handle that? (R1, also related to generalizability concern from R2).
- **Data leakage from using unlabeled test samples for LoRA merging** (R4): The merging paradigm uses unlabeled test samples, which violates supervised learning protocol by exposing test set distribution to the model, making learned coefficients better fit the test set.
- **Unjustified greedy LoRA selection** (R3): 
  - Need explanation why local optima from greedy can substitute for global optimum given complex dependencies between LoRAs for different tasks.
  - Provide comparative experiments: random selection, using all LoRAs, selection based on importance, etc. Include computational complexity analysis.
  - Show how the number of LoRA sets (beyond two) affects performance.
- **Orthogonality claim insufficiently supported** (R3): Line 196 asserts simple initialization makes different LoRAs orthogonal after training. Only visualized on CIFAR; provide quantitative orthogonality measures across tasks and datasets.
- **Reproducibility and hyperparameter details missing** (R3): Hyperparameters are not listed. Provide detailed ablation on key hyperparameters showing their effect on performance.
- **Results in Table 1 not clearly reproduced** (R3): Several inconsistencies compared to original authors’ reported results. Describe reproduction process, any implementation differences, and experimental setup variations.
- **Missing iCARL and DER results** (R2): The paper states comparison with iCARL and DER but corresponding results are not found in the paper.
- **Generalizability concerns with fixed backbone** (R2): Backbone is pre-trained on ImageNet-1K and kept fixed. CIFAR-100/Tiny ImageNet distributions are similar to ImageNet-1K; if using datasets with features very different from ImageNet-1K, can the backbone still be kept fixed, or can it be trained continually with DESIRE?
- **Limited novelty of classifier refinement** (R4): Sampling “pseudo-features” from statistical information to alleviate classifier bias is not novel; it resembles Semantic Augmentation (Class-Incremental Learning via Dual Augmentation, NIPS 2021). Provide a direct comparison table/figure against DER and other relevant methods on methodology and performance (R3 also requests this).
- **Missing ImageNet-1K experiments** (R3): Many incremental learning methods perform poorly on ImageNet-1K; experiments on ImageNet-1K would strengthen validation (stated not to reduce score if provided later).
- **Disagreement on unlabeled data use**: R2 considers use of unlabeled data for merging coefficients innovative, while R4 flags it as a protocol violation (test-set exposure). This contrast is noted.

**Minority positive viewpoint**: R2 is notably more positive about the method’s efficiency and performance, while R4 is more critical of the protocol and novelty, and R1/R3 raise multiple missing experiments and justifications.
