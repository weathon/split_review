## Merged Review

### Summary
This paper proposes Matryoshka Multimodal Models (M³), an LMM framework that learns to represent visual content as nested sets of visual tokens at multiple coarse-to-fine granularities. It generates multi-scale visual features by applying average pooling on CLIP-ViT outputs with different kernel sizes, and jointly trains a single model on all scales (continual finetuning over LLaVA and LLaVA-NeXT). The method allows control of visual token length at inference, and is evaluated across a broad range of MLLM benchmarks with extensive ablations. Empirical analysis reveals that COCO-style benchmarks can use ≈9 tokens instead of 576 with similar accuracy, and a large gap exists between fixed-scale representations and the oracle upper bound.

### Strengths
- The paper tackles a meaningful and urgent problem: reducing the excessive number of visual tokens in LMMs for efficiency. The motivation is coherent, well-motivated, and easy to follow. (R1, R2, R3, R4)
- The proposed method is simple, effective, and easy to implement. Instead of tuning the LLM, it shows that tuning CLIP works, offering a practical advantage. (R1, R2, R4)
- Extensive experiments with strong results: M³ achieves performance comparable to LLaVA-1.5 and LLaVA-NeXT baselines while using significantly fewer visual tokens, across benchmarks that do not demand dense visual perception. (R1, R2, R3)
- The empirical study offers several valuable insights:
  - A substantial gap exists between naive use of all tokens and the oracle upper bound (selecting optimal tokens per instance). (R3)
  - Different vision-language tasks require different numbers of visual tokens (dense tasks like TextVQA, DocVQA need more tokens). (R3)
  - Reducing the number of visual tokens does not increase hallucination for M³. (R3)
  - Comprehensive ablation studies compare token reduction methods, showing the advantage of average pooling. (R3)
- The presentation is clear and concise. (R1, R4)
- The method provides a useful tool for analyzing the visual complexity of benchmarks by assessing granularity needed for correct answers. (R3)

### Weaknesses
- **Missing comparison with cross-attention (Flamingo-style) methods**: Flamingo-style models (e.g., [1], [2]) naturally handle variable-length visual sequences more efficiently because visual tokens do not go through the expensive MLP and quadratic-complexity self-attention in the LLM. The paper lacks discussion, theoretical comparison of computational complexity, or FLOPs analysis between the two paradigms, even at a qualitative level. (R1)
- **Missing comparison with dynamic sampling methods**: Performance drops significantly when reducing tokens, while dynamic sampling methods like Chat-UniVi can surpass their full-token baseline. M³ can be viewed as a special case of dynamic sampling, and a fair comparison is needed. (R2) *Minority note: Reviewer 2 rated contribution 2, while others gave 3, indicating a more critical view of the method's novelty relative to dynamic sampling approaches.*
- **Training cost is a concern**: All scales of all images are used during training, so training cost is several times that of single-scale training. The paper should provide a detailed breakdown of training cost, discuss scalability (especially as MLLM training data approaches billion-scale), and explore mitigation strategies (e.g., selective scale sampling, curriculum learning). (R1)
- **Inference token count is predefined, not adaptive**: The method cannot adaptively adjust the number of visual tokens per instance at inference; the user must choose a fixed granularity in advance. The word “adaptively” is misleading because it implies a dynamic inference strategy, not a user-tunable tradeoff. (R3, R4)
- **Weak video baselines and encoding**: The best baseline on EgoSchema reaches only 35.8%, whereas recent 7B-scale video LMMs achieve >60%. M³ would benefit from integration with more advanced video LMMs. Also, the video encoding method (arranging frames into a collage) is limited and should be compared with alternative approaches (e.g., LLaVA-HD, SPHINX, LLaMA-VID). (R3)
- **Oracle performance explanation is unclear**: The method for obtaining the oracle (selecting the scale with fewest tokens that answer correctly per instance) is not clearly described; it is unclear what happens if the model cannot answer correctly at any scale. (R3)
- **LMM capability ignored in visual complexity analysis**: When using M³ to analyze the visual complexity of tasks, the method does not account for whether the LMM can effectively consume additional visual information. If the model cannot use extra tokens, increasing token count may hurt performance even if the task needs more information. (R3)
- **Extensibility to arbitrary token counts**: The method currently supports only a discrete set of token numbers (e.g., 576 → 144 → …). It is unclear how to extend to any desired number of tokens for smoother switching. (R2)
- **Symbol clarification for Matryoshka property**: The statement $X_{S_i} \subset X_{S_{i+1}}$ appears self-contradictory because the average of a subset of features is not necessarily one of the original elements. A more rigorous definition of $X_{S_i}$ and the Matryoshka property is needed. (R1)
- **Minor writing issues**: In Table 13, the unit of FLOPs should be T (teraFLOPs) not TB (teraBytes). There is a repeated reference item (Zhang et al 2023a / Zhang et al 2023b). (R1)
- **Missing speed/computation cost in main paper**: Speed and computation cost comparisons should be included in the main paper, not only in the appendix. (R2)
