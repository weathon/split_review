## Merged Review

### Summary
This paper introduces PruMerge, a training-free method to reduce visual tokens in Large Multimodal Models (LMMs) by exploiting sparsity in attention scores between the class token and visual tokens. It first uses an Interquartile Range method to select outlier (important) visual tokens, then applies k-nearest neighbor clustering to merge similar unpruned tokens. PruMerge+ adds spatially uniform sampling. On LLaVA-1.5, it achieves comparable performance across six visual reasoning benchmarks while using only 5.5% of original tokens (14× compression). For Video-LLaVA, it reduces tokens from 2048 to 256 (12.5%) without performance loss. The method requires no model architecture change or fine-tuning.

### Strengths
- Addresses LMM efficiency via input compression without requiring significant fine-tuning or model architecture changes, making deployment easier.
- Achieves high visual token pruning rates (up to 94%) and reduces computational cost (FLOPs by ~10×), yielding faster inference and lower memory usage – advantageous for resource-constrained settings.
- Maintains or improves performance on six benchmarks using only 5.5% of tokens on LLaVA-1.5; also reduces Video-LLaVA tokens from 2048 to 256 while preserving or improving performance.
- Adaptive selection mechanism exploits sparse attention to retain essential information while discarding redundant tokens, offering flexibility per input image.
- One reviewer notes that PruMerge outperforms former SOTA methods on token pruning for ViTs (though other reviewers flag missing baselines; see Weaknesses).
- Writing is clear and easy to understand.

### Weaknesses
- **Limited model generalization**: Experiments are restricted to LLaVA-1.5 and Video-LLaVA. Testing on other LMM architectures (e.g., Flamingo, Qwen, LLaVA-Next with AnyRes) and visual encoders (e.g., SigLIP, CNNs, other ViTs) is needed to confirm generalizability. The sparsity assumption in the CLIP visual encoder is not validated for other encoders.
- **Missing baselines**: The paper compares only with ToMe, ATS, and EViT. It omits crucial recent token reduction methods such as Token Pruning [2403.06764], Token Summarization [2410.14072], Progressive Token Pruning [2301.13741], prompt compression methods, and especially FastV [2403.06764] and VTW [2405.05803], which reportedly maintain performance with minimal loss. One reviewer notes outperformance on ViT pruning, but these missing baselines challenge that claim.
- **Real-world efficiency not demonstrated**: Experiments are on a Tesla V100 GPU, which is not representative of deployment on resource-constrained devices. The paper would benefit from reporting memory, FLOPs, and latency on mobile hardware (e.g., Macbook, iPhone, Pixel).
- **FlashAttention incompatibility**: The method requires attention scores for outlier detection, making it incompatible with FlashAttention. Comparisons with FlashAttention-enhanced baselines (peak memory, latency) are needed to verify effectiveness in practice.
- **Risk of losing auxiliary visual information**: Aggressive token reduction (up to 94%) may discard fine-grained details needed for tasks like OCR, object detection, fine-grained classification, or image captioning. The method shows weaker performance on POPE, and has not been tested on such detail-sensitive tasks. The request-agnostic pruning likely preserves only primary content, limiting broader applicability in multi-turn dialogues where comprehensive image details are required.
- **Performance degradation despite high pruning rate**: PruMerge shows ~8% performance drop and PruMerge+ ~2% drop on some benchmarks, which is substantial compared to methods like FastV and VTW that maintain integrity. Even with fine-tuning (Table 6), degradation persists.
- **Limited memory savings for long text generation**: Visual token pruning has minimal impact on memory usage when large numbers of language tokens dominate, and the method does not excel in short-text generation speed either.
- **Ignoring LLM–visual interaction**: The method treats visual token reduction as a pre-processing step for the visual encoder, without considering the interaction between visual and text tokens in MLLM. More exploration and visualizations of how token relevance affects the multimodal encoder are needed.
- **Ambiguity about fine-tuning**: It is unclear whether results in Table 1 are from the base model or after fine-tuning (Table 6 shows fine-tuning helps). The authors should clarify this and present both scenarios to allow proper assessment of the method’s reliance on fine-tuning.
- **Missing ablation on image complexity**: The paper does not examine whether visual token redundancy holds across different image complexities (e.g., high-texture, densely populated scenes) or how the pruning adapts.
- **Missing adaptation to AnyRes**: The method’s compatibility with high-resolution strategies like AnyRes (used in LLaVA-Next) has not been demonstrated.
