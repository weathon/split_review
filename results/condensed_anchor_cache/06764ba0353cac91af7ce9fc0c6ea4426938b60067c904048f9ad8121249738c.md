## Merged Review

### Summary
This paper introduces IGL-Bench, a benchmark for imbalanced graph learning that covers 24 algorithms across 17 datasets, addressing node-level and graph-level tasks under class and topology imbalance. It provides a unified data processing pipeline, splitting strategy, and evaluation protocols. The benchmark evaluates algorithms on effectiveness, robustness, and efficiency, organized around four research questions. The analysis yields insights into the strengths and limitations of current IGL methods. The open-source codebase facilitates reproducible research and provides a standardized testbed for future development.

### Strengths
- **Originality and significance:** The benchmark fills an important gap by providing a comprehensive and standardized testbed for IGL, which is crucial for tracking progress in graph learning on imbalanced data. (R1, R3)
- **Well-structured and thorough evaluation:** The experiments are well-designed, covering multiple dimensions (effectiveness, robustness, efficiency) and including four relevant research questions. The analysis leads to interesting insights. (R1, R2, R3)
- **Clarity and accessibility:** The paper is well-written, easy to follow, and organizes a large experimental study clearly. (R1, R2, R3)
- **Reproducibility and usability:** The open-source code enables easy comparison and development of IGL methods, enhancing the community’s ability to build on this work. (R2, R3)

### Weaknesses
- **Incomplete method coverage:**  
  * A minority reviewer (score 6) noted that recent general booster-type IGL methods (e.g., topological augmentation [1] and automated loss engineering [2], both ICML '24) are not included, and suggested incorporating them for more comprehensive evaluation. (R3)  
  * Another reviewer recommended including traditional class-imbalance baselines such as reweighting or PC Softmax for node-level tasks, and reporting per-class F1 scores to better assess minority-class performance. (R2)  
- **Missing depth in analysis:**  
  * Some findings lack explanation; for example, the poor performance of most algorithms on the large-scale ogbn-arXiv dataset is reported without investigation or discussion of underlying causes. (R2)  
  * The efficiency evaluation in Section 4.4 is conducted on Cora, the smallest dataset, making runtime and memory usage heavily dependent on implementation rather than algorithmic complexity. A theoretical complexity analysis would provide a more meaningful comparison. (R2)  
- **Clarity and documentation gaps:**  
  * Certain visualizations (e.g., multi-metric plots across multiple imbalance ratios) could benefit from clearer explanations to aid interpretability for readers less familiar with the metrics. (R1)  
  * The paper does not discuss the specific challenges encountered in standardizing data splits and evaluation protocols across diverse IGL methods, nor how hyperparameter tuning is handled for methods sensitive to different imbalance types. (R1)  
  * There are no plans described for an API reference to enhance usability. (R3)  
- **Unexplained implementation issues:**  
  * On ogbn-arXiv, some resampling algorithms (GraphENS, GraphSHA) run successfully while others like GraphSMOTE encounter memory issues. It is unclear whether this stems from algorithmic complexity differences or specific implementation choices, which should be clarified. (R2)  
- **Limited novelty in datasets:** The benchmark does not introduce any new datasets. (R1)  
- **Scalability:** Future plans to study scalability on larger, more complex graphs are not addressed. (R1)
