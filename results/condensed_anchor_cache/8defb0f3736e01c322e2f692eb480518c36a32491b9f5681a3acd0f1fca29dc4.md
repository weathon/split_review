## Merged Review

### Summary
The paper proposes CodeUnlearn, a zero-shot machine unlearning method for LLMs that uses codebook features and Sparse Autoencoders (SAEs) to structure the latent space, enabling targeted removal of specific topics without retraining. Reviewers are divided: two find the approach novel and sound, one is moderately critical, one is highly negative, and one notes methodological concerns. The main issues are poor technical clarity, missing comparisons, insufficient validation on LLMs, a potentially misleading “zero-shot” and “removal” claim, and lack of ablation studies.

### Strengths
1. The studied problem (machine unlearning for LLMs) is interesting, meaningful, and highly relevant given data privacy concerns.
2. The focus on generative tasks (machine translation) rather than only discriminative classification is a positive feature.
3. The idea of integrating a codebook/vector quantization into machine unlearning is novel and sound; it provides a structured representation for targeted information removal.
4. The method is amortized: it unlearns efficiently without additional model training (no retraining), which is a computational advantage over existing approaches.
5. The experimental setup includes multiple metrics (BLEU, METEOR, BERTScore) across different topics, and results are described as decent.
6. The approach uses discrete representations, which can scale well with large models compared to retraining-based methods.

### Weaknesses
1. **LLM applicability and architecture specificity**: The paper does not specify which LLM architecture (encoder-only, decoder-only, encoder-decoder) the method is compatible with, nor which layers the bottleneck is inserted into. The method requires a special architecture and is not directly applicable to existing LLMs. One reviewer notes that the evaluation appears to be on sparse autoencoders, not actual LLMs, contradicting claims about unlearning in LLMs.
2. **Contradiction in the “unlearning” claim**: The method does not truly remove sensitive knowledge from the model; it instead learns to avoid using it (i.e., it “remembers what should be unlearned”). The abstract claims machine unlearning methods aim to remove specific information, yet the proposed approach retains that information in the system. This conceptual flaw undermines the contribution.
3. **Unclear role of Sparse Autoencoder (SAE)**: It is unclear why SAE is employed, how it works in this context, and why it would be effective. The paper lacks an explanation for this design choice.
4. **Misleading “zero-shot” claim**: The method requires (a) joint training and (b) a controlled dataset for retrieval (D_T and D_{\tilde{T}}). The term “zero-shot” is therefore misleading; the paper should clarify how this qualifies as zero-shot.
5. **Missing experiments and comparisons**:
   - No comparison with existing unlearning methods (e.g., those cited in related works), including zero-shot techniques.
   - No ablation studies to evaluate the importance of individual components (e.g., codebook, SAE, hyperparameters).
   - No parameter sensitivity study (e.g., how the choice of S and S' affects the trade-off between performance and unlearning success).
   - No systematic analysis of the learned codebook quality or interpretability.
   - No investigation of how the quality and size of the controlled dataset (D_T) affect unlearning performance.
   - No evaluation using standard benchmarks or metrics for unlearning (e.g., it is unclear if “Normalized Improvement Drop” is a standard metric).
6. **Technical flaws in method description**:
   - The relationship between Sections 3.1 and 3.3 is unclear; they appear to describe similar processes except for two additional linear layers, but how they connect is not explained.
   - The code selection uses argtopk, which is non-differentiable; the paper does not explain how training handles gradient flow.
   - The method’s sensitivity to hyperparameters S and S' is noted; with S=8, it is questionable whether this can represent complex contexts of long inputs (≥512 tokens). The variable trade-off makes practical hyperparameter selection difficult.
   - The “Security through ReLU” argument is not justified: why would a single linear layer cause information leakage, and how does ReLU mitigate it?
   - The L1 penalty is claimed to promote sparsity, but since code selection uses cosine similarity, the L1 term may only reduce code vector scales, not necessarily induce sparsity in code usage.
   - It is unclear whether a user must always prepare both D_T (topic data) and D_{\tilde{T}} (non-topic data) for unlearning; the paper does not justify the requirement.
   - The motivation for using Equation 14 (enrichment description) is not given, and no alternatives to the chi-squared test are discussed.
7. **Writing and presentation clarity**: The writing is poor, with typos, incomplete sentences, and disorganized structure. Key implementation details (e.g., how the codebook and SAE are implemented, concrete experimental settings) are missing, making reproduction impossible. The case study uses a French example without explanation, making it inaccessible to non-French readers. The placement of Section 3.2 (codebook design discussion) is criticized as belonging in Related Work rather than Methods.
8. **Risk of collateral damage**: The paper does not adequately discuss the risk of unintentionally removing semantically related information (e.g., unlearning “love” may affect performance on “like”). The evaluation metrics (BLEU, BERTScore) may not capture these subtle losses in fluency or task accuracy.
9. **Overstatement of novelty**: The paper claims to be “the first work that successfully enables unlearning specific topics with contextual relevance,” but this overlooks significant existing research in machine unlearning. One reviewer rates the contribution as minimal because of this overstatement and the lack of proper evaluation.
10. **Minor issues**: The code selection process (after the residual connection) is only mentioned in the figure caption, not in the main text. The sufficiency of a single linear layer with ReLU for encoding/decoding is questioned; more layers should be explored.
