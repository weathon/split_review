## Merged Review

### Summary
The paper proposes JsonTuning, a structure-to-structure approach that reformats instruction tuning data into JSON to improve generalization, robustness, and controllability. Experiments with LLaMA models (7B, 13B) on benchmarks including Flan and P3++ show consistent improvements over text-to-text baselines. Ablation studies highlight the importance of label space and control information. The method is simple and the experiments are comprehensive.

### Strengths
- **Originality & novelty**: The use of JSON format to reduce ambiguity and leverage LLMs’ understanding of structured data is a novel direction. Two reviewers (scoring 6) particularly emphasized the originality and simplicity of the approach.
- **Simplicity**: The method is straightforward and works well.
- **Clarity**: The paper is well-written and easy to follow (all reviewers agree).
- **Quality**: Claims are supported by citations and empirical results; comprehensive comparisons and ablation studies (e.g., label space, control information) are provided.
- **Potential**: The structured format shows promise for controllability and robustness.

### Weaknesses
- **Token overhead and inference cost**: JSON introduces many additional tokens; the extra decoding/computation cost (FLOPS, memory, processing time) is not quantified. A detailed breakdown of token usage per task and input/output length is needed. [Reviewers 2, 4]
- **Fair comparison with text baselines**: It is unclear whether gains come from the JSON format itself or from additional information (e.g., input/output types, candidate answers) that could be added to plain-text instructions. A fair baseline should incorporate the same structured information in text. [Reviewers 1, 3]
- **Generalization limitations**: Training and evaluation tasks overlap; performance on entirely unseen task types is not tested. Evaluation focuses on structured prediction; open-ended instruction following (e.g., AlpacaEval, Super-NI test set) is missing. Real-world complex scenarios (multi-turn dialogue, nuanced document extraction) may not fit a rigid JSON structure. [Reviewers 3, 4]
- **Practicality and usability**: Manually crafting JSON prompts is challenging for non‑expert users; automatic translation of user requests into JSON is not addressed. Nested JSON structures for output control may be fragile. [Reviewers 3, 4]
- **Missing analyses and comparisons**: Invalid JSON generation frequency and potential benefits of constrained decoding (Scholak et al.) are not examined. No comparison with other structured formats (XML, YAML). No experiments with code LLMs (e.g., CodeLLaMA). No study of text-tuned models used as base for JSONTuning or few-shot JSON prompts. [Reviewers 1, 2, 3]
- **Data construction details**: How training data was converted from plain text to JSON (manual vs. automatic) is not explained. [Reviewer 1]
- **Limited significance/novelty**: Two reviewers rated contribution as fair (2), noting that the data format is just one system choice and the idea has limited scope. One reviewer rated contribution as good (3), indicating disagreement. Reviewer 2 (confidence 5, absolutely certain) noted that the “format examples as JSON” idea can only be taken so far. [Reviewers 1, 2]
- **Missing references**: Relevant prior work on task definitions (Yin et al., 2023) and structured instruction-tuning datasets (Dynosaur) is not cited. [Reviewer 3]
