## Merged Review

### Summary

The paper studies learning Gaussian mixture models (GMMs) with the help of a predictor that supplies, for each sample, a list of β possible labels; the true label is in the list with probability at least 1−α. The authors propose a polynomial-time algorithm that, under certain separation assumptions, uses \(k\cdot\text{poly}(d,\log k,\varepsilon^{-1})\) samples to recover the mixture up to total variation distance \(\tilde O(\varepsilon)\), breaking exponential barriers that apply without such advice. The algorithm builds on prior robust GMM estimation techniques (Diakonikolas et al., 2020; Ivkov & Kothari).

### Strengths

- **Direction.** The general “learning‑augmented” approach is promising (R1).
- **Numerical verification.** The paper includes experiments that verify the algorithm’s efficacy (R1).
- **Key insight.** The work demonstrates how even possibly corrupted and partial label information can be used to construct a mixture close in TV distance in polynomial time, provided the dataset is large enough (R3).
- **Analytical control.** The merging criteria and the required dataset size are analytically controlled, guaranteeing the main result (R3).
- **Problem interest.** Studying mixtures of Gaussians with auxiliary information is an interesting problem, and the polynomial sample complexity is a notable achievement (R4).
- **Writing.** Some reviewers found the paper well‑written (R1, R2), though another reviewer noted clarity issues (R3).

### Weaknesses

- **Definitional ambiguity.** Definition 2.4 does not clarify whether the list labels correspond to a fixed set of means and covariances or are merely class assignments without parameter correspondence. This ambiguity affects how the advice relates to the true GMM (R1). There is also a broken sentence in Definition 2.4 (R3).  
- **Definition of \(d_{\text{param}}\).** Definition 3.1 only states when \(d_{\text{param}}\) is upper bounded, but Lemma 3.1 requires a lower bound. It should explicitly state what a lower bound means (e.g., minimum separation or eigenvalue), rather than relying on negation of the upper‑bound conditions (R1). It should also clarify that at least one condition must hold; there is a “relative‑Frobenius” typo (R3).
- **Motivation and realism.** The problem appears highly fabricated. No concrete motivation or real‑world application is given; it would be helpful to show experiments on datasets where the number of components is large enough to see a difference (R2). The example in lines 111‑123 suggests a robust algorithm might already suffice – the paper does not explain why this is not the case in general (R2).  
- **Reliance on prior work.** The proofs are not self‑contained; they require going through details of Diakonikolas et al. (2017, 2020) and Ivkov & Kothari (2022). The key adaptations to the current setting are not clearly outlined (R1). The core algorithmic component is essentially taken from these prior works, and it is unclear what fundamentally new techniques are introduced beyond using the labels to ensure conditions that already existed (R4). The paper should clearly distinguish novel contributions from existing results; theorem statements should not be theorems from other papers (R2).  
- **Missing state‑of‑art comparison.** No comparison is made with a standard multiclass classification strategy that uses the oracle labels (e.g., cross‑entropy with soft labels) – would such an approach already suffice for correct labeling, and how would it compare with the proposed algorithm? (R3)  
- **Gaussian specificity.** The algorithm heavily relies on the mixture being Gaussian; robustness to non‑Gaussian components is not obvious (R3).  
- **Pseudocode issues.**  
  - Algorithm 1, line 4: the loop indices “i,j ∈ [|ℒ|]” are ambiguous; the output (the grouped ℒ) is not clearly described (R3).  
  - Algorithm 2: ℘ is initialized and returned but never used; notation ℘ᵢ vs. Pᵢ is inconsistent (R3).  
- **Algorithm 3 parameters.**  
  - What is γ? In the pseudocode it is set to ½ and never updated; from the appendix it seems to relate to an upper bound on the oracle error rate (R3).  
  - The choice of Δ in line 3 (and the numerical prefactor in Lemma 3.9) needs intuition (R3).  
  - Step 13 calls `RobustGaussian` (Theorem B.5) – this should be mentioned and referenced in the main text (R3).  
- **TV distance vs. parameter estimation.** Theorem 1.1 is stated in TV distance, not parameter distance, yet the paper claims parameter estimation as a goal. Why not state the result directly in terms of parameter distance? Is there a known implication from small TV distance to small parameter distance? (R2)  
- **List oracle via k‑means++.** The paper suggests using k‑means++ to generate the list labels, but does not explain how such a heuristic would provide confidence signals (the list size β and the success probability 1−α) (R2).  
- **Numerical experiment details.**  
  - How were the lists of Gaussians generated in the experiment? Was the Frobenius separation criterion neglected? (R3)  
  - Are the experiments only in d=2? Is there a numerical estimate of the decay rate of \(d_{\text{TV}}\) with \(n\)? (R3)  
- **Questions requiring clarification.**  
  - How do the results change if the number of classes \(k\) is not known in advance? (R1)  
  - Why is the list‑decoding parameter written as \(1/\beta\) in Algorithm 3? (R1)  
  - What is the explicit dependence of the sample complexity on \(\beta\) and \(\alpha\)? (R1)  
  - Typo at line 474 (sentence starts with “finds”) (R3).  
- **Terminology.** The term “learning‑augmented” is somewhat a misnomer because the role of any learning algorithm that produces the predictor is incidental; “oracle‑augmented” would be more accurate (R3).
