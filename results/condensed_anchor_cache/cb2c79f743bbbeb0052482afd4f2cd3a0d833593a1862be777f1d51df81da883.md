## Merged Review

### Summary
The paper proposes TST-LLM, a framework for self-supervised tabular representation learning that uses LLMs to generate task-specific pretext tasks. It first leverages an LLM (GPT-3.5) to discover relevant features from natural language descriptions of the downstream task and data meta-information, then treats these discovered features as pseudo-labels for a pre-text training objective (e.g., supervised contrastive learning). The framework is evaluated on 22 benchmark datasets (binary/multi-class classification and regression) and reportedly outperforms baselines STUNT and LFR with win ratios of 95% and 81%.

### Strengths
- **Task-specific alignment**: Using natural language descriptions to define pretext tasks that align with downstream objectives improves relevance and performance over task-agnostic approaches (Reviewer 1).
- **Well-explained method**: The feature discovery and integration steps are described clearly and are easy to follow (Reviewer 2).
- **Superior empirical performance**: TST-LLM consistently beats STUNT and LFR across 22 diverse datasets, demonstrating effectiveness (Reviewers 2, 3, 4).
- **Interesting feature-augmentation concept**: Leveraging LLMs to extract new task-related features for self-supervised training is a creative direction (Reviewer 3).
- **End-to-end design**: The framework integrates feature discovery, selection, and multi-task learning into a cohesive solution (Reviewer 4).
- **Thorough experimental validation**: Extensive comparisons and ablation studies across multiple datasets support the results (Reviewer 4). Diverse dataset evaluation enhances robustness and generalizability claims (Reviewer 1).

### Weaknesses
- **Limited novelty**: Several reviewers found the contribution incremental. The core idea—using LLMs for feature engineering via prompts and using those features as self-supervision signals—has been explored in other fields and directly builds on existing LLM-based feature engineering methods (CAAFE, OCTree, FeatLLM) without fundamental technical advances (Reviewers 1, 2, 4). The reliance on existing techniques like supervised contrastive learning further diminishes originality (Reviewer 1). The overall methodology is straightforward, lacking deep innovation; feature selection and multi-task learning use basic methods (Reviewer 4).
- **Missing comparisons to strong baselines**: The paper does not compare against several competitive supervised learning methods (XGBoost, CatBoost, TabR, FT-Transformer, ModernNCA), general tabular learners (TabPFN, Tp-Berta, XTFormer), or existing LLM-based feature engineering techniques as direct baselines (Reviewer 2). Also missing are comparisons to prior self-supervised / pretraining methods for tables (TUTA, TabLLM, XTab, TabPFN) and standard mask-and-predict self-supervised approaches (Reviewer 3).
- **Incomplete ablation on feature engineering**: The ablation study does not properly compare against automatic feature engineering methods like OPENFE. A fairer comparison would use TST-LLM’s feature selection on the most informative features from OPENFE rather than random selection (Reviewer 2).
- **Limited applicability**: The method is designed specifically for a given downstream task, which restricts broader use (Reviewer 3). It appears most effective on datasets with clear semantic relationships that LLMs can articulate, limiting generalizability to domains where such relationships are less obvious (Reviewer 2).
- **Small-scale training**: The encoder is only a two-layer MLP and training uses relatively limited datasets compared to large-scale self-supervised approaches, which limits the method’s broader applicability and leaves scaling unclear (Reviewer 3). The reviewer asked whether the authors plan to scale up.
- **Lack of theoretical foundation**: No analysis is provided for why LLM-generated features improve performance, nor any guarantees on feature quality. The approach feels empirical and lacks theoretical justification (Reviewer 4).
- **No evaluation of other LLM backbones**: Only GPT-3.5 is used; experiments with other open-source LLMs (e.g., Llama, Mistral) are missing, raising questions about generality and robustness (Reviewer 1).
- **Unclear definition**: It is not fully clarified what it means to treat discovered features as “ground-truth labels” for pre-text tasks (Reviewer 1).
- **Implementation complexity**: The task-specific design may require more intricate setup and understanding compared to simpler, task-agnostic approaches (Reviewer 1).
