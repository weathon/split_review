## Merged Review

### Summary
The paper proposes Hierarchical Chains with Multi-Level Abstention (HCMA), a cascade of LLMs (e.g., Llama 3 8B, 70B, 405B) where each stage can abstain, delegate to the next larger model, or answer based on recalibrated P(True) token probabilities. The calibration uses Platt scaling with nonlinear feature transformations and logistic regression. The goal is to simultaneously improve efficiency and risk control (measured by accuracy and abstention rate). Results are shown on MMLU (cutting error rate of Llama3 405B by 30% at 20% abstention) and TruthfulQA (zero-shot prompting drives error to 0% at high abstention, but chain-of-thought is ineffective). The method requires only 50–100 labeled examples for calibration.

### Strengths
- The proposed HCMA method operates independently of model weights, allowing it to function within API-based LLM query setups (no training or weight access needed). (R1)
- The related work is covered in great detail, particularly on uncertainty quantification, calibration, and cascades. (R2)
- The paper tries to reduce cost by utilizing smaller LLMs for easy queries rather than always using the largest model, and delegates difficult queries to larger models or abstains if confidence is low. (R2)
- The topic of using model cascades to cut costs is of practical relevance. (R3)
- The paper uses cross-validation across 100–500 seeds, which is a positive methodological practice. (R3)

### Weaknesses
- **Unclear motivation**: The simultaneous focus on efficiency and risk control is not well justified. It is unclear why existing methods addressing either aspect separately are insufficient. (R1)
- **Lack of baselines**: No comparison against any routing / abstained prediction SOTA from the literature (e.g., cascades, selective prediction, uncertainty-based routing). This severely limits benchmarking. (R1, R2, R3)
- **Limited evaluation**: The method works only on one dataset (MMLU) and one cascade of models (Llama 3 family). Results on TruthfulQA are presented but found to be poor (chain-of-thought ineffective) and no convincing generalization is shown. (R2, R3)  
  - Evaluate on more datasets: HellaSwag, SQuAD, etc. (R2)  
  - Evaluate on other model families: Mistral, Flan-t5, Gemma, OPT (e.g., OPT 350M, 1.3B, 2.7B to test when model size differences are small). (R2)
- **Calibration method concerns**:  
  - The nonlinear feature transformation is arbitrary and called “statistically grounded” without justification. Logistic regression only minimizes a loss, it does not guarantee calibrated probabilities. (R3)  
  - Since all transformations are monotonic, the two thresholds could have been computed on the original probabilities directly. The need for recalibration is not conceptually justified. (R3)  
  - No comparison against other uncertainty quantification / calibration techniques such as semantic entropy (Kuhn et al.), P_true (Kadavath et al., 2022), or eigenvalue/eccentricity methods (Lin et al., 2024). (R2)
- **Oversold claims**: Phrases like “excellent calibration error” (remaining ECE 0.05–0.07 is far from excellent) and “only 50 or 100 labeled examples” should be removed or toned down. The 50% ECE reduction claim should be replaced with the exact range (e.g., “between 17% and 55%”). (R3)
- **Hyperparameter search**: The method requires searching over 39^5 (≈90M) hyperparameter combinations. This could be reduced, e.g., by Bayesian optimization or by excluding impossible combinations. (R3)
- **Regret analysis missing**: For a model chain (e.g., Llama 8B, 70B, 405B), given ground truth on the smallest model that could answer correctly, compute the error and the cost introduced by misrouting. The current Figure 3 only shows if the delegated model is correct, not if it is the optimal one. (R2)
- **Threshold setting in practice**: How should acceptance and rejection thresholds be set to work well on various query types in a real-world scenario? (R2)
- **Runtime vs. meta-model**: This delegation approach is more expensive at runtime than training a meta-model to route queries. When would this method be preferred? Possibly if it generalizes better out-of-domain, but no empirical evidence is given. (R2)
- **Figure / Presentation issues**:  
  - Figure 1 has odd x-axis values (0, 0.86, 0.982, 0.998, 1.0, 1.0, 1.0, 1.0) and shows only the logistic curves, not the data points. This makes it impossible to verify the interpretation that “differently sized models share a common notion of difficulty.” (R1, R3)  
  - In Figure 1, the y-axis appears to change despite a fixed x-axis value of 1.0 on the right. Clarify if it is extrapolation. (R1)  
  - Figure 3 uses $/Mtok on the x-axis, yet token cost is typically fixed per model. Explain the variability. (R1)  
  - Table 1 lacks standard deviations (though multiple seeds were used) and a comprehensive analysis of the results. (R1, R3)  
  - The paper uses reduced font size and margins, potentially breaching ICLR guidelines. (R3)  
  - Many terms are introduced without explanation or citation: “abstention rate,” “based on hidden layer embeddings, repeated sampling, and neural-network correctness predictors,” “uncertainty-based delegation,” “Platt scaling.” (R1)  
  - Proposition 1 notation is unclear: is $1_D$ a vector across decisions, each entry 1 or 0? (R3)
- **No code released** to replicate the experiments. (R3)
- **Additional questions**: How would the approach generalize when more than one family of LLMs exists (e.g., Mistral 7B, Llama 2 7B, Gemma 2B)? (R2)
