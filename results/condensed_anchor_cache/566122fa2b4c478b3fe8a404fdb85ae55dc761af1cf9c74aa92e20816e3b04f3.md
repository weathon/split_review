## Merged Review

### Summary
The paper proposes FlashSampling, a method to speed up and reduce memory for exact categorical sampling by using the Gumbel-Max trick to avoid softmax computation and a group-based partitioning for parallelization. The method is presented as a drop-in replacement for standard softmax sampling.

### Strengths
- The problem is important: efficient discrete sampling has applications in language models, video, and other domains where large softmax distributions are used.
- The method is simple, well-motivated, and presented clearly with pseudocode and PyTorch-like code.
- It is a drop-in replacement that maintains mathematical equivalence to standard sampling.
- FlashSampling avoids computing the denominator of the softmax, which saves computation and memory, especially for very large category sizes.
- Experimental results show comparable sampling quality and significant speed and memory gains as the number of categories increases.

### Weaknesses
- **Insufficient baseline comparisons.** The main baseline is a naive softmax implementation. The paper does not compare against parallelized softmax (e.g., FlashAttention-style), MCMC methods, speculative decoding, or distributed versions of softmax using the same group technique. This undermines the claim of efficacy. A discussion of the method’s limitations and how it differs from prior acceleration approaches (e.g., Qi et al. on fast Gumbel-Max for multiple samples, Sampled Softmax for large cross-entropy) is missing.
- **Limited and poorly described experiments.**  
  - The experimental setup is unclear: detailed hardware (CPUs, GPUs), how latency is measured, and how many runs were performed are not reported.  
  - The evaluation is restricted to one application (Llama 3-8B). For this application the speedup is much smaller (Fig. 4) than in the toy setting; this is not discussed.  
  - In the toy experiment (Section 4.1), the actual setup is unclear and the baseline implementation is not specified.  
  - The method’s time advantage appears minor for category sizes below 50,000, which is a typical range for large language models. The paper provides no real-world examples where the extremely large categories (e.g., 524,288) tested would occur.  
  - No statistical significance tests or multiple runs with different hardware are provided.  
  - The sampling quality evaluation (Section 4.3) is qualitative only; it lacks quantitative metrics and number of experiments.  
- **Theoretical contribution is weak.** Proposition 3.1 is a trivial restatement of the Gumbel-Max trick. Proposition 3.1.1 is not formally proven, and the derivation is largely algebraic. The paper would benefit from a more concise presentation of these results.
- **Missing quantification of softmax cost.** The paper claims softmax is a bottleneck without providing concrete data showing its overhead relative to the rest of the sampling process. In Figure 4, softmax appears to be a minor component; it is unclear whether the gains from FlashSampling are impactful in practice.
- **Writing and presentation issues.**  
  - Spelling errors (e.g., “Experitments”, “Gumble”), typos, and missing parentheses in citations.  
  - The paper is dense with algorithms and code; simplifying or consolidating the presentation would improve readability.  
  - Notation is inconsistent (e.g., \(p_k\) used differently in equations; Eq. (1) missing indices).  
  - The related works section is too broad (MCMC, differentiable sampling, variational inference) and not well-connected to this work.  
- **Unaddressed reviewer questions that overlap with criticisms:**  
  - What is the difference between “Vanilla Sampling” and “Naive Sampling” (Fig. 1 vs. Section 4.3)?  
  - How does FlashSampling perform with only the Gumbel-Max trick (without the group technique)?  
  - Why are example Llama outputs included in the main text? If the method is provably equivalent, qualitative comparison is unnecessary; if not, quantitative metrics should be provided.  
  - Can the method be compared against distributed softmax using the same group technique to avoid materializing logits?

**Note on reviewer disagreement:** One reviewer (score 1) is significantly more critical, emphasizing that the time advantage is minor for typical LLM category sizes and questioning the motivation that softmax is a bottleneck. This reviewer also found the paper’s motivation underdeveloped without quantification. The other three reviewers (scores 3) were more positive about the idea but agreed on the need for stronger experiments and baselines.
