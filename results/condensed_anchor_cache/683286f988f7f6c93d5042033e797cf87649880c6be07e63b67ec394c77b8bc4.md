## Merged Review

### Summary

The paper proposes MoRA, a parameter-efficient fine-tuning method that replaces LoRA’s low‑rank decomposition with a square update matrix, using non‑parametric compression/decompression to maintain the same number of trainable parameters while achieving higher rank. The authors evaluate on instruction tuning, mathematical reasoning, continual pretraining, and memorization tasks with Llama 2 7B.

### Strengths

- **Motivation via memorization task.** A clever controlled experiment (10 k UUID pairs, 100 epochs) shows LoRA rank 8 fails, motivating higher‑rank updates (R1, R3). This clearly highlights a limitation of low‑rank adaptation (R2, R3).

- **Rigorous benchmarking across multiple training regimes.** Evaluation includes instruction finetuning (IFT), continual pretraining, and pretraining from scratch, which is uncommon among LoRA‑style papers. The authors also note the relevance of using modern LLMs rather than BERT/GLUE (R1).

- **Ablation of compression strategies.** Table 4 compares different decompression approaches (Sharing, Decouple, Rotation), providing insight into design choices (R1).

- **Training speed and memory usage reported.** MoRA is only 1.15× slower than LoRA with the same parameter count, and memory usage is documented (Table 5). This is often missing in PEFT studies (R1).

- **Code quality.** The provided code is well‑written (R3).

- **Detailed analysis of LoRA’s limitations in knowledge‑intensive tasks** (R2, R3).

- **Conceptual novelty.** The idea of increasing rank by compressing the input dimension and decompressing the output, while keeping parameter count unchanged, is interesting (R4).

### Weaknesses

1. **Limited improvement outside continual pretraining.** MoRA shows clear gains only on memorization and continual pretraining tasks. On instruction tuning and mathematical reasoning it does not outperform baselines—and on the latter it underperforms other methods despite mathematical reasoning being memory‑intensive (R2, R3, R4). This contradicts the goal of a general‑purpose PEFT method (R4). Reviewer 1 emphasises the strong empirical results, but Reviewer 3 and 4 note that full fine‑tuning is often more practical for high‑cost continual pretraining, and MoRA cannot outperform full fine‑tuning even in that setting (Table 2).

2. **Missing baseline comparisons.** Sections 5.1 and 5.3 compare only against standard LoRA. More baselines (e.g., AdaLoRA, DyLoRA) are needed to support the claim that high‑rank updating benefits memory‑intensive tasks (R2). Related contemporaneous work (LoRA‑XS, arXiv:2405.17604; VeRA, arXiv:2310.11454) is not cited (R1).

3. **Unclear compression/decompression operations.** The choice of the specific compression and decompression functions (Eq. 8 and following) is not well justified. The method section lacks flowcharts or diagrams, making definitions of \(f_{comp}\) and \(f_{decomp}\) confusing (R3, R4).

4. **Insufficient explanation of the rotation operation.** The paper claims “rotation information can help the square matrix to distinguish the input information” but provides no technical justification. At rank 256, differences between Sharing, Decouple and Rotation are minimal, questioning the necessity of rotation at higher ranks (R4).

5. **Potential undertuning of the LoRA baseline.** In Table 1, MoRA rank 8 achieves 100% memorization while LoRA rank 8 achieves only 52%. This large gap raises the possibility that LoRA was not properly tuned (R4). Reviewer 1 notes the memorization task is a clever motivation, but does not flag this discrepancy.

6. **Sparse update matrix.** The final \(\Delta W\) obtained with MoRA contains many zero entries, which may limit its ability to update parameters essential for diverse downstream tasks (R3).

7. **Missing dataset details.** The paper does not give sample/token counts for the continual pretraining corpora (biomedicine, finance). It would be useful to compare with the regime studied in “LoRA Learns Less and Forgets Less” (R1).

8. **Unanswered questions (weakness overlap).**
   - Why does MoRA rank 8 converge on the memorization task while LoRA rank 8 does not? (R1)
   - How many total extra parameters (including frozen compression/decompression stages) does MoRA require relative to LoRA? (R1)
   - In Section 5.1, is the same learning rate used for all results in Fig. 3? (R2)
   - Why are the baselines used in Section 5.2 excluded from Sections 5.1 and 5.3? (R2)
   - For Table 5, please report the number of trainable parameters for both methods under both ranks (R4).

9. **Presentation issues.**
   - Grammar and typos: “Compare” → “Compared” (line 130); “f_comp” → “f_decomp” (line 200); “use” → “uses” (line 256); “adapt to the” → “adapt to” (line 321); “5.2.2 Baselines and Implements” → “Implementations” (line 342); missing articles and awkward phrasing throughout (R1, R2).
   - “Continual pretraining” is not defined; presumably next‑token prediction on a domain corpus (R1).
   - Hardware for Table 5 speed/memory measurements is not stated (R1).
