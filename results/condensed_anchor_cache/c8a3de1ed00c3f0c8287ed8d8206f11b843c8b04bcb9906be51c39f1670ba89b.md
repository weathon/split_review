## Merged Review

### Summary
This paper introduces CoRNStack, a large-scale, high-quality contrastive dataset for code retrieval and reranking, built from The Stack V2. The dataset uses dual consistency filtering to remove noisy positives and mines hard negatives for more effective contrastive learning. Training embedding models on CoRNStack yields state-of-the-art results across code retrieval benchmarks, and fine-tuning a reranker (using QWen 32B as a teacher) further improves ranking quality. The combined retriever+reranker pipeline also demonstrates significant gains on real-world GitHub issue localization. The paper is easy to follow, the motivation (addressing noise and inconsistencies in existing datasets) is clear, and the approach achieves strong empirical results. However, several reviewers note minor flaws in experimental exposition, missing ablations, and concerns about the novelty and coupling of dataset construction with training methods.

### Strengths
- Addresses genuine problems in existing code retrieval datasets (noisy positives, false negatives) through careful filtering and hard negative mining.
- CoRNStack is a large-scale, high-quality contrastive dataset that can benefit both retrieval and reranking research.
- Fine-tuning LLMs as code rerankers is an interesting and effective approach, largely underexplored in code.
- The work evaluates on real-world GitHub issue localization, demonstrating practical impact beyond standard benchmarks.
- The paper is clearly written with a well-articulated motivation.
- Models trained on CoRNStack achieve state-of-the-art results across multiple code retrieval benchmarks and reranking tasks.
- The authors train both a retriever and a reranker, showing consistent improvements.

### Weaknesses
- **Incremental contribution (per reviewer 4):** The filtering and negative mining techniques are largely built on prior work [1,2] (e.g., Stack V2) with only minor improvements; the overall novelty is limited.
- **Missing analysis for reranker improvement:** The paper does not explain why the reranker performance improves (likely due to hard negatives) – an analysis or ablation would clarify.
- **Undiscussed prior work on false negatives:** The paper should discuss Li et al. (2024, ACL) and other works that address false negatives during fine-tuning, not just during dataset construction.
- **Unjustified choice of Arctic-Embed-M:** The motivation for selecting Arctic-Embed-M as the initial encoder (over other models) is not explained.
- **Clarity of Section 4.2.1:** The description of the sampling strategy (window sizes 3–10, random shuffling, 250k instances) needs more elaboration.
- **Missing teacher model comparison in Table 6:** The teacher (QWen 32B) performance should be included in the reranker evaluation to show how close the student gets.
- **Missing ablation on softmax-based negative sampling:** The softmax sampling strategy for diverse negatives (Section 2.3) lacks an ablation study to validate its effectiveness over top-k sampling.
- **Insufficient dataset quality validation:** The accuracy of (text, code) pairings in CoRNStack is not manually checked or illustrated with examples; the variety of code tasks (simple vs. complex distributions) is not reported.
- **Lack of detailed comparison with original Stack V2:** Beyond quantity, the paper does not provide case studies or statistical conclusions showing how filtering changes the data distribution.
- **Coupling of dataset construction and mining method:** The writing mixes dataset filtering with hard negative mining (including curriculum learning, which is model-dependent); these two aspects should be more clearly separated.
- **Discrepant results for CodeT5+:** The reported results for CodeT5+ differ from those in the original paper; the experimental settings need clarification.
- **Missing related work section:** A dedicated related work section would help readers unfamiliar with code retrieval details.
- **Figure 1 explanation lacking:** The negative sample handling pipeline in Figure 1 is not sufficiently detailed.
- **Undiscussed alternative paradigm:** The Generation-Augmented Retrieval (GAR) framework may reduce the need for contrastively fine-tuned retrieval models; the paper should address this viewpoint.
- **Typographical error:** Line 272 contains "high-qualit,y" (missing character).
- **Minority reviewer concern:** One reviewer (score 5) found the contribution incremental and the writing less clear (presentation 2, soundness 2); other reviewers were more positive (scores 6,6,8).
