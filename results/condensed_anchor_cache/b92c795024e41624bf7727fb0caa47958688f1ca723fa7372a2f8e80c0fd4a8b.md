## Merged Review

### Summary
The paper proposes MVDream, a multi-view diffusion model for text-conditoned 3D generation. It fine-tunes a 2D image diffusion model on both 3D multiview renders (from Objaverse) and 2D images (from LAION) to produce four consistent views of an object given a text prompt. This model is then used as a 3D-aware prior for score distillation sampling (SDS), eliminating the multi-face Janus problem and enabling DreamBooth-style 3D personalization. Evaluations show high-quality generations with 78% user preference over four prior methods, comprehensive ablations, and consistent 360-degree views.

### Strengths
- Addresses the critical consistency problem (multi-face Janus, content drift) that prior 2D-lifting methods neglect. The generated objects are consistent across 360° views and avoid the Janus artifact in many shown examples.
- Among the first works to adopt a multi-view generation setting instead of generating each view separately, enabling view-consistent gradients during SDS.
- The model is designed to accept both single images (from 2D datasets) and multi-view images (from 3D data), allowing reuse of large 2D image datasets. The positive effect of mixing 2D and 3D data is ablated and confirmed.
- Demonstrates a distinctive improvement over state-of-the-art: 78% of user study participants preferred MVDream results over the combination of four other methods (DreamFusion, Magic3D, etc.).
- The trained multi-view diffusion model is a valuable community asset; the authors are encouraged to release the rendering pipeline and training code.
- The paper is well-written and easy to follow, with intuitive justification for the method (e.g., why using a 3D-aware diffusion model for SDS removes the Janus problem).
- Results are extensive with multiple metrics (CLIP score, IS, FID), ablations on attention modules and data mixtures, a user study, and DreamBooth-style 3D generation examples.

### Weaknesses
- No explicit 3D prior is learned to enforce multi-view consistency; the model only sees multi-view images during training. The mechanism for achieving consistency is not fully explained.
- Experimental presentation is poor (noted by Reviewer 3): there is no overview of experiment goals, and it is often hard to understand the point of each experiment or to distinguish between the multi-view diffusion model and the final text-to-3D model. For example, Section 4.1 versus 4.2 is confusing; results in Figure 5 appear in the same paragraph as Table 4 without clarifying which model produced them.
- The ablation on attention modules (Figure 4) is difficult to understand: missing details on baselines, implementation of “3D self-attention,” the caption, and only one qualitative example, making it hard to draw confident conclusions.
- Lack of robustness analysis: there is no evaluation of multiple generations from the same prompt to estimate the variance in quality or how consistently the Janus problem is avoided (e.g., 5%, 50%, 100% of the time). The reported results may be cherry-picked.
- The main comparison in Figure 6 is unfair because all other methods reuse standard 2D diffusion, while MVDream uses additional 3D datasets. A fair baseline would be Zero-123 + SDS. The paper should also discuss combining MVDream with other SDS variants (SJC, VDS, etc.).
- Training set details are omitted from the main paper (should be included). In Table 1, it is unclear whether the 1000 subjects are from a held-out set or a subset of the training set. The training set is used for evaluation, which is questionable.
- The need for a slow optimization-based generation process (SDS) is a limitation. It is not explored whether the multi-view diffusion model could directly generate 3D representations without SDS.
- Several algorithm details are unclear: what “re-using 2D self-attention” means (inheriting weights or same architecture?), how 4 views are sampled from 32 rendered views (uniformly?), and no training algorithm pseudocode.
- Hyperparameter choices lack justification: why 4 views instead of more? How are camera parameters embedded? Is there an ablation for different embedding strategies? Are negative prompts and CFG rescaling crucial, and how are they tuned?
- Does the method completely remove view-dependent prompting (used in DreamFusion), or is some directionality still included in the text prompt?
- Dreambooth-style results are presented without intuition for why the fine-tuning works; they appear disconnected from the core contribution.
- Optimization time is not compared; it is unclear if incorporating 3D data speeds up the SDS optimization.
- The paper does not explore rendering with large elevation angles (top, bottom) to provide more information during score distillation.
