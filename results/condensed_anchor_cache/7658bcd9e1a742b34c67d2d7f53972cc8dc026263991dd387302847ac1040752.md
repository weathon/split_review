## Merged Review

### Summary

The paper introduces CodeChain, a million-scale repository-level code dataset that uses a random walk algorithm on dependency graphs to create “code chains” (sequences of files with cross-file dependencies). It also provides Chain-Instruct, a set of five instruction-tuning tasks (e.g., dependency prediction, code completion) for supervised fine-tuning. Models fine-tuned on CodeChain/Chain-Instruct are evaluated on single-file (HumanEval) and repository-level benchmarks. Reviewers’ scores range from 1 to 6 (scores: 1, 3, 5, 5, 6), reflecting strong disagreement—one reviewer (score 1) claims the main contribution is based on a misinterpretation of prior work, while another (score 6) finds the work novel and significant. All reviewers agree the problem (capturing cross-file dependencies) is important, but raise concerns about baseline comparison, experimental rigor, dataset limitations, and presentation.

### Strengths

- **Addresses a critical, under-explored problem.** Multiple reviewers note that repository-level code understanding with cross-file dependencies is an important and practical task (R1, R2, R3, R5).
- **Large-scale dataset and pipeline.** CodeChain provides over 562k code chains and 1M+ instruction samples; the construction process is clear and includes human-in-the-loop quality control (R1, R2). R2 specifically praises the dataset as a significant contribution.
- **Random walk algorithm for dependency-aware file ordering.** The novel random walk approach outperforms prior methods (e.g., topological sorting from DeepSeek-Coder) on repository-level benchmarks (R1, R2). R2 highlights the originality of this algorithm.
- **Chain-Instruct instruction-tuning tasks.** Five designed tasks (e.g., dependency prediction, code completion) encourage models to become dependency-aware and show substantial improvements after fine-tuning (R1, R3). R3 states the instruction finetuning approach is the main strength.
- **Evaluation on both single-file and multi-file benchmarks.** The effectiveness of CodeChain/Chain-Instruct is demonstrated on several downstream tasks (R1, R5).
- **Novelty of the dataset.** Few code datasets exist at the repository level (R2). However, one reviewer (R5) considers this an incremental improvement over DeepSeek-Coder (see Weaknesses).

### Weaknesses

- **Misrepresentation of the baseline (Guo et al. 2024 – DeepSeek-Coder).** One reviewer (R3, score 1) strongly criticizes the paper for incorrectly presenting the topological sorting algorithm from DeepSeek-Coder as “sorting by in-degree,” whereas the actual algorithm decreases child degrees after adding a parent. The paper also displays “incorrect” orderings in Figure 2 (right) that are not the actual topological orders. This raises questions about the validity of the claimed main contribution (fixing file ordering). R5 also views the work as merely incremental (replacement of topological sort with random walk) and asks for a deeper analysis of why random walk is better.
- **Unfair baseline comparison.** Multiple reviewers (R1, R3, R4) note that the main comparison in Table 1/Table 7 is against DeepSeek-Coder-base (a pretrained-only model), not DeepSeek-Coder-Instruct (which underwent supervised fine-tuning). R1 calls this comparison unfair; R3 and R4 request adding the instructed version. R4 also points out that the fine-tuned 1.3B model is missing from Table 2, and R5 echoes the need for a more rigorous comparison.
- **Lack of cross-file evaluation with a more relevant benchmark.** Single-file evaluation on HumanEval does not reflect real-world repository complexity (R1). Reviewers suggest using CrossCodeEval (R1) and emphasize that the main experimental focus should be on cross-file benchmarks rather than single-file ones (R5).
- **Dataset limitations: Python only, not publicly available, file-level granularity, instruction diversity.** The dataset is limited to Python (R1, R3), not yet released (R1), and only captures file-level dependencies, missing finer granularity (e.g., function calls) (R1). R2 criticizes Chain-Instruct for having nearly duplicated instructions (same prompt templates, only code changes) and lacking diversity; they recommend using multiple templates or LLM rephrasing to increase diversity. R2 also notes the absence of evaluation for documentation tasks.
- **Missing details and insufficient ablation.** 
  - Random walk termination threshold is not specified (R4).
  - Rationale for selecting chain length 2–4 is missing; if longer chains improve performance (Section 5.5), why not use longer chains (R4)?
  - No discussion of initial node selection or probability choices for random walk jumps (R5).
  - Repository-level evaluation lacks key experimental details (e.g., use of RAG, settings) (R4).
  - The proportion of nodes/edges covered by the selected instruction chains is not reported (R4).
  - Evaluation metrics EM (Exact Match) and ES (Edit Similarity) are not defined in the main text (R2, R3).
  - Human-in-the-loop process: instructions for student annotators and consensus mechanism are not described (R3).
- **Presentation and completeness issues.**
  - No “Limitations and Future Work” section (R2).
  - It is unclear whether “CodeChain” refers to the dataset or the pipeline (R2).
  - Line 261: “this, After the GPT4 scanning” – the specific GPT-4 process is not elaborated (R2).
  - Figure 2: The case 2 green underline sequence appears incorrect (should be b→c→d→f) and colors (e.g., red background) are not distinguishable for color-blind readers (R2).
  - Spelling error: “fune-tuning” (R2).
  - Writing quality needs improvement; the introduction lacks sufficient motivation and related work (R5). R5 suggests including prior work on pre-training data construction (Ding et al., Shi et al.) and re-organizing the experimental section to emphasize cross-file benchmarks.
  - Table 2: DeepSeek-Coder-1.3B + Chain-Instruct shows no improvement over base; no intuition provided (R3).
- **Reviewer disagreement on novelty.** While R2 considers the work novel and original, R3 and R5 view it as largely overlapping with DeepSeek-Coder and only an incremental change (replacing topological sorting). This contrast should be noted—the paper’s main contribution is contested.
