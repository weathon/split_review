## Merged Review

### Summary
The paper proposes MMEvol, a multimodal instruction data evolution framework that iteratively improves data quality via fine-grained perception, cognitive reasoning, and interaction evolution, starting from the SEED-163K seed dataset. The method generates a more diverse and complex instruction set, achieving an average accuracy improvement of 3.1 percentage points over baseline models and state-of-the-art performance in nine out of thirteen vision-language tasks with less training data.

### Strengths
- The paper addresses a well-motivated problem: the scarcity and quality bottleneck of instruction data for training multimodal large language models (MLLMs). [R1, R2]
- The proposed data evolution framework is novel and effective, featuring three distinct evolution stages (fine-grained perception, cognitive reasoning, interactive evolution) and an instruction elimination stage to enhance data diversity and complexity. [R2, R3, R4, R5]
- Empirical results are promising: MMEvol achieves an average 3.1 percentage point improvement over LLaVA-Next baselines and reaches SOTA in nine tasks with less data (e.g., on MMBench, MM-Vet, POPE, etc.). [R1, R5]
- Generated instructions are more compositional, have longer reasoning chains, and are more balanced between objects, as shown by data statistics. [R5]
- The authors state that data and code will be released, which will benefit the community by setting a higher baseline for LLaVA-style models. [R1]
- The paper is well-written and easy to follow. [R3]

### Weaknesses
1. **Unfair comparison due to dataset size mismatch**: In both Table 1 and Table 2, MMEvol uses an augmented set (447K additional data) while the baseline LLaVA-Next uses only the seed set (163K). This makes the comparison unfair, as more data generally leads to better performance. To isolate the effectiveness of the evolution method, the seed set should be scaled to a comparable size. [R3] Additionally, experiments should control for architecture and dataset to fairly evaluate MMEvol’s contribution. [R4]

2. **Lack of technical clarity**:  
   - It is not explicitly stated which model or commercial API (e.g., GPT-4, GPT4o-mini) is used for instruction evolution; only the prompt templates (Figs. 4–7) are shown. [R1]  
   - Details about the “pseudo function calling” setup for visual reasoning evolution are missing: which model generates the function calls, what templates are used, and how the function calls are integrated. [R1]  
   - The MLLM used for rewriting the instructions and its corresponding prompt are not described, nor is there an ablation study showing the significance of the rewriting step. [R1]

3. **Reliability and limitations of using GPT-4/GPT4o-mini**:  
   - The entire framework relies on closed-source frontier models (GPT-4 series), which suggests a form of knowledge distillation and limits scalability, interpretability, and reproducibility. [R2]  
   - No analysis of the reliability of GPT-4 as a data rewriter is provided. [R2] The same model (GPT4o-mini) is used for both evolution and elimination; it is unclear whether it can reliably detect bad cases it generates itself. [R3]  
   - The paper does not compare different prompt templates used in each evolution stage, leaving the impact of prompt design unclear. [R2]  
   - Because the method evolves instructions over multiple rounds, there is a risk of error accumulation, which is not addressed. [R3]

4. **Insufficient evaluation and missing baselines**:  
   - The seed dataset emphasizes vision-centric capabilities including OCR, but OCR-related benchmarks (OCRBench, ChartQA, DocVQA, TextVQA) are not reported. [R1]  
   - More ablation studies are needed: ratio of the three evolution methods per round, success/failure rates for each round, elimination rate, and per-round model quality gains. [R1]  
   - In Table 2, comparisons with recent open-weight models such as InternVL2-8B (2024/07) and Qwen2-VL-7B (2024/08) are missing. [R1] Additionally, the Qwen2-7B baseline performance is not reported. [R5]  
   - MMEvol-8B shows significant performance declines on key benchmarks like MMMU, AI2D, and MMStar compared to Cambrian-1 8B. [R2] This requires explanation.

5. **Marginal performance gains**: The reported improvements are only 2–3% on average. Given that language ability can be improved by larger margins with other approaches, the actual contribution of the data evolution may be limited. [R4]

6. **No failure case analysis or saturation study**: The paper does not explore failure scenarios or provide concrete examples where MMEvol produces suboptimal results. It also lacks an analysis of how performance changes with increasing evolution rounds, which could identify saturation points. [R5] For instance, Fig. 12 shows negative scaling around step 6k–7k that is not explained. [R5]

7. **Incremental technical contribution and missing direct comparison**: The technical contribution appears incremental compared to prior works like MIMIC-IT and MM-Instruct, which also iteratively refine instructions from image metadata. The paper does not include a direct comparison with these methods (e.g., generating instructions on the same seed set using MIMIC-IT or LLaVA-Next and comparing quality, diversity, complexity). [R5]

8. **Limited data examples and robustness study**: The paper provides very few example instructions from the evolved dataset, making it hard to assess data quality. [R3] There is no study on how the quality or quantity of the seed instruction set affects the resulting instructions. [R5] It is also unclear which types of data (e.g., math, code, general visual reasoning) benefit most from the evolution. [R4]

**Minority negative contrast**: One reviewer (R2, score 5) was notably more critical, highlighting the reliance on GPT-4 as a form of knowledge distillation that reduces interpretability and scalability, the lack of prompt comparison, and the significant performance drops on MMMU, AI2D, and MMStar. These concerns are reflected in weaknesses 2, 3, and 4.
