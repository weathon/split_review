## Merged Review

### Summary
This paper introduces a text-to-graph generation task conditioned on functional requirements, posing it as text-to-text generation using a fine-tuned LLM. The approach includes: a serialization/de-serialization method that uses the edge graph to resolve node ambiguity; a modified negative log-likelihood objective (Eqn 1) that weights each graph instance equally; and interleaving message-passing (MP) layers between transformer layers with causal graph masking. Experiments are conducted on a reformulated PCQM4M molecule dataset (QED and Valency subsets) and WebNLG+ 2020. Three reviewers score the paper 5 (two with confidence 4, one with confidence 3), while one reviewer scores it 3 (confidence 4). The minority reviewer finds the task ill-defined and the technical contribution limited, while the majority see the problem as underexplored but raise concerns about the clarity of technical contributions, statistical significance of the MP component, and missing rationale for design choices.

### Strengths
- The problem of text-to-graph generation based on functional requirements is underexplored, and the paper makes a good contribution. The reformulation of PCQM4M is a helpful new resource for this task. (R1)
- The paper proposes techniques to handle ambiguous nodes (edge graph) and incorporate graph structure (interleaved message passing). (R2, R4)
- The paper clearly describes the method; diagrams (especially Figure 1) are very well done and illustrate the approach effectively. (R1)
- Experiments cover molecular generation (QED, Valency) with significant improvements compared to baselines, plus additional analysis of parsability and diversity, and generalization to WebNLG. The paper provides code and comprehensive implementation details in the appendix. (R4)
- The modified NLL loss, message-passing layer, and edge graph for node disambiguation are noted as novel contributions. (R4)

### Weaknesses
- **Task definition and evaluation soundness (minority view)**: One reviewer (R2, score 3) argues the task is ill-defined; key challenges of property-to-graph generation are not clarified. The evaluation datasets and metrics lack soundness discussion – if the benchmark can be derived from prior work with little modification, why not use the same benchmarks and metrics? Baselines are inadequately explored and results are far from convincing. (R2)
- **Clarity of technical contribution**: Multiple reviewers find the main technical contribution (interleaving message-passing with LLM fine-tuning) unclear or incremental. R3 notes that when the number of fine-tuning examples increases (400k), the model without MP achieves much better performance (half MAE on QED), raising the question: would w/ MP and w/o MP be comparable with enough data? Also, results on QED and Valency are inconsistent on the 400k examples. (R3) R4 states that message passing for molecular graphs is incremental (citing Klicpera et al.), and the modified NLL objective is an engineering trick rather than a model contribution. (R4) R2 adds that using causal masks for autoregressive generation is just a standard trick, not a key contribution. (R2)
- **Missing reasoning for the training objective (Eqn 1 vs Eqn 2)**: The paper does not explain why the denominator in Eqn 1 is formulated differently from the standard autoregressive objective in Eqn 2. This is a core component, and the absence of rationale undermines validity. (R1) Additionally, there is a presentation conflict: Page 4 says "regen only differs from SGG-LLM without message passing in that it was trained using Equation 2 instead of 1", but Page 16 says "regen is a model trained with equation 1". The true difference between the proposed method and the baseline is unclear. (R3)
- **Statistical insignificance of message passing component**: In Table 2, the MAE on QED with message passing is 0.036 ± 0.005 vs 0.044 ± 0.011 without, which is within the margin of error (improvement of 0.008). This makes the performance improvement not statistically significant. (R1, R3) R1 asks for arguments why the MP inductive bias should work and what might be wrong in the current approach. (R1)
- **Unjustified design choice for node feature vector**: The feature vector for a node is taken as the last element describing that node, without justification or exploration of alternative aggregation (e.g., mean-pooling). (R1) No ablation experiments on this are provided. (R1’s question 4)
- **Unclear choice of backbone LLM (BLOOM)**: BLOOM is not trained on molecular data, making it a suboptimal baseline. Galactica (Taylor et al., 2022), trained on SMILE strings, would be more suitable. A simple autoregressive model can outperform the proposed MP with increased training data. (R4) R1 also asks why BLOOM was selected. (R1)
- **Parsability and baseline comparisons**: Table 3 shows that baselines sometimes perform better; the paper lacks additional analysis for these cases. (R4) R1 also asks why parsability was affected when using message passing (Table 3). (R1)
- **Missing investigation of in-context learning**: For the baseline without fine-tuning (Appendix D), it is unclear how the model was prompted. No investigation using in-context learning / few-shot prompting to get parsable generation was conducted. (R1, question 1)
- **Rationale for graph masking details**: The paper does not explain why the causal graph masking includes a self node (node attending to itself) – is it for the same reason as causal masking tokens attending to themselves? (R1, question 2)
- **Presentation issues**: The paper is hard to follow (R2, R4). The paragraph on causal masking in Section 1 seems out of place (R1 suggests moving to Section 3.1). Colours used in Tables 2 and 3 are difficult to distinguish (R1). Language needs polishing (R4). The Introduction should better highlight the major contributions (R3).
