## Merged Review

### Summary

Phidias introduces a reference-augmented diffusion framework for 3D generation from text, image, or 3D conditions. The method uses a retrieved or user-provided 3D model as auxiliary guidance, generating 6 novel views via Zero123++ and reconstructing the 3D object with LGM. Key components are meta-ControlNet (dynamic conditioning strength), dynamic reference routing (coarse-to-fine resolution handling via feature pyramid to mitigate misalignment), and self-reference augmentations (self-supervised training with progressive curriculum). The retrieved 3D object’s 6 canonical coordinate maps (CCMs) guide the multi-view diffusion. The model is trained and retrieved from a database of 40K Objaverse objects. Applications include retrieval-augmented image-to-3D, text-to-3D, theme-aware 3D-to-3D, interactive generation, and 3D completion.

### Strengths

1. **Controllability and quality improvement.** The framework extends controllability of image-to-3D by using an auxiliary 3D reference to improve reconstruction quality. The meta-ControlNet combined with 3D reference models provides strong shape guidance and excellent geometric consistency (R1, R5).

2. **Dynamic reference routing.** The coarse-to-fine approach, starting with low-resolution reference CCMs at high noise levels, effectively handles discrepancies between input image and reference model (R3). This is motivated by the observation that coarse structure is established early in diffusion, finer details later (R3).

3. **Unified framework for multiple tasks.** Phidias extends to text-to-3D and 3D-to-3D generation, enabling retrieval-augmented image-to-3D, theme-aware 3D-to-3D, interactive generation with coarse guidance, and high-fidelity 3D completion—broad downstream applications (R1, R3).

4. **Clear and accessible presentation.** The paper is well-organized, clearly written, and easy to follow (R2, R4, R5).

5. **Industrial relevance.** The combination of 3D reference models and images for 3D generation has significant industrial value (e.g., gaming and asset creation) and could inform future work in 4D generation (R5).

6. **Straightforward and effective approach.** Gathering information from a 3D reference model is intuitive; the method’s simplicity and effectiveness are strengths (R2, R5). (Note: R5 acknowledges the ControlNet adaptation may lack methodological novelty but considers it an elegant solution, not a reason for rejection.)

### Weaknesses

1. **Dependence on retrieval quality and lack of failure-case analysis.** Performance heavily depends on the quality and relevance of the retrieved 3D reference (R1, R3, R4, R5). The paper does not adequately analyze behavior when retrieval is poor:
   - Training uses self-augmented ground-truth objects; but as Appendix A.4 notes, augmented views are still very similar to the ground truth (R1).
   - All showcases have very similar front views and little conflict; no examples with geometrically dissimilar or semantically inconsistent references are studied (R1, R4).
   - Fig.7 shows that a random reference can produce unreasonable results (R1).
   - The method does not explicitly handle cases where the reference is significantly different in shape/structure, which could cause artifacts (R3, R4).
   - No analysis of the feature space used for retrieval and its impact on output quality (R4).
   - Reliance on a finite database (40K from Objaverse) restricts diversity and generalization; the model may bias toward database objects (R3).
   - In extreme cases, finding an appropriate reference model is challenging, limiting applicability (R5).

2. **Unfair evaluation settings.** The paper constrains all competitor models to only front-view inputs (line 221-222). Other works that accept random or multi-view inputs (e.g., OpenLRM) would contain more geometric information, making the comparison unfair and not reflecting their true capabilities (R1).

3. **Marginal quantitative improvements.** Even in optimal settings with very similar references, the quantitative gains in Tab.1 are marginal (R1). The dynamic routing component shows limited effectiveness in Table 3, with marginal quantitative gains that raise questions about its necessity and computational expense (R2). The comparison with ground-truth reference (“Ours (GT Ref.)”) is not a fair practical evaluation (R1).

4. **Lack of user control under conflict.** When the reference and input image conflict, which side the model follows is unclear; it performs a model-decided interpolation without user-adjustable guidance strength (R1). This limits practical usefulness for designers who need to control the influence of either side (R1).

5. **Missing efficiency and speed analysis.** No evaluation of generation speed or latency (R2). Retrieving the 3D model and rendering CCMs introduces additional overhead; detailed timing breakdowns for each pipeline stage are not provided (R2, R4). R4 also asks about time/resource consumption for retrieval during inference.

6. **Limited analysis of meta-ControlNet and training details.**
   - The meta-ControlNet mechanism is not tested in challenging settings where reference topology or geometric details differ significantly from the input (R4). 
   - It is unclear whether meta-ControlNet is trained on images of multiple resolutions or only the highest resolution (R2).
   - The rationale for using a diffusion model vs. pixel-based networks or traditional CG methods is insufficiently explained; one interpretation is that the model learns a 3D texture mapping from the concept image to 6-view CCMs, and the diffusion handles conflicts (R1).
   - Important details (e.g., retrieval process, dataset specifics) are placed in supplementary material; moving them to the main paper would improve clarity (R1).

7. **Novelty concerns.** Given the restricted task and unfair evaluation settings, the novelty of meta-ControlNet and reference-based inference may solve a limited problem and provide limited contribution (R1). The combination of ControlNet with 3D references, while effective, could be seen as an incremental adaptation of an established method (R5). However, R5 does not consider this a reason for rejection.

8. **Additional specific issues.**
   - The point cloud for retrieval contains only 10K points; the reason for this limit (e.g., constraints from Uni3D) is not explained (R4).
   - Performances in Figure 14 differ noticeably from the last row of figures in Figure 4, and some cases in Figure 4 show pose mismatch with the input image (R4).
   - A citation for the canonical coordinate map (also known as NOCS map) is missing at line 186 (R3).
