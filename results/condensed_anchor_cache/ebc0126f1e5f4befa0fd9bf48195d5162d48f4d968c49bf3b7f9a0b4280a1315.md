## Merged Review

### Summary

This paper conducts a longitudinal study examining adversarial robustness—specifically misclassification, jailbreak, and hallucination—across successive versions of GPT-3.5, GPT-4, and LLaMA. It evaluates 12 model versions using established benchmarks (PromptBench, GLUE, AdvGLUE) under zero-shot and few-shot in-context learning settings with 10 types of adversarial queries generated by six surrogate models. The key finding is that LLM updates do not consistently improve robustness; GPT-3.5 v0613 shows decreased performance on some tasks, GPT-4 incrementally improves, and larger LLaMA models do not uniformly yield better robustness. The paper argues that robustness considerations should be integral to model updates.

### Strengths

- **Novel research problem.** This is the first investigation using model version as a variable for robustness comparison across 12 versions of two major LLM families (GPT-3.5, GPT-4, LLaMA). The finding that most new releases lack robustness improvements has implications for responsible AI (Reviewers 2, 3).
- **Comprehensive adversarial evaluation.** The study covers 10 malicious query settings (including zero-shot and few-shot ICL), multiple prompt components (descriptions, demonstrations, questions), diverse datasets (PromptBench, GLUE, AdvGLUE), and six surrogate models for adversarial example generation. This workload is substantial (Reviewers 1, 2, 3).
- **Thorough experimental design.** The paper is well-written and straightforward. It employs diverse evaluation metrics (e.g., Robust Test Scores, PDR) to assess benign and adversarial performance across multiple scenarios and model versions (Reviewers 1, 2, 4).
- **Impactful empirical observations.** Results show that benign performance does not significantly improve with updates (Figures 3, 4), while robustness often shows a decreasing trend. Specific declines are noted (e.g., GPT-3.5 v0613 on some tasks) (Reviewer 2, 3).

### Weaknesses

- **Limited technical innovation and scope.** The paper applies existing adversarial benchmarks with modifications but does not introduce new evaluation benchmarks or methodologies. One reviewer (score 5, confidence 4) considers this insufficient for ICLR standards and notes that the evaluations rely on commonly used datasets that may have been part of GPT training, compromising the conclusions. Another reviewer (score 8, confidence 4) suggests broadening to other thematic categories and model dimensions (e.g., exploring robustness across different LLaMA parameter sizes). (Reviewers 3, 4)
- **Missing discussion on improving adversarial robustness during upgrades.** The paper identifies robustness gaps but does not propose or discuss strategies for enhancing robustness in version updates. A reviewer explicitly asks for underlying explanations and potential mitigation strategies. (Reviewers 2, 3)
- **Need for elaboration on adversarial example generation.** The process by which surrogate models generate adversarial examples is not sufficiently detailed. (Reviewer 3)
- **Missing results and clarification requests.** 
  - Reviewer 3 asks for results or details about LLaMA-30B, which is listed in Section 4.2 but no results are presented.
  - Reviewer 1 requests more detailed description of "zero-shot ICL learning" and "few-shot ICL learning" in Figure 2.
  - Reviewer 1 asks to clarify the meaning of the "Adversarial Query" column in Table 1.
  - Reviewer 1 asks which table or figure supports the statement about SST2 and BertAttack yielding Robust Test Scores near 0 for both GPT-3.5 versions.
- **Assumptions about update objectives.** One reviewer (score 5, confidence 4) argues that expecting substantial robustness improvements from GPT-3.5 updates may be unreasonable, since the update objective (e.g., v0301 to v0613) likely targets reasoning, prompt following, or efficiency, not robustness. (Reviewer 4)
- **Future direction: new features in model evolution.** Model updates may introduce new features (e.g., internet access in recent ChatGPT). Future work should explore the correlation between such features and robustness. (Reviewer 2)
