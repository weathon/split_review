## Merged Review

### Summary
This paper aims to create a small-scale but high-quality dataset for efficient CLIP model training by leveraging knowledge graphs (WordNet, Wikidata) and LLMs to generate queries (entity, entity-attribute, type-attribute) and then collect images via search engines (Google, Bing). The resulting dataset, LivingThings, contains 8.9M images and 12.2M texts focused solely on animals and plants. A CLIP ViT-Base model trained from scratch on this dataset (using only 8 RTX 2080 Ti GPUs, ~30 hours per training round) achieves comparable or better performance than large-scale trained CLIP variants on the target domain (e.g., iNaturalist21), but not on broader benchmarks. The paper is well-organized and the overall motivation is clear.

### Strengths
1. **Motivation**: Investigates whether a high-quality small-scale dataset can achieve comparable performance to CLIP models trained on much larger data, with a focus on resource efficiency.
2. **Dataset construction via knowledge graphs**: Leveraging Wikidata and WordNet ensures wide category coverage within the chosen domain, and the query creation + search pipeline is a principled method for building a focused high-quality dataset (Reviewers 1, 2, 3). The dataset is a contribution that could benefit the community.
3. **Efficiency**: Training is resource-friendly—only 8 RTX 2080 Ti GPUs and ~30 hours per round—demonstrating practical feasibility.
4. **Effective results on target domain**: The ViT-B-32 model trained on LivingThings improves over much larger state-of-the-art CLIP models on iNaturalist21 object classification, and performs well on attribute classification tasks (CUB, OVAD). (Minority: Reviewer 2 is more positive about these results, noting “comparable or better performance over large-scale trained CLIP variants.”)
5. **Presentation**: Well-written, easy to follow, with clear motivation and flow (Reviewers 2, 3).

### Weaknesses
1. **No comparison with similar domain-specific baseline (TreeOfLife)**: The proposed LivingThings dataset is similar in size (~10M) and domain (biological) to TreeOfLife. Without a direct comparison to a model trained on TreeOfLife, it is difficult to isolate the benefit of the knowledge graph–guided dataset construction. This is a critical missing baseline. (Reviewer 3, strong concern)
2. **Limited domain coverage and scalability concerns**: The method is demonstrated only for animals and plants (two manually defined root entities). Extending to other domains (e.g., urban, molecular) would require manual definition of new root entities, limiting generalizability. It is unclear whether the knowledge graph provides sufficient entity diversity or effective natural types for other domains. (Reviewers 1, 2, 3)
   - Reviewer 1 specifically questions how the pipeline can be scaled to billion-scale datasets (e.g., DataComp, LAION) without simply replicating their size, and whether the approach would still prove better than those baselines.
   - Reviewer 2 asks how many images would be needed to match standard CLIP performance if extended to unlimited domains.
3. **Model size scalability unverified**: Only ViT-Base is tested; it is unknown whether the LivingThings dataset can support training larger models (e.g., ViT-Large) that are common in state-of-the-art CLIP. (Reviewer 2)
4. **Lack of detailed ablations and scaling analysis**: The paper lacks experiments on the effect of attribute number, number of entities, scaling laws, and model performance with much smaller subsets (e.g., 100K, 1M images). More thorough ablation studies are expected to justify dataset design choices. (Reviewers 1, 2)
5. **Loose quality control in data collection**: The alignment between image and text from search engines is not rigorously ensured. Reviewer 1 suggests using a CLIP filter to remove unaligned image-text pairs. The combination of results from Google and Bing is unclear, potentially introducing noise or unaligned images (Reviewer 3).
6. **Underutilization of knowledge graph**: Entities and types are extracted from the knowledge graph, but attributes are generated by LLMs rather than extracted from the graph’s structural information. Reviewer 3 questions whether using the knowledge graph’s own relational data (e.g., attributes of entities) would be more natural and potentially more effective.
7. **Performance remains below general SOTA CLIP**: The model trained on LivingThings cannot match the performance of state-of-the-art CLIP models on broader benchmarks (e.g., ImageNet full). Reviewer 1 questions what the paper offers to improve SOTA CLIP models, beyond domain-specific gains.
