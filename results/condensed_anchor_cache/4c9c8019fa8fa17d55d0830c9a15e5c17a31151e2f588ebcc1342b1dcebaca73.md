## Merged Review

### Summary
This paper introduces PvNeXt, an efficient point cloud video recognition framework that replaces iterative dense inter-frame queries with a personalized one-shot query mechanism. Two modules are proposed: the Motion Imitator, which generates virtual motion for each frame by implicitly learning adjacent-frame correlations, and the Single-Step Motion Encoder, which performs a single query from points to these virtual frames. Experiments on MSR-Action3D and NTU-RGBD show high inference speedup (23× over PST-Transformer) and low parameter count (0.72M), but with accuracy trade-offs compared to other modalities (pose, RGB, depth) and not always surpassing the PST-Transformer baseline (e.g., on NTU-RGBD with background clutter).

### Strengths
- **Efficiency through one-shot query design**: PvNeXt eliminates looping over all frames and dense patch overlaps, achieving 23× inference speedup and 98% parameter reduction (0.72M parameters) compared to PST-Transformer, which uses over 60× more parameters [R1, R2, R3].
- **Innovative modules**: The Motion Imitator and Single-Step Motion Encoder jointly capture temporal dynamics while drastically reducing computational overhead [R1, R2].
- **Rethinking core challenges**: The paper identifies two main computational overhead sources – traversing all frames and overlapping local patches – and proposes reducing the temporal receptive field, an interesting departure from prior work that focused only on spatial receptive field reduction [R2].
- **Good experimental results on efficiency**: The method achieves state-of-the-art in FLOPs and parameter count, supported by comprehensive ablation studies [R3].
- **Inspiration for new 4D tasks**: The finding that a single inter‑frame query can suffice highlights the need for additional 4D benchmarks beyond classification (e.g., segmentation, prediction) [R2].

### Weaknesses
- **Lower accuracy compared to other modalities**: PvNeXt shows lower recognition accuracy than pose-, RGB-, and depth-based methods on the same benchmarks, raising doubts about the practical significance of point‑cloud‑only video recognition [R1].
- **Limited validation scope**: The method is evaluated only on human action recognition (MSR-Action3D, NTU-RGBD). It is not validated on other tasks such as object recognition, scene understanding, or point-cloud video action segmentation (e.g., HOI4D action segmentation). One reviewer questions whether it can handle dense frame‑wise prediction tasks [R1, R2, R3]. Another notes the conclusion lacks discussion of application scenarios, especially given the lightweight nature [R3].
- **Potential difficulty with fine-grained or fast motion**: The one-shot query mechanism may struggle to capture very subtle or high-speed motions across frames, impacting precision for small movements [R1]. A question is raised about effectiveness on longer time‑series data or very fast motion [R3].
- **Motion Imitator learning concerns**: The motion imitator implicitly performs point tracking. One reviewer (score 8) notes this correlation is easy to learn on the human body but becomes significantly harder when backgrounds, occlusion, or interactive objects are present. The NTU-RGBD results (which include background scene) are not better than PST-Transformer, possibly confirming this limitation [R2]. The reviewer suggests evaluating the motion imitator by computing the distance between predicted and ground‑truth point clouds to judge its learning quality [R2].
- **Missing recent comparisons and efficiency metrics in Table 10**: Reviewer 1 requests that Table 10 be updated to include more recent methods and to report FLOPs and parameter counts alongside accuracy [R1].
