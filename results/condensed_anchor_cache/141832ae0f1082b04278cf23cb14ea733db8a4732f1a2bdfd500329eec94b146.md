## Merged Review

### Summary
This paper introduces DoraemonGPT, an LLM-driven system for video question-answering. It first converts video into a symbolic spatial-temporal memory (Space-Dominant and Time-Dominant components) using off-the-shelf models (BLIP, YOLOv8, PaddleOCR, etc.) and stores task-relevant attributes in a table that LLMs can query via symbolic language. A set of sub-task tools (each with task-specific prompts and examples) performs spatial-temporal reasoning. External knowledge sources (search engines, textbooks, databases) are incorporated via plug-and-play tools. An LLM-driven planner based on Monte Carlo Tree Search (MCTS) explores the large planning space for scheduling tools, iteratively finding feasible solutions by backpropagating answer rewards. Evaluation on the NExT-QA dataset (a subset) shows advantages over baselines like ViperGPT and VideoChat, achieving around 50% accuracy. Three reviewers rated the paper positively (scores 8, 8, 6), while one reviewer (score 5) strongly criticized overclaim and insufficient related work.

### Strengths
- Novel combination of a symbolic memory database with an MCTS planner using LLMs for video tasks (R1, R4).
- Clear presentation with detailed information about prompts, experiments, and analysis results; easy to follow methods and experiments (R1, R3, R4).
- Impressive results on the challenging NExT-QA dataset, outperforming strong baselines including ViperGPT and VideoChat (R2, R3, R4).
- Important topic: augmenting LLMs with tools and smarter planning for multimodal domains; likely to drive broad interest across multimodal learning and LLM communities (R2).
- Technically sound: building a symbolic knowledge base first and then invoking an LLM-based system to query it is sensible for complicated multimodal data like videos; decomposing queries into sub-questions is a promising approach beyond canonical LLM tool-use (R2).
- Novel idea to use MCTS to explore the large planning space for scheduling various tools (R3).

### Weaknesses
- **Overclaim**: With ~50% accuracy on only one dataset, claiming “Toward Solving Real-world Tasks” is an overclaim; the performance is far from demonstrating a general solution to real-world tasks. The claim should be more carefully contextualized to reflect the actual scope—primarily a specific type of video understanding task (R3, supported by R4’s concern on small evaluation).
- **Insufficient related work and unclear motivation**: The authors state “current LLM-driven agents mainly focus on solving tasks for the image modality” as motivation for studying dynamic video tasks, but this ignores the large number of LLM-driven agents not related to image/video at all (e.g., [1,2,3,4] by R3; missing references [3-5] by R2). The motivation for focusing solely on dynamic video tasks is not well justified given the broader landscape of LLM agents (R3). 
- **Limited evaluation and small dataset**: Only one dataset (NExT-QA) is used, raising concerns about generality and robustness. The evaluation set is a subset of the original NExT-QA; the ablation study uses only 3 question types with 10 questions each (R4). Additional datasets should be considered (R2 suggests [1-2]; R3 notes lack of evaluation on other video understanding datasets). This limits the generalizability of findings (R2, R3, R4).
- **Missing fair comparison and cost analysis**: All baselines in Table 2 are “straight-through” (end-to-end or simple sub-query) without the separate symbolic database building stage. A fair comparison should take the time cost of building that database into account. No details are given on how long it takes to build a symbolic database on average or how this compares to overall inference time of baselines (R2). The small evaluation is partly attributed to budget limit, suggesting the method is expensive; token consumption and average cost per question should be reported (R4). Average inference time per answer is important for users (R4).
- **Dependence on external models unclear**: The system relies on many off-the-shelf models (BLIP, YOLOv8, PaddleOCR, and others). It is not clear how shortcomings of these models affect DoraemonGPT (R1). Additionally, a reviewer asks: can’t a model like BLIP with a query-based frame selection (taking the query and features from BLIP) figure out which frames are relevant, eliminating the need for TSM? The necessity of TSM is not sufficiently justified (R1).
- **Can the method work without a pre-built database?** Some queries might be answerable by directly invoking a tool like VideoQA, without needing the symbolic database; this alternative is not discussed (R2).
- **Comparable approach achieves higher accuracy**: Works by Yu et al. achieved better zero-shot performance on NExT-QA than DoraemonGPT, which is not acknowledged or addressed in the paper (R1).
