## Merged Review

### Summary
The paper proposes a plan-based prompting approach for zero-shot literature review generation, where an LLM first generates a review plan and then uses it to produce the actual text. The authors create a new test corpus, MXS-2308, from recent arXiv papers to avoid test-set contamination. They benchmark multiple extractive, abstractive fine-tuned, and zero-shot LLMs (including open-source, code LLMs, and GPT-*) on Multi-XScience and MXS-2308, using both automatic (ROUGE, GPT-4 judgment) and human evaluation. The plan-based method generally outperforms vanilla zero-shot generation. Reviewers disagree: one rates the paper 1 (very negative) citing limited novelty and poor evaluation; another rates it 5 (very positive) citing a comprehensive investigation; three rate it 3.

### Strengths
- **Problem importance**: The task of literature review generation is useful for real-world applications (Reviewer 5).
- **Plan-based prompting approach**: Proposes an intermediate planning step for literature review generation, conditioning on the query paper abstract and reference abstracts (Reviewers 1, 2, 4). Reviewers 2 and 4 note it improves zero-shot performance.
- **New dataset (MXS-2308)**: Constructed to avoid overlap with pretraining data; promised to be released, benefiting the community (Reviewers 2, 3, 4).
- **Comprehensive investigation**: Benchmarks many models – extractive baselines, abstractive fine-tuned models, open-source LLMs (LLaMA-2, CodeLLaMA, StarCoder, Lemur-70B), GPT-3.5, GPT-4 – under different settings (longer context, fine-tuned LLaMA-2). Evaluates coverage, uses both automatic and human evaluation, and includes GPT-4-based assessment (Reviewers 2, 3, 4).
- **Auxiliary materials**: Prompts, generation examples, and evaluation results are provided in the Appendix (Reviewer 2).
- **Clarity**: The paper is well organized and easy to follow (Reviewer 1; note: Reviewer 5 strongly disagrees on presentation).

### Weaknesses
- **Limited novelty of plan-based generation**: Separating content planning from surface realization is well-known in text generation (Reviewer 1). The plan intermediate step has been published prior (Wang et al., ACL 2023, Plan-and-Solve) and others (Skeleton-of-Thought, Self-planning Code Generation, etc.) (Reviewers 2, 5). The technical contributions beyond prompting are minimal (Reviewer 1).
- **Heavy reliance on human-designed plans**: The most effective method (plan-based) requires manually designing a plan based on the ground truth summary in advance, which is unrealistic for real-world scenarios. The learned plan underperforms, indicating poor generalization without oracle information (Reviewer 4). In some experiments, plans even require human writing (Reviewer 5).
- **Problem formulation**: The generation pipeline lacks literature retrieval, ranking, and weighting – critical aspects of literature review creation (Reviewer 1). It is unclear how to handle numerous references, multiple citations in one sentence, and papers not discussed in detail (Reviewer 3, question).
- **Missing dataset details**: Statistics of MXS-2308 (size, average reference length, average number of cited papers, average review length, train/validation/test split) are not reported (Reviewers 2, 3, 4). No example from the dataset is shown for case study (Reviewer 3).
- **Potential ground-truth leakage in plan generation**: The plan is derived from the ground-truth text using a rule-based approach, which could leak information about the target organization and inflate ROUGE scores. The method for deciding plan parameters (number of sentences, word count, exact citation placement) is not explained (Reviewers 3, 4).
- **Insufficient evaluation design**:
  - **Automated metrics**: ROUGE does not measure factual accuracy or hallucinations (Reviewer 1). Additional faithfulness metrics are needed (Reviewer 3).
  - **Hallucination claims**: The paper claims plan-based reduces hallucination but provides no quantitative or qualitative evidence (Reviewer 3).
  - **Human evaluation**: Details are missing – number of annotators, inter-annotator agreement, annotator profiles, compensation, working hours, and procedure (Reviewers 2, 4). The computation of metrics (Avg Rating, Avg Win Rate, Coverage in Table 8) is not defined (Reviewer 4).
  - **Error analysis**: Qualitative error analysis per error type across baselines is absent (Reviewer 2).
- **Experimental presentation and reproducibility issues**:
  - Section 2 is confusing: how models are prompted to generate plans is unclear; some methods appear to require training despite being described as zero-shot (Reviewer 5).
  - Results in Table 2 only show partial methods (4 for Turbo, 1 for GPT-4; “GPT-4 (Plan)” is ambiguous) (Reviewer 5).
  - Generation configuration (greedy decoding vs. sampling, temperature) is not reported for LLMs (Reviewer 4).
  - No code is provided for reproduction (Reviewer 2).
- **Narrow conclusions**: The conclusions do not extend to broader implications (Reviewer 1). The dataset may quickly become outdated due to rapid LLM evolution (Reviewer 1).
- **Questions / missing ablations**:
  - How to ensure the plan prompts cover all related concepts hierarchically? (Reviewer 1)
  - Why does the method sometimes fail to generate some paragraphs? Is it due to LLM limitations, source complexity, or plan generation? (Reviewer 1)
  - Why is learned plan only implemented for GPT-3.5? (Reviewer 2)
- **Typos**: “were” → “were” should be “where”; “related works” → “related work” (Reviewer 1).
