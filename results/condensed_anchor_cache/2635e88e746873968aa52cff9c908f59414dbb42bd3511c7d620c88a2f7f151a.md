## Merged Review

### Summary
The paper presents OWL, a large language model for IT operations, along with the OWL-Instruct dataset (built from seed samples by domain experts and enriched via GPT-4 self-instruct) and an evaluation benchmark Owl-Bench (balanced across IT topics). The authors propose a mixture-of-adapter (MoA) strategy for parameter-efficient tuning and HMCE (inspired by NBCE) for context length extension. OWL is fine-tuned from LLaMA2 and outperforms existing LLMs (including ChatGPT) on IT tasks.

### Strengths
1. **Dataset and Benchmark Construction** – Provides a detailed, reproducible process for building domain-specific instruction data (OWL-Instruct) and a balanced evaluation benchmark (Owl-Bench) covering diverse IT operations topics. (Reviewers 1,3,4)
2. **Holistic Evaluation** – OWL achieves superior performance over existing SOTAs in all IT tasks tested. (Reviewers 1,4)
3. **Multiple Orthogonal Contributions** – The paper introduces several techniques (OWL-Instruct, HMCE, MoA, domain‑specific token expansion), each of which could be significant if properly evaluated. (Reviewer 2)
   * **MoA** is seen as a significant contribution for task‑specific adaptation. (Reviewer 2)
   * **HMCE** is considered a novel (to the reviewer’s knowledge) training‑free context extension method. (Reviewer 2)
   * **Token expansion** (adding IT‑domain tokens) enhances the model’s value. (Reviewer 2)
4. **Practically Relevant Process** – The complete pipeline from dataset creation to model training is useful for researchers building other domain‑specific LLMs. (Reviewer 1)

### Weaknesses
1. **Limited Novelty** – The core techniques are mainly slight variations of existing approaches (e.g., LoRA, self‑instruct, NBCE), with only incremental contributions. (Reviewers 1,3,4)  A minority view (Reviewer 2) considers MoA and HMCE significant, but this is not shared by the other reviewers.
2. **Lack of Thorough Ablations for Each Contribution** – The paper contains many orthogonal ideas (HMCE, MoA, token expansion, dataset creation) but does not evaluate each idea independently from the empirical setting of OWL and IT operations. (Reviewer 2)
3. **Evaluation Rigor Concerns**
   * *GPT‑4 scoring for Q&A tasks* – GPT‑4 is used both to generate the instruction data and to assess model performance, creating a potential bias favoring OWL. Human evaluation is preferred but absent. (Reviewers 1,3)  Reviewer 3 specifically asks if GPT‑4’s scores correlate with human judgments.
   * *Possible data leakage* – It is unclear whether any part of the constructed training dataset overlaps with the Owl‑Bench evaluation set; if so, results would not be convincing. (Reviewer 4)
   * *Unfair baseline comparison* – In Figure 3, baseline models likely do not benefit from MoA (or LoRA) adaptation, while OWL does, making the comparison unfair. (Reviewer 2)  Clarification requested: did OWL use MoA in Figure 3, and if so, why were baselines not given the same adapters? (Reviewer 2)
4. **HMCE Integration and Description** – HMCE is evaluated only on a separate long‑context testbed and does not clearly relate to the OWL model or its dataset. (Reviewer 2)  Moreover, the description is unclear; the paper cites only the unpublished NBCE rather than the many well‑known long‑context techniques, leaving the advantages of HMCE ambiguous. (Reviewer 4)
5. **Missing Coverage of IT Operations Challenges** – The paper focuses on model development but does not discuss specific IT‑domain challenges (e.g., log detection) or how OWL addresses tasks that traditional models cannot handle. (Reviewer 3)  For downstream tasks, OWL shows only a small advantage over LogPrompt (based on ChatGPT); it is unclear whether a domain‑specific model provides better consistency or robustness than open‑domain models like ChatGPT or GPT‑4. (Reviewer 3)  This also ties to a request to show what specific traditional‑model limitations OWL overcomes. (Reviewer 3)
6. **Token Expansion Training Details** – When the embedding matrix is expanded for new IT‑domain tokens, it is not stated whether any LLaMA layers are retrained or how the heads encoding the embedding space are updated. (Reviewer 2)
7. **Content Organization** – Related work is placed in the appendix, and the main text omits relevant background on IT operations tasks. (Reviewer 3)
8. **Typos** – Page 8: “We have propose HMCE…” (should be “proposed”); “Without NMCE” (should be “Without HMCE”). Also a questionable wording: “…where a group of LoRA adapters is lightweight compared to the pre-trained model.” (Reviewer 2)
