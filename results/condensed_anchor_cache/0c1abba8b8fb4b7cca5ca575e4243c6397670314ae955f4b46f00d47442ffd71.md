## Merged Review

### Summary
AndroidWorld is a dynamic, parameterized benchmark for autonomous agents on Android, comprising 116 tasks across 20 apps with automated initialization, success checking, and teardown for reproducibility. The best agent (M3A) achieves only 30.6% success, human performance is higher, and a robustness analysis shows task variations significantly affect results. Two reviewers rated the paper 8, highlighting its foundational contribution and generalization challenge; two rated 6, questioning practicality due to low success rate, limited app coverage, and missing details. The benchmark fills a gap for interactive evaluation but faces concerns about real-world representativeness and experimental completeness.

### Strengths
- Dynamic task construction with extensive parameterization introduces realistic variability and tests generalization across instructions (R1, R2, R4).
- Comprehensive related work and comparisons to existing benchmarks provide clear context (R2, R3).
- Robust baseline evaluation and thorough experiments, including human performance and error analysis (R1, R3, R4).
- Clear writing and good presentation (R3, R4).
- Lightweight environment compatible with task random parameterization (R4).
- Detailed examples and error analysis in the appendix (R4).
- Initialization and teardown logic ensure reliability and reproducibility (R4).
- Foundational contribution advancing understanding of mobile device control for LLM agents (R2).
- Parameterized tasks effectively assess agent generalizability across varying instructions (R2).
- Interesting robustness analysis provides new information on performance variability (R3).
- Incorporation of MiniWoB++ tasks offers additional evaluation angles (R2, though rationale questioned).

### Weaknesses
- Low overall success rate (30.6%) raises questions about the benchmark’s practicality and whether the gap to human performance is too large to bridge with current methods (R1).
- Lack of granular analysis on how specific task parameters (e.g., number of steps, UI complexity, app) affect agent performance; only aggregate results are reported (R1).
- High latency of large foundation models (agents take significantly longer than humans) is not addressed with optimizations or alternative architectures (R1).
- Action space explanation is insufficient: purpose of STATUS action is unclear, and differentiation between SWIPE and SCROLL is not justified despite similar descriptions (R2).
- Limited details on the high-level APIs mentioned in Appendix B, making it hard to assess the scope and limitations of actions (R2).
- Rationale behind task categorization tags is not elaborated, weakening understanding of coverage of mobile interaction scenarios (R2).
- Need for more baseline comparisons: missing a basic agent without prompting (R2) and open-source models for reproducibility and iteration (R3).
- Benchmark lacks many real-world apps (e.g., YouTube, Twitter) because reproducibility constraints force use of open-source apps, creating an inherent sim-to-real gap (R3).
- Fixed device and OS (Pixel 6, Android 13) limits diversity; real-world use requires performance across different devices and OS versions (R3).
- Experimental setup is unclear: no explicit stop criteria (step/time limits per task), decoding temperature, or explanation of how human performance was measured (R4).
- Need for results from more models, including recent APIs (e.g., Claude) and additional ablations such as Reflexion (R2, R4).
- Reproducibility concerns: it is unclear if all tasks and apps are offline (e.g., does SendSms send actual messages?); real-world time and date could affect calendar/timer tasks (R4).
- Missing discussion of related work: AgentStudio and Ferret-UI are not cited (R4).
- Missing comparison to B-MoCA regarding task diversity, randomization, and reproducibility; unique advantages of AndroidWorld over B-MoCA are not clearly stated (R1).
- Full list of tasks with initialization logic and success evaluation code is not provided (R1).
- No explicit training/test split or guideline for task category configuration (R2).
- Not confirmed whether results in Table 3 are averaged across multiple random seeds, despite mention that multiple seeds provide fair representation (R2).
- Method for calculating confidence intervals in Figure 3 is not explained (R3).
- The integration of MiniWoB++ into a mobile environment seems auxiliary; rationale for its inclusion and challenges versus standard AndroidWorld tasks is not justified (R2).
- Extensibility to different action spaces (e.g., multi-finger actions) is not discussed (R2).
- Potential for agent actions outside the defined teardown process to alter system state and affect reproducibility is not considered (R4).
