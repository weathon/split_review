## Merged Review

### Summary
The paper proposes MotionFlow, a camera-controllable image-to-video (I2V) model that integrates camera and object motions into pixel motion. It uses a Reference Motion Network to learn motion maps from a reference image and camera trajectory, and a Semantic Encoder for image conditioning, built on AnimateDiff. Evaluated on RealEstate10K and DL3DV-10ks, it claims to outperform SOTA methods like CameraCtrl and MotionCtrl. Reviewers divided: two (scores 5) see the approach as novel and effective; two (scores 3) criticize writing clarity, missing details, and overstatement of contributions.

### Strengths
- Novel feature extraction and injection via a Reference Motion Network that progressively interacts with camera motions and image semantic features, achieving more effective camera control than simple fusion of camera trajectory with latent space (Reviewers 1, 2, 3, 4; especially Reviewer 2 highlights “progressively and synchronously interacts” vs. “simple fusion”).
- Quantitative and qualitative experiments demonstrate significant improvement over SOTA methods (CameraCtrl, MotionCtrl) on RealEstate10K and DL3DV-10ks; results show precise motion control (all reviewers agree on effectiveness; Reviewers 2 and 4 emphasize the improvement margin).
- Clear description of modifications over existing frameworks (AnimateDiff, Stable Diffusion) and the role of each component (Reviewer 4).
- Addresses a gap in video generation requiring complex camera trajectory control alongside object motion, with potential applications in 3D reconstruction, film production, VR, AR (Reviewer 4).

### Weaknesses
- **Informal writing and missing details**: Title includes “Conference submissions”; missing references at lines 135 and 315; undefined “motion extractor” at line 316; redundant experimental setting sections 3.6 and 4 (Reviewers 1, 3).
- **Incomplete architectural specification**: Need concrete details of trajectory encoder (layers, types, activation functions) and reference motion network UNet (down/up blocks, channel dimensions, skip connections). Clarify whether reference motion map is computed once at start or recomputed per denoising step, and how the network handles changing noise levels. Provide mathematical formulation for denoising process and Object Attention. Expand Figure 2 with separate diagram for Trajectory Encoder and Semantic Encoder integration (Reviewers 2, 4).
- **Overclaiming on object motion extraction**: Abstract and text (e.g., line 80, line 243) claim extracting object motion priors from existing videos to maintain consistent object motions, but method only uses the reference image as a condition (turning T2V into I2V); no actual motion prior extraction. Figures 1 and 3 mostly show camera movement around static objects, not moving objects (Reviewers 1, 3).
- **Missing visualizations of stated limitations**: Introduction (lines 73–78) criticizes MotionCtrl for object‑scene confusion and CameraCtrl for limited generalizability, but paper provides no concrete failure examples of these baselines to support the argument (Reviewer 2).
- **Incomplete experimental reporting**: Tables 1–3 should specify number of videos used for evaluation and criteria for classifying trajectories as basic vs. difficult. Table 1 results differ from original CameraCtrl paper; aligned comparison needed (Reviewer 3).
- **Design choices require explanation**: Why use AnimateDiff instead of an existing I2V model (e.g., SVD)? Why add semantic features to input noise rather than concatenating the reference image latent code with noise (as in SVD)? Explain how semantic information from the encoder addresses moving foreground and stationary background (Reviewers 1, 3).
- **Additional qualitative comparisons needed**: Include more challenging scenarios (multiple moving objects, varying lighting) and a “Limitations” subsection discussing failure cases (Reviewer 4).
- **Metrics lacking explanation**: Add brief discussion of why Rotation Error and Translation Error matter for real‑world camera control applications (Reviewer 4).
- **Introduction framing**: Could more compellingly frame the significance for interactive media and virtual environments (Reviewer 4).
- **Baseline result anomalies**: Figure 4 shows notable distortion in MotionCtrl and temporal inconsistencies in CameraCtrl that deviate from expected behavior based on SVD’s strong frame consistency; authors should clarify these discrepancies (Reviewer 1).
