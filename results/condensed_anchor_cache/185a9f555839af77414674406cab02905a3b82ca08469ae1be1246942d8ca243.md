## Merged Review

### Summary

The paper proposes SetCSE, a framework that uses set operations (intersection, difference, series) on sentence embeddings for complex information retrieval. It fine-tunes sentence embedding models with an inter-set contrastive learning objective. Experiments use baselines including TF-IDF, BERT, RoBERTa, Contriever, SimCSE, DiffCSE, MCSE, SGPT on AG News, Financial PhraseBank, Banking77, MTOD. Applications include semantic search, data annotation, topic discovery on ESG stance analysis.

### Strengths

- Provides a well-defined, practical framework enabling complex information retrieval tasks not possible with existing search methods (R1, R2, R3, R4).  
- Formulates sentence retrieval as a combination of sentence-set similarity and set operations, which is novel for the community (R3).  
- Applies contrastive learning to sentence embeddings in a unique way, emphasizing contextual differentiation between sets of sentences (R1).  
- The idea is clever, simple, and straightforward (R2).  
- Comprehensive experiments with new settings (set intersection and set differences), multiple baselines, sentence embedding visualizations, detailed hyperparameters, and quantitative justification (R3).  
- Compelling real-world applications (e.g., ESG stance analysis from earnings calls), each paired with background papers and results (R1, R3, R4).  
- Feasibility demonstrated in artificial settings across several sentence embeddings (R4).  

### Weaknesses

- Missing error analysis to understand limitations and frequent error patterns of SetCSE (R1).  
- No quantification or comparison with existing set-based methods from the literature. R4 explicitly cites missing comparisons to: Zhelezniak et al. (ICLR 2019, “Don’t Settle for Average, Go for the Max”), Bhat et al. (RepL4NLP 2020), Dasgupta et al. (ACL 2022, “Word2Box”). Both Tables 1 and 2 lack such comparisons (R1, R4).  
- Missing quantitative comparison with traditional retrieval methods like DPR and BM25 for sentence retrieval tasks (R3).  
- In Table 2, some baseline models (e.g., SGPT) show only marginal improvements; the paper does not analyze why improvements vary across models (R3).  
- No analysis of capabilities lost: do models trained with SetCSE underperform on standard sentence similarity or information retrieval datasets? (R2) How do they perform on other general NLU tasks such as sentence classification, sequence tagging, extractive QA, or multiple choice QA? (R2)  
- Evaluation is performed only in artificial settings; application results are only case studies, making it unclear how stably the method works in real use (R4).  
- The core concept assumes sentences are clustered with semantic meaning, which limits generalization; using set semantics provides additional information for training that other baselines lack (R3, R4). R3 asks how to adapt the method when sentences are not clustered or when clusters do not exist.  
- The set operation does not satisfy the commutative law (it orders elements in the first set), deviating from usual set theory. This limitation is not discussed in detail and may confuse users (R4).  
- No code is provided (R3).  
- Typos: “DISUCSSION” in Section 7 (R1).  
- Scaling behavior with dataset size and query complexity is not addressed (R1).  
- The approach is only applied up to RoBERTa-like models; its scalability to larger models or application with LoRA is not explored (R2).
