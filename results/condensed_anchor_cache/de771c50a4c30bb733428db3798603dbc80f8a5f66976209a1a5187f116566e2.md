## Merged Review

### Summary
The paper introduces Continuous Relative Rotary Positional Query (CR2PQ), a self-supervised framework for dense visual representation learning that avoids explicit pixel/patch correspondence across views. It uses continuous rotary positional embeddings and a positional-aware cross-attention module to predict local representations from one view to another guided by relative positional cues. The method achieves state-of-the-art results on COCO and ADE20K with faster convergence compared to previous methods like PQCL.

### Strengths
- **Novelty**: Pioneering use of continuous relative rotary positional embeddings for dense self-supervised learning (Reviewers 1, 3, 4). Elegantly eliminates the need for explicit dense correspondence (Reviewer 4).
- **State-of-the-art performance**: Outperforms previous SOTA (PQCL) on COCO by 3.4% mAP^bb and 2.1% mAP^mk (detection and segmentation) with 300 epochs pretraining, and by 10.4% mAP^bb and 7.9% mAP^mk with only 40 epochs (Reviewers 1, 2, 3, 4). Also achieves leading results on ADE20K (Reviewer 1). Demonstrates faster convergence (Reviewer 4).
- **Versatility**: CR2PQ is simple and can be easily integrated into various representation learning frameworks (mask-based, contrastive, distillation) (Reviewer 1). The positional-aware cross-attention module enhances semantic learning without significant additional computational cost (Reviewer 3). The method is robust to view augmentations, including random cropping (Reviewer 3).
- **Thorough experiments**: The paper provides extensive experiments and ablation studies supporting the method (Reviewer 3).
- **Writing quality** (Reviewer 1): The paper is well-structured and clearly written. *Note: This strength is contested by other reviewers who found the writing difficult to follow due to notation issues and typos (see Weaknesses).*

### Weaknesses
- **Reliance on random cropping**: The method’s view generation relies on random cropping, which in extreme cases may produce views with almost no overlap, limiting correspondence learning. No systematic approach to view generation is provided (Reviewer 1).
- **Computational complexity**: The relative position embedding and rotary embedding require complex matrix operations; no detailed analysis of the computational overhead is given, raising concerns about scalability in resource-constrained environments (Reviewer 1).
- **Notation and writing inconsistencies** (multiple reviewers):
  - **Positional encoding confusion**: L142 states “Relative positional encoding = RoPE?” but RoPE is a specific type of positional encoding; unclear if a modified version is used (Reviewer 2). The reference frame for size/position encoding (original image grid vs. crop) is not clarified (Reviewer 2).
  - **Inconsistent notation**: L161: \(\mathbf{W}_{pos}\) vs. \(\mathbf{P}_{pos}\) distinction unclear; line 161 should be \(\mathbf{P}^{i}_{pos}\) (Reviewers 2, 4). Line 214: \(\mathbf{p}_{a}\) vs. \(\mathbf{p}_{A}\) inconsistency (Reviewer 4). Line 234: notation inconsistent with left side of Equation 3 (Reviewer 4).
  - **Equation 1 misleading**: Suggests patches do not interact and representation of a patch is context-independent; the input to \(f_\theta\) is inconsistent (z contains linear layer on left but not right) (Reviewers 2, 4).
  - **Equation 2 errors**: Variables \(n\) and \(m\) mixed; the angle of the key appears incorrect (should be relative, not absolute) (Reviewers 2, 4).
  - **Patch size contradictions**: L219 says “set each patch size of view A as 1” but L227 defines \(p_A\) as patch size (Reviewers 2, 4). L228 “set each grid size of anchor view as 1” is unclear (Reviewer 2).
  - **Definition errors**: L297: definition of \(q\) is incorrect/inconsistent (Reviewer 2). Line 210 image dimensions inconsistent with line 157 (Reviewer 4).
  - **Figure errors**: Figure 1 notation inconsistent with method; [CLS] should be global information, patch is local (Reviewer 1). Also notations inconsistent with text (Reviewer 4).
  - **Typos and formatting**: Table 1 “Framwork” → framework (Reviewer 4). “pertaining” → “pretraining” (11 occurrences) (Reviewer 4). Line 86: “exhausted” → “exhaustive” (Reviewer 4). Line 082 typo (Reviewer 2). Line 203: sentence starting with “i.e.” (Reviewer 2). Line 274: table-caption overlap (Reviewer 3). Font different from other papers (Reviewer 3). Negative vertical spacing used to fit page limit (Reviewer 4).
- **Ablation and fairness concerns**:
  - The method differs from baselines in three ways: use of rotary positional embeddings, pretrained frozen teacher, and the pretext task. This makes it difficult to assess each component’s contribution; the comparison is unfair because baselines are trained from scratch while CR2PQ uses a pretrained teacher (Reviewer 4). Need ablation on teacher initialization (random vs pretrained), teacher architecture, pretraining dataset (Reviewer 4). Need independent validation of 2D RoPE and cross-attention module separately (Reviewer 2). 
  - Specific missing ablations/questions: 
    - Why use a pretrained teacher instead of training from scratch? (Reviewer 2)
    - In Table 1, what does the “RoPE” row correspond to? Is it a ViT-S/16 with rotary embedding randomly initialized and finetuned? (Reviewer 4)
    - In Table 4, what does “EMA update (Contrastive)” correspond to? Is the teacher randomly initialized? (Reviewer 4)
    - Performance on strong detectors like DINO or Co-DETR not explored (Reviewer 3).
  - **Scalability**: Most experiments use ViT-S; need experiments on larger backbones (e.g., ViT-L/ViT-G) to validate scalability (Reviewer 3). The method may not improve with larger student backbones (Reviewer 3 question). Computational complexity concerns also affect scalability (Reviewer 1).
