## Merged Review

### Summary
This paper presents MARTINI, a backdoor mitigation technique that reverse-engineers triggers via a learned transformation layer operating on feature vectors. The method models backdoor effects as feature-space perturbations, generates synthetic backdoor samples paired with correct labels, and fine-tunes the model to remove the backdoor. Evaluated on 14 attack types across five datasets (max resolution 178×218), it outperforms 12 state-of-the-art defenses, reducing ASR from 96.56% to 5.17% on average. The approach is applied to image classification, self-supervised learning, and object detection.  

### Strengths
- Novel trigger reverse-engineering mechanism that uses a transformation layer to generalize across diverse backdoor attacks, including those with abstract/semantic triggers.
- Extensive evaluation covering 14 backdoor attacks, five datasets, multiple model architectures, and tasks (classification, self-supervised learning, object detection).
- Outperforms 12 state-of-the-art defense methods; reduces ASR to 5.17% on average (best baseline 26.56%).
- Design is conceptually simple and easy to understand; applicable across different learning paradigms.
- Experiments are detailed and the methodology is thoroughly explained, making the approach intuitively effective.

### Weaknesses
- **Threat model is unclear.** The defender is assumed to know the attacker’s target class; no discussion of how to handle ALL-to-ALL attacks or source-specific attacks. Also unclear how decoded images are paired with the target label (similar to Neural Cleanse?).
- **Scalability concerns.** Evaluated only on small/medium models and low-resolution images (max 178×218). Performance on large-scale models (e.g., GPT-3, LLaMA-7B) or high-resolution datasets (e.g., ImageNet) is unknown. The need for a separate transformation layer for each target class would add prohibitive overhead for datasets with many classes (e.g., ImageNet’s 1000 classes).
- **Assumption limitation.** The method assumes the backdoor trigger’s effect is a function of the original image’s pixel neighborhood. This contradicts invisible, sample-agnostic triggers (e.g., reflection, invisible watermarks) and complex triggers, requiring theoretical justification.
- **Trigger reconstruction quality.** Prior work (Gangsweep, De-trigger autoencoder, 2020) already uses autoencoders for feature-space trigger reverse engineering. MARTINI’s transformation layer must be jointly trained with the classifier, increasing training complexity. It is questionable whether a simple transformation layer can reconstruct high-quality triggers (as shown in Figure 1) or whether it just generates same-effect adversarial noise. The figure (Figure 1) is confusing in how vivid triggers are produced from clean samples; notation (a vs a’) is inconsistent (lines 143 and 164).
- **Detection mechanism absent.** MARTINI always performs full autoencoder training, trigger reconstruction, and classifier fine-tuning, even when no backdoor exists. This introduces unnecessary overhead, risk of distribution drift, and may be impractical in deployment.
- **Missing implementation details.** Hardware settings, training parameters for the decoder and victim model, and other specifics are not reported, hindering reproducibility.
- **Overclaim for object detection and self-supervised learning.** No comparison with existing backdoor defenses for object detection (e.g., Django NeurIPS 2023, ODSCAN S&P 2024). Triggers in object detection are often obvious patches (checkerboard, random, watermelon); it is unclear how MARTINI’s transformation layer and smoothness loss (L_smooth) effectively reverse-engineer such patterns. No visual examples of reconstructed triggers in object detection are provided.
- **Ablation and loss-function roles.** All four loss components appear to contribute equally to performance. This is surprising because L_smooth helps even with obvious triggers (e.g., in object detection), raising doubt about a key mechanism. The lack of a primary component suggests potential instability or over-engineering.
- **Multi-trigger/complex attacks.** The search optimizes a single trigger type; when faced with multi-trigger or compound backdoor attacks, the simple iterative search may fail to find optimal parameter combinations.
- **Writing quality issues.** Typos (e.g., line 37); motivation section is unclear on why the transformation layer achieves backdoor defense.
- **Questions from reviewers** (overlap with weaknesses):
  1. Scalability: How does MARTINI perform on large-scale models like LLaMA-7B or GPT-3?
  2. Computational overhead: What is the impact on the classifier and the overall training cost?
  3. Object detection: Can the authors show visual examples of reverse-engineered triggers for classic patterns (checkerboard, random, watermelon)?
  4. Threat model: How does the defender know the target class? How are ALL-to-ALL and source-specific attacks handled?
