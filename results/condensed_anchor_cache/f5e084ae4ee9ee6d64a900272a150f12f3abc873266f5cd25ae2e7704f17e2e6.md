## Merged Review

### Summary
This paper proposes LLM-LNS, a dual-layer self-evolutionary LLM agent to automate neighborhood selection in Large Neighborhood Search (LNS) for large-scale MILP. The inner layer evolves heuristic strategies for convergence; the outer layer evolves prompt strategies for diversity. A Differential Memory for Directional Evolution feeds back fitness scores. Experiments on online bin packing, TSP, and large-scale MILP show improvements over manually designed LNS (ACP), ML-based LNS (CL-LNS), solvers (Gurobi, SCIP), and ML-based MILP frameworks (GNN&GBDT, Light-MILPopt), as well as over LLM-driven agents FunSearch and EOH. Reviewers acknowledge novelty in combining LLMs with LNS and the dual-layer structure, but raise concerns about clarity, missing ablations, insufficient baselines, lack of reproducibility, and overclaim. One reviewer (score 8) is more positive about the results; others (scores 5,5,3) are more critical, with the lowest reviewer questioning technical clarity and novelty.

### Strengths
1. **Novel task and dual-layer framework**: The combination of LLMs with LNS-based heuristics is new; the dual-layer structure (inner: heuristic evolution for convergence; outer: prompt evolution for diversity) is innovative and reasonable. (R1, R2, R3, R4)
2. **Strong experimental results**: The proposed method shows leading performance across three problem classes (online bin packing, TSP, large-scale MILP), outperforming state-of-the-art LLM agents (FunSearch, EOH), hand-crafted LNS, ML-based LNS (CL-LNS), and large-scale solvers (Gurobi, SCIP). (R1, R3, R2) 
3. **Effective for variable ranking**: The LLM-based method for ranking decision variables in MILP is a novel contribution. (R4)
4. **Good scope of evaluation**: Evaluation on three distinct CO problem sets is satisfactory. (R2)
5. **Interesting mechanism**: Using prompt evolution to avoid local optima is an interesting idea. (R2)
6. **Dual-layer novelty**: The dual-layer self-evolutionary LLM agent is novel and reasonable. (R3)
7. **Scalarization**: The results show good scalarization. (R1)

### Weaknesses
1. **Lack of ablation studies**: No ablation experiments are provided to assess the individual contribution of the three key components (prompt evolution, heuristic evolution, differential memory). This is a major gap that prevents validating the effectiveness of the proposed submodules. (R1, R2, R3, R4)  
   - Specific requests: ablation of Differential Memory (R3, R4), ablation of each layer (R1, R2).
2. **Insufficient baseline comparisons**:  
   - Missing baseline: adaptive large neighborhood search (ALNS) with different heuristic scoring functions (not LLM-designed). (R2)  
   - Missing comparisons with prior studies that use similar concepts: the prompt evolution resembles [1] (not cited in text); differential memory aligns with [2]; authors should compare experimentally and clearly delineate differences. (R4)  
   - Unclear how the proposed method compares to EoH and FunSearch *on the LNS tasks* — those results are not shown. (R1)  
   - Lack of comparisons with other LLMs (e.g., Llama) or testing robustness across multiple LLMs; only GPT-4o-mini is used. (R4)
3. **Clarity and reproducibility issues**:  
   - Figure 1 is confusing: too many components; the relationship between arrows is hard to parse; needs improved visualization. (R2)  
   - The method relies heavily on textual explanations with insufficient mathematical formalization; missing mathematical definitions, formulas, and pseudocode. (R4)  
   - No open-source code is provided, limiting reproducibility. (R4)  
   - Criteria for selecting evolutionary strategies in the outer layer are not explained (e.g., “parents are combined with evolutionary strategies” — no selection criteria). (R4)  
   - “Underperforming strategies are pruned” is not defined (what is a poorly performing strategy?). (R4)  
   - Grammatical errors: e.g., “In the Appendix A B C D” on page 8. (R4)  
   - Terms in Table 1 (“Evolutionary Prompt,” “Strategic Evolution,” “Directional Evolution”) are not explained. (R4)
4. **Training and experimental details missing**:  
   - Training process of the LLM agent is unclear: how many parameters? Is it fine-tuned on an existing open-source LLM (e.g., Llama) using MILP data? (R4)  
   - Training set size for each task is not clearly stated. (R2)  
   - Only trained on small-scale problems and generalized to larger ones — why not train directly on larger problems? (R2)  
   - For TSP, only 5 instances are evaluated; how were they selected? Need larger and more diverse instance sets. (R2)  
   - Online Bin Packing and TSP experimental settings are missing (e.g., for TSP, it seems GLS is used; this is misleading). (R3)  
   - Population size settings differ between LNS tasks and CO tasks — why? How does population size affect outcomes? (R1)  
   - Detailed settings for Differential Memory (both thought directions and code directions?) and an illustrative example are needed. (R1)
5. **Novelty concerns**:  
   - The three components (prompt evolution, heuristic evolution, differential memory) have all been proposed in previous works; combining them, while effective, may not be sufficiently novel. (R2)  
   - The paper claims introducing LLM-driven heuristics to LNS is an application-level innovation, but it is unclear whether other comparative algorithms (e.g., EoH) could be similarly introduced to LNS. (R3)  
   - The concept of using LLMs to evolve strategies resembles prior work [1]; differential memory aligns with [2]; the distinctions are not clearly delineated. (R4)
6. **Potential overclaim**:  
   - It is unclear if the initial seed heuristics are hand-crafted; Figure 3 shows an initial advantage for the proposed method, potentially introducing unfair comparison. (R3)  
   - SCIP, which is used to generate labels in prior work [Reference: Huang et al., ICML 2024], performs poorly on the LNS tasks — this needs explanation. (R3)  
   - The contributions of the dual-level framework are not well-defined: how do inner and outer loops interact? How does differential evolution in the outer loop influence prompts and subsequent heuristic generation? (R1)
7. **Robustness and consistency**:  
   - Only one LLM (GPT-4o-mini) is used; results may not be robust across different LLMs. (R4)  
   - Consistency of results given the use of LLMs needs more rigorous investigation; number of repeated trials for the proposed method, EoH, and FunSearch should be reported. (R1)  
   - Can existing LLMs (e.g., Llama) rank decision variables without pretraining on MILP data? If so, why not compare? (R4)
8. **Cost and input length analysis**: Differential Memory increases input token length / API cost; the relationship between input tokens and optimization effect should be analyzed. (R3)
9. **Missing limitations discussion**: The paper lacks a limitations section. (R3)
10. **Sensitivity to algorithm backbone**: It is unclear whether the method is sensitive to the algorithm backbone (e.g., ALNS vs. other search/decomposition methods, or LNS without adaptive size). (R2)
