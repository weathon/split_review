## Merged Review

### Summary
The paper proposes MALLM-GAN, a multi-agent LLM framework for synthesizing tabular data using in-context learning without fine-tuning. It emulates a GAN: one LLM as generator, a neural network as discriminator, and another LLM (GPT-4) as optimizer. The generator’s prompt includes a natural language description of the data collection context, schema, causal structure (DAG), and task instructions. During training, the discriminator is trained on both original and synthetic data; its performance score is fed to the optimizer LLM, which refines the generator prompt (the DAG and instruction). The process iterates. Experiments on 5 datasets evaluate MLE and DCR. The method is motivated by data scarcity in healthcare, but shows limitations.

### Strengths
- Solid experimental setting with 5 different datasets (R1).
- Idea of combining LLM and GAN makes sense (R1).
- Method is well-generalized, simple, and applicable to many tasks (R1).
- Well-written and easy to read (R2).
- Reveals a problem in previous deep generative models requiring large training data; LLM ICL has potential to address this (R2).
- Innovative setup: using an LLM optimizer to refine the generator prompt based on discriminator score saves compute (no finetuning) (R3).
- Using LLMs to rewrite prompts based on scores is good (R3).
- Conditional generation through natural language in the prompt enables simulations (R3).
- The explicit generation and optimization process offers better explainability than black-box models (R4).
- Pipeline enables automatic optimization and synthetic data generation, addressing data scarcity (R4).

### Weaknesses
- The proposed model does not always achieve SOTA performance (Tables 2 and 3) (R1).
- The combination of ICL-LLM and GAN is straightforward; the authors should clearly articulate the technical difficulty and novelty (R1).
- Dataset splitting was done by the authors rather than using standard small-dataset benchmarks, raising fairness concerns (R1).
- The central optimization of the DAG (Eq. 1) relies on the assumption that the DAG is crucial for generation quality. However, the authors themselves note (Lines 398–400) that incorporating causal structure alone did not significantly improve MLE compared to a model with only ICL, undermining a core foundation of the method (R2).
- There is doubt that an LLM can solve the optimization problem: it has no access to the function form of the score, and the search space is extremely high-dimensional (DAG and task instruction) given only a few previous <score, prompt> pairs. More trajectory results (similar to Table 4) are needed to show whether each optimization step consistently improves the score, how many steps are needed to converge, and what the trajectory looks like for different datasets (R2).
- An important baseline is missing: CLLM, which also relies on LLM ICL (post-hoc data selection). A comparison with CLLM without the data selection procedure is crucial since it directly tests the value of the adversarial prompt optimization (R2).
- Evaluation metrics are too limited. Only MLE and DCR are used; the metric that the discriminator itself uses (see Sec 3.2.2) is not reported. Metrics common in tabular synthesis (column density shape, pair-wise column correlation, Jensen–Shannon divergence from TabDDPM) are absent, undermining convincingness (R2).
- The claim that few-shot learning is not scalable due to limited context length is contradicted by models like Gemini with million-token context windows (R3).
- It is hard to assess whether the learning process has converged because optimization happens only at the prompt level (authors acknowledge this) (R3).
- The method has only been tested on datasets with at most 37 columns; its scalability to larger datasets (e.g., 100 columns) is unclear (R3).
- Optimizing prompts via an LLM is not a novel contribution; existing frameworks like DSPY already do this (R3).
- Only one model (GPT-3.5) was used; generalization to other models (Claude, Gemini, Llama-3) is not shown (R3).
- The initial prompt for both generator and optimizer requires empirical knowledge and labor, making application to different tasks difficult (R4).
- There is no comparison with methods that use the same base LLM (GPT-3.5) as a data generator. To demonstrate effectiveness, comparisons are needed against human-written instructions, instructions directly generated by GPT-4, or randomly selected few-shot examples (R4).
