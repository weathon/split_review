## Merged Review

### Summary
This paper introduces OGBench, a benchmark for offline goal-conditioned reinforcement learning (GCRL). It provides 8 environment types, 85 datasets, and reference implementations of 6 representative offline GCRL algorithms. The benchmark is designed to evaluate key capabilities: learning from suboptimal data, goal stitching, long-horizon reasoning, handling high-dimensional inputs (including images), and stochasticity. Environments cover locomotion, manipulation, and a drawing/painting task. Datasets are collected with varying suboptimality conditions. The paper evaluates several standard algorithms, discusses their strengths/weaknesses, and highlights unsolved tasks.

### Strengths
- **Novelty and motivation:** Offline GCRL is an important and growing research area, but before OGBench there was no centralized, standardized evaluation suite tailored to its specific challenges (e.g., stitching, suboptimal data, stochasticity). This fills a clear gap.
- **Comprehensive task design:** The benchmark directly probes different capabilities (stitching, long-horizon, visual input, stochasticity) across diverse domains (locomotion, manipulation, drawing). It includes both low-dimensional and image-based variants.
- **High-quality execution:** The benchmark provides fine-tuned implementations of state-of-the-art offline GCRL algorithms that often surpass original versions. Datasets are collected with multiple suboptimality levels (e.g., expert, medium, mixed, exploratory).
- **Challenging baselines:** The paper evaluates 6 standard offline GCRL algorithms (e.g., WGCSL, IQL, etc.) and provides solid baselines. Results show stark differences in algorithm capabilities, revealing unsolved tasks and areas for improvement.
- **Practical considerations:** The benchmark is computationally efficient, user-friendly, and has minimal dependencies (Mujoco, PyTorch). Code and scripts are provided.
- **Clarity and presentation:** Well-written with clear figures, tables, and organized narrative. Easy to read and follow.

### Weaknesses
- **Limited number of evaluation goals per task:** Only 5 goals are used per environment. For goal-conditioned policies that should be able to reach any (viable) state from any state, this is a very restricted evaluation set compared to prior benchmarks like Fetch environments. (Multiple reviewers)
- **Unclear novelty of each environment:** It is difficult to assess how many environments are unique to OGBench vs. adapted from existing benchmarks (e.g., AntMaze). The paper should clarify the level of novelty per environment. (Reviewer 1)
- **Missing discussion of limitations and future extensions:** The paper lacks a limitations section and discussion of possible extensions (e.g., robustness to data corruption, multi-modal goals, language instructions). (Reviewer 1)
- **No representation or transfer analysis:** The benchmark is motivated by learning transferable representations, but the task design and experiments do not study representation quality or transfer to downstream tasks. It would be better to include functionality for analyzing latent representations and report how SotA algorithms perform on this aspect. (Reviewer 2)
- **Only initial-state shift, no dynamics shift:** The tasks challenge policies with different initial states but not with changes in transition dynamics (e.g., different physics parameters). This limits evaluation of generalization. (Reviewer 2)
- **Transparent arm in pixel-based manipulation is unrealistic:** The transparent arm design in image-based tasks may not reflect real-world conditions. Better to let users choose between transparent/solid options and to show how transparency affects performance. (Reviewer 3)
- **Stochasticity limited to teleportation:** The only stochastic task (Stoch-AntDir) uses teleportation. More realistic stochastic settings should be explored, e.g., random observation perturbation during both data collection and evaluation. (Reviewer 3)
- **Baselines use MLP backbones only:** Current baselines rely on MLP networks. Could the authors implement more advanced architectures (e.g., transformers)? Are there limitations in the current tasks that more sophisticated architectures might address? (Reviewer 3)
- **Goal information missing in Table 6:** For image-based tasks, it is unclear whether the goal is another image provided to the agent or a transparent bot as shown in figures. (Reviewer 3)
- **No support for language instructions:** The benchmark currently only supports state/image goals. Given the research focus on LLMs, language-conditioned goals would be a valuable extension. (Reviewer 3)
- **Missing discussion of related work on stochastic offline GCRL:** The paper should mention and discuss GOPlan (Wang et al., 2024) and GoFar (Ma et al., 2022, NeurIPS 2022) in the context of stochastic settings (Section 5.4). (Reviewer 4)
- **Success condition not clearly defined:** The paper should clarify whether a rollout is considered successful if the goal is achieved at the last state, or if any state within the rollout reaches the goal. (Reviewer 4)
- **Decimal places in Table 2:** It would be better to retain one or two decimal places in Table 2 for more precise comparison, as done in D4RL and offline robotics benchmarks. (Reviewer 4)
- **Missing "exploratory" dataset for AntSoccer:** Reviewer 1 asks why no exploratory dataset was collected for AntSoccer (possible due to lack of coverage of dribbling states).
- **How is goal state provided in locomotion/manipulation?** Specifically, does the goal include the final pose of the agent? If so, the task becomes a convolution of environmental change and agent pose. (Reviewer 1)
- **How to ensure expert data optimality?** Expert data are collected from RL-trained policies. Could motion planning/search algorithms provide better data quality? (Reviewer 2)
- **Minority reviewer note (Reviewer 4):** The positioning of the paper is very similar to D4RL, which was rejected at ICLR 2021. This work makes a clear contribution by providing valuable benchmarks, but it does not introduce novel ideas. Nevertheless, given its potential importance, the reviewer assigned a slightly positive score. (This contrast should be preserved: the paper provides useful benchmarks but lacks algorithmic novelty.)
