## Merged Review

### Summary
The paper addresses multi-entity question answering (QA) over Wikipedia, where queries require aggregating information from multiple pages (e.g., “How many Turing Award winners are Canadian?”). Traditional RAG struggles with aggregation. The authors propose Structured QA (SQA), which extracts entities into a relational table and then uses table-based methods (TableQA or NL2SQL). They introduce a new benchmark, MEGraphQA (~4780 QA pairs), and claim SQA improves accuracy by 29.6% over existing solutions.

### Strengths
- The construction of the MEGraphQA benchmark is described in reasonable detail, including question templates, entity numbers, and question type analysis (Reviewers 1, 2, 3, 4). One reviewer (score 5) particularly emphasized the clarity of the construction process and dataset analysis.
- The motivation is straightforward: converting long, noisy retrieved text into a table filters irrelevant information, thereby improving accuracy (Reviewer 2). More positive reviewers found this idea reasonable and original in its use of a table as an intermediate object (Reviewers 3, 4).
- The paper introduces a new dataset specifically for multi-entity QA on Wikipedia, contributing a focused evaluation resource (Reviewers 1, 4).
- The presentation covers the overall pipeline (graph search → table generation → SQL execution) clearly (Reviewer 3).
- The work tackles a difficult, practically relevant problem: answering non-trivial multi-entity questions using Wikipedia (Reviewer 5).

### Weaknesses
- **Lack of novelty and insufficient justification.** The core idea of converting entity data into relational tables is already well-established in database query systems (e.g., NL2SQL) and table retrieval/exploration literature (e.g., “Semantic Table Retrieval Using Keyword and Table Queries,” “Web Table Extraction, Retrieval, and Augmentation,” “Novel Entity Discovery from Web Tables”). The paper does not convincingly argue why this specialized SQA framework is necessary over existing KBQA systems that already handle multi-entity questions (Reviewers 1, 3). One reviewer noted a weak correlation between the problem (multi-entity QA) and the solution (table simplification of long text); the method could apply to any scenario with long retrieved text, not specifically multi-entity questions (Reviewer 2).
- **Vague and insufficient experimental validation.**  
  - The main experiments compare SQA (using GPT-4 as the primary model, lines 212, 252) only against basic methods (GPT-3.5, Llama, vanilla RAG). Important baselines are missing: alternative RAG methods (e.g., BlendFilter [1]), graph-based approaches (e.g., CoTKR [2], Think-on-Graph [3]), and table-based QA systems (e.g., StructQA, HOMLES) (Reviewers 2, 4).  
  - The significance of the new benchmark is unverified: it is not shown that the benchmark is necessary or that it poses unique challenges not covered by existing multi-hop reasoning datasets (e.g., those reviewed in https://arxiv.org/pdf/2204.09140#page=27.11) (Reviewers 2, 4).  
  - Ablation studies are missing: the necessity of SQL over simpler alternatives (keyword extraction, summarization) is not tested (Reviewer 2).  
  - The 29.6% improvement claim is based on an unbalanced comparison (GPT-4 in SQA vs. weaker models for baselines; Reviewers 2, 3).  
- **Limited model availability.** The performance heavily relies on GPT-4 (for entity extraction, schema generation, SQL conversion). The paper does not verify whether the core idea holds with open-source LLMs, limiting applicability and reproducibility (Reviewers 2, 3).
- **Insufficient technical detail and clarity.** Several key steps are described too vaguely (Reviewers 1, 4, 5):  
  - The entity and relation parsing step (Sec 4.1) mentions using GPT-4, NER, and RE but provides no details on which models or methods are used (Reviewers 1, 4, 5).  
  - The table generation step (Sec 4.2) gives schema prompts but does not explain how Mistral-7B populates the table (Reviewer 4).  
  - The conversion of questions to SQL (Sec 4.3) is not described (Reviewer 4).  
  - The correctness of the inferred schema and entity relations extracted by GPT-4 is not addressed; no mechanism for handling errors in schema derivation or entity disambiguation is presented (Reviewers 1, 3).  
  - Quality control is mentioned in Sec 5.3 but not detailed; examples of how it was performed are missing (Reviewer 4).  
  - The dataset creation process (Sec 5.2) is unclear—the two paragraphs do not explain how QA pairs were generated (Reviewer 5).  
- **Scope and complexity concerns.** The paper only demonstrates simple schema extraction for straightforward queries; it does not address how SQA handles complex or ambiguous queries requiring relational or semantic inference (Reviewer 1). Failure modes (entity coverage, complex relationship resolution, accuracy limits) are not discussed (Reviewer 1).  
- **Missing details in writing.** Several paragraphs state opinionated advantages without supporting reasoning or evidence (Sec 4.4, lines 103–107, lines 358–362). Notations are inconsistent or undefined (e.g., $P$, $t$, duplicate $V$, missing $P_v$). No reproducibility statement is provided despite the highly empirical nature of the work (Reviewers 4, 5).
- **Minority positive reviewer notes.** One reviewer (score 5) found the motivation straightforward and the benchmark construction clear, but even this reviewer pointed out missing baselines and insufficient ablation, and questioned the necessity of the benchmark for future research.
