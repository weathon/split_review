## Merged Review

### Summary
The paper proposes InvAct, a method to reduce activation memory during training by storing the output tensor instead of the input tensor for pointwise nonlinearities (GELU, SiLU). During the backward pass, the input is reconstructed using an approximate inverse of the nonlinearity. This saves approximately 25% memory for transformer architectures (e.g., BERT, Llama) without significant accuracy or speed degradation. The method is implemented as a drop-in replacement in PyTorch. Evaluations show negligible impact on training loss and wall-clock time across several frameworks, and memory savings are measured for BERT and Llama.

### Strengths
- The core idea (storing output instead of input and inverting the activation) is simple, novel for GELU/SiLU, and leads to substantial memory reduction without introducing significant trade-offs in training time or performance. [All reviewers]
- The approximate inverses for GELU and SiLU are well constructed and the paper provides clear pseudocode, pseudocode, and detailed experimentation. [R1, R2]
- The method is a drop-in replacement, easily adoptable in existing PyTorch workflows, and compatible with widely used architectures. [R1, R3]
- Computational efficiency (execution time) is evaluated on multiple frameworks (PyTorch, JAX, TensorFlow). [R2]
- The paper is clearly written and well structured. [R1, R2, R3]
- The method is significant for scaling trends and resource-constrained settings. [R1]

### Weaknesses
- **Limited novelty outside GELU/SiLU and missing comparison with checkpointing / prior inversion methods.** Reviewer 2 notes that inverting computations of activation functions has been proposed before [1] and that a thorough comparison with activation/gradient checkpointing (e.g., [2-5]) is absent. The approach is very similar to storing only the input and recomputing the output, which does not require approximate inversion. Standard checkpointing can also achieve memory savings with an optimal trade-off for computation. [R2]
- **No direct experiment on memory footprint for several claimed beneficiaries.** The abstract mentions GPT, Mistral, ViT, CLIP, and Audio Spectral Transformer, but no memory savings or performance impact is reported for these models. [R1, R3] For the Llama model, memory savings are not shown in Listing 1. [R1 minor]
- **Experimental scope is too narrow.** Only BERT (fine-tuned on Yelp Reviews) and Llama (with training loss curves) are evaluated. Additional tasks (e.g., GLUE) would strengthen generalizability. [R1]
- **Missing task-specific metrics.** For the Yelp Reviews fine-tuning, only loss is reported; accuracy or F1 scores would better contextualize the effect of approximation errors on quality. [R1]
- **Insufficient experimental details.** Reporting of fine-tuning hyperparameters for Sections 3.2 and 3.3 is missing. It is unclear whether results in Table 1 are averaged over multiple runs; standard deviations are not provided. [R1]
- **Approximation error near zero is concerning.** Figure 2 shows non-negligible error in the derivative of the inverse for inputs close to zero, which may impact gradient quality. [R2]
- **Other activation functions (e.g., ReLU) are not considered.** The framework’s applicability to non-invertible or piecewise-linear activations is not discussed. [R2]
- **Precision Bit InvAct is not evaluated for downstream performance.** Table 1 shows less overhead for this variant, but no experiments on accuracy or F1 are provided. [R1 question]
- **Execution time increase for Plain GELU is not explained.** Only Plain GELU shows a rise in execution time; why this happens and whether it also applies to SiLU is unclear. [R2 question]
- **Two different frameworks used in Section 3.1 make comparisons ambiguous.** The paper shows runs in PyTorch for forward-only and in two other frameworks for full training, making it hard to isolate the method’s impact on computational efficiency. [R3]
- **Figure 3 lacks row/column labels**, making it hard to interpret. [R2 question]
- **Sequence length for BERT experiment (1024) exceeds typical limit (512).** How this was achieved is not clarified. [R1 question]
- **Clarity on FewBit comparison dataset.** In Figure 5, it is not explicitly stated whether the same dataset as in Section 3.2 was used. [R1 question]
- **Missing theoretical example.** A concrete example illustrating which tensors are discarded during backpropagation would make the contribution clearer. [R3]
- **Minor errors:** Typos at lines 182 ("based"), 337 ("implementatoins"), 701 ("assstance"), 464 (extra “in”); abstract formatting error. [R1, R2, R3]
- **Reviewer disagreement:** One reviewer (score 8) found the method novel and significant, while another (score 5) emphasized limited novelty and missing comparisons; a third (score 6) noted missing memory footprint measurements and unclear experimental setup. [All]
