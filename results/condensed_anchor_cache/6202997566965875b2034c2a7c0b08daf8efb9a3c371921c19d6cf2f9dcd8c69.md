## Merged Review

### Summary
STAMP proposes a task- and model-agnostic collaborative perception framework using lightweight adapter-reverter pairs to transform Bird’s Eye View (BEV) features between agent-specific domains and a shared protocol domain. The protocol feature space is learned jointly across agents and tasks, while local adapters/reverters are trained separately and are lightweight (~1 MB). Experiments on simulated (OPV2V) and real-world (V2V4Real) datasets validate performance.

### Strengths
- This is the first-of-its-kind task- and model-agnostic collaborative perception framework, initiating the study of simultaneous heterogeneity in sensors, model architectures/parameters, and downstream tasks (R2, R5).
- The adapter-reverter mechanism is a unique and intuitive design that bridges heterogeneity gaps in multi-agent collaboration (R2, R4). It is lightweight (~1 MB), enabling 7.2× computational savings (R3).
- Using a shared protocol feature space avoids sharing information about sensors, models, and tasks, thereby enhancing security and agnosticism (R3). The framework is scalable because the protocol space is learned once and adapter-reverter pairs are efficient to add new agents (R3).
- The problem of heterogeneity in collaborative agents is important for practical deployment beyond autonomous driving (R1, R3).
- Experimental validation is comprehensive: detection performance (Tab. 2, 3), scalability and efficiency (Fig. 2), robustness to noise (Tab. 1), task-agnostic and model-agnostic (Tab. 4), plus ablation studies (Fig. 3, 4) and feature visualizations (Fig. 5) (R3, R4).
- The paper is well written, easy to follow, and the manuscript is well organized with clear visualizations (R1, R3, R4, R5).

### Weaknesses
- **Novelty concerns** (R1, score 3): The method is straightforward and each component only marginally extends existing methods (e.g., Collaborative Feature Alignment simply projects BEV to a unified space). The paper overstates model-agnosticity because it relies on each agent computing a BEV representation. Security claims are not substantiated: using neural networks does not inherently guarantee security; no experiment on malicious attacks is provided (also R5 questions line 52 claim of robustness against agent attacks, noting an attacker could inject malicious protocol features). The coordinate frame of the BEV (ego-centric?) and how correspondence between agents is found is not clarified (R1).
- **Scalability not fully demonstrated** (R2): Experiments only include three agents. There is no analysis of performance degradation with more agents or communication overhead, which is critical for real-world deployments.
- **Task-agnostic definition and generalization** (R2, R5): The term “task-agnostic” is not clearly defined. The framework is trained on specific tasks and may not generalize to unseen tasks without significant retraining or fine-tuning of adapter-reverter pairs. The difference from prior work on task-agnostic CP (e.g., MRSC [1], which can be trained without knowing downstream tasks) should be clarified.
- **Missing baselines** (R5): The paper only compares with HEAL; it should include HM-ViT, DiscoNet, V2VNet, V2X-ViT, Where2comm, When2com, What2com.
- **Alignment failure risk** (R4, R5): Training with L2 norm to align agent-specific features to the protocol risks failure if there is a significant capability gap between models. This may explain the limitation reported in Appendix A.3 (performance constrained by weakest agent). The criteria for selecting a suitable protocol model are not provided; protocol model architecture, size, and capabilities compared to agent models are missing. All encoders in experiments are CNN-based; no combination with transformer-based protocol or agent encoders is tested (R4). Forcing feature distributions to be identical may cause negative effects since BEV feature styles differ across agents (Fig. 5) (R5). 
- **Performance on task-agnostic setting is weak** (R5): In Tab. 4, STAMP shows very little improvement or even degradation—not significant.
- **Limited scope** (R2, R3): The framework is only evaluated on vehicle-to-vehicle communication, narrowing impact within the ICLR community. The protocol space is learned from LiDAR BEV only; extending to RGB could improve modality-agnosticity and real-world scaling (R3). Model- and task-agnostic experiments are only on simulated OPV2V, not on real-world datasets like nuScenes (R3).
- **Writing and presentation issues** (R2): The main paper contains intricate details better suited for the appendix; main figure has redundant information. The core contributions and technical novelty are hard to grasp quickly.
- **Literature review is incomplete** (R2): Several highly relevant works on efficient and scalable CP [1–7] are missing.
- **Missing experiments** (R5): No communication efficiency experiments reported. The use of AP@30 and AP@50 (instead of AP@50 and AP@70) is not standard.
- **Multi-group collaboration** (R3): Agents may need to share extra information to form groups (e.g., which is the weaker modality), potentially affecting modality agnosticism or security.
- **Feature space alignment in decision space** (R5): How to align the decision space with different downstream tasks (ground truth) in Sec. 3.3 is unclear.
- **Market relevance** (R5): Given the trend towards larger end-to-end models and more powerful individual vehicles, the remaining market potential for intermediate-BEV cooperative perception is questioned.

*Note: One reviewer (score 3) is significantly more critical of novelty, overclaiming, and security; other reviewers (scores 8, 6, 6) acknowledge the contribution but note various limitations.*
