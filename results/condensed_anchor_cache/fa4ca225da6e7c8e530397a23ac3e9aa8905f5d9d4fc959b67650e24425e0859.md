## Merged Review

### Summary

This paper proposes a parameter-efficient fine-tuning (PEFT) method for convolutional neural networks by decomposing each convolution filter into spatial-only filter atoms and channel-combination atom coefficients. The method fine-tunes only the filter atoms while keeping the coefficients fixed. An overcomplete set of atoms is obtained by recursively decomposing each atom into another set of atoms, allowing more tunable parameters. Experiments on discriminative tasks (ResNet50, ConvNeXt) and a generative task (Stable Diffusion) show that the method achieves comparable or better results than LoRA and LoHa with fewer parameters. However, concerns about computational cost, incomplete baselines, limited evaluation of generative tasks, and missing hyperparameter guidance are raised.

### Strengths

1. The idea of decomposing the convolutional kernel into spatial and channel components and fine-tuning only the spatial part is interesting and clearly motivated (R1, R2, R3).
2. The use of overcomplete filter atoms (via recursive decomposition) provides a principled way to control the number of tunable parameters (R2, R3).
3. In some settings, the method achieves comparable or better performance than LoRA and LoHa while fine-tuning even fewer parameters (R1).
4. The mathematical exposition and formulas are clear and well-explained (R3).
5. Reviewer 2 finds the experiments comprehensive, covering multiple CNN architectures and both discriminative and generative tasks (R2). (Note: Reviewer 3 disagrees – see Weaknesses.)

### Weaknesses

1. **Parameter Plug-in vs. In-model Tuning**: Unlike LoRA, which is a plug-in module that reduces the risk of harming pre-trained capacity, this method directly adjusts parameters in the original model. It is unclear how the method can support multiple tasks simultaneously (e.g., multiple LoRAs for different tasks) (R1).  
2. **Relation to Existing Convolution Forms**: The decomposition into spatial-only convolution and cross-channel mixing appears similar to group convolution followed by point-wise convolution. The paper should clearly state the difference and advantage (R2).  
3. **Missing Memory and Computation Analysis**: For a PEFT method, GPU memory footprint and training-time computational cost are crucial. The paper reports only parameter counts.  
   - R2 asks for detailed memory usage and computation comparisons with baselines.  
   - R3 asks for the GPU memory footprint during fine-tuning, noting that many PEFT methods are not memory-efficient.  
4. **Preprocessing Sparse Coding Overhead**: The method requires an additional sparse coding step to decompose filter atoms and coefficient atoms at the start of training.  
   - R3 expresses concern about efficiency and asks for: number of iterations for convergence, GPU model, wall-clock time for this step across different model sizes, and analysis of the impact of hyperparameter λ on decomposition quality and downstream performance.  
5. **Outdated Baselines in Tables 1 and 4**: The comparisons include only older methods like LoRA (2021). R3 requests the addition of recent PEFT methods: SSF, FacT, Adapter, Compactor, BinaryAdapter, etc.  
   - Comparisons should report not only accuracy but also trainable parameters and computational cost for a fair evaluation (R3).  
6. **Insufficient Evaluation of Generative Task**:  
   - The paper uses only a single theme image (“castle”) for subject-driven generation, whereas standard setups (e.g., OFT) use 750 prompt-image pairs.  
   - OFT and COFT (available in HuggingFace PEFT library) should be included as baselines.  
   - Evaluation metrics should include DINO, CLIP-I, CLIP-T, and LPIPS scores (R3).  
7. **Hyperparameter Sensitivity**:  
   - R2 notes that critical hyperparameters (m, m₁, k_c) significantly affect performance; the paper lacks guidance on how to set them.  
   - R3 mentions λ (sparsity regularization) as an important hyperparameter whose impact on decomposition quality and fine-tuning needs analysis.  
8. **Overall Experimental Strength**: R3 finds the experiments insufficient to convincingly support the method’s effectiveness, citing the missing baselines, limited generative evaluation, and lack of efficiency analysis. (This contrasts with R2’s view that the experiments are comprehensive.)

*Note on reviewer disagreement*: Reviewer 2 rates the experiments as comprehensive (Strengths), while Reviewer 3 considers them not solid enough (Weaknesses). All three reviewers gave a score of 6, though Reviewer 3’s comments suggest they would rate below acceptance. Reviewer 1 had higher confidence (4) and soundness/presentation scores (3/3/3) than Reviewers 2 and 3 (confidence 3/5, soundness/presentation 2/2).
