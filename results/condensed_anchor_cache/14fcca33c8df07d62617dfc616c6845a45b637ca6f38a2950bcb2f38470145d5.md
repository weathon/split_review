## Merged Review

### Summary
The paper proposes Reinforced Advantage feedback (ReAd), which uses a pre-trained critic to compute an advantage score for LLM-generated actions, enabling internal replanning without physical interaction. A sequential advantage function is learned via critic regression from LLM-planned data, and the LLM is prompted to maximize this advantage. Experiments on Overcooked-AI and a difficult variant of RoCoBench (DV-RoCoBench) show higher success rates and fewer interaction steps/LLM queries compared to LLM-based baselines (ReAct, Reflexion, MindAgent, SayCan, etc.). Two reviewers gave 6, one gave 5, and one gave 3, indicating significant disagreement about the method’s novelty, fairness of baselines, and task complexity.

### Strengths
- Eliminates the need for direct physical interaction with the environment at inference time by using a pre-trained critic to approximate an advantage score and internally replan (R1).
- Provides extensive theoretical justification and guarantee for advantage decomposition in multi-agent settings, grounded in MARL theory (R1, R2).
- Generates direct low-level actions without requiring intermediate high-level plans, a significant advantage over previous methods (R1).
- Works with closed-source LLMs because it does not require access to exact action probabilities (R1).
- Innovative combination of MARL advantage-weighting with LLM self-refinement; well-developed theoretical foundation allows deep understanding (R2).
- Well-written and clearly organized, easy to follow (R1, R3, R4).
- Thorough analysis in the appendix that openly addresses robustness and limitations (R3).
- Addresses the practical and challenging problem of reducing interaction costs in embodied environments (R4).

### Weaknesses
- **Limited generalizability and domain-specific critic.** The critic is trained on domain-specific trajectories, so it requires a new critic for each environment. This defeats the purpose of using an LLM as a fast, adaptable planner. Several reviewers suggest exploring an LLM-based critic (e.g., few-shot prompted) as an alternative (R3 weak1, R2 visual perception simplification, R1 W3 critic training vs. training-free baselines, R4 data collection efficiency).
- **Unfair baseline comparisons and missing baselines.** Only LLM-based baselines are compared, while many standard RL methods (e.g., PPO, Q-learning) on Overcooked-AI achieve non-zero success rates and are not included (R2, R3 weak2, R4 weak3). The proposed method uses a trained critic (i.e., environment interaction), whereas baselines like ReAct and Reflexion are training-free – the same interaction data was not provided to them (R1 W3, R4 weak3). Also missing are retrieval-augmented planning (e.g., LLM-Planner) (R4 weak4) and methods that use RL for planning with LLM for communication (R3 weak2). The paper should include RL-based and human-performance baselines as in prior work (R3 weak4, R2).
- **Baseline implementation details are insufficient.** Some baselines (MindAgent, ReAct) may not have communication modules, which could make comparisons unfair on DV-RoCoBench where communication is needed (R3 weak3, Q6). More details on how baselines were implemented in each environment are needed (R3 weak3).
- **Tasks may be too simple or evaluation incomplete.** On DV-RoCoBench, ReAd achieves nearly 100% success, suggesting the task is easy (R2). On Overcooked-AI, all baselines have 0% success; this requires explanation (e.g., fixed timestep limit, inability to complete task even with more time) (R1 W2, R3 Q4, R2). Overcooked evaluation only tested a single delivery, but the environment has a multiple-delivery objective (R1 W2). Decentralized evaluation on Overcooked (ReAd-S) is missing (R1 W5, R3 Q3 – whether a cheaper LLM works for low-level control). The original RoCoBench was not used; instead a new variant (DV-RoCoBench) was created – comparison on the original benchmark would allow direct comparison with prior work (R3 Q5).
- **Lack of generalization to unseen partners.** The method assumes partner agents follow the same algorithm (joint action training). Zero-shot coordination with unseen agents is not tested, limiting practical applicability (R1 W1, Q1).
- **Data efficiency concern.** The on-policy (TRPO-style) data collection is less efficient than off-policy RL, even in single-agent settings (R4 weak2).
- **Novelty concern.** Applying MARL advantage decomposition to LLM planning appears straightforward and is independent of improving LLM reasoning itself (R4 weak1).
- **Assumption about wait action reward.** The claim that taking a wait action gives zero reward and leaves the state unchanged is a strong assumption; wait can cause negative rewards in some task configurations (R1 W4).
- **Presentation issues.** In Fig 3, the two variants ReAd-J and ReAd-S should be placed next to each other for easier comparison (R3 weak5).
- **Missing experimental details.** The size of dataset D is not reported (R4 Q2). The policy iteration procedure (how the critic is updated and new data collected) is unclear – is data collection done only once? (R4 Q3). The neural network architecture of the advantage function is not specified (R4 Q4). It is unclear whether environment observations are converted to text before passing to the LLM (R4 Q5). No ablation compares using the learned Q-function directly as a policy (e.g., picking max Q action) vs. the LLM optimizer (R4 Q6).
