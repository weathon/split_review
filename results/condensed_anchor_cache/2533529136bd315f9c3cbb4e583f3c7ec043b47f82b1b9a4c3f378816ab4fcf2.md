## Merged Review

### Summary
This paper introduces CABINET, a framework for table QA that reduces noise from irrelevant table content without explicit removal. It comprises an Unsupervised Relevance Scorer (URS), trained differentially with the QA LLM via variational inference and three losses (sparsity, centroid distance), and a weakly supervised module with a parsing statement generator and cell highlighter (trained on ToTTo). The relevance scores weight tokens before feeding to the QA LLM. The paper reports SOTA results on WikiTQ, FeTaQA, and WikiSQL, robustness to table perturbations, and outperformance on large tables.

### Strengths
- Achieves SOTA on WikiTQ, FeTaQA, and WikiSQL with orders of magnitude fewer parameters than LLMs like Codex (3.5B vs 175B).
- Outperforms other approaches (OmniTab, DATER, ReasTAP) across all three benchmarks; e.g., ~3 point accuracy gain on WikiTQ over a Codex prompting method.
- Shows strong robustness to perturbations (row/column addition, permutation, cell replacement) compared to OmniTab and ReasTAP.
- Maintains outperformance on tables of varying sizes, including large tables.
- Ablation study demonstrates each subcomponent (URS, parsing statement, cell highlighter, three loss functions) contributes positively.
- Smart use of ToTTo dataset to train the cell highlighter; the ~300 manually annotated parsing statement examples are a useful resource for the community.
- Paper is technically sound and well-written; Figure 2 is informative.
- Novel framework for table QA combining unsupervised relevance scoring with weak supervision.

### Weaknesses
- Model is complex, with multiple subcomponents of different natures, making it hard to build upon or reproduce; not end-to-end because the cell relevance loss is not learned.
- Computational cost may be extensive when the number of table tokens is large; no average inference latency comparison with baselines (e.g., OmniTab) is provided.
- The use of a latent variable for relevance (optimized probabilistically via VI) is then used as a scalar, creating inconsistency; a fully probabilistic model would be sounder. The description of variational inference (Section 3.1) is stated incorrectly (“model … as a latent variable … through VI” is imprecise).
- Missing experimental details: training procedure, hyperparameter settings, how the VI-related loss is used during inference (i.e., how relevance is predicted) are not given even in the appendix. The clustering model’s importance is unablated – would directly predicting a relevance probability work?
- Insufficient rationale for how the three loss functions interact; ablation shows all three together work best but the individual benefit of each loss is not clearly observable; no case studies illustrating where the improvement comes from.
- More ablation studies needed:
  - Replacing URS with BM25 or other off-the-shelf similarity metrics.
  - Using the original question (instead of parsed text) for the cell highlighter.
  - Using a direct indicator for cell value instead of the full parsing statement.
- The paper does not motivate the practical utility of dedicated table QA, given that open-domain QA systems could handle linearized tables. Also, the related work should discuss recent LLM-guided GNN models for QA (e.g., EACL 2023, AAAI 2020).
- Dataset statistics should be summarized in tabular form; the datasets are relatively small-scale (thousands of nodes) and results would be more conclusive on larger datasets. Runtime and memory complexity analysis is needed for scalability.
- Performance of the cell highlighter on the ToTTo validation set is not reported; no qualitative evaluation on sampled examples from FeTaQA, WikiTQ, WikiSQL showing the quality of the parsing statement generator.
- If the parsing statement quality is high but putting more weight on it degrades performance, that is an interesting point to discuss but is not addressed.
