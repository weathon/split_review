## Merged Review

### Summary
The paper proposes Relational Convolutional Networks (RelConvNets) for learning hierarchical relational representations. Key components: Multi-Dimensional Inner Product Relation (MD-IPR) module computes pairwise relation tensors; relational convolution with graphlet filters extracts higher-order relational features; grouping layers enable soft grouping for scalability. The architecture is analogous to CNNs. Evaluated on relational games and the SET card game, showing sample efficiency and strong performance, especially on SET where other models fail to learn.

### Strengths
1. **Intuitive and interpretable architecture**: Relational convolutions are analogous to CNNs, providing inspectable learned filters (R1). Design choices are general and non-arbitrary (R2). One reviewer (R3) views it as a novel graph-like CNN for processing images.
2. **Sample efficiency**: More sample-efficient on relational reasoning tasks compared to Transformers and other baselines lacking explicit relational structure (R1, R4).
3. **Strong performance on specialized tasks**: Particularly impressive result on the SET card game; other models unable to learn it (R2). Good performance on SET dataset (R4).
4. **Disentangled relational vs. non-relational features**: MD-IPR encourages this via inner products (R1).
5. **Learns higher-order relations without explicit modeling** (R4).
6. **New perspective on Transformers**: Discusses Transformers as message-passing with implicit relations (R2).
7. **Technically sound** with promising experimental performance (R3).

### Weaknesses
1. **Limited scaling and computational analysis**: MD-IPR grows quadratically ($n \times n \times d_r$); relational convolution considers all groups of size $s$ (exponential). Grouping helps but no parameter/FLOP metrics reported. No systematic experiments varying number of objects; experiments use small input sizes (R1). Claims of parameter efficiency lack analysis (R4).
2. **Evaluation on simple synthetic tasks**: Main benchmarks (relational games, SET) involve at most second-order relations, fixed small numbers of objects. No tasks requiring higher-order relations or variable larger numbers. Evaluation is a toy example; paper lacks discussion of real-world applications where hierarchical relational reasoning is crucial (R1, R2).
3. **Missing comparisons to recent related works**: Cites PrediNet, CoRelNet but does not compare to Abstractors, Graph Transformers, Relation GNNs, or other contemporaneous methods (R1, R3). Head-to-head comparisons needed to clarify unique advantages.
4. **Lack of qualitative interpretability analysis**: Despite claims of interpretability, no visualization or analysis of learned graphlet filters or group matrix $G$ (e.g., for SET: do dimensions correspond to color, shape, number?). This would strengthen interpretability claims (R2, R4).
5. **Technical details need clarification** (R3): (a) Fig.2 needs more explanation (symbol definitions, how pooling on graph works). (b) Motivation and details of attention-based pooling in relation convolution. (c) In experiments, are pixels treated as tokens (like Transformer) or patches (like ViT)?
6. **Architecture depth vs. task requirement**: Appendix Table 2 uses only one layer of MD-IPR and RelConv before MLP, but second-order relations may need two layers. How does the model accurately model SET and match pattern? Missing ablation/explanation (R2).
7. **Grouping design choice not justified**: Why use a learned matrix of size $m \times n_g$ instead of a simpler linear transform of size $|\mathcal{G}| \times n_g$? No explanation given (R2).
8. **No discussion of extension to knowledge graphs**: Reviewer 4 suggests this could aid interpretability due to hierarchical relationships, but it is not addressed.
9. **Reviewer disagreement**: One reviewer (R2, score 8) was significantly more positive about contributions, presentation, and the SET result; others (R1, R3, R4) were more critical, particularly on evaluation scope, comparisons, and analysis.
