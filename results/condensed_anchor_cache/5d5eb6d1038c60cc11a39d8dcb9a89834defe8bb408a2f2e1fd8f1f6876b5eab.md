## Merged Review

### Summary
The paper presents MathCoder2, a family of LLMs enhanced through continued pretraining on the MathCode-Pile dataset – a 19.2B‑token corpus combining math‑related web data, textbooks, synthetic data, and code using mathematical packages. The key innovation is pairing natural‑language reasoning steps with executable Python code by first extracting LaTeX expressions, their conditions, and results, then generating code that captures the reasoning process. Training base models such as Llama‑3‑8B, DeepSeekMath‑7B, and Code‑Llama‑7B on this corpus yields significant improvements on benchmarks like MATH and GSM8K. The entire data processing and training pipeline is open‑source.

### Strengths
- **Innovative methodology:** Pairing natural‑language reasoning steps with executable Python code via extraction of LaTeX expressions, conditions, and results is a novel approach that extends prior work on code‑augmented math reasoning.
- **High‑quality dataset:** MathCode‑Pile (19.2B tokens) is meticulously curated from diverse sources (web data, math textbooks, synthetic data, mathematical code), ensuring relevance and reducing noise.
- **Significant performance gains:** Continued pretraining on MathCode‑Pile leads to notable improvements across multiple models and benchmarks (MATH, GSM8K), demonstrating the effectiveness of the code‑paired reasoning data.
- **Clear presentation:** The paper is well‑organized with effective figures and tables that illustrate the data pipeline and evaluation results.
- **Reproducibility and transparency:** Full release of data processing and training code supports community validation and future work.

### Weaknesses
- One reviewer found no major weaknesses, but reviewers 2 and 3 identified several issues. The more critical reviewer (score 6) raised concerns about generalizability, evaluation clarity, scope, and ablation depth, while the other (score 8) noted a missing analysis.
- **Generalizability to advanced mathematics:** The method’s applicability beyond grade‑school‑level math is unclear. It relies on Python code generation for problems with clear computational solutions and may not extend to abstract algebra, advanced calculus, or symbolic manipulation that require formal proof assistants like Lean or Coq.
- **Evaluation uncertainty:** It is not clearly specified whether the generated Python code is executed during benchmark evaluations or only used during pretraining. If code execution is not part of inference, the practical impact of the code generation component is diminished.
- **Scope limitation:** The paper does not explicitly state that the dataset and method are primarily designed for high‑school‑level mathematics, potentially misleading readers about broader applicability to advanced mathematical reasoning.
- **Ablation study depth:** The ablation studies do not fully explore whether the paired alignment of reasoning steps and code is critical, or if treating them as independent training signals would yield similar improvements. Specifically, an ablation that separates reasoning steps and code into independent examples is missing.
- **Data leakage analysis:** The paper lacks an analysis of potential data leakage between MathCode‑Pile and the evaluation benchmarks, which could artificially inflate reported performance.
- **Missing analysis on non‑math domains:** The impact of the math‑focused dataset on performance in other domains (e.g., general coding abilities beyond math tasks) is not evaluated, leaving it unclear whether the specialization harms broad capabilities.
