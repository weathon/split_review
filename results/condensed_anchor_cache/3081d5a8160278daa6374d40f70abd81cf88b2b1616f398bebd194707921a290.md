## Merged Review

### Summary
The paper proposes EmbedLLM, a framework for learning compact vector embeddings of LLMs to facilitate model routing, task allocation, and benchmark performance forecasting. It uses an encoder–decoder (matrix factorization) approach: an LLM’s behavior on existing data points (binary correctness labels) is used to produce an embedding that can predict performance on new data points and benchmarks without running the model. Experiments on 112 large models show improvements in routing accuracy and latency, and that embeddings capture task-specific strengths (e.g., coding ability). The method is described as simple and intuitive, but several reviewers note that key details and motivation need clarification.

### Strengths
- Novel and useful framing of LLM embeddings for efficient model management and comparison (Reviewer 1, 2).
- Compact representations capture model strengths/weaknesses, enabling task-specific decisions without re-running each model on every input (Reviewer 1).
- General-purpose embeddings adapt to downstream tasks without retraining the models themselves; beneficial when computational resources are limited (Reviewer 1).
- Comprehensive experiments: tested on 112 large models (Reviewer 2).
- Once an embedding is built, performance can be estimated without access to the underlying model (Reviewer 3).
- Simple and intuitive method overall (Reviewer 3).

### Weaknesses
- **Terminology confusion (all three reviewers):** Calling the prediction module a “decoder” is misleading—it is simply a binary classifier (Reviewer 1, 3). The term implies a generative process whereas the model only outputs a label. Using “linear classifier applied to the Hadamard product of question and model embeddings” would be more accurate (Reviewer 3).
- **Scalability concern (Reviewer 1):** The embedder must be retrained to represent new models, making the framework non‑scalable. The paper should provide cost metrics for retraining vs. traditional benchmarking.
- **Encoding based solely on model IDs (Reviewer 2):** With only 30k training data points, can the embedding truly capture all model characteristics, especially for complex reasoning? The approach treats each model entirely as a black box.
- **Architecture clarity (Reviewer 2):** Figures 1–3 are similar and do not clearly illustrate the training, input, and output process; the overall architecture was not understood until Section 4.1.
- **Model scale not categorized (Reviewer 2):** Experiments do not separate models by scale; larger models may show smaller performance differences. The authors’ view on this issue is missing.
- **Underspecified baselines (Reviewer 3):** The kNN classifier description lacks the distance metric and tie‑handling method; the “random routing” baseline is vaguely described, making comparison difficult.
- **Missing references (Reviewer 3):** No citation of highly similar work (e.g., Xia et al. Predicting Performance for Natural Language Processing Tasks, 2020).
- **Motivation and justification (Reviewer 3):** The core assumption—that a model’s behavior on unseen data can be inferred from its behavior on existing data—needs stronger justification. It is not immediately clear why matrix factorization is the most suitable approach given the high dimensionality and potential non‑linearity of LLM behaviors.
- **No embedding analysis/visualization (Reviewer 3):** The histogram in Figure 6 is not informative; TSNE plots of the learned embeddings would be valuable. Reviewer 3 explicitly requested this.
- **Output confusion (Reviewer 2):** Why are two values (p(m,q)_0 and p(m,q)_1) output at line 256–257? Is it simply for a non‑linear operation?
- **Binary label limitation (Reviewer 3):** Why does the method assume binary correctness labels? Is this a limitation of the approach?
- **Unclear notation (Reviewer 3):** Lines 264–267 are unclear: what do `mxp` and `nxp` represent?
- **Prompt embedding impact (Reviewer 3):** Does the choice of prompt embedding affect results? For instance, using more recent LLM‑based embeddings.
- **Qualitative discussion missing (Reviewer 3):** How does the method behave when new data points are widely different from seen data? A qualitative example would be useful.
- **Minor citation error (Reviewer 3):** Vaswani et al. should be 2017, not attributed to LLMs.
- **Naming inconsistency (Reviewer 3):** The method should be named “EmbedLLM” rather than “Matrix Factorization.”

**Reviewer disagreement:** One reviewer (Reviewer 2, score 8) was more positive, praising the innovation and comprehensiveness of experiments. The other two reviewers (scores 6 each) found significant presentation and clarification issues. Reviewer 3 noted willingness to raise the score if presentation and qualitative analysis improve.
