## Merged Review

### Summary
The paper proposes an unsupervised model for instruction-based image editing that removes the dependency on ground-truth edited image triplets (input, edited, instruction) during training. It introduces Cycle Edit Consistency (CEC): applying a forward and backward edit in one step and enforcing consistency in image and attention space using CLIP. The method is trained on real image-caption pairs or triplets, and evaluated on MagicBrush test data. Three reviewers acknowledge the meaningful motivation and clear presentation, but raise concerns about training efficiency, evaluation rigor, and incomplete ablation.

### Strengths
- **Motivation is meaningful and well communicated**: Removing the need for triplet datasets and reducing biases in instruction-based editing is an important problem. The motivation is convincing and clearly presented (R1, R2, R3).
- **Novel application of cycle consistency**: While cycle consistency is known (e.g., CycleGAN), proving it works for instruction-based image editing is a contribution (R2).
- **Detailed experiments**: Evaluation covers quantitative, qualitative, and user studies. Single-turn and multi-turn editing are examined across different datasets (R3).
- **Easy-to-follow presentation**: The paper is well-written and the reasoning is understandable (R1, R2).

### Weaknesses
1. **Backpropagation efficiency**: The multiple consistency losses (image, pixel, attention) require backpropagating through the full diffusion process (from last step to first), which is computationally expensive and needs large GPU memory. The paper does not discuss this cost (R1 – minority, score 5, more critical).
2. **Cycle consistency does not guarantee good edits**: The forward-backward cycle can maintain consistency even if the forward edit is poor or biased. The loss only ensures reversibility, not disentangled high-quality editing. For example, if InstructPix2Pix pre-trained weights produce bad intermediate edits, the cycle could still close. Which loss contributes most is unclear from Table 4 (R1).
3. **Structure preservation not ensured**: CLIP similarity loss may drive the edit toward the instruction semantics but does not inherently preserve structure; an edited image that differs radically in layout could still be reversed. This needs elaboration (R1).
4. **Insufficient evaluation breadth**: Compared only on MagicBrush test data; more diverse editing types and datasets such as PIE should be evaluated (R1). Additionally, without ground truth, accurate comparison is difficult. In Figure 4, the proposed method does not clearly outperform baselines (HIVE, MagicBrush, MGIE, MAIE, InstructPix2Pix, SmartEdit) – e.g., R2 prefers HIVE in row 1, MagicBrush in row 2, MagicBrush/MGIE in row 3, MGIE in row 6, MAIE in row 8, InstructPix2Pix/SmartEdit in last row (R2).
5. **Attention map consistency unclear**: Which attention maps (at which timestep) are enforced? Since forward and reverse processes are opposite, attention maps can differ. More visualization and clarification needed (R1).
6. **Incomplete ablation**: The paper only ablates L_sim and L_attn (Table 4). Other losses (L_cyc, L_mask, etc.) are not ablated. Moreover, the method involves many loss functions, making it hard to find the best checkpoint (R3).
7. **Multi-turn results not shown**: The paper mentions multi-turn editing but does not provide explicit results or examples (R3).
8. **Pre-training dependency**: The method uses InstructPix2Pix as backbone – does it start from pre-trained weights or from scratch? Can it be trained from Stable Diffusion checkpoint directly? Requires paired instruction pre-training? (R2, R3).
9. **Fewer DDIM steps phenomenon**: Observation that UIP2P can edit successfully in fewer DDIM steps, but no explanation is offered (R3).
10. **CLIP loss confusion**: In Fig.3, CLIP loss is added only between input image and edited image. Why is it not also applied to the reconstructed image? The purpose of this selective application is unclear (R3).
11. **Minor formatting issue**: Equations are not numbered (R1).

*(Reviewer disagreement: R1 is more negative overall, raising fundamental concerns about backpropagation cost and edit quality guarantees, while R2 and R3 are overall positive but note comparison difficulties and incomplete ablations.)*
