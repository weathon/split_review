## Merged Review

### Summary
This paper introduces Agent Security Bench (ASB), a comprehensive framework to formalize, benchmark, and evaluate attacks and defenses for LLM-based agents. ASB covers 10 scenarios (e.g., e-commerce, autonomous driving, finance), 10 agents, over 400 tools, 23 attack/defense methods, and 8 metrics. It benchmarks 10 prompt injection attacks, a memory poisoning attack, a novel Plan-of-Thought (PoT) backdoor attack, a mixed attack, and 10 defenses across 13 LLM backbones with nearly 90,000 test cases. Results show high vulnerability (average ASR 84.30%) and limited defense effectiveness.

**Reviewer disagreement:** Three reviewers scored 8 (highly positive), one scored 3 (negative). The negative reviewer found the evaluation unrealistic and insufficiently justified, while positive reviewers praised the framework’s comprehensiveness and scale. This contrast is preserved throughout.

### Strengths
- **Comprehensive framework:** Covers diverse attack types (DPI, OPI, memory poisoning, novel PoT backdoor) and defense strategies across 10 real-world agent scenarios with tailored tools/tasks. Includes over 400 tools and 13 LLMs.
- **Structured metrics:** Provides Attack Success Rate (ASR), Refuse Rate (RR), and others (including Performance Not under Attack – PNA – though its computation is questioned). Enables systematic evaluation.
- **Large-scale testing:** Nearly 90,000 test cases across multiple models (including GPT-4, Llama, Gemma2-9B, etc.) provides statistical evidence of vulnerabilities.
- **Novel Plan-of-Thought (PoT) backdoor attack:** Targets the hidden system prompt, a unique vector not covered by standard DPI/OPI. Formalized mathematically, enabling reproducibility.
- **Valuable systemization:** Unifies different prompt injection and poisoning attack types under a single cohesive framework, including effective mixed attacks combining multiple vectors.
- **Interesting finding – “Larger Models Tend to be More Fragile”:** Figure 2 shows correlation between LLM leaderboard quality and ASR; larger models are more likely to follow attacker instructions. (One reviewer noted this conclusion is simplistic without context from no-attack performance.)
- **Open-source and usable** (easy to run code, per R1).
- **Defense analysis** (e.g., paraphrasing, PPL detection) is discussed as relevant for securing agents, though effectiveness is limited.

### Weaknesses
- **Limited new insights beyond known vulnerabilities:** The main conclusion that agents are vulnerable at multiple stages is already established in prior work (R3). The paper could provide deeper comparative analysis of attack/defense trade-offs to highlight design spectra (R3).
- **“Larger Models Tend to be More Fragile” is oversimplified:** The claim that larger models have higher ASR because they “follow attacker instructions more” is not critically examined. Without presenting ASR alongside no-attack PNA (e.g., from appendix), the result confounds capability with security. One reviewer (R1) requested results combining ASR with PNA for proper context.
- **Attack realism concerns:**
    - *Direct prompt injection:* Adversary is assumed to control the full user prompt, making the problem under-defined and the attack trivial; there is no way to distinguish user from adversary instructions when the adversary controls the entire input (R2).
    - *Tool call evaluation:* The benchmark checks *if* a tool is called, but not *correctness of arguments* (e.g., JSON format, specific parameters). This makes attacks too easy and misses realistic security requirements (R2). The authors state they did not set tool parameters “to simplify tool-calling,” but this conflates model capability with security evaluation (R2).
    - *Simulated tool calls* (not real APIs) and ReAct framework instead of official APIs may not capture real-world vulnerabilities. The 20-line threshold for attack success seems arbitrary; more justification is needed (R2, R3).
- **Terminology issue:** “Observation Prompt Injection” is introduced while “Indirect Prompt Injection” is already standard; the reason for repurposing is unexplained (R2).
- **PoT backdoor motivation is unclear:** It assumes an adversary who controls the system prompt but not the API. If the adversary is the API provider, the user has no defense, making the attack unrealistic (R2). Defense against this vector is also underexplored (R4).
- **Missing qualitative analysis:** Heavy reliance on quantitative metrics (ASR, RR) obscures how and why attacks succeed in specific scenarios. Case studies (e.g., e-commerce) are needed to show operational context, such as the role of human oversight or task context in making attacks damaging (R4). ASR does not explain stealthiness or practical impact (R4).
- **Defense utility unclear:** Defenses appear only in the appendix; the main text should highlight both effectiveness and impact on agent performance. For some models (e.g., Gemma2-9B), PNA is very low, raising questions about metric validity (R2). The paper does not propose substantial new defenses, and analysis of why current defenses fail is superficial (R3).
- **Comparison with existing benchmarks (InjecAgent, AgentDojo) is insufficient:** The paper should elaborate on prior limitations versus ASB’s advances (R4).
- **Unexplained metrics:** The difference between PNA and BP is not clearly defined, and several introduced metrics are barely shown (R2).
- **Requested analysis:** Why do some models have higher ASR than PNA? (R2). How would memory poisoning or mixed attacks impact a specific real-world use case (e.g., financial services)? (R4). Could more advanced defenses (dynamic prompt rewriting, context-aware anomaly detection) be considered, and what are the challenges? (R4).
