## Merged Review

### Summary
CFGen is a flow-based conditional generative model for multi-modal single-cell count data (scRNA-seq and ATAC-seq). It uses a latent flow-matching framework with an autoencoder that decodes negative binomial and Bernoulli distributions to capture discrete, over-dispersed properties. Compositional classifier-free guidance allows conditioning on multiple attributes. The model is evaluated on data generation quality, rare cell type classification via data augmentation, and batch correction, outperforming baselines such as scDiffusion and scGAN.

### Strengths
- Adapting flow matching for single-cell data generation is a novel contribution.
- CFGen can be easily adapted for different uni- and multi-modal scenarios, as long as modality-specific autoencoders with a common latent space exist.
- The paper addresses an important problem by generating raw count values and extending generation to multimodal data (scRNA and ATAC).
- The paper is well-written; the authors convey major limitations of the model clearly, and the experimental setup is detailed with appropriately referenced related work.
- Results show CFGen captures statistical characteristics of the training dataset (e.g., sparsity, overdispersion) and generates cells with similar properties.
- The model is tailored to real biological settings: it handles two modalities and any number of attributes, with compositional guidance for multiple biological attributes.
- Practical applications are convincingly demonstrated: data augmentation for rare cell types improves downstream classification, and batch correction is effective.
- The idea to extend flow matching for generation with multiple attributes is interesting and important for single-cell biology.

### Weaknesses
- **Missing baseline:** scVI should be included as a baseline in Figure 2 because it accounts for overdispersion and zero inflation, unlike the current baselines (scDiffusion and scGAN).
- **Guidance strength selection:** The manuscript lacks a clear methodology for selecting the classifier guidance strength parameters for conditional generation. This choice is crucial for balancing fidelity and the conditional effect, making results difficult to reproduce and interpret. For batch correction, it is unclear whether CFGen’s Batch and Bio scores are sensitive to varying these parameters and how they should be tuned in practice.
- **Evaluation of compositional guidance:** Quantitative results are missing for evaluating compositional classifier guidance in Section 5.3. The authors should report the change in MMD and WD with respect to the target distribution when increasing guidance strength. Additionally, it is unclear how the authors ensure that generated cells at the intersection of two labels are not due to mode collapse (i.e., only a limited set of samples that happen to satisfy both conditions).
- **Classification evaluation improvements:** (a) For cell type classification, does data augmentation with CFGen improve performance for a simple logistic regression model? (b) Figure 4 should report raw accuracy numbers for each cell type to evaluate the effect of CFGen.
- **Figure clarity:** Figure 3 is unclear: add contrasting colors for points representing generated vs. real data; explain what the red points represent; add a quantitative metric such as an oracle model predicting the attributes. In Figure 2b, consider removing the bars because they obstruct observation of the overlapping density curves.
- **Multimodal training effect:** For Section 5.2, add a comparison with CFGen trained only on RNA data to measure the effect of using multimodal data for training.
- **Computational complexity:** The paper lacks discussion of computational complexity. A detailed breakdown of computational requirements (training and sampling times) for CFGen and baselines, especially scDiffusion which also requires multiple time steps, would improve the paper.
- **Imputation applicability:** It is unclear whether CFGen can be applied to gene expression imputation (inferring missing or zero-inflated values). The authors should clarify whether the current architecture or flow matching framework could be adapted for this task.
- **Novelty of negative binomial modeling:** Handling discrete count data via negative binomial is presented as a contribution, but many methods already use negative binomial or Poisson distributions for count data and overdispersion. The authors should justify why this aspect constitutes a contribution.
- **Factorization justification (Eq. 5):** What is the rationale behind conditioning the latent factor \(z\) on library size? This design choice requires thorough justification, especially since library size is often considered a technical artifact.
- **Conditional independence assumption (Proposition 1):** The attributes \(y_1, y_2, \dots\) are assumed conditionally independent given \(z\), but the factorization in Eq. 5 connects attributes to \(z\) via a V-structure. According to d-separation, this would cause attributes to be dependent given \(z\). This contradiction needs clarification.
- **Guidance scheme novelty:** The proposed compositional guidance differs from standard classifier-free guidance only in that some attributes (and one attribute during training) are fed to the decoder. The authors should clarify whether this is equivalent to standard dropout-based methods and specify the specific advantages of their approach.
- **Explanation for outperforming scDiffusion:** In Table 1, CFGen heavily outperforms scDiffusion. Since diffusion models can perform on par with flow matching (apart from training stability), the paper should provide a deeper explanation for this performance gap, considering architectural and training differences rather than just stating that CFGen performs better.
