## Merged Review

### Summary
The paper proposes GIFT4Code, which uses synthetic data and execution-derived feedback to generate natural-language input-output specifications for instruction fine-tuning of code LLMs. Evaluated on Arcade and DS-1000, the method shows improvements over the base model. Reviewers found the problem important and the design intuitive, but raised substantial concerns about novelty, baseline comparisons, evaluation sufficiency, reproducibility, practical applicability, and the clarity of the technical contribution. One reviewer (score 3) was significantly more critical of the motivation and baseline choices than the others (scores 5).

### Strengths
- The paper addresses an important problem: ambiguity of human intent in code generation, where input-output specification can concretize requirements. (R1, R2, R3, R4)
- The methodology for I/O-specification-grounded code generation is clearly presented; the comparison of performance between no context and full context is insightful. (R1)
- The core design of summarizing I/O as a natural-language specification is intuitive and smart, bridging the gap between constraints and the LLM’s semantic space. (R2)
- Fine-tuning with synthetic data yields a significant improvement on Arcade and a modest improvement on DS-1000 (even though 500 problems from that dataset were used for training). (R1)
- The benefits are reflected in both prompting and fine-tuning evaluation setups. (R2)
- Improving code generation from natural language is a timely topic. (R4)

### Weaknesses
**Novelty and Prior Work**  
- Bootstrapping LLMs with synthetic data from strong LLMs is well known. (R1)  
- Using execution feedback for synthetic data generation is also known (e.g., Code Llama). (R1)  
- The overall approach closely resembles CodeT (which also uses model-generated test cases); the paper fails to cite CodeT and does not clearly differentiate the two. (R3)  
- One reviewer (score 3) questioned the technical contribution, finding the motivation unclear. (R4)

**Evaluation and Baselines**  
- Missing comparisons with strong open-source and proprietary models such as GPT-4, Code Llama, and Llama-2-70B. (R1, R2)  
- The only 62B baseline is an anonymous code LLM already fine-tuned on data science data; 15B baselines perform comparably to the vanilla 62B, making that baseline weak and the comparison to WizardCoder vs. StarCoder uncontrolled. (R2)  
- No evaluation on standard benchmarks like HumanEval or MBPP to check for regression after fine-tuning. (R1)  
- Generalizability is unclear; the authors should also instruction-tune open-source code LLMs (e.g., Code Llama-7B, 13B, 34B) to show the method works beyond the anonymous model. (R2)  
- Baseline prompting is overly naïve (e.g., not providing necessary column-name information in Figure 1), and no evidence is given that users would omit such details from their prompts. (R4)  
- One base model performs worse with the TypeDesc spec than without. (R1)

**Practical Applicability and Motivation**  
- It is unclear how to obtain an I/O summary in realistic deployment: only human intent is available, there is no ground-truth code to execute for output summarization. The test-time simulation of noisy I/O still leaks ground-truth code. (R2)  
- The paper assumes that developers write I/O specifications similar to those used, but that may not be realistic. (R1)  
- For the examples in Table 1, the I/O information appears necessary; one reviewer (score 3) was confused why users would not already include it in the prompt, and questioned the practical value of the approach. (R4)

**Reproducibility and Missing Details**  
- No details are given on the architecture of the 62B base model (layers, hidden dimensions, positional encoding). (R2)  
- Training configuration (learning rate, duration, impact of hyperparameters) is absent. (R2)  
- Implementation and training data are not publicly available; a detailed reproducibility statement is needed. (R2)  
- The modest improvement on DS-1000, despite using 500 training examples from that dataset, raises questions about the method’s general efficacy. (R1)
