## Merged Review

### Summary
The paper provides a theoretical analysis of multi-task representation learning for two-layer convolutional neural networks trained with gradient descent, under a data model with task-shared and task-specific features. It derives generalization bounds showing that multi-task learning achieves asymptotically zero test error while single-task learning does not. Experiments on synthetic data and CIFAR-10-C illustrate the benefits.

### Strengths
- **Theoretical contribution.** The effort to theoretically analyze why multi-task learning generalizes better than single-task learning in a gradient descent setting is commendable (R1).
- **Originality.** The setting (shared input patches with task-specific noise) has not been tackled theoretically before; prior work assumed a single shared representation or used learning-theoretic analyses, while this work studies gradient descent dynamics (R2, R3).
- **Presentation.** The analysis is thorough, with detailed calculations, intuitive descriptions alongside formal statements; the notation, though involved in Section 5, is presented clearly (R2, R3).
- **Investigative value.** The idea of separating shared and task-specific features in neural network representation learning is interesting; the literature review is rich (R4).
- **Potential significance.** The mathematical tooling and modeling approach may inspire similar analyses for other problems (R3).

### Weaknesses
- **Oversimplification of networks and data.** The problem setup is a significant oversimplification of networks used in practice; implications for deeper or more complex networks are unclear and likely limited (R1). The analysis only covers two-layer CNNs and binary classification; it is unclear whether proof techniques scale to deeper networks or to multi-label/regression problems (R2, R3).
- **Assumptions about noise and features.** The data generating process places noise only on task-specific features, not on shared features. This assumption seems artificial and is not justified; in many MTL scenarios task-specific features may be noisy but shared features can also be noisy (R2). The model captures only one variant of MTL (different data sources, same output) and is closer to data augmentation than to the common MTL setting of different objectives over the same data (R3). **Minority view (R4, rating 3):** The setting (different noise in input X, same output categories Y) is essentially data augmentation, and the conclusions about shared vs. task-specific features are already known from the invariant/spurious feature view; the theoretical contribution is therefore not novel.
- **Experiments provide limited validation of theory.** The empirical results only show that multi-task learning outperforms single-task learning, which is already well-known (R1, R3). The experiments do not verify the predicted two-stage learning dynamics, convergence rates, or the lower bound for single-task learning (R2, R3). It is unclear how CIFAR-10-C experiments complement the theory given that the data generating process does not accurately model that dataset (R2). Ablations are missing: e.g., what happens if weight decay (regularization) is removed? Do the two stages appear? (R2). **Further experimental concerns (R1):** In synthetic experiments, given shared patches, task-specific patches, and noise patches, how can the total number of patches H be 2?
- **Mathematical exposition issues.** Parameter α in Definition 3.1 is expected to have a strong impact (as α→1 shared and task-specific features become identical), yet it does not appear in any derived quantities (R1). Symbols are not properly introduced: e.g., *n* and *polylog(n)* in Definition 3.3 – if *n* is the number of training examples per task, then the test error bound in Theorem 4.1 is counter-intuitive (larger *n* gives larger generalization error) (R1). Other undefined symbols: *c* in “Other Requirements” (page 4), *p* on page 5; Theorem 4.2 states test error = *poly(1/n)*, but it is unclear whether it should be *poly(1/(nK))* with K tasks (R3). The paper does not specify the number of examples in the multi-task setting; in the experiments the multi-task set is the union of single-task sets, meaning it has many more examples, which could trivially explain the improvement (R4, minority view).
- **Lack of discussion on assumptions.** The requirements at the end of Section 3 should be discussed in terms of how realistic they are (R1). The data generating process is narrow and may not capture many MTL problems in common benchmarks (R2). The model may be better thought of as analyzing data augmentation rather than general MTL (R3).
- **Missing comparisons and ablations.** No comparison to prior theoretical bounds (e.g., from Baxter, Maurer, Tripuraneni) to position the novelty of this analysis (R2). No ablation study verifying the two-stage learning process or the effect of noise levels (R2, R3).
