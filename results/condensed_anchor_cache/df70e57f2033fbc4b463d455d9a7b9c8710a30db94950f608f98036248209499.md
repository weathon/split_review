## Merged Review

### Summary
The paper proposes Probe Pruning (PP), an online dynamic structured pruning framework for LLMs that uses probing on a small subset of hidden states to identify important weights per batch, enabling dynamic pruning without fine-tuning. It consists of probing (selecting key hidden states based on residual importance and running them a few layers ahead), history-informed pruning (integrating probing and historical states), and full inference on remaining weights. Evaluated on LLaMA-2/3 and OPT, PP reports efficiency gains with minimal overhead (e.g., 1.5% FLOPs). However, reviewers consistently note trade-offs: speedups are limited (<2×), throughput can decrease, the method requires large batch sizes, and it does not reduce model storage. Some reviewers find the problem interesting and the approach novel; others question novelty and fairness of comparisons.

### Strengths
- The problem is interesting and novel (R3, R4). Dynamic pruning is a promising avenue, and PP brings novel aspects: probing and a new pruning metric (R4).
- The approach is well motivated: calibration dataset choice leads to different pruning structures, and selective importance estimation is a great idea (R3). PP leverages the insight that calibration datasets are not perfectly representative (R4).
- Importance tracking via history-informed pruning is liked (R3).
- The method is easy to implement without extensive hardware changes and provides real-time speedups on GPUs, critical for deployment (R1).
- Comprehensive experimental results across LLaMA-2, LLaMA-3.1, and OPT, with consistent outperformance of baselines (R2, R4). Good set of baselines (R4).
- Every design choice is carefully described and ablated (R1, R4). Full-Batch Pruning provides an upper bound to measure sampling effect; PP’s pruning mask is more similar to full-batch than fixed-prune (R4).
- Validates on text generation and reasoning tasks (R4).

### Weaknesses
- **Unfair comparison**: PP is a dynamic inference technique but mainly compared to static pruning. Static pruning reduces storage and gives consistent acceleration; dynamic pruning cannot reduce storage and acceleration varies per input (R2). Some reviewers note that PP does not beat FLAP and Wanda-SP in final speedups and performance boosts (Table 5, R1).
- **Lack of comparison to other dynamic inference approaches** (e.g., dynamic early exits, token-level dynamic decoding). Authors should discuss advantages over these (R2).
- **Not enough novelty**: The historical states method is similar to EMA or Memory Bank in contrastive learning; considered a trade-off rather than an essential solution (R2). (Contrast: R3, R4 found the approach novel and well-motivated.)
- **Absence of recent LLM evaluations**: lacks Llama 3.2 1B/3B, DeepSeekMoE, Mixtral-8x7B, and larger Llama 3 70B (R2).
- **Missing discussion of recent LLM pruning works**: Pruner-Zero (ICML 2024), Discovering Sparsity Allocation (NeurIPS 2024), Adaptive Layer Sparsity (NeurIPS 2024) (R2).
- **Calibration data concerns**: Method is not zero-shot; it relies on a calibration set. Section 5 lacks detailed calibration dataset descriptions, raising concern that probing may look into final test data, making comparison unfair to zero-shot methods. Calibration set should be kept same across methods (R1).
- **Figure 3**: zero probe sequence ratios are all below the reference line – reason unexplained (R1).
- **Probing overhead**: Speedup is limited to <2× (R1). Improvement in perplexity comes with reduction in model throughput (Table 5, R3). End-to-end inference measurements are needed to prove that benefits of probing + dynamic pruning outweigh costs (R4).
- **Batch size limitation**: Method relies on rather large batch sizes and sequence lengths to generate a probe; many inference setups have small batch size (down to 1) and the auto-regressive phase dominates (one token at a time). Does PP speed up the auto-regressive phase? (R4)
- **No comparison against Minitron** (arXiv 2408.11796). For LLaMA3.1-4B, Minitron (50% pruning) achieves HellaSwag 76.1 while PP (40% pruning) achieves 65.3, so it is unclear if PP beats SOTA (R4).
- **Pruning metric**: Empirical data shows superiority but no theoretical justification (R4). Further explanation needed on why the proposed metric (Wanda with squaring) is superior (R4).
- **Clarity and exposition**: Paper is written in a complicated way; idea and method can be described more intuitively (R3). The concept of “residual importance” is unclear before page 5; likely it is the L2 norm of the hidden state – should be introduced earlier and simplified (R3). “Full-Batch Probing” is not clearly distinguished from standard structured pruning (R3).
- **Limitations not highlighted**: Table 1 does not mention that the entire model must be loaded (R3). The paper does not specify what is pruned exactly: heads, MLP intermediate dimension, hidden dimension, layers? (R3)
- **Batch composition**: Evaluations assume the whole batch consists of a single task; performance degradation is expected with mixed batches (R3). Will history-informed pruning counterbalance limited sampling when batch size or sequence length is small? (R4)
- **Empirical evidence needed**: The claim on page 1 about calibration datasets overlooking batch-dependent outlier properties requires empirical support (R3).
- **Full-Batch Probing outperforms all methods** in Tables 2-3 – is it because the pruning mask changes between batches? (R3)
