## Merged Review

### Summary

This paper extends the forward-forward (FF) algorithm to graph neural networks (GNNs), proposing ForwardGNN, a forward-only learning procedure that avoids backpropagation constraints (e.g., storage of forward activations, non-local gradient signals). The method builds on Hinton’s FF but replaces the two-forward-pass (positive/negative) design with a single forward pass, incorporates top-down signals from higher layers, and uses virtual nodes for node-level tasks. Experiments on five real-world datasets (node classification and link prediction) with three GNNs (GCN, GAT, SAGE) show that ForwardGNN performs on par with or better than backpropagation while using less memory in some configurations. The work is novel in adapting FF to graphs and provides model-agnostic algorithms. However, reviewers highlight several weaknesses: insufficient motivation specific to graph learning, missing comparisons with related layer-wise/forward-only GNN methods, non-standard evaluation splits, lack of training time analysis, ambiguous details (e.g., virtual node role, optimizer setup), and potential over-squashing or memory overhead issues.

### Strengths

- **Novel application and adaptation**: The paper systematically investigates forward learning for GNNs, extending the forward-forward algorithm with several technical contributions: a single forward pass (no negative data), node-label-based learning, virtual nodes for node classification, and top-down signal incorporation. (Reviewers 1, 2, 3, 4)
- **First FF outperforming BP**: This is the first instance where a forward-forward variant achieves performance matching or exceeding backpropagation-trained deep neural networks on real-world tasks. (Reviewer 4)
- **Comprehensive experiments**: Extensive experiments on five datasets and three GNN architectures demonstrate effectiveness and training efficiency (e.g., memory usage). (Reviewers 1, 2)
- **Model-agnostic and general**: The proposed algorithms are architecture-agnostic and could inspire further forward-forward research. (Reviewer 4)
- **Well written and structured**: The paper is clear and the incorporation of top-down signals is a clever intuition. (Reviewer 3)

### Weaknesses

- **Motivation not clearly graph-specific**: The paper does not adequately articulate what specific problems of backpropagation on *graphs* (beyond general NN limitations) motivate forward learning. The three points (scalability, parallelism, flexibility) are not graph-related. A stronger graph-focused motivation is needed. (Reviewers 1, 4)
- **Missing comparisons with related layer-wise / forward-only GNN methods**: The paper does not differentiate itself clearly from existing layer-wise training of GNNs (e.g., L2-GCN [You et al., CVPR 2020]; greedy layerwise learning [Belilovsky et al., ICML 2019]; GFF by Paliotta et al., specifically for GNNs; Decoupled Greedy Learning of GNNs). Including experiments with these baselines and explaining how the proposed method goes beyond them (e.g., does it truly avoid backprop within each layer?) would strengthen the contribution. (Reviewers 2, 3, 4)
- **Non-standard data splits**: In node classification, the paper uses 64% of nodes for training, which deviates from the standard semi-supervised practice (e.g., GCN, GAT, SAGE use very few labels). This makes results hard to compare with prior work. Experiments on limited training data are needed, as the method may be sensitive to label quantity. (Reviewers 1, 4)
- **No training time analysis**: Only memory efficiency is reported; training time is missing. Forward-forward is often a time-for-space trade-off, so the overhead must be measured. (Reviewers 1, 3, 4)
- **Virtual node design and over-squashing risk**: It is unclear whether virtual nodes are treated as standard nodes (with initial features, sending/receiving messages) or only as receivers. Since each class has one virtual node connected to many real nodes, this creates a bottleneck prone to over-squashing, especially for large graphs with few classes. An analysis of this effect (e.g., varying graph scale or class count) is missing. (Reviewer 3)
- **Optimizer details not provided**: In Algorithms 1–4, the step “optimize layer using the computed loss” lacks specifics: which optimizer (SGD, Adam?), learning rate schedule, and how hyperparameters were tuned. This hampers reproducibility. (Reviewer 4)
- **Figure 2 is cluttered**: The upper-left corner contains too many overlapping methods, making it hard to read. A table (simpler than Tables 2/3) would be clearer. (Reviewer 4)
- **Performance degradation of SF-Top-To-Loss with depth**: In Table 2, SF-Top-To-Loss achieves state-of-the-art with one layer but its performance degrades with more layers. An explanation (e.g., overfitting, noisy gradients) is needed. (Reviewer 4)
- **Best method varies across datasets**: The optimal method differs per dataset; the paper should provide intuition based on dataset characteristics (e.g., graph density, label correlation). (Reviewer 4)
- **Memory overhead for some methods**: In Table 3, some ForwardGNN variants use up to 20× more memory than backpropagation (e.g., on GAT). This could be a major bottleneck for large graphs and needs discussion. (Reviewer 4)
- **Generality to other tasks**: The paper focuses on node classification and link prediction. It is unclear whether the approach can be applied to graph classification or non-graph tasks. If not, the unique graph properties that enable the method should be explained. (Reviewers 2, 3)
- **Minor**: Algorithms 1, 2, 3 are mentioned but not in the main paper; this should be clarified. (Reviewer 3)
