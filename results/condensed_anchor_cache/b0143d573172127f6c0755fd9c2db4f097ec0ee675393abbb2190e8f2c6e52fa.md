## Merged Review

### Summary

The paper introduces TAIL, a framework for continual imitation learning that adapts large pretrained models (GPT2 backbone, CLIP encoders) to new control tasks by adding small, task-specific parameter-efficient fine-tuning modules—specifically LoRA, Bottleneck Adapters, and Prefix Tokens—while keeping the base model frozen. Evaluated on the LIBERO robotic manipulation continual learning benchmark, TAIL with LoRA (rank r=8) is shown to outperform full fine-tuning and other baselines in forward transfer and backward transfer, using only 1% of the trainable parameters.

### Strengths

- The paper is well-written, clearly structured, and easy to follow; the motivation for studying task-specific adapters in continual imitation learning is well justified.
- Extensive experiments on the LIBERO benchmark provide a thorough comparison of PEFT techniques, with convincing results that TAIL with LoRA outperforms existing baselines in both forward and backward transfer, while using only 1% of the trainable parameters of full fine-tuning. The evaluation is multi‑angle (performance, retention, parameter count, compute) and includes sufficient ablations (e.g., LoRA rank, hyperparameter sweeps).
- The method is intuitive and simple, with low overhead for each new task; it mitigates catastrophic forgetting more effectively than experience replay (ER) and avoids plasticity loss compared to full fine-tuning.
- The practical recommendations for fine-tuning large models (e.g., LoRA settings) and the ability to run experiments on a single GPU make the work useful for many practitioners.
- One reviewer (score 8) considers the amount of results and experiments to merit acceptance, and notes that the insights for fine-tuning will support future work.

### Weaknesses

1. **Limited novelty.** The framework is an umbrella term that directly applies existing PEFT methods (LoRA, Bottleneck Adapter, Prefix Token) without substantial modification or creative combination. Using separate adapters per task to avoid forgetting has been explored in prior work (e.g., Rebuffi et al. 2017, RoboAdapter). The paper lacks a detailed discussion of how TAIL’s integration techniques fundamentally differ from prior adapter-based methods. One reviewer (score 5) considers the contribution incremental.

2. **Unfair comparison with baselines.** TAIL uses task‑specific adapters that inherently prevent forgetting (since each task has its own dedicated parameters), while baselines such as full fine-tuning, EWC, and ER must overwrite shared weights. This gives TAIL an inherent advantage; a more apples‑to‑apples comparison would include baselines that also add per‑task parameters (e.g., Mixture‑of‑Experts methods). The difference in the number of trainable parameters also confounds the comparisons. Additionally, it is unclear whether task IDs are used only for adapter selection or also in training, which would further bias the comparison.

3. **Evaluation is limited to a single benchmark.** All conclusions are drawn only from LIBERO, a single robotic manipulation dataset. Generalizability to other robot control tasks (e.g., Franka-Kitchen, Metaworld, RGB-Stacking) and to different embodiments (e.g., different arm dynamics) remains unverified. Moreover, the baselines (especially RoboAdapter) may not have been optimally tuned for LIBERO—their default configurations were originally designed for other tasks—so the comparison may not reflect their best performance.

4. **Questionable evaluation metric.** The paper uses validation error (over 10 validation episodes) as a proxy for performance, but prior work shows validation error does not necessarily correlate with task success rates. Direct evaluation of success rates is needed. The paper also omits basic baselines such as the success rate of the expert demonstrations and of a random policy, making it hard to assess absolute performance and whether the method is overfitting.

5. **Scalability concern.** The number of adapters grows linearly with the number of distinct task instructions. Since each new task (defined by instruction and initial state) adds a new adapter, the memory footprint becomes a practical concern unless adapter sharing via task similarity is introduced (as hinted in the appendix).

6. **Redundancy of backward transfer metric.** Because TAIL uses separate adapters per task that are not updated when later tasks are learned, achieving a BWT of exactly 0 is expected and self‑evident; using BWT as a performance indicator for TAIL is arguably redundant.

7. **Unclear description of evaluation setup.** The definition of “validation scene” is not explained. It is also unclear whether ER retrains from scratch or continues from current parameters (which could cause plasticity loss). The description of how the best FWT model is selected for each task and how that affects BWT calculation lacks clarity.

8. **Missing experiments and ablations.**  
   - No results on combining multiple integration techniques (e.g., LoRA + P‑Tuning) are provided.  
   - Ablation studies on LoRA rank are limited; it would be informative to test ranks up to the GPT2 hidden dimension (e.g., 32, 256, 512, 768) to understand the effect of parameter count.  
   - Per‑task success rates are not reported, leaving open whether adapters are well‑specialized or perform similarly across tasks.

9. **Minor issues.**  
   - Page 2: “It is” should be “it is”.  
   - Figure 2: The colors for “Prefix Token” and “Frozen” are difficult to distinguish.  
   - Acronyms (e.g., TAIL) are defined multiple times; they should be defined once and used consistently.  
   - The term “limited data” for the 10‑episode validation setup is not clearly contextualized.
