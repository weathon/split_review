## Merged Review

### Summary
The paper introduces Wonderful Team, a multi-agent Vision-Large Language Model (VLLM) framework for zero-shot robotics. It uses interconnected agents for high-level planning, subgoal verification, target grounding, iterative refinement, and memory updates, without fine-tuning. The system is validated on simulated (VIMABench) and real-world tasks, including manipulation, goal-reaching, and visual reasoning. Reviewers agree that integrating task and motion planning is important and that the system’s iterative refinement and self-correction are beneficial for long-horizon tasks. However, they raise concerns about overclaiming, missing details on low-level execution and action space, limited task diversity, insufficient comparisons with related methods (MOKA, TAMP, RT-2, OpenVLA, Embodied CoT), and lack of justification for exclusive VLM use. While one reviewer (R1, score 5) found the system design and appendix very strong, the other two (R2 and R3, both score 3) found novelty limited and evaluation weak.

### Strengths
- Very good system design: iterative refinement and memory updates are critical for long-horizon reasoning and precise actions, often overlooked in prior multi-agent VLM robotics works (R1).
- Detailed appendix including ablation studies, task details, and comparisons with additional baselines (PIVOT underperforms direct-output GPT-4o). Section A showing the progress of VLM backbones is appreciated (R1).
- Integrating task and motion planning is important (R2).
- The system utilizes VLMs’ reflection capabilities, enabling iterative refinement and self-correction, beneficial for long-horizon tasks (R2).
- Interesting presentation structure with rhetorical questions to explicitly discuss problems in using (V)LMs for robot control and potential solutions (R3).
- Breaking up the robotic control stack into sub-”teams” is sensible and parallels ROS’s node communication architecture (R3).

### Weaknesses
- **Overclaiming and scope inflation.** The system is not a complete robotics solution; it outputs 2D/3D points that must be converted to joint torques for execution. The title, abstract, and introduction should be rewritten with appropriate scope (R1). The term “robotics problems” is too broad – the evaluation covers only manipulation tasks (R2). The claim of handling “unstructured environments” (e.g., cluttered scenes) is unsubstantiated (R2).
- **Missing critical details on low-level execution and action space.** It is unclear how the robot executes VLM outputs in implicit goal planning (Sec. 5.2) and spatial planning (Sec. 5.3) tasks (R1). The action space is not defined: how is it parameterized, and how does the VLM choose actions? (R3). The action primitives in VIMABench appear to be only pick-and-place; it is unclear whether the VLM can generate more complex actions such as unscrewing a cap using image coordinates (R2). The model’s depth determination mechanism and how occlusions are handled are not explained (R2). No comprehensive list of agents or their specific roles is provided (R3).
- **Evaluation gaps and contrived tasks.** In VIMABench, almost half of the tasks are not included in the comparison with baselines (Fig. 9). This is a red flag; the main text must clearly state which tasks are used and how many trials are performed per method and baseline (R1). The evaluated tasks appear extremely contrived: the superhero snack task requires little semantic reasoning (just color matching), and the fruit price task mainly tests GPT-4o’s basic math ability rather than physical motion complexity (R3). Task diversity is limited, predominantly consisting of simple pick-and-place actions (R2). The system only works with well-calibrated front and overhead views, a limitation not explicitly stated (R1).
- **Unclear justification for exclusive VLM use and missing hybrid considerations.** Motivating examples are poorly supported empirically; e.g., the VLM fails to generate bounding boxes for grapes, but specialized models (grounding DINO, SAM, OWL) could handle this zero-shot. A hybrid approach – VLM critiquing outputs of other vision models – is not considered, and no justification is given for using VLMs exclusively in the “team” (R3). More citations demonstrating that the presented issues affect many existing VLM-robotics approaches would strengthen the motivation (R3).
- **Novelty limited by omitted related work.** The approach has substantial overlap with MOKA (VLMs for task planning and action grounding, affordance-based reasoning) but MOKA extends to tool functionality and waypoint planning, which are missing here (R2, R3). Missing comparisons or citations with robot foundation models trained on robot data, especially VLAs such as RT-2, OpenVLA, and Embodied Chain-of-Thought (R3). The literature review lacks discussion of task and motion planning (TAMP) literature (R2).
- **Presentation and clarity issues.** The rhetorical motivating examples take up too much space, while the main contribution (agent module details) is relegated to the appendix; those descriptions could be condensed (R3). Numerous formatting errors: a missing reference in App E.1 (“Figure ?? shows this fact”), a typo in the grounding team description (“corre ctly”), and other polish issues (R3). Bold text is overused (R2). The heading in Section 6.1 (“COMPARISON WITH METHODS THAT TRAIN”) is too casual (R2). The term “abstract” tasks (Line 59) is not elaborated (R2). The heading “spatial planning” is misleading because none of the tasks in Sec. 5.3 involve reasoning about spatial relationships (R1).
- **Reviewer disagreement.** R1 rates the system design and appendix highly (score 5), while R2 and R3 rate novelty and evaluation much lower (both score 3). R1 notes missing details but is less critical; R2 and R3 argue that critical information (e.g., action space, agent list) remains unclear even after reading the appendix, and that the system does not go far enough in bridging semantic reasoning with smooth robot motion.
