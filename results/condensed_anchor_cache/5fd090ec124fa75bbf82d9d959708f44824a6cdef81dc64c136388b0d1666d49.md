## Merged Review

### Summary
The paper proposes FARS, a finite state machine (FSM)-based constrained decoding approach to ground LLM generation to a set of available APIs, eliminating the need for external retrievers, shortlisting, or exemplars. The FSM enforces a Begin-API-Argument-Value-End structure and limits token selection to valid transitions. The implementation uses a dynamic trie for efficiency. Experiments on SNIPS, MultiWOZ, and a Smart Home Control dataset with Vicuna-33B show significant improvements over an unconstrained LLM. Three reviewers rated the paper 6, 6, and 8 (all confidence 4), indicating some disagreement. The more positive reviewer found fewer weaknesses, while the others raised substantive concerns about implementation details, computational overhead, generalizability, and semantic error analysis.

### Strengths
1. **Novel FSM-constrained decoding approach** – An inference-time intervention that enforces correct API formats and prevents hallucination of invalid API calls. The approach is sound and well-illustrated.
2. **No need for external retrievers or exemplars** – Reduces complexity and potential points of failure compared to methods that require shortlisting of APIs.
3. **Structured and grounded generation** – The FSM provides a principled way to dynamically select API arguments and their order.
4. **Strong experimental results** – On three datasets (SNIPS, MultiWOZ, Smart Home Control), FARS shows apparent and significant improvements over an unconstrained LLM baseline.

### Weaknesses
*While one reviewer (score 8) was more positive and had fewer criticisms, the following weaknesses were raised by multiple reviewers or represent significant gaps.*

1. **Missing implementation details** – The paper does not specify how FSM states and transitions are defined and constructed from API specifications, how the FSM interacts with the LLM during decoding, what criteria determine valid transitions, how conflicts or ambiguities among multiple valid API calls are resolved, and what temperature was used in experiments (which could affect baseline comparisons). Also unclear is how the FSM is updated when APIs are added or modified (automation, real-time impact).
2. **Lack of computational overhead and latency analysis** – No wall time comparison with an unconstrained LLM baseline. The approach involves many CPU operations (constrained decoding, trie traversal), and the effect of FSM complexity (number of states/transitions) on inference speed is not quantified.
3. **Limited evaluation scope** – Only Vicuna-33B is tested, on three datasets. Broader assessment across different model architectures, API complexities, and domains is needed to establish generalizability. Additionally, no comparison is made with retrieval-based API selection baselines, making it unclear how FARS compares to systems that shortlist APIs.
4. **Potential increase in semantic errors** – The method eliminates syntactic errors but may introduce semantic errors (e.g., correcting a valid API name but producing a semantically wrong call). The paper does not analyze the trade-off between syntax correction and semantic accuracy, nor does it measure how much of the improvement comes from syntax correction alone.
5. **Conditional engagement of the FSM not analyzed** – The model’s ability to decide when to engage the FSM (i.e., when API calls are necessary vs. when free-text conversation is appropriate) is not studied, which is crucial for multi-turn dialog scenarios.
6. **Limited discussion of limitations and future work** – The paper does not address how to handle APIs from unknown domains, how to dynamically incorporate new APIs at inference time, or how the FSM update mechanism would work in practice for a changing API catalog.
