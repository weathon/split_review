## Merged Review

### Summary
This paper proposes FlashEVA, an efficient implementation of EVA (Efficient Attention via Control Variates) using custom CUDA and Triton kernels. It fine-tunes Transformers with as few as 1.6B tokens to adapt to the new attention mechanism, achieving up to 6.7× higher inference throughput and lower memory consumption at the cost of degraded performance on retrieval-focused tasks. FlashEVA offers adjustable hyperparameters to balance throughput, accuracy, and memory usage. Most reviewers (R1,R2,R4) gave score 3, while R3 gave 5, acknowledging clearer throughput/memory gains but still noting incremental contribution.

### Strengths
- The paper is well organized, clearly written, and easy to understand (R1,R2,R4). Background and motivation are well integrated (R2,R3). Experimental results are systematically laid out with tables and figures (R2,R3,R4).
- Adjustable hyperparameters allow a trade-off between throughput, accuracy, and memory usage (R1). FlashEVA is compatible with existing optimized attention implementations and can leverage CUDA kernels for performance optimization (R1).
- FlashEVA achieves obvious better throughput and memory consumption compared with both vanilla EVA and FlashAttention (R3). It can be finetuned from a standard attention model, making it easier to use (R3).
- The discussion of trade-offs and limitations shows a balanced approach, enhancing readability and impact (R2). Extensive experiments cover various downstream tasks (R3,R4).

### Weaknesses
- **Lack of novelty**: The method is overly simplistic and largely an incremental implementation of the existing EVA framework, not a new algorithm (R1,R2,R3,R4). The core derivation (Eq.11 from Eq.9–10) only defines an augmented key-value set (R4). Improvements come mainly from optimizing existing CUDA/Triton kernels (R2). The paper reads more like an experimental report than an academic contribution (R4); it is not ready for a venue like ICLR (R4).
- **Missing comparisons / unconvincing baselines**: 
  - Figure 1 only shows a trade-off between Dijiang and Sliding Window, without demonstrating clear advantages over either (R1).
  - FlashEVA is not thoroughly compared with Mamba; Mamba outperforms FlashEVA across most tasks even with fewer computational resources, and the paper offers no rationale for preferring FlashEVA or discussing complementary integration (R2).
  - No experiments on larger models (7B, 13B, 70B) to verify scalability (R1).
  - No comparison with or integration of FlashAttention‑3 (R1).
- **Limited improvement for short sequences**: Gains are prominent for long sequences but marginal for shorter or mixed-length sequences, reducing scalability and practical applicability (R2). The authors should optimize random feature computation or use adaptive techniques to reduce overhead (R2).
- **Insufficient implementation details**: More details about the CUDA/Triton implementation are needed, including pseudo-code and how custom attention masks are achieved. Current presentation of FlashEVA is too simple (R3). Background on FlashAttention could be added for readers unfamiliar with it (R3).
- **Retrieval-focused task degradation**: The method performs poorly on retrieval tasks, and the paper does not explain whether this is inherent to linear attention or due to other factors (R3; also implied by R1 and R4 as a limitation). This missing analysis weakens the understanding of when FlashEVA should be used.
