## Merged Review

### Summary
GenBot automates robotic skill learning at scale via a generative propose-generate-learn cycle. It uses LLMs (GPT-4) to propose tasks, generate simulation scenes with retrieved or generated assets, decompose tasks into sub-goals, choose a learning method (RL, motion planning with action primitives, or trajectory optimization), and produce training supervision including reward functions. The paper demonstrates the idea on several simulated manipulation and locomotion tasks. Reviewers agree the core idea is novel and promising, but widely criticize the experimental validation as insufficient, with major gaps in quantitative evaluation, task diversity verification, systematic validation of generated scenes and rewards, and missing implementation details.

### Strengths
- **Novel automated pipeline** for generating diverse tasks and skills with minimal human intervention, leveraging foundation models for each component (propose, generate, learn). (R1, R2, R3, R4)
- **Clear narrative and well-written** paper that is easy to follow. (R1, R4)
- **Interesting method for task generation**: GPT-4 learns object affordances by being instructed on how objects can be manipulated, the meaning of each joint and link, enabling generation of tasks tied to object structure. (R3)
- **Scene generation** that connects LLM output to 3D mesh assets (retrieval via Sentence-Bert + VLM verification, or generation via Midjourney + Zero-1-to-3) to construct appropriate scenes. (R3)
- **Effective task decomposition** shown in Figure 3, demonstrating that the method can break high-level tasks into meaningful sub-skills. (R3)
- **Variety of demonstrated tasks** including object manipulation, locomotion, and soft body manipulation. (R3)
- **Significant engineering effort** and potential to reduce human involvement in simulation task creation. (R2)

### Weaknesses
- **Insufficient quantitative evaluation**: The experiments are overwhelmingly qualitative. Specific missing analyses include:
  - Task diversity measured only via language descriptions, which is prone to biases (verbosity differences). Quantitative measures in state space (e.g., robot joint motion diversity) or image space (goal configurations) are needed. (R1, R2)
  - Scene validity lacks statistics on how often retrieval vs. generation is used, viability of generated assets, and ablation of individual components (e.g., importance of both Bard and BLIP-2, why Sentence-Bert). (R1)
  - Training supervision validity lacks numbers such as average number of decompositions per task, average duration to solve sub-goals vs. full task, or direct planning baseline. (R1)
  - Skill learning results shown only for 4 tasks; improvement over RL-only baseline needs to be measured separately for each method (trajectory optimization, planning with action primitives, RL) and over many more tasks. (R1)
  - System-level performance lacks a quantitative overview of how many tasks are successfully solved, success rates, and nature of those tasks. (R1, R2)
- **Incomplete task verification**: There is no systematic validation of whether the automatically generated tasks are correctly implemented (success conditions, initial state distributions, physical parameters, collision avoidance). (R2) Examples: LLM-generated descriptions can omit crucial details (e.g., “bowl heating” missing a timer setting). (R4) Additionally, it is unclear what percentage of generated tasks are solvable and how trivial tasks (e.g., picking a block given a grasp primitive) are filtered out. (R2)
- **Questionable necessity of LLMs and human input**: It is not shown that the LLM-based pipeline is more effective than simple heuristics (e.g., random object placements) for generating diverse tasks, nor that it genuinely reduces human effort given the extensive prompting required. (R2) Reward function generation heavily depends on in-context examples derived from human task understanding, which may limit applicability to novel tasks. (R4)
- **Critical assumption about sub-task solvability**: The framework assumes that decomposed shorter-horizon sub-tasks are always solvable by one of the fixed policy categories (RL, motion planning with action primitives, trajectory optimization). This may limit complexity and generalizability (e.g., tasks requiring intricate coordination or novel control strategies). (R3) It is unclear how often this assumption breaks in practice. (R3)
- **Missing implementation details and clarity**:
  - Sections 3.1 and 3.2 are text-heavy and hard to follow; a structured list or additional graphic for the pipeline would help. (R1)
  - The Midjourney + Zero-1-to-3 asset generation pipeline is not elaborated. (R2)
  - Precise output format from LLMs and how scenes are imported into the simulator are unspecified. (R2)
  - Handling of unsolvable scenes (e.g., object out of reach, collisions), initial state distribution, and generation of physical parameters (e.g., friction, weight) is not described. (R2, R3)
  - The method lacks a formal algorithmic description or mathematical formulation. (R4)
- **Reliance on limited object assets and closed-source software**: The paper relies heavily on PartNetMobility and RLBench for objects; the Midjourney+Zero123 generation pipeline is not detailed; the Genesis simulator is private; code is not released. (R2)
- **Cascading errors**: The pipeline is fully cascaded; errors or infeasibility at the task generation stage can propagate to skill learning, and no strategies are proposed to improve interplay between generation and acquisition. (R4)
- **Missing related work citations**: Relevant works on learning diverse skills in simulation (e.g., VIMA, Visual Cortex for Embodied AI, RoboCat) should be cited. (R1)
