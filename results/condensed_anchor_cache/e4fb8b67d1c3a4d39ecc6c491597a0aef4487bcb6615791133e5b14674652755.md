## Merged Review

### Summary
The paper proposes three data-driven high-level counterfactual explanation (CFE) generators: hl-continuous (uses ILP to find least-cost set of continuous actions), hl-discrete (solves a set cover problem for discrete actions), and hl-id (for cases where action costs and effects are unknown). The approach formulates optimal CFEs as weighted set cover problems (NP-hard) and trains deep networks on (instance, optimal CFE) datasets to predict cheap CFEs for new agents. Experiments use real-world health, semi-synthetic, and fully synthetic datasets. The work also discusses fairness.

### Strengths
- Interesting topic: generating higher-level actions (groups of feature changes) that may be easier to communicate to users (Reviewers 2, 3).
- Algorithm is concise and several case studies are provided (Reviewer 2).
- The paper provides a comprehensive analysis across diverse feature types, dataset dimensions, and varying CFE frequencies, and also discusses fairness (Reviewer 1).
- The proposed methods are model-agnostic, so they can be adapted to different models (Reviewer 1).
- Once the generator is trained, CFE prediction is very efficient; with proper training and a high-quality dataset, the generator can achieve high accuracy (Reviewer 4).
- If a predefined set of actions is available, generating counterfactuals for subgroups is more straightforward (Reviewer 4).
- The proposed approach enables fairness auditing in a more structured and systematic manner (Reviewer 4).

### Weaknesses
- **Motivation and applicability contradictions (Major – Reviewer 3):** The paper motivates the technique for individuals who lack access to the classifier, but the proposed method requires generating CFEs for *thousands* of individuals (a training dataset) and then training a generator. This demands *more* privilege, not less. How would this be deployed in practice? Who generates the initial CFE dataset under the claimed access restrictions? (Reviewer 3 weakness [#1]; also related Reviewer 4 weakness #3: hl-continuous/discrete still require query access and cost info for training).
- **Unclear definition of high-level actions and why they are suitable (Reviewer 2):** The paper does not clearly explain why high-level actions are suitable for users to act upon, nor how these actions are identified (Reviewer 2). Also, Reviewer 1 asks why these are considered “high-level” – adjusting multiple features is not new. Reviewer 4 suggests introducing high-level actions earlier.
- **Linear classifier assumption (Equation 2) (Reviewers 1, 4):** The ILP formulation presumes a linear classifier, which may not represent real-world complexity. This simplification restricts performance and generalizability. The parameters (c, b) are not derived from data; there is no sensitivity analysis of these pre-defined parameters (Reviewer 1). For non-linear models, the ILP cannot be used directly; brute-force methods are inefficient, raising concerns about scalability to complex models (Reviewer 4). [Reviewer 4 weakness #1].
- **hl-discrete is a special case of hl-continuous (Major – Reviewer 3):** hl-discrete is just hl-continuous with binary weights on features. It does not need separate focus (Reviewer 3 [#6]). Also, hl-discrete is limited to positive changes only, which may not achieve recourse by only increasing feature values; it requires additional preprocessing and model internals understanding (Reviewer 4 weakness #2).
- **hl-id generator is generic and not useful (Reviewer 3):** The suggestions (e.g., increase credit score) are not specific or actionable; the point of a CFE is to provide specific, small, achievable changes (Reviewer 3 [#7]). Additionally, it is unclear how the training dataset is constructed for hl-id or what loss is optimized when the classifier is inaccessible (Reviewers 3 [#11], 4 [#4]).
- **Lack of theoretical guarantees (Reviewer 2):** The paper lacks a theoretical guarantee to demonstrate the efficiency of the proposed algorithm (Reviewer 2). Also, the claim that solving the problem is “computationally expensive as it is NP-hard for each new agent” is challenged: in practice, many CFE methods are cheap, fast, and scalable (Reviewer 3 [#3], citing Verma et al. 2020). “Agent” is not defined (Reviewer 3).
- **Overlooked practicality and scalability (Reviewers 2, 3):** Formula 2’s ILP could be time-consuming when the action space is large, and the paper does not explain how to constrain the action space (Reviewer 2). The role of neural networks is unclear: if ILP can generate optimal CFEs directly, why train a neural network? The experimental section (4.2) is poorly written; the full pipeline (data generation, role of NN, how it differs from ILP) is not clearly explained or diagrammed (Reviewer 3 [#9]). How are “actions” obtained for hl-continuous/discrete (Reviewer 3 [#10])?
- **Unsupported or obvious claims in experiments (Reviewer 3):**
    - Line 362: sparsity is claimed as undesirable; in CFE literature, individuals want *fewest* changes, not many. The health example is invalid (Reviewer 3 [#12.1]).
    - Line 372: hl-continuous CFEs have fewer actions but more feature changes – this is obvious because one high-level action clubs multiple feature changes. One could trivially define an action that changes all features (Reviewer 3 [#12.2]).
    - Line 404: more distant state is also obvious given large feature changes (Reviewer 3 [#12.3]).
    - Line 409: claiming hl-continuous CFEs are “more desirable” without a user study or any metric is unsupported (Reviewer 3 [#12.4]).
    - “CFEs frequency” (line 390) is undefined (Reviewer 3 [#13]).
- **Lack of comparison to other CFE methods (Reviewer 1):** The study only compares against low-level CFEs, not other existing high-level or cause-based CFE generators.
- **Binary classification only (Reviewer 1):** The method is limited to binary classification.
- **Incorrect claim about low-level CFEs (Reviewer 3):** Line 157 says low-level CFEs modify “an individual feature,” but many causality-based CFE techniques (e.g., Consequence-aware, Geco, Amortized) modify groups of features sequentially (Reviewer 3 [#4]).
- **Irrelevant example (Reviewer 3):** The celiac example is unrealistic – celiac classification is rule-based, not a black-box model. A more relevant example from algorithmic hiring or credit scoring would be better (Reviewer 3 [#5]).
- **Poor referencing (Reviewer 3):** Limitations of low-level CFEs (line 152) lack references (Reviewer 3 [#2]).
- **Typographical and formal errors (Reviewer 4):** In Definition 2, the condition ε_j ≤ a_j appears redundant; there is a typo (ε_i should be ε_j). In Definition 4, the constraint should be Σ d_{ji} a_j + x_i ≥ t_i. Include variance/std dev in figures.
- **Figure 2 interpretation problems (Reviewer 4):** Comparing number of actions between high-level and low-level is not meaningful because one high-level action can modify multiple features. More feature changes does not necessarily hurt explainability; more distant state does not indicate higher improvement (CFE goal is minimizing cost, not maximizing improvement). Higher frequency is expected because predefined actions are more global.
- **“Diverse improvements” ambiguous (Reviewer 4):** The phrase at line 367 requires clarification.
