## Merged Review

### Summary
The paper proposes a best-first tree search algorithm for LM agents to improve multi-step planning and exploration in interactive web environments. The method is applied to VisualWebArena and WebArena, showing relative improvements of 39.7% (26.4% success) and 28.0% (19.2% success) over GPT-4o without search. The search uses an LLM-based value function (multi-modal, last d screenshots, 0/0.5/1 scores averaged over reasoning) and generates action candidates via CoT sampling and top-b aggregation. Reviewer opinions diverge sharply: one reviewer (score 8) finds the work original, clear, and significant, praising the value function design and generation strategy; another (score 3) considers it lacking technical novelty, poorly evaluated, and unconvincing on WebArena performance; the other two (scores 5 and 6) note incremental innovation, computational costs, and limited practical applicability. All reviewers acknowledge the robust methodology and comprehensive ablation studies, but concerns about execution speed, destructive actions, value function reliability, and benchmark performance dominate.

### Strengths
- Experiments on practical benchmarks (VisualWebArena, WebArena) demonstrate effectiveness on realistic web tasks.
- Search algorithm is compatible with various LM agents and requires no fine-tuning or retraining.
- Extensive hyper-parameter analysis (e.g., search budget, branching factor, depth, value function variants).
- Claimed to be the first tree search algorithm for LM agents on realistic web tasks (Reviewer 2; but see Weaknesses regarding novelty).
- Value function design is smart: multi-modal, uses last d screenshots, scores in {0,0.5,1} with averaging over reasoning to reduce noise, with trade-off of more compute.
- Action generation via 20 CoT outputs, counting candidates, and top-b aggregation produces distinct action candidates effectively.
- Qualitative examples in Section 5.3 aid understanding of how search improves trajectories.
- Paper is well-written with clear formulas, figures, and tables; experimental section is meticulous and reproducible.
- Robust methodology: tree search in actual environment space is a natural and effective solution.
- Logical structure and clear articulation of method and results.
- Novel approach with rigorous testing and comprehensive ablation studies.

### Weaknesses
- **Limited novelty / technical contribution.** Integration of tree search with LLM planning is already present in prior work (e.g., Language Agent Tree Search, Oct 2023; When is Tree Search Useful for LLM Planning?, Feb 2024; LLM Self-Training via Process Reward Guided Tree Search, Jun 2024; LiteSearch, Jun 2024). The paper incrementally applies existing frameworks to the web agent domain (Reviewer 3; also Reviewer 4 notes tree search is commonly used elsewhere). High reviewer disagreement: Reviewer 2 considers it original and “first to the flag,” while Reviewer 3 and 4 see limited innovation.
- **Computational and time inefficiency.** Demands significant resources due to increased environment interactions; practical applicability in real-time or resource-constrained settings is questionable (Reviewer 1). Algorithm may be especially slow because, during expansion, each action requires resetting the environment to the parent state and re-executing previous actions (Algorithm 1, line 23). This introduces substantial waiting time even for actions that are never searched over (Reviewer 2). No comparison of execution times with other methods; only search budget c is discussed, but c does not reflect actual wall-clock time (Reviewer 4).
- **Destructive actions and backtracking challenges.** The paper briefly addresses destructive actions (irreversible changes in real environments) but lacks a comprehensive solution. In realistic web settings, backtracking may be impossible or costly (Reviewer 1, 2). The description of how backtracking and environment resets are implemented is insufficient; multiple reviewers ask for details (Reviewer 2, Reviewer 1 question). The section on destructive actions is characterized as highly speculative (Reviewer 2).
- **Value function dependency.** Success heavily depends on value function quality; self-consistency helps but further improvements are needed (Reviewer 1). No dedicated evaluation method for the value function (e.g., mean squared error when ground truth is available). The paper only assesses value functions through overall success rate, which can be indirectly influenced by other factors (Reviewer 3). Questions remain about why self-consistency was chosen over RL-based value functions (Reviewer 1).
- **Limited performance and credibility on WebArena.** The highest success rate is only 19.2% on WebArena, considerably lower than multiple SOTA baselines, raising doubts about efficacy (Reviewer 3). The paper uses different baselines across datasets (e.g., not reporting GPT-4o on WebArena to match), and only reports results on two base LLMs augmented by the method, not on domain-specific SOTA agents under the same step constraints. This suggests the method may not universally integrate (Reviewer 3). Results on the full VisualWebArena show GPT-4o with search at 26.4%, but on a 200-question subset the same model gets 37%—a large discrepancy that is not adequately explained (Reviewer 2 question). Improvements from base sub-optimal LLMs are not surprising (Reviewer 3).
- **Missing experiments and comparisons that are deferred to future work.** The paper should have reported: (a) performance of proposed search integrated with domain-specific SOTA baselines under the same step constraints; (b) experiments with larger search budgets (c > 20) to explore further gains and diminishing returns (Reviewer 4 question; Reviewer 3 mentions future work); (c) analysis of the time cost and mitigation strategies, which are crucial for practical feasibility. Deferring these to future work without any evidence undermines credibility (Reviewer 3).
- **Clarity issues.** Algorithm 1 should be in the main text; the description of the search budget and how the algorithm terminates (commit to highest-value trajectory after budget exhausted) is not integrated into the algorithm definition (Reviewer 2). Figure 1 is not referred to in the text; there are minor errors (e.g., “alloted” → “allotted”, “backtracks” needed) (Reviewer 2). Questions remain about tie-breaking when states have equal value (Reviewer 2). Also, note that LLaVa only accepts one screenshot, which should be stated explicitly (Reviewer 2 suggestion).
