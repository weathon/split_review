## Merged Review

### Summary
Point-SAM extends the 2D Segment Anything Model (SAM) to 3D point clouds by designing a promptable transformer-based architecture with a Voronoi tokenizer for efficient patch encoding. It is trained on multiple 3D datasets (ShapeNet, PartNet, ScanNet, S3DIS, etc.) and uses a data engine that distills knowledge from 2D SAM via pseudo-label generation to improve generalization. Evaluated on zero-shot point-prompted segmentation, zero-shot object proposal, and few-shot part segmentation, Point-SAM achieves performance on par with or surpassing existing methods. Two reviewers score 8 (high), four score 6 (moderate); the higher-score reviewers emphasize the contribution toward 3D foundation models, while the lower-score reviewers question novelty, fairness of comparisons, and thoroughness of experiments.

### Strengths
- **Extension of SAM to 3D**: The paper successfully adapts the SAM paradigm (promptable segmentation, encoder-decoder) to unconditional point clouds, eliminating the need to run 2D SAM or 2D-to-3D lifting at inference time (R1, R2, R6).
- **Unified training across diverse datasets**: Training on datasets covering parts, objects, indoor scenes, and outdoor scenes (single-object and scene-level) enables generalization (R1, R4).
- **Knowledge distillation from 2D SAM**: The data engine generates part- and object-level pseudo-labels at scale, allowing the model to benefit from SAM’s knowledge during training rather than only at inference (R1, R2, R6).
- **Efficient Voronoi tokenizer**: Achieves comparable segmentation performance to the k-NN tokenizer while being notably more efficient on large point clouds (e.g., KITTI360); especially beneficial when the number of prompt points is low (R3, R4, R5).
- **Impressive real-world potential**: Interactive 3D annotation video demonstrates practical usefulness (R2).
- **Good zero-shot performance**: Outperforms baselines (e.g., AGILE3D) on zero-shot point-prompted segmentation tasks (R1, R6).
- **Clear writing and framing**: The paper is well-organized, presenting the problem from task, model, and data perspectives (R3).

### Weaknesses
- **Insufficient novelty in model design**: The Voronoi tokenizer shows only marginal IoU improvement over a simple k-NN tokenizer; the gains are mostly visible when very few prompt points are used. This raises concerns about the core architectural contribution (R1, R3, R5).
    - *Disagreement*: One reviewer (R4) sees the efficiency advantage as a clear strength.
- **Data leakage in zero-shot OOD evaluation**: The held-out categories in PartNet-Mobility (scissors, refrigerators, doors) are part of the PartNet training set, so the model has seen their general shapes. This weakens the claimed zero-shot transferability to unseen categories (R1).
- **Pseudo-label generation process unclear**: The iterative refinement (2D-3D proposal projection, negative prompt sampling) described in lines 265–269 and Figure 3 is ambiguous; it is not clear exactly how the error region between the 2D and 3D proposals is used to sample negative prompts across views (R1).
- **Lack of rigorous baseline comparisons**:
    - Main comparison is with AGILE3D, but Point-SAM is trained on much larger datasets. When trained on the same data (Table 6a), it only clearly outperforms on 2 of 4 datasets; the authors’ overfitting argument is not cross-validated (e.g., train A test B and vice versa) (R6).
    - MV-SAM, the multi-view SAM aggregation baseline, is weak; the paper should compare against stronger multi-view aggregation methods like SAM-guided Graph Cut, SAI3D, Open3DIS, OpenIns3D (R6).
    - Table 3 omits MV-SAM on ScanObjectNN; no explanation (R1).
    - Reference “InterObject3D++” is unclear – is it the same baseline used in AGILE3D? (R1)
- **Insufficient visualization and qualitative results**: Only a few visualizations are provided (Figure 4 in main paper); more complex examples from the supplementary video should be shown; applications like few-shot part segmentation and zero-shot object proposal lack any visual results (R2, R3).
- **Segmentation quality concerns**: The paper does not directly compare boundary quality with multi-view aggregation frameworks (SAM3D, Gaussian Grouping) which reportedly produce sharper boundaries, especially on internal structures (R2).
- **Prompt point selection not documented**: In Figure 4, the placement and color (red/blue meaning) of point prompts differ between Point-SAM and AGILE3D; it is unclear whether the same prompts are used in the main experiments (R2, R6).
- **Missing references to related 3D SAM works**: The paper should discuss/compare with “Segment Anything 3D”, “SANeRF-HQ”, “SERF: Fine-Grained Interactive 3D Segmentation and Editing with Radiance Fields”, “Segment Anything in 3D with Radiance Fields” (R5).
- **Limited evaluation on outdoor and sparse data**: Evaluated only on KITTI360 among outdoor datasets; missing experiments on Waymo Open Dataset, nuScenes, or sparse LiDAR point clouds that are common in real-world outdoor scenarios (R4).
- **No computational cost breakdown**: The paper lacks detailed speed and memory comparisons for tokenization, feature extraction, and mask prediction across varying prompt points and point cloud sizes (R4).
- **Challenges not fully addressed**: The paper claims to solve “non-unified data formats” but only designs for point cloud representation, not a truly unified representation (R4).
- **Table 4 limited**: Evaluating only on PartNet-Mobility is insufficient; adding ScanNet is less beneficial than ShapeNet – further explanation or additional experiments needed (R6).
- **Replica evaluation selective**: In Table 2, only OpenMask3D comparison is in appendix; other baselines are omitted – reason unclear, possibly due to model sensitivity to large-scale data (R6).
- **Practicality concerns**: For labeling tasks, requiring manual point prompts on each object may be inefficient, especially for object-part distinction where prompt placement is critical (R3).
- **Missing cross-analysis ablation**: To substantiate the overfitting claim, the paper should perform train-A-test-B and train-B-test-A experiments (R6).
