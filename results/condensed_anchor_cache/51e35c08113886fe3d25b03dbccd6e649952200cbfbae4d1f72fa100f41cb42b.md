## Merged Review

### Summary
The paper proposes NETINFOF, a framework to measure and exploit Network Usable Information (NUI) for graph tasks (link prediction, node classification). It consists of NETINFOF PROBE (measures NUI without model training) and NETINFOF ACT (solves tasks using the measured information). The framework claims theoretical guarantees, closed-form solutions, linear scalability, and strong empirical results on synthetic and real-world datasets, outperforming many GNN baselines in link prediction. Reviewer 1 and 2 are positive (scores 8), while Reviewer 3 is more critical (score 6) and raises concerns about claims and missing related work.

### Strengths
- **Methodological innovation**: Novel approach to measure NUI directly from graph structure and features, avoiding heavy model training; interesting adjustment of node similarity using compatibility matrix with negative edges (R1).
- **Theoretical foundation and empirical validation**: Provides theoretical analysis (NetInfoF_Score as lower bound for accuracy) supported by strong empirical results on both synthetic and real-world datasets (R1, R2). Outperforms GAE baselines in both accuracy and scalability (R1). Extensive experiments across many datasets (R3).
- **Scalability**: Linear scaling with input size (Fig. 6); uses only 1280 parameters vs 279k for GAE; though slower than SlimG, achieves better accuracy (R1). Promising for large-scale tasks (R1, R2).
- **Generality and clarity**: Handles both link prediction and node classification; well-written and organized paper (R2). Practical tool for assessing graph usefulness before training GNNs (R2).

### Weaknesses
1. **Proof error for Theorem 2 (major)**: The proof in Appendix A.2 misuses conditional entropy, using joint probabilities $p_{ij}$ instead of conditional probabilities $P(Y=y_j|X=x_i)=p_{ij}/p_i$. This invalidates the application of Jensen's Inequality and thus the derived bound on the NetInfoF score. Reviewers request a corrected justification (R1). (See also R1 Q1)
2. **Missing comparisons and related works**: 
   - Should include subgraph-based methods like SEAL as baselines (e.g., SOTA on Ogbl-collab); even if NetInfoF is more scalable, such comparisons would give a fuller evaluation (R1).
   - Missed related works connecting graph information with task performance: [1]–[5] (R3).
3. **Unclear derivations and notation**:
   - How are the "Our bound" lines in Figures 3 and 4 derived? (R1 Q2)
   - How does NetInfoF_Probe estimate and calculate the discretizer in Section 4.2? Please provide examples (R1 Q3).
   - Notation: What is $f$ in C4? Avoid reusing $f$ for features (R3).
   - Theorem 1: "accuracy(Y)" is ambiguous; what is $p_y$? Needs a stricter statement (R3).
4. **Questionable claims about heterophily**: 
   - “Predicting links by GNNs relies on measuring node similarity, which is incorrect if the neighbors have heterophily embeddings.” – Counterexample: embeddings can be similar even with heterophily if nodes share similar neighborhood patterns (R3, citing [6]).
   - “It results in low value when node i and node j have heterophily embeddings, even if they are connected by an edge.” – Not correct; see [2,3,6] (R3).
5. **Unclear statement about linear GNNs**: “the node embeddings of linear GNNs require no model training” – why no training? Do the authors mean SGC? (R3)
6. **Sensitivity to compatibility matrix and label rates**: Need additional empirical results showing how NetInfoF performs under different label rates, since the estimated compatibility matrix H is sensitive to label rate (R2). 
7. **Robustness to noise and diverse structures**: How does NetInfoF handle noisy/incomplete graph data? Are there graph structures or node features where it fails? (R2)
8. **Ablation study needed**: The relative contributions of the five node embedding components (Section 3.2) are not analyzed. Are they equally influential? (R1 Q4)
