## Merged Review

### Summary

The paper proposes CRITIC, a framework enabling LLMs to self-correct by interacting with external tools (Knowledge base, code interpreter, text APIs, Wiki, calculator, search engine) via in-context learning, without specialized training. Experiments on free-form question answering, mathematical program synthesis, and toxicity reduction show consistent performance improvements over baselines including CoT, Self-Consistency, ReAct, and PoT. Reviewers are split: two rate the paper highly (8) for timeliness, strong results, and comprehensiveness; two rate it lower (5) citing insufficient novelty compared to prior work on tool use and self-correction.

### Strengths

- Novel framework addressing LLM limitations by enabling self-verification and correction through interaction with external tools (R2, R3).
- Comprehensive evaluations across diverse tasks, datasets, and multiple model families/sizes, with universal improvements (R1, R2, R3).
- Strong results: CRITIC consistently outperforms strong baselines on all evaluated tasks (R1, R2, R3).
- Simplicity and practicality: approach uses only in-context learning, facilitating wide application (R1).
- Ablation (CRITIC w/o Tool) clearly demonstrates the critical role of external feedback; an important learning for the community (R3).
- Comparison with ReAct provides insight into the role of parameter knowledge vs. language feedback (R4).
- Paper is well-written, easy to understand, with comprehensive comparisons to strong baselines (R3, R4).
- Covers a wider range of tools compared to many prior works that typically employ a single tool type (R3).
- Research topic (LLM tool use) is very timely (R3).

### Weaknesses

- Novelty concerns: prior works (Self-Correct, Self-Ask, Self-Debug, and others using natural language feedback or tools) already demonstrated external feedback for LLM correction, and these are not cited (R1, R4). The unifying framework and new downstream tasks (e.g., toxicity with Perspective API) may not pass the bar for a top conference (R1, R4). Reviewer 4 additionally notes that the idea of using natural language feedback and tools is “pretty old” (R4).
- Oracle settings are idealistic; moving these results to an appendix (as done by other works) would improve clarity (R1).
- Missing error analysis: failure modes after using tools for feedback are not discussed (R3).
- No breakdown of the contribution of each tool per task; such analysis would provide insight into where improvements come from (R3).
- Additional costs of calling external tools are not reported; should be reported for each experiment (R2).
- Sampling configurations differ across tasks (p=0.9 for section 4.3 vs. p=0.5 for 4.1 and 4.2) without justification (R3).
- Important related work (e.g., active-prompt [2]) not cited in Appendix C.2 (R2).
- Claim that tool use “mimic[s] human thinking and behavior” is overblown; humans use tools differently, typically not through a text-only interface (R4).
- No comparison with other frameworks that endow LLMs with self-correction and tool use (R4). Reviewer 1 notes that Self-Debug and Self-Ask have striking resemblance to CRITIC but are not referenced.
- Inconsistency in Table 1: the AmbigNQ EM score of 50.0 is highlighted for Text-Davinci-003, but it is not the highest – possible bug or misemphasis (R1).
- In the GSM non-oracle setting, interpreter feedback appears limited to syntactic correctness; substantial improvements suggest many initial programs were syntactically wrong, which raises questions about the nature of the improvements (R1).
- A recent study [1] reports that LLMs cannot self-correct themselves (though it did not involve external tools); a discussion of how CRITIC’s setting differs would be valuable (R2).
