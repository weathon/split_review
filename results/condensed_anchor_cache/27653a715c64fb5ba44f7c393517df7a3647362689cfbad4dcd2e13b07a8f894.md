## Merged Review

### Summary
The paper investigates whether Compressed-Language Models (CLMs)—decoder-only Transformers trained autoregressively on raw byte streams from JPEG-compressed images—can understand compressed file formats. Experiments are conducted on small image datasets (MNIST 28×28, CIFAR-10 32×32, TinyImageNet 64×64) using a small LLaMA-like model with a byte-level tokenizer. Three tasks evaluate understanding: (i) recognition of inherent file properties (JPEG quality setting and semantic class), (ii) detection/localization/correction of single-byte anomalies, and (iii) generation of valid JPEG files. Results show high accuracy (e.g., 99% file recognition on MNIST, 74% on CIFAR-10; 99% of generated MNIST files are valid JPEGs). The authors claim CLMs can understand semantics of compressed data directly from byte streams.

### Strengths
- The research topic is novel and interesting: exploring LLM capabilities directly on compressed file formats (JPEG as representative CFF) is a bold idea that may reveal unseen capabilities or important limitations (Reviewers 2, 3, 4).
- Evaluation tasks (property recognition, anomaly handling, generation) are reasonable first steps and shed some light on compression/decompression capabilities of plain LLMs (Reviewer 4).
- Concrete results demonstrate effectiveness: 99% accuracy on MNIST file recognition, 74% on CIFAR-10; near-perfect anomaly detection and generation validity on MNIST (Reviewer 1).
- The modeling approach (byte-level tokenization, standard autoregressive training) is clearly described and uses publicly available models/datasets (Reviewer 1).

### Weaknesses
- **Novelty and contribution are modest** (Reviewer 1 rating 2/2/2; Reviewers 2, 3, 4 rating 2/1/1). The central claim that CLMs can understand compressed file semantics is insufficiently supported because the experiments use only one custom-trained model (not existing LLMs) and small image sizes (28×28, 32×32) where overfitting is likely and generalizability to larger/in-distribution data is unproven (Reviewers 2, 3).
- **Paper positioning is unconvincing** (Reviewer 4). The claimed advantages of working directly on compressed formats (ubiquity, compactness) are flawed: decompressing before training would retain those benefits. Practical relevance is unclear because real pipelines already use domain-specific techniques (augmentation, tokenization, specialized models), and teaching a model to decompress/compress when efficient algorithms exist wastes resources (Reviewer 4).
- **Missing analysis of token distribution and data properties** (Reviewer 3). Binary streams from compression algorithms may lack generic patterns. A detailed examination of token distribution in compressed data is needed to justify the approach, as in-context learning may depend on data distributional properties (Chan et al., 2022).
- **Limited insight and over-claiming** (Reviewer 4). The paper only tests JPEG, includes JPEG-specific information (quality setting), uses one image size, and focuses on whether tasks work rather than where/why they fail. Also, JPEG-encoded data inherently has sequential structure—it is not surprising that a model trained for next-token prediction works well on in-distribution sequences (Reviewer 2).
- **Training/evaluation setup has issues** (Reviewers 2, 4). For task (i), prediction targets (quality, class) are fed to the decoder-only model in a contrived way; it is unclear why a decoder-only LLM is appropriate. For task (ii), only single-byte replacement anomalies are considered (not more realistic types like multiple-byte or structural changes), and when detecting/localizing/correcting, the model ignores input after the erroneous token—a limitation of decoder-only architecture (Reviewers 2, 3, 4). For task (iii), validation relies solely on file validity (can the image be decoded?) but does not evaluate generation quality beyond anecdotal examples (Reviewer 4).
- **Insufficient justification and missing experiment details** (Reviewer 2). The paper does not clarify why CLMs are needed for CFFs or why testing understanding is important. No tables/figures for Section 4.2 results (anomaly handling?); unclear whether “validation set” in anomaly experiments means training validation set and what test set results are; dataset split not clarified (Reviewer 2). Fine-tuning details for semantic class recognition (data used, procedure) are missing (Reviewer 2). In file generation, only 10 files (one per class) are used to assess validity; how does this yield “15% of anomalous files are broken”? (Reviewer 3)
