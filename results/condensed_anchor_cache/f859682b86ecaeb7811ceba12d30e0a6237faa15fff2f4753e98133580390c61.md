## Merged Review

### Summary
The paper proposes Video2Demo, a framework that uses GPT-4 to interactively query a generative VLM (e.g., LLaVA) to produce temporally coherent text-based state-action sequences from videos. These sequences are then fed to an LLM (GPT-4) to generate robot task code. The method is evaluated on EPIC-Kitchens videos using a small human-annotated set of state-action predicates, and the authors claim it outperforms pure VLM-based baselines in both state-action and code generation tasks.

### Strengths
- The paper is well-written, well-structured, and easy to follow. Reviewers across the board praised its clarity and presentation.
- The interactive dialog design (LLM asks follow-up queries to VLM) is a novel and logical prompt-engineering strategy for extracting temporally coherent state-action descriptions from video.
- The authors contribute a human-annotated validation set of state-action predicates for EPIC-Kitchens, which is seen as a useful resource for the community.
- The paper demonstrates not only perception (state-action extraction) but also a downstream application (code synthesis for robot task planning).
- Two reviewers (R3, R4) emphasized that the evaluation on real-world EPIC-Kitchens data is extensive and shows superior performance over baselines. R3 specifically noted that failure cases (spatial grounding, hallucinations) are well discussed.

### Weaknesses
- **Evaluation scale and rigor**: There is strong disagreement. Two reviewers (R1, R2) found the evaluation insufficient: only 7 videos are used, the pseudo-code generation task is not a standard benchmark, and no quantitative metrics (beyond ChrF) are provided for the state-action predicates. R2 noted the evaluation relies heavily on GPT-based metrics, which weakens the results despite the human-annotated set. In contrast, R3 and R4 considered the experiments extensive. The small evaluation set makes it difficult to assess generalizability.
- **Misleading claims about grounding**: Both R1 and R2 pointed out that the paper repeatedly uses the term “state-action demonstration” and “grounding” but actually produces high-level text predicates and pseudo-code (e.g., “check_if_dirty(object)”). This is a symbolic, abstract representation, not a grounded state-action sequence directly usable for robot control. The abstraction level makes it impossible to test in a real control setup.
- **No robotic evaluation**: All four reviewers noted the absence of any simulated or real robot experiments. R1 stated this makes the claim of generating “state-action demonstrations” an overclaim. R3 and R4 added that without execution-based validation (e.g., in ALFRED, or by actually running the generated code), the practical utility for teaching robots is unproven.
- **Lack of ablation and generalization**: Multiple weaknesses were raised: (i) Only GPT-4 and LLaVA are used; the framework’s generality to other LLMs/VLMs is untested (R4). (ii) Results for GPT-4V (even via ChatGPT UI) are missing (R4). (iii) The heavy reliance on prompt engineering makes it unclear whether the same prompts work beyond EPIC-Kitchens egocentric videos (R3). (iv) Scalability to third-person videos is questionable (R3). (v) The method is extremely expensive, requiring many GPT-4 calls per timestep (R1).
- **Contribution significance**: R2 argued that using LLM+VLM with text history is an obvious design choice, and the prompt-engineering improvements over the Socratic Model do not constitute enough novelty for a top conference paper. R1 also noted the pseudo-code generation task is not standard and lacks comparable baselines.
- **Missing related works**: R4 recommended discussing additional prior works (ProgPrompt, VoxPoser, Voyager).
- **Reviewer questions that overlap with weaknesses**: 
  - What was the cost of running the experiments? (R1)
  - How big is the human-annotated set? (R2)
  - Please clearly define “structure and temporal consistency” as used in the abstract. (R2)
  - Can the method scale to third-person tutorial videos? (R3)
  - How does ChrF compare to other code generation metrics (e.g., CodeBERTScore)? Does high ChrF correlate with human preference and physical executability? (R3)
- **Potential error accumulation and latency**: R3 highlighted that the interactive dialog loop may compound errors, and the latency makes the approach unsuitable for real-time robot control. R1’s point about high cost reinforces this concern.
