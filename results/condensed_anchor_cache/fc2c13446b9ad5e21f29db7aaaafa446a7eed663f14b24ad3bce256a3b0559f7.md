## Merged Review

### Summary

Five reviewers assess SlideChat and its associated datasets SlideInstruction and SlideBench. Reviewer 1 (score 5) finds the application of MLLMs to WSIs valuable and the resources (SlideBench, SlideInstruction) useful for the community. Reviewers 2–5 (score 3 each) agree the overall concept and architecture are sound, but raise significant concerns about inadequate comparisons with pathology‑specific methods, flawed baselines, limited dataset size, lack of quality control, missing ablation studies, and insufficient clinical relevance. The minority positive view (Reviewer 1) is notably more optimistic about the contributions and experimental scope.

### Strengths

- Application of multimodal large language models (MLLMs) to whole‑slide images (WSIs) is well‑motivated and addresses a gap in patch‑level‑only analysis.
- The architecture combining a frozen patch‑level encoder (CONCH), a slide‑level encoder (LongNet), and a pretrained LLM (e.g., Qwen 2.5‑Instruct) is sound.
- SlideBench and SlideInstruction are potentially valuable open‑source resources. SlideBench includes captioning and VQA tasks; the VQA portion (SlideBench‑VQA) was reviewed by five pathologists to ensure question quality.
- On VQA tasks, SlideChat outperforms general‑purpose MLLMs (GPT‑4o) and broad‑domain medical MLLMs (LLaVA‑Med, MedDr) on the held‑out TCGA and external BCNB datasets.
- This work is the first slide‑level “LLaVA‑style” MLLM that unifies both captioning and VQA in computational pathology (though not the first for each task individually: e.g., MI‑Gen for captioning, WSI‑VQA for VQA).
- The paper is well‑written and easy to follow.

### Weaknesses

**Insufficient comparison with pathology‑specific baselines**

- The baselines include only general MLLMs (GPT‑4o, LLaVA‑Med, MedDr) and no domain‑specific slide‑level or patch‑level MLLMs. Missing comparisons with: **PRISM** (slide‑level VLM), **Quilt‑LLaVA**, **PA‑LLaVA**, and **WSI‑VQA** (SOTA slide‑level VQA model). This likely inflates SlideChat’s reported gains. [Reviewers 1, 2, 3, 4]
- For WSI captioning, SlideChat is worse than **MI‑Gen**, the only pathology‑specific captioning baseline included. [Reviewers 2, 3, 4]
- No comparison with a **supervised slide‑level classification** baseline (e.g., ABMIL trained on CONCH features) on BCNB tasks (ER, PR, HER2 status, grading, subtyping). On BCNB, SlideChat’s accuracy on grading, subtyping, and HER2 is even **worse than random guess** (Appendix B.3). [Reviewers 3, 4]

**Flawed evaluation scheme for patch‑level MLLMs**

- Using a **1024×1024 thumbnail** (aspect ratio destroyed) or **only 30 random 224×224 patches** as input to GPT‑4o does not capture critical diagnostic information. The random sampling introduces high variance and may miss diagnostically relevant regions (slides typically contain >10⁴ patches). [Reviewers 1, 2, 3]
- More convincing comparisons would use larger crops (e.g., 1k×1k), prototypical‑based patch selection (e.g., feature clustering), or directly feeding slide‑level features (from Prov‑GigaPath, mSTAR) into patch‑level MLLMs. [Reviewers 2, 3, 4]
- Why not use multiple large crops (1k×1k) for GPT‑4o, given it supports images up to 2k? [Reviewer 2]

**Dataset size, quality, and preprocessing concerns**

- SlideInstruction uses **only 4,181 WSI–caption pairs** (from ~10,000 available TCGA reports). Why this subset? The prior TCGA‑report resource curates over 9K reports. [Reviewers 3, 4, 5]
- An average of **~40 VQA pairs per caption** is generated from reports that typically contain only **3–4 key findings**, likely producing many redundant or ineffective questions. [Reviewer 1]
- Dataset quality control is limited: only the SlideBench test set was reviewed by pathologists. No discussion of **inter‑rater criteria, specialties, number of questions reviewed**, or **how disagreements were resolved**. The training set (SlideInstruction) has **no expert quality control**. [Reviewer 5]
- **Over‑reliance on GPT‑4** for caption and QA generation introduces unknown biases; using other LLMs (e.g., Claude) for diversity was not explored. [Reviewer 5]
- TCGA reports are **noisy** (some very short, some include radiology data). The paper lacks a quality‑control pipeline for cleaning. Using raw or cleaned original reports instead of GPT‑generated captions could avoid hallucination propagation. [Reviewer 5]
- Handling of **one report linked to multiple WSIs** (up to 3 per patient) is not clearly addressed; the report often specifies which image it refers to, so these could be grouped appropriately. [Reviewer 5]

**Potential data leakage / unfair comparisons**

- It is unclear whether any WSIs from the **WSI‑VQA test set** appear in the SlideBench‑VQA training set; if so, comparisons would be unfair. [Reviewer 1]
- The claimed “zero‑shot” evaluation for SlideChat is questionable because the test set (TCGA) has the same distribution as the training data. The baselines are the only truly zero‑shot methods. [Reviewer 5]
- Train/test split proportions and **site‑preserving splits** (to control for TCGA batch effects) are not reported. [Reviewer 3]

**Missing analyses and ablations**

- **No failure case or hallucination analysis**, which is critical for medical MLLMs. [Reviewer 3]
- **No out‑of‑domain evaluation** (e.g., non‑cancer slides, rare diseases like EBRAINS). [Reviewer 3]
- Evaluation metrics only report **accuracy** for VQA; for medical use, **F1, false positive/negative rates**, and proper handling of “I don’t know” responses are needed. [Reviewer 5]
- No ablation on **number of patches for MIL** (e.g., 300 vs 30) or **use of global vs. all contextualized patch tokens** from the slide encoder. [Reviewers 1, 2]
- The patch size for CONCH is **224×224**; the original CONCH was trained at **448×448** – why the change? [Reviewer 2]
- The slide encoder initialization is not clarified (random vs. from a prior checkpoint). [Reviewer 2]

**Clinical significance and methodology novelty**

- The clinical utility of the VQA tasks is unclear – pathologists would not typically ask questions like those in the benchmark. Captioning might aid report writing, but current performance is insufficient for that purpose. [Reviewer 4]
- The methodology is considered **incremental**: combining an existing MIL architecture (LongNet) with LLaVA. [Reviewer 4]

**Additional reviewer questions (overlapping with criticisms)**

- How was the **diversity of the ~40 VQA pairs per WSI** verified? [Reviewer 1]
- Could **in‑context learning** be used for the baselines to make the comparison fairer? [Reviewer 5]
- The GPT cleaning prompt aims to remove sizes/measurements, but Figure 7 still contains **sizes** – can the model realistically predict size from a slide? Similarly for laterality (“left breast”). [Reviewer 4]
- How can the cleaning prompt ensure that all content in the cleaned caption is actually **visible in the slide**? [Reviewer 4]
- What are the distributions of **diagnosis/cancer types** and **submitting sites** across train/test? Is the split **site‑preserved**? [Reviewer 3]
