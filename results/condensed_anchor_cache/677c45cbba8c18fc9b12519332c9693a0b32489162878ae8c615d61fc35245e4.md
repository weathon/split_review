## Merged Review

### Summary
QRazor proposes a two-stage post-training quantization (PTQ) scheme for 4-bit quantization of weights, activations, and KV cache in transformer-based LLMs. Stage 1 quantizes data to 8- or 16-bit integers using absolute max scaling. Stage 2 compresses to 4-bit via Significant Data Razoring (SDR), which retains the four most salient bits after identifying the most significant non-zero bit in sign-magnitude representation per block. An integer-based arithmetic unit enables direct low-precision operations without decompression. Evaluations on LLaMA and LLaMA2 models show accuracy comparable or better than prior 4-bit methods, with reported hardware area and power reductions.

### Strengths
- Simple, clear, and straightforward technique combining known quantization principles.
- Enables 4-bit quantization for weights, activations, and KV cache while reducing memory and computation demands.
- Achieves accuracy better or comparable to state-of-the-art 4-bit methods (reviewer 1, 3: "much better than baselines"; reviewer 4: improvements over fine-tuned prior work are not super-impressive, but comparison is presented).
- Provides a dedicated integer-based arithmetic unit that allows direct low-precision arithmetic without decompressing SDR data; reported 61.2% area and 57.8% power reduction (reviewer 4 notes this is a simplified estimation in isolation).
- Demonstrates adaptability across different model families (LLaMA, LLaMA2) and quantization settings.
- Extensive evaluation includes task accuracy, resource usage, and power efficiency estimates.

### Weaknesses
- **Novelty concerns (reviewer 5 is strongly negative; reviewer 4 notes technique is a combination of known methods):**  
  SDR is identical to dynamic per-group max scaling, disguised with bitwise operations. The approach is merely fine-grained dynamic max-scaled quantization, not a novel compression method.

- **Incomplete comparisons against recent SOTA:**  
  Missing comparisons with QuaRot, TesseraQ, AWQ (for W4A8), GPTQ, QuIP, FrameQuant, and weight-only quantization methods. This limits assessment of relative effectiveness.

- **Limited evaluation scope:**  
  - Only tested on LLaMA/LLaMA2; missing results on Mistral, Gemma, Llama 3.2 edge versions (1B, 3B) and other architectures.  
  - Tasks primarily multiple-choice questions (reviewer 5); no perplexity results (e.g., Wikitext-103 test set).  
  - Not evaluated on fine-tuned LLMs for specific downstream tasks or complex reasoning tasks.  
  - Unclear how quantization affects inference speed; per-token activation quantization may cause slowdown (reviewer 3).

- **Accuracy and fairness issues in Table 1:**  
  - FP16 baselines for the same model show different accuracies across separate rows, raising questions about fair comparison (reviewers 3, 5).  
  - Effective bit-widths (including scaling factors, flags) are not clearly stated for baselines and QRazor, preventing fair comparison.

- **Hardware and implementation shortcomings:**  
  - No discussion of implementation on existing hardware.  
  - Hardware analysis is presented in isolation, neglecting unchanged components (e.g., memory hierarchy), potentially inflating power advantages.  
  - No area/power comparison against baseline arithmetic units for the same QAT/PTQ methods.  
  - Overhead of the two-stage quantization process (computational and memory) is not analyzed (reviewer 1).

- **Technical flaws and omissions:**  
  - Integer shifts limit precision compared to floating-point scaling, as the method does not effectively use the full range of the 4-bit representation (reviewer 3).  
  - Outlier analysis is superficial; it is unclear why initial truncation does not always place a 1 in the most significant bit, and the impact of block-level max from larger groups is not explored (reviewer 4).  
  - Coarse-grained scaling is claimed favorable for activation quantization, but this is incorrect since fine-grained scaling can be fused with prior ops, whereas coarse-grained scaling requires a slow reduction (reviewer 5).  
  - Min-max scaling is introduced but never used in the work (reviewer 5).  
  - Figure 1 is hard to read without zooming; caption is unhelpful (reviewer 5).  
  - Sign representation description is ambiguous ("2s complement except the sign bit for negative activations") (reviewer 5).  
  - Missing experiments: percentage of zeroed elements per block after aggressive quantization, average number of leading bits truncated per block (reviewer 4).
