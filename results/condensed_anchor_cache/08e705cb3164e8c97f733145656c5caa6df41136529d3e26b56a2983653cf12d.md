## Merged Review

### Summary

The paper proposes the In-context Autoencoder (ICAE), which uses a fixed LLM with LoRA to compress a long context into a small number of memory slots. ICAE is pretrained with autoencoding and language modeling objectives on unsupervised text, then instruction fine-tuned on a new Prompt-with-Context (PwC) dataset. Experiments demonstrate roughly 4× compression on Llama-7B with ~1% additional parameters, and show that compression ratio affects reconstruction quality in interesting ways.

### Strengths

- The problem of compressing context for LLMs is timely and important; the proposed solution is simple, intuitive, and well grounded.
- The idea of using autoencoding to compress context is novel, and the assumption that better LLMs allow more compact compression is validated and connects to human memorization.
- The paper is well packaged and generally clear; important information is provided in both the main text and appendix.
- The analysis of how compression ratio affects reconstruction performance, and how different text formats affect memorization, is insightful.
- A thorough set of experiments demonstrates 4× compression with little degradation in task quality, making this a promising first step toward even higher compression (e.g., 10×) with larger models.
- ICAE introduces only ~1% additional parameters via LoRA, can be incorporated into any LLM, and has diverse potential applications (long context, CoT reasoning, etc.).

### Weaknesses

- **Limited comparison with existing work.** Baselines are lacking: the paper does not compare with Gisting, Recurrent Memory Transformer, Compressive Transformer, or Auto Compressor. At least one direct comparison (e.g., Gisting, which claims 26× compression) is needed to judge trade-offs. The discussion of related work is also incomplete regarding other long-context techniques such as LongLoRA and FIRE. The paper only briefly mentions Chevalier et al. (2023), which covers very similar ideas.
- **Missing ablation studies on design choices.** For example, whether the encoder’s input token embeddings must be in the same space as the decoder’s input embeddings, and the impact of using LoRA versus full fine-tuning. Both are important to understand the method’s behavior.
- **Single-use overhead not evaluated.** Compression is only beneficial when the same context is used multiple times; the paper does not examine the trade-off between compression time and benefits for single-use scenarios. The overhead of compressing new contexts needs more thorough analysis.
- **Quadratic complexity of encoding still required.** The encoder still processes the full context with quadratic self-attention. The proposed multiple-span approach (Figure 6) is preliminary and only evaluated on perplexity; additional validation on practical benchmarks (e.g., QA) is needed to confirm the method works when fine-tuned on a single span.
- **No comparison to explicit summarization.** One could simply summarize the context with a model like GPT-4 and feed the summary as words. The claim in Figure 2 that black-box memory is more compressive is not supported by experiments, and summarization has the advantage of working with black-box API models.
- **Adaptive compression not explored.** Since the amount of information varies with content, adaptive-sized memory slots could yield more compact compression but is not investigated.
- **Both pretraining tasks and instruction fine-tuning lack details.** The token count or number of examples for each pretraining task is not reported; convergence speed is not discussed; it is unclear whether the two pretraining tasks are interleaved or sequential.
- **Potential unfairness in instruction fine-tuning comparison.** In Table 5, it is unclear whether “System 2” (rows 2–5) was also fine-tuned on the PwC dataset; if not, that comparison is unfair. Furthermore, a direct comparison to Llama2-7b-chat (without ICAE) and GPT-4 is missing from that table.
- **Training cost and scalability concerns.** Training required 8 A100 GPUs (80GB); approximate cost in time and money is not provided. The method requires pretraining even though parameter overhead is small, which may limit applicability in resource-constrained settings.
- **Unclarities about memory slot representation and attention.** The exact format of memory slots (e.g., whether they are vectors before the final softmax) is not described. The effect of causal attention on memory slot order and whether that is optimal is not addressed. Additionally, it is unclear whether the encoder and decoder are initialized from the same LLM checkpoint, and how to reconcile bidirectional encoder attention with the decoder’s autoregressive attention.
- **Unexplained experimental results.** The rightmost plot in Figure 4 shows a U-shaped loss trend with no intuitive explanation. Table 1’s first row shows a perplexity increase even with no compression, which is not explained.
- **Hallucination claim needs clarification.** The claim that pretrained ICAE suffers less hallucination than a non-pretrained model: are both trained on the same instruction fine-tuning set? If not, the comparison is invalid.
- **Missing experiments on prompt placement.** In instruction fine-tuning, passing the user prompt to the encoder (rather than the decoder) was not tried; its effect is unknown.
- **Minor issues:** In Section 3.3.3, “Table 6(Right)” should be “Figure 6(Right)”; table/figure placement and link colors could be improved for readability.
