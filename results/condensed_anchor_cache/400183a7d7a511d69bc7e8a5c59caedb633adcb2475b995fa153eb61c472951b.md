## Merged Review

### Summary
The paper presents CAKE (Cascading and Adaptive KV Cache Eviction), a method that improves LLM inference efficiency by optimizing KV cache eviction through adaptive cache allocation across layers, guided by layer-specific attention dynamics (spatial and temporal). It formulates cache allocation as a cake-slicing problem and introduces a novel eviction indicator that accounts for shifting token importance over time. Experiments on LongBench and NeedleBench show CAKE preserves performance with only 3.2% cache, consistently outperforms baselines, and achieves 10× faster decoding for 128K sequences vs. full cache with FlashAttention.

### Strengths
- **Novel and practical approach**: CAKE is the first work to consider adaptive memory budgets for different layers of LLMs, addressing a timely problem for on-device applications. The approach is intuitive, given insights from attention dynamics analysis.
- **Clear writing and presentation**: The paper is well-organized, with clear motivations, a great paper flow, and beautiful figures (e.g., Figure 2 clearly contrasts CAKE with existing methods). Writing is clear, though one reviewer found the structure slightly chaotic; another reported almost no typos.
- **Theoretical rigor**: Theorem 2 rigorously demonstrates equivalence between the preference-guided cascading cache management and the vanilla preference-prioritized adaptive allocation strategy. Theorem 1 is noted as basic but sound.
- **Comprehensive empirical analysis**: Experiments span 16 tasks across multiple LLMs (Llama, Mistral) with 7B-8B parameters, under various memory constraints, especially low-memory scenarios. The method shows actual improvement in inference latency (10× faster decoding).
- **Compatibility and efficiency**: CAKE is straightforward, compatible with existing KV caching strategies (easy to integrate), and outperforms full cache with FlashAttention on speed. The method also demonstrates superior performance at very low memory (3.2% cache).

### Weaknesses
- **Limited model scale and backbone diversity**: Most experiments use 7B-8B LLMs (only Llama and Mistral), limiting generalizability to much larger models. It would be valuable to see computational cost and performance across different LLM sizes. A reviewer suggested adding backbones like Phi, Qwen, or Gemma.
- **Modest empirical improvements over baselines**: On some benchmarks (noted in Table 1), existing methods like TOVA and SnapKV achieve better results. The improvements over baselines are relatively modest, which could suggest limited practical advantage in some cases. The paper should analyze when CAKE succeeds or fails (e.g., what dataset characteristics lead to better/worse performance).
- **Unclear motivation and necessity of adaptive allocation components**: The motivation for using spatial dispersion and temporal shift in cache size allocation is unclear; deeper intuition would help. Table 2 shows the adaptive allocation strategy provides minimal improvement, raising questions about its necessity.
- **Incompatibility with FlashAttention**: One reviewer flags that CAKE is incompatible with FlashAttention, which is widely adopted for efficient LLM training/inference. This may limit practical adoption. (Note: Abstract claims CAKE outperforms full cache with FlashAttention, suggesting a disagreement about incompatibility.)
- **Missing strong baselines**: The comparison set is not sufficiently strong. The paper should include KVQuant, KIVI (both joint with FlashAttention), and GEAR (original settings) for more robust evaluation.
- **Terminology and presentation issues**: 
  - "KV" should be spelled as "Key-value" on first use (abstract/title).
  - The word "optimally" in the abstract is controversial; suggest "adaptively" unless proven optimal.
  - Equation (4) is confusing: clarify whether `A[i,:] log A[i,:]` is an inner product and add explanation.
  - Theorem 1 is basic and better described as a proposition; the notation "For layer l ∈ [L]" should clarify whether it means any fixed layer or existence.
- **Reproducibility concerns**: The code has not been open-sourced, raising concerns about reproducibility.
- **Minor reviewer disagreement**: One reviewer (score 10) sees no major weaknesses, while others identify several limitations. The high-scoring reviewer questions how CAKE scales to larger models and whether it could help transformers compete with RNN-based models like Mamba.
