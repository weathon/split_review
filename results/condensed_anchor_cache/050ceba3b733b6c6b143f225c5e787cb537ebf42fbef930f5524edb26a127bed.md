## Merged Review

### Summary

This paper proposes SensorLLM, a two-stage framework to enable text-only LLMs to understand time-series sensor data for human activity recognition (HAR). Stage 1 (Sensor-Language Alignment) uses a pre-trained time-series embedding model (Chronos) and an MLP alignment module to map sensor embeddings into Llama-3’s input space, with training data generated by automatically creating trend-descriptive text from signal processing. Stage 2 (Task-Aware Tuning) freezes the aligned LLM and trains a small MLP classifier on the final token embedding for HAR classification. The method is evaluated on four HAR benchmarks and compared against both HAR-specific models and GPT-4o.

### Strengths

- **Important problem**: Enabling LLMs to understand wearable sensor time-series is a relevant and underexplored direction, with potential for personalized AI assistants and cross-dataset generalization (Reviewers 2, 4, 3).
- **Clear presentation and open-source code**: The paper is well-written, and the approach is described in sufficient detail to follow. Code is already available (Reviewers 1, 2). Figure 2 (schematic) is clear (Reviewer 4).
- **Comprehensive evaluation on 4 datasets** with multiple metrics and comparisons to prior HAR models; appendix provides SOTA context, dataset details, and many example outputs (Reviewers 1, 2). The metrics for sensor data understanding are well-implemented (Reviewer 1).
- **Interesting alignment data generation**: The use of automatically generated QA pairs to obtain sensor embeddings without human labels is a clever way to adapt time-series embeddings to the language space (Reviewer 4). The data generation process is novel for alignment (Reviewer 4).
- **General formulation**: The framework can handle different sensor modalities and channel counts, which is well appreciated (Reviewer 4).

### Weaknesses

- **Unclear value of using a large LLM for a fixed multi-class HAR classifier**: The approach effectively uses frozen Chronos (~100M params) + frozen Llama-3-8B + a small MLP classifier. This is massive overkill for a standard supervised HAR task, with no exploration of zero-shot classification, reasoning, or question-answering on sensor data. The paper claims “LLM” but the model is essentially a feature extractor plus a classification head, making the name a misnomer (Reviewer 2). A proper baseline of Chronos + MLP classifier (without the LLM) is missing (Reviewer 2). The problem formulation—using a versatile LLM only for restrictive multi-class classification—needs justification (Reviewer 2). [See Listen, Think, and Understand (ICLR’24) for an example of LLM QA on input sensor data.]

- **Marginal or no accuracy gains over simpler, smaller models despite huge parameter cost**: On 3 out of 4 datasets, the F1 score of SensorLLM overlaps with that of Attend (Abedin et al., 2021), a model with a plain convolutional backbone + GRU + attention. SensorLLM is roughly two orders of magnitude larger but on UCI-HAR it achieves a *lower* F1 score than Attend (Reviewer 2). This undermines the practical benefit of the LLM stack (Reviewer 2). Moreover, the SOTA baselines compared (e.g., Essa & Abdelmaksoud 2023, Suh et al. 2023) report higher F1 scores than cited for some datasets (e.g., PAMAP2 0.86, MHealth 0.94, USC-HAD 0.83), raising concerns about whether the baselines are the current best (Reviewer 1). Note: other pre-trained HAR models like LIMU BERT or models leveraging UK Biobank are not compared, making the comparison unfair in terms of model complexity and data size (Reviewer 3).

- **Sensor-language alignment methodology is questionable and limited in expressiveness**: The alignment training data is generated by running simple signal processing (slope detection) to produce trend descriptions (increasing, decreasing, stable) and then filling in templates automatically. This could be done without an LLM; the added value of having the LLM produce such outputs is unclear (Reviewer 2). The trend descriptions and simple statistics (min, max, mean) ignore signal amplitude and higher-order features, which are critical for motion data. For example, very different activities (e.g., walking vs. running) might only differ in amplitude, not trend direction (Reviewer 4). The capacity of this alignment to handle complex signal representations is untested (Reviewer 3). Furthermore, the assumption that LLMs can reliably produce these trends without hallucination is not validated (Reviewer 3).

- **Missing ablation or evaluation with other LLMs**: The approach keeps Llama-3-8B frozen and claims generality, but no experiments with other LLMs (e.g., Mistral, GPT-2, etc.) are provided. It is unclear whether any observed performance is dependent on Llama-3 specifically (Reviewer 2).

- **Insufficient architectural detail**: The exact operation of the task-aware tuning module is not explained clearly. It is not evident how the alignment module output is fed into the classification head, what type of head is used (linear/MLP), or how the special tokens per sensor channel are incorporated and what advantage they provide. An architecture diagram with these components would help (Reviewer 1). The number of trainable parameters in the task-aware module is not stated (Reviewer 1).

- **Unfair or missing comparisons**: 
  - SOTA comparisons on page 9 (lines 447-455) lack sufficient detail (data splits, preprocessing, training details) to assess true gains (Reviewer 1). 
  - Baselines are trained on limited data compared to the large LLM+Chronos stack; controlling for model complexity and data size is missing (Reviewer 3).
  - GPT-4o is the only LLM baseline for sensor understanding; other methods for sensor data description exist but are not referenced (Reviewer 1). 
  - Included pretrain+finetune HAR models as baselines would be relevant (Reviewer 3). 
  - The cross-dataset experiment (Table 3) lacks clarity on how it is implemented (same channels but different activity classes?) (Reviewer 4).

- **Evaluations on small, limited datasets**: Three out of four datasets have test sets from ≤3 subjects. Given the large model capacity, overfitting is a concern. Larger benchmarks (e.g., Capture24) or leave-one-subject-out evaluation should be included to assess generalization (Reviewer 4).

- **Motivation not fully aligned with claimed contribution**: The paper states it aims to address scaling across sensor configurations (a HAR generality problem), but the method focuses on improving interpretation via language trends. The evidence for enhanced interpretation of sensor data via LLMs is not provided (Reviewer 4).

- **Missing details on experimental setup and human evaluation**:
  - Data preprocessing (sampling rate, augmentation, window length) not reported (Reviewer 4).
  - How the 5 human experts evaluated the sensor understanding outputs—who they are, level of expertise, and how data was presented—is not described (Reviewer 1).
  - The role of synonymous QA generation variants is not ablated; is there a performance benefit? (Reviewer 4)
  - GPT-4o’s use as a baseline lacks details (e.g., input formatting, prompting method) (Reviewer 4).
  - Training efficiency claims based on “small set of trainable weights” ignore total parameter count and training cost (Reviewer 4).
