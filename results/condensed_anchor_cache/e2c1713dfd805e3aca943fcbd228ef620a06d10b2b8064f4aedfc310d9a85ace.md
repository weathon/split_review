## Merged Review

### Summary
This paper proposes FedGC, a framework that adds synthetic data generated by foundational models (e.g., Stable Diffusion, ChatGPT) to each client’s private dataset in federated learning (FL) to mitigate data heterogeneity. The authors summarize four key aspects of data generation (budget allocation, prompt design, generation guidance, training strategy) and propose three simple approaches for each. Experiments on image (CIFAR-10, EuroSAT) and language (PACS, VLCS, Sentiment140, Yahoo! Answers) datasets—with heterogeneity synthesized via Dirichlet distribution—show that mixing generated data with private data improves FL performance (FedAvg, FedProx, SCAFFOLD) and reduces privacy risk (membership inference attack success). Ablations find that increasing generative data always helps, that performance gains occur even when generated data is not similar to private data, and that generative data reduces client drift. However, one reviewer (score 3, confidence 5) is highly skeptical of the practicality, while another (score 8, confidence 4) praises clarity but questions theoretical depth; the third (score 6, confidence 3) raises conceptual inconsistencies.

### Strengths
- The use of foundational models to assist federated learning is an interesting and timely direction. (R1, R2, R3)
- The experiments and ablation study are detailed and thorough, covering algorithmic choices (amount of generative content, equal allocation per user, multiple prompts, simultaneous use of prompts and private data) and their effects on FL dynamics (client drift, heterogeneity reduction). (R1, R2)
- The paper is clear, straightforward, and easy to read, with a well-motivated problem. (R3)

### Weaknesses
- **Practical infeasibility for cross-device FL** (R1): Stable Diffusion requires ≥4.2 GB space and heavy GPU memory for local generation, which is unrealistic for IoT/edge devices. Using black-box APIs like ChatGPT leaks private prompts to a third party, contradicting FL’s privacy goal.
- **Increased local computational burden** (R1): Combining real and generated data enlarges the local dataset, raising memory and iteration costs, which may be prohibitive for resource-constrained clients.
- **In-domain generation / dataset contamination** (R1, R2, R3): Stable Diffusion is trained on LAION-5B, which may contain test samples (e.g., CIFAR-10). This could inflate performance via memorization rather than genuine learning. The paper’s synthetic dataset (merging CIFAR-10, EuroSAT, PACS, VLCS, Sentiment140, Yahoo! Answers with Dirichlet-based heterogeneity) is not a realistic FL benchmark; real-world datasets or standard FL benchmarks should be used instead.
- **Counterintuitive performance pattern** (R2): Table 2 and Figure 2 show that more generative data always improves performance, yet Table 5 shows FL on *only* generative data (no private data) performs poorly. The authors should explain this inconsistency.
- **No incentive for federated learning** (R2): If local training on private data plus generated data already achieves comparable performance, clients have no reason to participate in FL. The setting risks being insignificant.
- **Lack of theoretical contribution** (R3): The paper contains no theorem, proof, or new equation. The proposed approaches for the four aspects are straightforward engineering choices, not novel representations suitable for a venue like ICLR.
- **Unclear relationship between generation and FL** (R3): The only communication about generation is the number of samples per client; there is no cross-client information exchange about generation quality or strategy. The work could be presented in a non-federated local learning setting.
- **Dependence on a suitable generative model** (R3): The method assumes a generative model exists for the problem domain. What if no such model is available (e.g., for niche or new tasks)?
- **Missing experimental details** (R1, R2): (a) How many synthetic samples per client were generated for Table 1? (b) Does each client generate data only for its observed labels or for the entire label space? (c) The paper should explicitly discuss whether the benchmark datasets used for evaluation overlap with the generative model's training data.
