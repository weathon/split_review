## Merged Review

### Summary
The paper proposes FastAttention, adapting FlashAttention to NPUs (Ascend) and low-resource GPUs (Volta V100). It introduces two-level tiling, a tiling-mask strategy for causal masking, and a tiling-AllReduce strategy for multi-NPU communication; on Volta GPUs it redesigns operand layout in shared memory and adds a CPU-GPU cooperative strategy for long-context inference. Achieved speedups: 10.7× on NPUs compared to standard attention; 1.43× on V100 versus equivalents in xformers. Llama-7B reaches 5.16× higher throughput; Pangu-38B gets 1.46× end-to-end speedup. Supports up to 256K input length on 8 V100 GPUs.

### Strengths
- The ability to run memory-efficient attention on a greater number of AI accelerators (NPUs and pre-Ampere GPUs) is an important contribution to the community. [R3]
- Novel tiling strategies (two-level tiling, tiling-mask, tiling-AllReduce) for memory efficiency, causal-mask memory saving, and communication reduction. [R1, R2, R3]
- Well-designed solution that effectively utilizes the Cube/Vector units and memory hierarchy of Ascend NPUs. [R3, R1]
- Clear comparison of Matrix Multiply Accumulator (MMA) usage in Volta versus later architectures. [R3]
- The software pipeline and CPU-GPU cooperative offloading method are not explored in the official FlashAttention. [R2]
- Achieves good speedup: 10.7× on NPUs (single-accelerator), 1.43× on Volta GPUs, 5.16× throughput for Llama-7B, 1.46× end-to-end for Pangu-38B. [R1, R2, R3]
- Thorough and comprehensive evaluation covering single and multi-accelerator scenarios. [R3]
- The paper is reasonably well-written and understandable. [R1]

### Weaknesses
- **Unclear tiling description (Section 4.1):** The two-level tiling strategy is not fully explained. It lacks a mathematical representation with equations showing tile dimensions, a step-by-step breakdown of operations, and a comparison with existing FlashAttention tiling. [R1]
- **Undefined term “Linear calculation” (Section 4.2):** This term is introduced without definition, yet many optimizations rely on it. The paper should define “Linear calculation” when first used and clarify how these calculations proceed under two-level tiling. [R1]
- **Unclear CuTe sentence (lines 298-299):** “Given the CuTe library typically focuses… “ is ambiguous; clarification is needed. [R1]
- **Data layout adaptation (Section 4.3):** It is unclear whether the operand layout adaptation (using CuTe) is architecture-agnostic or must be done manually for each new model. The process for resolving bank conflicts is also not described; procedural details are missing (the appendix is insufficient). [R1]
- **Undefined notation (Section 4.4):** The symbols \(L_{\text{CPU}}\) and \(L_{\text{GPU}}\) are introduced but never defined. [R1]
- **Missing baseline in Figure 8:** A comparison with the HuggingFace Transformers implementation of standard attention is missing. Given the large user base, this would better demonstrate improvements over vanilla implementations. [R1]
- **Minor typo:** “thread in a Wrap” (line 287) should be “warp”. [R1]
- **Incremental contribution:** The fusion and tiling do not show significant difference from FlashAttention or memory-efficient Attention (Self-attention Does Not Need O(n^2) Memory). The paper also lacks proper credit to this earlier work, which already supports TPU. [R2, R3]
- **Inaccurate claim about non-CUDA support:** The introduction states existing FlashAttention cannot run on non-CUDA architectures, but memory-efficient Attention supports TPU, and AMD FlashAttention (RoCM) exists. [R2]
- **Two-level tiling vs. standard GEMM (Section 4.2):** The two-level tiling described appears similar to normal GEMM implementations on NPU (block-level and warp/MMA-level). A comparison with typical GEMM tiling would clarify the unique contribution. [R2]
- **Research challenge of V100 support not highlighted:** The adaptation to Volta GPUs is presented largely as an engineering problem. Highlighting the unique design differences (e.g., lack of tensor cores) and discussing the value of supporting older architectures would strengthen the paper. [R2]
- **Limited hardware scope:** The title mentions “low-resource GPUs,” but the paper only demonstrates support for V100 (Volta). The authors should explicitly state which hardware architectures are supported (e.g., all Volta? Pascal? earlier? non-NVIDIA?) and which are not. [R3]
- **Only inference scenario discussed:** It is unclear whether FastAttention supports training. If training is supported, the paper should discuss memory requirements during backpropagation and how optimizations affect gradient computation. If not, the scope should be clarified. [R3]
- **Insufficient background on attention–linear fusion (Section 4.2):** The prior work and background on the fusion of attention and linear calculations could be explained more clearly, with relevant citations. [R3]
- **Causal mask optimization (Section 4.1):** The tiling-mask strategy generates a causal matrix. Could the masking be achieved with a simple kernel instruction that sets forbidden entries to zero? Evaluating this alternative in the experiments would strengthen the paper. [R3]
- **Figure captions need more detail:** Captions should be self-contained; they should specify whether results measure prefill vs. decode latency, describe the parallelization strategy, and include key takeaways. [R3]
- **Implementation details missing:** The paper should state whether the code was built on existing libraries or repositories, and whether there is a plan to integrate FastAttention into open-source LLM frameworks. [R3]
- **NPU generality not addressed:** Does FastAttention work with any type/version of NPU, or only the Ascend model tested? [R3]
