## Merged Review

### Summary
This paper proposes a framework (GRAPHTEXT) for representation learning on text-attributed graphs (TAGs). It uses an LLM to generate zero‑shot classification predictions and textual explanations. An LLM‑to‑LM interpreter translates these explanations into features. The final GNN predictor combines LLM predictions, LM‑encoded raw text and explanation features, and shallow embeddings. Experiments are done on Cora, PubMed, ogbn‑arxiv, and a newly introduced dataset tape‑arxiv23.

### Strengths
- The paper is clearly written and easy to follow. (R1, R2)
- Bagging LLM predictions, LM features (from raw text and explanations), and shallow embeddings is a reasonable design for node classification. (R1)
- The method achieves state‑of‑the‑art results on well‑established TAG datasets: Cora, PubMed, ogbn‑arxiv, and the new tape‑arxiv23. (R1, R3)
- Training is significantly sped up: 2.88 × improvement over the closest baseline on ogbn‑arxiv. (R3)
- The approach augments language models with LLM‑generated features. (R2)
- Reviewer 3 considers the integration of LLMs with GNNs “novel and effective,” while reviewers 1 and 2 find the technical contribution limited (see Weaknesses). (R3 positive, R1/R2 negative)

### Weaknesses
- **Limited novelty and graph‑related contribution.** The method is essentially an application of LLMs for data augmentation on TAGs; it has little to do with graph structure beyond using a GNN at the final step. (R1, R2)
- **Missing important baselines.** GraphFormers (GNN‑nested transformer) and Patton (language model pretraining on text‑rich networks) are not included, making it hard to judge performance against related work. (R2)
- **Missing experimental results.** Table 1 lacks entries for the Giant baseline. (R3)
- **Lack of evaluation tasks.** Only node classification is performed; link prediction (or graph classification) should be added to demonstrate representation quality. (R2)
- **Insufficient ablation studies.** (R2, R3)
  - Are separate LMs needed for original text and explanation encoding? (R2)
  - Is fine‑tuning the LM in step 2 necessary? (R2)
  - Only BERT is evaluated; experiments with Sentence‑BERT, RoBERTa, or other embedding models are missing. (R3)
  - Prompt robustness is not explored – only one prompt is used; sensitivity to different prompt phrasings should be tested. (R3)
- **Theorem 4.4 is not specific to the problem.** It assumes strong conditions not clearly justified in the context of LLMs and LMs on TAGs. (R2)
- **Time and monetary cost analysis missing.** The paper uses the ChatGPT API but does not report number of API calls, input/output token lengths, total monetary cost, or processing time per dataset given API rate limits. (R3)
- **Training memory cost.** Full fine‑tuning DeBERTa requires substantially more memory than pure GNN methods. (R1)
