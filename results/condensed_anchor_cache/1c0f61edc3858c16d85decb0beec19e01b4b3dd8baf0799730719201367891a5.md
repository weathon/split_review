## Merged Review

### Summary

The paper introduces EMMA-500, a multilingual language model (based on Llama 2 7B) continually pre-trained on 546 languages using the newly compiled MaLA Corpus (spanning 939 languages, filtered to those with >100k tokens). It also presents PolyWrite, an open-ended generation benchmark using machine-translated prompts and BLEU-based evaluation. The model is evaluated across multiple multilingual benchmarks (FLORES, XCOPA, XStoryCloze, Glot500-c, etc.) and claims strong performance in commonsense reasoning, machine translation, and open-ended generation, especially for low-resource languages. The main technical contributions are the data pipeline, the model, and the benchmark. Two reviewers (score 5) found the work solid and the resources beneficial; one reviewer (score 3) was substantially more critical, especially concerning evaluation rigor, novelty, and presentation.

### Strengths

- Tackles the long tail of low-resource languages (546 languages) and shows that more languages are reachable for inclusive language modeling.
- In-depth documentation of preprocessing steps (ISO code normalization, writing system treatment, whitespace cleaning) – essential for reproducibility and often undervalued.
- Extensive evaluations performed on a plethora of datasets (FLORES, XCOPA, XStoryCloze, TyDiQA, MMLU, MBPP, HumanEval, Glot500-c, PolyWrite).
- The MaLA Corpus and PolyWrite benchmark will be beneficial to multilingual NLP researchers if made public.
- Good emphasis on normalizing ISO codes and handling writing systems, which is crucial for multilingual modeling.
- Extensive experiments demonstrating effectiveness of continual pre-training for underrepresented languages.

### Weaknesses

- **Limited novelty / Related work:** The corpus is compiled by merging and cleaning existing datasets; the method for creating the multilingual benchmark is standard in the community. The paper does not discuss how it differs from past efforts beyond covering more languages. The key finding (continual pre-training improves multilingual capacity) is considered trivial by one reviewer. One reviewer specifically noted that missing baselines include ALMA and Bayling (other Llama 2 7B continual pre-training models).
- **Missing comparisons:** A direct comparison with Aya-23 (a multilingual-first decoder released in May 2024) is omitted from most evaluations despite using its evaluation sets. Aya-23 is only included in code generation tasks with no explanation for this selective inclusion. Additionally, Llama 3.1 (which supports only 8 languages) is benchmarked prominently, which is questionable for evaluating a multilingual model.
- **Evaluation metrics and reliability:**
  - Two of three main evaluation results (FLORES, PolyWrite) rely on BLEU, which is not equally suitable for all 500+ languages (e.g., surface-based, underestimates paraphrases, tokenizer-dependent). ChrF++ would be more robust.
  - PolyWrite is entirely machine-generated, machine-translated, and machine-filtered; its reliability and Western-centric bias are unclear. The self-BLEU diversity metric is questionable without an accuracy metric.
  - BLEU scores in low ranges (e.g., 1–2 BLEU differences in Table 6) are not supported by significance tests or qualitative examples.
  - Self-BLEU evaluation presumably depends on sampling hyperparameters, which are not reported.
- **No human evaluation:** There is no human evaluation of the final model, especially for low-resource languages. The only 500+ language benchmark is intrinsic modeling on Glot500-c, which may overlap with pre-training data, masking quality issues.
- **Unfair comparisons:** Comparing models that do not officially support certain languages on those languages distorts averages. The paper should separate evaluation: (a) on languages supported by all baselines, (b) on newly covered languages with basic quality checks (language correctness, output length).
- **No safety evaluation:** Data quality issues in low-resource languages can introduce biases; no safety-related evaluation is performed.
- **Presentation issues:** 
  - Contributions section is confusing (especially given MaLA-500 from prior work). Should use bullet points.
  - Result tables are overcrowded with text; key results supporting main claims are hidden in the appendix. The main goal (tail languages vs. matching other models in their supported languages) is unclear.
  - Tables should be easier to read: bold important numbers, add arrows for higher/lower better.
  - Standard language resource taxonomy (Joshi et al.) is not used; the authors create their own high/mid/low categorization based on token count without justification.
- **Missing details:**
  - Relation to prior MaLA-500 model/work and key improvements over it are not explained.
  - How the data mix weights were chosen (no ablations or process description).
  - No 0-shot evaluations on n-shot benchmarks (e.g., FLORES 3-shot) to isolate ICL contribution.
  - Global batch size set to 16M tokens instead of the common 4M (as in Llama 2) – no explanation.
  - Linear 121–122: “This issue is resolved …” – which issue?
  - Whitespace cleaning only applies to whitespace-tokenized languages; it is unclear if non-whitespace languages have other cleaning issues.
- **Specific questions that double as criticisms:**
  - Why was Aya-23 excluded from most evals despite being a popular multilingual benchmark?
  - Why does Tower-Instruct (built for translation) perform so poorly in Table 4?
  - For PolyWrite, are the prompts equally representative for all 500+ languages?
  - What sampling parameters were used for self-BLEU, and how do they affect diversity scores?
  - Are 1–2 BLEU differences significant? Provide evidence (significance tests or examples).
