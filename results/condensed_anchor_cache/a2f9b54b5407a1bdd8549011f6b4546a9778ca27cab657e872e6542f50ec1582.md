## Merged Review

### Summary

This paper presents Articulate-Anything, a system that automates the creation of articulated 3D objects from diverse input modalities (text, images, videos) for use in simulators. It leverages vision-language models (VLMs) to generate code (URDF) with an actor-critic iterative refinement loop, and retrieves meshes from existing datasets. On PartNet-Mobility, it achieves 75% success rate, substantially outperforming prior work (8.7–12.2%). The paper also demonstrates robotic policy training using generated assets and real-world transfer.

### Strengths

- **Multi‑modality**: Handles text, images, and videos as input, enabling broader application.
- **Training‑free VLM usage**: No network training or fine-tuning required, avoiding the need for large articulated‑object datasets.
- **Iterative actor‑critic refinement**: The closed‑loop, self‑correcting design demonstrably improves accuracy and robustness.
- **Strong quantitative results**: On PartNet‑Mobility, success rate jumps from ~10% (prior) to 75%; comparative gains in link placement and joint prediction are clear.
- **Well‑motivated and original**: Addresses an important problem (automated articulation) with a novel combination of VLMs and code generation; contribution considered significant by most reviewers.
- **Detailed failure‑case analysis**: Figure 8 provides insight into where the pipeline outperforms baselines and where it still fails.
- **Code as structural representation**: Using code to model articulation is a principled and extensible choice.
- **Manual ablations**: The effects of different input modalities are explicitly studied (Sec. 5.1).
- **Comprehensive supplementary material**: The website offers visualizations, code, and additional results.

### Weaknesses

- **Lack of statistical rigor**: Table 1 reports only averages without variance or confidence intervals; Figure 5’s success rates lack error bars or statistical tests (e.g., χ², Fisher’s exact). The claim “significantly outperforms” is not formally justified.
- **Robotics evaluation incomplete**: The robotic policy experiment (Sec. 6) lacks quantitative metrics (success rates). It is unclear whether the generated assets come from video/images of the same RoboSuite objects or directly from RoboSuite’s built‑in assets. Real‑world experiments are absent; the section feels superficial.
- **Retrieval dependency**: The system retrieves part meshes from a fixed dataset (e.g., PartNet‑Mobility) rather than reconstructing the input object. This constrains the method to existing shapes and may produce objects that differ from the real‑world counterpart, especially when using CLIP‑based text retrieval. No quantitative reconstruction metric (e.g., Chamfer Distance) is reported. (One reviewer (rating 3) considers this a fundamental limitation.)
- **Limited technical novelty**: Several reviewers note that the core approach is “mainly prompting VLMs” with actor‑critic refinement providing “only limited accuracy gains”. This contrasts with other reviewers who found the contribution significant and well‑applied.
- **Missing ablation on VLM architecture**: Only Google Gemini is tested; performance may vary with different VLMs (e.g., GPT‑4V, Claude), and the system’s robustness to such changes is unknown.
- **Unclear 3D positioning and collision handling**: The spatial relations in the code (e.g., “door left of furniture body”) are 2D and do not resolve the 3D placement (e.g., front vs. back surface, height). No mechanism is described to prevent part meshes from colliding or overlapping. The number of candidate solutions generated by the actor and whether the relation set covers all possibilities is not specified.
- **Joint‑type generality limited**: Only prismatic and revolute joints are evaluated; more complex types (cylindrical, universal, helical, combined motions) are not tested, limiting real‑world applicability.
- **Threshold justification lacking**: The success criteria (position 50 mm, angle 0.25 rad ≈14.3°) are used without rationale or sensitivity analysis; the loss weighting in Eq. (1) is not discussed.
- **In‑the‑wild results incomplete**: The main text presents only brief qualitative examples; quantitative evaluation of in‑the‑wild inputs is not provided.
- **Missing references to related actor‑critic LLM works**: For example, Text2Reward (arXiv:2309.11489) uses a similar iterative refinement paradigm, yet is not cited.
- **Technical clarity issues**: The target affordance extraction (Sec. 4.4) and how link placement/joint prediction adapt to different input modalities are not sufficiently explained; a pseudo‑code would help.
- **Category‑wise accuracy unreported**: Performance may vary significantly across object categories (e.g., simple windows vs. complex toilet seats), but no per‑category breakdown is given.
- **Impact of prompted examples unknown**: The number of few‑shot examples used in prompts is not ablated, leaving its effect on performance unclear.
- **Iteration evolution not shown**: The paper does not illustrate how link and joint predictions improve over the actor‑critic iterations.
- **VLMs for numerical output**: Directly outputting dimensions and angles from VLMs raises reliability concerns for safety‑critical embodied applications, as LLMs struggle with consistent numerical reasoning.
