## Merged Review

### Summary
This paper proposes a framework combining Evolutionary Algorithms (EAs) with Large Language Models (LLMs) to generate node-scoring functions for identifying critical nodes in complex networks. The method includes Manual Initialization (seeding initial scoring functions), Population Management (diversity- and fitness-based selection), and LLM-based Evolution (crossover and mutation via LLM prompts). Experiments on six networks (Jazz, Twitter, Network Science, Synthetic Network, Power Grid, LastFM) compare against nine baselines using ANC_gcc and ANC_pc metrics. Results show the method often outperforms baselines. Ablation studies and function analysis are also provided.

### Strengths
1. **Novel problem framing**: Casting critical node identification as a code-generation task, using LLMs to produce node-scoring functions, is a creative departure from traditional heuristics (reviewers 1,2,4,5).
2. **Integration of EA + LLM**: The LLM-based evolution operator extends the use of LLMs beyond question-answering, and the general framework (generation-update mechanism, crossover/mutation via LLMs) is a promising paradigm for combinatorial optimization (reviewers 2,4,5).
3. **Population management for diversity**: The use of semantic similarity and function embeddings to maintain population diversity is an innovative addition (reviewer 1).
4. **Strong experimental scope**: Comparisons against many (9) baselines across diverse network types (social, power, synthetic) with consistent results support the method’s effectiveness (reviewers 1,3).
5. **Interpretability contribution**: The function analysis and case study show that generated code can improve interpretability over black-box models (reviewer 3).
6. **Clarity of presentation**: The paper is easy to follow, Figures 1 and 2 clearly illustrate the workflow, and Research Questions 1–4 structure the evaluation well (reviewers 3,5).

### Weaknesses
1. **Novelty concerns**:
   - Using LLMs as mutation/reproduction operators in EAs is not new; prior work such as ELM (Lehman et al., 2023) and other LLM-based algorithm generation works (e.g., Liu et al. 2024, Romera-Paredes et al. 2024) are not adequately discussed or differentiated (reviewers 3,4,6).
   - The contribution is limited because the approach largely applies existing techniques to a new domain without structural innovation; some components (3.2.1, 3.2.3) are standard or very similar to prior work (reviewer 6).

2. **Narrow scope and generalizability**:
   - The method is only tested on one task (critical node detection). Reviewers question whether it can generalize to other network tasks such as influence maximization, immunization, or graph dismantling, where curve of largest connected component should be plotted (reviewers 3,6).
   - The method seems to tailor a specific function per dataset, raising brittleness concerns; cross-task generalization is not shown (reviewer 3).

3. **Experimental validation gaps**:
   - **Source of improvement unexplained**: The method dramatically outperforms baselines while all baselines cluster together; no detailed analysis (e.g., via ablation on the best-found function) identifies which computational step (crossover, mutation, selection, initialization) drives the gain (reviewers 2,4).
   - **Ablation study insufficient**: Only comparing against one epoch of traditional evolution (or random selection) is not convincing. A proper comparison should use multiple epochs of a standard EA (selection + mutation) to isolate the value of LLM-based operators (reviewers 3,4).
   - **Manual initialization reliance**: Ablation shows that removing manual initialization drastically reduces performance, raising the suspicion that the initialization set includes functions that already outperform baselines. Whether any initialization function is a baseline (or stronger) is not disclosed. This expertise requirement could be a bottleneck in new domains (reviewer 2).
   - **Missing runtime analysis**: The method incurs high overhead from LLM calls and multiple epochs, but no end-to-end runtime comparison is provided. GNDR achieves an average rank of 3.0 across datasets with far lower cost, making it unclear whether the complexity is warranted (reviewer 4).
   - **Stability not reported**: Both LLMs and EAs involve randomness; no statistical analysis (e.g., variance across runs) confirms whether the same result is consistently obtained (reviewer 6).
   - **Missing key experimental settings**: Crossover rate, mutation rate, and other typical EA hyperparameters are not reported (reviewer 6).

4. **Inadequate descriptions and missing details**:
   - Prompting strategy for LLM-based crossover/mutation is not fully specified (e.g., constraints, handling of invalid outputs) (reviewer 4).
   - Criteria for splitting initial functions into “topology-based” vs. “algorithm-based” categories are unclear (reviewer 4).
   - Population management implementation (especially 3.2.2 “classification” – is it just diversity-augmented fitness?) is vague; no full algorithm or pseudocode is provided (reviewers 3,4,5).
   - Motivation for using multiple populations (inner vs. outer) is not justified; discussion of existing EA research relevant to this optimization (e.g., subset selection) is missing (reviewer 5).

5. **Presentation and terminology issues**:
   - Numerous grammatical errors and awkward phrasings (e.g., “LLMs-based” → “LLM-based”, “combinational optimization” → “combinatorial optimization”, “evolutional learning” → “evolutionary learning”). Citations are incorrectly formatted (citep instead of cite) (reviewers 3,5,6).
   - Section 3.2 is difficult to follow; terminology for populations (singular/plural) is confusing (reviewer 3).
   - No pseudocode or flowchart of the overall algorithm workflow (reviewer 5).

6. **Missing comparisons and analyses**:
   - No comparison with the related LLM-guided evolution methods cited in the paper (e.g., Guo et al., Li and Wu) – the paper does not justify why its specific approach is preferable (reviewer 4).
   - No interpretability mechanism (e.g., feature importance) to understand which generated functions are effective on which network structures (reviewer 1).
   - No analysis of when the method underperforms baselines – under which network properties does it fail, and how could that be addressed? (reviewer 1).
   - Impact of prompt design on generated functions is not studied (reviewer 1).
   - Possibility that solutions for the datasets exist in LLM training data is raised but not addressed (reviewer 3).
