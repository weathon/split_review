## Merged Review

### Summary
The paper proposes a top‑k attention mechanism for KV‑cache compression that enables long‑context inference (up to 1M tokens) on a single GPU with ≈16GB RAM. It stores the full KV cache in CPU memory and transfers only the top‑k keys/values to GPU for attention computation, using a vector database and approximate k‑NN search. On benchmarks (LM‑Eval, AlpacaEval, RULER) the method achieves >95% accuracy while attending to <1% of tokens. The approach requires no model retraining or architectural changes.

### Strengths
- **Well‑motivated and timely problem** – enabling LLMs to handle long contexts under memory constraints is critical; the paper convincingly demonstrates attention sparsity across layers (Figures 1–3).
- **Drop‑in efficiency improvement** – the method works with any pretrained transformer LLM, no additional training needed; users can trade off accuracy for speed without retraining a separate model.
- **Clear presentation** – the paper is well‑written with thoughtful diagrams (figures effectively illustrate the top‑k mechanism).
- **Solid empirical evaluation** – uses standard benchmarks (AlpacaEval, Open LLM Leaderboard, RULER) covering both short and long contexts; accuracy remains high even with very small top‑k.
- **Simplicity and adaptability** – the algorithm is simple to implement within a KV‑cache‑accelerated inference framework and is adaptable across transformer‑based models.

### Weaknesses
- **Lack of novelty** – top‑k attention itself is not new (many prior papers propose it), though its application to transformer LLM inference with KV caching is a specific context (Reviewers 1, 3). Reviewer 2 stresses this more strongly.
- **Missing comparisons with other KV‑cache sparsity methods** – no comparison with H2O, “Model Tells You What to Discard”, Attention Sink, or other approximate attention algorithms. The paper claims <1% KV retention yields >95% accuracy, but those methods often suffer significant drops below 30% retention – the reason for this difference is not explained (Reviewer 2).
- **No latency/throughput measurements** – the method uses PCIe for CPU‑GPU transfer, which could add significant latency per attention layer. No system‑level benchmarks (latency, throughput, supported context length) are provided, raising concerns about practical speed (Reviewers 1, 2, 3).
- **No GPU memory consumption numbers** – there is no quantitative comparison of memory usage with and without the method across different context lengths and model sizes (Reviewer 1). Reviewer 3 also notes the absence of compute/memory savings in a table or graph.
- **Limited dataset scope** – evaluation does not include reasoning or math datasets (GSM8K, MATH), leaving the method’s impact on tasks requiring strong reasoning unclear (Reviewer 2).
- **Only accelerates decoding, not prefill** – long‑context inference on a single GPU is still infeasible for the prefill stage without more powerful machines or alternative algorithms (Reviewer 2).
- **Minor implementation issues** – Algorithm 2 has inconsistent formatting for Softmax and attention score S; the relationships between `K_cache`/`K_cache_gen` and `V_cache`/`V_cache_gen` are unclear (Reviewer 1).
- **Questions that overlap with criticisms / missing experiments** (from all reviewers):
  - How does this method compare quantitatively (accuracy, speed) with RAG? The paper notes similarity but provides no benchmarks.
  - How does it scale to larger models with more attention layers? Are the savings proportionally larger?
  - What is the maximum context length achievable for a given model under fixed GPU memory constraints?
  - Can latency be justified at scale, or does CPU‑GPU overhead dominate?
- **Disagreement in tone** – Reviewer 2 (rating 3, very low soundness/presentation/contribution) is substantially more critical, especially on missing comparisons and system performance; Reviewer 3 (rating 6) views the evaluation as solid and the problem as important. Reviewer 1 (rating 5) is intermediate, raising specific concerns.
