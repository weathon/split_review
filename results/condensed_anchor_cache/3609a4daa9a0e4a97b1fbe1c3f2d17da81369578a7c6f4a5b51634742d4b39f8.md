## Merged Review

### Summary
The paper introduces FedDTPT, a federated learning (FL) framework for discrete prompt tuning in black-box large language models (LLMs). Clients perform gradient-free, token-level discrete prompt optimization using prediction accuracy feedback via an MLM API. The server aggregates local prompt tokens using attention based on semantic similarity, followed by elbow detection and DBSCAN clustering to select representative tokens. Experiments compare with several baselines and claim higher accuracy, lower communication overhead, and robustness to non-iid data. The optimized prompts are said to be transferable.

### Strengths
- The problem setting is novel: combining FL, black-box LLMs, and discrete prompt tuning. (Reviewer 1)
- The authors target a realistic setting where clients cannot access the embedding layer or output distribution. (Reviewer 2)
- Extensive experiments are conducted, including comparisons with recent FL-LLM frameworks like OpenFedLLM and FedPrompt. (Reviewers 2, 3)
- Some preliminary experimental results are provided to demonstrate the effectiveness of the proposed algorithm. (Reviewer 4)

### Weaknesses
- **Incremental contribution**: Prompt tuning (including discrete prompts) is widely explored; the contribution is largely an adaptation of existing methods (clustering, cosine-similarity aggregation). (Reviewer 1)  
- **Limited technical novelty**: The local optimization and central clustering steps appear straightforward. The search space for optimized prompts is only 3–4 prompts (per appendix); selecting the best is obvious from human experience. The authors should provide more challenging examples and discuss technical challenges, especially under FL non-iid data. (Reviewer 3)  
- **Unclear how FL-specific benefits are demonstrated**: It is not shown how FedDTPT solves FL-specific problems better than a centralized approach. The only mechanism to handle heterogeneity appears to be a “small” public dataset, but such a dataset may not be easily obtainable—defeating the purpose of FL. Also, centralized prompt learning could use similar clustering/attention without an iterative FL framework. (Reviewer 1)  
- **Experimental results are unconvincing and lack important details**:
  - It is surprising that black-box LLM with discrete prompts outperforms white-box parameter fine-tuning by a large margin; it is unclear if the white-box baselines were sufficiently trained or how they were set up. (Reviewer 3)
  - For the manual prompt baseline, it is unclear how prompts were selected and distributed across clients. (Reviewer 3)
  - FedBiOT is listed as a baseline but no results for it appear in the tables. (Reviewers 3, 4)
  - Baseline results (e.g., on SST-2) seem significantly lower than reports in other papers, raising doubts about faithful implementation. (Reviewer 4)
  - Evaluation of “transferability” is unclear (e.g., what “D to L” or “L to D” means in Table 2). (Reviewer 3)
  - No clear demonstration of performance under varying degrees of data heterogeneity. (Reviewer 1)
- **Reliance on a representative public dataset**: The clients have access to such a dataset; it is unclear how it is constructed. This makes comparison with other methods unfair, and the improvement under non-IID may come entirely from the public dataset. Moreover, if the public dataset is truly representative, FL may not be necessary. (Reviewer 2)
- **High computational cost of aggregation**: FedDTPT uses an additional language model for server aggregation, likely incurring high computational costs. (Reviewer 2)
- **Problems in the aggregation algorithm**: 
  - It is unclear how “representative tokens from each cluster are reordered according to their original positions” – the algorithm cannot guarantee that selected tokens correspond to different positions in the respective prompts. (Reviewer 2)
  - Choosing the highest-weighted token in server optimization may bias the global prompt toward slightly overrepresented tokens, hurting performance for all clients. (Reviewer 1)
- **Incomplete and unclear description**:
  - Section 3.4 appears unfinished. DBSCAN is mentioned in the text but never appears in Algorithm 2; it is unclear how k-means and DBSCAN work sequentially. The section stops without explaining how the server generates the global prompt or shares updated information with clients. (Reviewer 4)
  - The term “MLM” is never spelled out until page 5 despite being used earlier. On page 5, it refers to both masked language models and (embedding layers of?) pre-trained language models. The input/output of the MLM API is unclear. (Reviewer 4)
  - Equation 1 has inconsistent notations (P vs. \mathcal{P}) and undefined symbols (L, w). Algorithm 1 uses “modifications” and “feedback_info” without proper introduction. It is unclear how clients use the MLM to fine-tune the local prompt. (Reviewers 2, 3)
  - The dark blue charts in Figure 1 are hard to read. (Reviewer 2)
- **Missing convergence and privacy analysis**:
  - No criteria or metrics are defined to decide retention/discard of token replacements in the gradient-free feedback loop, nor is there a clear convergence definition. (Reviewer 1)
  - Sharing token embeddings with the server may pose privacy risks—specific tokens could reveal sensitive client information. (Reviewer 1)
  - Discrete prompts are touted as interpretable, but it is unclear if the final global prompt remains interpretable after multiple aggregation rounds. (Reviewer 1)
