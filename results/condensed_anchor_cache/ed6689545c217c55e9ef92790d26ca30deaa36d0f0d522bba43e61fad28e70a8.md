## Merged Review

### Summary

The paper proposes WorkflowAgent, a text-only web agent that fine-tunes open-source LLMs (e.g., Qwen2-7B-Instruct) using LoRA on a large-scale proprietary workflow dataset (6B tokens from >250 domains). The method uses HTML preprocessing (attribute filtering based on character-to-token ratio >2, sequential chunking when exceeding context length) and is evaluated on Mind2Web, WebArena, and a proprietary benchmark. It claims SOTA direct generation on Mind2Web and a 7.3% improvement over previous text-only agents on WebArena. Ablation studies examine model type, context window size, and dataset size.

### Strengths

- Innovative approach: fine-tuning open-source LLMs (7B parameters) on production-scale workflow data outperforms much larger prompting-based agents (e.g., GPT-4) with parameter-efficient LoRA.
- Detailed dataset collection and preprocessing pipeline (Section 3.2.1–3.2.2) is clear, well-written, and can inspire future data work.
- Preliminary experiments (Section 3.2.4) systematically justify model choice, window length, and dataset size.
- Sufficient performance gains across three different benchmarks (Mind2Web, WebArena, proprietary) demonstrate generalization.
- DOM preprocessing removes non-useful attributes (those with character-to-token ratio > 2; threshold depends on tokenizer) and sequentially chunks the DOM when it exceeds context length.
- Ablation shows training dataset size has a monotonic effect on accuracy.
- Model is trained to predict the next action given DOM + action history; results on Mind2Web are promising without adapted training for that benchmark.

### Weaknesses

- **Novelty and contribution limited by closed-source nature.** The core methodology (LoRA fine-tuning on Qwen2-7B-Instruct) relies on standard techniques. The primary contribution—the large-scale workflow dataset—is proprietary and not released (nor are the trained models beyond a version trained only on public data). This makes results unreproducible and limits community impact. (Reviewer 2, 3)
- **Heavy reliance on GPT-4o for WebArena evaluation.** The reported WebArena performance intensively integrates GPT-4o to translate the environment (markup language), plan, and self-evaluate. This makes WorkflowAgent part of a multi-agent system rather than a standalone agent. If the agent requires GPT-4o for these tasks, the claimed “less inference cost” is misleading, and the system is a combination of prior techniques. (Reviewer 3)
- **Unrealistic and potentially unfair observation chunking.** The agent uses the last chunk when the DOM exceeds context length, but the required web element may be in a different chunk. This introduces chance into performance and is “unreasonable and unrealistic.” (Reviewer 3)
- **Questionable validity of Mind2Web results.** Exact match metric on a fixed environment (Mind2Web) reflects pattern memorization rather than true web interaction capability. Results on that benchmark are missing from supplementary materials. Moreover, WebArena episodes are incomplete and hard to interpret. (Reviewer 3)
- **No comparison to stronger text-only baselines.** More recent MLLM-based agents (e.g., WebVoyager text-only mode) are not compared. The paper does not justify why a text-only approach is chosen despite the inherent visual nature of web navigation. (Reviewer 2)
- **Missing baseline: non-fine-tuned performance in main results.** Table 1 does not show performance of the same models without fine-tuning on Mind2Web/WebArena; only Table 4 (proprietary) includes that. (Reviewer 1)
- **No memory component for DOM history.** The agent does not remember previous pages; this could be helpful but would require embeddings due to context length limits. (Reviewer 1)
- **Ablation study design raises concerns.** The four-stage GPT-4o multi-agent baseline (34.2%) performs worse than several LLM-based agents on the WebArena leaderboard, suggesting it may have been artificially weakened. The ablation should emphasize how WorkflowAgent’s specific contributions drive success vs. the system as a whole. (Reviewer 3)
- **Missing details on dataset collection.** The workflow documentation platform and how action descriptions were obtained (human annotators?) are not clearly described. The training dataset size is 6B tokens but number of episodes is not given. (Reviewer 3)
- **Inconsistency with scroll actions.** The paper states scroll mouse operation is excluded, yet incomplete WebArena episodes include scroll actions. (Reviewer 3)
- **Action description consistency unclear.** It is not specified whether the model is trained to generate natural language action descriptions; if not, how is consistency maintained during deployment? (Reviewer 3)
- **Accessibility tree claim questionable.** The paper states the accessibility tree cannot show element interactivity, but the WebArena environment (which uses that representation) does include such information. (Reviewer 3)
- **Questions about WebArena results on specific tasks.** Gaining 51.9% on the map task without effective combobox selection and 70.2% on Reddit with strict keyword-matching evaluator seems suspicious; possibly interaction scripts were modified. (Reviewer 3)
- **Concerns about metric suitability.** Using exact match as metric for Mind2Web rewards pattern recognition over true planning ability. End-to-end benchmarks like WebVoyager would better test generalization. (Reviewer 3)
- **Missing multimodal perspective.** Given the visual nature of web tasks, using a vision model (screenshots) would avoid preprocessing difficulties and context-length limits; the paper does not train or evaluate such a variant on multi-modal benchmarks (e.g., multi-modal Mind2Web). (Reviewer 1)
