## Merged Review

### Summary
The paper proposes Graph Edge Attention Network (GREAT), a node-free GNN architecture operating on edge features, applied to the Traveling Salesman Problem (TSP) in two settings: supervised edge classification to sparsify graphs by predicting optimal edges, and reinforcement learning for constructive TSP solving on both Euclidean and non-Euclidean (asymmetric) TSP. Reviewers acknowledge the work addresses dense graph limitations and coordinate-free TSP, but raise major concerns about limited novelty, incomplete baselines, insufficient experimental validation, overclaimed state-of-the-art, lack of scalability, and presentation issues.

### Strengths
- Addresses tasks on non-sparse dense graphs for which standard GNNs are not well-suited (R1, R4).
- Paper is clear and well-organized, with nice illustrations (Fig 3, 4) of edge-based message passing (R1).
- Little prior work on coordinate-free TSP solvers; GREAT is a node-free GNN, different from previous GNNs, potentially inspiring other fields (R3). (Note: other reviewers question whether this is truly novel given existing edge-feature transformers [R1] and baselines for asymmetric TSP [R1,R4].)
- Motivation is well-demonstrated: addresses GNN limitations like over-smoothing on dense graphs; operates on edges ideal for edge-selection tasks (R4).
- Evaluated in both supervised and RL settings, achieving good performance on asymmetric TSP distributions (R4).

### Weaknesses
**Novelty and Technical Contribution**
- The architecture is a slight variation of existing GNN+Transformer combinations; many similar works exist (R1). It is unclear what distinguishes GREAT from node-based attention mechanisms; the concatenation operation in eq. (6)-(7) may be the crucial component, not the attention itself (R2).
- Technical contribution is limited: focuses on encoding while adopting the same training pipeline as POMO (R3). The RL framework ends with a node-based layer, which undermines the node-free motivation and requires justification (R4).
- WL isomorphism testing is mentioned several times but not directly connected or used for any proof; no empirical/theoretical breakthrough demonstrated; no experiments on skeptical graphs (e.g., random regular graphs) (R2).

**Incomplete and Insufficient Experimental Evaluation**
- Missing important baselines and comparisons:
  * Edge classification: missing [1] and Joshi et al. 2019 on Euclidean TSP (R1).
  * Asymmetric TSP: missing [2] (which outperforms MatNet) and other recent methods like GLOP (R1,R3,R4). The claim “on TMAT, the only other neural solver is MatNet” is false (R4).
  * Euclidean TSP: missing DIFUSCO and numerous recent methods [1-7] (R3,R4).
  * Node-based GNN baselines (e.g., Vinyals et al., Prates et al., Jin et al., Joshi et al. 2021, Dai et al.) should be compared, especially since the paper claims to overcome GNN limitations (R2).
- Claim of state-of-the-art is not supported:
  * Table 2: “MatNet x8” clearly outperforms GREAT variants (R1).
  * Tables 3,4: GREAT NFx8 performance is between MatNet x1 and x128, showing no clear gains; should compare MatNet x8, x16, etc. (R1). GREAT does not surpass MatNet in tour length or running time (R3).
  * GREAT does not outperform or match traditional heuristics like LKH, which is the typical SOTA benchmark (R3).
- Evaluation is limited to TSP only; should test other routing problems (CVRP, OP) and classic edge-level tasks (link prediction, edge classification on benchmark graphs) to demonstrate generalizability (R1,R3,R4).
- Dataset issues:
  * Euclidean dataset used is not typical; authors should use the conventional uniform dataset (1280 instances for TSP-50/100, 128 for TSP-500, and TSPLIB) for consistent comparison; generation process needs clarification (R4).
  * Scale/magnitude of datasets not clearly described; “Gap” in percent is unconvincing without absolute solution lengths (R2).
  * In Table 3, raw MatNet lengths are not reported, making results hard to verify (R3).
- Sparsification evaluation is weak:
  * Only precision/recall for edge classification, not directly tied to TSP solution quality; should use search methods (greedy, beam search, MCTS) to convert edge predictions into tours and report optimality gaps (R1,R4).
  * No mechanism discussed for when preserved edges do not form a valid tour (R3).
  * Sparsification experiments should be on larger instances (N ≥ 500) to demonstrate practicality (R4).
  * Add F1-score to Table 1; clarify how “# edges” is calculated (total across 100 instances?) (R4).
- No generalization results for instances larger than 100 nodes; scalability not demonstrated; need experiments on >1000 nodes and computational complexity analysis (R1,R3,R4).
- Missing analysis: training time not reported (R3); should compare computational costs, training time, parameter efficiency across methods (R2,R4). What is the purpose of reporting parameter counts? (R2).
- Ablation studies needed:
  * Compare node-free GREAT vs. previous GNNs/GATs using random, handcrafted, or trainable node embeddings, controlling for parameters and compute (R4).
  * Explain when and why node-free vs. node-based models outperform each other (lines 437, 465) and when more/less parameters perform better (line 451) (R4).
- Gurobi configurations unclear; would like to see Gurobi performance with strict time limits (e.g., 0.01s, 1s) to contextualize speed (R2).

**Presentation and Writing**
- Irrelevant content (WL isomorphism testing) (R2).
- Notations not clearly defined: “NB” and “NF” in tables (guessed as node-based and node-free); “k” and “M” in tables not defined (R2).
- Unnecessary abbreviation “FF” (feedforward) used before definition (R2).
- Diagrams have poor formatting (subscripts for edge notations exposed as “_”) (R2). Arrows in Fig. 3 and 4 may be reversed (R4).
- Results analysis is unclear and hard to follow; important points buried (R3). Code not provided for verification (R3).
