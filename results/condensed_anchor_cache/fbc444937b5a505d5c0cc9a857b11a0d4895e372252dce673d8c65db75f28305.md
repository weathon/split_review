## Merged Review

### Summary
DOTS enables LLMs to reason dynamically by searching for the optimal reasoning action trajectory (analysis, solution, verification modules) per question. It first defines atomic reasoning actions, then searches for the best trajectory for each training question via iterative exploration and evaluation, and finally fine-tunes either an external planner LLM or internalizes the planning into the solver LLM itself. Experiments across eight reasoning tasks (in‑distribution, near‑distribution, out‑of‑distribution, zero‑shot, few‑shot) show that DOTS outperforms static prompting methods and vanilla instruction tuning.

### Strengths
- **Dynamic reasoning:** Adapts the reasoning strategy to the specific question and the capability of the task‑solving LLM (all reviewers).
- **Comprehensive evaluation:** Extensive experiments covering in‑distribution, near‑distribution, out‑of‑distribution, few‑shot, and zero‑shot settings on multiple benchmarks (R1, R3). Works on both open‑source and closed‑source models (R1).
- **Two learning paradigms:** Supports both an external lightweight planner and an internalized capability in the solver LLM, increasing adaptability (R2, R3).
- **Unifies diverse reasoning methods:** Combines CoT, PoT, self‑verification, and other actions into a single framework, and can incorporate future methods (R3).
- **Performance gains:** Consistently improves over static baselines and self‑refinement (most scenarios), with lower inference cost than non‑CoT methods (R2).
- **Ablation and analysis:** Includes ablation studies verifying the importance of each module (Table 6), analysis of action preferences across tasks, and efficiency comparisons showing comparable cost to advanced prompting (R3).
- **Clear presentation:** Easy to read, with straightforward ideas and helpful illustrations (R4). Simplifies the construction of planning prompts (R4).

### Weaknesses
- **OOD performance and generalization:** Improvement on out‑of‑distribution tasks is marginal and not significant (R1, R4). The margin over baselines shrinks on OOD data, raising concerns about generalization (R3). Since training sets may not be available for new domains, this limits practical applicability (R3). On some OOD datasets, a single static baseline beats DOTS, suggesting dynamic selection is not always beneficial (R3). While Reviewer 1 (rating 8) found the method promising overall, others (R2 rating 5, R3 and R4 rating 6) highlighted this as a key limitation.
- **Fairness of comparison:** Baselines use only 1–2 reasoning layers; DOTS uses 3 layers (analysis, solution, verification). A fairer baseline would enforce three layers (e.g., Decomposition + POT + self‑verification) (R4). Additionally, the vanilla SFT baseline only uses CoT training data; comparisons with program‑of‑thought (PoT) data or mixed CoT+PoT training are missing, making it hard to attribute gains solely to dynamic reasoning (R1). Reviewer 4 also asks that 3‑layer baselines be added (Questions 3).
- **Computational cost and complexity:** The search phase involves iterative exploration and evaluation, which is computationally expensive (R1). The overall method is complex, and the paper lacks ablations that justify each component’s necessity (R2). The efficiency of the external DOTS planner is not reported (R3, Question). The method requires re‑SFT for each new base LLM, new atomic action, or new layer, limiting generalization (R4).
- **Missing ablations and insufficient analysis:** Ablation studies are only performed on the in‑distribution (IND) benchmark, not on OOD datasets, which would be more important (R4). The search strategy is compared only to random path selection; it should be compared to heuristics like combining non‑empty actions from each layer (R1). The ablation in Table 6 does not isolate whether improvement comes from the explanation (prior knowledge) rather than from dynamic selection (R4, R3). For example, removing the explanation hurts performance, suggesting the gain may be due to added context (R4).
- **Methodology gaps:** The paper does not explore decomposition or tool use for more complex tasks (R2). The collection method for atomic reasoning trajectories is not clearly described (R2). It does not attempt multiple candidate trajectories and then choose the best, which would better align with “trajectory search” (R3). The technique also requires separate fine‑tuning for each model/action set, reducing plug‑and‑play usability (R4).
- **Unanswered reviewer questions that imply weaknesses:**  
  - How many trajectories are needed to achieve substantial improvement at fine‑tuning time? (R2)  
  - How does the approach scale to more complex problems where process rewards are beneficial? (R2)  
  - Would combining PoT with code models improve the PoT baseline? (R1)  
  - For the few‑shot settings, is the planner trained on MATH? If so, those settings are near‑distribution, not true zero‑shot (R3).  
  - Why is ablation shown only on IND and not on OOD, where the margin is smaller? (R4)  
  - In an internalized setting, would training only on reasoning process+answer (without planning) allow the model to choose actions automatically (cf. FireAct)? (R4)  
  - The distribution of selected paths across the 12 combinations of 3 layers is missing for multiple benchmarks (R4).  
  - Equation 2 uses an undefined variable T (R3).
