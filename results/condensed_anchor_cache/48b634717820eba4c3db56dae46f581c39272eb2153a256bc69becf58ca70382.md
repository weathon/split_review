## Merged Review

### Summary

The paper identifies and corrects a fundamental information leakage bug in existing online time series forecasting (OTSF) research: models predict and then evaluate on historical time steps that have already been used for backpropagated parameter updates, leading to an overly optimistic training loss and a gap between training and causal evaluation. The authors redefine OTSF to focus solely on predicting unknown future steps and evaluate performance only on those predictions. To address the challenges of this new setting—leveraging incomplete ground-truth–prediction pairs for backpropagation and avoiding overfitting to noise in recent data—they propose a dual-stream framework (DSOF). DSOF combines a slow stream (updates with complete data via experience replay, ER) and a fast stream (adapts to recent data via temporal difference learning, TD) within a teacher-student model learned through residual learning (coarse-to-fine). Extensive experiments across multiple datasets (ECL, ETT, Traffic, Weather, Exchange), models (DLinear, FITS, FSNet, OneNet, iTransformer, PatchTST, NSTransformer), and settings demonstrate improvements in forecasting performance under changing environments.

### Strengths

- Importance of the information leakage problem: It is a fundamental bug, verified by checking code of previous OTSF works (R1, R4). The redefinition of OTSF will make the field clearer and more practical (R1, R3, R4).
- The proposed DSOF framework is a logical and innovative solution to the emerging problem in the leakage-free setting; it will serve as a baseline for future comparisons (R3, R4). It provides insights from reinforcement learning (RL), specifically temporal difference learning (R4).
- Thorough experimentation across multiple datasets (ECL, ETT, Traffic, Weather, Exchange) and a variety of model architectures (DLinear, FITS, FSNet, OneNet, iTransformer, PatchTST, NSTransformer) with different settings (forecasting horizons, learning rates) clearly demonstrates the effectiveness of DSOF (R1, R3, R4).
- Ablation studies highlight the importance of core components (ER and TD loss), providing a detailed understanding of design choices (R3).
- The paper addresses an important topic in time series forecasting via online model adjusting to hedge distribution drifting (R2).

### Weaknesses

- Presentation and novelty concerns: The presentation is poor—long sentences, vague indices (e.g., line 45 “the whole sequence” not defined), Figure 1 not clarifying the information leakage problem, and appendices missing from the submitted PDF (R1, R2). The novelty appears limited; teacher-student and experience replay are standard. Toy examples or theoretical analysis are needed to motivate the method from a principled way (R2). The new OTSF framework is not rigorously formalized (e.g., what data can/cannot be used at each time to prevent leakage) (R1). The connection to RL and TD learning is very loose; it would be better not to use TD terminology (R1).
- Fast learning stream contradiction: The teacher model is outdated, yet the fast stream updates the student using labels generated by the teacher. This seems contradictory for staying up-to-date; only the immediate next label \(x_{t+1}\) is used, which is very small updates. Alternatives like using \(k>1\) next real data (at cost of delay) or a hierarchy of models with different \(k\) (e.g., powers of 2) are not considered (R1).
- Computational cost: DSOF involves two networks, and the teacher model generates a long sequence at each time step, which can be very costly for architectures like decoder transformers. It is unclear if the reported outperformance holds under the same computational budget as baselines (R1). There is no thorough analysis of latency, memory usage, and training time compared to baseline batch learning and other online frameworks for real-time environments (R1, R3).
- Baseline results raise concerns: OneNet (theoretically more robust) performs worse than FSNet on datasets like ECL (many variables), which is unexpected. Hyperparameters settings for baselines need clarification and sensitivity analysis to rule out misconfiguration (R3). The combined use of ER and TD in Figure 3 gives a large boost, but individual contributions seem minimal. This pattern is confusing; a detailed analysis of how they complement each other, along with additional ablation studies or visualizations, is needed (R3).
- Practical relevance of the new setting: Many real-world applications update the model immediately with each new data point, not accumulating a sequence. Avoiding information leakage may conflict with this common practice. The paper should justify why avoiding overlap offers a practical advantage and show use cases where the benefit is clear (R3).
- Fixed look-back length of 96: Not entirely convincing. Different datasets have different temporal dependencies; a grid search for optimal lookback length per dataset per model (following practice in FITS, PatchTST) would be more rigorous. While this is computationally heavy, a subset (e.g., DLinear, iTransformer on ETTh1, Exchange; \(H=24\)) could be tested (R4). The experiments on buffer size in the appendix do not fully replace look-back experiments (R4 response to question).
- Missing code: Sample code not provided to assist reproducibility (R2).
- How DSOF addresses information leakage is not well discussed in the methodology section (Section 3) (R2).
- Questions that overlap with criticisms/missing experiments: Can the predictions of base models (including foundation models for time series forecasting) be improved by DSOF? (R4). Can experiments on different buffer sizes partially represent look-back horizon experiments? (R4, but answer likely no).
