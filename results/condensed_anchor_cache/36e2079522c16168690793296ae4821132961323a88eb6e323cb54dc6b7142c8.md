## Merged Review

### Summary
The paper proposes a token alignment method for handling incomplete subword tokens in prompts during text/code completion with generative models. The algorithm backtracks to a previous complete token (B tokens) and decodes subsequent tokens while constraining generation to starts-of-tokens that match the partial prompt, using a trie lookup. The method is tested on code generation and natural language benchmarks, showing improvements across several partial token scenarios (e.g., subword splits, space prefixes, indentation). Reviewers generally acknowledge the problem as relevant and the method as simple and practical, but they raise concerns about demonstrated evidence, positioning in the literature, and the need for certain clarifications and additional comparisons. Scores varied: one reviewer was very critical (3), one was positive (6), and two were moderate (5).

### Strengths
- Interesting approach to improve efficiency in code generation (Reviewer 1).
- Tackles an important and neglected issue with tokenisation in LLMs; partial tokens are relevant for autocompletion like code generation (Reviewer 3).
- Method is simple, intuitive, easy to implement for existing LLMs, and achieves large gains on some datasets (Reviewer 3).
- Useful categorization of common partial token scenarios (natural language subwords, space prefixes, contiguous spaces in code), which itself is a contribution (Reviewer 3).
- Clear description of the proposed algorithm (Reviewers 2, 3).
- Comparison performed on both code and NLP benchmarks (Reviewer 2).
- Minimal latency overhead (median 3–7 ms increase) (Reviewer 2, also noted as a strength by Reviewer 2; Reviewer 3 acknowledges limited increased latency but requests more detail).
- Method can be combined with other techniques such as subword regularization (Reviewer 4).
- Meaningful for code completion and text output applications (Reviewer 4).

### Weaknesses
- **Problem evidence.** One reviewer (score 3, minority) states there is no empirical evidence or support that the problem of subword misalignment actually exists and causes failures; no experiments demonstrating the problem itself. This reviewer questions novelty and asks for explicit proof (Reviewer 1).
- **Literature positioning.** Several reviewers note insufficient connection to related work: decoding literature in LMs and sequence models, beam search variants that could handle hierarchical subword/word generation (Reviewer 1, Reviewer 2, Reviewer 3). Reviewer 3 asks how the work differs from a known backtracking algorithm (ACL 2019 D19-1507). Reviewer 2 requests adding related-work/literature context to introduction and methodology.
- **Missing comparisons / baselines.** Reviewer 2 questions whether the selected baseline is strong compared to other related work like fine/instruction tuning or character-based models. Reviewer 4 asks for detailed comparison between token alignment and “token healing” across datasets and scenarios. Reviewer 4 also asks about multilingual/cross-lingual performance and scenarios where other methods might be more appropriate.
- **Uncertainty about backtracking steps (B).** The paper is unclear why backtracking multiple tokens (B=3) works better than backtracking one token, given that one token back seems sufficient. The ablation study shows B=3 is optimal but the reason is not explained (Reviewer 3).
- **Latency details insufficient.** Although latency is reported as 3–7 ms on average, the paper should include hardware details and a practically informative breakdown of added latency (ms and percentage). Increased latency is a real-world concern (Reviewer 3, also noted by Reviewer 4 as a weakness).
- **Framing of the problem.** Reviewer 3: The claim that subword partial tokens (e.g., “banana” split into “ban” + “ana”) cause issues should be cited or proven experimentally. Models often handle such tokenisations well; more examples of where token alignment helps (e.g., completing “bana” to “bananas” given context) would strengthen the paper.
- **Prefix-indentation case.** Reviewer 4 notes that for prefix-indentation splitting, the proposed method still lags behind the baseline.
- **Prompt sensitivity.** Reviewer 4 raises concerns about LLM output instability due to prompt changes; asks whether the specific impact of prompts was considered.
- **In-context learning.** Reviewer 4 suggests exploring whether adding relevant knowledge to prompts could further enhance the method. Reviewer 2 also asks whether alignment is based on fine-tuning or in-context learning, and wants elaboration on differences and benefits.
- **Code data dilution.** Reviewer 4 asks whether excessive code data in the dataset might dilute pre-trained knowledge and impair code generation capabilities.
- **Long texts.** Reviewer 4 questions whether token alignment maintains effectiveness for texts exceeding the model’s maximum input length.
- **Statistical significance.** Reviewer 2 suggests adding a statistical significance test for results.
- **Hyperparameters.** Reviewer 2 requests elaboration on the selection and importance of hyperparameters (e.g., backtracking B).
- **Subword regularization latency.** Reviewer 3: The paper claims subword regularization increases inference latency but does not explain how.
- **Tokenizer of examples.** Reviewer 3: It is unclear which model’s tokeniser was used for examples in Figures 1–3; if hand-constructed, this should be stated.
- **Typos.** Reviewer 3 lists multiple typos: Tables 1–3 have incorrectly boldfaced results (lower than comparable results); “incomplete token ‘sys’ in Figure 2” should be “‘re’ in Figure 2”; unclear wording about latency; notation inconsistency (N vs B); trie lookup phrasing; grammar errors in Section 4, page 4, Section 5; and unclear wording in Section 6.2. These affect presentation quality (noted by Reviewer 1 as 2/5 for presentation).
