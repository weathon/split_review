## Merged Review

### Summary
The paper introduces a pixel-based framework combining entity-centric decision transformers with symbolic planning for long-horizon compositional tasks. It first discovers and learns basic skills from random rollouts in simplified environments, then uses genetic algorithms to give these skills symbolic interpretations (preconditions and effects). During evaluation, MCTS searches over skill sequences. An object-centric representation is extracted from images. Experiments on a 2D grid-world Minecraft domain and IsaacGym tabletop manipulation show the method outperforms baselines, especially on longer-horizon tasks.

### Strengths
- Tackles a hard and relevant problem: long-horizon compositional tasks from pixel observations requiring reasoning about multiple entities and skill composition.
- The method learns useful skills from random rollout data alone, without human intervention, by clustering rollouts based on changes in the feature representation.
- Provides a concrete approach to train policy, precondition, and effect functions for each skill, enabling MCTS planning over skills.
- The idea of mapping object-centric representations to a discrete set of “features” for planning is interesting; in the future, VLMs might automate feature discovery.
- Using symbolic regression (PySR/EQL) to learn precondition and effect sets is a promising alternative to hand-coded transition models.
- Focuses on both skill learning and state abstraction simultaneously, which is a nice positioning of the overall problem.
- The method is tested on relevant and challenging simulated environments (Minecraft crafting, multi-object manipulation) and shows strong performance, significantly outperforming baselines when task complexity increases.
- Some exemplary skill structures are shown in the appendix; including them in the main manuscript would be beneficial.

### Weaknesses
- **Missing fundamental related work**: The paper omits the highly related “From Skills to Symbols” (Konidaris et al., JAIR 2018, IJCAI-JAIR 2020 best paper) and its object-oriented counterpart for Minecraft (James et al., ICLR 2022). Other bottom-up symbolic abstraction works (e.g., Ugur & Piater 2015, Ahmetoglu et al. 2022, Asai et al. 2022, Chitnis et al. 2022, Shah et al. 2024) are not cited. Automatic skill discovery works (e.g., Bagaria & Konidaris 2019, Bagaria et al. 2021) and the semi-MDP option framework (Sutton et al. 1999) are missing. The related work claiming “many existing methods employ a top-down structure” lacks a balanced discussion of bottom-up approaches.
- **Hand-designed symbolic features**: The feature state used for planning is hand-designed per environment, requiring expert knowledge and access to simulator ground-truth state. This is a significant assumption that undercuts claims of automatic skill discovery and end-to-end pixel-based planning. The paper should explicitly state this in the main text.
- **Missing ablation studies**: The method has many components (OCR, symbolic regression, EQL networks, skill clustering, dependency graph, MCTS, image segmentation). No ablation study is provided to understand which parts are essential. Important controlled experiments would include: swapping OCR with a standard image feature extractor, replacing PySR with a traditional regression network, replacing the precondition EQL network with a simple binary classifier, using images directly instead of a segmentation model, removing the dependency graph, or varying the number of skills / time horizon limits.
- **Unfair or unclear baseline comparisons**: The proposed method uses random rollouts in a simplified environment, whereas baselines may not have access to the same data or assumptions. It is unclear whether comparisons are apples-to-apples (e.g., do RL baselines use the same random data? Is GAIL given the same simplified environment?). The choice of baselines is not motivated; there is no discussion of what SOTA is on these environments or what each baseline contributes to answering the experimental questions. The baselines for the Minecraft task (SMORL, ECRL) are model-based but cited as model-free; their reward design is not specified. GAIL’s imitation data source is unspecified. Methods like Deepsynth and DiRL are claimed to have “simple decompositional logic relying on expert knowledge,” but no failure analysis is given.
- **Unclear notation and missing details**: Multiple definitions are imprecise or inconsistent (e.g., $\mathcal{P}_m$ in Def. 2 undefined; Def. 5 includes $l$ as a tuple of $s$ and ground operator components redundantly; Eq. (1) uses $\hat{f}$ apparently as ground-truth features but source is not clearly stated – Appendix C suggests hand-design from simulator state). The termination condition $\beta$ in Def. 4 is later replaced by a fixed time horizon without explanation. “Subgoal state $g^i$” is introduced in Sec. 5.4 without explaining how subgoals are generated.
- **Trace generation and clustering ambiguity**: Random rollout segmentation is described vaguely (e.g., “a significant number of rollouts,” trace lengths unspecified). It is not clear how traces are represented (concatenation of per-step features?) or how L2 distance between variable-length traces is measured. The motivation for segmentation and the choice of number of clusters $K$ is not explained.
- **Skill policy concerns**: The skill policy is learned via behavioral cloning from a random policy, which may produce inefficient skills. The loss function for GCBC (Eq. (2)?) includes a term that appears unrelated to policy parameters; the subscript $t$ may be $T$ as a typo. The skill policy is not goal-conditioned, yet tasks can be multi-goal. No mechanism for online refinement of skills from on-policy data is provided.
- **Dependency graph is redundant**: It is unclear why a dependency graph is explicitly constructed when the symbolic precondition/effect definitions already afford tree search; the need for the graph is not motivated.
- **Object-centric representation vs. feature aggregation**: The paper first extracts object-centric representations (OCR) but then aggregates them into a fixed-size feature vector for planning, negating the benefit of object factorization. It is not justified why this aggregation is needed instead of directly mapping from pixels to features. The cross-attention in the aggregation Transformer uses “temporal difference” without explanation.
- **Image segmentation not explained**: Sec. 5.4 mentions using an image segmentation algorithm for segmenting semantics, but this is not described, not visualized, and not connected to the rest of the pipeline. It is unclear how a skill learned in a simple environment (e.g., single cube) is applied to images with multiple cubes.
- **Compositional generalization claims lack evidence**: Generalization results in changed environments are trivial (object appearance changes only). No definition of compositional generalization is given; zero-shot composition of unseen subtasks is not demonstrated. The paper claims “superiority due to awareness of temporal attributes,” but RL baselines could also be given ordering information via reward shaping, making comparison questionable.
- **Missing experimental rigor**: No error bars or number of seeds are reported in Tables 1 and 2. No visualizations of policy rollouts or failure cases are provided. No code is released; many hyper-parameters are missing, hindering reproducibility.
- **Minor presentation issues**: “Urges” (requires), “inherent order” (specified), “contrarily” (in contrast), “Isaacgym” (IsaacGym), missing reference for k-means (original work, not survey). The term “real-world object manipulation” is misleading; IsaacGym is a simulator. Some awkward phrasing throughout.
