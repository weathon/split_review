## Summary
TOKENCOUNT proposes a training-free object counting framework that leverages SAM's internal output tokens for verification, combined with a probabilistic prompt generation stage that iteratively explores the image. The method achieves strong results on FSC-147 (MAE 16.25, outperforming the closest SAM-only baseline TFOC at 19.95) and CARPK (MAE 4.68). The core idea of repurposing SAM's decoder output tokens as a discriminative verification space is novel and well-motivated.

## Strengths
- **Novel use of SAM output tokens for verification**: The idea of directly using SAM's internal decoder tokens as a verification space — rather than operating on image encoder embeddings — is genuinely original and well-motivated. Figure 5's PCA visualization convincingly shows that positive and negative prompts form clearly separable clusters in the output token space but overlap in the image embedding space.
- **Iterative probability-guided exploration is a reasonable design**: The framework of iteratively sampling prompts from a probability distribution that is updated based on verification outcomes is sensible and addresses a real problem (how to cover an image efficiently without exhaustive prompting).
- **Strong FSC-147 results over comparable SAM-only baselines**: On FSC-147, the method achieves MAE 16.25 vs. 19.95 for TFOC and 42.48 for vanilla SAM, demonstrating a clear improvement in the training-free, SAM-only regime.
- **The paper is well-structured and readable**: The method is presented in a logical flow from probabilistic prompt generation to output token verification, with helpful figures (Figures 1-3, 5).
- **Reasonable ablation coverage of the verification stage**: Tables 3 and 5 ablate the verification metric choice and compare output token vs. image embedding spaces, providing evidence for the design decisions.

## Weaknesses

### Major
- **TS-SS ambiguity makes the verification pipeline unreproducible**: Equation (2) defines TS-SS = TS × SS = (|a||b|sin(θ)/2) × (π(ED+MD)²×θ/360°). For identical vectors (θ=0), TS-SS=0, making it a dissimilarity measure where smaller values indicate greater similarity. Yet the paper consistently calls it a "similarity" metric, speaks of "high similarity to exemplars," and sets a threshold of 300 without specifying whether values *below* or *above* 300 indicate a positive match. This is the core decision rule of the entire verification stage. Without this specification, readers cannot reproduce the method or interpret any of the verification results. The direction can be inferred (likely below 300 = positive), but the paper must state it explicitly.

- **Iterative verification mechanism is underspecified**: Two critical algorithmic details are not formalized. (1) When a candidate output token is compared against a growing exemplar set, the paper states only that verified output tokens "are added to the exemplar list to use as new verification criteria" — but the comparison rule (minimum distance? mean embedding? voting? one-vs-all threshold?) is never specified. (2) The probability distribution update for negative verifications is described only qualitatively as "the value … is decreased" with no formula or decay rate. Figure 3 shows an example but no general rule. These gaps prevent independent reimplementation.

- **No baseline for the probabilistic prompt generation claim**: The paper claims probabilistic prompt generation "reduces redundant background sampling" and achieves "intelligent exploration." However, Table 4 only varies iteration count and prompts per iteration — it never compares the probabilistic strategy against a uniform grid or random baseline using the same total prompt budget. The observed improvement with more prompts could be due solely to using more prompts, not to the probabilistic placement. The claim of adaptive, intelligent exploration is therefore unsupported by the experiments provided.

- **Runtime comparison is unsubstantiated**: The paper claims the method is "more than twice as fast" as TFCAC (Section 4.2) and reports 1.69s/image on an A100, but provides no runtime measurements for TFCAC or any other baseline. This efficiency claim, which is presented as a key advantage, has no evidence behind it.

- **CARPK evaluation protocol is unclear and may disadvantage baselines**: The paper uses 12 exemplars for CARPK ("following the testing procedure" without citing the protocol), which is unusually high for few-shot counting on this benchmark. Standard few-shot counting protocols on CARPK typically use 3 exemplars. The paper does not confirm whether the baselines in Table 1 were evaluated under the same exemplar count, making the CARPK comparison potentially unfair. The same ambiguity extends to FSC-147 — the paper never states the exemplar count used for the few-shot setting in Table 1.

### Minor
- **Motivational framing overclaims**: The paper claims to "bypass the uncertainty of similarity" but both stages operate on computed similarities: the prompt generator uses cosine similarity on image embeddings, and the verification stage uses TS-SS on output tokens. The contribution is more accurately described as shifting similarity computation to a more discriminative representation space, not bypassing similarity altogether. This mismatch weakens the narrative.

- **Table 5 confound**: The comparison between output token space (MAE 16.25) and image embedding space (MAE 16.94) is confounded: the paper does not state what verification metric was used in the image embedding space (likely cosine similarity, per the probabilistic prompt generation stage), so the benefit of the output token space per se vs. the benefit of switching to TS-SS cannot be separated.

- **FSC-147 exemplar count not stated**: The paper never specifies how many exemplars were used for the few-shot FSC-147 experiments in Table 1, though the one-shot setting (Table 2) is clear. This is a basic reporting omission.

- **TS-SS gain over cosine similarity is marginal**: Table 3 shows TS-SS (MAE 16.25) improving over cosine similarity (MAE 16.48) by only 0.23 MAE. While the paper frames this as evidence that hybrid metrics are needed, the practical difference is small, and the ablation lacks error bars to assess whether this difference is significant.

### Trivial
- The paper states "we could overlapping masks more precisely" (Section 4.1) — likely a typo for "we could handle/process overlapping masks more precisely."
- Table 3 is referenced as "the performance hierarchy in 3" instead of "Table 3" in Section 4.4.

## Nice-to-Haves
- A uniform-grid or random-sampling baseline with matched prompt budget to isolate the benefit of probabilistic placement.
- Runtime measurements for at least TFOC or TFCAC to substantiate the "twice as fast" claim.
- Hyperparameter sensitivity analysis for the temperature τ and NMS IoU threshold.
- Qualitative failure cases illustrating where the method degrades (dense small instances, as mentioned in the Discussion).
- Explicit statement of the FSC-147 few-shot exemplar count.

## Novel Insights
The paper makes a genuinely insightful observation: SAM's output tokens, which are produced as a byproduct of mask decoding, encode a joint semantic-positional representation that is more discriminative for instance verification than the image encoder's embeddings. The PCA visualization (Figure 5) provides compelling qualitative evidence that this token space naturally separates positive from negative instances. This observation — that internal decoder tokens can serve as a "free" verification signal — could be useful beyond counting, for any task requiring instance-level discrimination from SAM.

## Suggestions
- Resolve the TS-SS ambiguity immediately: explicitly state that TS-SS is a dissimilarity (0 = identical), and that candidates with TS-SS < 300 are considered positive matches. Provide geometric intuition for why this particular composite measure captures the dual semantic/positional nature of output tokens better than cosine or L2.
- Formalize the verification update rule: specify the comparison mechanism for the growing exemplar set (e.g., "a candidate is positive if its TS-SS distance to any exemplar in the set is below 300") and give an explicit formula or algorithm for the probability decrease on negative regions (e.g., multiply by a decay factor α).
- Add a uniform/random prompt baseline to Table 4: for a fixed total prompt budget, compare the probabilistic strategy against uniform grid placement. This is the minimum experiment needed to support the "intelligent exploration" claim.
- Measure and report TFCAC runtime (or at minimum TFOC runtime) on the same hardware to support the efficiency claim, or remove the claim.
- State the FSC-147 exemplar count explicitly and clarify what CARPK "testing procedure" was followed.
