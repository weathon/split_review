## Summary

This paper introduces Multi-Method Self-Training (MMST), a technique where a language model is fine-tuned on pseudo-labels generated by one problem-solving method (e.g., chain-of-thought text) and those pseudo-labels are translated to train a different method (e.g., code), and vice versa. Using BLOOM-176B on math word problems (SVAMP, GSM8K, MAWPS, MathQA), the authors show that MMST substantially improves both the weaker method (text, up to ~30 percentage points) and the stronger method (code, up to ~32.2 percentage points), and also yields gains on out-of-domain reasoning tasks (StrategyQA, CommonSenseQA). Ablation studies isolate that the gains stem from multi-method diversity, not merely more data.

## Strengths

- **Novel and well-motivated training paradigm.** The idea of using one prompt-engineering method's outputs to train another method within the same model is original and cleanly distinguished from prior co-training (different data views) and single-method self-training. The paper explicitly notes: "With LLMs, instead of using different sets of data about the same examples, we can use different methods available to the language model for solving the same problem."

- **Large improvements on both the weaker and stronger methods.** On SVAMP, text accuracy rises from 28.6% (BLOOM baseline) to 52.2% (MMST), and code accuracy from 53.4% to 85.6% (Table 1, Table 2). The fact that outputs from a less performant method (text) can improve a more performant method (code) is a surprising and noteworthy result.

- **Ablation isolating multi-method diversity from data quantity.** Table 3 (limited-data ablation) shows that when the total training data is constrained to the size of single-method self-training, MMST-limited still outperforms single-method ST (e.g., SVAMP text: 45.3% vs. 40.1%). This cleanly demonstrates that the gains are not solely due to more data.

- **Out-of-domain transfer is demonstrated.** MMST improves text performance on StrategyQA (61.3% → 68.2%) and CommonSenseQA (49.3% → 59.6%) after training only on math problems (Table 5), suggesting improved general reasoning capability.

- **Anti-correlation analysis provides a plausible mechanistic explanation.** Computing correlations between text and code correctness on each dataset (Table 4) shows that datasets with more negative correlation among positive pseudo-labels tend to see larger MMST improvements, offering initial evidence for why the method works.

## Weaknesses

### Fatal
None.

### Major

- **The central translation step is critically underspecified.** The paper repeatedly states that pseudo-labels are "translated" between methods (e.g., "text examples are turned into code, code examples are turned into text"), but provides no description of *how* this translation is done. No prompt template, no details on whether generation is deterministic or sampled, no handling of ambiguous cases. This is the core methodological step of MMST; without specifying it, the method cannot be reproduced and the reported gains cannot be disentangled from properties of the translation process itself. The paper's own Limitations section (line 279) acknowledges that "LLMs can easily convert text to code and vice versa" as if it's trivial, but the actual mechanism is never documented.

- **Missing critical experimental parameters (k and data quantities).** The parameter *k* (number of candidate solutions generated per example per method) is introduced in Section 4.2 but never given a value. The number of pseudo-labels generated per dataset is also never reported, making it impossible to assess data quantity or properly interpret the limited-data ablation.

- **No variance or confidence intervals on any result.** None of the accuracy numbers in Tables 1–5 are accompanied by error bars, standard deviations, or significance tests. While single-run evaluation is common practice for very large models (176B), the problem is that several claimed improvements are small enough to be within run-to-run variation: MathQA code improves only from 14.5% to 14.8%, and MathQA text from 5.9% to 7.1%. Without measures of variance, these specific claims are unsubstantiated. The larger improvements (SVAMP, GSM8K) are likely real, but the paper does not distinguish the robust from the fragile.

### Minor

- **Human evaluation lacks key reporting details.** The human evaluation (Section 5.1) states that "professional computer scientists who volunteered" served as annotators, but does not report how many annotators participated, how many problems were evaluated, or any measure of inter-annotator agreement. This weakens the claim that MMST improves explanation quality beyond correctness.

- **OOD rationale-generation claim is stronger than the evidence supports.** The abstract states that MMST improves OOD tasks "by improving the ability of the model to generate rationales," but the only direct evidence about rationale quality is the human evaluation, which was conducted on math problems, not on OOD tasks. The results section (line 239) more cautiously frames this as a hypothesis ("We hypothesize that this is caused by improvements of abilities..."). The abstract overstates what is actually demonstrated.

- **Correlation analysis has a complicating outlier that is not deeply explored.** MathQA has the strongest negative correlation among positive pseudo-labels (-0.731) but the smallest improvement from MMST. The paper mentions this in passing but does not analyze why. This weakens the strength of the anti-correlation story as a general explanation.

- **Text solution generation is not described.** Section 4.3 provides detailed procedures for code generation (the `exec` function, the `solution` function, error handling) but gives no equivalent description of how chain-of-thought text solutions are generated or templated.

### Trivial
None.

This directly addresses the concern.

## Novel Insights

The reviewer critiques collectively highlight a productive tension: the paper's core idea is genuinely novel and the results on most datasets are compellingly large, yet the methodological description has a black-box quality at its most critical step (translation between methods). The anti-correlation analysis is the most interesting lens for future work — the fact that MathQA (which has the strongest negative correlation) shows the smallest improvement suggests that anti-correlation is a *necessary but not sufficient* condition for MMST gains, and that other factors (baseline performance, data quantity, task difficulty ceiling) interact in ways the current analysis cannot disentangle. This observation could motivate a more systematic study of when cross-method training is most beneficial.

## Suggestions

1. **Specify the translation prompt and procedure in full.** Provide the exact prompt template used to convert text solutions to code and vice versa, including whether generation is sampled or greedy, and how the model handles cases where translation is ambiguous.
2. **Report the value of k** and the number of pseudo-labels per dataset used for MMST versus single-method self-training.
3. **Add error bars** for at least the MathQA results, where improvements are small. Recognizing the cost of running 176B models multiple times, even 2–3 seeds on the smallest dataset would substantially increase confidence.
4. **Reconcile the abstract's claim about OOD rationale improvement** with the results section's more cautious language. Either provide direct evidence (e.g., rationale quality analysis on OOD outputs) or soften the abstract.
5. **Report the number of human annotators, problems judged, and inter-annotator agreement** for the human evaluation.
