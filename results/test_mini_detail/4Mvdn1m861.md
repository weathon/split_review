## Summary
The paper proposes TokenCount, a training-free framework for object counting using SAM alone. Two components work together: (1) probabilistic prompt generation that adaptively places prompts based on a probability distribution derived from SAM's image embedding, and (2) output token-based verification that uses SAM's decoder output tokens (with a TS-SS hybrid metric) to distinguish positive from negative instances. On FSC-147 the method achieves MAE 16.25 (best among SAM-only training-free methods), and on CARPK it achieves MAE 4.68 (outperforming all supervised methods listed).

## Strengths
- **Output token verification is a genuinely novel and well-motivated use of SAM internals.** The paper identifies that prior similarity-based methods operate in the image embedding space, where semantic and positional information are entangled in a way that standard metrics handle poorly. The idea of using SAM's own output tokens — which already aggregate semantic and positional information through the decoder's attention mechanisms — as the verification signal is a creative contribution. The ablation in Table 3 (TS-SS 16.25 vs. cosine 16.48, L2 16.53, dot product 19.58) and Table 5 (output token space 16.25 vs. image embedding space 16.94) provides direct evidence that this design choice matters.
- **Best reported accuracy among training-free SAM-only methods.** On FSC-147, the method beats TFOC (19.95), Count-Anything (27.97), and vanilla SAM (42.48) by a clear margin. On CARPK, it achieves 4.68 MAE, surpassing all listed supervised methods including BMNet+ (5.76) and SAFECOUNT (5.33). This is achieved with no training, no additional models, and no extra encoders — only SAM.
- **TS-SS selection is principled.** Section 3.2 gives a clear, reasoned justification for why dot product, cosine similarity, and Euclidean distance each fail on the dual-natured output tokens, and why a hybrid geometric metric (TS-SS) is appropriate. This level of diagnostic analysis is absent from most prior counting work.

## Weaknesses

### Fatal
None.

### Major
- **Abstract makes a factually incorrect blanket claim.** The abstract states the method "outperforms existing training-based and training-free counting methods" (MAE 16.25). The paper's own Table 1 contradicts this on FSC-147: LOCA achieves 10.79, BMNet+ 14.62, SAFECOUNT 14.32, PseCo 13.05, and TFCAC 12.26 — all substantially better. The body text (page 6) correctly notes that the method is best "among training-free SAM only methods" and acknowledges TFCAC's superiority. The abstract should be revised to match the actual scope; as written, it misrepresents the results.
- **Missing ablation for the probabilistic prompt generation component.** The paper claims that probabilistic prompt generation improves over deterministic methods (grids, superpixels), but never runs the controlled experiment that would substantiate this: comparing probabilistic vs. uniform grid prompting with the *same* output-token verification pipeline, holding the prompt budget fixed. Table 4 varies iteration count and prompts-per-iteration, which only shows that more prompts help — a trivial finding that applies to any prompting strategy. Without this comparison, the claimed advantage of the probabilistic stage over grid-based alternatives is unverified. The contribution of this component to the overall result is therefore unsubstantiated.
- **No statistical variance reported.** All MAE/RMSE/NAE/SRE values in Tables 1–5 are single point estimates with no error bars, standard deviations, or confidence intervals. The method involves random sampling from a multinomial distribution and, for CARPK, random exemplar selection ("randomly selected 12 objects from the training set to use as exemplars"). The differences between verification metrics in Table 3 (e.g., 16.25 vs. 16.48) are small enough to fall within plausible noise ranges. Without multiple runs or variance reporting, the reader cannot assess whether the reported differences are statistically meaningful.

### Minor
- **Output token selection is underspecified.** SAM's decoder produces multiple output tokens per prompt (typically 4, where the first is the highest-confidence). The paper says "output tokens from SAM's decoder" but does not specify which token is used, how it is matched to the predicted mask, or how the exemplar's output token is obtained. This is essential for reproducibility.
- **Iterative update rule is incompletely described.** Section 3.1 states that when a prompt is verified as positive, its mask is added to the "exemplar list to use as new verification criteria in the next iteration." However, it is unclear whether the similarity computation (Eq. 1) is recomputed using the expanded exemplar list, or whether the verification criteria remain based on the original exemplar. The probability distribution updates (setting positive regions to 0, decreasing negative regions) are described, but how the similarity map interacts with the growing exemplar set is not specified.
- **Table 4 anomaly is unexplained.** The configuration with 32 iterations × 128 prompts yields MAE 16.65 — worse than 16.25 at 16 iterations × 128 prompts — while the mean prompt count rises from 1438 to 1596. The paper invokes early stopping, but if anything, the higher mean prompt count suggests the stopping criterion did not fire earlier. The non-monotonic trend is not discussed or explained.
- **SAM baseline in Table 1 is not described.** The row labeled "SAM" (MAE 42.48) does not specify what prompt generation strategy or verification method it corresponds to, making the baseline uninterpretable.
