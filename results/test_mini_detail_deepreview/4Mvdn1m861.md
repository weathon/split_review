## Summary

The paper proposes TokenCount, a training-free object counting framework that leverages SAM's internal output tokens (from its decoder) for instance verification, paired with a probabilistic prompt generation strategy. The key idea is to avoid reliance on image embedding similarity for final counting decisions by instead using SAM's output tokens—which encode both semantic and positional information—to distinguish positive from negative instances. Results are reported on FSC-147 and CARPK benchmarks.

## Strengths

1. **Novel use of SAM's output tokens for counting verification.** Unlike prior training-free methods (TFOC, Count-Anything) that rely on image embedding similarity or additional models (OmniCount, TFCAC use DINO), the paper directly repurposes SAM's decoder output tokens as a verification signal. Table 5 shows that using output tokens (MAE 16.25) outperforms using the image embedding space (MAE 16.94) for the same verification pipeline, and Figure 5 provides PCA visualizations supporting that output tokens produce more separable positive/negative clusters.

2. **Strong CARPK results.** On CARPK, the method achieves MAE 4.68, outperforming all training-based methods (BMNet+ 5.76, SAFECOUNT 5.33, LOCA 9.97) and all training-free methods except TFCAC (4.39, which uses an additional DINO encoder). This is a genuine empirical demonstration that a purely SAM-based approach without auxiliary models can compete with and exceed supervised approaches on a real-world benchmark.

3. **Principled probabilistic prompt generation with adaptive exploration.** Section 3.1 describes a well-motivated iterative sampling procedure that sets probability to zero on verified positive regions and decreases probability on negative regions. Table 4 provides a systematic ablation showing monotonic MAE improvement from 29.10 (8 iterations, 32 prompts) to 16.25 (16 iterations, 128 prompts), confirming the iterative expansion strategy works correctly.

4. **Clean, purely SAM-based architecture.** The method adds no auxiliary models or fine-tuning—only SAM's frozen inference. Section 4.1 reports 1.69s per image on FSC-147, which is faster than methods relying on additional encoders. This computational efficiency is a concrete advantage over TFCAC and OmniCount.

## Weaknesses

### Major

1. **Abstract claim is factually incorrect.** The abstract states: "our method achieves superior accuracy with an MAE of 16.25, outperforming existing training-based and training-free counting methods." This is false as written: TFCAC (a training-free method) achieves MAE 12.26 on FSC-147 and 4.39 on CARPK—both strictly better than the proposed method's 16.25 and 4.68. The main text (Section 4.2) correctly acknowledges TFCAC's superiority, creating an inconsistency between the abstract and the body. Claims must be accurate as stated.

2. **RMSE on FSC-147 is very high, indicating catastrophic failures.** The method's RMSE of 133.11 is the second-worst among all methods in Table 1 (only SAM alone at 137.50 is higher), and far worse than training-based methods like LOCA (56.97) or training-free TFCAC (56.33). The MAE (16.25) masks that on a subset of images the errors are very large. The paper does not analyze this discrepancy—no error distribution plots, no discussion of which types of images produce large failures, and no characterization of the failure modes despite acknowledging in Section 5 that "dense distributions of very small instances" cause degradation. This omission makes it impossible to assess whether the method is practically reliable.

3. **TS-SS metric improvement is marginal and unaccompanied by significance testing.** Table 3 shows TS-SS (MAE 16.25) vs. cosine similarity (16.48) and L2 distance (16.53)—a 0.23 MAE improvement (~1.4% relative). The paper asserts that "non-hybrid metrics have reached a performance plateau" and that TS-SS "effectively integrates" both information types, but a 0.23 MAE gap from a single run with no error bars or statistical tests cannot support these strong conclusions. Without multiple trials or significance testing, the claimed superiority of TS-SS over cosine similarity is not established.

### Minor

4. **Prompt generation uses cosine similarity from the same image embedding space that the paper criticizes.** The paper motivates its approach by arguing that prior methods rely on "the inherent uncertainty of the similarity metric derived from [SAM's] image encoder" (Abstract, Section 1). Yet the prompt generation stage (Section 3.1, Eq. 1) builds a probability distribution entirely from cosine similarity computed on the same image embedding. This is not a contradiction—the similarity is used only for coarse prompt placement, while verification (the actual counting decision) uses output tokens—but the paper does not draw this distinction explicitly. Acknowledge that the similarity map, while imperfect, suffices for coarse spatial exploration and only becomes unreliable for the final counting decision.

5. **No statistical significance or error bars reported anywhere.** All experiments appear to be single-run. Given that the method uses probabilistic sampling (multinomial draws), results may vary across runs. The TS-SS vs. cosine difference (0.23 MAE) could easily be within noise. Reporting standard deviations over multiple runs is standard practice for sampling-based methods.

6. **Hyperparameter sensitivity unexplored.** τ = 0.066 and verification threshold = 300 are given without any sensitivity analysis. A brief sweep over 3–5 values per parameter would substantially increase confidence that performance is not brittle.

7. **CARPK exemplar count (12) is high but the paper states it follows the standard testing procedure.** The paper says "following the testing procedure, we randomly selected 12 objects from the training set to use as exemplars." This is more exemplars than typical few-shot protocols (1–3). The paper should explicitly state the exemplar counts used by baselines for transparency. However, note that training-based methods have the advantage of full dataset training, so the comparison is not obviously unfair—the concern is about lack of transparency, not about an inherent advantage.

### Trivial

8. The nonzero operation in Eq. 1 (`nonzero(F^I ⊙ M^R)`) is notationally unclear—the dimensions are 64×64×256 for F^I and 64×64×1 for M^R, so the Hadamard product semantics need clarification.
9. Qualitative analysis (Section 4.3) shows only success cases. Adding failure case analysis would strengthen the paper given the high RMSE concern.

## Nice-to-Haves

- An ablation that compares the full method against a variant using image embedding similarity for *both* prompt generation and verification (isolating the output token contribution from the iterative sampling benefit).
- Error distribution analysis (box plots or histograms) to contextualize the MAE/RMSE discrepancy.
- Analyze sensitivity to the number of exemplars on CARPK (1-shot, 3-shot, 12-shot).
