## Summary
The paper presents a systematic evaluation of 9 open-source LLMs on two reverse engineering tasks: name recovery and type inference, using 40,000 decompiled/assembly samples across 4 architectures and 4 optimization levels. The core finding is that all evaluated models achieve low F1 scores (<0.1 most tasks), and fine-tuning provides inconsistent improvements. The paper also evaluates real-world firmware and analyzes model behavior (size vs. quality, formatting failures).

## Strengths
1. **Broad multi-model, multi-task evaluation**: Evaluates 9 LLMs (CodeLlama, Llama2, DeepSeek-R1, Qwen2.5/3, etc.) on both name recovery and type inference across 4 architectures (x86-64, x86-32, ARM, MIPS) and 4 optimization levels, with 40,000 samples (Section 4.1, Tables 2-4). This is substantially broader than prior single-model reverse engineering studies.
2. **Standardized output normalization pipeline**: Uses an auxiliary LLM to normalize heterogeneous model outputs into a consistent schema (Section 3.2), enabling automated large-scale comparison that prior work lacked.
3. **Evidence that architecture/training matters more than size**: CodeLlama 7B, 13B, and 34B show similar performance (Figure 2), and Qwen2.5 outperforms its fine-tuned descendant DeepSeek-R1 despite identical architecture (Finding 5) — these are concrete, evidence-driven insights.
4. **Real-world firmware evaluation with two decompilers**: Table 6 evaluates models on stripped firmware using both Ghidra and IDA Pro, showing consistent near-zero F1 scores and practical insight that IDA Pro yields marginally better results.
5. **Documentation of practical LLM failure modes**: Tables 7-8 and Findings 7-8 document issues such as prompt template sensitivity affecting training time by 3×, chain-of-thought truncation, and formatting non-compliance — useful practical observations.

## Weaknesses

### Fatal
None.

### Major
1. **Inconsistency between Figure 1 and Table 2 F1 scores**: The paper states in Section 3.4 that name recovery uses CodeWordNet (SYMLM) for evaluation. However, Table 2 reports F1 scores of 0.01–0.06 for original models on function name recovery, while Figure 1 shows that the same models score ~0.10–0.25 *with* CodeWordNet and ~0.02–0.08 *without* it. For example, CodeLlama O0: Table 2 = 0.04, Figure 1 w/CWN ≈ 0.15, Figure 1 wo/CWN ≈ 0.05. Table 2 values align with the "without CodeWordNet" condition, contradicting the stated metric. The paper never explains this discrepancy. Since the paper's primary contribution is a benchmark, the reader cannot determine what metric was actually used, which undermines all reported absolute scores.

### Minor
2. **200-step fine-tuning protocol is insufficiently justified**: The paper fine-tunes each model for only 200 steps on 160,000 training samples (Section 4.3), with no reported batch size, learning rate, epochs, or convergence criteria. Without knowing whether models actually converged, the conclusion that "fine-tuning has limited impact" (Finding 1) cannot be fully trusted — the models may simply be undertrained. This weakens the fine-tuning analysis but does not affect the zero-shot results.
3. **CodeWordNet metric implementation underspecified**: Section 3.4 states that name recovery uses SYMLM/CodeWordNet and "the inferred name could obtain partial scores," but does not define how sub-word semantic matching converts to precision/recall/F1 counts. Standard F1 requires a crisp definition of true/false positives; with partial credit, this is non-trivial and needs explicit specification.
4. **No validation of auxiliary LLM output parser**: The automated pipeline uses an auxiliary LLM to normalize heterogeneous responses (Section 3.2), but the paper provides no validation (e.g., manual spot checks or agreement rates) of this step. Errors in the parsing LLM could systematically affect results across models.
5. **No discussion of training data contamination**: All evaluated LLMs were pretrained on large code corpora likely containing the GNU projects used in the dataset. The paper neither acknowledges this nor attempts to estimate its effect. While the overall low scores somewhat mitigate this concern (memorization would inflate scores, not suppress them), the omission remains a standard methodological gap.
