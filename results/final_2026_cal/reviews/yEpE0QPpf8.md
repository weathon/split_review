## Summary
This paper introduces Grounding-IQA, a new IQA paradigm that integrates multimodal referring (input location) and grounding (output location) with quality assessment. It comprises two subtasks: GIQA-DES (quality descriptions with precise bounding boxes) and GIQA-VQA (visual QA about local quality attributes, with positions in questions or answers). The authors construct GIQA-160K (167K samples, 43K images) via an automated annotation pipeline using Llama3, Grounding DINO, and Q-Instruct, and propose GIQA-Bench (100 images, 250 human-annotated samples) for evaluation across description quality, VQA accuracy, and grounding precision. Fine-tuning four backbone MLLMs (LLaVA-v1.5 7B/13B, LLaVA-v1.6 7B, mPLUG-Owl2 7B) on GIQA-160K yields consistent improvements across all three evaluation axes.

## Strengths
- **Novel paradigm definition with clear motivation.** The paper identifies that existing MLLM-based IQA methods only give contextual descriptions without precise localization, and formally defines the grounding-IQA task with two complementary subtasks (DES and VQA). Examples in Fig. 2 effectively illustrate the limitation being addressed (Q-Instruct cannot localize quality-critical regions).

- **Automated annotation pipeline with demonstrable quality improvements (Algorithm 1, Sec. 3.2, Tab. 2a).** The four-stage pipeline uses object tag extraction → bounding box detection → IQA-Filter + Box-Merge refinement → coordinate discretization. The ablation in Tab. 2a shows that Ref-Box improves mIoU from 0.5624 to 0.5851 and Tag-Recall from 0.5045 to 0.5497 over Raw-Box, and Fig. 6 shows the refinement shifts the box area distribution closer to human-annotated GIQA-Bench.

- **Large-scale, multi-architecture validation (Tab. 4, Tab. 5).** The dataset is evaluated on four different backbone architectures (LLaVA 7B/13B, LLaVA-v1.6 7B, mPLUG-Owl2 7B) and consistently improves performance. Tab. 5 compares against four groups of baselines (general, grounding-only, IQA-only), showing that Grounding-IQA models substantially outperform prior methods on the new benchmark — e.g., 0.7417 Acc (Total) vs. best IQA-only at 0.6017, while also producing meaningful bounding boxes that no prior IQA method provides.

- **Multi-task synergy validated (Tab. 3).** Joint training on both GIQA-DES and GIQA-VQA outperforms either sub-task alone. Only-VQA yields 0.7217 Acc but poor grounding (Tag-Recall 0.3283); joint training achieves 0.7417 Acc AND 0.7372 Tag-Recall on VQA, plus better DES metrics (LLM-Score 63.00 vs. 61.75).

- **Coordinate discretization is a practical contribution (Sec. 3.2 Eq. 1-2, Tab. 2b).** Reducing box representation from 21 tokens to ≤9 tokens via 20×20 grid discretization improves BLEU@4 (23.67 vs. 22.03) while maintaining grounding precision — a useful finding for efficient MLLM training.

## Weaknesses

### Major
- **Tag-Recall metric is underspecified (Sec. 3.4).** The paper defines Tag-Recall as requiring both IoU > 0.5 and "object name similarity exceeds a 0.5 threshold," but never states how object name similarity is computed. Is it exact string match? Cosine similarity of CLIP embeddings? A BLEU score between object name tokens? This makes the metric non-reproducible and is a genuine methodological gap. Since Tag-Recall is one of the two grounding metrics used to claim superiority over baselines (e.g., GroundingGPT, Ferret, Tab. 5), this needs to be resolved.

### Minor
- **VQA evaluation is confined to the in-house pipeline-generated benchmark, with no external VQA dataset tested.** The GIQA-Bench VQA questions are generated by the same pipeline (Llama3 + templates) used for GIQA-160K training data, with human refinement. While the human refinement helps, the lack of evaluation on an independently constructed VQA dataset (e.g., held-out Q-Pathway VQA splits or DepictQA subsets) makes it difficult to assess whether improvements reflect template familiarity vs. genuine VQA capability. The model's VQA Acc jump from 0.58–0.60 (Q-Instruct) to 0.74 is impressive, but without an external VQA benchmark the generalizability concern remains plausible.

- **Training data scale confound with Q-Instruct comparison.** GIQA-160K contains 167K samples (from 80K image-text pairs with augmentation), while Q-Instruct was trained on 53K image-text pairs (Q-Pathway). The comparison in Tab. 5 thus conflates the effect of the grounding format with the effect of additional training data. An ablation controlling for data quantity (e.g., training Q-Instruct-style on the same 80K image-text pairs without grounding) would isolate the grounding contribution.

- **Pipeline hyperparameter sensitivity unexplored.** The automated pipeline uses fixed thresholds (area threshold 0.256, overlap 95%, grid 20×20, Q-Instruct confidence filter) without any sensitivity analysis showing that results are robust to small variations in these choices.

### Trivial
- The radar chart in Fig. 1 uses different axis ranges for different metrics (e.g., mIoU 0–1, BLEU@4 0–25, LLM-Score 0–100), which can visually inflate the apparent improvement on some axes. The underlying Tab. 5 provides the correct numbers, so this is a presentation issue rather than a substantive flaw.

## Nice-to-Haves
- A human evaluation to validate the LLM-Score would strengthen the description quality analysis. The paper mentions a user study in the supplementary material; including the key findings (e.g., preference percentages) in the main text would help.
- A causal analysis showing that better grounding *causes* better quality assessment (rather than both improving from joint training) would sharpen the contribution. For instance, conditioning on grounding accuracy and measuring description quality.

## Suggestions
1. **Specify the Tag-Recall similarity computation.** Clearly define whether "object name similarity" uses exact string matching, CLIP text embedding cosine similarity, or another method. Provide the exact thresholding procedure.
2. **Evaluate on an external VQA benchmark.** Fine-tune the model on GIQA-160K and test on a held-out VQA subset from Q-Pathway or DepictQA to demonstrate generalization beyond the pipeline's output distribution.
3. **Add a data-quantity control ablation.** Compare grounding-IQA training against a model trained on the same quantity of non-grounded description data to isolate the effect of the grounding format.
4. **Include pipeline sensitivity analysis.** Report how varying the key thresholds (area threshold, overlap threshold, grid size) affects the quality of the generated data.
