## Summary

The paper presents Musketeer, a vision-language model with fully shared parameters trained jointly on seven heterogeneous tasks (visual grounding, VQA, captioning, classification, visual entailment, detection, summarization). The core innovation is the Task Explanation Prompt (TEP)—a structured natural-language prompt comprising Data Description, I/O Format, Output Description, and Instance Prompt—designed to reduce task interference by specifying differences and similarities among tasks. The central empirical finding is that TEP enables performance to improve as more tasks are added (3→7 tasks), while standard prompting (BaseP) degrades, and a single Musketeer model achieves results comparable to single-task OFA specialists.

## Strengths

- **Convincing task-number scaling result (Table 5/`tab:task_number`).** As training tasks increase from 3 to 7, TEP-prompted models improve on visual grounding (val: 86.0→87.5), caption (B@4: 37.1→38.3, CIDEr: 123.9→130.3), and visual entailment. BaseP-prompted models degrade monotonically over the same range (VG val: 86.7→85.8). This directly supports the claim that TEP mitigates interference and lets the model harvest synergistic information.

- **Consistent multi-task gains over simpler prompts.** Across three dataset scales (Subset$_{\text{small}}$, Subset$_{\text{vg}}$, Subset$_{\text{caption}}$) and two model sizes (Base, Large), TEP consistently outperforms both one-hot and BaseP on all six evaluated tasks (Table 3/`tab:task`). The advantage holds across visual grounding, visual entailment, VQA, caption, image classification, and text summarization—a broad and consistent signal.

- **Competitive with single-task specialists.** Musketeer$_{\text{Large}}$ (Subset$_{\text{caption}}$) matches or exceeds OFA$_{\text{Large}}$ specialists on visual grounding (90.8 vs 90.1 val), comes within 0.4 points on VE dev (89.9 vs 90.3), and achieves comparable caption scores (B@4 42.5 vs 42.4, CIDEr 140.2 vs 142.2)—all with a single jointly trained model and no task-specific fine-tuning.

- **Clean subprompt ablation (Table 8/`tab:componen`).** Removing any TEP subprompt degrades performance, confirming each component contributes positively. The full TEP achieves the best scores on all metrics.

- **Zero-shot and few-shot transfer benefits.** TEP improves zero-shot VE accuracy by >10 points over BaseP (49.1% vs 38.6%, Table 6) and boosts few-shot VG/VT by 3–4 absolute points (Table 4), demonstrating cross-task knowledge transfer enabled by structured prompts.

## Weaknesses

### Fatal
None.

### Major

1. **TEP substantially underperforms BaseP in the single-task (specialist) setting, and this trade-off is not discussed.** In Table 5 (`tab:task_number`), when trained on a single task (`#Task=1`), BaseP achieves VG val=88.6, VE dev=89.3, caption CIDEr=138.2, while TEP achieves only VG val=86.4, VE dev=84.5, caption CIDEr=128.9—a 2–5 point degradation. Since BaseP `#Task=1` is effectively the OFA specialist (same prompt and training), the TEP introduces substantial noise when no task interference exists. The paper claims TEP "reduces interference among tasks" and "allows the model to focus on shared structure," but the single-task degradation suggests TEP also introduces confusion that hurts performance even without interference. This is a real limitation of the prompt design that the paper neither acknowledges nor explains. Either TEP's extra tokens are harmful in isolation (requiring mitigation), or the paper should clarify that TEP is intended only for multi-task use and a model could switch prompt formats.

2. **The zero-shot unseen-task experiment is underspecified.** For the zero-shot visual entailment evaluation (Table 6), the paper reports training on six tasks and testing on SNLI-VE with TEP. However, it never describes how the TEP for the *unseen* visual entailment task was constructed—whether manually written, generated by ChatGPT (as for seen tasks), or derived automatically. Since TEP's structure (Data Description, I/O Format, Output Description, Instance Prompt) requires knowledge of the dataset and output space, the construction method matters for interpreting the result. A TEP hand-crafted for the unseen task using knowledge of SNLI-VE is qualitatively different from a procedure that could generalize to arbitrary unseen tasks. The paper should clarify the construction process and ideally provide the exact TEP used.

### Minor

3. **One-hot baseline performs surprisingly well, narrowing the gap attributable to TEP.** On Subset$_{\text{small}}$, one-hot achieves VG val=84.2 vs TEP's 87.5, and on Subset$_{\text{caption}}$ achieves 86.2 vs TEP's 88.7. The one-hot vector carries no task information beyond an index, yet it captures a significant fraction of the multi-task capability. This suggests that shared training in the architecture itself accounts for much of the multi-task performance, and TEP's added value, while real, is incremental (3–5 points). The paper should discuss this to set appropriate expectations about the mechanism.

4. **Comparison with prior multi-task models (Table 3) is informative but confounded by unequal data.** Musketeer is trained on Subset$_{\text{caption}}$ (44% of VQAv2, 100% of SNLI-VE and RefCOCO), while Unified-IO uses different data proportions. The paper acknowledges this, but the claim that Musketeer "surpasses other multi-task models substantially" is too strong when the leading competitor (Unified-IO XLarge, 6.2× larger) still beats Musketeer on VE test (91.1 vs 90.2) and VQA (77.9 vs 75.0), and the data mixture differences make direct comparison difficult. More precise caveats would strengthen the argument.

5. **No variance or significance estimates reported.** Given that differences between TEP and BaseP on several tasks are 1–3 points (within typical seed variance for models of this scale), reporting single runs without standard deviations weakens confidence. This is particularly important for the few-shot results (Table 4) where the sample sizes are very small (32 or 100 examples).

6. **"Task Description (ChatGPT)" baseline is discussed in the similarity analysis (Fig. 5) but not evaluated in the main performance tables.** Including it would help isolate whether TEP's structured multi-component design adds value over a richer single-sentence description generated by ChatGPT, versus whether the improvement is simply more informative text. The paper currently cannot rule out the latter explanation.

### Trivial
- Section 2.3 mentions "standard cross-entropy loss" for all tasks without clarifying how bounding box coordinates (for detection/grounding) are tokenized as text tokens. Following OFA's approach, this is fine, but a brief clarification would help.
- Table 6 and Table 7 both carry the caption "Experiments of zero-shot learning on unseen visual entailment task" (parser duplication); Table 7's caption should reference unseen datasets.

## Nice-to-Haves
- **Attention analysis linking TEP to model behavior.** The similarity matrices (Fig. 5) show TEP embeddings are more discriminative across tasks, but this is not causally linked to decoder attention patterns or output behavior. Visualizing attention maps for different TEPs would strengthen the "informational specialization" claim.
- **Full-data run for VQA.** The paper uses 44% of VQAv2 due to balanced sampling. A comparison showing Musketeer trained with 100% VQAv2 and proportionally more data for other tasks would strengthen comparisons with Unified-IO and other models.
- **Single-seed variance.** Reporting 2–3 seeds for key comparisons (especially Table 4 and the main `tab:task` table) would increase confidence in the reported margins.

## Novel Insights

The most interesting finding that emerges across the reviews is the *inversion* of the usual multi-task scaling pattern: while standard prompting (BaseP) suffers from negative interference as tasks increase, TEP prompts enable performance to improve monotonically with more tasks. This is a genuinely non-obvious result—structured textual task descriptions appear to turn task diversity from a liability into an asset. However, the single-task TEP degradation reveals that this benefit comes at a cost: the very structure that helps separate tasks when many are present appears to be harmful when applied to a single task. Whether this is due to token-length effects, unnecessary conditional computation, or a mismatch between the TEP content and single-task optimization dynamics remains an open question.
