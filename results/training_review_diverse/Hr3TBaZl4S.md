## Summary

The paper proposes Vector-Quantized Continual Diffuser (VQ-CD), combining a quantized spaces alignment (QSA) module that uses vector quantization to map different state/action spaces into a shared space, with a selective weights activation (SWA) diffuser that masks parameters per task to prevent catastrophic forgetting. The goal is to handle continual offline RL (CORL) with arbitrary task sequences, including those with different observation and action dimensions. Experiments on 15 CL tasks with 16 baselines are reported.

## Strengths

1. **Novel problem formulation that addresses a real limitation.** The paper correctly identifies that most prior CORL work assumes identical state/action spaces across tasks (Section 1, para 2), which is unrealistic. Proposing a method that handles different spaces is a meaningful and practical extension.

2. **Strong performance on same-space tasks (Ant-dir and CW10).** In Table 1 (Ant-dir sequence 10-15-19-25), VQ-CD achieves mean return 558.22±1.14, substantially outperforming the next best diffusion-based baseline (CoD, 478.19±15.84) and all LoRA variants. On CW10 (Figure 3), VQ-CD maintains stable performance across 10 tasks while baselines degrade, approaching the multitask upper bound.

3. **Quantized alignment demonstrably reduces feature discrepancies.** Table 2 shows that VQ's aligned features have much smaller differences across tasks (state diff ~8.5–9.0, action diff ~4.0–4.5) compared to AE-CD (state diff 42–58, action diff 13–15). This quantitative evidence directly supports the claim that vector quantization provides a more consistent shared representation than autoencoding alternatives.

4. **Weight assembling strategy is practical.** By training with standard masked weights and assembling task-specific parameters post-hoc (Section 4.2), the approach avoids the overhead of custom sparse optimizers while remaining compatible with complex architectures like U-Net. This is a clean engineering contribution.

5. **Ablation study validates design choices.** Figure 5 shows that replacing VQ with AE or VAE substantially lowers performance across all four D4RL settings, and the U-Net diffuser outperforms the MLP-based variant, confirming the importance of both the quantization and architecture choices.

## Weaknesses

### Fatal
None.

### Major

1. **Ambiguity about whether QSA or padding was used in the D4RL experiments — the paper's central claim is at stake.** The D4RL experiments (Figure 4) are the paper's only evaluation on tasks with different state/action spaces. Yet the figure caption states: *"We leverage state and action padding to align the spaces."* This language directly contradicts the method section, which claims QSA (vector quantization) is what enables handling different spaces. The main text (lines 278–288) discusses these results as if QSA were used, but never explicitly confirms it. Meanwhile, the ablation study (Figure 5) does compare VQ-CD vs. AE-CD vs. VAE-CD on D4RL settings, showing VQ works best — so QSA is tested *somewhere*. But the fact remains that the *main* D4RL comparison may have used a different technique (padding) than what the paper motivates as its core novelty (QSA). The paper must clarify: were the main D4RL results obtained with QSA or padding? If padding was used, the paper's claim that QSA enables arbitrary spaces is untested in the main experiments. If QSA was used, the caption is misleading and must be corrected. Either way, this ambiguity undermines confidence in the paper's central contribution.

2. **The inverse dynamics model is mentioned but never specified.** Section 3.2 (line 97) and the abstract mention an inverse dynamics model $\Psi(s_t,s_{t+1})$ that produces actions from state sequences generated by the diffuser. Yet the paper never describes its architecture, how it is trained, whether it is shared across tasks, or how it interacts with the QSA module. This model is essential to the method's pipeline (the diffuser outputs state sequences; actions come from $\Psi$), making the method description incomplete without it.

3. **Key hyperparameters and implementation details for SWA are missing.** The mask generation (Section 4.2) says masks are created by "randomly sampling unmasked positions from the remaining available mask positions" but does not specify: (a) what proportion of parameters is allocated per task, (b) whether the allocation is uniform across layers, (c) how total available parameters per layer are determined, or (d) how the mask interacts with the U-Net's residual connections, time embeddings, and skip connections beyond a generic element-wise product. These details are necessary for reproducibility.

### Minor

1. **No error bars or confidence intervals on CW10 and D4RL figures.** Table 1 reports 30 seeds with standard errors, but Figure 3 (CW10) and Figure 4 (D4RL) show only mean curves/bar charts without any variance indication. In continual RL with diffusion models, performance can be highly stochastic. Without error bars, the statistical significance of the reported advantages (e.g., "large performance margin" on D4RL, line 284) cannot be assessed. The number of random seeds is also not reported for these experiments.

2. **The QSA module's operational details are under-reported.** The paper does not state: how many codebook entries are used per task, whether the codebook is shared or task-specific, what the encoder/decoder architectures are, or how new tasks' codebook entries are added incrementally. While the parameter sensitivity analysis (Section 5.6) explores codebook size, it does not connect these hyperparameters to the continual learning protocol.

3. **The paper does not discuss limitations.** There is no limitations section or acknowledgment of constraints. For example, the mask allocation scheme implies a hard upper bound on the number of tasks (limited by network capacity), and the computational/memory overhead of storing per-task masks is not quantified. Adding a brief limitations paragraph would improve honesty and completeness.

4. **The "weights assembling" description conflates training and post-processing.** Section 4.2 says the approach uses "extracting and assembling the corresponding weights at the end of the training rather than updating the corresponding weights during training" (line 177). However, since gradients do flow through unmasked weights during training, weights *are* updated during training — the assembling is a post-hoc extraction step. The phrasing is misleading about the gradient flow.
