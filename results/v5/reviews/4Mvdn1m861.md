## Summary

The paper proposes TokenCount, a training-free object counting framework that repurposes SAM without architectural modifications or auxiliary models. The method has two components: (1) a probabilistic prompt generation stage that iteratively samples prompts guided by a probability distribution derived from SAM's image embedding, and (2) an output token-based verification stage that uses SAM's decoder output tokens with the TS-SS similarity metric to distinguish positive from negative instances. On FSC-147 and CARPK, the method achieves MAE 16.25 and 4.68 respectively, outperforming prior SAM-only training-free methods and being competitive with methods that use additional foundation models.

## Strengths

1. **Novel and clean repurposing of SAM's output tokens for counting.** The idea of using SAM's decoder output tokens — which jointly encode semantic and positional information via the decoder's bidirectional attention — as the verification representation is technically interesting and well-motivated. Table 5 shows that operating in the output token space (MAE 16.25) outperforms operating in the image embedding space (MAE 16.94), confirming the value of this design choice.

2. **Strong empirical results within the SAM-only training-free paradigm.** On FSC-147 (Table 1), the method achieves MAE 16.25, substantially improving over TFOC (19.95) and C-Anything (27.97). On CARPK, it achieves MAE 4.68, outperforming all training-based methods listed (e.g., SAFECOUNT 5.33, BMNet+ 5.76) and all training-free methods except TFCAC (which uses an extra DINO encoder). The CARPK result is particularly noteworthy.

3. **Principled probabilistic prompt generation.** The iterative probability distribution update (setting positive regions to zero, decreasing negative regions) is a clean mechanism for reducing redundant sampling. The ablation in Table 4 shows consistent improvement as prompts per iteration increase, confirming that the exploration strategy works as intended.

4. **Computational efficiency relative to methods using additional foundation models.** At 1.69 seconds per image on an A100, the method is more than twice as fast as TFCAC, which requires an additional DINO encoder. This demonstrates a meaningful speed-accuracy trade-off advantage.

## Weaknesses

### Major

1. **No error bars or measures of variance on any result.** All MAE, RMSE, NAE, and SRE values in Tables 1–5 are reported as single numbers without standard deviations, confidence intervals, or any indication of result stability. This is a significant concern because the claimed advantage of the TS-SS metric over cosine similarity (MAE 16.25 vs. 16.48, Table 3) amounts to only a ~1.4% relative improvement. Without error bars, it is impossible to determine whether this difference is meaningful or within noise. The same issue affects all other comparisons in Tables 1, 2, 4, and 5. In the object counting literature, reporting variance is standard practice when making comparative claims.

2. **Core metric contribution is empirically marginal.** The central technical argument of the paper is that TS-SS is the right metric for output token verification because output tokens encode both semantic (angular) and positional (magnitude) information. Yet the improvement over cosine similarity is only 16.25 vs. 16.48 MAE (Table 3) — a gap that, as noted above, is unreliably small without error bars. Meanwhile, the dot product (19.58) is much worse, which raises the question of whether the main benefit is simply using *any* reasonable metric on output tokens rather than the specific choice of TS-SS. The paper's claims about TS-SS being critically important are not well-supported by the evidence.

3. **Very high RMSE on FSC-147 despite competitive MAE.** The method achieves MAE 16.25 but RMSE 133.11 on FSC-147. For comparison, LOCA (training-based) achieves MAE 10.79 with RMSE 56.97, and even the simpler training-free TFOC achieves MAE 19.95 with RMSE 132.16. The RMSE being nearly an order of magnitude larger than the MAE indicates that the method produces extremely large errors on a non-trivial fraction of images. This is acknowledged qualitatively in the Discussion ("degradation in scenarios with dense distributions of very small instances") but is never quantified or analyzed — e.g., what fraction of images have error > 50, > 100? How does this compare to baselines? This undermines the reliability claim.

4. **Computational cost of the iterative prompting scheme under-discussed.** With 16 iterations and 128 prompts per iteration, the average number of SAM forward passes per image is ~1,438 (Table 4, "Mean prompts" column). Each prompt requires a full SAM decoder pass (including mask generation). While the paper reports 1.69 seconds per image on an A100 and notes being faster than TFCAC, this prompt count is two orders of magnitude higher than typical SAM-based counting methods (which might use hundreds of grid prompts). The relationship between the number of prompts and the method's advantage over simpler approaches (e.g., grid + cosine) is not explored. A practitioner reading the paper would want to know: can you achieve competitive results with far fewer prompts?

5. **Inconsistent overclaim in the abstract.** The abstract states: "Experimental results show our method achieves superior accuracy... outperforming existing training-based and training-free counting methods." On FSC-147 (Table 1), the method is outperformed by several training-based methods (BMNet+ 14.62, SAFECOUNT 14.32, PseCo 13.05, LOCA 10.79) and by the training-free TFCAC (12.26). The method only outperforms training-based Counting-DETR (16.79) by a slim margin. This overclaim should be corrected.

### Minor

1. **Threshold sensitivity not analyzed.** The token verification threshold is set to 300 "based on validation experiments" but no analysis of how performance varies with this threshold is provided. Given that threshold choice directly impacts the positive/negative decision boundary, this is a critical hyperparameter whose sensitivity should be examined.

2. **No comparison with simple baselines using output tokens with cosine similarity or L2 distance on full datasets.** Table 3 shows TS-SS vs. dot/cosine/L2, but without error bars and with only MAE/RMSE on the full FSC-147. A more detailed breakdown (e.g., per-category or per-complexity-bin) would help establish whether TS-SS consistently helps or only in specific scenarios.

3. **One-shot results are weak.** On FSC-147 one-shot (Table 2), the method achieves MAE 18.57, which is barely better than TFOC (22.96) and significantly worse than training-based methods like BMNet+ (16.89) and LOCA (12.53). The RMSE of 135.86 is the highest among all listed methods. The paper frames this as "competitive performance," but the results are weak, especially compared to the few-shot setting.

4. **The PCA visualization (Figure 5) is difficult to parse.** The figure description mentions a 2×2 grid with four subplots but the caption is confusing and the relationship between the subplots is unclear. The claim that output tokens "clearly distinguish between positive and negative objects" would benefit from a quantitative separability metric (e.g., silhouette score).

5. **Grammar and writing quality.** Several sentences have grammatical errors ("we could overlapping masks more precisely," "This limitation affects scalability for real-time applications and large datasets" — what limitation?), and the overall exposition is sometimes awkward. The paper would benefit from careful proofreading.

### Trivial

- The t-scale factor of 0.066 for prompt generation is noted but not explained or motivated.
- The reference to Equation (1) in the probabilistic prompt generation section uses notation (F^I, M, etc.) that requires careful cross-referencing to follow.
- Table 1 includes empty cells ("-") for some methods on CARPK without explanation.

## Novel Insights

The most interesting observation in the review corpus is that the paper's core insight — using SAM's output tokens directly rather than image embeddings — is well-supported by the PCA visualizations and the output-token vs. image-embedding comparison (Table 5), but the specific choice of TS-SS as the verification metric is empirically fragile. This suggests the paper's real contribution is the *token-space verification paradigm* itself, not the TS-SS metric, and that future work could explore simpler metrics or learned comparators on the output token space. The probabilistic prompt generation, while sensible, has the drawback of requiring many prompts per image; a more targeted analysis of the prompt-efficiency frontier would strengthen the method's practical appeal.

## Suggestions

1. **Run all experiments with at least 3 random seeds (or the standard evaluation protocol for each dataset) and report mean ± std.** This is essential for any comparative claim, especially given the small MAE differences.
2. **Temper the abstract's claims to accurately reflect that the method is best among SAM-only training-free methods, but not universally superior to all training-based or SAM+α methods.**
3. **Add an analysis of the error distribution** — what fraction of images have error > 50 or > 100 on FSC-147? How does the RMSE breakdown by object category? This would address the RMSE concern and provide actionable insights.
4. **Include a threshold-sweep plot** for the token verification threshold to demonstrate robustness.
5. **Add a baseline using grid prompts + cosine similarity on output tokens** to isolate the benefit of the probabilistic prompt generation.
