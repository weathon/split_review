## Summary

This paper introduces CONVCODEWORLD and CONVCODEBENCH, a pair of benchmarks for evaluating LLMs in multi-turn, feedback-driven code generation. CONVCODEWORLD systematically models 9 distinct interaction scenarios by combining compilation feedback, execution feedback (partial/full test coverage), and verbal feedback (novice/expert level, generated by GPT-4o). CONVCODEBENCH provides a cheaper, static alternative using pre-generated feedback logs, achieving Spearman rank correlations of 0.82–0.99 with the live benchmark. Evaluations of 17 closed- and open-source LLMs yield several empirical findings: model rankings depend on feedback combination, weaker models with sufficient feedback can outperform single-turn SOTA without feedback, training on specific feedback limits generalization to unseen combinations, and there is a trade-off between solving in few turns (MRR) and solving more problems overall (Recall).

## Strengths

- **Systematic variation of feedback types.** The paper goes beyond prior multi-turn benchmarks (InterCode, MINT) by explicitly modeling a Cartesian product of 3 feedback dimensions (compilation × execution coverage × verbal expertise), producing 9 distinct, directly comparable interaction scenarios (Table 6, Section 2.2). This is the paper's core design contribution.

- **Static proxy with strong rank correlation.** CONVCODEBENCH uses pre-generated logs from a deliberately weak reference model (CodeLlama-7B-Instruct) and achieves Spearman's ρ = 0.82–0.99 with the live CONVCODEWORLD (Section 4.3, Figure 2). The rationale for choosing a weak reference model (Table 2) is empirically grounded and well-articulated.

- **Empirical finding that weaker models can surpass single-turn SOTA with sufficient feedback.** The demonstration that DeepSeek-Coder-6.7B-Instruct (82.8 Recall) can match or exceed GPT-4o's single-turn performance (82.3) when given expert-level verbal feedback (Section 4.2.2, Tables 3–4) concretely validates the need for multi-turn, feedback-rich evaluation and is the paper's most striking result.

- **Large-scale, high-coverage base dataset.** Building on BigCodeBench-Instruct (1,140 problems, ~99% branch coverage) provides a more challenging and generalizable evaluation than HumanEval or MBPP-sanitized, which is appropriate for a benchmark paper (Section 4.1).

## Weaknesses

### Fatal

None.

### Major

- **Feedback source bias from using GPT-4o for both feedback generation and evaluation.** CONVCODEWORLD generates all verbal feedback via GPT-4o (abstract, line 5; Section 2), yet GPT-4o is also one of the top evaluated models (Tables 3–4). This creates a circularity risk: the feedback may be inadvertently tuned to GPT-4o's typical output patterns (e.g., anticipating its common mistakes, providing hints aligned with its internal knowledge), making the feedback more useful for GPT-4o-family models than for others. The paper does not discuss this issue, nor does it run a control (e.g., swapping the feedback generator to a different model to check if rankings shift). This directly affects the interpretability of cross-model comparisons that are central to claims like "Weak LLMs with Feedback Surpassing Single-Turn SOTA." While not fatal (the benchmark's structure remains valuable, and many findings are robust to this bias), it is a significant oversight that the authors must acknowledge and ideally address.

### Minor

- **CONVCODEBENCH correlation range (0.82–0.99) reported without per-combination breakdown.** The paper states Spearman's ρ ranges from 0.82 to 0.99 across feedback combinations (Section 4.3), but does not reveal which combinations produce the lower bound or analyze why correlation degrades. A high overall range can mask meaningful disagreement in specific scenarios — exactly the cases users would care about most. Figure 2 likely provides some visual breakdown, but explicit per-combination ρ values and discussion of low-correlation cases are needed to substantiate the claim that CONVCODEBENCH is a reliable proxy.

- **Reproducibility details for verbal feedback generation are not provided in the paper.** The paper claims reproducibility as a design goal (abstract), but does not specify the exact prompt template, temperature, top-p, max tokens, or seed used for GPT-4o verbal feedback generation. While code release is promised, these details are core to the benchmark design and should be documented in the paper itself.

- **No explicit statement about deterministic vs. stochastic evaluation settings.** The results tables (Tables 3–5) report single numbers without variance. If all generations use temperature=0 (or equivalent deterministic decoding), this is fine, but the paper should state this explicitly. If there is any stochasticity, multiple runs or confidence intervals are needed.

- **Generalization analysis limited to one model family.** Section 4.2.3 compares ReflectionCoder-DS (fine-tuned on a specific feedback combination) against its base model DeepSeek-Coder-Instruct. This is a valid case study, but the claim in the abstract ("training on a specific feedback combination can limit an LLM's ability to utilize unseen combinations") would be substantially stronger with evidence from additional model families or training setups.

- **MRR vs. Recall trade-off presented qualitatively without statistical testing.** Section 4.2.4 lists model-specific observations but does not provide a systematic analysis (e.g., plotting MRR vs. Recall across all models and feedback combinations, or reporting a correlation statistic). The trend is plausible and visible in the tables, but a more rigorous presentation would strengthen the finding.

### Trivial

- **Data contamination not discussed.** GPT-4o may have been trained on BigCodeBench problems (a public dataset), which could inflate its performance relative to other models. This is a general concern for all public-benchmark evaluations and would be a brief but appropriate note in the paper.

## Nice-to-Haves

- Run the same models on InterCode and MINT and compare the resulting model rankings with CONVCODEWORLD. This would directly demonstrate what additional insights the proposed benchmark uncovers. (Scope-adjacent; the paper's contribution is independently valuable, but this would strengthen the motivation.)
- Run a small-scale control experiment where verbal feedback is generated by a different model (e.g., CodeLlama-7B-Instruct or GPT-4-Turbo) to verify that model rankings do not shift dramatically.

## Removed Points

- **"The paper does not compare against multi-turn results of strong LLMs under identical feedback conditions."** Removed because it is factually wrong. Tables 3 and 4 contain multi-turn results for all models, including GPT-4, GPT-4-Turbo, and GPT-4o, across all feedback combinations. The paper's claim is specifically about *single-turn* SOTA performance, and the multi-turn results for strong models are present for readers to inspect.
- **"The observation that weaker models outperform single-turn SOTA is not surprising."** Removed as a subjective opinion about significance, not a factual weakness.
- **Missing comparison with existing multi-turn benchmarks (reporting results of same models).** Moved to Nice-to-Haves — this is a reasonable suggestion for strengthening the motivation but is scope-adjacent to the paper's core contribution.

## Novel Insights

The most insightful observation across the reviews is that the feedback-bias concern (GPT-4o generating its own feedback) is structurally similar to, but opposite in direction from, the paper's own careful design choice for CONVCODEBENCH (deliberately using a weak model as the reference to avoid ceiling effects). The authors could reframe this symmetry: just as a weak reference model avoids bias from overly capable feedback logs, future work should explore whether the *generator* of verbal feedback introduces analogous rank-order bias. This parallel is worth noting because it suggests a general design principle for reproducible feedback benchmarks — the feedback generator should be distinct from (and ideally weaker than) the evaluated models.

## Suggestions

1. **Address the GPT-4o feedback bias head-on.** Add a brief discussion acknowledging the limitation, and ideally run a small-scale control experiment with an alternative feedback generator (e.g., Llama-3.1-70B-Instruct) on a subset of problems to verify that model rankings do not shift materially.
2. **Report per-combination Spearman correlations for CONVCODEBENCH** in a table, and discuss cases where ρ is at the lower end of the 0.82–0.99 range.
3. **Release prompt templates and decoding parameters** for GPT-4o verbal feedback generation in the paper (appendix is appropriate) and in the code repository.
4. **State whether all generations use deterministic settings** (temperature=0) and, if not, report variance.
5. **Narrow the generalization claim** to reflect that it is observed on one model family, or add supporting evidence from additional families.

## Score and Decision

This is a solid benchmark paper with a genuine contribution: the systematic variation of feedback types fills a real gap between existing multi-turn benchmarks and the diversity of real-world interactive code generation. The static CONVCODEBENCH proxy is a practical addition. The main empirical findings are interesting and largely supported by the data.

The primary concern — GPT-4o serving as both feedback generator and evaluated model — is real but addressable and does not invalidate the core contributions. The other issues are standard minor presentation gaps for a benchmark paper. The paper's contributions outweigh its weaknesses by a clear margin.
