## Summary

MOCHA proposes to curate 10 publicly available spatial transcriptomics cohorts (covering breast cancer, colorectal cancer, DLPFC, mouse olfactory bulb, etc.) with expert pathologist annotations into a "standardized" multi-subject resource for benchmarking multi-sample SRT methods. The paper describes the selection criteria, summarizes the cohorts in a table, and includes two sections reviewing generic preprocessing workflows and existing multi-sample clustering methods. It contains no experiments, no validation, no data availability statement, no repository link, and no demonstration that the curated resource enables anything beyond downloading the original data from their public sources.

## Strengths

- **Curation of 10 cohorts across diverse tissues and platforms is a reasonable starting point.** Table 1 provides a concise overview of cancer (BC subtypes, CRC, kidney/lung/RCC), brain (DLPFC), and mouse olfactory bulb datasets spanning 10x Visium and ST technologies, with cohort sizes ranging from 1 to 94 subjects. Having these assembled in one place could save researchers some searching effort.

- **The paper correctly identifies a genuine need** in the SRT community: the lack of multi-subject, multi-cohort resources with consistent spatial annotations for benchmarking multi-sample integration methods.

## Weaknesses

### Fatal

- **No demonstration that the resource exists or is useful.** This is a structural failure for a dataset/resource paper. The paper provides no data availability statement, no repository URL, no download link, no file format specification, and no code release. A reader cannot access, inspect, or use MOCHA after reading the paper. There are zero experiments, zero baseline runs of any multi-sample method on the curated data, and zero comparisons to raw downloads from the original repositories. The abstract claims that MOCHA "provides standardized data organization, efficient storage formats for large-scale processing, and protocols for handling batch effects," but none of these are described, specified, or validated anywhere in the body.

- **Abstract claims are entirely unsupported.** The abstract and introduction promise standardized formats, efficient storage, protocols for batch effect handling, and formats "readily usable with Python and R." The actual paper contains no description of any file format, no storage efficiency analysis, and no MOCHA-specific protocol — Section 3 is a generic textbook review of normalization steps (TMM, RLE, log-transform) and existing tools (Harmony, Crescendo) that any practitioner would already know.

- **No results section, no conclusion, no structural completion of the paper.** The paper ends abruptly after Section 4 ("Multi-Sample Spatial Clustering Methods"). There is no Results, Discussion, or Conclusion section. The Author Contributions and Acknowledgments sections are empty. This reads as an incomplete draft or extended abstract, not a finished submission suitable for review.

### Major

- **Novelty over existing repositories is unquantified and unclear.** The paper acknowledges that several SRT data aggregators already exist (SORC, Aquila, SODB, STOmicsDB, SpatialDB) but does not provide any structured comparison. The claimed distinguishing feature is "expert pathologist annotations," but the selection criteria (Section 2) state that these annotations were required as a condition for inclusion — meaning they come from the original studies. The paper never clarifies whether the annotations are newly generated by the authors or recompiled from existing sources. If recompiled, the contribution is merely relisting what is already available. If new, the annotation protocol, inter-rater reliability, and quality control are all absent.

- **Sections 3 and 4 are generic background, not MOCHA-specific contributions.** Section 3 (Pre-processing and Batch Effect Correction) describes standard normalization, HVG selection, Harmony, and Crescendo in textbook fashion without any MOCHA-specific pipeline, parameter settings, or analysis. Section 4 (Multi-Sample Spatial Clustering Methods) is a 3-row table listing BayeSMART, BASS, and STAGATE — purely background. Neither section describes anything the authors did with or for MOCHA.

- **The "multi-subject" framing is misleading for some cohorts.** MOB.ST has 1 subject with 12 technical replicates (Table 1), which is single-subject, not multi-subject. This matters because multi-subject and multi-sample (technical replicates from one individual) pose fundamentally different challenges for batch correction and biological variability modeling.

### Minor

- **The paper does not address annotation quality.** Even accepting that annotations are existing pathologist labels, there is no validation, consistency check across cohorts, or mention of whether annotations from different studies use compatible labeling schemas. The Supplementary Material is referenced for a "four broad categories" grouping but cannot be verified.

## Nice-to-Haves

- A structured comparison table (MOCHA vs. SODB, STOmicsDB, SpatialDB, etc.) covering annotation availability, multi-subject support, format standardization, and download procedures would clarify the actual contribution.
- Baseline runs of one multi-sample method (e.g., BASS or STAGATE) across all cohorts, with standard metrics, would demonstrate that the resource works as intended.
- A data card or datasheet describing the curation process, exclusion criteria, and known limitations would strengthen the resource.

## Suggestions

1. **Release the resource.** Before resubmission, make the curated data and code publicly available at a persistent repository (Zenodo, Figshare) with a clear license, documented file format (e.g., AnnData/h5ad, Seurat objects), and a download procedure.
2. **Run baseline experiments.** Apply at least one multi-sample clustering method (e.g., BASS, BayeSMART, or STAGATE) to the curated cohorts and report standard clustering metrics (ARI, NMI). This validates that the resource is usable and provides initial benchmarks.
3. **Clarify what is new.** State explicitly whether annotations are newly generated or aggregated. If aggregated, explain what curation steps MOCHA adds (e.g., format conversion, quality filtering, label harmonization).
4. **Compare to existing repositories.** Include a table comparing MOCHA with SODB, STOmicsDB, SpatialDB, SORC, and Aquila across relevant dimensions.
5. **Complete the paper structure.** Add a Methods section describing the actual curation process, a Results section with baseline experiments, a Discussion of limitations, and a Data Availability statement.
