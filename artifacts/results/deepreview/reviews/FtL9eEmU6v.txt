# Review

## Summary
This paper proposes a new benchmark, EditBench, for evaluating LLMs' capabilities in performing code edits based on user instructions. The benchmark is built on real-world data collected from software developers using a VS Code extension. It consists of 540 problems spanning multiple natural and programming languages, and a diverse set of real-world use cases, ranging from resolving errors to adding features. The authors evaluate 40 LLMs on this benchmark and find that it is a challenging set of problems where only one model scores over 60%. They also find that model performance varies across different categories of user instructions and that the inclusion of additional contextual information (e.g., highlighted code) can improve task success rate.

## Strengths
- The paper addresses an important and timely problem of evaluating LLMs' capabilities in performing code edits, which is becoming increasingly relevant as LLM-powered code assistants gain popularity.
- The benchmark is built on real-world data collected from actual software developers using a VS Code extension, making it more reflective of real-world usage and challenges compared to existing benchmarks that rely on artificial sources or educational-style problems.
- The benchmark covers a diverse set of problems ranging from error resolution to feature addition, and spans multiple natural and programming languages, making it comprehensive and inclusive.
- The evaluation of 40 LLMs on the benchmark reveals insights into their capabilities and limitations, and shows that the benchmark is challenging even for state-of-the-art models, which highlights its effectiveness in distinguishing between different LLMs' strengths and weaknesses.

## Weaknesses
- While the benchmark is built on real-world data, the process of transforming it into a standardized set of test cases may introduce some degree of artificiality and potential biases, as the authors mention in the paper.
- The benchmark is currently limited to Python and JavaScript, and while the authors mention plans to expand to other languages, this limitation may affect its applicability to developers working with a wider range of programming languages.
- The benchmark may inadvertently reinforce existing biases present in the data from which it is derived, such as gender biases in the user base of the VS Code extension, as the authors discuss in the paper. This could limit its effectiveness in evaluating LLMs' fairness and inclusivity.

## Questions
- Have you considered any methods to mitigate potential biases present in the benchmark, such as gender biases in the user base of the VS Code extension? What steps could be taken to make the benchmark more inclusive and representative of a diverse developer community?
- Do you have any plans to expand the benchmark to include other programming languages? If so, how would you collect and process the data to ensure the quality and diversity of the examples?
- Have you considered any methods to make the benchmark more challenging for state-of-the-art models, such as incorporating more complex and ambiguous editing tasks?
